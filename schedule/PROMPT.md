# Cowork 운영 프롬프트

`SPEC.md`와 함께 세션에 넣는다. SPEC이 규칙이고, 이 파일이 작업 지시다.

---

## 역할

하루 시간표 텍스트를 받아 JSON으로 변환하고, 저장소에 커밋하고, 캘린더에 등록한다.
파싱 규칙은 전부 `SPEC.md`에 있다. 규칙이 애매하면 임의로 정하지 말고 물어본다.

**사용 서비스 (2026-08-17 확정)**

| 용도 | 서비스 | 비고 |
|---|---|---|
| 캘린더 | **Google Calendar** MCP | `#데일리` 캘린더에만 등록 |
| 미리알림 | **없음** | 외부 등록하지 않음. JSON과 뷰어에만 남긴다 |
| 커밋·푸시 | 미구현 | 아래 '작업 3' 참고 |

애플 캘린더·애플 미리알림 MCP는 존재하지 않는다. 애플 쪽으로 넣으려 시도하지 않는다.

---

## 작업 1 — 계획 등록 (텍스트를 받았을 때)

### 순서

1. **파싱** — SPEC의 규칙대로 텍스트를 JSON으로 변환한다.
2. **확인** — 변환 결과를 요약해서 보여준다. 특히 아래 세 가지는 반드시 짚는다.
   - 빈칸 연속으로 **2시간 이상**이 된 일정 (예: 샤워가 3시간이 되는 경우)
   - 자정을 넘긴 슬롯이 있는지
   - 슬래시로 분리된 항목
   틀렸으면 여기서 잡는다. 사용자 확인 전에는 다음 단계로 넘어가지 않는다.
3. **저장** — `schedule/data/YYYY-MM-DD.json` 작성. `data/index.json`의 `dates`와 `updated`도 갱신한다.
4. **캘린더 등록** — 아래 규칙대로.
5. **커밋 안내** — 커밋 메시지는 `schedule: YYYY-MM-DD` 형식. 자동 푸시는 아직 미구현이므로 사용자에게 직접 푸시하라고 알린다.
6. **결과 보고** — 등록한 일정 수, 커밋 대기 파일, 배포 주소를 한 줄씩.

### 캘린더 규칙

- **Google Calendar MCP를 쓴다.** `list_calendars`로 `#데일리` 캘린더 ID를 먼저 찾는다.
- **`#데일리` 캘린더에만 등록한다.** 다른 캘린더는 절대 건드리지 않는다.
  `#데일리`가 없으면 **멈추고 사용자에게 만들라고 알린다.** 다른 캘린더로 대체하지 않는다.
- **알림(alert) 없음, 반복(repeat) 없음.**
- **연속 구간은 하나로 병합해서 등록한다.** 30분짜리로 쪼개지 않는다.
  `07:30~10:00 헬스장` 하나이지 헬스장 5개가 아니다.
- **자유 시간은 등록하지 않는다.**
- **`[메모]` 섹션은 등록하지 않는다.**
- **중복 방지:** 등록 전에 `list_events`로 `#데일리` 캘린더의 해당 날짜 일정을 조회해 `delete_event`로 지우고 새로 넣는다.
  같은 날짜를 두 번 처리해도 결과가 같아야 한다.
- 자정 넘긴 슬롯(`24:00` 등)은 **다음 날 00:00으로 변환해서** 등록한다. JSON에는 24:00으로 남기고, 캘린더에 넣을 때만 바꾼다.
  이때 삭제 대상 조회 범위도 **다음 날 06:00까지**로 잡아야 전날 밤 슬롯이 남지 않는다.
- **시간대는 `Asia/Seoul`을 명시한다.** 생략하면 캘린더 기본 시간대에 따라 밀릴 수 있다.

### 리마인더 처리 규칙

- **어디에도 등록하지 않는다.** `[리마인더]` 섹션은 JSON에 저장하고 뷰어 사이드바에 표시하는 것으로 끝이다.
- 사용자가 아침에 뷰어를 보고 직접 판단해서 수행하거나 옮긴다. 이게 의도된 동작이다.
- `[공부]`, `[운동]`, `[메모]`도 마찬가지로 등록하지 않는다.
- 사용자가 그날 명시적으로 "이건 등록해줘"라고 지시하면 그때만 처리한다.

## 작업 2 — 매일 23:00 점검 (예약 작업)

1. 다음 날짜를 계산한다. **하루 경계는 06:00 기준**이므로, 23시 시점에서 "다음 날"은 달력상 내일이다.
2. `schedule/data/<내일>.json`이 있는지 확인한다.
3. **없으면** 알림을 보낸다. 있으면 아무것도 하지 않는다. 조용히 넘어간다.
4. 알림 문구는 짧게. 예: `내일(8/19) 시간표가 아직 없습니다.`

파일이 있는 날에는 보고하지 않는다. 매일 알림이 오면 무시하게 된다.

## 작업 3 — 커밋·푸시 (미구현, 나중에 붙일 예정)

현재 상태: **자동 푸시 불가.**

Cowork의 셸은 사용자 PC와 분리된 리눅스 샌드박스라서 Windows 자격증명 관리자에 접근할 수 없다.
`git push`를 시도하면 `could not read Username for 'https://github.com'`로 실패한다.
GitHub Desktop이 갖고 있는 토큰을 셸로 끌어올 방법은 없고, 끌어와서도 안 된다(자격증명은 다루지 않는다).

**따라서 당분간은 파일 저장까지만 하고, 커밋·푸시는 사용자가 GitHub Desktop에서 직접 한다.**

나중에 자동화할 때의 현실적인 선택지:

1. **컴퓨터 제어로 GitHub Desktop 조작** — 화면을 보고 Commit·Push 버튼을 클릭한다. 실제로 동작하는 유일한 자동 경로.
2. **PC에서 도는 스크립트에 위임** — 사용자가 `push.bat` 같은 걸 만들어 두고, 예약 작업이나 파일 감시로 스스로 돌게 한다. Claude는 파일만 저장한다.

어느 쪽이든 사용자와 합의한 뒤에 진행한다.

**커밋 전 주의:** 로컬이 원격보다 뒤처져 있을 수 있다(`news/` 쪽 커밋이 다른 경로로 올라온다). 반드시 `git pull` 먼저.

## 지켜야 할 것

- **JSON에 병합 결과를 저장하지 않는다.** 30분 슬롯이 원본이다. 병합은 캘린더에 넣을 때만 계산한다.
- **날짜를 추측하지 않는다.** `[날짜]` 섹션이 없으면 물어본다. 전날 밤에 쓰는 경우가 많아서 "오늘"로 넘겨짚으면 하루씩 밀린다.
- **index.html은 건드리지 않는다.** 디자인 수정은 별도 요청으로만.
- **파싱이 애매하면 멈추고 묻는다.** 잘못된 JSON이 커밋되면 캘린더까지 오염된다.

## 환경 점검 결과 (2026-08-17)

| 항목 | 결과 |
|---|---|
| 캘린더 커넥터 | Google Calendar MCP 사용. 애플 캘린더 MCP는 없음 |
| 일정 삭제 지원 | `delete_event` 있음 → 중복 방지 가능 |
| `#데일리` 캘린더 존재 | **미확인.** 커넥터 연결 후 `list_calendars`로 확인 필요 |
| 미리알림 연동 | 사용하지 않기로 결정. 리마인더는 뷰어에만 표시 |
| 저장소 푸시 | **불가.** 작업 3 참고 |
| `schedule/` 배포 상태 | **미배포.** 폴더 자체가 아직 커밋되지 않음 |

안 되는 단계는 그 단계만 빼고 나머지를 돌린다. 되는 척하지 않는다.
