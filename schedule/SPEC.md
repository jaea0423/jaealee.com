# 하루 기록 시스템 — 명세

매일 시간표를 텍스트로 입력하면 → JSON 저장 → 웹 시각화 → 캘린더 등록까지 도는 개인용 시스템.

목적은 **계획 · 실행 · 리뷰 · 기록**. 현재 구현된 건 계획 파트까지이고, 리뷰는 아직 없다.

---

## 1. 폴더 구조

```
<repo>/schedule/
├── index.html          뷰어 (1개만 유지. 날짜별로 만들지 않는다)
├── template.txt        입력 틀
└── data/
    ├── index.json      날짜 목록
    └── 2026-08-17.json 하루치 데이터
```

배포는 GitHub Pages. 접근 주소는 `jaealee.com/schedule/`,
특정 날짜는 `jaealee.com/schedule/?date=2026-08-17`.

**핵심 원칙: 데이터와 표현을 분리한다.**
매일 커밋하는 건 JSON뿐이다. HTML은 하나만 두고 재사용한다.
디자인을 바꿀 일이 생겨도 파일 하나만 고치면 되고, 나중에 통계를 뽑을 때도 JSON만 긁으면 된다.

## 2. 입력 포맷

```
[날짜]
2026-08-18

---

[시간표]
07:00 | 기상 / 약 복용
07:30 | 헬스장
08:00 |
10:00 | 프로틴 / 샤워
10:30 | -

---

[리마인더]
- 도서관 책 반납

---

[공부]
- 자료구조 3장 정리

---

[식사]
아침: 프로틴
점심: 학식
저녁: 닭가슴살, 밥

---

[운동]
등 / 이두

---

[메모]
러닝은 우천시 생략
```

### 파싱 규칙

| 기호 | 의미 |
|---|---|
| 빈칸 | 위 일정이 다음 일정 직전까지 이어짐 |
| `-` | 앞 일정을 여기서 종료. 그 뒤는 '자유' 시간 |
| `/` | 구분자. 항목을 나눠 각각 별개로 취급 |
| `( )` | 색 배분에서만 무시. 제목 자체는 그대로 유지 |

**슬래시 분리 후 연속 판정은 항목별로 한다.**

```
07:00 | 공부 / 커피
07:30 | 공부
→ 공부는 07:00~08:00 하나로 병합, 커피는 07:00~07:30만
```

### 그 외 규칙

- **섹션은 통째로 비면 생략 가능.** 순서가 바뀌어도 상관없다.
- **자정 넘김은 줄 순서로 판단한다.** 위에서 아래로 읽다가 시각이 작아지는 지점부터 다음 날. 맨 위의 `06:00`은 아침이고, `23:30` 아래의 `00:00`은 그날 밤이다.
- **`[날짜]`는 필수.** 전날 밤에 작성하면 하루 뒤 날짜를 써야 한다.
- **`[메모]`는 캘린더에 등록하지 않는다.** HTML에만 표시되는 참고사항 보관함이다. `러닝은 우천시 생략` 같은 조건은 자동 반영되지 않는다.
- **`[리마인더]`도 외부 서비스에 등록하지 않는다.** 뷰어 사이드바에서 직접 보고 판단하는 용도다. (2026-08-17 결정)

## 3. JSON 스키마

```json
{
  "date": "2026-08-17",
  "slots": [
    { "t": "07:00", "i": ["기상", "약 복용"] },
    { "t": "07:30", "i": ["헬스장"] }
  ],
  "reminders": ["도서관 책 반납"],
  "study": ["자료구조 3장 정리"],
  "meals": { "아침": "프로틴", "점심": "학식", "저녁": "닭가슴살, 밥" },
  "workout": ["등 / 이두"],
  "memo": ["러닝은 우천시 생략"]
}
```

- `t` — 30분 단위 시각. **24:00, 24:30 형식으로 자정 이후를 표현한다.** 날짜를 바꾸지 않는다.
- `i` — 그 슬롯의 항목 배열. 슬래시로 나눈 결과.
- **빈칸은 앞 항목을 복제해서 저장한다.** 연속 규칙을 파싱 단계에서 이미 펼친다.
- **`-`(종료)와 완전히 빈 구간은 슬롯 자체를 넣지 않는다.** 뷰어가 이를 '자유'로 렌더링한다.
- **병합 결과는 저장하지 않는다.** `07:30~10:00 헬스장`은 파생 데이터이므로 필요할 때 계산한다. 30분 슬롯이 원본이다.
- 비어 있는 섹션은 키 자체를 생략해도 되고 빈 배열이어도 된다.

### data/index.json

```json
{ "updated": "2026-08-17", "dates": ["2026-08-17"] }
```

날짜 목록. **현재 뷰어는 이 파일을 읽지 않는다.** 자동화가 유지만 해두고, 나중에 달력 UI나 주간 통계를 붙일 때 쓴다.

## 4. 뷰어 (index.html)

- 상단: 날짜 + 이전/다음 버튼 + 달력 아이콘 (누르면 날짜 선택 팝업)
- 날씨: 상태 / 기온 / 습도 / 강수확률 칩. 강수확률 50% 이상이면 파란 경고 띠에 비 오는 시간대를 글로 표시
- 시간표: 왼쪽에 정시 라벨, 그 옆에 1시간 단위 눈금자(홀짝 음영), 오른쪽에 30분 단위 블록
- 빈 시간은 회색 블록. 1시간 이상이면 `자유` 라벨
- 사이드: 리마인더 / 공부 / 식사 / 운동 / 메모

### 동작 세부

- **하루 경계는 06:00.** 새벽 5시에 열면 어제 날짜가 뜬다. `CONFIG.dayResetHour`로 조정.
- **날씨는 춘천시 효자동 고정** (37.8656, 127.7414). Open-Meteo, API 키 불필요.
- **색은 제목 기준으로 매일 재배분된다.** 날짜를 해시해서 색상환 시작점을 정하고, 그날 등장하는 제목 수만큼 균등 분할한다. 괄호는 무시하므로 `공부`와 `공부 (예습)`은 같은 색, `공부하기`는 다른 색.
- **글씨가 넘치면 한 줄에 들어갈 때까지 자동 축소**된다 (최소 9.5px, 그 이하는 말줄임).
- 오늘 날짜면 현재 시각선이 그려지고 그 위치로 자동 스크롤된다.
- 글꼴은 Pretendard 하나. 숫자는 `tabular-nums`로 폭을 고정한다.

### 알려진 제약

1. Open-Meteo 예보 API는 약 3개월 전까지만 지원한다. 그보다 오래된 날짜는 "날씨 정보 없음".
2. 자정 이후 시간대의 강수확률은 그날 새벽 값이 들어간다 (다음날 값이 아님).
3. 자유 시간이 많은 날은 화면이 회색으로 덮인다. 실사용 후 판단 필요.

### 손보기 쉬운 곳

CSS 상단 `:root` 토큰만 바꾸면 대부분 조정된다.

```css
--row:34px;        /* 30분 칸 높이 */
--paper:#E6E9E1;   /* 바탕색 */
--sans: ...        /* 글꼴 */
```

## 5. 아직 없는 것

- **리뷰 입력.** 계획만 저장되고 실행 여부가 안 남는다. 밤에 리뷰를 따로 받아 같은 JSON에 병합하는 구조가 필요하다.
- **주간/월간 통계.** JSON이 쌓이면 바로 뽑을 수 있다.
- **체중·수면 등 기록값.**
