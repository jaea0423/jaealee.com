# 아이맥 자동 발행 인계

상태: Windows에서 인계 준비와 보조 도구 검증을 완료했습니다. 아이맥의 인증·예약 실행은 아직 설정하지 않았습니다.

## 운영 방식

- 아이맥: 뉴스 → 지식 더하기 → 기회를 하나의 실행에서 순서대로 작성하고 한 번에 발행합니다. 세 개의 예약을 같은 시각에 따로 실행하지 않습니다.
- Windows: 홈페이지 디자인·기능을 수정합니다. 자동 발행 데이터와 목록을 같은 시간에 수동 수정하지 않습니다.
- 자동화용으로 별도 복제본 `jaealee-daily`를 사용합니다. 수동 작업용 복제본, iCloud 동기화 폴더와 분리합니다.
- 일일 자동화의 변경 허용 범위는 당일 데이터 3개와 뉴스·지식·기회 목록 3개뿐입니다. HTML/CSS/JS, 다른 날짜 데이터, 봇 파일은 변경하지 않습니다.
- Git의 일반 푸시는 최신 원격 이력을 잃게 만드는 푸시를 거절합니다. 서로 다른 파일은 최신 이력 위에 다시 적용할 수 있지만, 같은 파일이 양쪽에서 바뀌면 중단하고 검토합니다. 충돌 0%를 보장하지 않습니다.

## 아이맥에서 이어서 할 일

1. GitHub에 접근 가능한 계정인지 확인합니다. GitHub Desktop의 로그인 또는 SSH/HTTPS 인증 중 현재 환경에 맞는 방식을 사용합니다. 비밀번호·토큰을 채팅, 문서, 저장소에 쓰지 않습니다.
2. `https://github.com/jaea0423/jaealee.com.git`를 자동화 전용 폴더에 복제하고 main 브랜치로 둡니다. Node.js와 Git을 확인합니다.
3. 이 문서, `AGENTS.md`, `automation/DAILY.md`, 세 콘텐츠별 프롬프트를 읽습니다. 사용자의 비공개 관심사·신청 상태는 저장소 밖에서 전달받습니다.
4. `node automation/publish.cjs check`를 실행합니다. 최신 예시 JSON과 목록 연결을 검사합니다. 검사는 사실성·인용 출처 검증을 대신하지 않습니다.
5. 원격 읽기 권한, 커밋 작성자 설정, `git push --dry-run origin HEAD:main`을 확인합니다. dry-run만으로 모든 서버 정책과 실제 푸시 성공을 보장하지 않습니다.
6. 실제 발행 전, 임시 디렉터리에서 조사·작성·검증을 한 번 실행합니다. 같은 날짜의 기존 공개 원고를 덮어쓰지 않습니다. 브라우저에서 세 탭을 확인합니다.
7. 기존 Claude 자동화와 다른 컴퓨터의 같은 발행 예약을 확인합니다. 전환 전에 중복 실행을 해제합니다. 접근할 수 없으면 사용자에게 해당 예약 해제를 요청합니다.
8. 아이맥에서 예약 도구로 자동화를 등록합니다. 사용자가 매일 06:00 Asia/Seoul 시작, 뉴스 → 지식 → 기회 순차 실행과 자동 커밋·푸시를 확정했습니다. 시각이나 일일 게시 승인을 다시 묻지 않습니다. 06:00에 시작하여 07:00 전 검증·푸시·배포 완료를 목표로 합니다. 화면의 발행일 전환은 07:00입니다.
9. 이 전용 복제본을 프로젝트로 연결하여 로컬 실행합니다. 도구가 작업 트리만 지원하면 이 발행 스크립트를 그대로 사용하지 말고 아이맥에서 흐름을 맞춘 뒤 검증합니다. 현재 스크립트는 main 브랜치의 전용 복제본을 요구합니다.
10. 수동 실행 1회와 다음 예약 실행을 확인한 뒤 운영 시작으로 보고합니다. 본문 생성·커밋·푸시·사이트 반영을 각각 구분합니다.

공식 문서에 따르면 로컬 프로젝트 예약 작업은 컴퓨터가 켜져 있고 앱이 실행 중이어야 합니다. 아이맥에서 전원·시스템 잠자기·앱 실행·네트워크 권한을 확인하세요. 계정 설정이나 전원 설정 변경은 사용자 확인을 받고 진행합니다.

## 예약 프롬프트

`automation/DAILY.md`를 읽고 그대로 실행하세요. 한국시간 07:00부터 익일 07:00 직전까지를 한 발행일로 하는 뉴스, 지식 더하기, 기회를 순차 작성하여 검증된 데이터만 발행하세요. 이미 발행된 날짜는 자동으로 덮어쓰지 마세요. 동기화·잠금·허용 파일 제한·일반 푸시 규칙은 `automation/publish.cjs`로 적용하고, 충돌·검증 실패 시 초안을 보존하고 중단하세요. 완료 시 세 콘텐츠의 결과, 커밋·푸시·배포 확인 상태와 필요한 사용자 조치를 간결하게 알려주세요.

## 정기 실행 명령

저장소 루트에서:

```sh
# 시작 시 clean main을 확인하고 최신 원격과 동기화합니다.
node automation/publish.cjs prepare
# DAILY.md에 따라 당일 자료를 작성합니다. 기존 발행본은 건너뜁니다.
node automation/publish.cjs check
# 허용된 파일만 커밋합니다. 원격 변경을 확인하고 일반 푸시합니다.
node automation/publish.cjs publish
```

prepare가 출력하는 실행 날짜를 끝까지 사용합니다. 작업 도중 생성 날짜 경계(06:00)가 지나도 다른 날짜 파일로 바꾸지 않습니다.

잠금은 Git 내부에 저장되며 이 전용 복제본에서 중복 실행을 막습니다. 다른 컴퓨터까지 잠그는 전역 잠금은 아닙니다. 원격 경합은 파일 비교와 일반 푸시로 제어합니다.

실패 시 잠금·초안·커밋을 보존합니다. 재예약은 진행하지 못하게 막힙니다. 원인을 조사한 뒤 처리하세요. `cancel`은 변경과 미발행 커밋이 없는 경우에만 잠금을 해제합니다. 실패 상태를 감추려고 삭제·리셋·강제 푸시하지 마세요.

## Windows 작업 규칙

작업 시작 전 상태 확인 → 깨끗하면 fetch 및 fast-forward 동기화 → 디자인 수정·검증 → 요청 파일만 커밋 → 원격 갱신 확인 → 일반 푸시. 작업 중 변경이 있으면 자동 stash/reset하지 않습니다. 원격 변경과 겹치면 검토 후 이어갑니다.

아이맥 자동화가 실행 중인 날의 데이터·목록 수동 수정은 가능한 피합니다. 필요한 정정은 자동화를 잠시 멈추고 처리하며 기존 내용을 임의 병합하지 않습니다.

## 화면과 데이터

- 뉴스: `news/data/YYYY-MM-DD.json`, `news/index.json` → `/home/#news/YYYY-MM-DD`
- 지식: `knowledge/data/YYYY-MM-DD.json`, `knowledge/index.json` → `/home/#knowledge/YYYY-MM-DD`
- 기회: `opportunities/YYYY-MM-DD.json`, `opportunities/index.json` → `/home/#opportunities/YYYY-MM-DD`
- 기회 기본 탭은 현재 발행일 이하의 최신 발행분을 목록에서 선택합니다. 표시 날짜·요약도 데이터에서 읽습니다.
- 날짜 파일과 해당 목록은 함께 발행합니다. 날짜별 JSON은 06시 이후 미리 푸시할 수 있지만 기본 화면과 날짜 선택 목록에서는 07시 전 당일호를 숨깁니다. 공개 저장소·JSON URL에 대한 접근을 막는 보안 기능은 아닙니다.
- 관심사·개인 신청 여부·토큰은 공개 JSON/프롬프트에 저장하지 않습니다.

## 확정된 무인 운영 요구

매일 06:00 한국시간에 자동 시작하여 조사·작성·검증·커밋·푸시·배포 확인까지 진행합니다. 정상 발행은 사용자 확인을 기다리지 않습니다. 사용자는 매일 수동 실행하거나 푸시하지 않습니다. 한 시간의 준비 여유를 두되 장애로 늦어질 수 있습니다. 완료된 자료는 07:00부터 홈페이지에 표시하고, 늦으면 이전 발행분의 날짜를 표시하여 유지합니다.

발행일 예: 9월 12일 06:59:59는 9월 11일호, 9월 12일 07:00:00부터 9월 12일호입니다. 행사 신청 마감·날씨·시장 시각은 실제 달력 시각 그대로 검증합니다. 발행일 규칙 때문에 실제 마감 날짜를 이동하지 않습니다.

아이맥에서 인증과 비대화형 실행 권한을 최초 설정·검증합니다. 잠자기·종료·오프라인으로 누락된 실행은 복귀 후 현재 발행일의 누락분을 한 번 보충하는 복구 동작도 테스트합니다. 무제한 재시도하지 않으며 기존 성공본은 보존합니다. 외부 도구의 장애나 같은 파일 충돌까지 성공을 보장할 수는 없습니다. 이런 예외만 원인과 필요한 조치를 알리고 초안을 보존합니다. 정상적인 일일 게시에는 추가 승인을 요구하지 않습니다.

## 06시 사전 생성 규칙

06:00 생성 대상은 그날 07:00에 표시할 날짜입니다. 예: 9/12 06:00 생성 → 9/12호 JSON과 목록 추가 → 07:00 전까지 홈은 9/11호 → 07:00부터 9/12호. prepare가 출력하는 date는 preparationDate이며 화면의 date와 06~07시 사이에는 다릅니다.

기존 날짜 원고는 수정하지 않습니다. index.json 세 개는 기존 항목을 보존하면서 새 날짜만 추가합니다. 무수정 원칙의 예외는 이 목록의 추가 갱신뿐입니다. 새 파일과 목록을 한 커밋으로 게시합니다.
