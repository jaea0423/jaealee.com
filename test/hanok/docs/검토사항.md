# 한옥반점 예약 시스템 — 검토 요청 목록

작성일: 2026-08-30
용도: 사장님(고모)께 확인받을 항목 정리. 확인되면 시스템에 반영.

## 0. 사장님께 받아야 할 자료 (실제 계정 만들기 전)

시스템을 실제로 쓰려면 아래 자료가 필요합니다.
**지금 들어 있는 값은 전부 제가 임의로 넣은 가짜 데이터**라, 이 자료가 없으면 테스트만 가능합니다.

### 0-1. 예약 전화 응대 방식
- **예약 받을 때 쓰는 매뉴얼이나 정해진 순서가 있나요?**
  (있다면 그대로 받아서 시스템의 질문 순서를 맞추겠습니다)
- 없다면, 전화를 받을 때 실제로 어떤 순서로 물어보시는지
  (지금 시스템 순서: 경로 → 날짜·시간 → 인원 → 좌석 → 메뉴 → 성함·연락처 → 요청사항)
- 손님에게 꼭 안내하는 말이 있는지 (주차, 브레이크타임, 노쇼 정책 등)
- 예약을 거절해야 하는 경우가 있는지, 그때 뭐라고 말하는지

### 0-2. 수기 예약 노트
- **지금 쓰고 계신 예약 노트 사진 몇 장** (한 페이지 전체가 보이게)
- 어떤 항목을 적는지, 시스템에 빠진 항목이 있는지
- 표시(동그라미, 별표, 색깔 등)에 의미가 있는지

### 0-3. 좌석 실제 정보
- 룸 8개의 실제 최소·최대 인원, 층
- **홀 사진** — 이게 가장 중요합니다
  - 홀 전체가 보이는 사진 (1층·지하 각각, 여러 각도로 2~3장씩)
  - 테이블이 어떻게 놓여 있는지, 어디가 창가인지 알 수 있게
  - 사진으로 애매하면 손그림 배치도도 좋습니다
- 사진을 보고 제가 **구역(창가 / 가운데 / 안쪽 등)**을 나눠 설정하겠습니다
- 함께 확인할 것
  - 몇 인석이 몇 개인지
  - 어느 테이블끼리 붙일 수 있는지 (거리가 멀어 못 붙이는 조합)
  - 한 번에 최대 몇 개까지 붙이는지
  - 붙였을 때 실제로 몇 명이 앉는지 (4인석 2개 = 정확히 8명인지, 6~7명인지)
- 발렛 가능 대수, 두 매장이 함께 쓰는지

### 0-4. 메뉴판
- **코스 메뉴판 사진** (오/촉/한/위, 요리사/동한/서한, 요리사/B/A 확인용)
- 각 코스의 인원 조건이 있는지 (예: 2인 이상부터)
- 점심·저녁 구분이 실제 메뉴판과 맞는지

### 0-5. 운영 정보
- 요일별 영업시간·브레이크·라스트오더 (네이버 정보가 맞는지)
- 정기 휴무일이 있는지
- 명절 등 특별히 쉬는 날을 어떻게 정하시는지

### 0-6. 계정
- PIN 번호를 몇 번으로 할지 (지금은 1234)
- 이 번호를 누구까지 공유할지 (점장만? 홀 직원 전체?)
- 관리자 비밀번호를 사장님이 직접 정하실지 (지금은 admin1234)

## 1. 지금 당장 확인이 필요한 것

### 1-1. 좌석 정보 최신화 (가장 급함)
지금 시스템에 들어 있는 값은 전부 **제가 임의로 넣은 가짜 값**입니다.
실제 값으로 바꿔야 예약 판정(자리 있음/없음)이 의미가 생깁니다.

**룸 8개**

| 룸 | 현재 설정 | 실제 값 |
|---|---|---|
| 조조 | 2인~4인 · 1층 | |
| 유비 | 2인~4인 · 1층 | |
| 장비 | 2인~4인 · 1층 | |
| 관우 | 4인~6인 · 1층 | |
| 공명 | 4인~6인 · 지하 | |
| 주유 | 4인~6인 · 지하 | |
| 초선 | 6인~8인 · 지하 | |
| 동탁 | 8인~10인 · 지하 | |

- 각 룸의 **최소 인원 / 최대 인원**이 맞는지
- **층**이 맞는지
- 최대 인원을 넘겨 받는 경우가 실제로 있는지 (간이 의자 등)
- 룸 이름이 더 있는지, 빠진 게 있는지

**홀 2개**

현재 설정:
- 1층 홀: 창가(2인석 2개 + 4인석 2개, 최대 2개까지 붙임) / 가운데(4인석 6개, 최대 4개까지) / 단체석(6인석 1개, 붙임 불가)
- 지하 홀: 홀(4인석 8개, 최대 3개까지) / 안쪽방(6인석 2개, 최대 2개까지)

확인할 것:
- 테이블이 실제로 몇 인석 몇 개인지
- **어느 테이블끼리 붙일 수 있는지** (자리가 떨어져 있어 못 붙이는 조합이 있는지)
- 한 번에 최대 몇 개까지 붙이는지
- 붙였을 때 실제로 몇 명까지 앉는지 (4인석 2개 = 정확히 8명인지, 6~7명인지)

### 1-2. 룸 배정 우선순위
좌석을 정하지 않고 접수한 손님에게 시스템이 자리를 미리 잡아 둡니다.
그때 **어느 룸부터 쓸지** 순서를 정해야 합니다.

- 현재는 조조 → 유비 → 장비 → 관우 → 공명 → 주유 → 초선 → 동탁 순
- 실제로 먼저 채우고 싶은 방이 있는지 (예: 1층부터 채운다, 안쪽 방은 마지막에 쓴다)
- 단, 인원이 맞는 방 중 **남는 자리가 가장 적은 방**이 항상 먼저입니다.
  (4명 손님을 6인 룸에 넣지 않음)

### 1-3. 운영시간 확인
현재 설정 (네이버 정보 기준):

| 요일 | 영업 | 브레이크 | 라스트오더 |
|---|---|---|---|
| 일 | 11:00–20:30 | 없음 | 19:10 |
| 월~금 | 11:00–22:00 | 15:30–17:00 | 20:40 |
| 토 | 11:00–22:00 | 없음 | 20:40 |
| 공휴일 | 11:00–22:00 | 없음 | 20:40 |

- 맞는지, 계절이나 시기에 따라 달라지는지
- **브레이크타임에 손님이 매장을 나가야 하는지, 주문만 안 받는지**
  (전자면 브레이크 전에 식사가 끝나도록 예약을 잡아야 함)
- 공휴일 운영시간이 토요일과 같은지

### 1-4. 체류 시간
예약이 자리를 얼마나 차지하는지 계산하는 기준입니다.

- 현재: 룸 점심 2.5시간 / 룸 저녁 3시간 / 홀 점심 2시간 / 홀 저녁 2.5시간
- 실제 감각과 맞는지. 코스 종류에 따라 크게 다른지

### 1-5. 코스 구성
현재 설정 (메뉴판 기준으로 3줄):

| 구분 | 항목 | 적용 시간대 |
|---|---|---|
| 저녁 (종일) | 오 / 촉 / 한 / 위 | 평일저녁, 주말저녁 |
| 평일 점심 | 요리사 / 동한 / 서한 | 평일점심 |
| 주말 점심 | 요리사 / B / A | 주말점심 |

- 이름과 적용 시간대가 맞는지
- 공휴일 점심은 주말 점심으로 보는 게 맞는지
- 룸은 코스 주문이 전제인지 (현재는 룸인데 코스가 아니면 경고가 뜸)


### 1-6. 체류 시간 (자리를 얼마나 잡아 둘지)
예약 하나가 좌석을 몇 시간 묶는지 계산하는 기준입니다.
이 값이 틀리면 자리가 있는데 없다고 하거나, 없는데 있다고 합니다.

| 구분 | 현재 설정 | 실제 |
|---|---|---|
| 룸 · 점심 | 2시간 30분 | |
| 룸 · 저녁 | 3시간 | |
| 홀 · 점심 | 2시간 | |
| 홀 · 저녁 | 2시간 30분 | |

확인할 것:
- 룸과 홀이 실제로 다른지 (같다면 하나로 통일)
- 점심과 저녁이 다른지
- 평일과 주말이 다른지 (지금은 구분하지 않음 — 필요하면 추가)
- 코스 종류에 따라 크게 다른지 (오/촉/한/위가 서로 다른지)
- 단체 손님은 더 오래 걸리는지

### 1-7. 좌석 미정 손님을 룸에 넣어도 되는지
지금은 접수할 때 "홀 중 상관없음 / 룸 중 상관없음 / 상관없음" 중에 고릅니다.

**질문**: 룸이 비어 있을 때, 홀을 원한 손님이나 아무 데나 괜찮다는 손님을 룸에 넣어도 되나요?

- 넣어도 된다면 → 좌석 활용률이 올라감
- 안 된다면 → 한 번 허용하면 다음부터 계속 룸을 원할 수 있음.
  룸은 코스 주문이 전제인데 홀 손님은 일반 주문이라 매출 차이가 남

지금은 **‘상관없음’을 골라도 룸까지 후보에 넣고 있습니다.** 이게 맞는지 확인 필요.

## 2. 만들지 말지 결정이 필요한 것

### 2-1. 예약 확인 문자
노쇼를 실제로 줄이는 건 전날 확인 연락입니다.

- **A안**: 예약 상세에서 전화번호를 눌러 바로 전화 걸기 (무료, 즉시 가능)
- **B안**: 문자 양식을 복사해서 문자앱에 붙여넣기 (무료, 반자동)
- **C안**: 문자 자동 발송 (유료 API 필요, 월 비용 발생)

확인할 것: 지금 확인 전화를 돌리시는지, 돌린다면 몇 건 정도인지

### 2-2. 주방 전달용 요약
그날 코스 구성과 알러지를 한 장으로 뽑는 화면.

- 지금은 사장님만 보는 정보라 주방에는 구두로 전달해야 함
- 필요하다면 "오늘 코스 8인분, 알러지 2건" 식으로 정리해 인쇄하거나 화면으로 띄울 수 있음
- 확인할 것: 주방에 지금 어떻게 전달하는지

### 2-3. 예약금
코스 단가가 높아 노쇼 손실이 큽니다.

- 예약금을 받으시는지, 받는다면 얼마인지
- 받는다면 입금 여부를 시스템에 기록할지

### 2-4. 두 매장 통합 화면
안집과 발렛을 함께 쓰신다고 들었습니다.

- 시간대별 예상 차량 수를 두 매장 합쳐서 보는 화면이 필요한지
- 안집 시스템을 언제 만들지


### 2-5. 예약 규칙 추가 검토
지금 들어 있는 규칙:
- 라스트오더 이후 접수 → 경고
- 브레이크타임 접수 → 경고
- 식사가 마감을 넘김 → 경고
- 룸 최소·최대 인원 → 경고
- 룸인데 코스가 아님 / 코스 인원이 성인보다 적음 → 경고
- 브레이크가 ‘음식 주문만 중단’일 때, 브레이크 60분 전 이후 입장 → 경고

넣을지 검토할 규칙:
- **예약 가능 기간**: 몇 개월 전까지 예약을 받는지 (예: 3개월 전부터)
- **당일 예약**: 당일 전화 예약을 받는지, 몇 시간 전까지인지
- **하루 최대 단체 수**: 주방 부담 때문에 단체를 하루 몇 팀까지만 받는지
- **예약금 미입금 자동 취소**: 며칠 안에 입금 없으면 취소


### 2-6. 손님용 TV 안내 화면 (디스플레이 모드)
지금 만들어 둔 "오늘의 예약 안내" 화면입니다. 좌석별로 예약 시각과 손님 이름(이○아)을 보여줍니다.

**먼저 확인할 것: 매장에 TV나 모니터를 놓을 자리가 있나요?**
- 없다면 이 기능은 만들어도 못 씁니다 (지금은 만들어 둔 상태)
- 놓는다면 어디에? (입구, 대기 공간, 복도)
- 화면 크기와 가로/세로 방향

**그 다음 확인할 것**
- 손님 이름을 띄워도 되는지 (지금은 가운데 글자를 ○로 가림)
- 예약 시각을 다 보여줘도 되는지 (다른 손님 예약을 알 수 있음)
- 오히려 대기 순번이나 메뉴 안내가 더 필요한 건 아닌지
- TV를 안 놓는다면, 대신 **카운터 태블릿 화면**으로 직원이 확인하는 용도로 바꿀지

만들어는 뒀지만 TV가 없으면 의미가 없으니, **매장에 화면을 놓을지부터** 정해야 합니다.


### 2-7. 예약 확인 문자 — 언제 보낼지
문자를 보낸다면 아래 세 시점 중 어디에 보낼지 정해야 합니다.
(2-1 에서 문자 방식을 정한 뒤 결정)

| 시점 | 내용 | 판단 |
|---|---|---|
| **① 예약 등록 직후** | "예약이 접수되었습니다" | 손님이 안심함. 잘못 적었을 때 바로 확인됨 |
| **② 예약 내용이 바뀌었을 때** | "시간이 변경되었습니다" | 착오 방지에 가장 효과적 |
| **③ 방문 전날** | "내일 뵙겠습니다" | 노쇼를 줄이는 데 가장 효과적 |

- ②에서 **좌석 미정 → 좌석 배정**은 손님과 무관하므로 문자를 보내지 않습니다
  (룸 이름이 바뀌는 건 매장 사정이지 손님 사정이 아님)
- 셋 다 보내면 손님이 부담스러워할 수 있음. 몇 개를 쓸지 확인 필요
- ③만 써도 노쇼는 상당히 줄어듦

### 2-8. 유아용 의자 기본값
예약을 받을 때 유아 인원을 입력하면 유아용 의자 개수가 자동으로 따라옵니다.

**질문: 유아 2명이면 의자도 기본 2개로 둘까요, 아니면 0개로 두고 물어볼까요?**

- **유아 수와 같게 (지금 방식)**: 대부분 필요하다면 이게 편함
- **0개로 두기**: 아기띠나 유모차로 오는 경우, 큰 유아가 그냥 앉는 경우가 많다면 이쪽

의자가 몇 개나 있는지, 실제로 얼마나 자주 쓰는지에 따라 다릅니다.

## 3. 나중에 검토할 것 (지금은 안 해도 됨)

- **월간 캘린더 뷰** — "다음 주 토요일 비어요?"에 빠르게 답하기
- **단골 이력** — 전화번호로 과거 방문 횟수, 선호 룸 조회
- **엑셀 내보내기** — 세무·정산용
- **매출 관리** — 지금은 코드를 주석 처리해 둠. 필요하면 되살릴 수 있음
- **직원·근태 관리** — 위와 같음
- **룸 대기 (예약 대기열)** — 원하는 룸이 이미 찼을 때 대기를 걸어 두고,
  일단 다른 룸에 임시 배정했다가 원하던 룸이 비면 자동으로 옮기는 기능.
  전화 응대가 "그럼 대기 걸어드릴까요?"로 늘어나고, 자동 이동 후 손님에게 알리는 절차도 필요함.
  실제로 "그 룸 아니면 안 된다"는 손님이 얼마나 자주 오는지 확인한 뒤 판단.
- **테이블 구성 고급 모드** — 구역이 복잡해지면 화면에서 하나씩 넣기가 번거로움.
  설정에서 프롬프트를 복사 → AI에게 배치 사진과 함께 주고 → 결과 텍스트를 붙여넣으면
  한 번에 구성되는 방식. 지금은 구역이 5개 이하라 필요 없지만,
  실제 배치를 받아보고 복잡하면 만들 것.
  (필요한 것: 정해진 텍스트 양식, 붙여넣기 입력창, 잘못된 형식 검사)
- **접속 기록(로그)** — 설정에서 숨겨 둠. IP·시각·동작이 계속 쌓이고 있음.
  Supabase 로 옮기면 재아가 원격에서 확인할 수 있게 됨
- **테이블 붙임 조합 상세 지정** — 지금은 '구역' 단위로만 붙일 수 있음.
  "1번+2번+3번은 되지만 1번+3번은 안 됨" 같은 세밀한 조합이 실제로 필요한지 확인 필요.
  필요하다면 테이블마다 옆자리를 지정하는 방식으로 바꿀 수 있으나 설정이 복잡해짐.
