## 0. 먼저 이것부터 — 데이터가 저장되지 않습니다

### 0-1. `window.storage` 가 존재하지 않습니다 【재현 확인 · 최우선】

`src/index.html` 에서 저장소를 쓰는 곳은 두 줄뿐입니다.

```js
2330:  const r = await window.storage.get(STORAGE_KEY);
2382:  try{ await window.storage.set(STORAGE_KEY, JSON.stringify(DATA)); }
2383:  catch(e){ console.error("저장 실패", e); }
```

그런데 `window.storage` 는 **파일 어디에도 정의돼 있지 않습니다.** 브라우저 기본 객체도 아닙니다.

브라우저에서 확인한 결과:

```
typeof window.storage  →  "undefined"
localStorage 키 목록   →  []           (아무것도 안 씀)
예약 등록 → 새로고침    →  사라짐
```

**무슨 일이 일어나는가**

1. `loadData()` 가 `window.storage.get` 에서 `TypeError` → 바로 아래 `catch` 가 삼킴 → `seedDemo()` 로 **예시 데이터를 다시 깔음**
2. `saveData()` 는 매번 실패하지만 `console.error` 만 찍고 조용히 넘어감
3. 화면에는 아무 오류도 안 뜸

**그래서 지금 이 시스템은:**

- 예약을 등록해도 **새로고침하면 전부 사라집니다**
- 사라진 자리에 **예시 데이터(김하람·이도현 등 1,300여 건)가 다시 채워집니다**
- 예시 데이터는 한국 이름·정상 시각·룸 배정까지 갖춰져 있고, 화면 어디에도 "예시"라는 표시가 없습니다
- 즉 **직원이 어제 받은 예약이 사라진 것을 알아채지 못하고, 가짜 예약을 진짜로 착각합니다**

인수인계 문서 3장의 "브라우저 저장소(`window.storage`)에 JSON 하나로 저장됩니다. 현재 약 410KB" 는 사실과 다릅니다.

**고치는 법 (둘 중 하나)**

- **임시**: `window.storage` 를 `localStorage` 래퍼로 정의 — 10줄이면 됩니다. 한 기기 안에서는 저장됩니다
- **본래 계획**: Supabase 연동 (인수인계 7장). `loadData`/`saveData` 두 함수만 교체하면 되는 구조는 실제로 맞습니다

**어느 쪽이든 이걸 먼저 해야 나머지 점검이 의미가 있습니다.**

### 0-2. 저장 실패를 사용자가 알 수 없습니다 【코드 확인】

`saveData()` 는 실패해도 `console.error` 뿐이고, 호출부는 전부 `await` 하지 않습니다.

```js
saveData(); render();     // 실패 여부와 무관하게 화면은 "저장됨"
```

0-1을 고쳐도 이건 남습니다. 저장소 용량이 차면(로그 3,000건 + 예약) **그때부터 모든 예약이 저장 안 되는데 화면상으로는 정상**입니다.

→ `saveData` 를 `await` 하고, 실패하면 화면 상단에 빨간 띠를 띄워야 합니다.

### 1-1. 손님이 도착해 '방문'을 누르면 그 룸이 '빈 방'이 됩니다 【재현 확인】

좌석 충돌 판정의 원천인 `roomStatus()`(2674)가 **`status==="확정"` 인 예약만** 봅니다.

브라우저에서 같은 예약의 상태만 바꿔 가며 측정한 결과:

| 예약 상태 | 룸 판정 | 홀 남은 테이블 |
|---|---|---|
| (예약 없음) | free | 11 |
| 확정 | **blocked** | 10 |
| **방문** | **free** ← 문제 | 10 |
| **노쇼** | **free** | **10** ← 문제 |
| 취소 | free | 11 |

**룸**: 손님이 와서 '방문'을 누르는 순간 그 방이 비어 보입니다. 지금 식사 중인 손님 위에 다른 팀을 **경고 한 번 없이** 잡을 수 있습니다.

**홀**: 반대입니다. '노쇼' 처리해도 테이블이 계속 사용 중으로 계산됩니다. 그 자리에 워크인 손님을 넣으려 하면 "남은 테이블 부족"이 뜹니다.

**같은 버튼이 좌석 종류에 따라 정반대로 동작합니다.** 원인은 판정 기준이 파일 안에서 갈려 있기 때문입니다.

```js

2749  hallStatus   : r.status!=="취소"      ← 노쇼도 자리를 잡음
2711  canRelocate 룸 : status==="확정"
2718  canRelocate 홀 : status!=="취소"      ← 같은 함수 안에서도 다름
3749  dayStat      : status!=="취소"
```

→ **"좌석을 점유하는 상태"의 정의를 한 곳에 두고**(확정 + 방문, 취소·노쇼 제외) 위 다섯 곳이 전부 그걸 쓰게 해야 합니다.

확인 대화상자 떴나 : false

`saveRes()`(4733)에는 `roomStatus` · `hallStatus` · `timeWarn` 호출이 **하나도 없습니다.**

손님이 "6시를 7시로 바꿔주세요" 할 때, 7시에 이미 다른 팀이 있어도 조용히 저장됩니다. 통화 중에는 모르고, 끊은 뒤 대시보드 경고에서야 발견합니다.

### 1-3. 좌석을 삭제하면 그 예약이 화면에서 완전히 사라집니다 【재현 확인】

재현: 조조 룸에 예약 1건 → 설정에서 조조 삭제

예약의 roomId       : 'r1' (그대로 남음)

`delRoom()`(4563)은 `st.rooms` 에서만 지우고 예약의 `roomId` 는 그대로 둡니다. 확인 문구는 "기존 예약은 '미배정'으로 표시됩니다"라고 하지만 **실제로는 그렇지 않습니다.**

그 결과 예약은:
- 타임라인에서 사라짐 (`effSeat(r)` 가 어떤 줄과도 안 맞음)
- "룸 미배정" 지표·목록에 안 뜸 (`!r.roomId` 가 거짓)
- 확인 필요에도 안 뜸
- 경고도 안 뜸 (좌석 검사가 전부 `if(seat && ...)`)

같은 문제가 **홀 테이블 수를 줄일 때** 도 생깁니다. 넘치는 예약은 타임라인에서 사라지고(`lane===null` → 빈 문자열) 오른쪽에 "초과 N" 작은 글씨만 남습니다. 게다가 자리를 못 잡은 예약은 테이블을 0개 쓴 것으로 계산되어 **홀이 실제보다 여유 있게 표시됩니다.**

→ `saveBlock()` 이 이미 하고 있는 방식(걸리는 예약을 세어 목록으로 보여주기)을 `delRoom` · `delZone` · `delZSet` · `delCourseRow` · `saveSchedule` · `saveOverride` 에 그대로 붙이면 한 번에 막힙니다.

## 2. 중대 — 조용히 틀립니다

### 2-1. 코스 구성 행을 삭제하면 기존 예약의 코스가 어긋납니다 【재현 확인】

코스 키가 **배열 인덱스**로 만들어집니다.

```js
6454:  const key = `${gi}|${name}`;      // gi = courseGroups 배열의 index
```

```
저장된 키      : "2|A"
삭제 전        : 주말 점심 / A
1행 삭제 후    : 행 없음        ← 가리키는 곳이 사라짐
```

`delCourseRow` 는 `splice` 만 하므로 뒤 행의 인덱스가 앞으로 밀립니다. 예약에 저장된 키는 그대로입니다.

그 예약의 코스를 수정하려고 팝업을 열면 **아무 항목에도 선택 표시가 없는데 하단 합계는 4명**이라고 뜹니다. 직원이 비어 보이는 항목을 4번 누르면 **합계 8명**이 됩니다. 항목 이름을 고쳐도 같은 일이 생깁니다.

→ 행마다 고정 `id` 를 주고 마이그레이션 한 번 돌리는 것이 근본 해결입니다.

### 2-2. 설정 임시본이 새는 곳들 【코드 확인】

설정은 임시본(draft) 방식으로 잘 보호돼 있습니다. 다만 세 군데가 샙니다.

**(a) 임시본을 안 거치고 즉시 저장되는 것들**

`toggleClosed`(임시 휴무), `saveSchedule`(운영시간), `saveOverride`(임시 일정), `clearNoshow`(노쇼 제외), `addRole`/`delRole` 은 `store().settings` 에 **직접** 씁니다. 나머지는 임시본을 씁니다.

그래서 이런 일이 생깁니다:
1. 설정에서 체류 시간 3h → 2.5h (임시본에 기록)
2. 같은 화면에서 운영시간 수정 → 금요일 마감 22:00 → 21:00 → 저장 (실제 데이터에 바로 씀)
3. 하단 **적용하기** → 임시본이 통째로 덮어씀 → **금요일 21:00 마감이 사라짐**

**(b) 화면을 나가도 임시본이 안 지워짐**

`setTab` 은 변경사항이 있을 때만 임시본을 지우고, `lockNow`(로그아웃)는 아예 안 지웁니다. 설정을 한 번 열었다 나오면 임시본이 남아, 나중에 다시 들어갔을 때 낡은 임시본이 되살아나 "저장하지 않은 변경이 있습니다"가 뜹니다.

**(c) 새로고침하면 경고 없이 사라짐**

`view.draft` 는 메모리에만 있고 `beforeunload` 경고가 없습니다.

**(d) 적용한 뒤에는 되돌릴 수 없음**

`revertSettings` 는 "마지막으로 적용한 상태"로만 돌아갑니다. 직원이 룸 정원을 잘못 고치고 적용하면 원래 값을 아무도 모릅니다.

**(e) 설정 화면에 잠금이 없음**

상단바 톱니 한 번이면 들어갑니다. PIN 은 앱 진입만 지키고, 관리자 비밀번호는 PIN 변경에만 씁니다. 홀 직원이 실수로 룸을 지우고 적용할 수 있습니다.

### 2-3. 영업시간 입력에 검증이 하나도 없습니다 【재현 확인】

`saveSchedule` 은 `from`(적용 시작일)만 검사합니다.

**영업 종료를 비우면** — 브라우저 확인 결과:

```

예약률          : 계산 불가
```

`toMin("")` 이 `NaN` 이 되고, `axisRange` 의 폴백은 `o>=c` 비교인데 NaN 비교는 항상 거짓이라 **폴백이 작동하지 않습니다.**

| 입력 | 결과 |
|---|---|
| 종료 비움 | 타임라인 붕괴 · 예약률 NaN |
| 종료 < 시작 | 그대로 저장 · 예약률 계산 이상 |
| 브레이크 종료 < 시작 | 그대로 저장 · **브레이크 경고가 조용히 사라짐** |
| 라스트오더가 영업시간 밖 | 그대로 저장 · 모든 시각에 "라스트오더 넘김" |
| 마감을 02:00 (자정 넘김) | 예약률 100% 고정 · 모든 예약에 "영업시간 아님" · 하루 종일 "영업 종료" |

추가로 `autoLO()` 는 종료가 비면 `"NaN:NaN"` 을 만들어 설정에 저장합니다.

**운영시간을 줄일 때 그 시간대 예약을 검사하지 않습니다.** 금요일 마감을 22:00 → 20:00 으로 줄이면 이후 모든 금요일 20:30 예약이 조용히 경고 예약이 되는데, 그 사실은 해당 날짜를 직접 열어야만 알 수 있습니다. 예약 12건이 있는 날을 임시 휴무로 등록해도 경고가 없습니다.

## 3. 구형 TV 브라우저 — 조용히 깨집니다

디스플레이 모드의 목표는 "2018~2020년 크롬"(크롬 64~87)입니다. `build.py` 는 **JS 문법만** 검사하고 CSS 는 전혀 보지 않습니다. 그 사각지대에 심각한 것들이 있습니다.

### 3-1. `inset:` 17곳 — 크롬 87 이상 【코드 확인 · 치명】

`inset` 단축 속성은 **크롬 87(2020년 11월)** 부터입니다. 목표 범위의 거의 전 구간에서 무시됩니다.

```
 288: .overlay{position:fixed; inset:0; ...}   ← 모든 시트 팝업
 380: .wz{position:fixed; inset:0; ...}        ← 예약 등록 마법사 전체
 568: .tv{position:fixed; inset:0; ...}        ← 디스플레이 모드 전체
 (그 외 14곳)
```

무시되면 `top/right/bottom/left` 가 전부 `auto` 로 남아 **내용만큼만 크기를 갖습니다.**

- **디스플레이 모드가 전체화면을 덮지 못하고 화면 왼쪽 위 작은 상자로 찌그러집니다.** 배경 사진도 크기 0 이라 안 보입니다
- 예약 등록 마법사와 모든 팝업도 화면을 못 덮습니다
- JS 오류가 아니므로 `window.onerror` 안내도 안 뜹니다. **조용히 깨집니다**

→ `top:0;right:0;bottom:0;left:0` 로 풀어 쓰면 끝입니다.

### 3-2. `gap` 폴백이 정작 대상 브라우저에서 발동하지 않습니다 【코드 확인 · 치명】

```js
2198: @supports not (gap: 1px){ ... }
```

- `gap` 이 **그리드용으로는 크롬 66** 부터 파싱됩니다
- **flexbox 의 gap 은 크롬 84** 부터입니다

따라서 **크롬 66~83 구간에서 `@supports (gap:1px)` 가 참**이 되어 폴백이 적용되지 않습니다. 그런데 flex gap 은 동작하지 않습니다.

파일에 `gap` 선언이 166곳, 그중 flex 와 같은 규칙에 쓴 것이 108곳입니다. 그 구간의 TV 에서 **간격이 전부 0** 이 됩니다 — 디스플레이 모드의 예약 줄과 룸 카드가 서로 붙습니다.

### 3-3. `clamp()` 폴백이 5개만 감싸져 있습니다 【코드 확인】

`clamp()` 는 크롬 79 부터입니다. 파일에 34곳, 그중 TV 화면에 30곳이 몰려 있는데 폴백 블록은 5개만 다룹니다. 나머지는 크롬 79 미만에서 선언 자체가 버려져 **여백과 줄 간격이 전부 0** 이 됩니다.

### 3-4. `env()` 폴백 없음 — 크롬 69 미만 【코드 확인】

```css
291: .sheet{ padding:18px 16px calc(24px + env(safe-area-inset-bottom)) }
```

크롬 69 미만에서는 `calc()` 전체가 무효가 되어 **padding 선언이 통째로 폐기**됩니다. 모든 팝업의 안쪽 여백이 0 이 되어 글자가 테두리에 붙습니다. 앞에 폴백 한 줄만 두면 됩니다.

### 3-5. `window.onerror` 가 목표한 오류를 못 잡습니다 【코드 확인】

`<script>` 블록이 파일 전체에 **하나**입니다. 구형 문법이 들어가면 그 블록 전체가 파싱 단계에서 실패하므로 `window.onerror` 대입 자체가 실행되지 않습니다. 안내 화면도 안 뜨고 그냥 흰 화면입니다.

→ `window.onerror` 를 앞쪽 **별도 `<script>` 태그**로 빼야 의도대로 동작합니다.

### 3-6. `build.py` 에 CSS 검사를 추가해야 합니다

지금 검사: `?.` `??` `structuredClone` `.flat(` `.replaceAll(` — **JS 5종뿐**.

추가할 것: `inset:` · flex `gap` · `@supports` 밖의 `clamp(` · 폴백 없는 `env(` · `accent-color` · `:focus-visible` · `:is(` · `:has(` · `aspect-ratio` · `backdrop-filter` · `dvh/svh/lvh`, 그리고 JS 쪽 `.at(` `Object.fromEntries` `.flatMap(` `||=` `&&=` `??=` `catch{}` `findLast` `Object.hasOwn` `matchAll` `globalThis` `Promise.allSettled`.

**안 하면 3-1~3-4를 고쳐도 다음 수정에서 되돌아옵니다.**

## 6. 기능 부족 — 실제 운영에서 걸립니다

### 6-1. 전화가 끊겨 이름만 받았다 → 저장할 수 없습니다

새 예약을 만드는 길은 **7단계 마법사 하나뿐**입니다. 단계마다 통과 조건이 있고, 등록 버튼에서 날짜·시간·인원을 다시 검사합니다.

한 화면짜리 폼(`sheetRes`)은 "새 예약" 제목을 그릴 준비까지 돼 있는데 **`openRes()` 를 인자 없이 부르는 버튼이 없습니다.** 사실상 사장된 코드입니다.

지금 직원은 종이에 적거나, 시간·인원·좌석·메뉴를 지어내 저장하고 나중에 고칩니다. **지어낸 값이 그동안 타임라인에서 실제 자리를 3시간 잡아먹습니다.**

→ `openRes()` 를 "빠른 접수" 버튼으로 노출. **작은 작업**이고 6-2도 같이 풀립니다.

### 6-2. 워크인 손님을 넣으려면 14번을 눌러야 합니다

워크인 전용 입구가 없어 마법사로 예약을 하나 만들어야 합니다. 오늘·지금·2명·홀·연락처 없음 기준으로 **약 14탭 + 이름 입력**.

손님이 입구에 서 있는데 그걸 하기 어려워 안 넣게 되고, 그러면 **타임라인이 실제보다 비어 보여 전화 예약을 과다 수락합니다.**

### 6-3. 같은 손님이 여러 날 예약하면 매번 처음부터

등록 완료 화면의 "추가 예약" 버튼이 `openWizard()` 를 부르는데, 이 함수가 `WZ` 를 통째로 새로 만듭니다. 넘어가는 건 날짜 하나뿐이라 **이름·전화번호를 3일치면 3번** 칩니다. 그 사이 오타가 나면 노쇼 집계와 검색이 어긋납니다.

→ name/phone/allergy/people/source 를 유지한 채 날짜 단계로 보내면 됩니다. **작은 작업**.

### 6-4. 취소된 자리에 넣을 대기 손님을 기록할 곳이 없습니다

`"대기"` 라는 개념이 코드에 없습니다. 취소 전화를 끊는 순간 "6시에 동탁 비었다"를 아는 곳은 직원 머리와 종이뿐입니다. "자리 나면 연락 주세요" 한 손님은 예약 검색으로도 못 찾습니다.

### 6-5. 늦게 온다는 연락을 기록할 곳이 없습니다

상태는 `확정 / 방문 / 취소 / 노쇼` 4개뿐입니다. 요청사항에 적으면 목록에는 "요청" 알약만 뜨고 **내용은 마우스를 올려야 보입니다 — 태블릿에서는 사실상 안 보입니다.**

시간을 실제로 고치면 체류 시간이 통째로 밀려 뒤 예약과의 판정이 왜곡됩니다.

### 6-6. 종이로 뽑을 수 없습니다

`window.print` · `@media print` 가 **0건**입니다. 브라우저 인쇄를 눌러도 타임라인은 스크롤 컨테이너 안이라 잘리고 예약 목록은 접혀 있습니다. 디스플레이 모드로 대신할 수도 없습니다 — 이름을 가리고 코스·알러지가 안 나옵니다.

→ 오늘 예약을 시각순 표로 뽑는 `@media print` 섹션. 데이터는 이미 다 있습니다. **작은 작업**.

### 6-7. 20명을 두 룸에 나눠 받을 수 없습니다

한 예약은 좌석을 하나만 가집니다. 두 건으로 쪼개면 중복 예약 경고가 매번 뜨고, 취소 전화가 오면 두 건을 각각 찾아 취소해야 하며 한쪽을 잊으면 룸이 잠긴 채 남습니다.

→ 근본 해결은 큽니다. **현실적 대안(작음)**: 예약에 `groupKey` 를 붙여 두 건을 묶고 상세에서 "연결 예약"으로 함께 보여주기 + 취소 시 같이 물어보기.

### 6-8. 손님 이력이 집계되지 않습니다

검색은 잘 됩니다 — 전 기간, 이름 2자·번호 4자리부터, 010 빼고 비교, 최신순. 전화 응대에 잘 맞습니다.

없는 것은 **집계**입니다. "이 손님 5회 방문, 주로 초선" 같은 요약이 없어 직원이 목록을 눈으로 세야 합니다. 그리고 **마법사 안에서는 과거 이력을 볼 수 없습니다** — 확인하려면 마법사를 닫아야 하고, 닫으면 입력한 내용이 사라집니다.

### 6-9. 명절 대비가 약합니다

- 공휴일을 **하루씩** 등록합니다. 설 연휴 5일이면 5번, 매년 반복
- 임시 휴무·단축도 하루씩입니다 (기간제는 좌석 사용 중지만)
- **하루 총량 제한이 전혀 없습니다.** 저녁 6시에 단체 4팀이 몰려도 시스템은 조용합니다

### 6-10. 인수인계 문서와 코드가 어긋난 곳

- "월간 캘린더 없음" → **있습니다** (`renderCal`, 상단 날짜를 누르면 열림). 날짜별 건수와 예약률 막대까지 나옵니다
- 화면 배율 "기본 125% / 100·110·125·150%" → 실제는 `[100,105,110,120,135]`, 기본 110

## 7. 죽은 코드

- **주석 처리된 블록 366줄** (매출 99+65+46, 직원·근태 114+30) — 파일의 5%. 검색할 때마다 걸립니다
- **호출되지 않는 함수 14개** — 특히 `renderRes()`(58줄)는 `renderResList()` 와 필터바 로직이 거의 같아, 필터를 고칠 때 어느 쪽이 진짜인지 헷갈립니다
- **세로 화면 미리보기 CSS 약 86줄** — 세 겹으로 쌓여 있는데 `.tv-note` · `.tv-zoom` · `.tv.zoomed` 가 HTML/JS 어디에서도 만들어지지 않고, 뒤의 `@media(max-width:900px)` 가 통째로 숨깁니다. **어떤 화면 크기에서도 적용되지 않습니다**
- **미사용 CSS 클래스 약 55개** — `.topnav`, `.ratecard`, `.fab`, `.stepper`, `.dash2` 등
- 요일 배열이 **8벌** — 한 곳만 고치면 화면마다 표기가 달라집니다

## 8. 접근성

- **aria-label 이 9개뿐** — 인원 `−`/`＋`, 유아 `−`/`＋`, 유아의자 `−`/`＋` 가 전부 같은 기호라 라벨 없이는 구분 불가
- **타임라인 경고 예약이 색으로만 표시됩니다** — `잠정` 은 글자와 title 에 다 있는데 `경고` 는 벽돌색 배경뿐입니다. `resWarn(r)` 로 사유를 이미 계산해 놓고 title 에 안 넣습니다. **마우스를 올려도 왜 경고인지 알 수 없습니다** → `title` 에 `resWarn(r).join(", ")` 붙이기, 한 줄
- 키보드만으로는 사실상 조작 불가 — 모든 버튼이 `render()` 를 불러 포커스가 매번 초기화되고, 마법사에 포커스 트랩이 없어 뒤 화면 요소가 전부 탭 순서에 남습니다
