# 디자인 개편 — 애플식으로

작성일: 2026-09-01
목적: 관리 화면(직원이 만지는 화면)을 애플식으로 다시 정리
읽는 사람: Claude Code

---

## 0. 결정된 것

| | 결정 |
|---|---|
| **작업 폴더** | **`v2/` 안에서만.** 원본(v1)은 링크가 이미 나가 있어 읽기 전용입니다 |
| **범위** | **관리 화면만.** 대시보드 · 예약 · 설정 · 마법사 · 팝업 · 잠금 · 매장 선택 |
| **손대지 않을 것** | **손님용 디스플레이 모드(`.tv*`, `.dsec*`)와 인트로(`.intro*`)** |
| **색** | 새 팔레트를 제안받아 고른다 (아래 3장) |

### 왜 디스플레이·인트로는 빼는가

그 둘은 **손님이 보는 화면**이고, 한옥반점의 정체성(명조체·한지색·창살 무늬)을
일부러 넣은 곳입니다. 관리 화면과 같은 무채색으로 만들면 가게 브랜드가 사라집니다.

**직원이 만지는 화면 = 도구 → 애플식(빠르고 안 헷갈리게)**
**손님이 보는 화면 = 간판 → 한옥(분위기)**

두 언어가 한 파일에 공존하는 게 맞습니다. 섞지 마세요.

## 1. 시작하기 전에 — CSS 통합이 먼저입니다

**이 단계를 건너뛰면 디자인 작업 내내 CSS 우선순위와 싸우게 됩니다.**

### 지금 상태

| | 수치 |
|---|---|
| CSS | 약 2,500줄 / 규칙 약 1,230개 |
| **3번 이상 재정의된 셀렉터** | **75개** |
| 최다 | `.tl-name` 13번 · `.tv` 8번 · `.tl-rate` 8번 · `.bdate` 7번 |
| `@media` | 61개 |

요청이 올 때마다 파일 끝에 덮어쓰기 블록을 붙여 온 결과입니다.
`.tl-name` 의 최종 모습을 알려면 **13군데를 다 읽고 순서를 따져야** 합니다.

### Phase 0 — 통합 (디자인 변경 없이)

**화면이 1픽셀도 바뀌지 않아야 합니다.** 이게 이 단계의 합격 기준입니다.

1. 셀렉터별로 흩어진 정의를 한 곳으로 모읍니다.
   - 합치기 전후로 **같은 폭에서 스크린샷을 찍어 비교**하세요. 픽셀이 달라지면 되돌립니다.
   - 순서가 의미를 갖는 곳이 있습니다(뒤가 앞을 덮는 게 의도인 경우). 함부로 재배열하지 마세요.
2. CSS 를 구역으로 나누고 각 구역 앞에 무엇인지 주석을 답니다.

```
1. 토큰 (:root)
2. 리셋 · 기본 타이포
3. 공통 부품 (버튼 / 입력 / 카드 / 태그 / 배지)
4. 레이아웃 (상단바 / shell / content)
5. 대시보드 (지표 / 타임라인 / 목록 / 확인 필요)
6. 예약 — 마법사 / 시트 / 모달
7. 설정
8. 잠금 · 매장 선택
9. 손님용 화면 (.tv / .dsec / .intro)  ← 이번에 안 건드림
10. 반응형 (@media 모아두기)
```

3. `@media` 61개 중 같은 조건끼리 합칩니다. 지금은 `max-width:900px` 가 여기저기 흩어져 있습니다.
4. 죽은 규칙을 지웁니다 (`.sp-b` 처럼 이미 안 쓰는 것들).

**Phase 0 을 끝내고 커밋한 뒤에 Phase 1 로 가세요.** 한 커밋에 섞지 마세요.
섞으면 "디자인이 이상해졌는지, 합치다가 깨졌는지" 구분이 안 됩니다.

## 2. 애플식이란 무엇인가 — 이 프로젝트 기준

"애플 같다" 는 말이 사람마다 다르므로 여기서 뜻을 못 박습니다.

### 지킬 것

| 원칙 | 이 화면에서는 |
|---|---|
| **여백이 정보다** | 지금 카드가 빽빽합니다. 안쪽 여백을 키우고 요소 사이를 벌립니다 |
| **위계는 크기·굵기·색으로, 선으로 하지 않는다** | 지금 실선(`--border`)이 너무 많습니다. 절반은 여백으로 대체 가능 |
| **간격을 하나의 계단으로** | 4의 배수로 통일 (4·8·12·16·24·32·48). 지금은 6·7·9·11·13px 이 섞여 있습니다 |
| **글자 크기도 계단으로** | 지금 10.5 / 11.5 / 12.5 / 13.5 / 14.5px 이 섞여 있습니다. 5~6단으로 줄입니다 |
| **누를 수 있는 것은 44px 이상** | 카운터에서 손가락으로 씁니다. 지금 일부 버튼이 30px대입니다 |
| **모서리 반경도 계단으로** | 지금 2·3·4·5·8·9·10·12·16px 이 섞여 있습니다. 3단(6/10/16)으로 |
| **그림자는 최소** | 카드 경계는 아주 옅은 선 하나로 충분합니다 |
| **한 화면에 강조색 하나** | 지금 초록·벽돌·호박·파랑이 동시에 뜨는 화면이 있습니다 |

### 하지 말 것

- **`backdrop-filter` 유리 효과** — 구형 TV 에서 안 되고, 이 화면은 정보 밀도가 높아 안 어울립니다
- **애니메이션 남발** — 전화 받으면서 쓰는 화면입니다. 기다리게 하면 안 됩니다
- **아이콘만 남기기** — 사장님은 아이콘 뜻을 모릅니다. **글자를 지우지 마세요**
- **회색 위의 연회색 글씨** — 카운터 태블릿은 밝은 조명 아래 있습니다. 대비를 낮추지 마세요
- **정보 줄이기** — 여백을 만든다고 표시를 빼면 안 됩니다. 이건 도구입니다

### 한국어 타이포

- 본문은 이미 `Pretendard` → `Noto Sans KR` → `Apple SD Gothic Neo` 순입니다. 유지하세요.
- **웹폰트를 새로 불러오지 마세요.** 이 파일은 오프라인·구형 TV 에서도 떠야 합니다.
- 한글은 라틴보다 크게 보여야 합니다. 영문 기준 크기를 그대로 쓰면 작아 보입니다.
- `letter-spacing` 은 한글에서 음수로 주지 마세요. 자간이 무너집니다.

## 3. 색 — 제안을 받아서 고릅니다

### 지금 팔레트

```css
--bg:#F5F4EF          /* 한지 크림 */
--surface:#FFFFFF
--surface-2:#FAFAF8
--border:#E3E2DC  --border-strong:#CFCDC4
--text:#1B1B19  --text-2:#5F5E58  --text-3:#8E8C84
--pine:#1E4A3C        /* 소나무 초록 — 확정·주요 버튼 */
--amber:#8A6114       /* 주의 */
--rust:#9C3B27        /* 경고 */
--blue:#1F4E79        /* 당일 변동 표시 = 사장님의 '파란 펜' */
```

### Claude Code 가 할 일

**팔레트 3안을 만들어 실제 화면에 입혀 보고, 스크린샷으로 비교해서 제안하세요.**
색상표만 보여주면 판단이 안 됩니다. 대시보드 한 화면에 적용한 그림이 있어야 합니다.

제안할 세 방향(예시이고, 더 나은 안이 있으면 바꿔도 됩니다):

1. **따뜻한 뉴트럴** — 크림기를 아주 살짝 남긴 회색. 지금과 이어지되 정돈된 느낌
2. **차가운 뉴트럴** — iOS 설정 앱에 가까운 순회색 + 파랑 액센트
3. **뉴트럴 바탕 + 한옥 액센트** — 배경·카드는 무채색, 강조색만 소나무 초록/벽돌색 유지

### 색에서 반드시 지킬 것

| | 이유 |
|---|---|
| **파란색(`--blue`)의 뜻을 바꾸지 마세요** | 사장님이 수기 장부에서 쓰던 **'파란 펜'** 을 옮긴 것입니다. 당일 변동 표시 전용입니다. 이걸 액센트/링크 색으로 쓰면 뜻이 무너집니다 |
| **경고는 빨강, 주의는 호박** | 이미 몸에 익은 구분입니다 |
| **본문 대비 4.5:1 이상** | 밝은 조명 아래 태블릿입니다 |
| **초록·빨강만으로 구분되는 표시를 만들지 마세요** | 색약 대응. 지금은 모양·글자도 함께 다릅니다 |

## 4. 순서

| Phase | 할 일 | 끝났다는 기준 |
|---|---|---|
| **0** | CSS 통합·구역화 | **화면이 1픽셀도 안 바뀜** |
| **1** | 토큰 정리 — 간격/글자/반경 계단 | 하드코딩 px 이 거의 없음 |
| **2** | 색 팔레트 3안 → 스크린샷 비교 → 재아가 고름 | 고른 안이 토큰에 반영됨 |
| **3** | 공통 부품 (버튼/입력/카드/태그) | 같은 종류가 전부 같아 보임 |
| **4** | 화면별 — 대시보드 → 예약/마법사 → 설정 | 한 화면씩 커밋 |
| **5** | 반응형 재점검 (430 / 820 / 1280 / 1920) | 네 폭 스크린샷 |

**한 Phase 끝날 때마다 커밋하고 스크린샷을 남기세요.**
되돌릴 지점이 없으면 "예전이 나았는데" 를 확인할 방법이 없습니다.

## 5. 손대면 깨지는 것들 — 디자인 작업 중 특히 조심

`docs/인수인계.md` 5장에 전부 있습니다. 그중 **CSS 와 직접 얽힌 것만** 여기 옮깁니다.

### 5-1. 타임라인 좌석 이름 열 (`.tl-name`) — 13번 재정의됨

가로 스크롤할 때 왼쪽에 고정되는 흰 열입니다. 두 가지가 걸려 있습니다.

- `align-self:stretch` — 없으면 이름 칸 높이가 글자 높이밖에 안 돼서
  줄이 높은 좌석(테이블 11개짜리 홀)에서 위아래로 그래프가 비칩니다
- `box-shadow:-26px 0 0 var(--surface)` — `.tl-scroll` 이 좌우로 삐져나와 있어서
  고정 열 왼쪽에 틈이 남습니다. 그림자로 그 틈을 칠합니다
  (가상요소로 하다가 좌표가 계속 어긋나서 이 방식으로 바꿨습니다)

**모바일 430px 에서 가로로 밀어 보고 흰 열이 끊기지 않는지 반드시 확인하세요.**

### 5-2. 디스플레이 모드 크기 단위 (`--tvu`)

`--tvu:1vh` 를 기준으로 모든 크기를 배수로 씁니다. **`clamp()` 로 되돌리지 마세요.**
clamp 의 상한 때문에 화면이 커질수록 글자가 상대적으로 작아집니다.
(이번 개편 범위 밖이지만, 토큰을 정리하다가 건드리기 쉬운 곳입니다)

### 5-3. 폴백은 반드시 `@supports` 로 감싸거나 앞쪽에 두세요

CSS 는 우선순위가 같으면 뒤가 이깁니다. 파일 끝에 둔 "구형 브라우저용 기본값" 이
모든 브라우저에서 앞의 값을 덮어쓴 사고가 실제로 있었습니다.

### 5-4. 배율(`zoom`)이 걸린 요소

`.shell` `.lock` `.modal-ov` 에 `zoom:var(--ui-zoom, 1.1)`.
`.modal-ov` 는 `.shell` **밖**에 그려져서 따로 걸어 준 것입니다.
시트·마법사·달력은 `.shell` 안에 있어 여기서 또 걸면 배율이 두 번 곱해집니다.

### 5-5. 흉내 표시를 지우지 마세요

`.mockbar` `.sb-mock` `.lk-open` — "문자는 실제로 안 나갑니다",
"PIN 이 열려 있습니다" 를 알리는 표시입니다. 디자인상 거슬려도 **없애면 안 됩니다.**
사장님이 "문자 보냈겠지" 하고 확인 전화를 안 하시면 그게 사고입니다.

## 6. 확인 방법

브라우저를 띄워 **직접 보세요.** 추측하지 마세요.

```
430px    폰 — 타임라인 가로 스크롤, 마법사 7단계
820px    태블릿 세로
1280px   노트북 — 주 사용 환경
1920px   PC / TV
```

각 폭에서 봐야 할 화면:

- 대시보드 (지표줄 / 타임라인 / 예약 목록 / 확인 필요)
- 예약 등록 마법사 7단계 전부
- 예약 상세 시트 (문자 칸 포함)
- 설정 폴드 10개 (특히 좌석·코스 구성처럼 복잡한 것)
- 잠금 화면 · 매장 선택

**바꾸기 전후 스크린샷을 나란히 두고** "정말 나아졌나" 를 스스로 물어보세요.
여백만 늘리고 정보를 덜어낸 화면은 예뻐 보이지만 도구로서는 나빠집니다.
