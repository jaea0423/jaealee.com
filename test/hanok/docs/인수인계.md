# 한옥반점 예약 관리 시스템 — 인수인계

이 문서 하나로 프로젝트를 이어서 작업할 수 있게 정리했습니다.
새 대화나 Cowork에서 시작할 때 이 파일을 먼저 읽으면 됩니다.

작성일: 2026-08-30

---

## 1. 프로젝트 개요

- **무엇**: 고모가 운영하는 식당 두 곳(한옥반점·안집)의 예약 관리 시스템
- **누가 만듦**: 재아 (개발 전담, 무상 제작)
- **누가 씀**: 사장님(고모)과 홀 직원
- **현재 상태**: 한옥반점만 구현 완료. 안집은 화면만 있고 비활성
- **형태**: HTML 파일 하나 (CSS·JS·이미지 전부 내장, 약 1.3MB)

### 쓰이는 환경
| 기기 | 용도 | 우선순위 |
|---|---|---|
| 카운터 태블릿 | 전화 예약 접수 (주 사용처) | 1 |
| 사장님 휴대폰 | 확인·수정 | 2 |
| TV·모니터 | 손님용 안내 화면 (`/screen`) | 3 |
| PC | 가끔 | 4 |

## 2. 파일 구조

작업 폴더에 이렇게 두면 됩니다.

```
hanok/
├── src/
│   └── index.html          # 자리표시자 버전 (__BG1_B64__ 등)
├── assets/
│   ├── anjip.b64           # 안집 배경 사진
│   ├── hanok.b64           # 한옥반점 배경 사진
│   └── bg1.b64 ~ bg7.b64   # 디스플레이 모드 배경 7장
├── build.py                # 자리표시자에 이미지를 넣어 최종 파일 생성
├── dist/
│   └── hanok-admin.html    # 배포용 최종 파일
├── index.html              # 사이트(jaealee.com/test/hanok)로 올라가는 파일
│                           #   build.py 가 dist 와 같은 내용으로 함께 만듭니다
└── docs/
    ├── 인수인계.md          # 이 문서
    └── 검토사항.md          # 사장님께 확인받을 목록
```

**주의**: 지금까지는 자리표시자 버전(`v2.html`)을 고치고, 마지막에 이미지를 넣어
최종 파일을 만드는 방식으로 작업했습니다. **최종 파일을 직접 고치면 안 됩니다.**
1.3MB짜리 base64 덩어리 때문에 편집이 사실상 불가능합니다.

빌드 방법:
```python
html = open('src/index.html', encoding='utf-8').read()
subs = [('__ANJIP_B64__','anjip.b64'), ('__HANOK_B64__','hanok.b64')] + \
       [(f'__BG{i}_B64__', f'bg{i}.b64') for i in range(1,8)]
for key, f in subs:
    html = html.replace(key, open('assets/'+f).read())
open('dist/hanok-admin.html','w',encoding='utf-8').write(html)
```

## 3. 데이터 구조

브라우저 저장소(`window.storage`)에 JSON 하나로 저장됩니다. 현재 약 410KB.

```
DATA
├── _auth      { pin, admin }                 ← PIN·관리자 비밀번호 (평문! 3.5 참고)
├── _session   { authed, since }              ← 새로고침해도 로그인 유지
├── _ui        { theme, zoom }                 ← 화면 배율 (5.10 참고)
├── _logs      [ {ip, at, action, detail, ua} ]  ← 최근 3000건
├── hanok
│   ├── name, enabled
│   ├── reservations [ ... ]                  ← 예약 (아래 참고)
│   └── settings { ... }                      ← 설정 (아래 참고)
└── anjip      (같은 구조, enabled:false)
```

### 예약 한 건
```js
{
  id, date, time,                 // "2026-08-30", "19:00"
  name, phone,
  people,                         // 총 인원 (유아 포함)
  infants,                        // 그중 유아
  chairs,                         // 유아용 의자 개수
  roomId,                         // 배정된 좌석 (없으면 null)
  seatPref,                       // "room-any" | "hall-any" | "any" | null
  tentativeRoomId,                // 시스템이 잡아 둔 잠정 자리
  assignedLater,                  // 미배정 → 배정된 이력
  source, sourceDetail,           // 예약 경로
  menuType,                       // "코스" | "코스 상당" | "확인 필요" | "해당 없음"
  courses,                        // { "0|촉": 2, ... }  키는 "행번호|항목명"
  courseUndecided,                // 코스는 하지만 구성 미정
  request, allergy, allergyChecked,
  changes,                        // 변동 이력 (5.14 참고)
  status,                         // "확정" | "방문" | "취소" | "노쇼"
  auto,                           // 자동으로 방문 처리된 건
  createdAt, demo
}
```

### 설정
```js
settings: {
  rooms: [                        // 룸과 홀을 한 배열에. 순서 = 배정 우선순위
    { id, name, type:"room", capacity, minCapacity, floor, blocks:[ ... ] },
    { id, name, type:"hall", floor, zones:[ ... ], blocks:[ ... ] }
    // blocks = 사용 중지 기간 (5.9 참고). 옛 blocked/blockNote 는 migrate 에서 옮겨집니다
  ],
  schedules: [                    // 운영시간. 적용 시작일별로 여러 벌
    { from:"2000-01-01", days:[7개], holiday:{...} }
  ],
  overrides: [ {date, closed, open, close, bs, be, lo, note} ],  // 임시 휴무·단축
  holidays: [ "2026-09-16", ... ], holidayMode, holidayAsWeekend,
  courseGroups: [ {label, items:[], when:[]} ],
  sources: [ "전화", "네이버예약", "기타" ],
  displayRows: [ [id...], [id...], [id...] ],   // TV 화면 3줄 배치
  stayHours, lunchStayHours, hallStayHours, hallLunchStayHours, lunchUntil,
  lastBookingBuffer, breakMode, breakEntryBuffer,
  minCountAdultsOnly, groupSize, tableSeats
}
```

### 홀의 존(zone) 구조 — 가장 중요한 개념
```js
zones: [
  { name:"창가",   sets:[{seats:2,count:2},{seats:4,count:2}], maxJoin:2 },
  { name:"가운데", sets:[{seats:4,count:6}],                   maxJoin:4 },
  { name:"단체석", sets:[{seats:6,count:1}],                   maxJoin:1 }
]
```
- **같은 존 안에서만** 테이블을 붙일 수 있음
- `maxJoin` = 한 번에 붙일 수 있는 테이블 수
- 창가는 2+4=6명, 4+4=8명 등 조합이 자동 계산됨 (`zoneCombos()`)
- "1,2,3은 붙는데 1,3은 안 됨" 같은 세밀한 조합은 표현 못 함 → 검토사항 3장

## 4. 핵심 함수 지도

| 함수 | 하는 일 |
|---|---|
| `render()` | 전체 화면을 다시 그림. 상태가 바뀌면 무조건 이걸 호출 |
| `hoursFor(date)` | 그 날짜의 운영시간 (요일별 + 공휴일 + 임시 일정 반영) |
| `stayMinAt(time, seatId)` | 체류 시간 (룸/홀 × 점심/저녁) |
| `dayStat(date)` | 예약률 계산. `roomShare + hallShare = rate` |
| `hallStatus(...)` | 그 시각 홀의 테이블 사용 현황 |
| `pickTables(free, people)` | 남은 테이블로 이 인원을 앉힐 조합 찾기 |
| `suggestSeat(...)` | 좌석 미정 예약에 잡아 둘 자리 추천 |
| `reflowTentatives(date)` | 예약이 바뀔 때 잠정 배정을 다시 계산 |
| `timeWarn(date, time)` | 그 시각에 예약하면 생기는 문제 |
| `resWarn(r)` | 예약 한 건의 경고 사유 목록 |
| `changeTag(r)` | 당일 변동 표시 (5.14) |
| `diffRes(a,b)` | 두 예약을 비교해 바뀐 항목만 |
| `blockSpans(room, date)` | 그 날짜에 좌석이 잠기는 구간들 (5.9) |
| `blockedAt(room, date, time)` | 그 시각에 좌석이 잠겼는지 |
| `blockHits(room, draft)` | 입력 중인 중지 기간에 걸리는 예약 |
| `fitDisplay()` | 디스플레이 모드 글자 크기 자동 맞춤 (5.8) |
| `autoCloseDays()` | 지난 확정 예약을 자동으로 '방문' 처리 |
| `noshowList()` | 전화번호로 노쇼 집계 (별도 저장 없음) |
| `draft()` / `applySettings()` | 설정 임시본. '적용하기'를 눌러야 반영 |

### 화면 함수
`renderSelect` → `renderLock` → `renderStore`(`renderDash` / `renderSettings`) → `renderDisplay`
팝업은 전부 `renderSheet()` 안의 `inner` 객체에 등록되어 있음.

## 5. 설계 결정과 이유

이유를 모르면 되돌리기 쉬운 것들입니다.

### 5.1 '방문'을 자동 처리하는 이유
매번 직원이 눌러야 하면 아무도 안 누르고 데이터가 썩습니다.
**손님은 왔다를 기본으로 두고, 예외(노쇼·취소)만 누릅니다.**
지난 날짜의 확정 예약은 자동으로 '방문'이 되고, 확인 필요에
"어제 예약 15건 중 15건 자동 방문 처리"가 떠서 수정할 수 있습니다.

### 5.2 경고는 막지 않고 알리기만 함 — **예외 없음** (2026-08-30 강화)
사장님이 판단할 일을 시스템이 막으면 안 됩니다.
라스트오더 이후, 브레이크타임, 최소 인원 미달, 룸인데 코스 아님 등
모두 빨갛게 표시하고 확인 팝업을 띄우지만, 누르면 그대로 진행됩니다.
접수된 경고 예약은 대시보드 '경고 예약' 지표에 남습니다.

**룸에 1시간 안에 확정 예약이 있는 경우만 유일하게 진짜로 막고 있었는데,
2026-08-30 에 이것도 경고로 바꿨습니다.** 이유:
취소를 깜빡해 지난 예약이 남아 있는 채로 손님과 통화 중인 상황이 실제로 생깁니다.
그때 시스템이 막아버리면 전화를 끊고 정리한 뒤 다시 걸어야 합니다.

대신 겹쳐 받은 예약은 **접수 뒤에도 계속 보입니다.**
`resWarn()` 이 `좌석 겹침` 을 붙여서 대시보드 '경고 예약'과 '확인 필요'에 남고,
타임라인 블록도 빨갛게 표시됩니다. 나중에라도 정리할 수 있게 하려는 것입니다.
(겹친 두 건 모두에 표시됩니다 — 어느 쪽이 취소돼야 할 예약인지는 시스템이 모릅니다)

### 5.3 예약률이 낮아 보이는 이유
룸 8개 + 홀 21테이블 = 29자리 기준의 **가중 평균**입니다.
룸 43%, 홀 10%면 전체는 (43×8 + 10×21) ÷ 29 = 19%.
홀 테이블이 많아 홀 쪽으로 당겨집니다. 그래프는 룸·홀을 쌓은 막대로 그려
쌓인 높이가 곧 전체 예약률이 되게 했습니다.

### 5.4 운영시간에 '적용 시작일'을 두는 이유
시간을 그냥 바꾸면 과거 예약률 계산이 전부 틀어집니다.
`schedules` 배열에 시작일별로 보관하고, `hoursFor(date)`가 그 날짜에 맞는 걸 고릅니다.

### 5.5 PIN이 평문임 (반드시 고쳐야 함)
`DATA._auth`에 그대로 들어 있어 개발자도구로 볼 수 있습니다.
지금은 프로토타입이라 넘어갔지만 **배포 전에 서버 검증으로 바꿔야 합니다.**

### 5.6 구형 스마트TV 대응
TV 브라우저는 2018~2020년 크롬에서 멈춰 있어 최신 문법을 못 읽습니다.
`?.`, `??`, `structuredClone`, `.flat()`을 전부 제거했습니다.
**앞으로 코드를 고칠 때도 이 문법들을 쓰면 안 됩니다.**
`@supports not (gap:1px)` 폴백과 `window.onerror` 안내 화면도 넣어 뒀습니다.

### 5.7 코스 선택 팝업을 마법사와 수정 시트가 같이 씀 (2026-08-30 추가)
예약 등록 마법사는 `WZ`, 예약 수정 시트는 `tmpRes` 라는 서로 다른 임시 객체를 씁니다.
코스 선택 팝업을 두 벌 만들면 나중에 한쪽만 고치는 사고가 나므로,
**어느 쪽을 고칠지 `cTgt()` 한 곳에서만 정하도록** 했습니다.

```js
function cTgt(){ return WZ ? WZ : tmpRes; }   // 마법사가 열려 있으면 WZ, 아니면 수정 시트
function cSync(){ if(!WZ && tmpRes) syncRes(); }  // 시트일 때만 입력창 값을 먼저 옮겨 담음
```

- `openCourse / closeCourse / bumpCourse / resetCourse / toggleUndecided / courseCount / renderCourse`
  가 전부 `cTgt()` 를 통해 값을 봅니다.
- `cSync()` 가 필요한 이유: 시트는 화면을 다시 그릴 때 입력창을 새로 만듭니다.
  먼저 `syncRes()` 로 값을 옮겨 두지 않으면 치던 글자가 날아갑니다.
- 팝업은 `renderStore()` 에서 시트와 **형제로** 그립니다. 시트 안에 넣으면
  바깥 오버레이 클릭이 겹쳐 시트까지 같이 닫힙니다.
- 마법사와 수정 시트가 동시에 열리는 경우는 없어서 `WZ` 유무만으로 구분해도 안전합니다.

### 5.8 디스플레이 모드는 TV 기준으로 만든다 (2026-08-30 추가)
모니터에서 잘 보이는 화면이 업장 TV에서는 안 보입니다. 기준이 다릅니다.

- **시청 거리**: 3~5m. 모니터는 60cm. 같은 글자라도 체감 크기가 5배 이상 차이납니다
- **어두운 계조**: 업장 TV는 값이 싸서 어두운 색을 뭉갭니다(black crush).
  반투명 카드 위 글자는 뒤 사진이 바뀔 때마다 대비가 달라져 묻힙니다
  → **카드를 거의 불투명하게(93~95%)** 두고, 사진은 카드 바깥에서 보이게 했습니다
- **색이 아니라 밝기로 구분**: 탁한 금색(`#A9967A` 등)은 TV에서 배경과 붙습니다.
  밝기를 올린 값으로 바꿨습니다
- **가는 획**: 명조는 TV 샤프닝에서 획이 날아갑니다.
  제목·룸 이름만 명조로 남기고 시각·이름은 고딕 굵게로 바꿨습니다

**글자 크기 자동 맞춤 (`fitDisplay()`)**

1. 화면 전체가 들어가는 가장 큰 크기를 고릅니다 (`TV_SIZES`, 2.2vh → 2.0vh).
   화면 전체에 **한 값**만 씁니다 — 행마다 다르면 위아래가 따로 놀아 보입니다
   → **글자가 크거나 작다는 말이 나오면 `TV_SIZES` 첫 값(상한)만 바꾸면 됩니다**
2. 하한으로도 안 들어가면 글자를 더 줄이지 않고 칸마다 보이는 줄 수를 줄입니다
   (`capLists`) — 지난 예약부터 접고, 그래도 넘치면 늦은 시각부터 접으며 "외 N건"

**행은 내용만큼만 씁니다** (`.tv-row{flex:0 0 auto}` + `.tv-grid{justify-content:center}`).
행을 늘려 화면을 꽉 채우면, 예약이 1건인 칸도 큰 상자가 되고 그 안에 글자만 덩그러니 떠서
글자가 실제보다 커 보입니다. 남는 높이는 위아래 여백으로 두고 배경 사진이 보이게 합니다.

행이 가운데 정렬이라 넘칠 때 위로도 삐져나가므로, 높이 검사는 `scrollHeight` 대신
행 높이를 직접 더해 씁니다 (`gridContentH`).

**홀은 2열 그리드입니다.** `grid-template-rows` 를 실제 필요한 줄 수로 맞춰야 합니다.
6줄로 고정해 두면 예약이 적어도 빈 줄의 간격만큼 자리를 먹고,
목록을 접어도 열만 비고 높이가 안 줄어듭니다 (`reflowTwoCol`).

## 6. 지금 상태

### 구현된 것
- 예약 등록 7단계 마법사 (경로 → 날짜·시간 → 인원 → 좌석 → 메뉴 → 예약자 → 요청사항)
- 좌석 가동 타임라인 (룸 간트 + 홀 층별 배치, 클릭 시 상세)

### 5.9 좌석 사용 중지는 '기간'이다 (2026-08-30 전면 교체)
예전에는 `room.blocked` 켜짐/꺼짐 하나뿐이라 "내일 11시~4시 공사", "다음 주 내내 대관"
같은 실제 상황을 담지 못했습니다. 기간 배열로 바꿨습니다.

```js
room.blocks = [
  { id, from:"2026-09-01", to:"2026-09-01",
    fromTime:"11:00", toTime:"16:00",   // 비우면 하루 종일
    openEnded:false,                    // true 면 to 무시, '해제할 때까지'
    note:"에어컨 공사" }
]
```

여러 날 기간이면 **첫날은 fromTime 부터, 마지막 날은 toTime 까지, 사이에 낀 날은 하루 종일**
잠급니다. 이 규칙이 `blockSpans()` 한 곳에 들어 있고 나머지는 전부 여기를 통해 봅니다.

| 함수 | 하는 일 |
|---|---|
| `blockSpans(room, date)` | 그 날짜에 잠기는 구간들을 분 단위로 |
| `blockedAt(room, date, time)` | 그 시각(또는 그 날)에 잠겼는지 |
| `blockedAllDay(room, date)` | 하루가 통째로 잠겼는지 (줄 전체를 흐리게 할지) |
| `resBlocked(r)` | 예약 한 건이 중지 구간에 걸리는지 (체류 시간까지) |
| `blockHits(room, draft)` | 입력 중인 기간에 걸리는 확정 예약 목록 |

**화면 표시**
- 타임라인: 그 좌석 줄에만 벽돌색 빗금(`.blockband`) + 사유. 영업시간 밖 빗금과 같은 계열이되
  사람이 일부러 잠근 것이라 더 진합니다
- 빗금은 **예약 블록보다 뒤에** 그립니다(z-index 1). 앞에 두면 사유 글자가 예약을 가립니다
- 좌석 이름 칸에도 짧은 표시(`중지 N구간` / `하루 중지` / `일부 중지`)를 답니다.
  빗금 위 글자는 예약에 가릴 수 있지만 이름 칸은 항상 읽힙니다

**기존 예약 처리** — 막지 않습니다(5.2).
중지 기간에 예약이 있으면 설정 시트에서 목록을 보여주고, 누르면 그 예약으로 바로 갑니다.
그대로 진행하면 `resWarn()` 이 `사용 중지 좌석` 을 붙여 경고 예약으로 남습니다.

### 5.10 화면 배율 (2026-08-30 추가)

- **디스플레이 모드(`.tv`)에는 걸지 않습니다** — 거기는 vh 기준으로 따로 맞춥니다(5.8)

### 5.11 좌석을 잡고 있는 상태는 `holdsSeat()` 하나로 판정 (2026-08-30)
```js
function holdsSeat(r){ return r.status==="확정" || r.status==="방문"; }
```
'확정'은 앞으로 올 손님, '방문'은 지금 앉아 있는 손님 — 둘 다 자리를 씁니다.
'취소'와 '노쇼'는 자리를 비웁니다.

예전에는 이 판단이 다섯 갈래로 갈려 있었습니다.

| 곳 | 예전 | 증상 |
|---|---|---|
| `roomStatus` | `확정`만 | **손님이 도착해 '방문'을 누르면 그 룸이 빈 방이 됨** (이중 예약) |
| `hallStatus` | `취소`만 제외 | **노쇼 처리해도 테이블이 안 풀림** |
| `canRelocate` | 룸·홀이 한 함수 안에서 서로 다름 | |
| `dayStat` | `취소`만 제외 | 노쇼가 예약률에 잡힘 |

같은 버튼이 좌석 종류에 따라 정반대로 동작했습니다.
**새로 좌석 판정을 넣을 때는 반드시 `holdsSeat()` 를 쓰세요.**
타임라인과 예약률도 같은 기준을 씁니다 — 화면에 보이는 것과 시스템이 계산하는 것이 어긋나면 안 됩니다.

### 5.12 화면이 통째로 멈추지 않게 (2026-08-30)
`render()` 는 `app.innerHTML = ...` 한 줄입니다. 우변 계산 중 예외가 나면 **대입이 일어나지 않아**
화면이 직전 상태로 굳고, 이후 모든 클릭이 같은 예외로 죽습니다.
사용자 눈에는 "버튼을 눌러도 아무 일도 안 남" 으로만 보입니다.

```js
function render(){ try{ renderApp(); } catch(e){ showCrash(e); } }
```

`showCrash()` 가 화면 아래에 빨간 띠와 새로고침 버튼을 띄웁니다.
DOM 을 지우지 않으므로 사장님이 화면을 그대로 찍어 보낼 수 있습니다.

### 5.13 예약 수정에도 저장 전 검사 (2026-08-30)
마법사와 좌석 배정은 단계마다 물어보는데 **수정 화면만 아무것도 안 묻고 있었습니다.**
손님이 "6시를 7시로" 요청하면 이미 찬 방이어도 조용히 저장됐습니다.

`saveIssues(rec, excludeId)` 가 시간·사용중지·겹침·정원·최소인원·홀 자리를 모아 돌려주고,
수정 화면은 그 목록을 한 번에 보여준 뒤 확인을 받습니다. 막지는 않습니다(5.2).

### 5.14 변동 표시 — 사장님의 '파란 글씨' (2026-08-30)

사장님은 수기 장부에서 나중에 바뀐 예약을 **파란 펜**으로 표시해 왔습니다.
장부는 접수 순서대로 적히고 화이트보드는 영업 순서대로 다시 적는데,
종이 장부는 이미 쓴 줄을 고칠 수 없어 "이 줄은 검정 그대로 믿지 마라"는 표시가 필요했습니다.

**화면은 항상 최신값을 보여주므로 그 문제 자체는 없습니다.**
그대로 옮기면 이미 사라진 문제를 푸는 셈입니다. 그런데도 넣은 이유:

- **주방**은 여전히 최신이 아닙니다. 코스 수량을 구두로 넘긴 뒤 인원이 바뀌면 화면 어디에도 안 뜹니다
- 직원이 머리로 기억하는 자리 배치도 마찬가지입니다
- 그래서 남기는 것은 "값"이 아니라 **"무엇이 언제 바뀌었는지"** 입니다

**표시 조건은 '방문일 당일에 일어난 변동'입니다.**
어제 미리 바꾼 것은 오늘 아침에 이미 반영돼 있으므로 제외합니다.
날짜가 넘어가면 자연히 정리되므로 **따로 지우는 동작(확인 버튼)이 없습니다.**
지난 날짜를 열면 그날 무슨 일이 있었는지 기록으로 남습니다.

```js
r.changes = [
  { on:"2026-08-31",              // 그날 날짜(현지). at 만 쓰면 시차 때문에 어긋납니다
    at:"...ISO...",
    kind:"등록"|"변경"|"취소"|"노쇼",
    items:[{n:"인원", a:"4명", b:"6명"}] }
]
```

| 함수 | 하는 일 |
|---|---|
| `diffRes(old, new)` | 바뀐 항목만 뽑기. 대상은 `CHANGE_FIELDS` + 코스 |
| `addChange(rec, kind, items)` | 이력 한 줄 추가 (최근 40건까지) |
| `todayChanges(r)` | 방문일 당일 변동만 |
| `changeTag(r)` | 목록·타임라인에 붙일 짧은 표시 |
| `changeLines(r)` | 상세에 펼칠 전체 이력 |

**기록 지점 5곳** — 새 수정 경로를 만들면 여기에도 붙여야 합니다:
`saveRes`(수정·등록) · `setStatus`/`markRes`(취소·노쇼) · `assignSeat`(좌석) · `wzSubmit`(마법사 등록)

**'방문'은 변동으로 세지 않습니다.** 자동 처리라 매일 전부 표시되면 의미가 없어집니다.

**표시 규칙**
- 예약 목록: 오른쪽에 파란 태그 `변경 · 시간·인원` / `당일 접수` / `오늘 취소`
- 타임라인 블록: 왼쪽에 파란 세로 띠(`.blk.changed`). 경고(벽돌색 배경)와 겹쳐도 서로 안 가립니다
- 확인 필요: `오늘 변동 N건` 묶음. **취소·노쇼도 세야 하므로 확정 목록이 아닌 그날 전체에서** 셉니다
- 예약 상세: 몇 시에 무엇이 무엇으로 바뀌었는지 전부

**색만으로 구분하지 않습니다.** 업장 태블릿에서 파란 글씨는 잘 안 보이고 색맹이면 아예 안 보입니다.
그래서 무엇이 바뀌었는지 글자를 함께 넣었습니다.
`취소`는 상태 태그가 이미 옆에 붙으므로 `오늘 취소`로 적어 구분합니다 —
지난주에 취소된 건과 오늘 취소된 건은 대응이 완전히 다릅니다.

**디스플레이 모드에는 넣지 않았습니다.** 손님이 보는 화면이라 "변경됨"이 오해를 부릅니다.
디스플레이가 직원용 화이트보드를 대체하는 자리라면 여기에도 작은 표시를 넣을 수 있습니다.

### 5.15 타임라인 좌석 이름 열은 '한 줄짜리 라벨'이 아니라 '열'이다 (2026-09-01)

모바일에서 대시보드 그래프를 가로로 밀면 좌석 이름이 그래프 위에 둥둥 떠 보였습니다.
원인이 두 개 겹쳐 있었습니다.

1. **`.tl-name` 높이가 글자 높이밖에 안 됨.**
   `.tl-row` 가 `align-items:center` 라 이름 칸이 늘어나지 않았습니다.
   1층 홀처럼 테이블이 11개인 줄은 그래프 높이가 250px가 넘는데
   이름 칸은 30px밖에 안 되니, 흰 배경이 글자 주변에만 생기고
   위아래로는 그래프가 그대로 비쳤습니다.
   → `.tl-name{align-self:stretch}`
2. **고정된 열 왼쪽에 14px 틈.**
   `.tl-scroll{margin:0 -14px; padding:0 14px}` 로 그래프를 카드 밖까지
   내밀어 놨는데, `position:sticky; left:0` 은 그 14px 안쪽에서 멈춥니다.
   그 틈으로 스크롤된 그래프가 보였습니다.
   → 모바일에서 `padding-left:0`, 그리고 혹시 남는 틈은
     `box-shadow:-26px 0 0 var(--surface)` 로 한 번 더 칠합니다.

가상요소(`::before`)로 덮던 이전 방식은 지웠습니다.
`::before` 는 `left:-20px` 같은 좌표를 직접 계산해야 해서
행 높이나 padding 이 바뀔 때마다 어긋났습니다.
**box-shadow 는 좌표 계산 없이 요소 배경색을 그대로 왼쪽에 복사**하므로
행 높이가 얼마든 항상 정확히 붙습니다. 앞으로 고정 열을 덮을 일이 있으면 이 방식을 쓰세요.

곁들여 고친 것: `.tl-row.off-seat{opacity:.42}` 가 행 전체에 걸려 있어
사용 중지된 좌석 줄만 이름 열까지 반투명해지고, 그 줄에서 흰 열이 끊겨 보였습니다.
`opacity` 를 `.tl-track`·`.tl-rate` 에만 주고 이름은 글자색만 흐리게 바꿨습니다.

### 5.16 디스플레이 모드는 화면이 커져도 글자가 같이 커진다 (2026-09-01)

머리글·날짜·바닥글·나가기 버튼이 `clamp(15px, 2.3vh, 30px)` 같은 식이었습니다.
**clamp 의 세 번째 값은 상한입니다.** 화면이 커지면 `2.3vh` 가 30px 를 넘어서 30px 에 멈춥니다.
TV 가 크거나 브라우저 배율을 낮출수록 뷰포트는 커지므로, 글자는 30px 에 갇힌 채
화면만 커져서 **상대적으로 점점 작아 보였습니다.** '디스플레이 종료' 버튼은 13px 고정이라 더 심했습니다.

기준 단위 `--tvu` 를 하나 만들고 디스플레이 모드의 모든 크기를 그 배수로 적었습니다.

```css
.tv{--tvu:1vh}                                    /* 상한 없음 */
@media (max-aspect-ratio:4/3){ .tv{--tvu:.75vw} } /* 세로로 긴 화면은 가로 기준 */
@media (orientation:portrait) and (max-width:820px){ .tv{--tvu:7.2px} }
.tv-h h1{font-size:calc(var(--tvu) * 4.6)}
```

- 1080p 기준으로 기존 값과 거의 같게 맞췄으므로 지금 TV에서 보이던 크기는 그대로입니다.
- 화면이 두 배 커지면 글자도 정확히 두 배가 됩니다(1280×720 → 3840×2160 에서 3배 확인).
- **크기를 바꾸려면 파일 끝 블록의 숫자만** 고치면 됩니다. 예약 목록 글자만은 예외로
  자바스크립트의 `TV_SIZES` 첫 값입니다.
- 4:3 경계에서 `1vh = 0.75vw` 라 단위가 바뀌어도 크기가 튀지 않습니다.
- 세로 휴대폰 미리보기는 1280×720 판을 통째로 축소하는 구조입니다. 그 안에서 `vh` 는
  실제 화면 높이를 따라가 버리므로 `--tvu` 를 `7.2px`(720의 1%)로 고정했습니다.

곁들여 고친 것 두 가지.

- 좌석 이름 좌우의 보조 글씨(`지하`, `4~6인`)가 `.44em` 이라 TV에서 안 읽혔습니다. `.74em` 으로.
- `window.onresize` 가 없어서 창 크기나 배율이 바뀌어도 **'몇 줄까지 보일지'가 다시 계산되지
  않았습니다.** 글자 크기는 CSS 가 따라가지만 줄 수는 자바스크립트(`capLists`)가 정하기 때문입니다.
  180ms 디바운스를 걸어 `fitDisplay()` 를 다시 부릅니다.
- `@supports not (font-size: clamp(...))` 안에 있던 `.tv` 폴백은 지웠습니다.
  이제 디스플레이 모드는 clamp 를 쓰지 않고 `calc(var())` 만 씁니다(구형 TV 브라우저도 지원).

### 5.17 다시 그려도 스크롤 위치를 지킨다 (2026-09-01)

`render()` 는 `#app` 의 `innerHTML` 을 통째로 바꿉니다. 새 DOM 이라 **스크롤 위치가 0으로 돌아갑니다.**
마법사에서 분 단위를 5분씩 조절할 때마다 화면이 맨 위로 튀던 원인이 이것이었습니다.
분 조절은 누를 때마다 `render()` 를 부르니까요.

`renderApp()` 맨 앞에서 위치를 적어 두고 `afterRender()` 에서 되돌립니다.
대상은 `.wz-mid`(마법사), `.sheet`(팝업), `.calbox`(달력).

같이 저장하는 `viewKey()` 가 중요합니다. 단계나 팝업 종류가 바뀌었으면 되돌리지 않습니다 —
안 그러면 새로 연 팝업이 엉뚱하게 중간부터 보입니다.
단계를 옮길 때 맨 위로 가는 동작(`wzGo` 의 `mid.scrollTop = 0`)은 그대로 둡니다.

**앞으로 `render()` 를 부르는 동작을 추가할 때 이 문제를 다시 겪지 않으려면**,
새로 생기는 스크롤 영역을 `KEEP_SCROLL` 에 추가하세요.

### 5.18 현재 시각 선은 사라지지 않는다 (2026-09-01)

예전에는 지금 시각이 그래프 범위 밖이면 빨간 선을 아예 안 그렸습니다.
개점 전이나 마감 후에는 선이 없어져서 "지금이 어디쯤인지" 감이 끊겼습니다.
이제 범위를 벗어나면 **가까운 쪽 끝에 붙여** 두고, 실제 위치가 아니라는 걸 알 수 있게
점선(`.nowline.edge`)으로 바꿉니다.

### 5.19 전화번호 '해당 없음' (2026-09-01)

- 버튼이 초록(정상)이었는데 빨강으로 바꿨습니다(`.nonebtn.warn.on`).
  알러지의 '없음'은 정상이지만 전화번호의 '해당 없음'은 예외 상황이라 색이 달라야 합니다.
- 다음 단계로 넘어갈 때 확인창을 띄웁니다. **막지는 않습니다**(설계 5.2).
  '해당 없음'을 손이 미끄러져 누른 경우를 잡는 것이 목적입니다.

### 5.20 시각 구간은 `11:00 ~ 22:00` (2026-09-01)

`11:00–22:00`(en dash) 이 섞여 있었습니다. 전부 ` ~ `(앞뒤 공백)로 통일했습니다.
운영시간 편집 화면의 입력칸 사이 구분자도 같이 바꿨습니다.
**새 코드에서 시각 구간을 찍을 때도 ` ~ ` 를 쓰세요.**

### 5.21 인트로 — 중식당에서 한옥으로 (2026-09-01)

歡迎光臨 → 어서오세요 로 글자가 바뀌는 동안 배경도 함께 넘어갑니다.

| | 중식당 | 한옥 |
|---|---|---|
| 바탕 | 붉은색 `#8A2113 → #55130B` | 나무색 `#4A3524 → #241912` |
| 무늬 | 금색 45° 사선 격자 | 창살(가로세로 井) + 창호지 불빛 |
| 글자 | 금색 `#F4CE87` | 한지색 `#F6EEDD` |
| 테두리 | 없음 | 문틀 선이 떠오름 |

두 배경을 겹쳐 두고 위쪽(한옥)의 불투명도만 진행률(`n / (len-1)`)만큼 올립니다.
무늬는 전부 CSS 그라디언트라 **이미지 파일이 늘지 않습니다**.
`.intro-cn` / `.intro-ko` 의 `repeating-linear-gradient` 간격 숫자만 바꾸면 무늬 굵기가 달라집니다.

### 5.22 접속 기록 되살림 (2026-09-01)

`openLogs()` / `sheetLogs()` 는 남아 있는데 버튼만 없어서 들어갈 길이 없었습니다.
설정 → **기타**에 다시 넣었습니다(보안이 아니라 기타입니다).
섹션 요약에 기록 건수를 띄워 살아 있다는 걸 보이게 했습니다.
