# 1부. 판단이 필요한 것 — 재아용 정리

## 구분

세 가지가 섞여 있어서 헷갈리기 쉽습니다.

| 종류 | 예 | 어떻게 |
|---|---|---|
| **우리가 정할 것** | 화면 구성, 색, 저장 방식, 경고를 막을지 알릴지 | 묻지 않는다 |
| **사장님만 아는 사실** | 룸 정원, 영업시간, 코스 구성, 체류 시간 | 물어보면 답이 나온다 |
| **사장님의 판단** | 아래 목록 | **정답이 없다. 손익·철학이 걸려 있다** |

세 번째만 여기 모았습니다. 나머지는 `사장님_질문.md`.

## 1-1. 매출과 좌석 활용이 부딪치는 것

### ① "아무 데나 괜찮다"는 손님을 룸에 넣을까
- **넣으면**: 좌석 활용률이 올라감
- **안 넣으면**: 룸은 코스 손님 자리로 지킴. 홀 손님은 일반 주문이라 객단가가 다름
- 한 번 넣어주면 그 손님은 다음에도 룸을 원할 수 있음
- **지금**: 넣게 돼 있음
- 이건 매출 구조에 대한 판단이라 우리가 못 정합니다

### ② 룸을 어느 순서로 채울까
- 작은 방부터? 1층부터? 안쪽은 마지막?
- 동선·서빙 편의·소음·전망이 다 얽혀 있음
- **지금**: 조조 → 유비 → 장비 → 관우 → 공명 → 주유 → 초선 → 동탁
- 단, 인원이 맞는 방 중 **남는 자리가 가장 적은 방**이 항상 먼저 (4명을 6인 룸에 안 넣음)

### ③ 룸 최소 인원을 못 채우면
- 2명이 6인 룸을 원할 때 받을지
- **지금**: 경고만 뜨고 받아짐

### ④ 하루에 단체를 몇 팀까지
- 주방 부담 문제. 저녁 6시에 단체 4팀이 몰려도 지금은 아무 말이 없음
- **지금**: 제한 없음

## 1-2. 손님 응대 정책

### ⑤ 같은 시간에 겹치는 예약을 허용할지
- 이번에 **막지 않고 경고만** 하도록 바꿨음 (취소를 깜빡한 경우가 있어서)
- 사장님 생각이 다르면 되돌려야 함
- **지금**: 경고 후 진행 가능, 나중에 '경고 예약'으로 남음

### ⑥ 예약을 몇 달 전부터 받을지 / 당일 예약을 몇 시간 전까지
- **지금**: 제한 없음. 1년 뒤도, 10분 뒤도 받아짐

### ⑦ 노쇼 이력이 있는 손님을 어떻게 대할지
- 지금은 접수할 때 "이 번호 노쇼 N회" 안내만 뜸
- 예약금을 요구할지, 거절할지, 그냥 받을지

### ⑧ 브레이크타임에 손님이 나가야 하는지
- 나가야 하면 브레이크 전에 식사가 끝나도록 예약을 잡아야 함
- 예약 가능 시각 계산이 완전히 달라짐
- **지금**: 주문만 안 받는 것으로 설정

## 1-3. 개인정보

### ⑨ TV 화면에 손님 이름을 띄울지
- **지금**: 가운데를 가림 (이 * 아)
- 다 가릴지, 다 보여줄지, 아예 이름을 빼고 시각만 띄울지
- 다른 손님의 예약 시각이 보이는 것도 괜찮은지

### ⑩ 직원에게 어디까지 맡길지
- 지금은 PIN 하나만 알면 **설정 변경도, 예약 삭제도** 다 됩니다
- 룸을 지우거나 영업시간을 바꾸는 것도요
- 관리자 비밀번호는 PIN 바꿀 때만 씁니다
- 나눠야 하면 코드를 고쳐야 합니다

## 1-5. 이번에 새로 생긴 판단

### ⑯ 변동 표시를 언제 기준으로 할지
- 지금은 "그날 안에 바뀐 것"
- 그런데 **주방에 알려주는 시각**이 따로 있다면 그 이후 변동만 빨갛게 하는 게 맞습니다
- 주방 마감이 오후 3시인데 2시 변동과 5시 변동을 똑같이 취급하면 의미가 흐려집니다

- 공사·대관을 가정하고 만들었는데, 실제로 생기는 상황이 다를 수 있음

# 2부. 지금 만든 기능 — 사장님께 보여드릴 목록

쉬운 말로 적었습니다. 각 줄마다 **필요 / 없어도 됨 / 다르게** 를 받으면 됩니다.

## 매일 쓰게 될 것

| 기능 | 하는 일 |
|---|---|
| **예약 접수** | 전화 받으면서 순서대로 물어보면 저장됩니다. 그 시간에 자리가 있는지 바로 보여줍니다 |
| **하루 자리 현황** | 룸 8개와 홀이 시간대별로 얼마나 찼는지 막대로 보여줍니다. 막대를 누르면 그 예약이 열립니다 |
| **예약 목록** | 그날 예약을 시간순으로. 확정·방문·취소·노쇼로 걸러 볼 수 있습니다 |
| **예약 검색** | 이름 두 글자나 번호 뒷자리로 지난 예약까지 찾습니다 |
| **확인 필요** | 손이 가야 할 것만 모아 보여줍니다 (아래 따로) |
| **오늘 변동** | 그날 안에 바뀐 예약을 표시합니다. 고모 파란 펜을 옮긴 것 |

## 가끔 쓸 것

| 기능 | 하는 일 |
|---|---|
| **좌석 사용 중지** | 공사나 대관으로 기간을 정해 자리를 잠급니다. 그래프에 빗금과 이유가 뜹니다 |
| **임시 휴무·단축** | 특정 날짜만 쉬거나 시간을 줄입니다 |
| **노쇼 관리** | 안 오신 손님을 번호로 모아 봅니다. 다음 예약 때 안내가 뜹니다 |
| **월간 달력** | 한 달 예약 건수와 예약률을 한눈에 |
| **손님용 TV 화면** | 좌석별로 오늘 예약 시각과 이름을 띄웁니다 (이름은 가운데 가림) |

## 설정 (한 번 맞춰두면 거의 안 건드림)

| 기능 | 하는 일 |
|---|---|
| **운영시간** | 요일별 영업·브레이크·라스트오더. 공휴일도 따로 |
| **좌석** | 룸 정원·층, 홀 테이블 구성, 배정 순서 |
| **코스 구성** | 메뉴 이름과 점심/저녁 구분 |
| **예약 규칙** | 체류 시간, 단체 기준 인원 등 |
| **화면 크기** | 글자를 키우거나 줄입니다 |
| **PIN 잠금** | 앱을 열 때 번호 입력 |

## '확인 필요'에 뜨는 것들

지금 여덟 가지가 뜹니다. **너무 많으면 오히려 안 보게 됩니다.**

| 항목 | 언제 뜨나 |
|---|---|
| 오늘 변동 | 그날 안에 바뀐 예약 |
| 경고 예약 | 영업시간 밖, 자리 겹침, 정원 초과 등을 알고도 받은 건 |
| 좌석 미정 | 자리를 아직 안 정한 예약 |
| 알러지 | 알러지 적힌 손님 |
| 유아 의자 | 의자가 필요한 손님 |
| 메뉴 확인 | 코스를 아직 안 정한 손님 |
| 노쇼 이력 | 전에 안 오셨던 번호 |
| 단체 손님 | 기준 인원 이상 |
| 어제 자동 처리 | 지난 예약을 자동으로 '방문'으로 바꾼 것 |

→ **이 중에 안 보셔도 되는 게 있으면 빼는 게 낫습니다.**

# 3부. 우리가 과하게 만든 것 같은 것 — 솔직한 평가

물어보기 전에 스스로 의심해 볼 것들입니다.

## 아마 안 쓸 것

| 기능 | 왜 의심스러운가 |
|---|---|
| **예약률 추이 그래프** | 식당 사장님이 매일 볼 화면일까요. 월말 정산 때나 볼 텐데 그때는 다른 게 필요합니다 |
| **접속 기록** | 직원이 여럿이고 누가 뭘 지웠는지 따져야 할 때만 의미가 있습니다. 지금은 화면 진입 버튼도 없습니다 |
| **월간 달력** | "다음 주 토요일 비어요?"에 답하려고 만들었는데, 실제로는 날짜를 넘기며 보는 게 더 빠를 수 있습니다 |

## 오히려 혼란을 줄 것 같은 것

| 기능 | 걱정되는 점 |
|---|---|
| **잠정 배정** | 자리를 안 정한 손님에게 시스템이 미리 방을 잡아 둡니다. 화면에는 "미배정 · 잠정 조조" 로 뜨는데, **이게 확정인지 아닌지 헷갈릴 수 있습니다.** 설명 없이 이해되는 개념이 아닙니다 |
| **설정 임시본 + 적용하기** | 설정을 고쳐도 '적용하기'를 눌러야 반영됩니다. 실수를 막는 장치인데, **"고쳤는데 왜 안 바뀌지"** 가 될 수 있습니다 |
| **경고를 막지 않는 원칙** | 좋은 원칙이지만, 확인 팝업이 자주 뜨면 안 읽고 누르게 됩니다. 지금 경고 종류가 열 가지가 넘습니다 |

`점검결과.md` 6장에서 나온 것들입니다. **사장님께 물어보면 우선순위가 정해집니다.**

| **워크인 손님** | 그냥 오신 손님을 넣으려면 14번을 눌러야 합니다. 그래서 안 넣게 되고, 화면이 실제보다 비어 보입니다 |
| **인쇄** | 오늘 예약을 종이로 뽑을 수 없습니다. 주방에 넘길 종이가 필요하면 이게 있어야 합니다 |

| **늦음 표시** | "20분 늦는대요"를 적을 곳이 요청사항밖에 없습니다 |
| **손님 이력** | "이분 몇 번째 오시는 거예요?"에 답하려면 목록을 눈으로 세야 합니다 |
