## 1. 지난번에 50분을 날린 이유 — 같은 실수 반복 금지

### 1-1. 브라우저 탭을 숨기지 마세요

크롬은 **숨겨진 탭의 타이머를 1분에 한 번으로 묶습니다.** `requestAnimationFrame` 은 아예 안 돕니다.
화면을 하나씩 열며 잠깐 기다리는 스크립트가 전부 1분씩 늘어져서, 화면 30개에 30분이 걸렸습니다.

→ **브라우저 패널을 앞으로 꺼내 놓고 작업하세요.**
→ 그래도 기다림이 필요하면 `setTimeout` 대신 폴링(짧은 간격으로 조건 확인)을 쓰세요.

### 1-2. 페이지 안에서 긴 동기 루프를 돌리지 마세요

12분짜리 in-page 루프를 돌리다 중간에 끊겼습니다. **한 번에 30초를 넘기지 마세요.**
넘길 것 같으면 쪼개서 여러 번 부르고, 중간 결과를 `v2/work/` 에 파일로 남기세요.

### 1-3. 검증은 스크린샷으로

computed style 전수 대조는 정확하지만 이 규모에 과합니다. 실제로 그것 때문에 50분을 썼습니다.

→ **430 / 820 / 1280 / 1920 네 폭에서 스크린샷을 찍어 통합 전후로 비교하세요.**
→ 눈에 띄게 다른 화면이 나오면, **그 화면만** computed style 을 들여다보세요.

### 1-4. 셸 인용 문제

윈도우 셸로 파이썬·JS 를 긴 문자열로 넘기면 깨집니다(지난번에 파서 파일이 한 줄 깨져 통째로 다시 썼습니다).
**스크립트는 `v2/work/` 에 파일로 쓴 뒤 `python work/xxx.py` 로 실행하세요.**

### 1-5. 디스크에 남기세요

지난번엔 50분 동안 디스크에 아무것도 안 썼습니다. 중간에 끊기면 전부 날아갑니다.
**한 단계 끝날 때마다 파일로 저장하고, 진행 상황을 `v2/work/PROGRESS.md` 에 한 줄씩 적으세요.**
