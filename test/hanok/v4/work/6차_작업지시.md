## 6. 예약률 추이 — 좌석 수 변동 대응 (`dayStat`, 4420행 부근; `rateChart`, 3540행)

문제: `dayStat(date)` 가 **현재 설정의 룸·홀 테이블 수**로 모든 날짜를 계산합니다. 룸을 하나 없애면 지난달 예약률이 전부 오릅니다. 룸 사용 중지(blocks)도 분모에서 안 뺍니다.
해결(스냅샷):
- `s.snapshots = { "2026-09-12": { rooms: 8, hallTables: 11 }, ... }` 를 데이터에 추가(`migrate` 에서 없으면 `{}`).
- **`takeSnapshot()`**: 앱을 켤 때(`loadData` 끝)와 날짜가 바뀔 때(이미 있는 자정 넘김 처리 근처) 호출. `오늘 이전의 마지막 영업일들` 중 스냅샷이 없는 날짜에 **오늘의 설정으로** 채우고, 오늘 것도 매번 덮어씁니다(오늘은 아직 바뀔 수 있으니 계속 갱신). 하루 1~2줄이라 용량 걱정 없음. 1년 넘은 것은 지웁니다.
- `dayStat(date)`: `date < 오늘` 이고 스냅샷이 있으면 그 수치를 분모로, 아니면 현재 설정. 룸 사용 중지(`blocks`)는 그 날 해당 룸의 중지 시간만큼을 분모(룸수×영업시간)에서 뺍니다 — 계산이 이미 `roomUsed/(rooms.length*span)` 이므로 `rooms.length*span - blockedMin` 으로.
- Supabase 로 갈 때 `snapshots` 도 같은 JSON 에 있으니 그대로 따라갑니다. 별 테이블 안 만듭니다.

확인: 설정에서 룸 하나 삭제 → 지난 날짜 예약률이 **변하지 않고**, 오늘·이후만 변하는지 단위 테스트(콘솔에서 `dayStat` 호출 값 비교).

- 글자 `blur` 전환 시간은 gap 에 맞춰 `.55s` → `.7s`.

## 13. 빠른 입력 (새 기능 — 마지막에, 나머지가 다 끝난 뒤)

원칙: **새 화면을 만들지 않습니다.** 이미 있는 **예약 수정 시트(`sheetRes`, `view.form={type:"res"}`)** 가 한 화면 양식이므로, 빈 예약으로 그 시트를 여는 것이 빠른 입력입니다. 새 코드가 적어야 오류도 적습니다(발주자의 걱정이 이것).
- 진입점: **마법사 1단계(경로 선택) 타일 아래**에 텍스트 버튼 `한 화면으로 입력` 하나. 누르면 `WZ` 를 닫고 `tmpRes = 새 예약(오늘, 시각·인원 비움, 경로 비움)` 으로 `sheetRes` 를 엽니다. 경로(전화/네이버/기타)는 시트 안에서 **세그먼트 버튼**으로 고릅니다 — 발주자가 "경로별 버튼"을 제안했지만, 경로를 고른 다음 또 화면을 여는 것보다 한 화면 안에서 고르는 편이 탭이 하나 적습니다. 진입 위치(1단계 아래)는 발주자 제안대로.
- 시트가 **새 예약 모드**일 때: 제목 `빠른 입력`, 저장 버튼 `등록`, 필수는 시각·인원·이름(전화는 선택 — 마법사와 같음). 저장 시 마법사와 **같은 함수**(`wzFinish` 안의 등록 부분을 `createReservation(rec)` 로 빼서 둘이 공유)로 등록·잠정 배정·문자 흉내·로그·중복 확인을 태웁니다. 경고(겹침·정원·라스트오더)는 시트 안에 빨간 줄로 **보이되 막지 않음**.
- `sheetRes` 가 수정 전용으로 짜여 있어(`rec.id` 로 찾음) 새 예약이면 `id` 없는 임시 객체를 다루도록 분기가 필요합니다. 분기가 20줄을 넘으면 멈추고 보고.
- 확인: 빠른 입력으로 등록한 예약이 마법사로 등록한 것과 **데이터 모양이 완전히 같은지**(`newId`, `updatedAt`, `changes`, `source`) 콘솔에서 비교.

## 14. 마법사 도중 뒤로가기 보호

문제: 브라우저 뒤로가기가 눌리면 앱이 `history.replaceState` 만 쓰므로 **사이트 밖으로 나가 입력이 날아감.**
해결 두 겹:
- 마법사/수정 시트를 열 때 `history.pushState({wz:1}, "")` 한 번. `popstate` 에서 `WZ` 또는 `view.form` 이 있으면 `uiConfirm("입력 중인 예약이 있습니다. 나갈까요?")` → 취소면 다시 `pushState`, 확인이면 닫기. 이걸로 뒤로가기가 '마법사 닫기'가 됩니다.
- 그래도 새로고침·탭 닫기에는 `beforeunload` 로 브라우저 기본 확인창(문구는 브라우저가 정함 — "저장되지 않은 변경사항이 있습니다" 류. **우리 문구는 못 넣습니다**, 발주자에게 이 점 보고). `WZ` 나 `view.form` 이 있을 때만 `e.returnValue = ""`.
- 디스플레이(`view.display`)에서는 둘 다 걸지 않습니다(TV 는 방치용).
