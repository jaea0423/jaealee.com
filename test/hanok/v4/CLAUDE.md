## 1. 이 폴더의 목적

**Supabase 를 붙이기 전에 "데이터 모양"을 확정하는 것.**

화면은 이미 쓸 만합니다. 지금 고쳐야 하는 건 **한 번 DB 에 들어가면 되돌리기 어려운 것들**입니다.
자세한 내용과 이유는 `../docs/supabase_준비.md`.

순서를 지키세요.

| | 할 일 | 왜 지금인가 |
|---|---|---|
| 1 | 코스 키를 인덱스 → 고정 id | 설정에서 코스 순서만 바꿔도 **과거 예약이 전부 틀어집니다** |
| 2 | 예약 id 를 UUID 로 | 기기 두 대가 같은 밀리초에 만들면 같은 id 가 나옵니다 |
| 3 | 삭제를 `deletedAt` 로 (soft delete) | 기기 A 가 지운 걸 기기 B 가 모르면 되살아납니다 |
| 4 | `updatedAt` 추가 | 동시 수정을 감지할 수단이 지금 아예 없습니다 |
| 5 | 예시 데이터 자동 주입 차단 | 네트워크가 한 번 끊기면 **가짜 예약 1,300건이 진짜 DB 에 들어갑니다** |
| 6 | (그다음) Supabase 연동 | `loadData()` / `saveData()` 두 함수 |

**1~5 를 끝내고 빌드·확인한 뒤에 6 으로 가세요.** 섞으면 무엇이 깨졌는지 못 찾습니다.

## 2. 코드 규칙 (v1~v3 과 동일)

상위 `../CLAUDE.md` 2장을 그대로 따릅니다.

- **구형 스마트TV 문법 금지** — `?.` `??` `.flat()` `.replaceAll()` `structuredClone`,
  CSS 는 `inset:` `backdrop-filter` `color-mix()` `:has()` (v3 에서 `inset:` 을 0 으로 만들어 놨습니다. 되돌리지 마세요)
- 배율은 `zoom`, `transform:scale` 금지
- **경고는 막지 않고 알리기만** (설계 원칙, 예외 없음)
- 주석은 한국어로, '왜' 를 쓰기
- 흉내 표시(`.mockbar` `.sb-mock` `.lk-open`) 지우지 마세요
- 나타났다 사라지는 요소는 **자리를 미리 잡아 두고 보이기만** 바꾸기 (v3 원칙)

### 손님 화면 관련 (v3 에서 새로 생긴 것)

- `tv-mode-list` / `tv-mode-grid` — **`tv-grid` 는 안쪽 격자가 이미 쓰는 이름입니다.** 바깥에 붙이면 화면이 백지가 됩니다
- `adUrl()` — TV 는 `/screen/hanok` 주소로 엽니다. 상대 경로를 그대로 쓰면 영상이 안 나옵니다
- 영상은 **절대 base64 로 넣지 마세요.** 별도 파일 + H.264
