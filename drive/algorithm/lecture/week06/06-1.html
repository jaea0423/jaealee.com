02퀵 정렬 복습 — 수행시간과 피벗

시험 ★★★

퀵 정렬(quick sort)은 피벗(pivot) p 를 정해 S · M(p) · L 로 나누고, S 와 L 을 각각 재귀적으로 정렬했습니다.

T(n) = T(|S|) + T(|L|) + C·n        ← C·n 은 S, M, L 로 나누는 비용
입력점화식Big-O
worst이미 오름차순(또는 내림차순)으로 정렬된 배열 — 피벗 = 첫 값이 최솟값(최댓값)T(n) = T(n − 1) + C·nO(n²)
best잘 분배된 경우 — 매번 피벗이 가운데 값이라 반반 나뉨T(n) = 2T(n2) + C·nO(n log n)
average일반적인 입력—O(n log n) (best 와 같은 차수)
필기 확인 — "best == Average case"

best 와 average 가 같은 경우라는 뜻이 아니라, 둘 다 O(n log n) 으로 차수가 같다는 뜻입니다. best 입력은 교수님 말씀대로 "잘 분배돼 있는 경우" 입니다.

피벗을 중앙값으로 고르면?

best 가 되려면 피벗이 중앙값(median)이어야 합니다. 그런데 중앙값을 고르는 데 O(n) 이 걸립니다. 지금까지는 피벗을 첫 값(A[first])으로 정해 O(1) 이었습니다. 교수님 말씀은 "피벗을 중간값으로 하려면 O(n) 이 되니까 조금 그렇다" 는 느낌이었습니다.

보충 — 차수는 그대로

중앙값 찾기 O(n) 을 더해도 식은 T(n) = 2T(n2) + C·n + O(n) 이고, O(n) 은 C·n 에 흡수됩니다. 그래서 차수는 O(n log n) 그대로이고 상수만 커집니다. "조금 그렇다" 는 이 부담(느려짐)을 말씀하신 것으로 이해하면 됩니다.

오늘의 출발점

피벗을 신경 쓰지 말고, 그냥 반반으로 나눠 보자 → 병합 정렬(merge sort).

필기 원문
quick_sort ⇒ pivot 'p'를 임의로 정해서 S M(p) L 나누고 각각을 재귀적으로 quick_sort 해줬었음 이 수행시간을 생각해보면 T(n) = T(|S|) + T(|L|) + C*n # C*n은 SML을 나누는 과정에서 발생 우리는 이걸 worst case / best case 로 생각을 해봤었음 worst case ⇒ 이미 오름차순(혹은 내림차순)으로 정렬이 돼있는 배열 ⇒ T(n) = T(n-1) + C*n = O(n^2) best case ⇒ (무슨 배열이 베스트더라) ⇒ T(n) = 2*T(n/2)+C*n = O(n log n) == Average case pivot p를 어떻게? 중앙값(중간값)으로 잡앙야함 근데 피벗을 중간값을 고르는 과정이 O(n)이 걸림 우리가 피벗을 신경쓰는 순간 시간복잡도가 늘어나기 때문에(기존에는 피벗을 first로 설정해서 O(1)이었음) 반반 나누되 피벗을 신경쓰지 말고 나눠보자 ⇒ 오늘 배울 내용
필기 원문
피벗을 신경쓰면 늘어난다기 보다는 피벗을 중간값으로 하려면 O(n)이 되니까 조금 그렇다. 이런 느낌 best case는 그냥 잘 분배돼있는 케이스 정도로 말씀하셨어

03병합 정렬 아이디어

시험 ★★★

병합 정렬(merge sort)은 세 단계입니다.

① 나누기값은 보지 않고 강제로 반반 나눔 (피벗 없음)
② 정렬두 그룹을 각각 정렬 (재귀)
③ 병합두 그룹의 맨 앞 값끼리 1:1 비교해 작은 값을 새 배열 B 에 채움

③ 이 되는 이유: 각 그룹이 정렬돼 있으니 맨 앞 값이 그 그룹의 최솟값입니다. 두 최솟값 중 작은 쪽이 남은 값 전체의 최솟값이므로 B 의 다음 칸에 넣으면 됩니다.

04병합 과정 — 한 단계씩

시험 ★★★

B 에 들어가지 않은 값은 계속 비교 대상으로 남습니다. 화살표 버튼으로 넘겨 보세요.

[3, 20, 35, 40] 과 [9, 10, 80] 병합
정리

비교 6번 만에 한쪽(앞 그룹)이 비고, 남은 80 은 비교 없이 붙습니다. 병합 한 번의 비교는 많아야 (두 그룹 길이의 합) − 1 번 → 병합은 O(n).

05성질 — in-place · stable

시험 ★★★
성질답이유
in-placeX병합할 때 새 배열 B 를 만들기 때문 (B = [])
stable짜기에 따라 다름 — 수업 코드는 O같은 값일 때 앞 그룹 값을 먼저 B 에 넣으면(A[i] <= A[j]) stable

stable 확인 — 같은 값 10 이 두 개

A = [35, 10₁, 40, 3 | 9, 80, 10₂] 를 나눠 정렬하면 [3, 10₁, 35, 40] 과 [9, 10₂, 80]. 비교 2번 뒤 10₁ 과 10₂ 를 비교하는 순간이 옵니다.

비교 조건10₁ vs 10₂ 에서결과stable
if A[i] <= A[j] (수업)10 ≤ 10 참 → 앞 그룹 10₁ 먼저…, 10₁, 10₂, …O
if A[i] < A[j]10 < 10 거짓 → else → 뒤 그룹 10₂ 먼저…, 10₂, 10₁, …X

앞 그룹 값은 원래 배열에서도 앞에 있던 값이므로, 같을 때 앞 그룹을 먼저 넣어야 입력 순서가 유지됩니다.

06병합 정렬 의사코드

시험 ★★★

A[first] … A[last] 구간을 정렬합니다. 필기 코드에서 문법·들여쓰기만 고쳤습니다.

Pythonmerge sort
def merge_sort(A, first, last):
    if first >= last:                       # 원소 0~1개 → 이미 정렬됨 (재귀 종료)
        return
    merge_sort(A, first, (first+last)//2)       # 대략 반
    merge_sort(A, (first+last)//2 + 1, last)    # 반의 나머지
    merge_two_sorted_lists(A, first, last)      # 정렬된 두 그룹을 B 로 합침

def merge_two_sorted_lists(A, first, last):
    m = (first + last) // 2                     # [first … m][m+1 … last] — merge_sort 와 같은 m
    i, j = first, m + 1                         # i: 앞 그룹 맨 앞, j: 뒤 그룹 맨 앞
    B = []                                      # 새 배열 → not in-place
    while i <= m and j <= last:             # 두 그룹 모두 값이 남아 있는 동안
        if A[i] <= A[j]:                     # 같으면 앞 그룹 먼저 → stable
            B.append(A[i])
            i = i + 1
        else:
            B.append(A[j])
            j = j + 1
    for k in range(i, m + 1):                # 앞 그룹 남은 값 (while 과 같은 들여쓰기)
        B.append(A[k])
    for k in range(j, last + 1):             # 뒤 그룹 남은 값
        B.append(A[k])
    for i in range(first, last + 1):         # B 를 A 의 같은 구간에 되돌려 놓기
        A[i] = B[i - first]                     # B 는 0 부터, A 구간은 first 부터 → 차이 first
필기 코드에서 고친 곳

1. 남은 값 for 두 개와 마지막 for 는 while 과 같은 들여쓰기. 필기는 더 들여 써져 있었습니다. while 안에 들어가면 비교할 때마다 남은 값을 통째로 붙여 결과가 틀립니다.

2. while … last 끝에 : 추가, 함수 이름 merge_two _sorted_lists 의 공백 제거, for 줄 끝 : 추가.

3. i = i+1 과 i += 1 은 완전히 같습니다 (필기의 질문).

고친 코드로 길이 0 ~ 12 의 무작위 입력 3000개를 돌려, 모두 정렬되고 같은 값의 순서도 유지(stable)되는 것을 확인했습니다.

남은 값 for 두 개 — 하나만 돈다

while 은 한쪽 그룹이 다 빠지면 끝납니다. 그래서 값이 남은 그룹은 항상 한쪽뿐입니다. 빈 쪽의 for 는 범위가 비어 있어(예: i = m + 1 이면 range(m+1, m+1)) 한 번도 돌지 않습니다.

A[i] = B[i - first] 인 이유

B 는 이번 호출에서 새로 만든 배열이라 인덱스가 0 부터 시작합니다. 그런데 되돌려 놓을 A 의 자리는 first 부터 시작합니다. 두 번호는 항상 first 만큼 차이가 나므로 B 의 칸 번호 = i − first 입니다.

맨 바깥 호출은 first = 0 이라 B[i - 0] = B[i] 로 차이가 없습니다. 재귀로 들어가 구간이 중간에서 시작할 때만 이 보정이 필요합니다. 같은 일을 B 기준으로 쓰면 다음과 같습니다.

Python같은 동작
for k in range(len(B)):     # B 의 k 번째 →
    A[first + k] = B[k]         # A 의 first + k 자리
필기 원문
A[first] ... A[last] 를 정렬할거임 우리는 수도코드 def merge_sort(A, first, last): if first >= last : return merge_sort(A, first, (first+last)//2) # 대략 반 merge_sort(A, (first+last)//2 + 1, last) # 반의 나머지 merge_two_sorted_lists(A, first, last) #각각 sorting된 두 그룹을 B 배열로 다시 합쳐주는 새롭게 정의하는 함수(곧 적을거임) def merge_two _sorted_lists(A, first, last): m = (first + last)//2 # [first m][m+1 last] 이런 모양이 됨 i, j = first, m+1 # [i m][j last] 이런 모양이 됨 B = [] # B를 선언해줌 → not in-place while i<=m and j <= last #i랑 j가 각 그룹 안에 있어야되기 때문에 if A[i] <= A[j]: B.append(A[i]) i = i+1 (근데 여기서그냥 i+= 1 해도 되지 않나) else : B.append(A[j]) j = j+1 이 수도코드 하에선 not in-place, stable 임 왜냐면 A[i] <= A[j]에서 A[i]를 먼저 B에 어펜드 해주기 때문 남은 찌꺼기가 남을 수 있음 이어서 수도코드 계소 ㄱ작성 for k in range(i, m+1) #첫번째 그룹 남은 요소 정리(들여쓰기 맞는지는 모르겠어) B.append(A[k]) #앞 그룹에 남은 요소 쭈루룩 삽입 for k in range(j, last+1): B.append(A[k]) 이 두 for문은 둘 중 하나만 돌아가게 돼있음(요소가 남은건 무조건 한쪽 그룹일거기 때문. 남은게 없으면 for문 조건을 빠져나오게됨(예를 들면 i가 m+1이 됨)) for i in range(first, last+1) A[i] = B[i-first] # B를 A에 다시 옮기기 왜 i-first냐면 B는 우리가 새로 선언했기 때문에 인덱스가 0부터 시작함 근데 재귀적으로 들어가는거니까 A[first] A[first+1] 에 각각 B[0], B[1]이 들어가야하는거임 그래서 A[i] = B[i-first]가 되는거임. 나 이 부분 이해 잘 안돼. 너가 부가설명해주고 내 필기가 이상하거나 오류 있으면 물어봐줘.

07병합 정렬 수행시간 (보충)

시험 ★★☆
보충 — 수업에서 아직 다루지 않음

병합 정렬은 값과 상관없이 항상 반반 나누므로 입력에 따라 worst 가 생기지 않습니다. 나누기는 O(1), 병합은 O(n) 이라

T(n) = 2T(n2) + C·n  =  O(n log n)        ← worst · best · average 모두

08힙 자료구조 — 배열을 이진트리로

시험 ★★★자료구조 복습

힙 정렬(heap sort)은 힙(heap) 자료구조를 이용합니다. 오늘은 힙을 복습하고, 힙 정렬은 다음 시간에 합니다.

힙의 정의 (수업)

힙 = 힙의 성질을 가지는 배열(리스트).

배열 A = [2, 8, 6, 1, 10, 15, 3, 12, 11] 을 앞에서부터 순서대로, 위층부터 왼쪽→오른쪽으로 채우면 이진트리가 됩니다. 루트는 A[0] = 2 입니다. 아직 힙은 아닙니다.

찾을 노드인덱스예 (k = 2)
A[k] 의 왼쪽 자식A[2k + 1]A[5] = 15
A[k] 의 오른쪽 자식A[2k + 2]A[6] = 3
A[k] 의 부모A[(k − 1) // 2]A[5] 의 부모 = A[(5 − 1)//2] = A[2]

계산 한 번이면 자식·부모 위치가 나오므로 O(1) 에 찾습니다. 이 특징 때문에 힙 정렬의 시간이 줄어듭니다.

보충 — 부모 식 확인

왼쪽 자식 k = 2p + 1 이면 (k − 1)//2 = p, 오른쪽 자식 k = 2p + 2 이면 (k − 1)//2 = (2p + 1)//2 = p. 그래서 왼쪽·오른쪽 상관없이 같은 식 하나로 부모가 나옵니다. 예: A[6] 의 부모 = (6 − 1)//2 = 2.

코드 (보충)

보충 — 수업에서 코드는 아직 안 나옴

수업에서 말로 설명한 과정을 코드로 옮긴 것입니다. 다음 시간 힙 정렬에서 교수님 코드가 나오면 그쪽이 기준입니다.

Pythonmake heap
def heapify_down(A, k, n):
    while 2*k + 1 < n:                  # 자식이 하나라도 있는 동안
        c = 2*k + 1                       # 왼쪽 자식
        if c + 1 < n and A[c+1] > A[c]:  # 오른쪽 자식이 더 크면 그쪽
            c = c + 1
        if A[k] >= A[c]:               # 부모 ≥ 큰 자식 → 힙 성질 만족, 멈춤
            break
        A[k], A[c] = A[c], A[k]           # 큰 자식과 교환
        k = c                             # 내려간 자리에서 다시 확인

def make_heap(A):
    n = len(A)
    for k in range(n - 1, -1, -1):     # 맨 뒤부터 루트까지 (수업 방식)
        heapify_down(A, k, n)

수행시간

노드 n 개마다 heapify_down 을 한 번씩 합니다. heapify_down 은 트리 높이만큼, 즉 최대 log₂ n 번 내려갑니다.

n × heapify_down  =  n × log₂ n   →   make_heap 은 O(n log n)
보충 — 더 정확히 세면

leaf(전체의 약 절반)는 내려갈 곳이 없고, 아래층일수록 내려갈 거리가 짧습니다. 이걸 다 더하면 실제로는 O(n) 이 됩니다. O(n log n) 도 틀린 상한은 아니지만 여유 있게 잡은 값입니다. 시험 답은 수업대로 쓰고, 다음 시간에 교수님이 다루시는지 확인하세요.
