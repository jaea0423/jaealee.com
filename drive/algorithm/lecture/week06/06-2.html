01지난 시간 복습

시험 ★★☆
병합 정렬피벗 없이 강제로 반반 → 각각 재귀 정렬 → 맨 앞부터 비교해 채움. T(n) = 2T(n2) + Cn = O(n log n), worst · best · average 구분 없이 모두.
힙배열을 앞 인덱스부터 루트로 채운 이진트리. 부모 key ≥ 자식 key → 루트가 자동으로 최댓값: A 가 힙이면 A.max() = A[0].
인덱스부모·자식 인덱스를 O(1) 에 계산 (자식 2k + 1, 2k + 2 · 부모 (k − 1)//2).

02정렬의 공통 틀 — get_max 를 얼마나 빨리?

시험 ★★★

일반적인 정렬은 "A[0] ~ A[i] 의 최댓값을 찾아 맨 끝 A[i] 로 보내기" 를 i = n − 1 부터 1 까지 반복하는 것으로 볼 수 있습니다.

Python일반적인 정렬
def sort(A):
    for i in range(n - 1, 0, -1):
        m, index = get_max(A, i)      # A[0] ~ A[i] 중 최댓값과 그 인덱스
        A[index], A[i] = A[i], A[index]   # 최댓값을 구간 끝 A[i] 로
get_max(A, i) 방법1번 비용전체
선택 정렬A[0] ~ A[i] 를 전부 훑음O(i)O(1) + … + O(n − 1) = O((n − 1)n2) = O(n²)
힙 정렬힙이면 최댓값 = A[0], 꺼낸 뒤 heapify_downO(log i)(n − 1) · O(log n) = O(n log n)
핵심

틀은 같고 최댓값 찾는 방법만 다릅니다. 힙을 쓰면 최댓값은 바로 보이고(루트), 꺼낸 뒤 힙을 고치는 데 높이만큼(log i) 만 들기 때문에 O(n²) → O(n log n).

필기 확인

1. "getmax 를 n-번" → range(n-1, 0, -1) 은 n−1 부터 1 까지라 n − 1 번.

2. "(n − 1) · O(log i)" 는 정확히는 Σ O(log i). i ≤ n 이라 log i ≤ log n 이므로 상한(upper bound)으로 (n − 1) · O(log n) 이라 쓴 것입니다.

Pythonheap sort
def heap_sort(A):
    n = len(A)
    make_heap(A)                      # O(n log n) — 루트가 최댓값
    for i in range(n - 1, 0, -1):     # 정렬 안 된 구간의 끝 i: n-1 → 1  (n-1 번)
        A[0], A[i] = A[i], A[0]       # 최댓값을 구간 끝으로 → A[i] 확정
        heapify_down(A, 0, i)         # 크기 i 인 앞부분만 다시 힙으로 — O(log i)

04힙 정렬 — 수행시간과 성질

시험 ★★★
make_heap  +  (n − 1) × heapify_down  =  O(n log n) + O(n log n)  =  O(n log n)

heapify_down 은 트리 높이만큼 내려가므로 O(log n). 남은 힙 크기는 n − 1, n − 2, … 로 줄지만 모두 n 이하라서 log n 으로 크게 잡아도 됩니다 (상한). 교수님: best · worst 구분 없이 O(n log n).

성질답이유
in-placeO새 배열 없이 A 안에서 자리만 계속 바꾸기 때문
stableXA[0] ↔ A[i] 처럼 멀리 떨어진 칸을 교환하기 때문
보충 — stable X 반례 (코드로 확인)

A = [1₁, 1₂]. make_heap 에서 1₂ 는 1₁ 보다 크지 않아 그대로. 그다음 A[0] ↔ A[1] 교환으로 [1₂, 1₁] — 같은 값의 순서가 뒤집힘.

06상한과 하한

시험 ★★★
상한 (upper bound)이 알고리즘은 이보다 더 나빠질 수 없다. Big-O 표현 자체가 상한. 병합·힙 정렬은 O(n log n).
하한 (lower bound)최소 이 정도는 꼭 필요하다. 여기서는 비교 기반 정렬 전체의 일반적인 하한을 봅니다.
"하한이 n log n 이면 잘한 거" 의 뜻

하한 = 비교로 정렬하는 어떤 알고리즘도 이보다 적게 비교할 수 없음. 병합·힙 정렬의 상한이 이 하한과 같으면, 차수로는 더 줄일 방법이 없는 최적(optimal) 알고리즘이라는 뜻입니다.

표기

하한은 Big-O 대신 Ω (빅 오메가) 로 써서 Ω(n log n) 이라고 합니다. 수업에서도 Ω 를 배웠습니다 (10번 섹션).

07결정 트리 — a, b, c 의 비교 하한

시험 ★★★판서

a, b, c 세 값의 순서를 알아내려면 몇 번 비교해야 할까? 비교 결과에 따라 갈라지는 트리를 결정 트리(decision tree)라고 합니다. 판서를 다시 그린 것입니다.

리프 개수가능한 순서 전부 = 3 × 2 × 1 = 3! = 6
높이 h루트에서 가장 먼 리프까지 비교 횟수 = 3 → 하한 3번
필기 확인 — "어떻든 최소한 3번" 은 정확하지 않음

판서 트리에서 a < b < c 와 c < b < a 는 비교 2번(깊이 2) 만에 정해집니다. 하한 3 의 뜻은 "모든 입력에 3번" 이 아니라 "아무리 잘 짜도 어떤 입력에서는(최악) 3번이 필요하다" = 트리의 높이입니다.

왜 3! 이 높이 3 으로 이어지나

보충 — 계산 과정

비교 한 번은 두 갈래로 나뉘므로 높이 h 인 트리의 리프는 최대 2h 개. 리프가 6개 이상 있어야 하므로 2h ≥ 6.

h = 2 :  2² = 4 < 6   ✗        h = 3 :  2³ = 8 ≥ 6   ✓        → h ≥ 3   (log₂ 6 ≈ 2.58 을 올림)

n 개로 넓히는 것은 다음 섹션에서 수업 내용 그대로 정리합니다.

시험 ★★★

알고 싶은 것h ≥ ____ — 아무리 잘 짜도 h 가 이보다 작아질 수 없는 값

h 가 가장 작으려면 이진트리를 최대한 꽉 채워야 합니다. 높이 h 인 이진트리의 리프는 최대 2h 개이므로 2h ≥ n! 이고, 양변에 log₂ 를 취하면

09log₂ (n!) 을 n log n 으로 어림하기

시험 ★★★

n! 을 직접 다루기 어려우므로 n! 보다 작은 값으로 바꿔 아래에서 받칩니다. 하한을 구하는 중이므로 작은 값으로 바꿔도 h ≥ (그 값) 은 여전히 성립합니다.

n!  =  n × (n − 1) × ⋯ × (n2 + 1)  ×  n2 × ⋯ × 2 × 1
    ≥  n2 × n2 × ⋯ × n2   ×   1 × 1 × ⋯ × 1        ← 앞 n2 개는 n2 로, 뒤 n2 개는 1 로
    =  (n2)n/2
h  ≥  log₂ (n!)  ≥  log₂ (n2)n/2  =  n2 · log₂ n2  ≥  C · n log₂ n
필기 오류 — 부등호 이유가 반대

필기의 "n! 보다 (n/2)n/2 가 더 크기 때문" 은 반대입니다. (n/2)n/2 가 n! 보다 작습니다 (n! ≥ (n/2)n/2). 작은 값으로 바꿨기 때문에 h ≥ log₂ (n/2)n/2 가 성립합니다. 바로 위에 적은 "n! > 각 n/2 씩 곱해 줌" 과 같은 방향입니다. ((n-1) * (n-1) 의 두 번째는 n − 2 의 오타.)

보충 — 못 적은 부분 "n/2 개수"

n 부터 n2 + 1 까지는 n2 개이고, 하나하나가 모두 n2 보다 큽니다. 그래서 이 부분만 곱해도 (n2)n/2 이상이고, 나머지 n2 개는 1 이상이라 곱해도 줄지 않습니다. 교수님이 말씀하신 "n/2 개수" 는 이 지수 n/2 를 뜻하는 것으로 보입니다 (추측).

보충 — 마지막 ≥ C · n log₂ n 이 되는 이유

n2 · log₂ n2 = n2 (log₂ n − 1). n ≥ 4 이면 log₂ n − 1 ≥ 12 log₂ n 이므로 n2 (log₂ n − 1) ≥ 14 · n log₂ n. 즉 C = 14 로 잡으면 됩니다. 수업은 "차수만 생각" 해서 C 로 두었습니다.

nn!log₂ (n!)(n/2) log₂ (n/2)n log₂ n
4244.58 → 최소 5번28
840,32015.30 → 16번824
16약 2.1 × 101344.25 → 45번2464

표는 직접 계산한 값입니다. 세 열 모두 n log n 과 같은 속도로 커지고, (n/2) log₂ (n/2) ≤ log₂ (n!) ≤ n log₂ n 사이에 있습니다.

Q3선택 정렬과 힙 정렬을 "get_max 를 반복하는 정렬" 로 볼 때, 각각 get_max 의 비용과 전체 시간복잡도를 쓰고 차이가 나는 이유를 설명하시오.비교 서술응용

Q4힙 정렬에서 heapify_down 을 할 때 이미 뒤로 보낸 값들을 제외해야 하는 이유를 쓰시오.서술응용

Q7"비교 기반 정렬의 하한이 n log n 이다" 가 병합 정렬과 힙 정렬에 대해 의미하는 바를 쓰시오.서술심화

Q8비교 기반 정렬의 결정 트리에서 h ≥ log₂ (n!) 이 성립하는 이유를 쓰시오.서술응용
모범답안n 개(서로 다른 값)를 늘어놓는 순서는 n! 가지이고 각각 다른 리프가 필요하므로 리프는 n! 개 이상. 높이 h 인 이진트리의 리프는 최대 2h 개이므로 2h ≥ n!, 따라서 h ≥ log₂ (n!).
Q9n! ≥ (n2)n/2 임을 보이고, 이를 이용해 h 가 Ω(n log n) 임을 보이시오 (n 은 짝수).증명심화
