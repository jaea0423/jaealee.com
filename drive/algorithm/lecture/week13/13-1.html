노드 v 에서는 X[i] 를 결정하고, v 아래에서 X[i + 1] ~ X[n − 1] 을 결정합니다 (12-2 의 07).

필기 확인

k-S(v)-S[i] → K − s(v) − S[i] (용량은 대문자 K, 지금까지 무게는 소문자 s(v)). 코드에서는 s(v) 대신 남은 용량 size 를 들고 다니므로 왼쪽 B 는 frac_knapsack(i+1, size-S[i]), 오른쪽은 frac_knapsack(i+1, size) 입니다.

02frac_knapsack(i, size) — B 구하기

시험 ★★★
pythonfrac_knapsack(i, size) — 아이템 i ~ n−1 을 size 에 fractional 로
def frac_knapsack(i, size):          # 아이템 i ~ n-1 을 용량 size 에 fractional 로 채운 가치 = B
    B = 0
    # 가성비 P[j]/S[j] 가 높은 순서 (내림차순) 로 정렬
    items = sorted(range(i, n), key=lambda j: P[j] / S[j], reverse=True)
    for j in items:
        if size == 0:                # 배낭이 꽉 참 → 끝
            break
        if S[j] <= size:             # 통째로 들어감
            B += P[j]
            size -= S[j]
        else:                        # 넘침 → 남은 용량만큼 잘라 넣음
            B += P[j] * (size / S[j])
            size = 0
    return B

12-2 의 가성비 그리디 그대로: 가성비 높은 순서로 통째로 넣다가, 넘치는 아이템은 남은 용량만큼 잘라 넣고 끝.

호출 (P = [15, 16, 6], S = [3, 4, 2])계산B

frac_knapsack(1, 5)아이템 1 (4, 16) 통째로, 남은 1 → 아이템 2 를 6 × 1219
frac_knapsack(2, 2)아이템 2 (2, 6) 통째로6
frac_knapsack(3, 0)볼 아이템 없음0
필기 확인

① reverse = Trure → True. ② 주석 "가치(가성비)가 높은 순서" → 가치가 아니라 가성비 순서. ③ (보충) 호출할 때마다 정렬하면 매번 O(n log n) 이 듭니다. 수업 예시처럼 아이템을 처음에 가성비 순으로 한 번 정렬해 두면 range(i, n) 을 그대로 돌아도 됩니다.

03knapsack(i, size, profit) — 왼쪽 · 오른쪽 가지

시험 ★★★
pythonknapsack(i, size, profit) — X[i] 결정
def knapsack(i, size, profit):       # X[i] 를 결정 (size = 남은 용량, profit = 지금까지 가치 p(v))
    if i >= n or size == 0:          # 다 정했거나 꽉 참 → 더 볼 필요 없음
        update_best(profit)          # MP 갱신
        return
    if S[i] <= size:                 # i 번째가 들어갈 때만 X[i] = 1 가지
        B = frac_knapsack(i + 1, size - S[i])
        if profit + P[i] + B > MP:   # 왼쪽 상한 > MP 일 때만 방문
            X[i] = 1
            knapsack(i + 1, size - S[i], profit + P[i])
            X[i] = 0                 # 돌아오면 되돌림 (백트랙)
    # X[i] = 0 — if S[i] <= size 밖 (들어가지 않아도 안 넣는 가지는 항상 검사)
    B = frac_knapsack(i + 1, size)
    if profit + B > MP:              # 오른쪽 상한 > MP 일 때만 방문
        X[i] = 0
        knapsack(i + 1, size, profit)

필기 확인 — 들여쓰기 (중요)

필기에서는 # X[i] = 0의 경우 부분이 if S[i] <= size: 안쪽에 들여써져 있습니다. 그러면 i 번째가 넘쳐서 못 넣을 때 "안 넣는" 가지까지 사라집니다. 위 코드처럼 if 와 같은 높이 (밖) 에 있어야 합니다. 필기의 공백이 섞여 있어 잘못 옮겨 적었을 가능성이 큽니다.

코드로 돌려 본 결과: 아이템 3개 예시는 올바른 코드 21, [1, 0, 1] / 필기 들여쓰기 6, [0, 0, 1]. 4개 예시는 90, [1, 0, 1, 0] / 60, [0, 0, 1, 1]. [1] 에서 아이템 2 (4) 가 남은 용량 2 에 안 들어가자 [1, 0] 으로도 못 가기 때문입니다.

그 밖에: 함수 정의의 profit(p(v)를 뜻함 …) 은 메모이므로 코드는 def knapsack(i, size, profit):. profit = p(v) 가 맞습니다.

def update_best(profit):             # 답에 도착할 때마다 MP 갱신
    global MP, best_X                # (보충) 파이썬에서 전역 변수를 바꾸려면 필요
    if profit > MP:
        MP = profit
        best_X = X.copy()            # 의사코드에서는 best_X = X 로 써도 됨 (교수님)

MP, best_X = 0, None

05판서 — 트리로 풀기 (P = [15, 16, 6], S = [3, 4, 2], K = 5)

시험 ★★★

가성비 P / S = 5, 4, 3 (이미 정렬됨). 노드에는 p(v), s(v), 그때의 MP 를 적습니다. 왼쪽 가지 (넣음) 를 먼저 보고, 가지로 가기 전에 상한을 계산해 MP 와 비교합니다.

실선 = 간 가지, 빨간 점선 ✕ = 거른 가지 (① 넘침 · ② · ③ 상한 ≤ MP), ★ = 답. 결과 MP = 21, [1, 0, 1].

읽는 법 — frac_knapsack(a, b) 의 두 숫자

자리뜻정하는 법
a다음에 볼 아이템 번호지금 결정하는 i 의 다음 = i + 1
b남은 용량왼쪽 (넣음): K − s(v) − S[i] / 오른쪽 (안 넣음): K − s(v)

상태마다 — 배낭과 계산

1. 루트 [ ] — 아무것도 안 정함

p(v) = 0, s(v) = 0, MP = 0. 배낭 용량 5 가 통째로 비어 있습니다.

2. 왼쪽 X[0] = 1 → 상한 23 > MP 0 → 감

p(v) + P[0] + frac_knapsack(1, 2) = 0 + 15 + 8 = 23
  • P[0] = 15: 아이템 0 을 넣기로 했으니 그 가치.
  • 1: 다음에 볼 아이템 = i + 1 = 1 (아이템 1, 2 가 남음).
  • 2: 남은 용량 = K − s(v) − S[0] = 5 − 0 − 3.
  • 8: 남은 2 에 아이템 1 (무게 4, 가치 16) 은 다 안 들어가서 반만 → 16 × 24 = 8 (점선).

23 > 0 → 방문. 새 상태 [1]: p = 15, s = 3. 판서는 여기서 MP = 15 로 갱신 (아래 주의).

3. [1] 의 왼쪽 X[1] = 1 → 넘침

아이템 1 의 무게 4 > 남은 용량 5 − 3 = 2 → 들어가지 않음. 상한을 계산할 필요도 없이 거름 — 12-2 의 거르기 ①, 코드의 if S[i] <= size. 필기 "왜? 예전에 나온 내용" 이 이것.

4. [1] 의 오른쪽 X[1] = 0 → 상한 21 > MP 15 → 감

p(v) + frac_knapsack(2, 2) = 15 + 6 = 21
  • P[1] 은 더하지 않음 — 안 넣기로 한 가지 (필기 그대로 맞음).
  • 2: 다음 아이템 = 2.
  • 2: 남은 용량 = 5 − 3 = 2 (아무것도 안 넣었으니 그대로).
  • 6: 아이템 2 (무게 2, 가치 6) 가 딱 들어감 (점선).

21 > 15 → 방문. 새 상태 [1, 0]: p = 15, s = 3 — 아이템 2 는 상한을 본 것뿐 실제로 넣은 게 아니라서 그대로 (필기 맞음).

5. [1, 0] 의 왼쪽 X[2] = 1 → 상한 21 > MP 15 → 감 → 답

p(v) + P[2] + frac_knapsack(3, 0) = 15 + 6 + 0 = 21
  • P[2] = 6: 아이템 2 를 넣음.
  • 3: 다음 아이템 = 3 → 아이템이 0, 1, 2 뿐이라 남은 아이템 없음.
  • 0: 남은 용량 = 5 − 3 − 2 = 0.
  • frac_knapsack(3, 0) = 0.

방문. [1, 0, 1]: p = 21, s = 5 → 모두 정함 (꽉 참) → MP = 21, best_X = [1, 0, 1]. 하나 찾았지만 최대를 찾아야 하므로 백트랙.

6. [1, 0] 의 오른쪽 X[2] = 0 → 상한 15 ≤ 21 → 안 감

p(v) + frac_knapsack(3, 2) = 15 + 0 = 15
  • 3: 다음 아이템 3 → 없음. 2: 남은 용량 5 − 3 = 2 (아이템 2 를 안 넣었으니).
  • 빈 공간이 있어도 넣을 아이템이 없어서 0.

15 ≤ 21 → 거름 (12-2 의 ②). [1, 0] 의 두 가지를 다 봤으니 [1] 로, [1] 도 다 봤으니 루트로 백트랙.

7. 루트의 오른쪽 X[0] = 0 → 상한 19 ≤ 21 → 안 감

p(v) + frac_knapsack(1, 5) = 0 + 19 = 19
  • p(v) = 0: 루트에서 아이템 0 을 안 넣음 → 아무것도 없음.
  • 1: 다음 아이템 = 1. 5: 남은 용량 = 5 − 0 = 5 (통째로).
  • 19: 가성비 순으로 아이템 1 (4, 16) 통째로 → 남은 1 → 아이템 2 (2, 6) 를 반만 → 6 × 12 = 3 → 16 + 3 = 19 (점선).

아이템 0 을 빼면 쪼개서 넣는 반칙을 해도 19 가 최대 → 0/1 로는 19 보다 작거나 같음 → 이미 찾은 21 을 넘을 수 없음 → [0] 아래 전체를 거름 (③). 더 갈 곳이 없으므로 종료.
