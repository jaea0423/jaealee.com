01정렬 알고리즘 (Sorting)

시험 ★★☆

정렬은 리스트·배열의 값을 오름차순(또는 내림차순)으로 다시 배치하는 것입니다.

그냥 하면 모든 쌍을 비교하면서 교환해 나가야 해서 비교·교환을 아주 많이 하게 됩니다.

이 단원의 목표

비교·교환 횟수를 최소화하는 정렬 알고리즘을 설계하는 것.

파이썬 기본 함수

Pythonlist.sort
A = [2, 1, -2, -7]
A.sort()                # 오름차순 → A = [-7, -2, 1, 2]
A.sort(reverse=True)    # 내림차순 → A = [2, 1, -2, -7]
필기 오류 — 고쳐서 반영

필기에 오름차순은 A.sort(reverse=True) 로 되어 있는데, reverse=True 는 내림차순입니다. 바로 옆에 적은 결과 [2, 1, −2, −7] 도 큰 값부터라 내림차순이 맞습니다.

A.sort() 는 A 자체를 바꾸고 아무것도 반환하지 않습니다. 원래 리스트는 두고 정렬된 새 리스트를 받으려면 sorted(A) 를 씁니다.

필기 원문
정렬 알고리즘 (Sorting) : 리스트 / 배열 값을 오름차순(또는 내림차순)으로 재배치 예를 들어 A = [ 2, 1, -2, -7 ] 이 있다고 하면 이 배열을 정렬한다고 하면 (비교 → 교환)을 무지하게 많이 하게 됨(모든 쌍들을 비교하면서 교환해나감 → 정렬 완성 목표 : 비교, 교환 횟수 최소화하는 정렬 알고리즘을 설계 (우리의 목표임) ⇒ A.sort() # A = [ -7, -2, 1, 2 ] 이렇게 정렬되는 함수 오름차순은 A.sort(reverse=True) # A = [2, 1, -2, -7 ] 이렇게 정렬됨 파이썬에서 기본 제공되는 함수임

02성질 1 — stable / unstable

시험 ★★★

정렬 알고리즘을 배울 때마다 stable 한지 unstable 한지를 확인합니다. 기준은 같은 값을 가진 원소들의 순서입니다.

뜻A = [3₁, 7, 3₂, 9] 의 결과
stable
(안정 정렬)		같은 값끼리 입력 순서를 유지함을 보장항상 [3₁, 3₂, 7, 9]
unstable
(불안정 정렬)		입력 순서 유지를 보장하지 않음[3₂, 3₁, 7, 9] 가 될 수 있음
용어 바로잡기

필기의 "stable(정적) / unstable(유동적?)" 은 보통 안정 정렬 / 불안정 정렬이라고 합니다. 또 unstable 은 "순서가 반드시 뒤집힌다"가 아니라 "유지된다는 보장이 없다"는 뜻입니다. 우연히 순서가 유지될 수도 있습니다.

stable 이 왜 필요한가

학생을 이름순으로 정렬해 둔 뒤 점수로 다시 정렬하면, stable 정렬은 점수가 같은 학생끼리는 이름순이 그대로 남습니다. 즉 여러 기준으로 차례로 정렬할 때 앞의 결과를 깨지 않습니다. 파이썬의 sort() 는 stable 입니다.

필기 원문
성질 1. stable(정적) / unstable(유동적?) (이 알고리즘이 stable한지 unstable한지 확인) A = [ 3, 7, 3, 9 ] 이런 리스트가 있다고 생각하면 3, 3 처럼 이렇게 같은 값을 가진 입력이 있으면 각각 3_1, 3_2 라고 생각하면 정렬을 마친 후 당연히 A = [ 3, 3, 7, 9 ]가 될텐데 A = [ 3_1, 3_2, 7, 9 ] 가 된다면 이를 stable하다고 할 수 있음(정렬 후 같은 순서로 나열) 반대로 이를 보장하지 않은 Unstable(A = [ 3_2, 3_1, 7, 9 ])

03성질 2 — in-place / not in-place

시험 ★★★

알고리즘이 동작할 때 추가 메모리를 얼마나 쓰는지로 나눕니다.

추가 메모리예
in-placeO(1)원래 리스트 안에서 자리만 바꿈
not in-placeO(n) (교수님 예시)또 다른 리스트를 마련해 하나씩 채워 넣음

그래서 in-place 성질을 희망합니다 — 같은 일을 메모리를 덜 쓰고 하는 좀 더 좋은 알고리즘입니다.

추가 메모리가 O(log n) 이면? — 질문하신 부분

정의가 책마다 다릅니다. 엄격한 정의는 O(1) 만 in-place 로 봅니다. 하지만 재귀 호출 스택으로 O(log n) 만 더 쓰는 알고리즘(대표적으로 퀵 정렬)도 리스트를 새로 만들지 않고 제자리에서 바꾸기 때문에 in-place 로 분류하는 경우가 많습니다. 교수님 정리 글(10/1 결석자용)의 정의는 “필요한 추가 메모리가 O(1) 인가” 입니다. 그리고 일반 퀵 정렬은 O(N) 메모리가 필요해 in-place 가 아니고, 그래서 수업에서 In-place quick-sort 를 따로 본다고 하셨습니다. 재귀 스택 O(log n) 을 어떻게 세는지는 글에 없습니다 — 확인 필요에 적어 두었습니다.

필기 원문
성질 2. in-place / not in-place (이 알고리즘이 동작할 때 추가 메모리를 얼마나 사용하느냐. 추가 메모리가 O(1) 필요하다면 in-place라면 in-place, O(n)이라면 not in-place. 그러면 O(logn)은? 낫인플레이스인가? 교수님은 예시로 O(n)을 알려주셨어) 예를 들어서 정렬시 또 다른 리스트를 마련해서 하나씩 채워넣는다면 not-in place가 되는거임 그래서 우리는 in-place 성질을 희망함(좀 더 좋은 알고리즘)

04선택 정렬 (Selection Sort)

시험 ★★★

기본 정렬 알고리즘 세 가지 중 첫 번째입니다. 간단하지만 느립니다. n − 1 라운드 동안 라운드마다 숫자 하나의 위치를 확정합니다.

개요수업 판서 (의사코드 이전 단계)
for each round:
    find maximum           # n − 1 번 비교
    swap max and last      # 교환 1 번 (상수)

예시 — A = [12, 4, 9, 10, 21, 3, 8, 0]

1라운드는 21 을 찾아 마지막 0 과 바꾸고(비교 n − 1 번), 2라운드는 남은 7칸에서 12 를 찾아 그 구간의 마지막 8 과 바꿉니다(비교 n − 2 번). 이렇게 n − 1 라운드를 하면 끝납니다.

횟수 세기

기본 개념 :  1 + 2 + … + n = n(n + 1)2

비교 수 :  (n − 1) + (n − 2) + … + 1 = (n − 1)n2
교환 수 :  n − 1                       ← 라운드마다 1 번

⇒ O(n²)

교환은 n − 1 번으로 적지만, 최댓값을 찾는 비교가 n² 에 비례해서 전체가 O(n²) 입니다.

필기 원문
정렬 알고리즘을 살펴보자 기본 알고리즘 : Selection ⇒ 간단하지만 느리다(Selection 대소문자 잘 몰라. 너가 알아서 적절히 넣어줘. 상황이나 역할에 맞게) Selection ⇒ 간단함, 느림 ⇒ n-1 round 동안 각 round 마다 숫자 하나의 위치 결정 예를 들어서 A = [ 12 4 9 10 21 3 8 0 ] 이 있다고 하면(콤마 귀찮아서 안썼음) (지금 작성하는 코드는 수도코드까지는 아니야) for each round: - find maximum # n - 1 번 연산 - swap max and last # 상수 1 연산 첫 번째 라운드 먼저 가장 맥시멈을 찾는다. 21 # n-1번 연산 찾은 맥스(21)이랑 라스트(0)을 바꿈 두 번째 라운드 맥시멈 12 # n-2번 연산 맥스 라스트 바꿈 (이거 절차별로 보여주면 좋을 거 같아) 쭉 라운드 하면 n-1번의 라운드가 존재하게 됨 (1 + 2 + ... + n = n(n+1)/2) 기본 개념 비교 수 : (n-1) + (n-2) + ... + 1 = (n-1)n/2 교환 수 : n-1 결국 수행시간은 O(n^2) 소요

05버블 정렬 (Bubble Sort)

시험 ★★★

선택 정렬과 똑같이 간단하고 느리며, n − 1 라운드 동안 라운드마다 숫자 하나의 위치를 확정합니다. 차이는 최댓값을 찾아서 한 번에 옮기지 않고, 이웃끼리 바꾸면서 끝까지 밀고 간다는 것입니다.

for each round:
    이웃한 두 값씩 비교 → 앞이 크면 교환
    → 최댓값이 마지막으로 이동

비교 :  (n − 1) + (n − 2) + … + 1 = (n − 1)n2       ← 입력과 상관없이 항상
교환 :  (n − 1) + (n − 2) + … + 1 = (n − 1)n2       ← 최악 (비교할 때마다 바꾸는 경우)

교환 수가 "최악"인 이유

버블 정렬은 앞이 클 때만 바꿉니다. 그래서 교환 수는 입력에 따라 달라지고, (n − 1)n2 은 매 비교마다 바꾸는 최악(거꾸로 정렬된 입력)의 값입니다. 위 예시는 교환이 6 + 3 + 3 + 3 + 2 + 1 + 1 = 19 번으로 최악(28 번)보다 적습니다. 비교 수는 항상 (n − 1)n2 이라 결과는 그대로 O(n²) 입니다.

선택 정렬과 차이

둘 다 비교는 (n − 1)n2 로 같습니다. 교환이 다릅니다 — 선택 정렬은 라운드마다 1 번(총 n − 1), 버블 정렬은 이웃끼리 바꾸며 밀고 가서 최악 (n − 1)n2 번입니다.

06삽입 정렬 (Insertion Sort)

시험 ★★★

마찬가지로 간단하고 느리며 n − 1 라운드입니다. 왼쪽에 정렬된 부분을 한 칸씩 넓혀 가면서, 새로 추가되는 값을 들어갈 자리에 끼워 넣습니다.

개요수업 판서
for each round:
    insert a value         # 정렬된 앞부분에 새 값 하나를 끼워 넣음

라운드별 진행

필기 오타 — 고쳐서 반영

10라운드에서 4 9 12 10 → 3라운드입니다. 1라운드에 4, 2라운드에 9, 3라운드에 10 을 넣습니다. 원소가 8개라 라운드는 7까지만 있습니다.

한 라운드에서 하는 일

[  정렬된 i 개  ][ i+1 번째 ]

i+1 번째 값을 정렬된 i 개 쪽으로 끼워 넣을 때
→ 뒤에서부터 비교해 가며, 자신보다 작거나 같은 값이 나올 때까지 비교

횟수 세기

비교 :  1 + 2 + … + (n − 1) = (n − 1)n2       ← 최악
교환 :  1 + 2 + … + (n − 1) = (n − 1)n2       ← 최악

⇒ O(n²)
이것도 "최악"의 횟수

i 번째 라운드에서 최대 i 번 비교합니다 — 새 값이 정렬된 부분의 모든 값보다 작을 때(위 예시의 3, 0). 반대로 이미 정렬된 입력이면 라운드마다 1 번만 비교하고 끝나서 최선은 비교 n − 1 번입니다. 세 알고리즘 중 정렬된 입력에서 빨라지는 것은 삽입 정렬뿐입니다.

필기 원문
마지막 기본 알고리즘 : insert 얘도 마찬가지로 똑같이 간단하고 느리고, n-1 round 동안 각 round 마다 숫자 하나의 위치 결정 한다는 성질은 같음 for each round: - insert a value 1round에서 4 12 2라운드에서 4 12 9 에서는 9를 비교하면서 자기가 들어갈 자리를 찾음 → 4 9 12 10라운드에서 4 9 12 10 에서는 10을 비교하면서 자기가 들어갈 자리를 찾음 → 4 9 10 12 계속 범위를 확장해나가면서 추가되는 요소를 넣을 위치를 찾는 거임 [ i 개 ][i+1] i+1을 i개 쪽에 삽입하려고 하면(i개는 정렬이 완성된 상태) 비교해가면서 자신보다 작거나 같은게 나올 때 까지 비교 비교횟수 : 1 + 2 + ... + (n-1) 교환 : 1 + 2 + ... + (n-1) 비교 : (n-1)n/2 교환 : (n-1)n/2 ⇒ O(n^2)의 시간복잡도를 가짐

① 선택 정렬

Pythonselection sort
def selection_sort(A):
    n = len(A)
    for last in range(n-1, 0, -1):   # 뒤에서부터 한 칸씩 자리 확정
        m = 0
        for i in range(1, last+1):   # 0 ~ last 에서 최댓값 위치 찾기
            if A[i] > A[m]:
                m = i
        A[m], A[last] = A[last], A[m]     # 최댓값과 마지막 칸 교환 — 멀리 떨어진 두 칸
stableX — 마지막 줄의 교환이 멀리 떨어진 두 칸을 바꾸기 때문에, 바뀌는 원소가 같은 값을 건너뛰어 순서가 뒤집힐 수 있다.
반례 [5₁, 5₂, 1] → 1라운드에 5₁ 과 1 을 교환 → [1, 5₂, 5₁] (5₂ 가 5₁ 앞에 남음)
in-placeO — A 안에서 교환만 하고, 추가로 쓰는 것은 변수 m, i, last 뿐이라 추가 메모리 O(1).

② 버블 정렬

Pythonbubble sort
def bubble_sort(A):
    n = len(A)
    for r in range(n-1):               # n − 1 라운드
        for j in range(n-1-r):         # 확정 안 된 부분만 이웃끼리 비교
            if A[j] > A[j+1]:          # 앞이 '더 클 때만' 교환 — 같으면 안 바꿈
                A[j], A[j+1] = A[j+1], A[j]
stableO — A[j] > A[j+1] 일 때만 교환하므로 같은 값끼리는 바꾸지 않는다. 이웃끼리만 바꾸니 같은 값을 건너뛰는 일도 없어 입력 순서가 유지된다.
in-placeO — A 안에서 이웃끼리 교환만 하므로 추가 메모리 O(1).

③ 삽입 정렬

Pythoninsertion sort
def insertion_sort(A):
    for i in range(1, len(A)):        # A[0..i-1] 은 이미 정렬된 상태
        x = A[i]                         # 이번에 끼워 넣을 값
        j = i - 1
        while j >= 0 and A[j] > x:     # x 보다 '큰' 값만 한 칸씩 뒤로 — 같으면 멈춤
            A[j+1] = A[j]
            j -= 1
        A[j+1] = x
stableO — A[j] > x 인 동안만 뒤로 밀고, 자신보다 작거나 같은 값을 만나면 멈춘다. 그래서 x 는 같은 값의 뒤에 들어가 입력 순서가 유지된다.
in-placeO — A 안에서 값을 한 칸씩 옮기고, 추가로 쓰는 것은 변수 x, j 뿐이라 추가 메모리 O(1).

Pythonquick sort
def quick_sort(A):
    if len(A) <= 1:                # 원소가 0개나 1개면 이미 정렬된 상태
        return A
    P = A[0]                         # 피벗 = 첫 번째 값
    S, M, L = [], [], []              # 새 리스트 3개 → not in-place 의 근거
    for x in A:                     # A 의 순서대로 하나씩 → stable 의 근거
        if P > x:   S.append(x)
        elif P < x: L.append(x)
        else:        M.append(x)
    return quick_sort(S) + M + quick_sort(L)   # + 는 리스트 이어 붙이기

11퀵 정렬 수행시간

시험 ★★★
T(n) = T(|S|) + T(|L|) + C·n
왜 C·n 인가 — 질문하신 부분

맞습니다. for x in A 는 피벗 자신까지 포함해 정확히 n 번 돌고, 한 번에 비교 몇 번과 append 한 번으로 상수 시간입니다. 그래서 C·n 입니다 (n − 1 이 아니라 n 번). 마지막 줄의 리스트 이어 붙이기도 길이에 비례하는 O(n) 이라 같이 C·n 에 들어갑니다.

worst case — 한쪽으로만 쏠릴 때

A = [5, 4, 3, 2, 1]      피벗 = 첫 값

[5, 4, 3, 2, 1]  →  S = [4, 3, 2, 1] ,  M = [5] ,  L = []
[4, 3, 2, 1]     →  S = [3, 2, 1]    ,  M = [4] ,  L = []
       ⋮                  한 번에 하나씩만 줄어듦

T(n) = T(n − 1) + C·n  =  O(n²)

전개는 생략하셨는데, 04-2 쪽지시험 대비의 A-3 과 같은 꼴입니다: Cn + C(n−1) + … + C·1 = C·n(n + 1)2 → O(n²).

이미 정렬된(또는 거꾸로 정렬된) 입력에서 첫 값을 피벗으로 잡으면 매번 이렇게 됩니다. worst-case 는 기본 정렬 세 가지와 같은 O(n²) 입니다.

best case = average case — 반반으로 잘 나뉠 때

T(n) = T(n2) + T(n2) + C·n
     = 2·T(n2) + C·n
     = O(n log n)            ← 04-2 의 정렬 점화식 (두 갈래 나무)
정리

퀵 정렬은 계산상 O(n²) (worst) 이지만, 실제로는 대부분 반반에 가깝게 나뉘어 평균 O(n log n) 으로 동작하고, 실질적으로 가장 빠른 정렬 알고리즘입니다.

def quick_sort(A, first, last):
    # A[first] ~ A[last] 구간을 제자리에서 정렬한다. 처음 호출은 quick_sort(A, 0, len(A)-1)
    if first >= last:                    # 원소가 0개나 1개인 구간 → 할 일 없음 (재귀 종료)
        return
    P = A[first]                          # 피벗 = 구간의 첫 값
    left = first + 1                      # 왼쪽에서 오른쪽으로 훑는 포인터
    right = last                          # 오른쪽에서 왼쪽으로 훑는 포인터

    while left <= right:                  # 아직 확인 안 한 칸이 남아 있는 동안
        while left <= last and A[left] < P:     # P보다 작은 값은 왼쪽에 있는 게 맞으니 지나감
            left += 1                     #   → P 이상인 값(오른쪽으로 가야 할 값)에서 멈춤
        while right > first and A[right] > P:   # P보다 큰 값은 오른쪽에 있는 게 맞으니 지나감
            right -= 1                    #   → P 이하인 값(왼쪽으로 가야 할 값)에서 멈춤
        if left <= right:                 # 두 포인터가 아직 엇갈리지 않았다면
            A[left], A[right] = A[right], A[left]   # 서로 잘못된 쪽에 있는 두 값을 맞바꿈
            left += 1                     # 바꾼 칸은 이제 맞는 쪽이니 한 칸씩 안으로
            right -= 1

    A[first], A[right] = A[right], A[first]   # 피벗을 '작은 쪽 끝(right)' 자리로 → 경계에 놓임
    quick_sort(A, first, right-1)        # 피벗 왼쪽 (P 이하) 정렬
    quick_sort(A, left, last)             # 피벗 오른쪽 (P 이상) 정렬
필기 코드에서 고친 곳

1. right 조건 — 판서는 A[right] < P 였다고 하셨는데, > 여야 합니다. right 는 오른쪽에서 출발해 P 보다 큰 값을 지나가야 합니다. < 로 하면 반대로 작은 값을 지나가고 큰 값에서 멈춥니다. 이 예시에 넣으면 right 가 출발점 10 에서 바로 멈추고(10 < 4 가 거짓), left 의 5 와 10 을 바꾼 뒤 두 포인터가 더 이상 움직이지 않아 끝나지 않습니다 (직접 실행해 확인). 적어 주신 진행 "10 → 7 → 3 에서 멈춤" 도 > 일 때의 동작이라, 판서 실수이거나 받아 적을 때 바뀐 것으로 보입니다.

2. right -+ 1 → right -= 1, fist → first (오타).

3. 맨 앞에 if first >= last: return 추가. 필기 코드에는 재귀를 멈추는 줄이 없어서, 원소가 1개 이하인 구간에서도 계속 자기 자신을 부르게 됩니다.

4. 교환 뒤 left += 1, right -= 1 추가 (보충). 교수님 정리 글의 코드에도 이 두 줄이 없습니다. 그대로 실행하면, left 와 right 가 피벗과 같은 값에서 같이 멈췄을 때 두 칸을 계속 바꾸기만 하고 포인터가 안 움직여 무한 반복됩니다. 과제는 코드를 읽고 O·X 를 쓰는 것이라 영향이 없지만, 직접 짠다면 넣어야 합니다.

교수님 정리 글의 코드와 대조 (10/1 결석자용)

정리 글에 실린 코드를 그대로 옮기면 다음과 같습니다. 오른쪽 조건은 A[right] > p 로 위의 고친 코드와 같고, 재귀 호출 두 줄과 마지막 피벗 교환도 같습니다.

def quick_sort(A, first, last):
    p = A[first]
    left = first + 1, right = last
    while left <= right:
        while left <= last and A[left] < p:
            left += 1
        while right > first and A[right] > p:
            right -= 1
        if left <= right:
            A[left], A[right] = A[right], A[left]
    A[first], A[right] = A[right], A[first]
    quick_sort(A, first, right-1)
    quick_sort(A, left, last)

다른 점 두 가지. ① 교환 뒤 left += 1, right -= 1 이 없습니다. ② 재귀를 멈추는 if first >= last: return 이 없습니다.

이 코드를 그대로 실행한 결과입니다. 값이 모두 다르면 정렬이 됩니다. 피벗과 같은 값을 left 와 right 가 함께 만나면 끝나지 않습니다. 예: [2, 3, 2, 4], [2, 2, 2], 수업 예시, 재귀 중 [3, 2₁, 2₂] 구간. 다만 첫 분할 결과는 두 줄이 있든 없든 같아서 (수업 예시 → [2₂, 2₁, 3, 4, 6, 8, 5, 7, 10]), 제자리 퀵이 stable 이 아니라는 반례와 과제 답에는 영향이 없습니다.

A[last] ⇒ 정렬한다는 알고리즘임 # 첫번째 라운드는 quick_sort(A, 0, len(A)-1) P = A[first] left = first + 1 # 변수 설정 right = last # 변수 설정 ------ 갑자기 예시 나옴 A = [ 4 2_1 5 8 6 2 3 7 10 ] 4가 first pivot이 되고 2_1이 left가 되고 right는 10이 됨 firs는 4, last는 10 ------- while left <= right : # 더 훑을 요소가 있는지 보는거임 while left <= last and A[left] < P : # left가 넘치지는 않고 피벗보다 작으면 왼쪽에 있어야하는게 맞으니까 패스하면서 넘어가는 것임 left += 1 # left를 오른쪽으로 한칸 옮김 ------ 아까 그 예시에서 절차식으로 보여주면 좋을 거 같아 알아서 이해하기 쉽게 설명해주면 좋아 left가 옮겨가는 과정(첫 라운드)(5가 레프트가 됨) ------ while right > first and A[right] < P : # right(left의 반대) right -+ 1 #right을 왼쪽으로 한칸 옮김 ------ 계속 예시 기반으로 절차 보여주면 돼 시각화해서(주석도 개떡같이 적는 중이야 나는) right가 옮겨가는 과정(첫 라운드)(7이 right 됐다가 3이 right됨) ----- if left <= right # left가 right보다 여전히 왼쪽에 있다면(더 훑을 요소가 있다면) A[left], A[right] = A[right], A[left] # left와 right 둘 교체 # 끝나면 다시 큰 while로 돌아가서 더 훑을 요소가 있는지 확인함 ------ 다시 큰 while부터 돌아가는 절차 이어서 더 훑을게 남아있기 때문 left가 8이 되고 right 2가 됨 (2번째 훑음 완료) 더 훑을 요소가 있어서 left right 바꿔치기 더 훑을 요소가 있기 때문에 3번째 훑음 시작 left는 6이 되고 right는 6이 됨 더 훑을 요소가 있어서 left right 바꿔치기(사실 훑을 요소 없지만) 바꿔치기 다시 while문 4번째 훑음 시작 최종적으로 right이 한칸 더 움직이기 때문에 2가 되고 마지막 if(바꿔치기)와 while(재훑음)은 만족 안해서 끝남 A = [ 4 2 3 2 6 8 5 7 10 ] 이 되게 됨 그러면 다시 A = [ 4 / 2 3 2 / 6 8 5 7 10 ]으로 나눔 (in-place를 안하기 위한 발악) 우리가 원하는건 pivot이 2 3 2 랑 6 8 5 7 10 사이에 들어가는 게 목표임 이제 이 정렬이 끝나면 4(pivot)랑 2_2(right)을 바꿔주며녀 됨 ----- A[fist], A[right] = A[right], A[fist] # 자리 바꿔줌 ------ 최종적으로는 A = [ 2 3 2 4 6 8 5 7 10 ] 이 됨 모양은 A = [ 2(fist), 3, 2(right-1), / 4 / 6(left), 8, 5, 7, 10 ] ----- quick_sort(A, fist, right-1) quick_sort(A, left, last) 까지 하면 수도코드 끝 엄청 복잡하긴 한데 in-place하게 만들기 위한 노력임 주석 개떡같이 적었는데 야무지게 이해하기 쉽게 적어줘야해 stable한지 안한지에 따라서 2_1 2_2 이런식으로 아래첨자로 배열 시각화할 때 같이 적어줘 이제 이 바뀐 in-place quick_sort에 대해서 생각해보면 * in-place? ⇒ O (새로운 배열을 만들지 않고 자리를 계속 바꿔준거기 때문) * stable? ⇒ 다들 각자 생각해서 이거까지가 10월 8일 과제(아니 그래서 quick_sort가 나온다는거같아. 총 4개) 즉 10월 8일에 Bubble, selection, insertion, in-place quick_sort 이 4가지의 알고리즘 수도코드를 제공해주고 각 문제별로 in-place인지 stable인지 OX풀고 간략한 이유 설명
