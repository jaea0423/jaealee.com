01알고리즘·시간복잡도

알고리즘의 정의

특정 작업을 수행하기 위한 과정을 분명하게 기술한 것 (재료 = 자료구조)

목표: 알고리즘의 효율적 설계 & 효율성 분석 → 문제 해결 사고 능력 증가

효율성 = 시간

알고리즘 입장에서 "효율성"은 '시간'의 입장에서 보고, 이를 시간복잡도(Time Complexity)로 표현합니다.

알고리즘 수행 시간이란, 입력의 크기에 대해 시간이 얼마나 걸리는지를 뜻합니다.

입력의 크기

  • 정렬: 리스트 A = [ ... ]가 있을 때, 리스트의 크기는 |A| (요소의 수)
  • 팩토리얼: 5! = 5×4×3×2×1 → 자연수의 크기(= 입력의 크기)

입력의 크기를 미지수 n으로 두고, 시간이 얼마나 걸리는지를 n에 대한 함수로 표현합니다. 보통 f(n) 또는 T(n)이라고 표기합니다.

점근적 분석

예를 들어 f(n) = T(n) = 2n2 + 3nn 이라고 하면, 입력의 크기가 충분히 크다고 가정합니다.

→ 점근적 분석(Asymptotic Analysis): limn→∞ f(n)

limn→∞ 2n2 + 3nn = 2n + 3 → n이 커지면, f(n)이 2n+3의 비율로 증가한다는 것을 의미합니다.

n의 차수가 중요하고, 상수 등은 중요하지 않습니다. 2n + 3 = O(n)으로 표기합니다 (최대 차수가 1차이기 때문). 이걸 빅오(big-O) 표기라 합니다.

가정

f(n), T(n)은 양수로 가정합니다 (시간에 대한 식이기 때문).

이런 표기법들을 통틀어 점근적 표기법(Asymptotic Notation)이라고 합니다. 기존에는 빅오 표기만 배웠지만, 오늘은 여기에 세타(Θ)와 오메가(Ω)를 추가로 배웁니다.

02세타 표기법

Θ(f(n)): 최고차항의 차수가 f(n)과 일치하는 모든 함수의 집합입니다. (예: Θ(n²) → 대략 n²에 비례하게 시간이 소요됨)

  • 5n² + 4n ∈ Θ(n²)
  • 5n² + n log n ∈ Θ(n²) (log n이 n보다 작아서, 최고차항은 n²)

"=" 는 사실 포함 기호

원래는 포함 기호(∈)를 써야 하지만, 관례상 "=" 기호를 씁니다. (Θ, O, Ω 모두 마찬가지로, 실제로 "같다"가 아니라 "포함된다"는 의미로 "="를 씁니다.)

  • 5n + 4 ≠ Θ(n²)
  • 5n³ + 4n² ≠ Θ(n²)

또한 포함 기호이기 때문에 순서가 중요합니다 — Θ(n²) = 5n² + 4n 처럼 거꾸로 적으면 안 됩니다.

03빅오·오메가 표기법

빅오 표기법 — "최악의 경우 이 정도가 걸린다"

가장 많이 쓰이는 표기법입니다. O(f(n)): 최고차항의 차수가 f(n)과 같거나 더 작은 함수의 집합. 최악의 경우를 봅니다.

Θ vs O 한 줄 차이

Θ는 "정확히 이 정도"(위아래로 꽉 조인 범위), O는 "최악이라도 이 정도까지는 안 넘는다"(위쪽 한계만).

  • 5n² + 4n = O(n²)
  • 5n² + 4n log n = O(n²)
  • 5n + 4 = O(n²) — 차수 1 ≤ 2라서 조건을 만족 (단, O(n)이 더 타이트한 정확한 표기)
  • 5n³ + 4n² ≠ O(n²)

"이것보다 나빠지지는 않을 거야" — 이 표기법과 정반대되는 것이 오메가 표기법입니다.

오메가 표기법 — "최소 이 정도는 걸린다"

Ω(f(n)): 최고차항의 차수가 f(n)과 같거나 더 큰 함수의 집합.

  • 5n² + 4n = Ω(n²)
  • 5n² + 4n log n = Ω(n²)
  • 5n + 4 ≠ Ω(n²) — 차수 1 ≥ 2가 성립하지 않아서 불만족
  • 5n³ + 4n² = Ω(n²)

04재귀 · 예시1 Sum(n)

재귀 함수의 정의

함수(알고리즘) 내부에서 한 번 이상 자신의 함수(알고리즘)를 다시 호출하는 함수(알고리즘)

이 표기법들을 이용해서 실제 알고리즘을 분석해봅니다.

예시 1 — Sum(n) = 1 + 2 + ... + n

Sum(n) = 1 + 2 + ... + (n−1) + n 에서, 1 + 2 + ... + (n−1) 부분이 곧 Sum(n−1)입니다.

Pythonsum_recursive.py
def Sum(n):
    if n == 1: return 1
    return Sum(n-1) + n

전개 예시: Sum(4) = Sum(3)+4 = Sum(2)+3+4 = Sum(1)+2+3+4 = 1+2+3+4

시간복잡도 분석

Python주석 포함
def Sum(n):
    if n == 1: return 1  # 상수시간 소요 (==, return)
    return Sum(n-1) + n  # T(n-1) 소요

점화식: T(n) = T(n−1) + C (상수) ← an = an−1 + C 형태

T(n) = T(n−1) + C
     = T(n−2) + C + C
     = T(n−3) + C + C + C
     ...
     = T(1) + (n−1)·C

T(1)은 return 1이기 때문에 상수시간(= C) 소요입니다.

= C + (n−1)·C = Cn → T(n) = Cn = O(n)

재귀 알고리즘 분석 절차

  1. base case 확인: T(1) = C (또는 1)
  2. 재귀 호출 분석: T(n) = 점화식 → 전개 → T(n) = O(?)
필기 원문
이 표기법들을 이용하여 알고리즘 분석 재귀(recursion) 함수 / 알고리즘 ⇒ 함수(알고리즘) 내부에서 한번 이상 자신의 함수(알고리즘)를 다시 호출하는 함수(알고리즘) 예시 1_ 1+2+3+4+...+n 를 수행하는 재귀 알고리즘 Sum(n) = 1 + 2 + ... + (n-1) + n +n 전까지 밑줄. Sum(n-1) ⇒ def Sum(n) : if n == 1 : return 1 return Sum(n-1) + n Sum(4) = Sum(3)+4 = Sum(2)+3+4 = Sum(1)+2+3+4 = 1+2+3+4 def Sum(n) : if n == 1 : return 1 #상수시간 소요(==, return) return Sum(n-1) + n #T(n-1)소요 T(n) = T(n-1) + C(상수) <= 점화식(a_n = a_(n-1) + C) = T(n-2) + C + C = T(n-3) + C + C+ C ... = T(1) + (n-1)*C T(1)은 return 1이기 때문 상수시간 소요 = C + (n-1)*C = C + (n-1)*C = Cn T(n) = Cn T(n) = O(n) 재귀 알고리즘 : 1. n == 1 확인 : base case. T(1) = 1 or C 2. 재귀 호출 : T(n) = 점화식 ⇒ 전개. T(n) = O(?)

05재귀 · 예시2 Sum(a,b)

Sum(a, b) = a + (a+1) + ... + (b−1) + b (가정: a ≤ b)

Sum(3,8) = 3+4+5+6+7+8은 Sum(3,7)+8 처럼 하나씩 줄여도 풀 수 있지만, 절반으로 나눠서 Sum(3,5) + Sum(6,8)로도 풀 수 있습니다. (m = ⌊(3+8)/2⌋ = 5)

Pythonsum_range.py
def Sum(a, b):
    if a == b: return a
    if a > b: return 0
    m = (a + b) // 2  # 중간값 정하기
    return Sum(a, m) + Sum(m+1, b)  # 재귀 호출, T(n/2)+T(n/2)

점화식: T(n) = 2T(n/2) + C, T(1) = C

n = 2k라고 가정합니다 (정확한 값이 아닌 점근적 분석이라 문제없음).

T(n) = 2·T(n/2) + C
     = 2·(2·T(n/2²) + C) + C = 2²T(n/2²) + 2C + C
     = 2³T(n/2³) + 2²C + 2C + C
     ...
     = 2k·T(n/2k) + 2k-1C + 2k-2C + ... + 2C + C
     = 2k·C + C·(1 + 2 + ... + 2k-1)

등비수열의 합 — 초항 a, 공비 r, 항 개수 n개일 때 합 = a(rn − 1)r − 1

1 + 2 + ... + 2k-1 = 1·(2k − 1)2 − 1 = 2k − 1

T(n) = 2k·C + (2k − 1)·C
     = 2k·C + 2k·C − C
     = 2Cn − C   (n = 2^k 이므로)

따라서 Sum(a, b) ⇒ T(n) = 2Cn − C = O(n)

표기 수정 — 단순 오타로 판단해 고침

전개 3번째 줄 끝의 "... + 2C + 1"은 각 항이 전부 C의 배수인 흐름과 맞지 않아 "... + 2C + C"로 고쳤습니다. 바로 다음 줄의 C·(1+2+...+2k-1) 식과도 이렇게 맞아야 앞뒤가 일치합니다.

def reverse(A):
    if len(A) <= 1: return A
    return reverse(A[1:]) + [A[0]]

방법 2 — 양 끝 교체

reverse(A, Start, Stop) — A[Start]와 A[Stop−1]을 교체하고, 그 사이 범위로 좁혀서 재귀 호출: reverse(A, Start+1, Stop−1)

의사코드reverse 방법2
def reverse(A, Start, Stop):
    if Start >= Stop -1: return          # base case
    A[Start], A[Stop-1] = A[Stop-1], A[Start]   # 교체는 상수시간
    reverse(A, Start+1, Stop-1)              # 재귀는 반복

교체는 상수시간, 재귀는 반복됩니다. 재귀마다 앞뒤 한 개씩 총 2개씩 범위가 줄어듭니다.

T(n) = T(n−2) + C   # 재귀마다 앞뒤 한 개씩 총 2개 사라짐
     = T(n−4) + C + C
     ...
     = T(1) + (n/2)·C   # n/2개가 빠져나갔을 때
     = C + (n/2)·C

T(n) = O(n)
