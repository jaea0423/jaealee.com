1. 그리디 방법과 귀류법9주차 2차시

그리디 방법
현재 상태에서 가장 좋은(탐욕스러운) 선택(= greedy 전략)을 반복해서 해(= 답)를 구성하는 방법
greedy
탐욕스러운

지금까지 배운 방법과 비교

방법방식특징
분할 정복 (Divide and Conquer)큰 문제 → 작은 문제로 나눠 재귀 호출호출 때 같은 것을 다시 계산 → 비효율
동적 계획법 (Dynamic Programming)큰 → 작은 문제는 같음, 작은 문제의 답을 DP 테이블에 저장 후 다시 사용다시 계산하지 않음 → 비효율 줄임
그리디 방법 (Greedy Method)현재 상태에서 가장 좋은 선택을 반복선택을 되돌리지 않음 → 최적이라는 증명 필요

그리디로 푸는 순서

  1. 그리디 전략을 먼저 유추한다: 어떤 선택이 최적일까?
  2. 그 전략으로 답을 구한다.
  3. 선택한 전략이 항상 최적 해를 보장한다는 것을 증명해야 그 방법이 최적이라고 말할 수 있다. 증명에는 귀류법을 쓴다.
선수 지식: 귀류법 시험 범위가 아니라 그리디 증명을 이해하기 위한 도구

귀류법(proof by contradiction): 어떤 명제가 참임을 증명하고 싶을 때, 결론을 부정해서 모순이 발생함을 보임으로써 간접적으로 그 결론이 성립함을 보이는 방법

결론 부정 (가정) → 전개 → 모순 → 가정이 틀림 → 결론 참

그리디 증명에서 가정은 "그리디 전략으로 구한 해는 최적이 아니다".

유리수: 분수 nm 로 나타낼 수 있는 수 (n, m 은 자연수, 서로소)   무리수: 분수로 나타낼 수 없는 수   서로소: 약분이 안 되는 수 (최대공약수 1)

예: √2 는 무리수이다
  1. 가정
    √2 는 유리수이다 → √2 = nm (n, m 은 자연수, 최대공약수 1)
    결론을 부정
  2. 전개
    2m2 = n2 → n2 은 2의 배수 → n 도 2의 배수
    자연수를 제곱한 것이 2의 배수면 그 수도 2의 배수 (n 은 자연수)
  3. n = 2k 대입 → 2m2 = 4k2 → m2 = 2k2 → m2 은 2의 배수 → m 도 2의 배수
  4. 모순
    n, m 둘 다 2의 배수 ↔ 서로소 (최대공약수 1)
  5. 결론
    가정이 잘못되었다 → √2 는 무리수이다

3. 하루에 할 수 있는 일의 개수9주차 2차시, 예제 2

문제
하루에 할 수 있는 일의 개수를 최대로
예시
일 5개의 소요시간 A = [2, 1, 4, 6, 3] (시간 단위, 주어짐), 하루에 일하는 시간 T = 9
전략
소요시간이 적은 일부터 하기 (최대한 많은 개수를 해야 하므로)

동작

  • 1 + 2 + 3 + 4 에서 4 는 불가능 (하루 9시간을 넘어감) → 1 + 2 + 3 만 가능 → 최적 답은 3개
  • 다른 것도 가능: 1 + 3 + 4 = 8시간, 1 + 2 + 4 = 7시간 → 그래도 일의 개수는 3개
  • 일의 시간이 아니라 일의 최대 개수가 중요

최적성 증명 (귀류법)

전략: 적게 걸리는 일부터 센다. 그리디로 가능한 일 3개를 a1, a2, a3, 그다음으로 짧은 일을 a4 라고 하자.

적게 걸리는 일부터 하는 전략은 최적이다
  1. 가정
    그리디 전략으로 나온 답이 최적해가 아니다 → 최적해를 b1, b2, b3, b4 라고 하자 (3개보다 더 있음, 오름차순)
    a1, a2, a3 이 b1 ~ b4 가 아니다
  2. 기호
    X = a1 + a2 + a3 (전체 소요시간),   Y = b1 + b2 + b3
  3. ①
    X + a4 > T
    그래서 그리디 전략으로 4번째를 넣지 못함
  4. ②
    Y + b4 ≤ T
    b1 ~ b4 가 최적해라고 했으므로 성립해야 함
  5. ③
    X ≤ Y
    a1, a2, a3 은 시간이 가장 적게 걸리는 3개를 모아 놓은 것
  6. ④
    a4 ≤ b4
    그리디 전략은 최소로 걸리는 것부터 고름 → a4 는 4번째로 작은 값
  7. ⑤
    X + a4 ≤ Y + b4
    ③ 과 ④ 를 이용
  8. 모순
    ⑤ 와 ② → X + a4 ≤ T  ↔  ① X + a4 > T
  9. 결론
    이 모순 때문에 가정이 틀렸다 → 그리디 해가 최적해이다

4. 강의실 배정10주차 1차시, 예제 3

문제
되도록 많은 강의를 한 강의실에 배정 (강의의 개수를 최대로)
입력
시작 시간 S 와 끝 시간 F 가 리스트로 주어짐 (i 번째 강의 = S[i] ~ F[i])
i012345678910
S130535688212
F4567891011121314

수평선 위에 그리기

0 ~ 14 의 수평선 위에 강의를 선으로 나타낸다. 겹치는 강의만 층을 다르게 하고, 아래부터 채운다 (0번이 가장 아래, 3번은 자리가 있으므로 0번과 같은 층).

최적의 답은 0, 3, 7, 10 강의를 하는 4개가 최대이다. 1, 3, 7, 10 등 다른 경우도 있지만, 어떤 강의인지보다 개수가 중요하다.

그리디 전략 후보 (정답이 아니라 가능한 것을 생각)

번호전략판단
1소요시간이 적은 강의부터 배정a 와, 붙어 있는 b, c 가 있을 때 겹치는 2개(b, c)를 고르는 것이 더 이득이어도 a 를 먼저 골라 b, c 를 못 고름 → 별로
2빨리 시작하는 강의부터 배정b, c, d 를 고를 수 있는데 먼저 오는 a 를 골라 버림 → 별로
3가장 적게 겹치는 강의부터 배정강의별로 몇 개가 겹치는지 세서 배정
4빨리 끝나는 강의부터 배정남아 있는 시간이 많게 → 이 문제의 답 (최적인 전략)

1, 2번 전략은 반례가 있기 때문에 별로이다.

4번 전략의 알고리즘

pseudocode빨리 끝나는 강의부터 배정
1. F 값의 오름차순으로 정렬 (sorting)    # O(n log n)
2. L = [0], k = 0                        # L: 선택한 강의의 집합
                                         # k: 가장 최근에 배정을 마친 강의 인덱스
3. for i in range(1, n):
       if F[k] <= S[i]:
           L.append(i), k = i
4. return L / len(L)                     # 정하기 나름
  • 1번 정렬: O(n log n) (정렬은 이것이 최적, 이보다 좋을 수 없음)
  • 3번 for 문: O(n)
  • 따라서 소요시간은 O(n log n)

0번부터 보면서, 마지막으로 배정한 강의가 끝나는 시간보다 뒤에 시작하는 강의를 고른다. 0번(끝 4) → 3번(시작 5, 끝 7) → 7번(시작 8, 끝 11) → 10번(시작 12).

최적성 증명 (귀류법)

그리디 전략으로 구한 해: (0, 3, 7, 10). 강의는 끝나는 시간 순으로 정렬되어 있다.

빨리 끝나는 강의부터 배정하는 전략은 최적이다
  1. 가정
    (0, 3, 7, 10) 은 최적해가 아니다 → 4개가 최적해가 아니라는 것은 최소 5개가 있다는 것 → 최적해를 a1, a2, a3, a4, a5 라고 하자 (서로 겹치지 않음)
    귀류법으로 증명하기 위해 부정으로 가정
  2. a1 → 0
    전체 중 가장 빨리 끝나는 강의는 0번 → 0번이 a1 보다 먼저 끝남 → a1 을 0 으로 대체 가능 → (0, a2, a3, a4, a5)
    그리디 전략이 가장 빨리 끝나는 강의를 골랐으므로 (정렬되어 있음)
  3. 집합
    G1: 0번 강의와 겹치지 않는 강의들의 집합,  A1: a1 강의와 겹치지 않는 강의들의 집합 → A1 ⊂ G1
    a1 보다 앞에서 끝나는 강의는 있을 수 없음 (그리디 전략이 가장 먼저 끝나는 0번을 골랐으므로) → a1 과 겹치지 않는 강의는 0번과도 겹치지 않음
  4. a2 → 3
    3번 = G1 중 가장 빨리 끝나는 강의 (그리디 전략) → G1 이 A1 을 포함하므로 A1 중에 3번보다 빨리 끝나는 강의는 없음 → a2 를 3 으로 바꿔도 됨
  5. 연쇄
    이것을 연쇄적으로 하면 a3 → 7, a4 → 10 → (0, 3, 7, 10, a5)
  6. 모순
    가정대로라면 10번보다 뒤에 시작하는 a5 가 존재 → for i in range(1, n) 은 모든 인덱스를 훑으므로 그리디 전략이 a5 를 안 골랐을 수가 없음 → 그런데 구한 해에 a5 가 없음
  7. 결론
    가정은 모순 → 빨리 끝나는 강의 순서로 가능하게 넣는 전략 = 최적

5. Huffman 코딩10주차 1, 2차시, 예제 4

문제
문자를 비트로 표현하는 가변 길이 코드 만들기 — 전체 사용 비트 수를 줄이기

고정 길이 코드 (fixed-length code)

  • ASCII 코드: 키보드(영문 기준)의 문자를 컴퓨터는 2진수로 변환해야 함 — 'A' = 65, 'B' = 66, '+' = 43, 2진수로 8비트 ('A' = 01000001)
  • 하나의 문자를 무조건 8비트로 나타내므로 고정 길이 코드 → 영문 100자를 쓰면 800비트
  • 한글은 8비트로 부족해 16비트(2 bytes)를 씀 (유니코드)

가변 길이 코드 (variable-length code)

  • 영어 100자를 쓰면 모음 a, e, i, o, u 는 많이 나오고, 잘 안 쓰는 알파벳(y, x, z, q 등)은 적게 나옴 → 고정 길이 코드로 다 똑같이 8비트를 쓰면 비효율
  • 많이 나오는 문자에는 적은 비트, 적게 나오는 문자에는 많은 비트 → 가변 길이 코드

문자가 a ~ f 만 있고, 빈도수(나오는 횟수)를 세어 봤다고 하자. 빈도수를 다 더하면 100.

  • 문자 6개 → 3비트 필요 (23 개를 표현하는 것이 3비트) → 고정 길이: 100 × 3 = 300비트
  • 가변 길이: 1비트 43번, 3비트 41번 (13 + 12 + 16), 4비트 16번 (9 + 7) → 43 + 123 + 64 = 230비트 → 고정 길이보다 유용

prefix-free code

더 줄이려고 0, 1, 00, 01, 10, 11 로 배정하면 안 된다. 예를 들어 00101100 이 입력되면 앞의 00 을 aa 로 읽을지 c 로 읽을지 컴퓨터가 구분할 수 없다.

prefix-free
어떤 문자의 코드가 다른 문자 코드의 prefix(앞부분)가 아닌 코드

문제는 prefix-free code 를 찾으면서 전체 사용 비트 수를 어떻게 줄일지이다.

이진 트리로 나타내기

  • 루트에서 문자까지 온 길을 따라가면 코드 (예: e = 1101)
  • 리프 노드만 문자와 1 : 1 로 대응시키므로, 그 과정의 중간 노드는 문자가 아님 → 어떤 코드도 다른 코드의 prefix 가 될 수 없음 → 이진 트리를 만족하면 prefix-free 가 자동으로 만족

비용 cost(T)

문자 x, 빈도수 f(x), 비트 수 dT(x) (= 트리 T 에서 x 의 깊이)

cost(T) = Σx f(x) · dT(x)

이 값을 최소화하는 트리 T가 우리가 찾는 가변 길이 코드이다. 예시 트리의 cost = 230.

그리디 전략: 빈도수가 가장 적은 두 개씩 묶기

  • 빈도수의 오름차순으로 정렬: f 7, e 9, c 12, b 13, d 16, a 43
  • 빈도수가 가장 적은 2개를 묶어 트리를 만들고, 묶은 것은 두 빈도의 합으로 대표
단계묶는 두 개대표 빈도
1f (7) + e (9)16
2c (12) + b (13)25
3d (16) + fe (16)32
4cb (25) + dfe (32)57
5a (43) + cbdfe (57)100
  • 묶은 순서대로 트리를 만들면 앞 쪽의 트리 (왼쪽 0, 오른쪽 1) → cost 가 최소인 이진 트리 T = 1 : 1 로 대응하는 코드
  • 최적 트리는 하나만 있는 것이 아님 — 230비트가 최적인 것은 맞지만, 가지를 어디로 뻗느냐에 따라 트리가 달라질 수 있음

허프만 코딩 (Huffman Coding)

위의 방법을 Huffman Coding이라고 한다. 빈도수가 가장 많은 문자는 깊이를 가장 얕게 해서 사용하는 비트 수를 줄인다 → 전체 비트 수를 줄이는 것이 목표.

복습 예시 (10-2): a 3, b 7, c 15, d 20, e 40, f 60

단계묶는 두 개대표 빈도
1a (3) + b (7)10
2ab (10) + c (15)25
3d (20) + abc (25)45
4e (40) + dabc (45)85
5f (60) + edabc (85)145

의사코드

pseudocodeHuffman
def Huffman(T):                 # T: 이진 트리 (decode tree)
    while len(T) > 1:
        x = extract_min(T)      # T 에서 빈도수가 가장 적은 노드를 뺌
        y = extract_min(T)
        z = Node(left = x, right = y)
        f(z) = f(x) + f(y)      # f(): 빈도수
        insert(T, z)            # 새로 만든 노드를 트리에 넣음
    return T
함수동작 (T 를 min heap 으로 생각)시간
extract_min(T)루트(가장 작은 노드)를 꺼내고, 마지막 노드를 루트로 옮겨 루트부터 heapify_downO(h) = O(log n)
insert(T, z)z 를 T 의 마지막 노드 자리에 두고 heapify_upO(h) = O(log n)
  • min heap: 부모 노드가 자식보다 작은 이진 트리 → 루트가 가장 작음
  • while 을 n 번 수행 × 한 번에 O(log n) → 전체 O(n log n)

증명하려는 것

허프만 코딩의 그리디 전략이 최적인가: 허프만 코딩의 결과 T 가 최적 decode tree 를 무조건 찾는다 (정확히는 최적 decode tree 중 하나 — 여러 개일 수 있음).

증명은 보조 명제 2개를 먼저 보이고, 귀납법 안에서 귀류법을 쓴다.

보조 명제 1

명제
빈도수가 가장 작은 두 문자 x, y 를 가장 깊은 곳에 형제 노드로 갖는 최적 decode tree 가 항상 존재한다.
보조 명제 1의 증명 (귀류법)
  1. 가정
    명제의 부정: 그런 최적 트리가 하나도 존재하지 않는다 → 최적 트리 T 에서 가장 깊은 형제 a, b 는 x, y 가 아니고, x 는 중간 어딘가에 있음
  2. 교환
    T 에서 x 와 a 의 위치를 바꾼 트리를 T′ 이라 하자
    달라진 것은 x 와 a 뿐 → 나머지 리프의 비용은 같으므로 x, a 만 비교
  3. 비용 차
    cost(T) − cost(T′) = f(x)dT(x) + f(a)dT(a) − f(x)dT′(x) − f(a)dT′(a)
    교환했으므로 dT′(x) = dT(a), dT′(a) = dT(x)
  4. = (f(x) − f(a)) · (dT(x) − dT(a))
  5. 부호
    f(x) − f(a) ≤ 0,  dT(x) − dT(a) ≤ 0 → 곱 ≥ 0 → cost(T) ≥ cost(T′)
    x 는 빈도가 가장 작고, a 는 가장 깊은 곳에 있음
  6. 의미
    트리의 비용을 증가시키지 않고 x 와 a 를 바꿔 x 를 가장 깊은 곳에 둘 수 있다 → T′ 도 최적 → 같은 방법으로 y 와 b 를 바꾼 T″ 도 최적
  7. 모순
    T″ 은 x, y 를 가장 깊은 형제로 갖는 최적 트리 ↔ 그런 트리가 하나도 없다는 가정
  8. 결론
    가정이 틀렸다 → 명제가 참

귀납법의 틀

증명할 것: 허프만 트리 T 는 최적 decode tree 를 보장한다 (문자 개수 n 에 대한 귀납법).

단계내용
1. 바닥 조건n = 2: 허프만 트리는 최적이다 (자명)
2. 귀납 가정n < k 일 때 허프만 트리 T 는 최적이라고 가정 (증명할 필요 없음, 증명을 위한 가정)
3. 귀납 단계n = k 일 때 허프만 트리 T 가 최적임을 증명 → 증명 끝

2 일 때 성립 → 3 일 때 성립 → 4 일 때 성립 → … 모든 n 에서 성립. 바닥 조건은 자명하므로 3단계를 보이면 된다.

보조 명제 2

명제
문자 n 개에 대한 decode tree B 에서 가장 깊은 두 형제 노드 u, v (빈도수 상관없음)를 부모 w 하나로 합친 트리를 B′ (n − 1 개, f(w) = f(u) + f(v)) 이라 하면 cost(B) − cost(B′) = f(u) + f(v)
보조 명제 2의 증명
  1. 차이
    cost(B) − cost(B′) = f(u)dB(u) + f(v)dB(v) − f(w)dB′(w)
    달라진 것은 u, v 가 w 가 된 것뿐 → 나머지는 같아서 빠짐
  2. 대입
    = f(u)dB(u) + f(v)dB(u) − (f(u) + f(v))(dB(u) − 1)
    형제이므로 dB(v) = dB(u), 부모이므로 dB′(w) = dB(u) − 1, f(w) = f(u) + f(v)
  3. 전개
    = (f(u) + f(v))dB(u) − (f(u) + f(v))dB(u) + (f(u) + f(v))
  4. 결과
    = f(u) + f(v)
    형제 두 리프를 합치면 비용이 두 빈도의 합만큼 줄어든다

귀납 3단계: n = k 일 때 허프만 트리 T 는 최적

보조 명제 2 를 적용하면 cost(T) − cost(T′) = f(x) + f(y), 즉 cost(T′) = cost(T) − f(x) − f(y)

귀류법
  1. 가정
    T 가 최적이 아니다 → 다른 최적 트리 T″ 이 있다: cost(T″) < cost(T)
  2. 고르기
    보조 명제 1 에 의해 T″ 으로 x, y 가 가장 깊은 곳에 형제로 있는 최적 트리를 고를 수 있다
    처음에 먼저 증명한 명제를 여기서 씀
  3. 합치기
    T″ 의 x, y 를 부모 z 로 합친 트리를 T″ − {x, y} 라 하면 (문자 k − 1 개, 보조 명제 2): cost(T″ − {x, y}) = cost(T″) − f(x) − f(y)
    T‴ 은 ′ 이 너무 많아 헷갈려서 이렇게 이름 지었다고 하심
  4. 비교
    cost(T″) < cost(T) 이므로 cost(T″ − {x, y}) < cost(T) − f(x) − f(y) = cost(T′)
  5. 귀납 가정
    T′ 은 k − 1 개의 문자를 허프만 알고리즘으로 찾은 결과 → 귀납 가정 (n < k) 에 의해 T′ 은 최적
  6. 모순
    k − 1 개 문자의 최적 트리 T′ 보다 비용이 더 작은 트리 T″ − {x, y} 가 존재 (작거나 같은 것도 아니고 작다) → 모순
  7. 결론
    T 는 최적이다 → 귀납법 3단계 증명 → 허프만 코딩은 항상 최적 decode tree 를 찾는다
