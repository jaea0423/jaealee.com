01선택 문제

선택 문제 (Selection Problem)

입력: n개의 값, k (1 ≤ k ≤ n)
출력: k번째로 작은/큰 입력값
목표: 비교 횟수 최소화

최댓값 찾기 (k=n인 경우)

리스트 A가 있다고 할 때, 첫 번째 원소를 current Max로 두고 시작합니다. 다음 원소로 하나씩 넘어가며 A[i]와 비교해서, 더 크면 current Max를 그 원소로 갱신합니다.

원소가 n개면 n−1번 비교가 필요합니다.

상한과 하한 — tight bound

  • 상한 (upper bound): n−1번 이상 비교할 필요가 없음 (원소가 n개이므로) → n−1번
  • 하한 (lower bound): 최소 n−1번은 필요함 (이미 증명되어 있음)

상한과 하한이 같기 때문에 → tight bound = n−1번입니다.

필기 원문
아까 말한 화살표 점프점프는 1-2 1-3 1-4 가 아니라 1-2 2-3 3-4를 말한거야. 알려진 바에 의하면(공부하지는 않음) n-1번 이상 비교할 필요가 없음(개수가 n개이기 때문에) 즉, n-1번 - 상한(upper bound) 최소 n-1번 필요하다는 것도 알고 있음(하한 lower bound) (증명이 다 돼있음. 상한이 n-1이고 하한이 n-1이라는 것) 상한과 하한이 같기 때문에 ⇒ tight bound = n-1 번
필기 원문
선택문제 (Selection) 입력 : n개의 값, k (1<=k<=n) 값 출력 : k번째로 작은/큰 입력값 목표 : 비교 횟수 최소화 리스트 A가 있다고 가정 A o o o o o o o (여기서 o는 동그라미(리스트 요소 표현)) 첫번째 o에 화살표 해서 current Max라고 표시 첫 번째 o에서 두번째, 세번째 o로 점프뛰는 화살표 표현 후 A[i]와 비교. 라고 표현 ⇒ n-1 번 비교가 필요함 여기까지 일단 만들자

02토너먼트 방식

하나씩 비교하는 방법 말고, 토너먼트(Tournament) 식으로 비교할 수도 있습니다. 입력값이 7개라면, 둘씩 짝지어 비교하고 이긴 쪽(더 큰 값)만 다음 라운드로 올라갑니다.

토너먼트 도식상 비교를 6번 해야 한다는 것을 알 수 있습니다. 즉, 토너먼트 방식으로 해도 하나씩 비교하는 것과 동일하게 n−1번 비교를 하게 됩니다 (7개 − 1개 = 6개).

아직 명확하지 않은 부분

교수님이 토너먼트 방식으로 이 내용을 설명하시려는 의도가 아직 분명하지 않다고 하셨습니다. 다음 시간에 이어질 가능성이 있으니, 이후 필기에서 "왜 토너먼트 방식을 썼는지"가 나오면 이 부분을 보강하겠습니다.

필기 원문
→ 한개씩 비교하는 방법 말고 뭐가 있을까 입력값이 7개라면 o o o o o o o 하나씩이 아닌 토너먼트 식으로 비교할 수도 있음 (토너먼트식으로 표현해줘) 토너먼트 도식 상 가장 아래 있는 o가 (사진 참고) 출력이 됨 토너먼트도식 상 토너먼트(비교)를 6번 해야한다는 걸 알 수 있음 (나도 아직 교수님이 설명하고자 하는 걸 잘 모르겠어) 즉 토너먼트 방식으로 해도 하나씩 비교하는 것과 동일하게 n-1번 비교를 하게됨(7개-1개 = 6개)

03최대·최소 동시에 찾기

k문제비교 횟수
k = n최댓값 찾기n−1번
k = 1최솟값 찾기n−1번
k = 1, n최대·최소 동시에?

단순한 방법 — 상한 2n−3

  • 최댓값 찾기 → n−1번
  • 최솟값 찾기 → 최댓값을 제외한 나머지에서 찾으므로 (n−1)−1 = n−2번

최대·최소 동시에 = (n−1) + (n−2) = 2n−3번 → 이보다 더 비교할 필요는 없다는 뜻에서 상한이라고 생각할 수 있습니다.

여기서 더 낮출 수는 없을까? (상한을 줄이기 위한 노력)

토너먼트로 줄이기 — 상한 (3/2)n−2

토너먼트 도식에서 o는 흰 원(그 쌍에서 더 작은 값), O는 검은 원(그 쌍에서 더 큰 값)이라고 생각합니다. 예: o O o O O o O o (중간 값은 전부 O)

최소를 찾을 때, 처음부터 1라운드에서 이미 진 4개(o) 안에만 최솟값이 있다는 것이 보장됩니다 — 그 4개는 각각 자기 짝보다 작다는 게 이미 증명됐기 때문입니다. 따라서 최솟값은 n−2개가 아니라 n/2−1개만 비교하면 됩니다.

(n−1) + (n/2 − 1) = (3/2)n − 2

이전에 구한 2n−3보다 더 줄일 수 있습니다!

결론 — tight bound

최대·최소를 동시에 찾는 비교 횟수는 상한도 (3/2)n−2, 하한도 (3/2)n−2. 즉 tight bound = (3/2)n − 2입니다. (증명은 이미 되어 있는 내용이고, 이 수업에서 직접 증명하지는 않습니다.)

필기 원문
아까 도식에서 이 문구는 빼줘 : 1-2, 2-3, 3-4 ... (내가 그냥 너 화살표 도식화 하는데 이해하라고 쓴거야) k = n : 최댓값 찾기 ⇒ n-1번 비교 필요 k = 1 : 최소값 찾기⇒ n-1번 비교 필요 k = 1, n : 최대/최소 동시에 찾기 ⇒ ?? 최대는 → n-1번 최소는 → (n-1)-1 = n-2(최댓값 제외하고 비교) 최대/최소 동시에 = 2n-3번 → 2n-3번보다 더 비교할 필요가 없음(상한이라고 생각) 여기서 더 낮출 수는 없을까?(상한을 줄이기 위한 노력) 토너먼트 도식화(o는 하얀 동그라미, O는 검은 동그라미라고 생각해줘)(하얀 동그라미는 최소, 검은 동그라미는 최대) o O o O O o O o (중간 값은 전부 O) 이걸 토너먼트 하는 도식화 마지막 값은 n-1번 비교 생각해보면 맨 처음 토너먼트 시작 전 첫 번째 레벨(?)에 최소가 존재할거임(도식 상 첫 레벨의 o 해당) 최소 찾을 땐 즉, 다시 n-2가 아닌 n/2 - 1개만 비교하면 됨. 즉, (n-1) + (n/2 - 1) = (3/2)n - 2 = 아까 구한 2n -3 보다 줄일 수 있다! 최대와 최소를 동시에 찾는 비교 횟수는 상한도 3/2n - 2, 하한도 3/2n - 2. 즉 tight bound도 3/2n -2 임 (똑똑하신 분들이 증명하심. 우리는 증명 안함)

04최소·두 번째로 작은 값

단순한 방법 — 상한 2n−3

  • 가장 작은 값 → n−1번
  • 두 번째로 작은 값 → 가장 작은 값을 제외한 나머지에서 찾으므로 n−2번

최소·두 번째 작은 값 = (n−1) + (n−2) = 2n−3번 (상한)

가장 작은 값을 먼저 찾고, 그 정보를 이용해서 두 번째로 작은 값을 찾으면 횟수를 줄일 수 있을 것 같습니다.

토너먼트로 줄이기

요소 8개, 토너먼트에서 O는 작은 값(승자)이라고 하면 — 예: o O O o o O O o (다음 라운드로 올라가는 것은 모두 O)

두 번째로 작은 값은 최솟값을 만나지 않고는 탈락할 수 없습니다. 다른 원소에게 졌다면 그 원소가 두 번째로 작은 값보다 작다는 뜻인데, 그러면 그 원소가 최솟값이어야 하기 때문입니다. 즉 두 번째로 작은 값은 최솟값에게 직접 진 원소들 중에 반드시 있습니다.

최솟값에게 직접 진 원소의 개수 = 최솟값이 거친 라운드 수입니다 (최솟값은 모든 라운드를 거치므로, 매 라운드마다 누군가와 맞붙어 이겼기 때문). 이 후보들 중에서 최솟값을 찾으면 되므로:

두 번째로 작은 값 = (라운드 수 − 1)번 비교

라운드 수 구하기

입력 개수라운드 수
83

175

8 = 2³에서 감을 잡아보면, 라운드 수 = ⌈log₂ n⌉ (올림)입니다.

결론 — tight bound

두 번째로 작은 값 = ⌈log₂ n⌉ − 1번 비교. 따라서 최소·두 번째로 작은 값을 모두 찾는 비교 횟수 = (n−1) + (⌈log₂ n⌉ − 1) = n + ⌈log₂ n⌉ − 2번. 앞서 구한 2n−3보다 훨씬 적습니다. 이 역시 상한과 하한이 같은 tight bound라는 것이 증명되어 있습니다 (역시 이 수업에서 직접 증명하지는 않습니다).

05일반적인 경우 — Quick Select

지금까지는 최댓값, 최솟값, 최대·최소 동시, 최소·두 번째로 작은 값처럼 특수한 케이스였습니다. 이제 일반적인 경우로 넘어가서, k번째로 작은 수를 구하는 방법을 봅니다.

대표적인 알고리즘 2개 — Quick Select와 Median of Means(MoM)(Median=중앙값, Means=평균값). 오늘은 Quick Select만 다룹니다.

알고리즘 구조

  1. 아무 값 P를 고른다 (pivot). 랜덤이든 L[0]이든 L[n−1]이든 상관없습니다.
  2. 리스트 L의 각 원소를 P와 비교해서 세 그룹으로 나눕니다 — n−1번 비교가 필요합니다.
    • A = {P보다 작은 값}
    • M = {P와 같은 값} (P 자신 포함)
    • B = {P보다 큰 값}
    각 그룹 내부는 정렬되어 있지 않습니다.
  3. 찾는 순위 k와 |A|, |M|을 비교해서 어느 그룹에 답이 있는지 판단하고, 그 그룹 안에서 같은 과정을 재귀적으로 반복합니다.

재귀 조건

조건의미다음 호출
|A| ≥ k찾는 값이 A 안에 있음quick_select(A, k)
|A| + |M| < k찾는 값이 B 안에 있음quick_select(B, k−|A|−|M|)
그 외찾는 값이 M 안에 있음 (M은 전부 P와 같은 값)P 반환

B에서 찾을 때 순위가 k−|A|−|M|로 바뀌는 이유: A와 M에 있는 값은 전부 B의 값보다 작으므로, 전체 기준 1등부터 |A|+|M|등까지는 이미 A·M이 차지합니다. 그래서 B 안에서는 (k−|A|−|M|)번째로 작은 값이 전체 기준 k번째와 같습니다.

확인 필요 — 경계 조건 |A| > k vs |A| ≥ k

처음 필기에는 |A| > k였는데, 직접 예시(L=[5,3,8,3,1], k=1)로 검증해보니 |A| = k인 경우를 놓쳐서 잘못된 값을 반환했습니다. |A| ≥ k로 바꾸면 그 경우가 해결됩니다. 재아 님이 교수님께 직접 확인하시기로 해서, 아직 미확정이며 확인 후 반영 예정입니다.

의사코드

Pythonquick_select.py
def quick_select(L, k):
    P = L[0]                      # 아무 값(0번째)을 pivot으로 선정
    A, B, M = [], [], []
    for x in L:              # L의 요소를 순서대로 훑으며 분류
        if P > x:
            A.append(x)
        elif P < x:
            B.append(x)
        else:
            M.append(x)
    if len(A) >= k:            # 확인 필요 — 원래 필기는 '>' (위 참고)
        return quick_select(A, k)
    elif len(A) + len(M) < k:
        return quick_select(B, k - len(A) - len(M))
    else:
        return P

예시 — [6, 5, 1, 7, 9, 3, 8, 10, 2]

P = L[0] = 6. 리스트를 순서대로 훑으면서 A/M/B에 나눠 담습니다.

최선의 경우 vs 최악의 경우

  • 최선의 경우: 재귀할 때마다 요소가 절반으로 줄어듦
  • 최악의 경우: 재귀할 때마다 요소가 1개(피벗)만 줄어듦 (A 또는 B가 비어버리는 경우)

최악의 경우 점화식

Tw(n) = (n−1) + Tw(n−1) — 한 번 나누는 데 n−1번 비교하고, 딱 1개만 줄어든 나머지로 재귀합니다.

바로 아래 줄의 Tw(n−1)을 같은 식의 한 칸 아래 버전으로 다시 바꿔 넣으면 (n−1)에 대한 점화식이므로 Tw(n−1) = (n−2) + Tw(n−2)입니다. 이걸 원래 식에 대입하면:

T_w(n) = (n−1) + T_w(n−1)
       = (n−1) + (n−2) + T_w(n−2)     ← T_w(n−1)을 같은 식으로 한 번 더 펼침
       = (n−1) + (n−2) + (n−3) + T_w(n−3)
       ...
       = (n−1) + (n−2) + ... + 1 + T_w(1)

Tw(1)은 그냥 return하는 상수 시간이라 Big-O에서는 영향이 없어 사라집니다. 1+2+...+m = m(m+1)/2 공식을 m=n−1에 적용하면:

T_w(n) = (n−1)((n−1)+1) / 2 = (n−1)n / 2 = O(n²)
결론 — 최악의 경우

운이 나빠 매번 한쪽이 거의 비면 최악의 경우 O(n²)까지 나빠질 수 있습니다.

최선의 경우

재귀할 때마다 요소가 절반 정도로 줄어드는 경우입니다.

n/2   P   n/2
(A)      (M)      (B)

이렇게 계속 절반씩 줄어드는 게 이상적입니다. 정확히 딱 절반이 아니어도 괜찮습니다 — 목적은 정확한 값이 아니라 시간복잡도를 구하는 것이기 때문입니다.

TB(n) = (n−1) + TB(n/2)인데, 상수는 Big-O에서 중요하지 않으므로 계산 편의상 n−1을 n으로 씁니다:

T_B(n) = n + T_B(n/2)

여기서도 바로 위 줄의 TB(n/2)를 같은 점화식의 한 칸 작은 버전으로 바꿔 넣습니다. TB(n/2) = n/2 + TB(n/4)이므로 대입하면:

T_B(n) = n + T_B(n/2)
       = n + n/2 + T_B(n/2²)     ← T_B(n/2)를 같은 식으로 한 번 더 펼침
       = n + n/2 + n/4 + T_B(n/2³)
       ...
       = T_B(1) + n/2^(k-1) + ... + n/2² + n/2 + n
       = T_B(1) + n·(1 + 1/2 + 1/2² + ... + 1/2^(k-1))

괄호 안 (1 + 1/2 + 1/4 + ... + 1/2k-1)은 항이 계속 절반씩 작아지는 등비급수라서, 아무리 항을 더해도 2를 절대 넘지 않습니다 (무한히 더해도 정확히 2에 가까워질 뿐입니다). 그래서 이 괄호는 그냥 상수(C < 2)로 취급할 수 있습니다.

T_B(n) = T_B(1) + n·C = O(n)

최선절반씩O(n)
최악1개(피벗)씩O(n²)

06용어 정리

선택 문제selection problem

n개 값 중 k번째로 작은(큰) 값을 찾는 문제. 목표는 비교 횟수 최소화.

상한upper bound

이보다 더 많이 비교할 필요는 없다는 한계. 최악의 경우를 보장한다.

하한lower bound

아무리 잘해도 최소 이만큼은 비교해야 한다는 한계.

tight bound—

상한과 하한이 일치하는 경우. 그 값이 최적임이 증명된 상태.

피벗pivot

Quick Select에서 나머지 값을 비교할 기준으로 삼는 값.

분할partition

피벗을 기준으로 리스트를 A(작음)·M(같음)·B(큼)로 나누는 것.

점화식recurrence relation

T(n)을 더 작은 입력의 T로 표현한 식. 전개해서 시간복잡도를 구한다.

Q1n개의 값 중 최댓값을 찾을 때 필요한 비교 횟수의 tight bound는?객관식
  1. n
  2. n − 1
  3. n/2

정답 ②상한도 n−1(원소가 n개라 그 이상 비교할 필요 없음), 하한도 n−1(최소 n−1번은 필요함이 증명됨). 둘이 같으므로 tight bound = n−1.
Q2최댓값과 최솟값을 동시에 찾을 때, 단순히 각각 찾으면 2n−3번이다. 토너먼트를 쓰면 (3/2)n−2로 줄일 수 있는 이유를 설명하시오.서술형
모범답안최댓값 토너먼트(n−1번)를 진행하면, 1라운드에서 진 n/2개는 각자 자기 짝보다 작다는 것이 이미 밝혀진다. 따라서 최솟값은 반드시 그 n/2개 안에 있으므로, 나머지 전부(n−2개)가 아니라 그 n/2개 중에서만 찾으면 되고 이때 n/2−1번이면 충분하다. 합치면 (n−1)+(n/2−1) = (3/2)n−2.

Q5Quick Select의 최악의 경우 시간복잡도는?객관식
  1. O(n)
  2. O(n log n)
  3. O(n²)
