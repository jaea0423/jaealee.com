02허프만 코딩 (Huffman Coding)

시험 ★★★
허프만 코딩

빈도수가 가장 적은 두 개씩 묶어 이진 트리를 만드는 그리디 방법. 빈도수가 가장 많은 문자는 깊이를 가장 얕게 두어 그 문자가 쓰는 비트 수를 줄이고, 결국 전체 비트 수를 최소화하는 것이 목표.

위 예시에서도 가장 많이 나오는 f(60) 는 깊이 1 (코드 1비트), 가장 적게 나오는 a(3) · b(7) 은 가장 깊은 깊이 5 에 있습니다.

필기 원문
이걸 Huffman Coding 이라고 함(허프만 코딩) 빈도수가 가장 많은 건 깊이를 가장 얕게 내려가서 사용하는 비트 수를 최소화하는 것을 목표로 함. 전체 비트 수를 줄이는게 목표였음.

03허프만 코딩 의사코드

시험 ★★★
의사코드Huffman(T)
def Huffman(T):                    # T: 노드들을 담은 min heap (처음엔 문자 노드 n개)
    while len(T) > 1:              # 노드가 하나(루트)만 남을 때까지
        x = extract_min(T)          # 빈도수가 가장 적은 노드를 꺼냄
        y = extract_min(T)          # 그다음으로 적은 노드를 꺼냄
        z = Node(left = x, right = y)   # x, y 를 자식으로 하는 새 노드
        f(z) = f(x) + f(y)          # f() = 빈도수, 새 노드는 두 빈도의 합
        insert(T, z)                # 새 노드를 다시 넣음
    return T                         # 남은 노드 하나 = decode tree 의 루트
extract_min(T)T 안에서 빈도수가 가장 적은 노드를 빼는 함수 (자세히는 04)
Node(left, right)x 를 왼쪽 자식, y 를 오른쪽 자식으로 하는 새 노드 z
f(z) = f(x) + f(y)새 노드의 빈도 = 두 자식 빈도의 합 (예: 3 + 7 = 10)
insert(T, z)새로 만든 노드를 T 에 넣음
필기 확인

① 필기의 "x = extract_min" → 꺼낼 대상 T 를 넣어 extract_min(T) 로 썼습니다 (04 에서 교수님도 extract_min(T) 로 쓰심).

② "T : 이진트리. decode tree" → 반복 중의 T 는 노드들을 담은 min heap 이고 (04), 반복이 끝나면 T 에 노드가 하나 남는데 그 노드가 decode tree(허프만 트리) 의 루트입니다.

필기 원문
수도코드로 적어볼 것임. puseudocode def Huffman(T): * T : 이진트리. decode tree while len(T) > 1 : x = extract_min * extract_min : T 안에서 빈도수가 가장 적은 노드를 빼는 함수(자세히 쓰진 않을거임) y = extract_min z = Node(left = x, right = y) f(z) = f(x) + f(y) # f()는 빈도수 insert(T, z) #트리에 새로 만든 노드 넣어줌 return T

04extract_min 과 insert — min heap

시험 ★★★
min heap

모든 노드에서 부모 ≤ 자식 인 이진 트리 (완전 이진트리). 그래서 루트가 가장 작은 값. 6-1 에서 배운 힙(부모 ≥ 자식, max heap) 과 크기 방향만 반대입니다.

연산동작시간
extract_min(T)루트(가장 작은 값)를 꺼내고, 마지막 노드를 루트로 옮긴 뒤 루트에서부터 heapify_down (더 작은 자식과 교환하며 내려감)O(h) = O(log n)
insert(T, z)z 를 T 의 마지막 노드 자리에 두고 heapify_up (부모보다 작으면 교환하며 올라감)O(h) = O(log n)

h 는 힙의 높이이고, 힙은 완전 이진트리라 h = ⌊log₂ n⌋ 이므로 O(h) = O(log n).

필기 확인

"insert(T, z) 는 z 를 T 의 마지막 루트노드에 두고" → 마지막 노드 자리(배열의 맨 끝) 입니다. 루트에 두는 것이 아니라 맨 끝에 두고 위로 올리는 것이 heapify_up 입니다.

증명하려는 것

07보조 명제 — x, y 를 가장 깊은 형제로 갖는 최적 트리가 있다

시험 ★★★
명제

빈도수가 가장 작은 두 문자 x, y 를 가장 깊은 곳에 형제 노드로 갖는 최적 decode tree 가 항상 존재한다.

귀류법: 결론을 부정해 "그런 최적 트리는 하나도 존재하지 않는다" 고 가정하고 모순을 찾습니다. 그러면 어떤 최적 트리 T 를 잡아도 x 는 가장 깊은 곳이 아닌 중간쯤에 있고, 가장 깊은 곳의 형제 리프 a, b 는 x, y 가 아닙니다.

x 와 a 를 바꾸면 비용이 늘지 않는다

바뀐 것은 x 와 a 의 위치뿐이라 나머지 리프의 항은 cost(T) 와 cost(T′) 에서 똑같습니다 → x, a 의 항만 비교하면 됩니다. 바꿨으므로 dT′(x) = dT(a), dT′(a) = dT(x).

cost(T) − cost(T′)
 = [ f(x)·dT(x) + f(a)·dT(a) ] − [ f(x)·dT′(x) + f(a)·dT′(a) ]
 = f(x)·dT(x) + f(a)·dT(a) − f(x)·dT(a) − f(a)·dT(x)
 = (f(x) − f(a))·dT(x) − (f(x) − f(a))·dT(a)
 = (f(x) − f(a)) · (dT(x) − dT(a))
f(x) − f(a) ≤ 0x 는 빈도가 가장 작은 문자이므로 f(x) ≤ f(a)
dT(x) − dT(a) ≤ 0a 는 가장 깊은 곳에 있으므로 dT(x) ≤ dT(a)
곱(0 이하) × (0 이하) ≥ 0 → cost(T) − cost(T′) ≥ 0 → cost(T′) ≤ cost(T)

= 트리의 비용을 증가시키지 않고 x 와 a 를 바꿔 x 를 가장 깊은 곳에 둘 수 있다. 같은 식으로 y 와 b 를 바꾼 T″ 도 cost(T″) ≤ cost(T′) (f(y) ≤ f(b), d(y) ≤ d(b)).

모순

비용cost(T″) ≤ cost(T′) ≤ cost(T)
T 가 최적T 보다 비용이 작은 트리는 없음 → cost(T″) = cost(T) → T″ 도 최적
모순T″ 는 x, y 를 가장 깊은 형제로 갖는 최적 트리 → "그런 최적 트리는 하나도 없다" 는 가정과 모순
결론가정이 틀렸다 → 명제가 참: x, y 를 가장 깊은 형제로 갖는 최적 decode tree 가 항상 존재
필기 확인 — 결론에 영향 있는 2곳

① "T′ 은 최적이 아님 (가정상 최적은 T)" → 틀립니다. 위 계산으로 cost(T′) ≤ cost(T) 이고, T 가 최적이라 cost(T′) ≥ cost(T) 이기도 하므로 cost(T′) = cost(T), 즉 T′ 도 최적입니다. 최적 트리가 여러 개일 수 있다는 것(06)과 같은 이야기입니다.

② "T 보다 더 최적이 되는 T′ 이 발견됐기 때문에" → T 가 최적이므로 T 보다 더 좋은 트리는 나올 수 없습니다. 모순의 정체는 "더 좋은 트리" 가 아니라, 똑같이 최적이면서 x, y 가 가장 깊은 형제인 T″ 가 존재한다는 것 — "그런 최적 트리는 하나도 없다" 는 가정과 부딪힙니다.

필기 확인 — 식 오타

③ cost(T′) = f(a)·dT′(a) + f(a)·dT′(a) → 앞 항은 f(x)·dT′(x).

④ (f(x) − f(a)) · (dT(x) = dT(a)) → 가운데는 빼기: (dT(x) − dT(a)).

⑤ "dT(x) − dT′(a) ≤ 0" → dT(x) − dT(a) ≤ 0 (둘 다 T 에서의 깊이). dT′(a) = dT(x) 라서 원래 식대로면 0 이 됩니다.

⑥ "cost(T) 가 cost(T) 보다 작거나 같다" → cost(T″) ≤ cost(T). "그 말은 cost(T′) 이 최적" → T″ 도 최적.

⑦ "귀류법 (가정을 증명해서 모순 → 가정이 참)" → 귀류법은 결론을 부정한 가정에서 모순을 찾아, 그 가정이 틀렸으므로 원래 명제가 참이라고 결론 내는 방법입니다.

가장 깊은 a 옆에 왜 형제 리프 b 가 있나

09보조 명제 2 — 형제 두 리프를 하나로 합치면 비용이 f(u) + f(v) 줄어든다

시험 ★★★

문자 n 개에 대한 decode tree B 가 있고, 가장 깊은 곳의 두 형제 리프를 u, v 라고 합니다 (빈도는 상관없음). u, v 를 지우고 그 부모 w 를 리프(문자 하나)로 만든 트리를 B′ 이라 하면, B′ 은 문자 n − 1 개에 대한 decode tree 이고 f(w) = f(u) + f(v).

달라진 것은 "u, v 두 리프" 가 "w 리프 하나" 가 된 것뿐이고, 나머지 리프의 항은 같아서 서로 지워집니다. w 는 u 의 부모이므로 dB′(w) = dB(u) − 1, u 와 v 는 형제라 dB(v) = dB(u) (이 깊이를 d 라고 쓰면):

cost(B) − cost(B′)
 = f(u)·dB(u) + f(v)·dB(v) − f(w)·dB′(w)        # 달라진 항만
 = f(u)·d + f(v)·d − (f(u) + f(v))·(d − 1)                # f(w) = f(u) + f(v), 깊이 대입
 = f(u)·d + f(v)·d − f(u)·d − f(v)·d + f(u) + f(v)           # 괄호 전개
 = f(u) + f(v)
쉽게 말하면

u 와 v 의 코드는 끝자리(0 / 1) 만 다르고 앞부분이 같습니다. 둘을 부모 w 하나로 합치면 u 가 나올 때마다 1비트, v 가 나올 때마다 1비트씩 덜 쓰게 되므로, 전체 비트 수가 정확히 (u 의 빈도 + v 의 빈도) 만큼 줄어듭니다.

숫자로 확인 (10-1 예시)

a 0 · c 100 · b 101 · d 111 · f 1100 · e 1101 의 트리 (cost 230) 에서 맨 아래 형제 f(7), e(9) 를 부모 하나(빈도 16, 코드 110) 로 합치면 cost = 43·1 + 12·3 + 13·3 + 16·3 + 16·3 = 214. 차이 230 − 214 = 16 = 7 + 9 (코드로 확인).

필기 확인

"(f(u) + f(v)) · (dB′(u) − 1)" → u 는 B′ 에 없으므로 (dB(u) − 1) 입니다 (B 에서 u 의 깊이보다 1 작은 것이 B′ 에서 w 의 깊이). 이 식이 나머지 전개의 근거라 고쳐 두었습니다.

필기 원문
그 전에 잠깐 볼게 있음 * 문자 n개가 다고 하면 이 n에 대한 decode tree B 가 있다고 가정 이 트리의 가장 깊은 곳에 있는 노드를 u, v라고 함 아까처럼 삼각형 안에 시각화로 표현 u랑 v는 가장 깊은 두 형제 노드(빈도수 상관 없음) u랑 v위에 w라는 노드를 추가할 수 있음. 이걸 B'이라고 해보자.(u, v의 부모로 w를 두고 u, v를 제외한 트리를 B') B'은 n-1에 대한 decode tree가 됨 (f(w) = f(u) + f(v)) 이제 cost(B) - cost(B')을 관찰해볼건데(두 코스트의 차이를 관찰) 달라진건 u, v가 있던 걸 w로 만든 것만 있고 나머지는 다 같음. 그러면 나머지 다 빼고 차이나는 것만 비교하면 cost(B) - cost(B') = f(u)*d_B(u) + f(v) * d_B(v) - f(w) * d_B'(w) 근데 f(w) = f(u) + f(v)로 뒀기 때문에 = f(u)*d_B(u) + f(v) * d_B(v) - (f(u)+f(v)) * d_B'(w) 또 정리해주면 = f(u)*d_B(u) + f(v) * d_B(v) - (f(u)+f(v)) * (d_B'(u) - 1) 또 정리해주면 = f(u)*d_B(u) + f(v) * d_B(u) - (f(u)+f(v)) * (d_B'(u) - 1) 이렇게 어차피 형제니까 d_B에서 v를 u로 할 수 있음 이걸 다 열심히 전개하면 = f(u) + f(v)가 됨 그러면 우리가 안 사실은 문자 n개에 대해서 decode tree가 있을 때 B'이 있을 때 cost(B), cost(B')의 차가 f(u) + f(v)와 같다. (더 쉽게 써주면 좋을 거 같아) 이제 n=k일 때도 성립하는지 보면 됨 (나 이거 귀납법으로 하고 있는거 이해가 잘 안돼. 잘 단계별로 차근차근 주석도 필요하면 달고 이해 잘되게 설명해줘. 내 필기가 조금 개같을 수는 있어)

10귀납 3단계 — n = k 일 때 허프만 트리 T 는 최적 (귀류법)

시험 ★★★
보이려는 것

문자 k 개에 대한 허프만 트리 T 는 최적이다. 사용할 수 있는 것: 귀납 가정 "문자가 k 보다 적으면 허프만 트리는 최적", 보조 명제 1 · 2.

① T 에서 x, y 를 합친 T′

x, y빈도가 가장 작은 두 문자. 허프만은 이 둘을 가장 먼저 묶으므로 T 에서 형제 리프
T′x, y 를 지우고 그 부모 z (f(z) = f(x) + f(y)) 를 리프로 — 문자 k − 1 개의 트리. 허프만이 x, y 를 묶은 뒤 하는 일이 바로 "k − 1 개로 허프만" 이므로 T′ 은 k − 1 개 문자의 허프만 트리
보조 명제 2cost(T) − cost(T′) = f(x) + f(y) → cost(T′) = cost(T) − f(x) − f(y) … (가)

② 귀류법 — T 가 최적이 아니라고 가정

가정T 는 최적이 아니다 → T 보다 비용이 작은 최적 트리 T″ 가 있다: cost(T″) < cost(T) … (나)
보조 명제 1 사용최적 트리 중에는 x, y 가 가장 깊은 형제인 것이 항상 있으므로, T″ 를 그런 트리로 고른다 (그래야 x, y 를 z 하나로 합칠 수 있음)
보조 명제 2T″ 에서 x, y 를 z 로 합친 T″−{x, y} (문자 k − 1 개): cost(T″−{x, y}) = cost(T″) − f(x) − f(y) … (다)

③ 식을 이어 붙이면

cost(T″−{x, y}) = cost(T″) − f(x) − f(y)        # (다)
                  < cost(T)  − f(x) − f(y)        # (나): cost(T″) < cost(T)
                  = cost(T′)                      # (가)

→  cost(T″−{x, y}) < cost(T′)

④ 모순

T′ 은 최적T′ 은 문자 k − 1 개의 허프만 트리이고 k − 1 < k 이므로 귀납 가정(2단계) 에 의해 최적
그런데T″−{x, y} 도 같은 k − 1 개 문자 (x, y 대신 z) 의 트리인데 비용이 T′ 보다 작다 (작거나 같은 것도 아니고 작다)
모순최적인 T′ 보다 비용이 작은 트리가 있을 수 없다
결론"T 가 최적이 아니다" 는 틀렸다 → n = k 일 때 허프만 트리 T 는 최적 → 귀납 3단계 완료 → 모든 n 에서 허프만 코딩은 최적
필기 확인

① "T 에는 가장 마지막에 x, y 가 있을 것" → 정확히는 허프만이 x, y 를 가장 먼저 묶으므로 T 에서 둘이 형제 리프라는 것이 핵심입니다 (보조 명제 2 를 쓰려면 형제이기만 하면 됨).

② "T″ 에도 마지막에 임의의 x, y 가 달려 있을 것" → 임의의 두 문자가 아니라 빈도 최소인 바로 그 x, y 가 맨 아래 형제여야 합니다. 아무 최적 트리나 그렇다는 보장은 없어서 보조 명제 1 로 "그런 최적 트리가 있다" 를 쓴 것입니다 — 교수님이 말씀하신 "앞에서 구한 명제를 적용" 이 바로 이 자리.

③ "T″ 이 최적이라고 가정했으니까 cost(T″) < cost(T)" → 정확한 이유는 T 가 최적이 아니라고 가정했기 때문입니다 (최적인 T″ 가 T 보다 작다).

Q5"빈도수가 가장 작은 두 문자 x, y 를 가장 깊은 곳에 형제로 갖는 최적 decode tree 가 항상 존재한다" 를 귀류법으로 증명하시오.서술기본
모범답안가정: 그런 최적 트리가 하나도 없다. 최적 트리 T 에서 가장 깊은 형제 리프를 a, b 라 하면 (x, y 가 아님) f(x) ≤ f(a), dT(x) ≤ dT(a). x 와 a 를 바꾼 T′ 에 대해 cost(T) − cost(T′) = (f(x) − f(a))(dT(x) − dT(a)) ≥ 0 (0 이하 × 0 이하). 같은 방법으로 y 와 b 를 바꾼 T″: cost(T″) ≤ cost(T′) ≤ cost(T). T 가 최적이므로 cost(T″) = cost(T), 즉 T″ 도 최적이고 x, y 가 가장 깊은 형제 → 가정과 모순.
Q6트리 B 의 형제 리프 u, v 를 지우고 부모 w (f(w) = f(u) + f(v)) 를 리프로 만든 트리를 B′ 이라 할 때, cost(B) − cost(B′) = f(u) + f(v) 임을 보이시오.서술기본
모범답안달라진 항만 남기면 cost(B) − cost(B′) = f(u)·d + f(v)·d − f(w)·(d − 1) (d = dB(u) = dB(v), w 의 깊이는 d − 1) = f(u)·d + f(v)·d − (f(u) + f(v))(d − 1) = f(u) + f(v).
Q7Q3 의 허프만 트리 (cost 109) 에서 처음 묶인 a(4), b(6) 를 부모 하나(빈도 10) 로 합친 트리의 cost 를 구하고, Q6 의 결과와 맞는지 확인하시오.계산응용

Q8문자 개수 n 에 대한 귀납법으로 허프만 코딩이 최적 decode tree 를 만든다는 것을 증명하시오. 3단계(n = k) 에서 보조 명제가 어디에 쓰이는지 밝힐 것.서술심화
모범답안① 바닥: n = 2 는 두 문자에 0, 1 — 최적. ② 가정: n < k 이면 허프만 트리는 최적. ③ n = k: 허프만 트리 T 에서 먼저 묶인 x, y(빈도 최소) 는 형제. 둘을 z 로 합친 T′ 은 k − 1 개 문자의 허프만 트리이고 (보조 명제 2) cost(T′) = cost(T) − f(x) − f(y). T 가 최적이 아니라고 가정하면 cost(T″) < cost(T) 인 최적 T″ 가 있고, (보조 명제 1) x, y 가 가장 깊은 형제인 T″ 를 고를 수 있다. 합치면 cost(T″ − {x, y}) = cost(T″) − f(x) − f(y) < cost(T) − f(x) − f(y) = cost(T′). 그런데 T′ 은 가정 ② 로 최적 → 모순 → T 는 최적.
Q9허프만 최적성 증명에서 귀납법과 귀류법이 각각 어떤 역할을 하는지 쓰시오.서술응용
