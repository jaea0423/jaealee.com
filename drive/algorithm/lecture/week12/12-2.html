01Knapsack 문제 — 배낭에 무엇을 넣을까

시험 ★★★
한 줄 정의

용량 K 인 배낭에, 무게 합이 K 를 넘지 않게 아이템을 골라 담아서 가치 합을 최대로 만드는 문제.

Knapsack = 배낭. 필기의 K-=16 은 K = 16 의 오타로 보고 고쳤습니다.

항상 지켜야 하는 두 조건

내용
조건 1 (제약)선택한 아이템의 무게 합 ≤ K
조건 2 (목표)선택한 아이템의 가치 합이 최대

예시 — 2, 5, 5 를 넣은 경우

무게 2 (가치 40) → 5 (가치 30) → 10 (가치 50) 은 넣으면 2 + 5 + 10 = 17 > 16 이라 못 넣음 → 5 (가치 10) 넣음. 무게 12, 4 가 남음. 조건 1 은 만족하지만, 조건 2 (최대인가) 는 아직 모릅니다.

보충 — 이 예시는 최대가 아님

가치 합 80 입니다. 무게 2 + 10 = 12 (가치 40 + 50 = 90) 처럼 더 큰 조합이 있으므로 조건 2 를 만족하지 않습니다. 쪼갤 수 없을 때 (0/1, 다음 섹션) 이 예의 최대는 90 입니다 (4개로 만들 수 있는 조합 16가지를 모두 확인). 04 에서 수업으로 확인.

필기 원문
백트래킹 예시 이어서 진행 Knapsack Proble Knapsack은 배낭이라고 생각하면 됨 K-=16이라는 가방이 있다고 해보자(용량) 이걸 시각화로 빈 스택처럼 바구니 열어주면돼 아이템이 있음 2 5 10 5(각 사각형으로 표현하고 이 숫자 크기의 비례하는 사각형으로 표현하면 좋겠어. 너비 동일 높이 비례) 이 아이템들은 각각 가치를 가침 순서대로 40 30 50 10 2 5 10 5는 무게임 그래서 넾셐알고리즘이 무슨 문제야? 간단하게 한줄로. 이 무게들은 가방의 무게를 넘으면 안됨 항상 두 개의 조건을 만족해야하는데 1. 선택된 아이템의 크기(무게) 합이 <= k 2. 목표 : 선택된 아이템의 가치합이 최대가 되게 선택 내 가방에 넣을 수 있는 만큼 넣되 그 와중에 가방에 들어간 가치가 최대가 되게하는 조합을 찾고 싶은거임 이걸 배낭에 넣으면 k=16 바구니의 용량은 16 여기에 무게가 2, 가치가 40인걸 넣고 5, 가치가 30인걸 넣을 수 있고 (너비는 바구니에 맞추고 높이로 비례하게 쓰면 될듯. 색으로 구분해도 좋고) 10(가치50)은 넣을 수 없음. k를 초과하기 때문 5(가치10)을 넣을 수 있음 가치는 네모 안에 표시 이렇게 넣으면 4만큼 남게 됨(예시임.) 이 예시는 조건 1 만족시킴. 2는 만족하는지 아직 모르겠음.

040/1 — 가성비 순서로 넣으면 최적이 아님

시험 ★★★

쪼갤 수는 없지만, fractional 처럼 가성비 좋은 아이템부터 넣어 봅니다. 01 의 예시와 같습니다.

2 (40) → 5 (30) → 10 (50) 은 17 > 16 이라 못 넣음 → 5 (10). 빈칸 4, 가치 80. 하지만 이것이 정답이 아닙니다.

2 (40) 를 넣고 바로 10 (50) 을 넣으면 가치 90 → 더 좋습니다. 즉 0/1 에서는 가성비 그리디가 최적을 보장하지 않습니다. 01 의 "조건 2 는 아직 모름" 의 답이 이것입니다.

필기 원문
2번 방법 0/1 방법 쪼갤 수는 없지만, 가성비 좋은 아이템부터 넣어보자.! 그러면 아까 가성비 순서대로 이미 나열돼있으니까 앞 아이템부터 넣어보면 되니까 해보자 우리가 처음 예시로 뒀던 그거임(마찬가지로 시각화) 16 바구니에 2(40), 5(30), 10은 못넣고(k초과), 5(10)을 넣고 빈칸은 4만큼 남음 그러면 이렇게 하면 가치가 80이 됨 이게 정답인지는 모르겠지만 가성비 좋은 아이템부터 넣으니까 가치가 80 근데 이게 정답은 아님. 더 뛰어난게 있음 더 나은 방안은 16바구니에 2(40) 넣고 바로 10(50)을 넣음. 이렇게 하면 90이 돼서 더 나음

050/1 은 백트래킹으로 — 모든 경우 = 넣거나 안 넣거나

시험 ★★★

모든 경우를 보면 최적을 찾을 수 있습니다. 아이템마다 넣거나 (X[i] = 1) 안 넣거나 (X[i] = 0) 를 반복 → 백트래킹. 탐색은 X = [] (아무것도 안 정한 상태) 에서 시작합니다.

답이 될 수 있는 X (예)넣은 아이템무게가치
[1, 1, 0, 1]1, 2, 41280
[1, 0, 1, 0]1, 31290
[1, 0, 0, 0]1240

이 중 최적을 백트래킹으로 찾습니다. 경우의 수 24 = 16 가지를 모두 봐야 하는 것이 백트래킹의 단점입니다 (n 개면 2n).

12-1 복습 — 한계함수 B (bounding function)

비효율을 줄이는 방법: B 를 잘 설정해서 이 가지를 더 내려갈지, 여기서 접고 백트랙할지 정합니다. 필기의 "B 였나" → 맞습니다, Bounding function 의 B.

필기 확인 — [1, 0, 0] 부분

필기 문장대로 "넣을 수 있는데 안 넣은 답은 더 좋은 답이 될 수 없다" 는 마지막 아이템 하나에 대해서만 맞습니다 (예: [1, 0, 0, 0] 은 아이템 4 를 넣은 [1, 0, 0, 1] 보다 가치가 항상 작음 — 가치가 양수이므로). 하지만 중간 아이템에 대해서는 틀립니다 — 바로 위 04 에서 넣을 수 있는 아이템 2 를 안 넣은 [1, 0, 1, 0] 이 더 좋았습니다.

그래서 교수님 말씀은 아래 06 의 한계함수로 이해하는 것이 맞아 보입니다 (추측): 4개 예시에서 [1, 0, 1, 0] (가치 90) 을 찾은 뒤, [1, 0, 0] 에서 남은 아이템 4 를 다 넣어도 40 + 10 = 50 < 90 → 더 좋은 답이 나올 수 없으므로 그 가지를 탐색하지 않음. 수업 판서가 다르면 알려주세요.

필기 원문
백트레킹으로 할 수 이게되는거임 모든 가짓수를 보면 되기 때문 넣거나 안넣거나 반복 [1,0,0]을 찾게되는데 이건 넣어도 되는데 넣지 않는 것은 더 좋은 답이 될 수 없기 때문에 그 가지는 탐색하지 않아도 된다는걸 알 수 있음(바운딩펑션인거같음). 즉 가치가 낮아서 안하는 것도 있지만 그 전에 넣어도 되지만 안넣어서 나온 답이 더 좋은 답이 될 순 없다는거 같음. 근데 이해가 안가. 내가 잘못 적은걸수도 있어. 그 다음 꼭대기로 백트랙하게됨. 첫번째 아이템을 안넣는 방향으로 가야됨. 먼저 상태를 X=[]로 둠(추정하고 있는 답) 그리디 알고리즘으로 접근하는게 아닌 2번바아법(0/1)은 백트래킹을 이용해야함 각각의 아이템을 넣거나 안넣거나 답이 될 수 있는 것들 보면 X = [1, 1, 0, 1] X = 1,0,1,0 X = [1, 0, 0, 0] 이런것들이 가능 이 중에 최적인걸 찾아야하는데 백트래킹으로 찾음 백트래킹이 굉장히 직관적이지만 일반적으로 효율적이진 않음. 모두 탐색해야하기 때문에 이 경우에도 2^4번 탐색해야함(백트래킹의 단점) 백트래킹이 비효율적이긴 하지만 그나마 효율서을 높일 수 있는게 뭐라고 했냐면(지난시간에) bounding function(알파벳 B였나)을 잘 설정하면 효율성을 높일 수 있었음 (가지를 칠지 백트래킹을 할지 결정하는 거임...아마)

상태 공간 트리 (State-Space Tree, SST) — 전체

필기 질문 "무슨 트리였지" → 12-1 의 상태 공간 트리 (SST). 노드 하나 = 상태(state) = 지금까지 정한 X. 왼쪽 가지 X[k] = 1 (넣음), 오른쪽 가지 X[k] = 0 (안 넣음).

8개 잎 중 무게 ≤ 5 인 것: [1, 0, 1] (21), [1, 0, 0] (15), [0, 1, 0] (16), [0, 0, 1] (6), [0, 0, 0] (0) → 최적은 [1, 0, 1], 가치 21 (전수 조사로 확인).

한계함수 = fractional 로 푼 상한

상한(v) = 지금까지 넣은 가치 + 남은 아이템을 남은 용량에 fractional 로 채운 가치
상한(v) ≤ 지금까지 찾은 최대 (best)  →  이 가지는 더 볼 필요 없음 (가지치기)

이유: 0/1 답 가치 ≤ fractional 답 가치 (02). 그 가지에서 0/1 로 아무리 잘해도 상한을 넘을 수 없으므로, 상한이 best 이하면 내려가도 더 좋은 답이 없습니다.
