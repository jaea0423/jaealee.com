01지난 시간 수정 — find_way 들여쓰기

시험 ★

의사코드find_way(x, y) — 세 줄의 높이
def find_way(x, y):
    if x == n - 1 and y == n - 1:      # ① 도착
        return true
    if M[x][y] == safe:                # ② ①과 같은 높이
        try_down = find_way(x + 1, y)
        if try_down == true:
            return true
        try_east = find_way(x, y + 1)
        return try_east
    else:                              # ③ ②의 짝, 같은 높이
        return false

02subsetsum2 — 남은 원소를 인덱스 i 로 표현

시험 ★★★
의사코드subsetsum2(A, i, S) — {A[0], …, A[i]} 중 합이 S 인 부분집합이 있는가
def subsetsum2(A, i, S):              # A[0] ~ A[i] 만 보고 판단
    if S == 0:
        return True                       # 딱 맞음
    elif S < 0 or i == -1:
        return False                      # 넘쳤거나, 볼 원소가 없음
    else:                                 # A[i] 를 넣을지 말지
        with_i = subsetsum2(A, i - 1, S - A[i])    # 넣음
        without_i = subsetsum2(A, i - 1, S)        # 안 넣음
        return with_i or without_i        # 하나만 True 여도 True

# 호출: subsetsum2(A, len(A) - 1, S)

필기의 with 는 파이썬 예약어라서 11-1 과 같이 with_i / without_i 로 바꿨습니다.

subsetsum1 과 무엇이 다른가 (필기 질문)

subsetsum1(A, S)subsetsum2(A, i, S)
남은 원소 표현리스트를 잘라서 넘김 B = A[1:]리스트는 그대로, 인덱스 i 만 넘김
보는 순서앞에서부터 (A[0] 먼저)뒤에서부터 (A[i], i 를 1씩 줄임)
"원소가 없다"len(A) == 0i == -1
결과 · 동작같음 — 원소마다 넣는다 / 안 넣는다로 갈라지는 같은 백트래킹
이렇게 바꾼 이유

호출이 정수 두 개 (i, S) 로만 구분됩니다. 그래서 다음 섹션처럼 결과를 표 DP[i][S] 의 한 칸에 저장할 수 있습니다. 리스트를 잘라 넘기는 subsetsum1 은 이렇게 표로 만들기 어렵습니다. 덤으로 매번 리스트를 복사하지 않아도 됩니다.

03점화식 → DP 테이블 · 수행시간 O(nS)

시험 ★★★
subsetsum2(A, i, S) = subsetsum2(A, i − 1, S − A[i])  or  subsetsum2(A, i − 1, S)

DP[i][S] = DP[i − 1][S − A[i]]  or  DP[i − 1][S]

DP[i][S] 의 의미: A[0], …, A[i] 만 고려했을 때 합이 S 가 되는 부분집합이 있으면 True, 없으면 False.

표내용
행i = 0, 1, …, n − 1 → n 개
열S = 0, 1, …, S → S + 1 개
원하는 답마지막 칸 DP[n − 1][S]
한 칸 계산위 행의 두 칸을 or → 기본 연산 O(1)
수행시간칸 수 n × (S + 1) × O(1) = O(nS)

작은 예 — A = [8, 6, 7], S = 15 의 DP 표

초록 T = True. 노랑 테두리가 원하는 답 DP[2][15].

i \ S0123456789101112131415
i = 0 (A[0] = 8)TFFFFFFFTFFFFFFF
i = 1 (A[1] = 6)TFFFFFTFTFFFFFTF
i = 2 (A[2] = 7)TFFFFFTTTFFFFTTT

예: DP[2][15] = DP[1][15 − 7] or DP[1][15] = DP[1][8] or DP[1][15] = T or F = True. DP[1][8] 이 True 인 이유는 A[0] = 8 하나로 8 을 만들 수 있기 때문 → 답 {8, 7}.

점화식을 표로 채울 때 필요한 조건

① S − A[i] < 0 이면 DP[i − 1][S − A[i]] 칸이 없으므로 그쪽은 False 로 봅니다 (재귀의 S < 0 → False). ② DP[i][0] = True (재귀의 S == 0 → True). ③ 첫 행 i = 0 은 위 행이 없으므로 DP[0][S] = (S == 0 또는 S == A[0]) (재귀의 i == −1 → False). 위 표는 이 규칙으로 채웠습니다.

필기 원문
이 함수는 2개로 나눠짐(with 또는 without). 근데 인덱스 하나씩 줄고 S도 줄어드는거 보면 점화식을 찾을 수 있음 subsetsum2(A, i, S) = subsetsum2(A, i-1, S-A[i]) or subsetsum2(A, i-1, S) dp테이블처럼 생각해보면(재귀적으로 들어가는걸 표를 보고 그대로 쓰면 더 효율적) DP[i][S] = DP[i-1][S-A[i]] or DP[i-1][S] 라고 할 수 있음 의미 : A[0], ..., A[i] 고려 합이 S가 되는 부분집합이 있으면 트루 없으면 폴스를 DP[i][S]에 넣는거임 그러면 dp테이블 이용했을 때 수행시간 계산해보면 표를 하면(열은 S고 0, 1, 2, ..., S-1, S / 행은 i고 0, 1, 2, ..., n-1가 됨) 우리가 원하는건 가장 마지막 칸인 DP[n-1][S]임 결국 이 표를 다 채워야 연쇄적으로 구할 수 있음 그러니까 DP Size를 구해보면 행 n개 * 열 (S+1) = O(nS)가 되고 각각 칸을 계산하는 연산은 or 이용하는거라서 기본연산이 들어감 즉 최종 수행시간은 O(nS)가 됨

04O(nS) 의 문제 — 입력의 "값" 이 들어감

시험 ★★
교수님 예시

A = [1억, 5억, 1.5억, …, 7억] (10개), S = 20억 → O(nS) = O(10 × 20억). 수행시간에 입력의 크기가 아니라 입력의 값 S 가 들어가서, 실제보다 비정상적으로 크게 유추될 수 있음 → 바람직하지 않음.

nS
무엇인가원소 개수 = 입력의 크기목표 합의 값
숫자 단위만 바꾸면 (억 → 1)그대로 1020억 → 20 처럼 달라짐
정확한 용어

S 를 적는 데 필요한 자릿수(비트 수)는 log S 정도입니다. 그래서 O(nS) 는 입력의 길이 기준으로는 다항식이 아닐 수 있고, 이런 수행시간을 의사 다항 시간(pseudo-polynomial time) 이라고 부릅니다.

판서 확인

"억들 빼고 10 × 20 이 맞다" 는 모든 값이 1억의 배수일 때만 그대로 됩니다. 예시에 1.5억이 있으므로 모두를 0.5억으로 나누면 S = 40 이 됩니다. 교수님 뜻은 "값의 단위 때문에 수행시간이 부풀려진다" 는 것으로 보입니다 (추측).

필기 원문
예를 들어서 A = [1억, 5억, 1.5억, ..., 7억](10개) S = 20억이라고 하면 아까처럼 하면 T(n) = O(nS) = O(10*20억) ⇒ 이건 좀 너무 이상함 S처럼 입력의 크기가 아니라 입력의 값이 포함되는 경우가 있음. 이는 바람직하지 않음. 왜곡될 수 있기 때문에 사실 억들 빼고 10*20이 맞는건데 입력의 값이 시간복잡도에 들어가면 비정상적으로 크게 유추될 수 있음 = 바람직하지 않음

05subsetsum_sol — 답 부분집합 하나를 반환

시험 ★★★

subsetsum1 · subsetsum2 는 존재 여부(True / False) 만 봅니다. 이번에는 실제 답이 되는 부분집합 하나를 반환합니다 (모든 답이 아님).

의사코드subsetsum_sol(A, S) — 반환 누락 · 변수 이름 정리
def subsetsum_sol(A, S):
    if S == 0:
        return []                      # 다 맞췄음 → 더 넣을 것 없음 (빈 리스트)
    if S < 0 or len(A) == 0:
        return None                    # 불가능
    z = A[0]                           # 이번에 넣을지 정할 원소
    B = A[1:]                          # 나머지 원소 (재귀에 넘김)
    result = subsetsum_sol(B, S - z)   # z 를 넣고 나머지로 S − z 만들기
    if result is not None:             # 성공했으면
        return [z] + result            # z 를 앞에 붙여 반환
    return subsetsum_sol(B, S)         # z 를 넣으면 실패 → 안 넣고 시도
필기 확인 — 중요

필기의 result [Z] + result 는 return [Z] + result 여야 합니다. return 이 없으면 z 를 넣어서 성공해도 그 결과를 버리고 맨 아래 return subsetsum_sol(B, S) 로 넘어가서, z 를 넣은 답을 절대 반환하지 못합니다.

필기 질문에 대한 답

질문답
Z 를 소문자 z 로?네, 소문자가 일관됩니다. 11-1 의 subsetsum1 도 z 였습니다. 이름만 다를 뿐 동작은 같으므로 이 페이지는 z 로 씁니다. (시험에서 변수 이름이 바뀌어 나올 수 있으니 이름보다 역할로 기억하세요.)
z, B 는 무엇을 뜻하나z = 지금 넣을지 말지 결정하는 원소 (맨 앞 원소), B = 아직 결정 안 한 나머지 원소. "하나 정하고 나머지는 재귀에 맡긴다" 를 코드로 쓴 것입니다. 계산만을 위한 것은 아니고 읽기 쉽게 이름을 붙인 것이라, A[0], A[1:] 로 바로 써도 동작은 같습니다.
[] 와 None 의 차이(보충) [] = "성공, 더 붙일 원소 없음", None = "실패". 그래서 if result: 가 아니라 if result is not None: 으로 검사합니다. [] 는 if 에서 거짓으로 취급되어 성공을 실패로 착각하기 때문입니다.

예: A = [8, 6, 7, 5, 3, 10, 9], S = 15 → 반환 [8, 7]. 넣는 쪽을 먼저 시도하고, 성공하면 안 넣는 쪽은 호출하지 않습니다 (11-1 에서 교수님이 설명한 순서와 같음).

필기 원문
다시 돌아가서 subsetsum2로 돌아가면 subsetsum1도 그렇고 그러한 부분집합이 존재하는지 유무만 보는 알고리즘이었는데 그 부분집합을 구해보는 수도코드를 이번엔 적어볼거임 실제 답이되는 부분집합 반환하는 코드(모든 경우를 리턴하는게 아닌 그러한 답 1개 리턴하는 코드임) def subsetsum_sol(A, S): if S==0 : return [] if S<0 or len(A) == 0 : return None (불가능한 경우) Z = A[0] B = A[1:] result = subsetsum_sol(B, S-Z) (내 생각에는 z가 소문자가 되는게 더 보기 편하지 않을까..? 지금까지 나는 알파벳은 그냥 변수는 소문자, 배열을 대문자로 했던거같아서.. 그리고 Z, B를 왜 놓은건지 실질적으로 뭘 의미하는지 모르겠어. 그냥 계산을 위해 만든건가. 참고로 sol은 솔루션을 뜻해) if result is not None: #None이 아니고 다 무사통과했다면 result [Z] + result return subsetsum_sol(B, S)

06subsetsum_sol2 — 가능한 답을 모두 출력

시험 ★★★

X[k] = 1 이면 A[k] 를 넣음, 0 이면 안 넣음. 모든 답을 X 리스트로 출력합니다.

A = [8, 6, 7, 5, 3, 10, 9],  S = 15
X = [1, 0, 1, 0, 0, 0, 0]  → {8, 7}
X = [0, 0, 0, 1, 0, 1, 0]  → {5, 10}
의사코드subsetsum_sol2(k) — X[k] 를 정하는 함수, 첫 호출 subsetsum_sol2(0)
def subsetsum_sol2(k):                 # X[k] 결정: A[k] 를 넣으면 1, 안 넣으면 0
    if k == n:                         # X[0] ~ X[n-1] 을 다 정했으면
        current_sum = 0
        for i in range(n):             # 넣기로 한 원소의 합 계산
            if X[i] == 1:
                current_sum += A[i]
        if current_sum == S:
            print(X)                   # 합이 맞으면 출력
        return                         # 더 정할 X 가 없음 → 되돌아감
    X[k] = 1                           # A[k] 넣고
    subsetsum_sol2(k + 1)              #   다음 원소로
    X[k] = 0                           # A[k] 빼고
    subsetsum_sol2(k + 1)              #   다음 원소로
필기 확인

① if i in range(n): → for (반복이어야 합니다). ② if current_sum == S 뒤에 콜론. ③ print X → print(X). ④ k == n 블록 끝에 return 이 빠졌습니다 — 없으면 출력 후 X[n] = 1 을 실행해 범위를 벗어납니다 (IndexError). ⑤ 이름은 제안대로 앞의 것을 sol1 로 생각하면 헷갈리지 않습니다.

이 코드의 수행시간

원소마다 1 / 0 두 갈래로 끝까지 내려가므로 k == n 에 도달하는 경우가 2n 번, 그때마다 합 계산이 O(n) → O(n · 2n). 합이 이미 S 를 넘어도 끝까지 내려가는 것이 비효율적인 부분입니다. 교수님의 다음 질문 "좀 더 효율적으로 할 수는 없을까?" 가 여기서 이어집니다.

07용어 정리

DP[i][S]—

A[0] ~ A[i] 로 합 S 를 만들 수 있으면 True.

의사 다항 시간pseudo-polynomial time

(보충) 입력의 크기가 아니라 입력의 값(S) 에 대해 다항식인 수행시간. 예: O(nS).

None—

파이썬에서 "값이 없음". 여기서는 답이 없다(불가능) 는 표시.

X[k]—

A[k] 를 부분집합에 넣으면 1, 안 넣으면 0.
