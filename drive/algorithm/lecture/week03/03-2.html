02큰 수의 곱셈

분할 정복법의 또 다른 예 — 카라츠바 알고리즘(Karatsuba's algorithm). 엄청 큰 두 수의 곱셈을 효율적으로 하는 방법입니다.

왜 문제가 되는가

지금까지는 이런 코드가 있을 때

return select( … ) * select( … ) + 2

* 나 + 의 연산 시간을 상수로 처리했습니다. 그런데 그 숫자가 엄청 크다면 상수로 무시하기는 쉽지 않습니다.

"엄청 크다"는 게 어느 정도인가

C언어에서는 자료형을 정하고 시작합니다 — int, float, long … 그런데 이 자료형들은 담을 수 있는 크기가 정해져 있습니다. 그 한계를 아득히 넘는 숫자를 다룬다고 생각해 봅시다. 이건 그냥 상수 시간이 걸린다고 하기에는 무리가 있습니다.

필기 오타 — 고쳐서 반영

필기에는 "~32byte로 제한"이라고 되어 있는데, bit가 맞습니다. C의 int는 보통 4바이트 = 32비트이고 long long이 8바이트 = 64비트입니다. 32바이트면 256비트라 오히려 아주 큰 수를 담을 수 있게 됩니다.

철자도 함께 — Karatswba → Karatsuba, 한글로는 보통 카라츠바로 씁니다.

자리 번호 붙이기

n자리 수의 각 자리에 번호를 붙입니다. 오른쪽 끝이 0번입니다.

B = b₍ₙ₋₁₎ b₍ₙ₋₂₎ … b₁ b₀

04연산 횟수 세기 — O(n²)

시험 ★★☆

세로식에서 실제로 기본 연산이 몇 번 일어나는지 셉니다. 방향이 두 개입니다 — 가로는 곱셈, 세로는 덧셈.

① 곱셈 — n² 번

줄 하나를 만들려면 A의 n개 자리 각각에 bi를 곱해야 하므로 한 줄에 n번입니다. 그런 줄이 b₀부터 b₍ₙ₋₁₎까지 n개 있습니다.

n (한 줄) × n (줄 개수) = n² 번의 기본 곱셈

② 덧셈 — 2n² 번

줄을 다 만들면 세로로 같은 자리끼리 더합니다. 한 열에는 최대 n개의 숫자가 쌓이고, 열은 03번에서 본 대로 최대 2n개까지 생깁니다.

n (한 열) × 2n (열 개수) = 2n² 번의 기본 덧셈

③ 합계

연산방향한 줄/열당개수합
곱셈가로n번줄 n개n²
덧셈세로n번열 최대 2n개2n²
총합3n²
결론

초등학교 때 배운 곱셈 방법으로는 O(n²)이 걸립니다. 상수 3은 차수에 영향이 없으므로 떨어져 나갑니다.

주의 — 이건 아직 카라츠바 알고리즘이 아닙니다. 비교 대상이 되는 보통의 곱셈입니다.

필기 원문
한글로 카라츠바면 그걸로 통일하자 세로계산에서____ 밑에 각 줄마다 n번 계산을 하게 되고 그 줄이 n줄이 됨 즉 n^2의 기본 곱셈이 필요해 그리고 새로로는 덧셈을 하게 됨 n번씩 더하기가 각 줄마다 필요하게됨 n번 더하는게 줄마다 있는데 그 줄이 2n개까지 있다고 했기 때문에 더하는건 최대 2n^2번의 기본 덧셈 연산이 필요함 (이 내용들 도식에 넣어서 이해하기 쉽게 해야할거같아. 점점 복잡해져서) 최종적으로 3n^2의 기본 연산이 필요하게 됨 결론 : 초등학교 때 배웠던 곱하기의 방법으로는 O(n^2) 소요된다는 걸 알 수 있음 (카라츠바 알고리즘 아님 주의)

05분할 정복으로 — 수를 반으로 쪼개기

기본 곱셈은 O(n²)였습니다. 이걸 분할 정복법으로 더 낫게 만들어 보고 싶어집니다. 분할 정복은 나눠서 자기 자신을 다시 호출하는 것이니, 무엇을 나눌지부터 생각합니다.

왜 하필 절반인가

앞에서 절반씩 나눌 때 효율이 좋다는 감을 익혔습니다(power3, max 반분할). 그래서 자리수도 n2 기준으로 자릅니다.

u = x·10n2 + y 가 무슨 뜻인가

필기에 "이 부분 이해 잘 안돼"라고 적어두신 곳입니다. 결론부터 말하면 당연한 식인데, 기호로 써 놓으니 낯설어 보일 뿐입니다.

n자리 수 u의 자리를 앞뒤로 갈라 봅니다.

u =an−1 an−2 … an2앞 절반 = xan2−1 … a1 a0뒤 절반 = y

그런데 x를 따로 떼어내 "14" 같은 수로 보면, 원래 있던 자리값이 사라집니다. 원래 x는 n2번째 자리부터 시작했으니, 그만큼 왼쪽으로 다시 밀어줘야 합니다. 왼쪽으로 n2칸 미는 것이 곧 10n2을 곱하는 것입니다.

u = x · 10n2 + y
v = w · 10n2 + z        ← v 도 똑같이 앞을 w, 뒤를 z 로
필기 원문
그렇다면 원래 알고 있던 기본 곱셈은 O(n^2) 인데 이걸 효율적으로 하기 위해서 분할 정복법을 적용해서 O(n^2)보다 더 나은 알고리즘을 만들고싶어짐 분할정복법은 나눠서 자기 자신을 다시 호출하게 하는건데 그렇다면 뭔가 나누는걸 생각해보자. 두 수 u, v 가 있다고 해보자 u = a_(n-1) a_(n-2) ... a(n/2) a(n/2 -1) ... a_1 a_0 a_(n-1) ~ a_(n/2)를 x, 그 뒤에를 y로 나눠보자 (우리가 절반 정도 나눠야 효율이 좋다는 감을 익혔었고 그렇기 때문에 밑도 n/2 식으로 세팅한거임 u = x * 10^(n/2) + y (이 부분 이해 잘 안돼) v = b_(n-1) b_(n-2) ... b(n/2) b(n/2 -1) ... b_1 b_0 이것도 앞 절반 정도를 w, 뒤를 z = w * 10^(n/2) + z

07점화식 세우기

n자리 × n자리에 걸리는 시간을 T(n)이라 하면, n2자리 곱셈을 4번 호출하므로 일단:

T(n) = 4 · T(n2) + ?

왜 뒤에 C 가 아니라 C·n 이 붙는가

필기에 "무슨 개소리야"라고 적어두신 곳입니다. 지금까지는 덧셈 한 번을 상수 C로 봤는데, 여기서는 그럴 수 없습니다. 다루는 수가 엄청 크기 때문입니다.

해야 하는 일실제 작업비용
10n 곱하기뒤에 0을 n개 붙이는 것n에 비례
10n2 곱하기뒤에 0을 n2개 붙이는 것n2에 비례
세 덩어리 더하기최대 2n자리끼리의 덧셈 — 자리마다 한 번씩n에 비례

전부 n에 비례합니다. 다 합쳐도 결국 n의 상수배이므로 C·n으로 씁니다.

여기가 핵심 — 왜 C가 아닌가

작은 수라면 "a + b" 는 연산 한 번이라 C입니다. 그런데 n자리짜리 두 수를 더하는 것은 연산 한 번이 아니라 자리마다 한 번씩, 총 n번의 덧셈입니다. 그래서 C가 아니라 C·n 입니다.

T(n) = 4·T(n2) + C·n ,   T(1) = C
필기 원문
n자리 * n자리 가 T(n) 걸린다고 하면 n/2자리를 4번 정도 호출해야하는데 T(n) = 4 * T(n/2) 가 되는데 (+C로 안끝나는 이유 : 엄청 큰 수를 취급하고 있기 때문에 덧셈 같은 식을 C로 무시할 수 없음) 10^n 은 n번 소요 10^(n/2)는 n/2번 소요 그래서 덧셈을 할 때 C n 번 소요됨(무슨 개소리야) 그래서 T(n) = 4*T(n/2) + C*n 정도가 됨 [본인 요청으로 과제 관련 메모 일부 제외] T( n) = 4*T(n/2) + C*n / T(1) = C

     = 4·( 4·T(n2²) + C·n2 ) + Cn
     = 4²·T(n2²) + 4C·n2 + Cn
     = 4²·T(n2²) + 2Cn + Cn                   ← 4 × n2 = 2n

     = 4²·( 4·T(n2³) + C·n2² ) + 2Cn + Cn
     = 4³·T(n2³) + 4²C·n4 + 2Cn + Cn
     = 4³·T(n2³) + 2²Cn + 2¹Cn + 2⁰Cn         ← 규칙이 보이도록 2? 꼴로
     ...
     = 4k·T(n2k) + 2k−1Cn + … + 2¹Cn + 2⁰Cn

정리하기

n = 2k 이므로 n2k = 1 이고, T(1) = C 입니다.

= 4k · C + Cn·( 2⁰ + 2¹ + … + 2k−1 )
괄호 안은 등비수열

초항 1, 공비 2, 항의 개수 k개입니다. (등차수열이 아닙니다.)

2⁰ + 2¹ + … + 2k−1 = 1·(2k − 1)2 − 1 = 2k − 1
= C·4k + Cn·(2k − 1)
= C·4k + Cn·2k − Cn
개념 잠깐 — 지수 바꿔 쓰기
(ab)c = (ac)b

이걸 쓰면 4k을 n²으로 바꿀 수 있습니다.

4k = (2²)k = (2k)² = n²        ← n = 2k 이므로
= C·n² + Cn·n − Cn        ← 4k = n² , 2k = n
= Cn² + Cn² − Cn
= 2Cn² − Cn
⇒ O(n²)
그래서 결론은 — 나아진 게 없다

반으로 쪼개서 분할 정복을 적용했는데도 여전히 O(n²)입니다. 기본 곱셈과 차수가 똑같습니다.

원인은 곱셈을 4번 하기 때문입니다. 크기를 절반으로 줄인 이득(2배)을, 호출을 4배로 늘려 그대로 까먹습니다. 05번 power2에서 "반씩 쪼갰는데 2번 불러서 이득이 없었다"던 것과 같은 상황이고, 여기서는 4번이라 더 심합니다.

필기 원문
가정 : n = 2^k = 4*(4*T(n/2^2 + C * (n/2)) + C *n = (4^2) * T(n/(2^2)) + 2*C*n + C*n = (4^2) * (4 * T(n/(2^3)) + C*(n/(2^2)) + 2*C*n + C*n = (4^3) * T(n/(2^3)) + 2^2 C n + 2^1 C n + C n * 2^0 (규칙 찾기 위해 2^? 로 나타낸거야) ... 규칙 파악 어디까지 계산한다? n이 2^k까지 할 수 있으니까 = 4^k * T(n/2^k) + 2^(k-1)*C*n + ... + 2^0 * C * n 2^k는 n이니까 4^k * C + Cn(2^0+...+2^(k-1)) // C가 된 이유는 T(1) = C 4*k * C + (2^0(2^k -1))/(2-1) //등비수열인지 등차수열 하는 중이었는데 놓친거같음 = C* 4^k + Cn2^k - C n 개념 잠깐 (a^b)^c = (a^c)^b = C*n^2 + Cn^2 - C n //4^k = (2^k)^2 = 2Cn^2 - C n = O(n^2) 너무 어려워서 설명 잘해줘야돼 이번 차시
필기 오타 — 고쳐서 반영

4*k * C + (2^0(2^k -1))/(2-1) 줄이 흐트러져 있었습니다. 4k·C + Cn·(2k − 1) 이 맞습니다 — 4*k가 아니라 4k이고, 등비수열 합 앞에 Cn이 곱해져야 합니다. 바로 다음 줄부터는 정확합니다.

09카라츠바 — 곱셈 4번을 3번으로

교수님 강조시험 ★★★

08번 결과가 O(n²)이라 기존과 다를 게 없었습니다. 무엇이 문제였나 — T(n) = 4·T(n2) + C·n 에서 4가 문제입니다. 이 4를 낮추는 것이 목표이고, 그걸 해결한 것이 카라츠바 알고리즘입니다.

시작은 똑같습니다. u와 v를 x·y, w·z로 쪼갭니다.

u · v = x·w·10n + (x·z + y·w)·10n2 + y·z        ← 06번 식 그대로

"xw랑 yz가 두 번 호출되는 걸 보고" — 무슨 뜻인가

필기에 "뭔소리야"라고 적어두신 곳입니다. 핵심은 이겁니다.

xw 와 yz 는 어차피 이미 구해야 하는 값이다

위 식을 보면 x·w 는 맨 앞 항(10n 자리)에, y·z 는 맨 뒤 항에 반드시 필요합니다. 즉 이 둘은 무조건 계산합니다.

문제는 가운데 항 x·z + y·w 입니다. 이걸 구하려고 곱셈을 두 번 더 하니까 총 4번이 됩니다.

그래서 카라츠바는 이렇게 생각합니다 — "이미 가지고 있는 xw와 yz를 써먹어서, 가운데 항을 곱셈 한 번으로 얻을 수 없을까?"

식 바꾸기

(x+y)(w+z)를 전개해 보면 필요한 것이 들어 있습니다.

(x + y)(w + z) = x·w + x·z + y·w + y·z
                   └┬─┘  └───┬───┘  └┬─┘
                  이미 있음  원하는 것  이미 있음

그러니 이미 가진 두 개를 빼내면 원하는 것만 남습니다.

x·z + y·w = (x + y)(w + z) − x·w − y·z
"xw랑 yz가 사라짐(맞나)" — 정확히는 아닙니다

사라지는 게 아니라 재활용되는 것입니다. xw와 yz는 여전히 필요하고 여전히 계산합니다. 다만 한 번 구해둔 값을 가운데 항에서 다시 쓰는 것이라, 새로 곱셈을 할 필요가 없습니다. 뺄셈만 하면 됩니다.

u · v = x·w·10n + ( (x+y)(w+z) − x·w − y·z )·10n2 + y·z
숫자로 확인 — 1487 × 2356

x=14, y=87, w=23, z=56

① x·w         = 14 × 23 = 322
② y·z         = 87 × 56 = 4,872
③ (x+y)(w+z)  = 101 × 79 = 7,979

x·z + y·w = ③ − ① − ② = 7979 − 322 − 4872 = 2,785

u·v = 322×10⁴ + 2785×10² + 4872
    = 3,220,000 + 278,500 + 4,872 = 3,503,372  ✓

06번에서 곱셈 4번으로 구했던 값(x·z + y·w = 784 + 2001 = 2785)과 같습니다. 곱셈 3번만으로 같은 결과를 얻었습니다.

필기 오타 — 고쳐서 반영

xz + yz = (x+y)(w+z) − xw − yz → 좌변은 xz + yw 입니다. 우변을 전개하면 xw + xz + yw + yz − xw − yz = xz + yw 이므로 그렇습니다.

필기 원문
이렇게 해도 O(n^2)이네? 기존이랑 다를게 없네 그래서 뭐가 문제냐 T(n) = 4*T(n/2) + C*n 에서 4를 낮추는게 목표이고 이걸 해결한게 카라츠바 알고리즘임 저 4를 줄여보자 카라츠바 알고리즘도 시작은 똑같음(아까 u, v에 x랑 y로 w z 로 나누는거) u*v = x*w*10^n + (xz + yw) * 10^(n/2) + yz //아까 식임 카라츠바는 이걸 모양을 바꾸려고 했음 xw랑 yz가 두 번 호출되는걸 보고 이걸 바꾸려고 함(뭔소리야) xz+yz = (x+y)(w+z) -xw-yz이고 xw랑 yz가 사라짐(맞나) u * v = x*w*10^n + ((x+y)(w+z)-xw-yz)*10^(n/2) + yz

한 단계씩 펼치기

     = 3·( 3·T(n2²) + C·n2 ) + Cn

     = 3k·T(n2k) + (32)k−1Cn + … + (32)¹Cn + (32)⁰Cn

n = 2k 이므로 n2k = 1 이고 T(1) = C 입니다.

= 3k·C + Cn·( (32)⁰ + (32)¹ + … + (32)k−1 )
괄호 안은 등비수열

앞 항에 32를 계속 곱해 나가므로 등비수열입니다. (등차수열은 일정한 수를 더해 나가는 것입니다.)

합 = a(rk − 1)r − 1 = 1·((32)k − 1)32 − 1 = (32)k − 112 = 2·( (32)k − 1 )

12로 나누는 것은 2를 곱하는 것과 같아서 앞에 2가 붙습니다.

= 3k·C + 2Cn·( (32)k − 1 )

≈ 3k·C + 2Cn·(32)k

k를 n으로 바꾸기

가정이 n = 2k 였으므로 k = log₂ n 입니다. 그대로 대입합니다.

= C·3log₂ n + 2Cn·(32)log₂ n
여기서 쓰는 로그 성질 — 밑과 지수 바꿔치기
alogb c = clogb a

왜 성립하는지 확인하려면 양변에 logb 를 취해 보면 됩니다. 왼쪽은 logb c · logb a, 오른쪽은 logb a · logb c 로 곱하는 순서만 다를 뿐 같습니다.

이걸 쓰면 밑에 있던 3과 지수에 있던 n의 자리가 바뀝니다.

3log₂ n     = nlog₂ 3
(32)log₂ n = nlog₂ 32
= C·nlog₂ 3 + 2Cn · nlog₂ 32
= C·nlog₂ 3 + 2C·n log₂(32) + 1         ← na · nb = na+b
두 번째 로그 성질 — 더하기를 곱하기로
loga b + loga c = loga (b·c)

지수 부분의 +1을 로그로 바꿔 넣으면 하나로 합쳐집니다.

log₂(32) + 1 = log₂(32) + log₂ 2        ← 1 = log₂ 2
              = log₂( 32 × 2 )
              = log₂ 3
= C·nlog₂ 3 + 2C·nlog₂ 3
= 3C·nlog₂ 3
⇒ O( nlog₂ 3 )

T(n) = O(nlog₂3), 그리고 log₂3 ≈ 1.585 입니다. O(n²)보다 차수 자체가 낮습니다.

def bs(A, a, b, k):
    if a > b:
        return -1              # 범위가 뒤집힘 = 리스트에 없음
    m = (a + b) // 2          # 가운데 자리
    if A[m] == k:
        return m               # 값이 아니라 '인덱스'를 반환
    elif A[m] > k:
        return bs(A, a, m-1, k)  # 찾는 값이 더 작음 → 왼쪽 절반만
    else:
        return bs(A, m+1, b, k)  # 찾는 값이 더 큼 → 오른쪽 절반만

14이진탐색의 시간복잡도

한 번 호출할 때마다 비교 몇 번(상수 C)을 하고, 범위가 절반으로 줄어든 문제로 넘어갑니다. 재귀 호출은 한 번뿐입니다 — 왼쪽이든 오른쪽이든 하나만 타니까요.

T(n) = T(n2) + C ,   T(1) = C

전개 — 교수님이 못 적어주신 부분

T(n) = T(n2) + C
     = T(n2²) + C + C
     = T(n2³) + C + C + C
     ...
     = T(n2k) + k·C          ← C 가 k개

가정이 n = 2k 이므로 n2k = 1 이고, T(1) = C 입니다.

= T(1) + k·C
= C + k·C

n = 2k 에서 k = log₂ n 이므로:

= C + C·log₂ n
⇒ O(log n)
결론

단순 탐색의 O(n) → 이진탐색은 O(log n).
