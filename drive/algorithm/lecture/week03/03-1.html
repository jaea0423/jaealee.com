01분할 정복법

분할 정복법 (Divide & Conquer)

큰 문제 ⇒ 작은 문제  →  재귀적

문제를 그대로 풀기 어려울 때, 같은 형태의 더 작은 문제로 쪼갠 뒤 그 답을 이용해 원래 답을 만드는 방법입니다. 쪼갠 문제가 원래 문제와 같은 형태이므로 자연스럽게 재귀(recursion)가 됩니다.

02max(A) — 하나 vs 나머지

리스트 A가 다음과 같다고 합시다.

A :  3   0   -5   7   2   -4   6   9

가장 큰 값을 구하는 알고리즘 max(A)를 분할해서 풀 수 있습니다. 맨 처음 수 A[0]와 나머지 전체의 최댓값을 비교하면 됩니다.

재귀식

max(A) = max( A[0] , max(A[1:]) )
두 max는 서로 다른 것입니다 — 주의
위치무엇인가
바깥쪽 max( … , … )두 수 중 큰 값을 고르는 연산. 인자가 두 개.
안쪽 max(A[1:])우리가 만들고 있는 알고리즘 함수. 인자가 리스트 하나.

이름만 같고 하는 일이 다릅니다. 헷갈리면 안쪽을 maxOfList 같은 다른 이름으로 바꿔 읽으면 구분이 쉽습니다.

시간복잡도

한 번 호출할 때마다 비교 1번(상수 C)을 하고, 크기가 1 작아진 문제로 넘어갑니다.

T(n) = T(n−1) + C ,   T(1) = C
     = T(n−2) + C + C
     = T(n−3) + C + C + C
     ...
     = T(1) + (n−1)·C
     = C + (n−1)·C = Cn
⇒ O(n)

이 방식은 리스트를 원소 하나 vs 나머지로 분할한 경우입니다.

필기 원문
A : 3 0 -5 7 2 -4 6 9 이런 리스트가 있다면 가장 큰 값을 구하는 알고리즘 max(A)가 있다고 하자. 우리는 이걸 분할해서 풀 수 있었음 맨 처음 수 A[0]와 A[1:](나머지)를 비교해서 구할 수 있음(도식화) A[0] vs max(A[1:] ) max(A[1:])이 더 크다면 다시 A[1] vs max(A[2:]) max (A) = max(//max는 두 수 중 큰 값을 구하는 것임)(A[0], max(A[1:])) 다른 max는 알고리즘 함수임(두 수 중 큰 값을 구하는 max와 다름 주의)

03max(A) — 반씩 분할

이번에는 같은 문제를 반반으로 쪼갭니다. A가 8개이므로 앞 4개와 뒤 4개로 나눕니다.

인덱스 표기 주의

A[:4]라고 써야 인덱스 3까지 포함(0~3)합니다. 파이썬 슬라이싱은 끝 번호를 포함하지 않습니다.

재귀식

max(A) = max( max(A[:4]) , max(A[4:]) )
         ↑        ↑              ↑
      알고리즘   알고리즘        알고리즘
         └─ 이 자리의 max 만 "두 수 중 큰 값"을 고르는 비교 연산

시간복잡도

절반으로 자르니 각각 T(n/2)이고, 마지막 비교 1번이 상수 C입니다.

T(n) = T(n/2) + T(n/2) + C
     = 2T(n/2) + C ,   T(1) = C

     = 2( 2T(n/4) + C ) + C            = 2²·T(n/4) + 2C + C
     = 2²( 2T(n/8) + C ) + 2C + C      = 2³·T(n/2³) + 2²C + 2C + C
     ...
     = 2^k·T(n/2^k) + 2^(k−1)C + 2^(k−2)C + … + 2C + C     ← n = 2^k 로 가정
     = n·T(1) + C(2^(k−1) + 2^(k−2) + … + 2 + 1)
잠시 복습 — 등비수열의 합

초항 a, 공비 r, 항의 개수 n개일 때

a + ar + ar² + … + ar^(n−1) = a(r^n − 1)r − 1     (r > 1 일 때 쓰기 편한 꼴)

                              = a(1 − r^n)1 − r     (r < 1 일 때 쓰기 편한 꼴)

여기서는 초항 a = 1, 공비 r = 2, 항의 개수 k개이므로

1 + 2 + 2² + … + 2^(k−1) = 1·(2^k − 1)2 − 1 = 2^k − 1
T(n) = Cn + C(2^k − 1)        ← T(1) = C 이므로 n·T(1) = Cn
     = Cn + C(n − 1)          ← n = 2^k 이므로 2^k = n
     = 2Cn − C
⇒ O(n)
비교

하나씩 떼든 반씩 자르든 둘 다 O(n)입니다. 나아가 반반이 아니라 n/3과 2n/3으로 쪼개도 똑같이 O(n)이 나옵니다.

필기 오타 3건 — 고쳐서 반영했습니다
필기맞는 것
(a가 더 작으면 = a(1−r^n)/(1−r)r이 1보다 작을 때 쓰는 꼴입니다. a와는 관계없습니다.
공비가 2고 초항이 1이고 항의 개수가 초항이므로항의 개수는 k입니다.
2Cn − C  // 2^k을 C라고 가정했기 때문2^k = n 이기 때문입니다. C는 상수이고 2^k와 무관합니다.
필기 원문
T(n) = T(n-1) + C, T(1) = C = T(n-2) + C + C ... ⇒ O(n) (이 경우는 리스트를 하나의 원소 vs 나머지 분할) 이번엔 다른 방식 반씩 분할 A : 3 0 -5 7 2 -4 6 9 가 있다면 이걸 반반씩 분할(도식화) max(A[:4] //이렇게 적어야 인덱스 3까지 포함(0~3)) max(A[4:]) 이렇게 분할 가능 max(알고리즘 max)(A) = max(얘는 비교 수식 max)(max(얘는 알고리즘 max)(A[:4]), max(알고리즘 max)(A[4:)) T(n) = T(n/2) + T(n/2) + C //T(n/2)인 이유는 절반으로 자르니까 T(n) = 2T(n/2) + C , T(1) = C = 2(2T(n/4)+C) + C = 2^2 * T(n/4) + 2C + C = 2^2 (2 T(n/8) + C) + 2C + C = 2^3 T(n/(2^3)) + 2^2 C + 2C + C ... 가정 n = 2^k 규칙을 찾아보면 = 2^k T(n/2^k) + 2^(k-1) C + 2^(k-2) C + ... + 2^1 C + 2^0 C = nT(1) + C(2^(k-1) + 2^(k-2) + ... + 2^1 + 2^0) *잠시 복습 : 등비수열 합 : ar^0 + ar^1 + ar^2 + ... + ar^(n-1) (n개) = (ar^0(r^n - 1)) / (r-1) = (a(r^n -1)) / r - 1 여기서 a는 초항 n은 항의 개수, r은 공비 (a가 더 작으면 = a(1-r^n) / (1-r) 그러면 공비가 2고 초항이 1이고 항의 개수가 초항이므로 (1(2^k - 1)) / 2-1 = 2^k - 1 = Cn + C(2^k - 1) // T(1) = C이기 때문 = 2Cn - C // 2^k을 C라고 가정했기 때문 = O(n) 만약에 반반이 아니라 1n/3, 2n/3으로 쪼개도 동일하게 O(n)이 나옴

04an — power1 (하나씩 줄이기)

예: a = 3, n = 4 → 34

거듭제곱도 같은 방식으로 쪼갤 수 있습니다.

a^n = a × a^(n−1)
  ⇒  power1(a, n) = a × power1(a, n−1)
Pythonpower1
def power1(a, n):
    if n == 1: return a      # 기저 조건 — 상수 시간
    return a * power1(a, n-1)  # 곱셈 1번 + 크기 1 작은 문제

시간복잡도

호출마다 곱셈 1번(상수 C)을 하고 n이 1씩 줄어듭니다. 앞의 "하나 vs 나머지" max와 똑같은 모양입니다.

T(n) = T(n−1) + C ,   T(1) = C
⇒ O(n)
필기 원문
a^n 구하기 ex) a = 3, n = 4 → 3^4 power1(a, n) ⇒ a^n = a * a^(n-1) = power1(a,n) = a * power1(a, n-1) power1(a, n): if n==1 : return a return a * power1(a,n-1) T(n) = T(n-1) + C , T(1) = C ⇒ O(n) 3주차 1차시가 맞아. 미안

05an — power2 (반씩 쪼개기)

power1은 n을 1씩 줄였습니다. 이번에는 반씩 쪼갭니다. an = an/2 × an/2 이니까요. 다만 n이 홀수면 반으로 딱 안 나뉘어 1이 남습니다.

Pythonpower2
def power2(a, n):
    if n == 1: return a
    if n % 2 == 0:                          # n이 짝수이면
        return power2(a, n//2) * power2(a, n//2)
    else:                                    # n이 홀수이면
        return power2(a, n//2) * power2(a, n//2) * a   # 나머지 1이 남아서 a를 한 번 더 곱함

시간복잡도

재귀 호출이 두 번 일어나고 각각 크기가 n/2입니다. 곱셈은 상수 C입니다.

T(n) = T(n/2) + T(n/2) + C
     = 2·T(n/2) + C
⇒ O(n)
반씩 쪼갰는데 왜 안 빨라졌나

앞의 max를 반씩 쪼갰을 때와 완전히 같은 점화식(2T(n/2) + C)이 나왔습니다. power1도 O(n)이었으니, power2는 power1보다 나아진 게 없습니다.

원인은 power2(a, n//2)를 두 번 부른다는 데 있습니다. 같은 인자로 같은 값을 구하는 계산을 두 번 하는 셈이라, 반으로 줄인 만큼을 호출 횟수가 두 배로 늘어 그대로 상쇄해 버립니다.

앞 내용과의 연결

03번의 max를 반씩 쪼갠 경우와 점화식이 똑같습니다. 거기서는 왼쪽 절반과 오른쪽 절반이 서로 다른 데이터라 두 번 부르는 게 당연했지만, 여기 power2는 완전히 같은 계산을 두 번 합니다. 같은 점화식이라도 사정이 다릅니다.

필기 원문
power2(a, n) : if n==1 : return a if n%2 == 0 //n이 짝수이면 return power2(a, n//2) * power2(a, n//2) else : //n이 홀수이면 return power2(a, n//2) * power2(a, n//2) * a //*a를 하는 이유 : 나머지 1이 남기 때문 T(n) = (n/2) + T(n/2) + C = 2 * T(n/2) + C ⇒ O(n)

06an — power3 (중복 호출 제거)

시험 ★★★

power2의 문제는 power2(a, n//2)를 두 번 부른 것이었습니다. 한 번만 불러서 변수에 담아두고 재사용하면 됩니다.

Pythonpower3
def power3(a, n):
    if n == 1:
        return a
    x = power3(a, n//2)      # 재귀 호출은 딱 한 번만
    if n % 2 == 0:
        return x * x             # 구해 둔 x 를 두 번 쓰기만 한다
    else:
        return x * x * a         # 홀수면 나머지 1 때문에 a 를 한 번 더

시간복잡도

T(n) = T(n/2) + C ,   T(1) = C
     = T(n/4) + C + C
     = T(n/8) + C + C + C
     ...
     = T(n/2^k) + k·C          ← n = 2^k 로 가정
     = T(1) + k·C              ← n = 2^k 이므로 n/2^k = 1
     = C + k·C                 ← k = log₂ n
     = C·log₂ n + C
⇒ O(log n)

세 방법 비교

쪼개는 방식재귀 호출 횟수점화식시간복잡도
power1n → n−11번T(n−1) + CO(n)
power2n → n/22번 (중복)2T(n/2) + CO(n)
power3n → n/21번T(n/2) + CO(log n)
핵심

power2와 power3는 쪼개는 방식이 똑같습니다. 차이는 오직 재귀 호출을 몇 번 하느냐뿐인데, 그것만으로 O(n)과 O(log n)이 갈립니다. 분할 정복에서 "어떻게 쪼개느냐"만큼 "쪼갠 결과를 몇 번 계산하느냐"가 중요합니다.

필기 원문
power3 (a, n) : if n==1 : return a x = power3(a, n//2) if n%2 == 0 : return x*x else : return x*x*a ⇒ T(n) = T(n/2) + C, T(1) = C = T(n/4) + C + C = T(n/8) +C +C +C ... * 가정 n=2^k = T(n/(2^k)) + k*C = T(1) + k*C //2^k를 n이라고 가정했기 때문 //k = log_2 n = C*log_2 n + C = O(log n)

07피보나치 수 — fibo1

처음 두 수가 주어지고(0, 1 — 꼭 0과 1이 아니어도 됩니다), 그다음 수는 앞의 두 수를 더한 값입니다.

0  1  1  2  3  5  8  13  21  …
필기 오타 — 고쳐서 반영

필기에는 … 5 8 14 21로 되어 있었는데, 5 + 8 = 13입니다. 그래야 8 + 13 = 21로 이어집니다.

이 피보나치 수도 점화식으로 나타낼 수 있는지 확인해 봅니다.

F₀, F₁, …

F(n) = F(n−1) + F(n−2)
Pythonfibo1 — F(n)을 반환
def fibo1(n):
    if n == 0 or n == 1:
        return n            # 이 예에서는 F(0)=0, F(1)=1 이라 n을 그대로 반환하면 된다
    return fibo1(n-1) + fibo1(n-2)

시간복잡도

T(n) = T(n−1) + T(n−2) + C ,   T(0) = C ,  T(1) = C

이 점화식을 직접 푸는 것은 수업 범위를 넘어섭니다. 결과만 말하면:

T(n) = O(γ^n) ,   γ = 1 + √52 = 1.618…

이렇게 시간복잡도가 지수로 올라오면 exponential하게 걸린다고 하고, bad하다고 말합니다. 시간복잡도가 좋지 않다는 뜻입니다.

왜 이렇게 오래 걸리나 — 역토너먼트 구조

F(n)에서 시작해 F(n−1)·F(n−2)로, 다시 각각이 둘로 갈라집니다. 토너먼트가 위로 좁아지는 것과 반대로 아래로 퍼져 나가는 모양입니다.

power2에서 본 것과 같은 문제

05번의 power2가 같은 인자를 두 번 불러서 손해를 봤던 것과 구조가 같습니다. 다만 power2는 중복이 좌우 두 갈래뿐이라 O(n)에서 그쳤지만, 피보나치는 중복이 트리 전체에 퍼져 지수까지 올라갑니다.

그리고 거듭제곱은 이미 06번에서 power3로 O(log n)에 푸는 법을 배웠습니다. 숫자 대신 행렬을 넣어도 같은 수법이 통하므로, 지수 시간이던 피보나치를 로그 시간으로 끌어내릴 수 있습니다. 바로 다음 11번이 그 내용입니다.
