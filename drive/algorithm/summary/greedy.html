3. 하루에 할 수 있는 일의 개수9-2

문제 · 전략 · 결과→ 단원 정리 p.5

문제
일의 개수 최대 (A = [2, 1, 4, 6, 3], T = 9)
전략
소요시간 짧은 일부터
결과
1 + 2 + 3 = 6, +4 = 10 > 9 → 3개 (1 + 3 + 4 등 다른 조합도 3개, 개수가 답)

증명 뼈대 (귀류법)→ 단원 정리 p.5

a1~a3 = 그리디 해, a4 = 그다음 짧은 일
  1. 가정
    최적이 아님 → 4개 가능: b1 ≤ … ≤ b4
    X = a1+a2+a3, Y = b1+b2+b3
  2. ①
    X + a4 > T
    그리디가 멈춤
  3. ②
    Y + b4 ≤ T
    가정 (b 4개는 가능)
  4. ③
    X ≤ Y,  a4 ≤ b4
    a 는 가장 짧은 것들
  5. 모순
    ③ + ② → X + a4 ≤ T ↔ ①
  6. 결론
    짧은 일부터 = 최적
헷갈리는 점 · 판서 정정
  • 왜 4개만? 5개 이상이어도 그중 4개는 T 안 → 4개가 불가능하면 그 이상도 불가능
  • 그리디 해가 k 개면: 가정 "k + 1 개", X · Y = 앞 k 개의 합, ak+1 ≤ bk+1
  • ④ a₄ ≤ b₄ 의 이유: a₄ = 전체에서 4번째로 작은 값, b₄ = 서로 다른 4개 중 가장 큰 값

4. 강의실 배정10-1

문제 · 전략 후보→ 단원 정리 p.7

문제
한 강의실에 강의 개수 최대 (S[i] ~ F[i], 11개 예시 → 최대 4개)
#전략판단
1짧은 강의부터반례: a 가 b, c 를 막음
2빨리 시작하는 것부터반례: a 가 b, c, d 를 막음
3가장 적게 겹치는 것부터이유 미확인
4빨리 끝나는 것부터최적 — 남은 시간이 많게

알고리즘 · 결과→ 단원 정리 p.7

pseudocode빨리 끝나는 강의부터
1. F 오름차순 정렬          # O(n log n)
2. L = [0], k = 0           # k: 최근 배정 강의
3. for i in range(1, n):
       if F[k] <= S[i]:
           L.append(i), k = i
4. return L / len(L)
시간
정렬 O(n log n) + for 문 O(n) = O(n log n)
결과
0 (끝 4) → 3 (5~7) → 7 (8~11) → 10 (12~14) → L = [0, 3, 7, 10]

증명 뼈대 (귀류법)→ 단원 정리 p.9

그리디 해 (0, 3, 7, 10)
  1. 가정
    최적 아님 → 5개: a1, …, a5
  2. a1→0
    0번이 가장 빨리 끝남 (F[0] ≤ F[a1]) → 바꿔도 안 겹침
  3. 집합
    A1 ⊂ G1
    G1: 0번과 안 겹침, A1: a1 과 안 겹침
  4. a2→3
    3번 = G1 중 가장 빨리 끝남 → 바꿔도 됨
  5. 연쇄
    a3→7, a4→10 → (0, 3, 7, 10, a5)
  6. 모순
    a5 는 10 뒤에 시작 → for 문이 모든 강의를 훑으므로 그리디가 놓칠 수 없음
  7. 결론
    빨리 끝나는 것부터 = 최적
헷갈리는 점 · 판서 정정
  • 포함 방향: A1 ⊂ G1 (처음 필기 G₁ ⊂ A₁ 은 반대)
  • 끝나는 시간이 같아도 바꿔치기 가능 (≤)
  • 모순의 근거 = "for 문이 모든 인덱스를 훑는다"

5. Huffman 코딩10-1, 10-2

왜 가변 길이 코드인가→ 단원 정리 p.10

고정 길이
ASCII 8비트 (100자 → 800비트), 문자 6개면 3비트 → 100 × 3 = 300비트
가변 길이
많이 나오는 문자 = 적은 비트 → 예시 230비트
prefix-free
어떤 코드도 다른 코드의 앞부분이 아님 (반례: 0, 1, 00 … → 00 이 aa 인지 c 인지 모름)
이진 트리
왼쪽 0, 오른쪽 1, 문자 = 리프만 → prefix-free 자동 만족

비용과 그리디 전략→ 단원 정리 p.11

cost(T) = Σx f(x) · dT(x)  → 최소화
전략
빈도가 가장 작은 두 개를 합침, 합친 노드의 빈도 = 두 빈도의 합
예시
16 (f 7 + e 9) → 25 (c 12 + b 13) → 32 (16 + d 16) → 57 (25 + 32) → 100 (a 43 + 57)
문자abcdef
빈도4313121697
코드010110011111011100
헷갈리는 점 · 판서 정정
  • f = 1100 (판서 1110 은 오류 — d 111 이 앞부분이 됨)
  • d 의 깊이 3, 빈도 16 (판서 15)
  • 최적 트리는 하나가 아님 (가지 방향에 따라 다름)

의사코드와 시간→ 단원 정리 p.12

pseudocodeHuffman
def Huffman(T):
    while len(T) > 1:
        x = extract_min(T)    # O(log n)
        y = extract_min(T)
        z = Node(left = x, right = y)
        f(z) = f(x) + f(y)
        insert(T, z)          # O(log n)
    return T
min heap
extract_min: 루트 꺼내고 마지막 노드를 루트로 → heapify_down / insert: 마지막에 넣고 heapify_up — 둘 다 O(h) = O(log n)
전체
while n 번 × O(log n) = O(n log n)

보조 명제 1 — x, y 를 가장 깊은 형제로→ 단원 정리 p.13

빈도가 가장 작은 x, y 를 가장 깊은 곳에 형제로 갖는 최적 트리가 항상 존재 (귀류법)

  1. 가정
    그런 최적 트리 없음 → 최적 T 의 가장 깊은 형제 a, b ≠ x, y
  2. 교환
    x ↔ a 한 T′: cost(T) − cost(T′) = (f(x) − f(a))(dT(x) − dT(a)) ≥ 0
    (≤ 0) × (≤ 0)
  3. T′ 도 최적, y ↔ b 한 T″ 도 최적
  4. 모순
    T″ = x, y 가 가장 깊은 형제인 최적 트리 ↔ 가정
  5. 결론
    명제가 참

보조 명제 2 — 형제 합치기→ 단원 정리 p.14

가장 깊은 형제 u, v 를 부모 w 로 합친 B′ (문자 n − 1 개, f(w) = f(u) + f(v))

cost(B) − cost(B′) = f(u) + f(v)

이유: dB(v) = dB(u) (형제), dB′(w) = dB(u) − 1 (부모) → f(u)d + f(v)d − (f(u) + f(v))(d − 1)

본 증명 — 귀납법 + 귀류법→ 단원 정리 p.15

귀납내용
바닥n = 2 → 자명
가정n < k 이면 허프만 트리는 최적
단계n = k 일 때 최적임을 보임
n = k: T′ = T 의 x, y 를 z 로 합친 트리 (k − 1 개)
  1. 보조 2
    cost(T′) = cost(T) − f(x) − f(y)
  2. 가정
    T 최적 아님 → cost(T″) < cost(T)
  3. 보조 1
    T″ 은 x, y 가 가장 깊은 형제인 것으로 고름
  4. 비교
    cost(T″ − {x, y}) = cost(T″) − f(x) − f(y) < cost(T′)
  5. 모순
    T′ 은 귀납 가정으로 최적인데 더 작은 트리 존재
  6. 결론
    T 최적 → 허프만 = 항상 최적
헷갈리는 점 · 판서 정정
  • 보조 1: T′ 은 최적이다 (판서 "최적 아님" 오류) — 비용이 늘지 않으므로
  • 보조 1 식: (dT(x) − dT(a)) — 판서의 "=" 는 빼기, cost(T′) 앞 항은 f(x)·dT′(x)
  • 보조 2: dB′(w) = dB(u) − 1 (판서 dB′(u) − 1)
  • n = k 의 x, y 는 "임의" 가 아니라 빈도가 가장 작은 두 문자 → 여기서 보조 명제 1 사용
  • 모순의 핵심: k − 1 개의 최적 T′ 보다 작은(같은 것도 아니고) 트리가 존재
시험 포인트
  • 기말 확정 — 보조 명제 2개 + 귀납 3단계의 순서와 이유를 쓸 수 있게
  • 기호(T, T′, T″, B, u, v, w)가 바뀌어도 역할로 대응
