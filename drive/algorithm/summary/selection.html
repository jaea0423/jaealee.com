0한눈에 보기

선택 문제 = n개 중 k번째로 작은(큰) 값을 찾는 문제. 목표는 비교 횟수 최소화.

문제방법비교 횟수
최댓값 (또는 최솟값)하나씩 비교 / 토너먼트n − 1
최대 + 최소 동시에토너먼트 후 1R 패자에서 최솟값32n − 2
최소 + 두 번째로 작은 값최솟값에게 직접 진 원소에서 찾기n + ⌈log₂ n⌉ − 2
k번째 — Quick Select피벗 = 아무 값 (L[0])최선 O(n) · 최악 O(n²)
k번째 — 좋은 피벗|A|, |B| ≤ nc, 단 a ≤ n 가정O(n log n)
k번째 — MoMmedian들의 median을 피벗으로최악도 O(n) (T(n) ≤ 44n)

위 세 줄의 비교 횟수는 모두 상한 = 하한인 tight bound (증명은 수업에서 하지 않음).

1상한 · 하한 · tight bound

상한 upper bound이보다 더 많이 비교할 필요는 없다
하한 lower bound아무리 잘해도 최소 이만큼은 비교해야 한다
tight bound상한 = 하한 → 그 값이 최적
예 — 최댓값 찾기
n개면 n − 1번 이상 필요 없음(상한), 최소 n − 1번은 필요(하한) → tight bound = n − 1.

2토너먼트로 비교 줄이기

① 최댓값 — 토너먼트도 n − 1번

둘씩 붙여 이긴 쪽만 올라감. 비교 한 번에 정확히 1명이 탈락하고, 최댓값 1명만 남으려면 n − 1명이 탈락해야 하므로 n − 1번 (7개면 3 + 2 + 1 = 6번).

② 최대 + 최소 동시에 — 32n − 2

단순: 최댓값 (n − 1) + 나머지에서 최솟값 (n − 2) = 2n − 3
토너먼트: 최댓값 (n − 1) + 1라운드 패자 n2개에서 최솟값 (n2 − 1) = 32n − 2

③ 최소 + 두 번째로 작은 값 — n + ⌈log₂ n⌉ − 2

핵심 논리
두 번째로 작은 값은 최솟값에게만 질 수 있다. 다른 원소 x 에게 졌다면 x 와 최솟값, 둘이 자기보다 작아서 "두 번째"가 아니게 되기 때문. → 후보 = 최솟값에게 직접 진 원소들.

3Quick Select

  1. 피벗 P 를 고른다 (아무 값 — 수업 코드는 L[0])
  2. P 와 비교해 A (P보다 작음) · M (P와 같음, P 포함) · B (P보다 큼) 로 나눔 — n − 1번. 그룹 안은 정렬 안 됨
  3. k 와 |A|, |M| 을 비교해 답이 있는 그룹 하나만 남기고 재귀
조건답의 위치다음 호출
|A| ≥ kAquick_select(A, k) — 순위 그대로
|A| + |M| < kBquick_select(B, k − |A| − |M|) — 앞 순위만큼 당김
그 외Mreturn P
 
def quick_select(L, k):
    P = L[0]                          # 피벗 = 0번째 값
    A, B, M = [], [], []
    for x in L:                       # n − 1 번 비교로 분류
        if P > x:   A.append(x)
        elif P < x: B.append(x)
        else:       M.append(x)
    if len(A) >= k:                   # '>=' — '>' 면 |A| = k 를 놓침
        return quick_select(A, k)
    elif len(A) + len(M) < k:
        return quick_select(B, k - len(A) - len(M))
    else:
        return P

추적 — L = [6, 5, 1, 7, 9, 3, 8, 10, 2], k = 8

최선 · 최악

매번 줄어드는 크기점화식결과
최악1개 (A 또는 B 가 비어 버림)T(n) = (n − 1) + T(n − 1)O(n²)
최선절반T(n) = n + T(n2)O(n)
최악: (n − 1) + (n − 2) + ⋯ + 1 + T(1) = (n − 1)n2 = O(n²)
최선: n + n2 + n4 + ⋯ + T(1) = T(1) + n (1 + 12 + 14 + ⋯) 괄호 < 2 인 상수 = O(n)

4좋은 피벗 → O(n log n)

좋은 피벗 : |A| ≤ nc,   |B| ≤ nc   (c > 1 인 상수)
크기 n → nc → nc² → ⋯ → nck = 1  ⟹  n = ck  ⟹  재귀 횟수 k = logc n
한 단계 = 피벗 고르기 a + 나누기 n 나누기는 실제로 n, n/c, … 로 줄지만 전부 n 으로 크게 잡음
전체 ≤ logc n · (a + n) ≤ logc n · 2n = O(n log n) a ≤ n 가정
조건부 결론
a ≤ n (피벗 고르는 비용이 나누는 비용 이하) 은 증명이 아니라 가정. "좋은 피벗을 n 이하로 고를 수 있다면 O(n log n)". 그런 방법이 MoM.
좋은 피벗 ≠ a ≤ n
좋은 피벗 = 피벗의 위치(고르게 나뉨) 조건. a ≤ n = 피벗을 찾는 비용 조건. 서로 다른 조건.

5MoM — Median of Medians시험 ★★★

Quick Select 와 같고 피벗만 "median 들의 median" 으로 고른다. mean(평균)은 쓰지 않음.

단계하는 일비용
15개씩 묶기0
2각 묶음의 median (묶음당 6번 × n5묶음)6n5
3medians 의 median m* — MoM(medians, 가운데 순위) 재귀T(n5)
4m* 로 A / M / B 나누고 한쪽 재귀 또는 m* 반환n + T(nc)
T(n) = T(nc) + T(n5) + 11n5  →  c = 43 대입  →  T(n) = T(3n4) + T(n5) + 11n5
재귀가 두 군데
3단계 = 피벗 m* 를 구하려는 재귀 (크기 n5). 4단계 = 최종 답을 찾는 재귀 (크기 ≤ 3n4).

5개의 median 을 6번에

비교결과알게 되는 것
① ② ③a < b, c < d, a < ca 는 b, c, d 보다 작음 → 1등 또는 2등 → median 아님, 탈락
④ ⑤b < e, b < cb 가 {b, c, d, e} 중 최소 (c < d 는 ② 에서 앎)
⑥c < e{c, d, e} 중 최소 c = median

핵심 = 이미 비교한 결과를 다시 쓰기 (c < d 를 두 번 재활용).

6c = 43 증명 — |A|, |B| ≤ 3n4시험 ★★★

  1. X 의 원소 ≤ m* : x ≤ (자기 묶음의 median) ≤ m*. m* 자신도 X 에 들어 있으므로 "<" 가 아니라 "≤"
  2. |X| 세기 : 묶음 n5개 중 절반(n10개)의 median 이 m* 이하, 그런 묶음마다 3개 → |X| ≥ 3n10 ≥ n4 (수업은 여유 있게 n/4)
  3. |B| 의 상한 : X 의 원소는 m* 보다 크지 않으므로 B 에 못 들어감 → |B| ≤ n − n4 = 3n4. W 로 대칭 → |A| ≤ 3n4
  4. 따라서 nc = 3n4, c = 43 — "최소 25% 는 가져가고 75% 보다 작게 만들어 준다"

7귀납법 → MoM 은 O(n)시험 ★★★

단계기본 표현MoM 에 쓰는 표현
1. 기저가장 작을 때 (n = 1) 직접 확인
2. 가정n = k 일 때 성립k < n 인 모든 k 에서 성립
3. 귀납n = k + 1 일 때 성립 보이기k = n 일 때 성립 보이기
4. 결론1 에서 출발해 3 을 반복 → 모든 n 에서 성립

MoM 은 T(3n4), T(n5) 처럼 바로 앞(n − 1)이 아닌 값을 쓰므로 "n 보다 작은 건 전부 성립" 표현이 편함.

T(n) ≤ 44n 증명

기저   T(1) = 1 ≤ 44 ✓
가정   k < n 이면 T(k) ≤ 44k
귀납   T(n) = T(3n4) + T(n5) + 11n5
    ≤ 44 · 3n4 + 44 · n5 + 11n5 3n4, n5 < n 이라 가정 적용
    = 33n + 44n5 + 11n5 = 33n + 11n = 44n ✓
결론   T(n) ≤ 44n → O(n)
왜 44 · 왜 O(n) 인가 (정리본의 보충 설명)
T(n) ≤ Cn 으로 두면 C · 1920 + 115 ≤ C 이어야 닫힘 → C ≥ 44. 근본 이유는 34 + 15 = 1920 < 1 — 두 재귀 조각을 합쳐도 원래보다 작음.
4절 O(n log n) 과 모순?
아님. 4절은 a ≤ n 가정으로 크게 잡은 상한, 여기는 피벗 비용까지 넣어 정확히 푼 결과. O(n) 이 더 정확한 답.

8자주 틀리는 것

✗ 토너먼트로 최댓값 찾으면 비교가 줄어든다
✓ 그대로 n − 1. 줄어드는 건 "최대+최소", "최소+두 번째"
✗ 최대·최소 동시에 = 2n − 3
✓ 2n − 3 은 단순 방법. tight bound 는 32n − 2
✗ 라운드 수 = log₂ n
✓ 올림 ⌈log₂ n⌉ — 9개도 4라운드
✗ if len(A) > k
✓ >= — |A| = k 면 답은 A 의 맨 끝
✗ B 로 갈 때 k 그대로
✓ k − |A| − |M| — A, M 이 앞 순위를 차지
✗ Quick Select 최악 O(n log n)
✓ O(n²). O(n log n) 은 좋은 피벗 + a ≤ n 가정
✗ MoM 의 m* = 전체의 중앙값
✓ 피벗으로만 씀. 정확한 중앙값일 필요 없음
✗ X 의 원소 < m*
✓ ≤ m* (m* 자신 포함)
✗ 2단계 비용 = n
✓ 6 × n5 = 6n5, 합치면 11n5
✗ 5개가 아니면 아무 수로 묶어도 O(n)
✓ 두 재귀 비율 합이 1 보다 작아야 함 (5개: 1920)

9셀프 체크

답을 떠올린 뒤 눌러서 확인.

n = 16 에서 최소와 두 번째로 작은 값을 찾는 비교 횟수는?
18번 — 16 + ⌈log₂ 16⌉ − 2 = 16 + 4 − 2. (최솟값 15번 + 후보 4개 중 3번)
n = 10 에서 최대·최소를 동시에 찾는 최소 비교 횟수는?
13번 — 32 · 10 − 2. (최댓값 9번 + 1R 패자 5개 중 4번)
quick_select 에서 B 로 재귀할 때 순위를 바꾸는 이유는?
A 와 M 의 원소가 전체 1등부터 |A| + |M| 등까지를 이미 차지하므로, B 안에서는 k − |A| − |M| 번째가 전체 k 번째다.
Quick Select 최악의 점화식과 결과, 그리고 최악이 되는 상황은?
T(n) = (n − 1) + T(n − 1) = (n − 1)n2 = O(n²). 매번 A 또는 B 가 비어 크기가 1 씩만 줄 때.
MoM 의 점화식을 단계별 비용과 함께 쓰면?
0 + 6n5 + T(n5) + n + T(nc) = T(nc) + T(n5) + 11n5
MoM 에서 c = 4/3 이 나오는 과정을 세 줄로?
① X 의 원소 ≤ 묶음 median ≤ m*. ② |X| ≥ 3n10 ≥ n4. ③ X 는 B 에 못 들어가므로 |B| ≤ 3n4, 대칭으로 |A| ≤ 3n4 → c = 43.
T(n) ≤ 44n 귀납 3단계의 계산은?
44 · 3n4 + 44 · n5 + 11n5 = 33n + 44n5 + 11n5 = 33n + 11n = 44n.
5개의 median 을 찾을 때 첫 3번 비교 후 a 를 탈락시키는 근거는?
a < b, c < d, a < c 이면 a 보다 큰 원소가 최소 3개(b, c, d) → a 는 1등 또는 2등이라 3번째(median)가 될 수 없다.
