1stable · in-place시험 ★★★

stable같은 값의 원소들이 정렬 전 순서 그대로 남는 것을 보장. [3₁, 3₂, 7, 9] 가 유지되면 stable. "뒤집힌다" 가 아니라 "보장 안 됨" 이 unstable
in-place필요한 추가 메모리가 O(1). 판단: 새 리스트·배열을 만드는가 (만들면 not in-place)
답안 쓰는 형식 (교수님 예시)
in-place X — S, M, L = [], [], [] 로 새 리스트를 만들기 때문. stable O — for x in A 에 의해 A 의 순서 그대로 S, M, L 에 넣기 때문.
부등호를 먼저 본다
버블 A[j] > A[j+1], 삽입 A[j] > x 면 stable. >= 로 바뀌면 같은 값도 바꾸거나 넘어가서 stable X. 병합은 반대로 A[i] <= A[j] 여야 stable (< 면 X).

3퀵 정렬 (S / M / L)시험 ★★★

def quick_sort(A):
    if len(A) <= 1:                 # 판서는 |A| == 1 — 빈 리스트에서 멈추려면 <= 1
        return A
    P = A[0]                        # 피벗 = 첫 값
    S, M, L = [], [], []            # 새 리스트 → not in-place
    for x in A:                     # A 순서대로 → stable
        if P > x:   S.append(x)
        elif P < x: L.append(x)
        else:       M.append(x)
    return quick_sort(S) + M + quick_sort(L)
입력점화식결과
worst이미 정렬된(또는 역순) 입력 — 한쪽만 남음T(n − 1) + CnO(n²)
best = average잘 분배됨 — 반반2T(n2) + CnO(n log n)

계산상 worst 는 O(n²) 이지만 실제로는 평균적으로 가장 빠른 정렬. quick_select 는 한쪽만 재귀, quick_sort 는 S, L 둘 다 재귀.

피벗을 중앙값으로 고르면 best 가 보장되지만, 중앙값을 구하는 데 O(n) 이 들어 "조금 그렇다" (교수님).

4제자리 퀵 정렬시험 ★★★

def quick_sort(A, first, last):     # A[first] … A[last] 를 A 안에서 정렬
    p = A[first]                     # 피벗
    left = first + 1; right = last
    while left <= right:
        while left <= last and A[left] < p:     # p 보다 작으면 통과
            left += 1
        while right > first and A[right] > p:   # p 보다 크면 통과
            right -= 1
        if left <= right:
            A[left], A[right] = A[right], A[left]  # 둘 다 잘못된 쪽 → 교환
    A[first], A[right] = A[right], A[first]       # 피벗을 제자리로
    quick_sort(A, first, right - 1)
    quick_sort(A, left, last)
교수님 코드 그대로 (주의)
교환 뒤 left += 1; right -= 1 과 기저 조건이 없음 → 값이 모두 다르면 동작, 피벗과 같은 값을 둘 다 만나면 무한 반복. 첫 분할 결과는 두 줄이 있든 없든 같다.

예시 — A = [4, 2₁, 5, 8, 6, 2₂, 3, 7, 10], 피벗 4

회차left 멈춤right 멈춤동작
15 (2번)3 (6번)5 ↔ 3
28 (3번)2₂ (5번)8 ↔ 2₂
36 (4번)2₂ (3번)left > right → 종료
피벗A[0] ↔ A[3][2₂, 2₁, 3, 4, 6, 8, 5, 7, 10]

in-place O — 새 배열 없이 자리만 바꿈 (교수님). stable X — 멀리 떨어진 칸 교환과 마지막 피벗 교환 때문에 2₁, 2₂ 순서가 뒤집힘 (위 예시).

5병합 정렬시험 ★★★

  1. 값을 보지 않고 강제로 반반 나눔 (피벗 없음)
  2. 두 그룹을 각각 재귀 정렬
  3. 두 그룹의 맨 앞끼리 비교해 작은 값을 새 배열 B 에 채움 → 남은 쪽은 비교 없이 붙임 → A 로 되돌림
[3, 20, 35, 40] + [9, 10, 80]: 3 · 9 · 10 · 20 · 35 · 40 순으로 B 에 → 비교 6번, 남은 80 은 그대로 붙임
def merge_two_sorted_lists(A, first, last):
    m = (first + last) // 2
    i, j = first, m + 1
    B = []                                 # 새 배열 → not in-place
    while i <= m and j <= last:
        if A[i] <= A[j]:                   # 같으면 앞 그룹 먼저 → stable
            B.append(A[i]); i = i + 1
        else:
            B.append(A[j]); j = j + 1
    for k in range(i, m + 1):    B.append(A[k])   # 남은 쪽 (둘 중 하나만 돈다)
    for k in range(j, last + 1): B.append(A[k])
    for i in range(first, last + 1):
        A[i] = B[i - first]                # B 는 0 부터, A 구간은 first 부터
T(n) = 2T(n2) + Cn = O(n log n) — 항상 반반이라 worst · best · average 구분 없음

6힙시험 ★★★

찾을 노드인덱스
A[k] 의 왼쪽 자식2k + 1
A[k] 의 오른쪽 자식2k + 2
A[k] 의 부모(k − 1) // 2

계산 한 번 → O(1). 힙 성질 = 모든 노드에서 부모 key ≥ 자식 key → 루트 A[0] 이 최댓값. (모양: 배열은 항상 이진트리로 나타낼 수 있음)

make_heap — 맨 뒤 노드부터 heapify_down

A = [2, 8, 6, 1, 10, 15, 3, 12, 11]교환
A[8] ~ A[4] (leaf)없음
A[3] = 11 ↔ 12 (큰 자식)
A[2] = 66 ↔ 15
A[1] = 88 ↔ 12, 8 ↔ 11
A[0] = 22 ↔ 15, 2 ↔ 6
결과[15, 12, 6, 11, 10, 2, 3, 1, 8]
make_heap = heapify_down × n번, heapify_down = 높이만큼 O(log n) → O(n log n) 수업 기준

7힙 정렬시험 ★★★

  1. make_heap → 루트 A[0] = 최댓값
  2. A[0] ↔ 구간 끝 A[i] — 최댓값을 뒤로 (i = n − 1 → 1, 매번 한 칸씩 앞으로)
  3. 루트에서 heapify_down — 뒤로 보낸 값은 제외
라운드교환 후heapify_down 후
1 (i = 8)[8, 12, 6, 11, 10, 2, 3, 1, 15][12, 11, 6, 8, 10, 2, 3, 1, 15]
2 (i = 7)[1, 11, 6, 8, 10, 2, 3, 12, 15][11, 10, 6, 8, 1, 2, 3, 12, 15]
O(n log n) make_heap + (n − 1) × O(log n) heapify_down = O(n log n), best · worst 없음
get_max 관점
정렬 = "A[0] ~ A[i] 의 최댓값을 A[i] 로" 를 n − 1 번. 선택 정렬은 get_max 가 O(i) 라 O(n²), 힙 정렬은 최댓값이 A[0] 이고 고치는 데 O(log i) 라 O(n log n).
stable X 반례
[1₁, 1₂] → make_heap 그대로 → A[0] ↔ A[1] → [1₂, 1₁].

8비교 정렬의 하한 — Ω(n log n)시험 ★★★

상한 O이 알고리즘은 이보다 나빠지지 않는다
하한 Ω어떤 비교 정렬이든 최소 이만큼은 필요하다
리프 n! 개 · 높이 h 인 이진트리의 리프 ≤ 2h → 2h ≥ n! → h ≥ log₂ n!
n! = n × (n − 1) × ⋯ × (n2 + 1) × ⋯ × 1 ≥ (n2)n2 큰 쪽 절반은 각각 n2 이상, 나머지는 1 이상
h ≥ log₂(n2)n2 = n2 log₂ n2 ≥ C · n log₂ n → Ω(n log n)
결론
병합·힙 정렬의 상한 O(n log n) = 비교 정렬의 하한 Ω(n log n) → 최적. 퀵 정렬은 상한(worst)이 O(n²) 이라 해당 안 됨.
"최소 3번" 의 뜻
a, b, c 중 a < b < c, c < b < a 는 2번에 결정됨. 하한 3 = "최악의 경우 3번은 필요" (높이).

답을 떠올린 뒤 눌러서 확인.

A = [7, 3, 9, 1, 5] 에 선택 정렬 1라운드 후 배열과 그 라운드의 비교 횟수는?
최댓값 9 ↔ 마지막 5 → [7, 3, 5, 1, 9], 비교 4번.
버블 정렬의 비교를 A[j] >= A[j+1] 로 바꾸면 무엇이 달라지나?
같은 값도 교환해 순서가 뒤집힘 → stable X. 정렬 결과(값 순서)는 같다.
퀵 정렬(S/M/L)의 in-place · stable 과 그 이유는?
in-place X — S, M, L 새 리스트. stable O — for x in A 로 A 순서대로 넣음.
[4, 2₁, 5, 8, 6, 2₂, 3, 7, 10] 의 제자리 퀵 첫 분할 결과는?
5 ↔ 3, 8 ↔ 2₂, 피벗 A[0] ↔ A[3] → [2₂, 2₁, 3, 4, 6, 8, 5, 7, 10] — 2₁, 2₂ 순서 뒤집힘.
[1, 3, 5, 8] 과 [2, 7, 9] 를 병합할 때 비교 횟수는?
1, 2, 3, 5, 7, 8 순으로 6번, 남은 9 는 비교 없이 붙임.
힙에서 A[3] 의 자식과 A[8] 의 부모 인덱스는?
자식 A[7], A[8] (2·3 + 1, 2·3 + 2). A[8] 의 부모 A[3] ((8 − 1)//2).
[4, 10, 3, 5, 1] 을 make_heap 하면?
A[1] = 10 그대로, A[0] = 4 ↔ 10, 4 ↔ 5 → [10, 5, 3, 4, 1].
값 4개 정렬의 결정 트리 리프 수와 최악 비교 하한은?
리프 4! = 24. 2⁴ = 16 < 24 ≤ 32 = 2⁵ → 최소 5번.
