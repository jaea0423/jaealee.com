최단 경로 알고리즘 — 도입

Bellman-Ford & Dijkstra 시작 전, 문제 설정 잡기

01 최단 경로 알고리즘이란?

이번 단원부터는 그래프에서 실제로 많이 사용되는 알고리즘을 다룹니다. 첫 번째는 최단 경로 알고리즘 (Shortest Path Algorithm).

실생활 예시 — 도시 간 이동

도시들 사이에 길이 있고, 각 길마다 거리(또는 비용)이 있다고 합시다. "서울에서 원주까지 가는 가장 짧은(또는 가장 싼) 경로"를 구하는 문제가 바로 최단 경로 문제.

도시 간 거리 그래프 — 각 간선의 숫자가 가중치(거리)

가중치란?

가중치 (weight)

각 간선에 붙은 숫자. 거리, 시간, 비용 등 무엇이든 가능. 도로라면 km, 항공편이라면 운임, 인터넷이라면 지연 시간(ms) 등.

지금까지 본 그래프와 차이
이전 단원에서 본 그래프는 모두 가중치 없음 (간선 있냐 없냐만). 이번엔 간선에 숫자가 붙은 가중치 그래프 (weighted graph)를 다룹니다.

서울 → 원주 최단 경로 찾기 (감으로)

위 그래프에서 서울에서 원주로 가는 길은 여러 가지:

  • 서울 → 수원 → 원주 = 10 + 70 = 80
  • 서울 → 춘천 → 원주 = 30 + 10 = 40 ✓ 최단
  • 서울 → 대전 → 수원 → 원주 = 40 + 20 + 70 = 130
  • 서울 → 수원 → 대전 → ... (더 복잡)
최단 경로 문제의 본질
여러 경로 중에서 가중치 합이 가장 작은 경로를 찾는 것. 사람은 작은 그래프에서 감으로 풀 수 있지만, 수백 개 정점의 그래프에선 알고리즘이 필요.

오늘 배울 두 알고리즘

학습 대상
① Bellman-Ford Algorithm (벨만-포드 알고리즘)
② Dijkstra Algorithm (다익스트라 알고리즘)
실생활 활용
  • 네비게이션 길찾기 (T맵, 카카오맵, 구글맵)
  • 네트워크 라우팅 (인터넷 데이터 경로)
  • 비행기 예약 (가장 싼 환승 조합)
  • 게임 AI 경로 탐색

03 최단 경로의 성질과 dist[v]

그래프 A에서 a → i 최단 경로를 직접 따져보면서, 최단 경로 알고리즘의 기본 아이디어를 잡습니다.

예시 — a에서 i까지 가는 경로

a를 source(출발점), i를 destination(도착점)이라고 봅시다.

경로 1: a → b → f → g → i

경로 1: a → b → f → g → i (비용 13)

경로 2: a → c → b → f → g → i (최단 경로!)

경로 2: a → c → b → f → g → i (비용 12, 이게 최단)
잠깐, 어떻게 최단인 줄 알았나?
지금은 그냥 "이게 최단이구나" 정도로만 받아들이면 됩니다. 최단 경로를 어떻게 알고리즘으로 찾는지가 바로 오늘 배울 내용 (Bellman-Ford, Dijkstra).

★ 최단 경로의 핵심 성질 — 부분 경로도 최단

a → c → b → f → g → i가 a → i의 최단 경로라고 합시다. 그렇다면 자연스러운 질문:

생각해볼 질문

"a → c → b → f → g → i"가 a에서 i까지 최단이라면, 그 일부인 "a → c → b → f → g" (a에서 g까지)도 a에서 g까지의 최단일까?

답
그렇다. 부분 경로도 무조건 최단.

왜 그런가?

만약 a → g의 더 짧은 경로가 따로 있다고 가정해봅시다. 그 짧은 길로 g까지 간 다음, 거기서 → i로 가면 a → i 전체도 더 짧아져버려요. 그런데 우리는 처음에 a → c → b → f → g → i가 이미 a → i 최단이라고 가정했잖아요? 모순.

★ 부분 경로 최단성 (Optimal Substructure)

최단 경로의 일부 구간도 반드시 최단 경로다.

기호로 쓰면:

(a → ... → g → i 최단경로) ⊃ (a → ... → g 최단경로)

이 성질이 있기 때문에 큰 문제(a→i 최단)를 작은 문제(a→g 최단)로 쪼개서 풀 수 있음. 모든 최단 경로 알고리즘의 근간.

dist[v] 정의

이 성질을 활용하려면 표기가 필요해요. 다음과 같이 약속합니다.

dist[v]

출발점 s에서 정점 v까지 가는 최단 경로의 길이(비용).

예: 위 그래프 A에서 s = a라면:

  • dist[a] = 0 (자기 자신)
  • dist[c] = 1 (a → c)
  • dist[b] = 4 (a → c → b)
  • dist[g] = 8 (a → c → b → f → g)
  • dist[i] = 12 (a → c → b → f → g → i)

v로 도착하는 경로 분석

이제 v라는 정점이 있다고 합시다. s에서 v까지의 최단 경로의 맨 마지막 단계를 생각해보면: v 직전에 어떤 노드 u가 있고, u에서 v로 들어오는 간선이 있어요.

s에서 v로 가는 경로의 마지막 단계 — 직전 노드 u에서 한 간선으로 v 도착

그럼 v까지의 총 비용은 = dist[u] + w(u, v) (s에서 u까지 최단 + u→v 간선 비용)

여기서 w(u, v)는 u에서 v까지 가는 간선의 가중치를 뜻함.

u는 하나로 정해진 게 아님

그런데 v로 들어오는 노드 u는 여러 개일 수 있어요. v로 향하는 간선이 여러 개라면.

v로 들어오는 길이 여러 개일 수 있음 — u₁, u₂, u₃ 모두 v의 직전 노드 후보

★ dist[v] 점화식

v로 들어오는 모든 u 후보 중에서 가장 비용 합이 작은 것이 곧 dist[v]가 됨.

최단 경로의 점화식
dist[v] = min ( dist[u₁] + w(u₁, v),
                  dist[u₂] + w(u₂, v),
                  dist[u₃] + w(u₃, v) )
= v로 들어오는 모든 후보 중 비용 합 최소
이 식의 의미
  • v까지의 최단 거리는 "v 직전 노드까지의 최단 거리 + 마지막 간선 비용"의 최솟값
  • 즉 v를 푸는 데 필요한 건 v보다 먼저 푼 노드들의 dist 값
  • → 작은 문제(가까운 노드)를 먼저 풀고, 그걸 활용해 큰 문제(먼 노드)를 풀어가는 구조
  • 이게 모든 최단 경로 알고리즘의 뼈대
앞으로 배울 알고리즘이 하는 일
Bellman-Ford와 Dijkstra는 이 점화식을 어떤 순서로, 어떻게 계산하느냐의 차이입니다. 식 자체는 같음.

04 Relax 연산 — 모든 최단경로 알고리즘의 기본 동작

앞에서 본 dist[v] 점화식을 실제 코드로 어떻게 구현할까? 정말 짧은 if문 하나로 표현됩니다.

핵심 코드 한 토막

기본 갱신 로직 
if dist[v] > dist[u] + w(u, v):    # 지금까지 안 최단보다 짧은 길 발견하면
    dist[v] = dist[u] + w(u, v)      # 갱신!

한 줄씩 의미 풀기

  • dist[v]: 알고리즘이 지금까지 알아낸 s→v 최단 거리. 처음엔 ∞로 두고, 알고리즘이 돌면서 점점 작아짐 (개선됨).
  • dist[u] + w(u, v): s에서 u까지 간 다음 u→v 간선 하나 더 타고 가는 비용
  • 두 값을 비교해 새 경로가 더 짧으면 dist[v]를 갱신
★ 약속 — relax(u, v)

이 if문 한 덩어리를 앞으로 relax(u, v)라고 부릅니다. 짧게 쓰기 위한 약속.

정의 
def relax(u, v):
    if dist[v] > dist[u] + w(u, v):
        dist[v] = dist[u] + w(u, v)

"u를 거쳐 v로 가는 게 더 좋으면 dist[v]를 그 값으로 풀어준다(relax)"는 의미.

왜 "relax"인가?
팽팽한 고무줄(현재 dist[v])을 더 짧은 길이로 늘어뜨려 풀어준다는 비유. 절대 늘어나는 일은 없고, 줄어들기만 함.

05 Bellman-Ford 아이디어

이제 벨만-포드 알고리즘 (Bellman-Ford Algorithm)이 어떻게 모든 정점의 최단 거리를 찾아내는지 봅시다.

초기 상태

그래프 A에서 s = a, dest = i로 시작.

  • dist[a] = 0 (자기 자신, 자명)
  • dist[b], dist[c], ..., dist[i] = ∞ (아직 아무것도 모름)

모든 정점에 "현재 추정 최단 거리"를 표시하고, 알고리즘이 돌면서 이 값을 계속 줄여나갑니다.

아이디어 — 한 칸씩 늘려가며 갱신

한 칸으로 갈 수 있는 노드부터 풀고, 그 결과로 두 칸 거리 노드를 풀고, 이런 식으로 늘려나가는 거예요.

1단계 — 한 칸 거리 노드 갱신

a에서 한 번에 갈 수 있는 노드: b, c

  • relax(a, b): dist[b] = ∞ > 0 + 5 → dist[b] = 5
  • relax(a, c): dist[c] = ∞ > 0 + 1 → dist[c] = 1

2단계 — 두 칸 거리 노드 갱신

이미 갱신된 노드들(b, c)을 통해 더 멀리 갈 수 있게 됨.

  • relax(c, b): dist[b] = 5 > 1 + 3 = 4 → dist[b]를 4로 갱신 (c를 거치는 게 더 짧음!)
  • relax(b, d): dist[d] = ∞ > 4 + 4 = 8 → dist[d] = 8
  • ... 계속

왜 최대 n-1 라운드면 끝나나?

한 라운드마다 "한 칸 더 멀리"의 정보가 전파됨
★ 라운드 수의 근거
  • 최단 경로가 거칠 수 있는 중간 노드 최대 개수 = n−2
  • 최단 경로가 사용하는 간선 최대 개수 = n−1
  • 한 라운드에서 한 간선만큼 정보가 전파되므로 → 최대 n−1 라운드면 모든 최단 거리 확정

06 Bellman-Ford 의사코드

전체 코드

Bellman-Ford 
# 초기화
dist[s] = 0
for v in V (v ≠ s):
    dist[v] = ∞

# 본체
for i in range(n − 1):              # 최대 라운드 수
    for each edge (u, v) in G:        # 그래프의 모든 간선 검사
        if dist[v] > dist[u] + w(u, v):
            relax(u, v)

각 줄 의미

줄 의미
for i in range(n-1) 최대 n−1 라운드 반복 (간선 수의 최댓값)
for each edge (u, v) in G 매 라운드마다 그래프의 모든 간선을 한 번씩 검사
if dist[v] > ... 더 짧은 길이 있으면
relax(u, v) dist[v] 갱신

시간복잡도

Bellman-Ford 시간복잡도
바깥 루프 (n−1번) × 안쪽 루프 (간선 수 E번)
= O(n · E) = O(VE)
간선 수 E는 최대 n² (완전 그래프) → 최악 O(n³)
표기 두 가지
  • O(VE): 보통 정점 수 V, 간선 수 E로 씀 (가장 정확)
  • O(nE) 또는 O(nm): 같은 뜻 (n=V, m=E)
  • O(n³): 최악 케이스 (조밀한 그래프)

07 Bellman-Ford 실행 추적 — 그래프 A

s = a로 그래프 A에 Bellman-Ford를 직접 돌려봅시다. 각 라운드마다 dist 값이 어떻게 바뀌는지 추적.

Round 0 — 초기 상태

dist[a] = 0, 나머지 모두 ∞.

정점abcdefghi
dist 0 ∞∞∞∞∞∞∞∞

Round 1 — 모든 간선 검사

17개 간선 모두 차례로 relax 시도. 대부분 ∞끼리 비교라 무시되지만, a에서 나가는 간선들은 갱신됨.

  • relax(a, b): ∞ > 0 + 5 → dist[b] = 5
  • relax(a, c): ∞ > 0 + 1 → dist[c] = 1
  • 나머지 간선들 (b→d, c→b, d→f 등): u의 dist가 아직 ∞라서 갱신 X
정점abcdefghi
dist 0 5 1 ∞∞∞∞∞∞

Round 2

이번엔 b, c가 ∞가 아니라서 그 다음 노드들이 갱신됨.

  • relax(c, b): 5 > 1 + 3 = 4 → dist[b] = 4 (c 거치는 게 더 짧음!)
  • relax(b, d): ∞ > 5 + 4 = 9 (이번 라운드 시작 시점의 dist[b]=5 기준)
    • 구현에 따라 다르지만, 표준 BF는 같은 라운드 안에서도 갱신값 사용 가능. dist[b]=4가 이 라운드 내에 이미 갱신됐다면 → 4 + 4 = dist[d] = 8
  • relax(b, f): ∞ > 4 + 1 = 5 → dist[f] = 5
정점abcdefghi
dist 0 4 1 8 ∞ 5 ∞∞∞

Round 3

  • relax(d, c): 1 > 8 + 2 = 10? No (1이 더 작음 → 유지)
  • relax(d, e): ∞ > 8 + 9 = 17 → dist[e] = 17
  • relax(d, f): 5 > 8 + 1 = 9? No (5가 더 작음)
  • relax(f, e): 17 > 5 + 7 = 12 → dist[e] = 12
  • relax(f, g): ∞ > 5 + 3 = 8 → dist[g] = 8
정점abcdefghi
dist 0418 12 5 8 ∞∞

Round 4

  • relax(e, c): 1 > 12 + 2 = 14? No
  • relax(e, h): ∞ > 12 + 5 = 17 → dist[h] = 17
  • relax(g, e): 12 > 8 + 1 = 9 → dist[e] = 9
  • relax(g, h): 17 > 8 + 3 = 11 → dist[h] = 11
  • relax(g, i): ∞ > 8 + 4 = 12 → dist[i] = 12
정점abcdefghi
dist 0418 9 58 11 12

Round 5

  • relax(h, g): 8 > 11 + 2 = 13? No
  • relax(h, i): 12 > 11 + 1 = 12? No (같으면 갱신 안 함)
  • 그 외 다른 간선들: 갱신 없음

Round 5에서 아무 갱신도 일어나지 않음 → 종료 (사실 알고리즘은 n−1=8까지 돌지만, 실제로는 일찍 안정됨)

★ 결과 해석
  • a → i 최단 거리 = 12 ✓ (앞에서 손으로 푼 결과와 일치)
  • 한 번에 모든 정점의 최단 거리를 얻음 — a → b는 4, a → e는 9 등
  • 단, 출발점은 정해진 상태로 시작. 출발점 바뀌면 알고리즘을 다시 돌려야 함.

다른 도착점도 동시에 풀림
  • a → i 만 묻든, a → b를 묻든, a → h를 묻든 한 번의 BF 실행으로 모두 답이 나옴
  • 출발점 a 하나에 대해 모든 정점까지의 최단 거리 계산
  • 이런 문제를 SSSP (Single-Source Shortest Path, 단일 출발점 최단 경로)라고 함
  • 단, 출발점이 b로 바뀌면 처음부터 다시 돌려야 함

08 Dijkstra 알고리즘

BF의 문제 — 비효율

방금 본 Bellman-Ford는 매 라운드마다 모든 간선을 다 확인해요. 그래프 A에서:

  • 한 라운드 = 17개 간선 검사
  • n-1 = 8 라운드 → 총 17 × 8 = 136번 검사
  • 그런데 실제로 의미 있는 갱신은 그중 일부뿐 (위에서 본 추적 보면 Round 5에서 이미 안정됨)
너무 비효율적
이미 확정된 노드, 아직 ∞인 노드까지 매번 다 훑음. "방금 갱신된 부분 위주로만" 보면 훨씬 빠를 텐데.

더 효율 좋은 알고리즘 — Dijkstra

Dijkstra 알고리즘
매번 "현재 가장 가까운 미확정 노드"를 골라 그 노드만 처리.
한 번 확정된 노드는 다시 안 봄.

핵심 아이디어

Dijkstra의 전략
  • 모든 정점을 "확정"과 "미확정"으로 나눠 관리
  • 매 단계마다 미확정 중 dist 값이 가장 작은 노드를 골라 확정
  • 그 노드를 거쳐 갈 수 있는 이웃들만 relax
  • 모든 노드가 확정될 때까지 반복
비유

a에서 출발해 잉크가 천천히 번지는 모습. 가장 가까운 곳부터 점점 멀리 퍼져나감. BF는 종이 전체를 매번 다시 적시는데, Dijkstra는 번지는 가장자리만 계속 확장.

Dijkstra 의사코드 — 교수님 표기

먼저 — heap이 뭔지 짧게
  • heap: 트리 구조의 자료구조
  • min-heap: 루트가 항상 최솟값인 heap
  • 주요 연산:
    • deleteMin(): 루트(최솟값)를 꺼내고 트리 재구성 — O(log n)
    • decreaseKey(v, newKey): v의 키 값을 작게 갱신하고 재구성 — O(log n)
  • Dijkstra에서는 각 노드의 키 = dist[v]로 설정해 사용
Dijkstra (min-heap 버전) 
# 초기화: 모든 노드를 min-heap Q에 넣음
# 각 노드의 key는 dist[v] (출발점 s는 0, 나머지는 ∞)
# → s가 자연스럽게 루트에 위치
Q = min_heap with dist[v] as keys

while Q ≠ ∅:                          # Q가 텅 빌 때까지
    u = Q.deleteMin()                 # 가장 작은 dist 가진 노드 꺼내기 (= u 확정)
    
    for each edge u → v:              # u에서 나가는 모든 간선
        if dist[v] > dist[u] + w(u, v):
            relax(u, v)               # dist[v] 갱신
            Q.decreaseKey(v, dist[v])  # Q 안의 v 위치도 갱신된 키로 재정렬

한 줄씩 풀어보기

① Q = min_heap with dist[v] as keys

  • 모든 정점을 heap에 넣음. 각 노드의 키 = 그 노드의 dist 값
  • 초기에 dist[a] = 0이고 나머지는 ∞ → a가 자연스럽게 루트에 위치
  • 나머지 노드들은 자식 자리에 ∞로 늘어섬

② while Q ≠ ∅

  • "Q가 비어있지 않은 동안 반복"
  • 매 반복마다 노드 하나가 deleteMin으로 빠지므로, n개 노드면 정확히 n번 반복 후 종료

③ u = Q.deleteMin()

  • Q의 루트(최솟값) 꺼냄 → 이 노드 u가 이번 라운드에 "확정"되는 노드
  • 꺼낸 후 heap을 재구성 (다음으로 작은 값이 루트가 되도록)

④ for each edge u → v

  • u에서 나가는 모든 간선을 차례로 확인
  • u의 이웃 노드들 v에 대해 relax 시도

⑤ relax(u, v) + decreaseKey(v, dist[v])

  • relax: 더 짧은 길 발견 시 dist[v]를 줄임
  • ★ decreaseKey가 중요: dist[v]가 바뀌었으니, heap Q 안에서 v의 위치도 다시 정렬해야 함 → 안 그러면 다음 deleteMin이 잘못된 노드를 뽑게 됨

왜 이게 BF보다 빠른가

핵심 차이
  • BF: 매 라운드 모든 간선 검사 → 의미 없는 비교 多
  • Dijkstra: 한 번 deleteMin된 노드는 다시 안 봄 → 각 노드의 이웃만 1회씩 검사
  • heap이 "다음에 처리할 가장 가까운 노드"를 O(log n)에 알려줌

"Q가 텅 빌 때까지"가 뭔 뜻인가

자연스럽게 끝나는 과정
  • 매 while 반복마다 deleteMin으로 노드 1개 빠짐
  • 노드 9개(그래프 A 기준)면 9번 반복 후 Q가 비워짐
  • 모든 노드가 "확정"됐다는 뜻 → 알고리즘 완료
  • BF처럼 명시적으로 "n-1 라운드"를 세는 게 아니라, 자연스럽게 노드가 다 빠지면 끝

BF vs Dijkstra 차이

구분 Bellman-Ford Dijkstra
접근 방식 매 라운드 모든 간선 검사 가장 가까운 노드부터 하나씩 확정
확정 개념 없음 (n-1 라운드 다 돔) 있음 (한 번 확정 후 안 봄)
속도 느림 빠름
음수 가중치 가능 ✓ 불가 ✗
★ 중요 — Dijkstra의 한계
  • Dijkstra는 모든 간선 가중치가 양수일 때만 정확히 동작
  • 음수 가중치가 있으면 한 번 확정된 노드를 나중에 더 짧게 만들 가능성이 생겨서, "한 번 확정 후 다시 안 본다"는 전략이 깨짐
  • 음수 가중치가 있는 그래프에서는 BF를 써야 함
  • 그래프 A는 모든 가중치가 양수라 Dijkstra 적용 가능
왜 "가장 가까운 노드"부터 골라야 안전한가?

미확정 노드 중 dist가 가장 작은 노드 u에 대해 — 만약 다른 경로로 u에 더 빨리 도달할 수 있다면, 그 경로의 어딘가에 u보다 가까운 미확정 노드가 있어야 함. 그런데 u가 이미 미확정 중 최소였으니 그런 노드는 없음 → 모순. 따라서 u는 진짜 최단 거리로 확정 가능.

단, 이 논리는 모든 가중치가 양수일 때만 성립. 음수가 있으면 "거쳐가는 길이 더 짧을 수도" 있어서 무너짐.

09 Dijkstra 실행 추적 — 그래프 A

s = a로 Dijkstra를 그래프 A에 돌려봅시다. 각 단계에서 Q에 누가 있고, 누가 deleteMin되는지를 추적합니다.

표기 약속

Q = { a(0), b(∞), c(∞), d(∞), e(∞), f(∞), g(∞), h(∞), i(∞) }

Q.deleteMin()으로 a 꺼냄. a에서 나가는 간선: a→b(5), a→c(1).

  • relax(a, b): ∞ > 0 + 5 → dist[b] = 5, decreaseKey(b, 5)
  • relax(a, c): ∞ > 0 + 1 → dist[c] = 1, decreaseKey(c, 1)
Q = { c(1), b(5), d(∞), e(∞), f(∞), g(∞), h(∞), i(∞) }

  • relax(f, g): ∞ > 5 + 3 = 8 → dist[g] = 8

→ d와 g 둘 다 dist=8 (같음). 구현 따라 누가 먼저든 결과는 동일. 여기선 d 먼저

  • relax(g, h): ∞ > 8 + 3 = 11 → dist[h] = 11
  • relax(g, i): ∞ > 8 + 4 = 12 → dist[i] = 12
Q = { e(9), h(11), i(12) }

e에서 나가는 간선: e→c(2), e→h(5). c는 이미 확정.

  • relax(e, h): 11 > 9 + 5 = 14? No

갱신 없음.

Q = { i(12) }

i에서 나가는 간선 없음.

처리 순서 정리

★ 처리 순서의 특징
  • dist 값이 오름차순으로 정렬되어 처리됨 (0 → 1 → 4 → 5 → 8 → 8 → 9 → 11 → 12)
  • 가장 가까운 노드부터 차례로 확정되는 게 그대로 보임
  • 이 성질이 Dijkstra의 핵심 — "한 번 확정된 노드는 진짜 최단 거리"

  • 음수 가중치 있음 → Bellman-Ford (안전)

10 Dijkstra 시간복잡도 + Fibonacci heap

Dijkstra가 BF보다 얼마나 빠른지 정확히 따져봅시다.

두 가지 비용을 따로 계산

Dijkstra의 비용은 크게 두 종류로 나뉨:

  • ① heap 자체 관리 비용: 노드를 Q에 넣고 빼는 일
  • ② decreaseKey 비용: relax할 때마다 heap 재정렬

① heap 관리 — O(n log n)

각 노드는 정확히 한 번 들어가고 한 번 나옴
  • insert: n번 (각 노드 한 번씩) × O(log n) = O(n log n)
  • deleteMin: n번 × O(log n) = O(n log n)
  • 합계: 2n × O(log n) = O(n log n)

insert와 deleteMin 모두 heapify(siftup/siftdown)가 일어나서 O(log n).

② decreaseKey — O(E log n)

간선마다 한 번씩
  • 알고리즘 진행 중 각 간선은 정확히 한 번씩 relax됨 (u가 deleteMin되면 u에서 나가는 간선들 모두 검사)
  • relax 자체는 O(1) — if문 + 대입
  • relax 후 decreaseKey 호출 → 한 번에 O(log n)
  • 간선 E개 × O(log n) = O(E log n)

간선의 최악 개수는 n² (모든 정점 쌍이 연결된 경우) → O(E log n) = O(n² log n)

전체 합계

Dijkstra (min-heap) 시간복잡도
O(n log n) + O(E log n)
= O((n + E) log n)
최악 (E = n²): O(n² log n)

Bellman-Ford와 비교

알고리즘 시간복잡도 최악 (E = n²)
Bellman-Ford O(VE) = O(nE) O(n³)
Dijkstra (min-heap) O((n+E) log n) O(n² log n)

왜 Dijkstra가 더 빠른가

★ 결정적 비교
  • BF의 최악: O(n³)
  • Dijkstra의 최악: O(n² log n)
  • n이 충분히 크면 log n < n
  • 따라서 n² log n < n³ → Dijkstra가 더 빠름

예를 들어 n = 1000이면:

  • n³ = 10억
  • n² log n ≈ 10⁶ × 10 = 천만 → 100배 차이

★ 더 빠르게 — Fibonacci heap

심화 — Fibonacci heap (참고만)
  • 지금까지는 일반 min-heap (binary heap)을 사용
  • 더 발전된 자료구조인 Fibonacci heap (피보나치 힙)으로 바꾸면 시간복잡도를 더 줄일 수 있음
  • Dijkstra 알고리즘 자체는 똑같음 — heap 구조만 바뀜
  • Fibonacci heap을 쓰면 decreaseKey가 amortized O(1)이 되어서 전체가 O(E + n log n)으로 개선됨
  • 이건 심화 과정이라 이번 수업에선 안 다룸 — "이런 방식으로 더 줄일 수도 있구나" 정도만 인지
heap 종류 Dijkstra 시간복잡도
min-heap (binary heap) O((n + E) log n)
Fibonacci heap O(E + n log n)

핵심 정리

14주차-1 한 줄 정리
  • 최단 경로 알고리즘의 핵심 동작은 relax(u, v)
  • Bellman-Ford: 모든 간선을 n−1번 검사 — O(VE), 음수 가중치 OK
  • Dijkstra: 가장 가까운 노드부터 처리 — O((n+E) log n), 양수 가중치만
  • 같은 점화식 dist[v] = min(dist[u] + w(u,v))를 어떤 순서로 계산하느냐의 차이

11 최종 의사코드 — parent 포함

지금까지의 의사코드를 한 번 더 정리합니다. 이번엔 parent 배열까지 같이 다룸. parent가 있어야 "최단 거리"뿐만 아니라 "최단 경로 자체"를 복원할 수 있음.

왜 parent가 필요한가

dist만으론 부족
  • dist[v]: s에서 v까지 가는 데 드는 비용 (얼마나 먼지)
  • parent[v]: v 직전 노드 (어떻게 가는지)
  • 둘 다 있어야 "최단 경로의 길이"와 "최단 경로의 정체"를 모두 안다

최종 의사코드

Dijkstra — 완성판 
# 초기화
s = 0                                       # 출발점 (예: 노드 0번)
dist = [0, ∞, ∞, ..., ∞]                    # s에서 각 노드까지 최단 거리
parent = [None, None, ..., None]        # 최단 경로상 직전 노드

Q = min_heap of all nodes with key dist[v]    # 모든 노드 Q에 삽입 (key = dist)

while Q ≠ ∅:                              # Q가 빌 때까지
    u = Q.deleteMin()                     # 가장 가까운 미확정 노드 꺼내 확정
    
    for each edge u → v:                  # u에서 나가는 모든 간선
        if dist[v] > dist[u] + w(u, v):    # relax 조건
            dist[v] = dist[u] + w(u, v)    # 거리 갱신
            parent[v] = u                  # ★ v의 직전 노드는 u로 기록
            Q.decreaseKey(v, dist[v])      # Q 안의 v 위치 재정렬

return dist, parent

각 부분 한 줄씩

줄 의미
dist = [0, ∞, ..., ∞] 출발점만 0, 나머지는 모름(∞)
parent = [None, ..., None] 아직 어떤 노드를 거쳐가는지 모름
Q = min_heap ... 모든 노드를 heap에 넣음. s가 자연히 루트
u = Q.deleteMin() 가장 가까운 미확정 노드 = 이번 라운드 확정
if dist[v] > ... u 거쳐가는 게 더 짧으면
parent[v] = u ★ v로 가는 최단 경로의 직전 노드를 u로 기록
return dist, parent 거리 + 경로 정보 모두 반환

★ parent 배열의 의미
  • parent 화살표만 따라가면 모든 노드의 최단 경로를 복원할 수 있음
  • 모든 parent 화살표를 모으면 "최단 경로 트리(SPT, Shortest Path Tree)"가 됨
  • 그래프의 모든 간선 중 일부만 사용 (n-1개) → 트리 구조
  • s가 루트, 다른 모든 노드는 s에서 자기까지의 최단 경로의 마지막 부분만 보임

다른 노드까지의 경로도 동시에

  • a → b: a → c → b (parent[b]=c, parent[c]=a)
  • a → d: a → c → b → d
  • a → e: a → c → b → f → g → e
  • a → h: a → c → b → f → g → h

한 번의 Dijkstra 실행으로 출발점 a에서 모든 노드까지의 최단 경로를 동시에 얻음 (SSSP).

12 오늘 꼭 기억할 것

시험 포인트
  1. 최단 경로 문제: 가중치 그래프에서 출발점 s → 도착점 v까지 가중치 합이 최소인 경로
  2. ★ 부분 경로 최단성: 최단 경로의 일부 구간도 반드시 최단 경로 (= Optimal Substructure)
  3. dist[v]: s에서 v까지의 최단 거리. parent[v]: 최단 경로상 v 직전 노드
  4. ★ 점화식: dist[v] = min(dist[u] + w(u,v)) for all u → v
    • 모든 최단 경로 알고리즘의 뼈대
  5. ★ relax(u, v): if dist[v] > dist[u] + w(u,v): dist[v] = dist[u] + w(u,v)
    • 모든 알고리즘이 공유하는 기본 동작
  6. ★ Bellman-Ford:
    • n-1 라운드 × 모든 간선 검사
    • 시간복잡도 O(VE) = O(nE), 최악 O(n³)
    • 음수 가중치 OK
  7. ★ Dijkstra:
    • min-heap에서 가장 가까운 노드부터 deleteMin → 확정
    • relax 후 decreaseKey로 heap 재정렬
    • 시간복잡도 O((n+E) log n), 최악 O(n² log n)
    • 음수 가중치 안 됨 (한 번 확정 후 재검토 X 전략이 깨짐)
  8. 왜 가장 가까운 노드부터?: 양수 가중치일 때 그 노드의 dist는 더 줄어들 수 없음 (다른 미확정 노드를 거쳐도 항상 더 큼)
  9. BF vs Dijkstra:
    • BF: O(n³), 음수 OK
    • Dijkstra: O(n² log n), 양수만
    • logn < n이라 Dijkstra가 더 빠름
  10. Fibonacci heap: heap 종류만 바꿔서 Dijkstra를 O(E + n log n)으로 개선 가능 (심화)
  11. SSSP (Single-Source Shortest Path): 한 출발점에서 모든 노드까지의 최단 경로. BF와 Dijkstra 모두 SSSP 알고리즘. 출발점이 바뀌면 다시 돌려야 함
  12. parent 역추적: parent[v]를 계속 거슬러 올라가면 s까지의 실제 경로를 복원할 수 있음
  13. 최단 경로 트리 (SPT): parent 관계를 모으면 s를 루트로 한 트리가 됨. n-1개 간선
