문제은행 — AVL 트리 (2)

삽입·삭제 · 회전(Rotation) LL/RR/LR/RL · x·y·z 찾기 · 시간복잡도

이 문제집은 9주차 2차시 강의노트(AVL 삽입·삭제) 범위에서 출제했습니다.
유형·난이도는 중간고사 족보 기준입니다 (객관식 · 추적 · 빈칸 채우기 · 표 채우기 · 서술 · 코드 분석).
Q1객관식

AVL 트리의 삽입(insert)이 일반 BST의 삽입과 다른 점으로 옳은 것은?

  1. 삽입 위치를 찾는 탐색 규칙이 BST와 완전히 달라진다.
  2. 삽입 후 균형을 검사하고 회전으로 복구하는 단계가 추가된다.
  3. 키를 반드시 정렬된 순서대로만 삽입할 수 있게 제한된다.
  4. 삽입한 노드를 항상 루트 위치에 배치하게 된다.
✎ 나의 답안
정답 / 풀이 보기

정답: 2번

AVL 삽입은 ① 상속받은 BST insert로 일단 삽입 → ② 위로 올라가며 처음 불균형 노드 z 찾기 → ③ rebalance(회전) → ④ 루트 갱신. 삽입 위치 탐색은 BST와 동일합니다.

Q2빈칸 채우기

rebalance에 쓰이는 세 노드 x, y, z의 정의를 완성하시오. (z, y, x는 위에서 아래로 연속된 3개 노드)

  • • z : 삽입 위치에서 위로 올라가며 처음으로 ____________ 노드 (가장 가까운 불균형 조상)
  • • y : z의 자식 중 더 ____________ 쪽
  • • x : y의 자식 중 더 ____________ 쪽
✎ 나의 답안
정답 / 풀이 보기

정답: 균형이 깨진 / 무거운(높은) / 무거운(높은)

z는 처음 만나는 불균형 조상, y는 z의 더 높은(무거운) 자식, x는 y의 더 높은 자식입니다. 삽입의 경우 "올라온 방향"이 곧 무거운 방향이라 자연스럽게 결정됩니다.

Q3추적

키 10, 5, 15가 있고 5의 오른쪽 자식으로 7이 있는 AVL 트리에 9를 삽입했더니 균형이 깨졌다.

10 / \ 5 15 \ 7 \ 9 ← 새로 삽입

이때 z, y, x에 해당하는 노드를 각각 쓰시오.

✎ 나의 답안
정답 / 풀이 보기

정답: z = 5, y = 7, x = 9

9를 넣은 자리에서 위로 올라가면 7(OK) → 5에서 BF=2로 처음 깨짐 → z=5. z에서 올라온 방향의 자식 7 → y, 그 방향의 자식 9 → x. z-y-x가 우-우(오른쪽-오른쪽)로 이어지므로 RR 케이스입니다.

Q5추적

다음은 LL 케이스로 불균형이 생긴 트리이다. (T1~T4는 서브트리)

z / \ y T4 / \ x T3 / \ T1 T2

(1) rotateRight(z) 후 새 루트가 되는 노드는? (2) 회전 후 z의 왼쪽 서브트리로 옮겨가는 것은?

✎ 나의 답안
정답 / 풀이 보기

정답: (1) y   (2) T3

y가 위로 올라가 새 루트가 되고, z는 y의 오른쪽 자식으로 내려갑니다. 이때 y의 원래 오른쪽 서브트리 T3가 z의 왼쪽으로 옮겨갑니다. (x는 y의 왼쪽 자식으로 유지)

Q6객관식

회전(Rotation)을 해도 BST 조건이 깨지지 않는 이유로 가장 알맞은 것은?

  1. 회전이 노드들의 키 값 자체를 바꾸기 때문
  2. 회전 후에도 중위 순회 결과 순서가 그대로이기 때문
  3. 회전이 잎 노드 근처에서만 일어나기 때문
  4. 회전 후 전체 트리를 다시 정렬하기 때문
✎ 나의 답안
정답 / 풀이 보기

정답: 2번

회전은 키 순서(중위 순회 결과)를 보존한 채 트리 모양만 바꿉니다. in-order 결과가 그대로이므로 "왼쪽 < 루트 < 오른쪽"이라는 BST 조건이 유지됩니다.

Q7서술

LR(좌-우 꺾임) 케이스를 처리하는 핵심 아이디어를 한 문장으로 설명하고, 두 회전의 순서를 쓰시오.

✎ 나의 답안
정답 / 풀이 보기

정답 요지 / 순서: rotateLeft(y) → rotateRight(z)

꺾인 부분을 먼저 펴서 일자형(Case 1, LL 모양)으로 만든 다음 Case 1처럼 회전합니다. 즉 1단계 rotateLeft(y)로 z-x-y가 왼쪽 일자가 되게 만들고, 2단계 rotateRight(z)로 균형을 맞춥니다.

Q8케이스 판별

비어 있는 AVL 트리에 30, 10, 20 순서로 삽입하면 균형이 깨진다. (1) z, y, x를 쓰고 (2) 케이스(LL/RR/LR/RL)와 (3) 필요한 회전을 쓰시오.

✎ 나의 답안
정답 / 풀이 보기

정답: z=30, y=10, x=20 / LR 케이스 / rotateLeft(10) → rotateRight(30)

30 삽입 → 10은 30의 왼쪽 자식 → 20은 10의 오른쪽 자식. 30에서 BF=2로 깨짐(z=30). z의 왼쪽 10이 y, y의 오른쪽 20이 x → 좌-우 꺾임 = LR. 결과적으로 20이 루트, 10과 30이 양쪽 자식이 됩니다.

Q9계산 · 시간복잡도

AVL 삽입의 각 단계별 시간복잡도를 쓰고, 총 시간복잡도를 구하시오.

단계작업시간복잡도
1BST insert (내려가기)?
2x, y, z 찾기 (올라가기)?
3rebalance (회전)?
✎ 나의 답안
정답 / 풀이 보기

정답: O(log n) + O(log n) + O(1) = O(log n)

1단계·2단계는 트리 높이 h = O(log n)만큼 이동, 3단계 회전은 포인터 몇 개만 바꾸므로 O(1). 합치면 O(log n)입니다.

Q10객관식

AVL 삽입에서 rebalance(회전)는 한 번의 삽입당 최대 몇 번 일어나는가?

  1. 한 번의 삽입당 최대 1번
  2. 한 번의 삽입당 최대 O(log n)번
  3. 한 번의 삽입당 최대 O(n)번
  4. 한 번의 삽입당 항상 정확히 2번
✎ 나의 답안
정답 / 풀이 보기

정답: 1번

삽입에서는 한 번 회전으로 균형을 맞추면 그 위쪽 조상들의 높이가 원래대로 돌아와 전체가 다시 균형을 이룹니다. (삭제는 다름 → 다음 문제)

Q11서술 · 비교

AVL 삭제가 삽입과 결정적으로 다른 점은 무엇이며, 그 이유는 무엇인가? (rebalance 횟수 관점에서)

✎ 나의 답안
정답 / 풀이 보기

정답 요지

삽입은 rebalance가 최대 1번이지만, 삭제는 최대 O(log n)번(연쇄 rebalance) 일어날 수 있습니다. 이유: 삭제 후 한 곳을 회전해 맞춰도 그 부모 노드에서 또 균형이 깨질 수 있어, 루트까지 올라가며 반복 검사해야 하기 때문입니다.

Q12코드 빈칸 채우기

AVL 삭제 의사코드의 빈칸을 채우시오.

def delete(self, u):
    v = super().deleteByCopying(u)   # v = 지운 노드의 부모
    while v is _______:              # ★ ⓐ 루트까지 올라가며 검사
        if not v.is_balanced():
            z = v
            if z.left.height > z.right.height:
                y = z.left
            else:
                y = z.right
            ...
            v = rebalance(x, y, z)
            w = v
        v = v._______                # ★ ⓑ 한 단계 위로
    self.root = w
✎ 나의 답안
정답 / 풀이 보기

정답: ⓐ not None   ⓑ parent

while v is not None 으로 루트까지 올라가며 검사(삽입과 결정적 차이), 매 반복 끝에 v = v.parent 로 한 단계 위로 올라갑니다. 루프가 끝나면 w가 항상 루트가 됩니다.

Q13코드 빈칸 채우기

삭제 시 y(그리고 x)를 고르는 규칙이다. 빈칸을 채우시오. ("무거운 쪽 = 높이가 더 큰 쪽")

# z의 무거운 쪽 자식을 y로
if z.left.height > z.right.height:
    y = z._______
else:
    y = z._______
✎ 나의 답안
정답 / 풀이 보기

정답: y = z.left (if), y = z.right (else)

z의 자식 중 높이가 더 큰(무거운) 쪽으로 내려가 y를 정하고, x도 같은 방식으로 y의 무거운 자식을 고릅니다.

Q14표 채우기 · 종합

AVL 트리의 연산별 시간복잡도를 채우시오. (n = 노드 개수)

연산시간복잡도
탐색 (search)?
삽입 (insert)?
삭제 (delete)?
높이 (height)?
✎ 나의 답안
정답 / 풀이 보기

정답: 모두 O(log n)

삭제는 BST 삭제 O(log n) + 연쇄 rebalance O(log n)×O(1)이지만 합쳐도 O(log n)입니다. 균형 조건 덕에 높이가 O(log n)으로 보장되어 모든 연산이 O(log n)입니다.
