문제은행 — 그래프 기본

G = (V, E) · 인접 행렬 / 인접 리스트 · 방향/무방향 · 기본 연산 시간복잡도

이 문제집은 11주차 2차시 강의노트(그래프 기본) 범위에서 출제했습니다.
난이도·유형은 중간고사 족보 기준입니다 (객관식 · 계산 · 추적 · 빈칸 채우기 · 표 채우기 · 서술).
Q1빈칸 채우기

그래프의 수학적 정의 G = (V, E)에서 V와 E가 각각 무엇인지(영어 용어와 우리말) 채우시오.

정답 / 풀이 보기

정답: V = Vertex(꼭짓점·정점·노드)의 집합, E = Edge(모서리·간선)의 집합

그래프는 "어떤 노드가 있는지(V)"와 "어떤 노드끼리 연결됐는지(E)" 두 집합으로 정의됩니다. 각 모서리는 두 꼭짓점의 쌍 (u, v)입니다.

Q2계산

다음 그래프에서 n과 m을 구하시오. (표기: |V| = n, |E| = m)

V = {1, 2, 3, 4, 5, 6}
E = {(1,2), (1,5), (2,5), (2,3), (5,4), (4,6)}
정답 / 풀이 보기

정답: n = 6, m = 6

n = |V| = 꼭짓점 6개, m = |E| = 모서리 6개. (1, 2, 5는 서로 모두 연결되어 삼각형 사이클을 이룹니다.)

Q3객관식

무방향 그래프와 방향(유향) 그래프에서 모서리 표기 (u, v)에 대한 설명으로 옳은 것은?

  1. 무방향: (u,v) = (v,u) / 방향: (u,v) ≠ (v,u)
  2. 무방향: (u,v) ≠ (v,u) / 방향: (u,v) = (v,u)
  3. 둘 다 (u,v) = (v,u)
  4. 둘 다 (u,v) ≠ (v,u)
정답 / 풀이 보기

정답: 1번

무방향 그래프에서 (u,v)와 (v,u)는 같은 모서리입니다. 방향 그래프에서는 (u,v)가 "u→v"만 의미하므로 (v,u)와 다릅니다.

Q4계산 · 최단 경로

도시 거리 그래프의 일부이다. (가중치 = km)

서울—원주: 110    서울—수원: 30    수원—원주: 80
서울—춘천: 70     춘천—원주: 90

서울에서 원주까지 가는 최단 거리와 그 경로(들)를 구하시오.

정답 / 풀이 보기

정답: 110 km

직접: 서울→원주 = 110. 경유1: 서울→수원→원주 = 30+80 = 110. 경유2: 서울→춘천→원주 = 70+90 = 160. 최단은 110 (직접 경로와 수원 경유 경로 둘 다 110).

Q5객관식

이 수업의 약속에서 인접 행렬의 주대각 성분 A[i][i] = 1의 의미로 옳은 것은?

  1. 모든 노드에 self-loop(자기 자신으로 가는 모서리)가 실제로 존재한다.
  2. 실제 모서리는 아니고, 단순히 약속(관례)으로 1로 채운 것이다.
  3. 노드 i의 이웃 수가 1개라는 뜻이다.
  4. 노드 i가 루트라는 뜻이다.
정답 / 풀이 보기

정답: 2번

교수님 약속으로 주대각을 1로 채우는 것이며 self-loop가 있다는 뜻이 아닙니다(그림에 자기 자신 선 없음). 교과서에 따라 0으로 두기도 하지만 이 수업·시험에서는 1로 통일합니다.

Q6작성 · 인접 행렬

다음 무방향 그래프의 인접 행렬(6×6, 주대각 1 약속)에서 노드 4의 행(A[4][1]~A[4][6])을 쓰시오.

V = {1,2,3,4,5,6}
E = {(1,2),(1,5),(2,3),(2,5),(3,4),(4,5),(4,6)}
정답 / 풀이 보기

정답: 0 0 1 1 1 1

노드 4의 이웃: 3, 5, 6 (모서리 (3,4),(4,5),(4,6))에 자기 자신 4를 더함 → A[4][3]=A[4][4]=A[4][5]=A[4][6]=1, 나머지(1,2열)=0. 따라서 행 = [0,0,1,1,1,1].

Q7계산 · 메모리 사용률

n = 6, m = 7인 무방향 그래프를 인접 행렬(주대각 1 약속)로 표현했다. (1) 행렬에서 값이 1인 칸의 총 개수와 (2) 전체 칸 대비 사용률을 구하시오.

정답 / 풀이 보기

정답: (1) 20개   (2) 20/36 ≈ 55.6%

1의 개수 = (주대각) n + (무방향 모서리 양방향) 2m = 6 + 2×7 = 20. 전체 칸 = n² = 36. 사용률 ≈ 55.6%. 모서리가 적은 희소(sparse) 그래프일수록 0이 많아져 행렬은 메모리 낭비가 큽니다.

Q8객관식

인접 행렬의 대칭성에 대한 설명으로 옳은 것은?

  1. 무방향 그래프는 A[i][j] = A[j][i] (대각선 대칭), 방향 그래프는 비대칭일 수 있다.
  2. 무방향 그래프가 비대칭, 방향 그래프가 대칭이다.
  3. 둘 다 항상 대칭이다.
  4. 대칭성은 노드 개수에만 의존한다.
정답 / 풀이 보기

정답: 1번

무방향은 (u,v)=(v,u)라 A[u][v]=A[v][u]로 대각선 대칭입니다. 그래서 위쪽(또는 아래쪽) 삼각형만 저장해 메모리를 절반으로 줄일 수 있습니다. 방향 그래프는 한 방향만 1이라 비대칭이 됩니다.

Q9빈칸 채우기

인접 리스트(Adjacency List)의 구조와 메모리에 관한 빈칸을 채우시오.

노드 개수만큼의 (______)(헤더)가 있고, 각 칸은 그 노드의 이웃들을 담은 (______)를 가리킨다. 전체 메모리 사용량은 O(______)이다.

정답 / 풀이 보기

정답: 배열 / 연결 리스트 / O(n + m)

배열(노드 n개) + 모서리 수에 비례하는 연결 리스트 노드들 → O(n + m). 행렬의 O(n²)보다 희소 그래프에서 훨씬 효율적입니다.

Q10추적 · 방향 그래프

다음 방향 그래프의 인접 행렬(주대각 1 약속, 행=from·열=to)에서 세 칸의 값을 구하시오.

V = {1,2,3,4}
E = {(1,2), (2,4), (3,1), (3,2), (4,3)}   # (u,v)=u→v

(1) A[1][2]   (2) A[2][1]   (3) A[3][2]

정답 / 풀이 보기

정답: (1) 1   (2) 0   (3) 1

A[1][2]=1 (1→2 있음). A[2][1]=0 (2→1 모서리 없음, 방향이라 별개). A[3][2]=1 (3→2 있음). 방향 그래프라 A[u][v]와 A[v][u]가 독립입니다.

Q11표 채우기

그래프 기본 연산의 시간복잡도를 인접 행렬과 인접 리스트 각각에 대해 채우시오. (n=노드, m=모서리)

연산인접 행렬인접 리스트
① 메모리??
② (u,v)∈E? 확인??
③ u의 인접 노드 순회??
④ 모서리 삽입??
⑤ 모서리 삭제??
정답 / 풀이 보기
연산인접 행렬인접 리스트
① 메모리O(n²)O(n+m)
② 모서리 확인O(1)O(n)

Q12서술

인접 리스트에서 모서리 삭제가 O(n)으로 인접 행렬(O(1))보다 느린 이유를 설명하시오.

정답 / 풀이 보기

정답 요지

연결 리스트는 인덱스로 직접 접근할 수 없어, 삭제할 이웃 노드 v를 찾으려면 리스트를 처음부터 순회해야 합니다(search = O(n)). 찾은 뒤 제거 자체는 포인터 재연결로 O(1)이지만, 탐색이 지배적이라 전체 O(n)입니다. 행렬은 G[u][v]=0 한 칸만 바꾸면 되어 O(1)입니다.

Q13객관식

그래프 밀도에 따른 표현법 선택으로 옳은 것은?

  1. Sparse(m 작음) → 인접 리스트 / Dense(m이 n²에 가까움) → 인접 행렬
  2. Sparse → 인접 행렬 / Dense → 인접 리스트
  3. 밀도와 무관하게 항상 인접 행렬
  4. 밀도와 무관하게 항상 인접 리스트
정답 / 풀이 보기

정답: 1번

희소 그래프는 m이 작아 O(n+m)인 리스트가 메모리 효율적입니다. 빽빽한 그래프는 m ≈ n²이라 리스트도 O(n²)에 포인터 오버헤드까지 생기므로 행렬이 낫습니다.

Q14객관식

앞으로 배울 BFS, DFS 같은 그래프 탐색 알고리즘은 주로 어떤 표현법을 사용하며 그 이유는?

  1. 인접 행렬 — 모서리 확인이 O(1)이라서
  2. 인접 리스트 — 탐색의 핵심이 "인접 노드 순회"인데 리스트가 실제 이웃만큼만 순회해서
  3. 둘 다 성능이 같아서 아무거나
  4. 가중치 행렬만 사용한다
정답 / 풀이 보기

정답: 2번

BFS·DFS는 "한 노드의 인접 노드를 모두 방문"이 핵심입니다. 인접 리스트는 실제 이웃 수만큼만 순회하지만(행렬은 이웃이 없어도 n번 검사), 그래서 탐색 알고리즘은 대부분 인접 리스트를 씁니다.

Q15객관식

인접 리스트에 새 모서리를 추가할 때 리스트의 맨 뒤가 아니라 맨 앞에 넣는(pushfront) 이유는?

  1. 맨 앞 추가는 O(1), 맨 뒤 추가는 끝까지 가야 해서 O(n)이고, 이웃 순서는 중요하지 않기 때문
  2. 맨 앞에 넣어야 정렬이 유지되기 때문
  3. 맨 뒤 추가는 불가능하기 때문
  4. 메모리를 절반으로 줄이기 위해
정답 / 풀이 보기

정답: 1번

연결 리스트 맨 앞 삽입은 포인터 한 번 연결로 O(1)이고, 맨 뒤는 끝 노드까지 이동해야 해 O(n)입니다. 인접 리스트는 이웃의 순서가 의미 없으므로 빠른 pushfront를 씁니다.
