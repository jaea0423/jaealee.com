레드블랙 트리 높이 상계 개선

2-3-4 트리와의 관계로 더 타이트한 bound 구하기

01 복습 — 두 트리는 치환 가능

지난 시간 복습

탐색 트리에는 레드블랙 트리와 2-3-4 트리가 있고, 둘은 서로 1:1로 치환됩니다.

치환 규칙 정리

2-3-4 트리 레드블랙 트리 레벨 수
2-노드 (자식 2개) 1개 노드 (black) 1레벨
3-노드 (자식 3개) 상위: black / 하위: red 1개 2레벨
4-노드 (자식 4개) 상위: black / 하위: red 2개 2레벨

변환 후 모든 리프는 None으로 처리됩니다 (레드블랙 트리의 정의상).

왜 3-노드와 4-노드가 2레벨?

연결 학습 — 레드블랙 트리
레드블랙 트리는 이진 탐색 트리(BST)예요. 자식이 최대 2개. 그래서 3-노드(자식 3)나 4-노드(자식 4)를 직접 표현 못 함 → 2레벨로 펼쳐서 표현.

02 복습 — 기존 높이 분석

레드블랙 트리 높이

10주차-1에서 증명한 결과:

h' ≤ 2 · log2 n 즉 O(2·log₂n) = O(log n)

2-3-4 트리 높이

10주차-2에서 본 결과:

log4 n  ≤  h  ≤  log2 n 최선(모두 4-노드) ~ 최악(모두 2-노드)
표기 약속
이번 시간 내내:
  • 2-3-4 트리 높이 = h
  • 레드블랙 트리 높이 = h'

03 핵심 질문 — h'을 더 타이트하게?

기존 결과 h' ≤ 2·log₂ n은 상계. 더 작은 상계(더 타이트한 bound)를 구할 수 있을까?

연결 학습 — 상계는 작을수록 좋다
지난 시간 마지막에 배운 것: 상계(upper bound)는 작을수록 좋음. 알고리즘의 최악 성능을 더 정밀하게 보여주기 때문.

접근 방법

2-3-4 트리를 레드블랙 트리로 바꿨을 때, 레드블랙 트리 높이 h'이 최대가 되는 경우를 찾으면 그게 곧 h'의 상계.

즉, "2-3-4 트리가 어떤 모양일 때 변환 결과의 높이가 가장 클까?"라는 질문.

04 답 — 모두 3-노드일 때 h'이 최대

3종류 노드 각각의 "키 1개당 레벨 수"를 비교해봅시다.

노드 종류 키 개수 레드블랙 레벨 키 1개당 레벨
2-노드 1개 1레벨 1 레벨/키
3-노드 2개 2레벨 1 레벨/키
4-노드 3개 2레벨 0.67 레벨/키

왜 3-노드가 worst?

각 노드를 레드블랙으로 변환했을 때, 같은 키 개수 n에서 얼마나 깊어지는지 비교:

모두 2-노드

h = log₂ n
→ h' = log₂ n × 1
= log₂ n

모두 3-노드 ★

h = log₃ n
→ h' = log₃ n × 2
= 2·log₃ n ≈ 1.26·log₂ n

모두 4-노드

h = log₄ n
→ h' = log₄ n × 2
= 2·log₄ n = log₂ n
결론
셋 중 3-노드일 때 h'이 가장 큼. 그래서 worst case 분석은 "모두 3-노드"로 가정하고 시작합니다.

05 3-노드만 있을 때 2-3-4 트리 높이

모든 노드가 3-노드라고 가정. 그러면 각 노드는 자식이 정확히 3개씩.

일반 공식

연결 학습 — 균형 트리의 높이
이진 트리에서 자식 꽉 채우면 h = log₂ n이었음. 이걸 일반화하면:

자식이 x개씩 있는 균형 트리에서 노드 n개의 높이 = logx n

3-노드 트리에 적용

자식이 3개씩 → x = 3:

h = log3 n 모두 3-노드 가정

예시 — 3-노드 2-3-4 트리

06 변환 결과 — h' ≤ 2·log₃ n

이제 이 3-노드 트리를 레드블랙 트리로 바꿔봅시다.

3-노드 1개 → 레드블랙 2레벨

치환 규칙: 3-노드는 레드블랙에서 2레벨로 표현됨.

3-노드 [a, b] 하나가 레드블랙에서 2레벨로 펼쳐짐

전체 높이로 확장

2-3-4 트리의 모든 노드(h개의 레벨)가 각각 2배로 늘어남:

h' ≤ 2 · h 최악의 경우 (모두 3-노드)

그런데 위에서 모두 3-노드일 때 h = log₃ n이므로:

중간 결과
h' ≤ 2 · log3 n
잠깐, 이게 2·log₂n보다 작아?
겉보기엔 잘 모르겠죠. 두 식을 직접 비교하려면 밑을 통일해야 해요. 다음 섹션에서 처리합니다.

07 로그의 밑 변환 공식

2·log₃n과 2·log₂n을 비교하려면 둘의 밑을 같게 만들어야 합니다.

로그 밑 변환 공식 (Change of Base Formula)
loga b = logc blogc a

밑이 a인 로그를 밑이 c인 로그로 바꾸려면 분자에 logcb, 분모에 logca.

log₃n을 밑 2로 바꾸기

a=3, b=n, c=2 대입:

Step 1 · 공식 적용
log3 n = log2 nlog2 3
Step 2 · 2를 곱해서 정리
2 · log3 n = 2log2 3 · log2 n

즉:

h' ≤ 2log2 3 · log2 n 밑을 2로 통일한 형태

이제 기존 식 2·log₂n과 비교 가능. 그러려면 2/log₂3이 얼마인지 알아야 함.

08 log₂3은 얼마쯤?

부등식으로 추론하기

정확한 값 안 구해도 범위만 알면 됨. 로그가 단조증가 함수인 점을 이용합니다.

연결 학습 — 단조증가 함수
log2x는 x가 커질수록 log2x도 커지는 단조증가 함수. 따라서 a < b이면 log2a < log2b. 부등호 방향 안 바뀜.

유도 과정

Step 1 · 2 < 3 < 4 부등식 시작

자명한 사실:

2 < 3 < 4
Step 2 · 양변에 log₂ 씌우기

단조증가 함수이므로 부등호 방향 그대로:

log2 2 < log2 3 < log2 4
Step 3 · 양 끝 값 계산

log22 = 1은 자명. log24는 로그 성질을 써서 계산:

로그 성질
loga bc = c · loga b

4 = 2² 이므로:

log2 4 = log2 22 = 2 · log2 2 = 2 · 1 = 2
Step 4 · 종합
1 < log2 3 < 2

즉 log₂3은 1과 2 사이의 어떤 값. 실제 값은 약 1.585 정도.

2/log₂3은 얼마?

log₂3 ≈ 1.585이므로:

2log2 3 ≈ 21.585 ≈ 1.26
정확한 값보다 중요한 것
핵심은 2/log₂3 < 2라는 것. log₂3 > 1이니까 2를 그보다 큰 수로 나누면 당연히 2보다 작음.

09 최종 결론 — 더 타이트한 상계

비교

기존 상계

h' ≤ 2 · log₂ n
계수 = 2.0

개선된 상계 ★

h' ≤ 1.26 · log₂ n
계수 ≈ 1.26 (더 작음!)
최종 결론
h' ≤ 2log2 3 · log2 n ≈ 1.26 · log2 n

의미

왜 이게 중요한가
  • 2·log₂n과 1.26·log₂n은 둘 다 빅오로는 O(log n)으로 같음
  • 하지만 실제 상수 계수까지 보면 1.26이 훨씬 작음
  • 즉 같은 빅오라도 "더 정밀한" 분석이 가능
  • 레드블랙 트리가 우리가 생각한 것보다 실제로는 더 균형 잡혀있다는 의미

증명 전체 흐름 정리

증명 요약
  1. h'이 최대가 되는 2-3-4 트리는? → 모두 3-노드인 경우
  2. 모두 3-노드일 때 2-3-4 높이: h = log₃n
  3. 3-노드 → 레드블랙 2레벨이므로: h' ≤ 2h = 2·log₃n
  4. 밑 변환: 2·log₃n = (2/log₂3) · log₂n
  5. log₂3 > 1이므로 2/log₂3 < 2
  6. 따라서 h' ≤ 1.26·log₂n < 2·log₂n → 더 타이트한 상계 ✓
상계와 하계 다시 보기
  • 상계: 비용 ≤ c → 작을수록 좋음 (더 정밀한 분석)
  • 오늘 한 일: 상계를 2 → 1.26으로 줄였음 → 더 좋은 분석

10 왜 h를 줄이려고 하나?

교수님이 강조하신 부분
"h를 줄이는 것 = 수행 시간을 줄이는 것". 트리에서 모든 연산(search, insert, delete)이 O(h)이기 때문. 이 논리를 꼭 이해해야 한다고 강조하셨음.

비유 — 에러 허용치

두 시스템 중 어떤 게 더 좋을까요?

시스템 A

error ≤ 10
최악의 오차 10

시스템 B ★

error ≤ 2
최악의 오차 2 (더 정밀)
당연히 error ≤ 2가 좋음. 상계가 작을수록 시스템이 더 신뢰할 만함.

트리에서도 같은 논리

트리에서 연산 시간은 높이 h에 비례:

수행 시간 = O(h)

따라서:

  • h가 작다 = 연산이 빠르다
  • h의 상계가 작다 = 최악의 경우에도 빠르다는 보장

오늘 우리가 한 일의 의미

개선 결과
분석 레드블랙 높이 상계 최악 연산 시간
기존 2 · log₂n 2 · log₂n
개선 1.26 · log₂n 1.26 · log₂n
"조금의 차이"가 왜 중요한가
  • n = 1,000,000일 때 log₂n ≈ 20
  • 기존: 2 × 20 = 40번의 연산
  • 개선: 1.26 × 20 ≈ 25번의 연산
  • 큰 데이터에서는 이 차이가 누적되어 실제로 큰 차이가 됨

레드블랙 트리 단원 마무리

정리
  • 레드블랙 트리는 균형 BST의 대표
  • 2-3-4 트리와 1:1 대응 (같은 트리의 두 가지 표현)
  • 모든 연산 O(log n) 보장
  • 높이 상계가 2·log₂n → 1.26·log₂n으로 더 타이트하게 분석됨

이걸로 균형 탐색 트리 챕터(BST → AVL → 레드블랙 / 2-3-4)는 마무리됩니다.

11 Union-Find 자료구조

이제 마지막으로 배울 트리: Union-Find (Disjoint Set) 자료구조.

이름의 의미

두 가지 이름
  • Union-Find: Union(합집합)과 Find(찾기) 두 연산에 특화되었기 때문
  • Disjoint Set (분리 집합):
    • dis (부정) + joint (겹치는) + set (집합)
    • = "서로 겹치지 않는 집합"이라는 뜻

핵심 정의

Union-Find
집합(set)에 대한 연산을 효율적으로 제공하는 자료구조
연결 학습 — 이산수학의 집합
이산수학에서 배운 집합 개념을 자료구조로 직접 표현한 것. 합집합, 교집합, 차집합 같은 연산을 빠르게 처리하기 위해 만들어진 자료구조예요.

12 집합 예시와 연산 종류

집합 예시

두 집합 S와 T를 가지고 생각해봅시다:

S = { 1, 8, 4, −7 }
T = { 2, 5, 4 }
표현 방식
각 원소는 노드의 key 값으로 생각합니다. 트리 형태로 저장될 때 각 노드가 집합의 원소를 담는 구조.

집합의 성질 — 중복 허용 X

연결 학습 — 집합의 정의
이산수학의 집합 정의: 같은 원소를 두 번 갖지 않음. 중복되는 원소가 있어도 1개만 작성.

예: { 1, 2, 2, 3 } = { 1, 2, 3 }

제공할 연산들

Union-Find가 다루는 연산은 크게 두 종류:

① Membership 연산 (find)

정의

특정 원소가 어떤 집합에 포함되는지 확인하는 연산.

"2 ∈ S ?" → True / False

예시:

  • "2 ∈ S?" → S = {1, 8, 4, -7}에 2 없음 → False
  • "2 ∈ T?" → T = {2, 5, 4}에 2 있음 → True
  • "4 ∈ S?" → S에 4 있음 → True

② 집합 기본 연산 ★

정의

두 집합을 입력으로 받아서 새 집합 또는 결과를 반환:

연산 기호 의미
합집합 (Union) S ∪ T S와 T의 모든 원소를 합친 집합
교집합 (Intersection) S ∩ T S와 T 둘 다에 있는 원소만 모은 집합
차집합 (Difference) S − T S에 있고 T에 없는 원소만 모은 집합

예시 — S, T로 직접 계산

두 집합 S와 T의 관계 — 공통 원소 4가 교집합

이걸 왜 자료구조로?

미리보기
  • 집합 연산을 단순 배열이나 리스트로 하면 매번 전체 순회 필요 → O(n)
  • Union-Find는 트리 구조 + 영리한 트릭으로 거의 O(1) 수준까지 최적화 가능
  • 특히 union과 find가 핵심 (그래서 이름이 Union-Find)

구체적인 트리 표현 방식과 알고리즘은 다음 시간에 이어집니다.

13 Python set과 3개 핵심 연산

Python의 set 자료형

Python은 집합을 직접 다룰 수 있는 set 자료형을 제공합니다. 집합의 효율적인 구현체.

Python 
# 빈 집합 선언
A = set()        # A = {} (공집합)

# 원소가 있는 집합 - 중복은 자동 제거
B = {3, 5, 1, 3} # B = {3, 5, 1} (3 중복 제거됨)
집합의 성질 재확인
{3, 5, 1, 3}처럼 적어도 Python이 자동으로 중복을 제거해서 {3, 5, 1}로 처리. 집합 정의(원소는 한 번씩만)와 일치.

앞으로 집중할 2개 연산

Union-Find 자료구조에서 가장 중요한 두 연산: membership (find)와 union (합집합).

3개 핵심 연산 정의

① make-set(x)

x만으로 구성된 새 집합 { x }를 만드는 연산

  • 입력: 원소 x
  • 결과: 새 집합 {x}가 생성됨
② find(x)

x가 속한 집합 (또는 집합의 대표 원소)을 반환하는 연산

  • 입력: 원소 x
  • 결과: x가 속한 집합의 식별자 (보통 대표 원소)
  • membership 연산에 해당
③ union(x, y)

x와 y가 각각 속한 두 집합을 하나로 합치는 연산

  • 입력: 두 원소 x, y (key 값)
  • 결과: x가 속한 집합과 y가 속한 집합이 합쳐짐
  • 주의: 합쳐지는 건 x, y가 아니라 그들이 속한 집합

14 목표 — find와 union이 O(log n)

우리의 목표
find와 union이 모두 O(log n) 안에 끝나도록 만들기
왜 O(log n)을 목표로 하나?
  • 지금까지 본 균형 트리들(AVL, 레드블랙, 2-3-4)도 모두 O(log n)
  • 현실적으로 만들 수 있는 효율적인 자료구조의 한 기준선
  • 대량 데이터에서도 충분히 빠름

접근 — 2가지 방법 비교

두 가지 방법을 살펴봅니다:

  • 방법 1: 원형 양방향 연결 리스트 — 비교용 (공부 필요 X)
  • 방법 2: 트리 ★ — 실제로 쓰는 방법
교수님 안내
방법 1은 왜 방법 2가 좋은지 보여주기 위한 비교용. 시험에서 자세히 묻지 않을 가능성 높음. 그래도 비교 결과는 알아두기.

15 방법 1 — 원형 양방향 연결 리스트

참고용
이 방법은 비교를 위한 학습용. 실제로 사용하지는 않음. 트리 방식이 왜 좋은지 보여주려고 가져온 것.

구조

각 집합을 원형 양방향 연결 리스트 (Circular Doubly Linked List)로 표현. 더미 헤드(공집합 표시)를 두고, 원소들이 양방향으로 연결됨.

make-set(x)

make-set(x) — 더미헤드와 x가 양방향 원형으로 연결
make-set(x) = O(1) 노드 2개 연결만 하면 됨

find(x)

x가 어떤 집합에 속하는지 찾으려면 리스트를 전부 훑어야 함. 노드 n개면 최악 n번 탐색.

x를 찾으려면 더미헤드부터 차례로 비교 → 최악 n번
find(x) = O(n) 원형 양방향 리스트의 한계 — 전체 탐색 필요

find가 끝나면 발견된 집합의 식별자(예: 더미헤드)를 반환:

의사코드 
v = find(x)  # v는 x가 속한 집합의 대표 (예: 더미헤드)

union(x, y)

x가 속한 집합과 y가 속한 집합을 합치려면:

의사코드 
v = find(x)         # O(n) — x가 속한 집합
w = find(y)         # O(n) — y가 속한 집합
if v != w:          # 이미 같은 집합이면 합칠 필요 없음
    join(v, w)      # O(1) — 두 리스트를 연결
왜 v != w 체크?
이미 두 원소 x, y가 같은 집합에 있다면 합집합 결과가 원래 집합이랑 같음 → 합칠 필요 없음.
union(x, y) = O(n) + O(n) + O(1) = O(n) find 비용이 지배적

방법 1 시간복잡도 정리

연산 시간복잡도 평가
make-set O(1) 좋음
find O(n) 나쁨
union O(n) 나쁨
결론
O(n)은 좋지 않음. 우리 목표(O(log n))를 달성 못함. 트리로 바꿔보자.

16 방법 2 — 트리 (핵심) ★

핵심 발상

Union-Find의 트리 구조
  • 각 집합을 하나의 트리로 표현
  • 각 노드는 부모를 가리키는 링크만 가짐 (자식 X)
  • 루트 노드는 자기 자신을 가리킴
  • 같은 트리(=같은 루트)에 있으면 같은 집합
이전 트리들과의 차이
BST, AVL, 레드블랙, 2-3-4 트리는 부모 → 자식 링크를 썼음. Union-Find는 반대로 자식 → 부모 링크만 씀. 같은 트리지만 활용 방식이 정반대.

예시 — S = {1, 3, 5, 2}

집합 S의 모든 원소를 트리 하나로 묶기. 3을 루트로 하고 나머지가 모두 3을 부모로 가리킨다고 하면:

루트 3은 자기 자신을 가리킴. 나머지는 모두 3을 부모로 가리킴
자식 수 제한 없음
Union-Find 트리는 한 노드가 자식을 몇 개든 가질 수 있어요 (2-3-4 트리와 달리 제한 없음). 다진 트리 형태.

find(x) 구현

find(x)는 x에서 부모 링크를 따라 올라가며 루트를 찾는 것. 루트가 곧 집합의 식별자.

예시

  • find(2) → 2의 부모 = 3 → 3은 자기 자신(루트) → 3 반환
  • find(1) → 1의 부모 = 3 → 루트 → 3 반환
  • find(2) == find(1) → 둘 다 3 → 같은 집합 ✓

핵심 활용

두 원소가 같은 집합인지 판별
find(x) == find(y)이면 같은 집합. 다르면 다른 집합. 이게 Union-Find의 핵심 사용 패턴.

또 다른 예시 트리 — 자식 3개

find(6) — 6의 부모 7이 루트이므로 7을 반환

find 수행시간

find(x)는 x에서 루트까지 부모를 따라 올라감. 가는 거리 = 트리 높이.

find(x) = O(h) h는 트리 높이
왜 O(h)?
리프(또는 깊은 노드)에서 시작해서 한 레벨씩 부모로 올라가면 최대 h번 이동. 균형 잡힌 트리라면 h = O(log n).

17 트리로 union(x, y) 구현

아이디어

x와 y가 속한 두 트리(집합)를 찾아서, 하나의 트리로 합치면 됨. 합칠 때는 한 트리의 루트가 다른 트리의 루트를 가리키게.

예시 — union(2, 6)

두 개의 별개 집합이 있다고 가정:

  • 집합 1: 루트 3, 자식 1, 5, 2
  • 집합 2: 루트 7, 자식 4, 9, 6
union(2, 6) 직전 상태 — 별개의 두 트리

알고리즘

의사코드 
# union(x, y)
v = find(x)          # x가 속한 집합의 루트 — O(h)
w = find(y)          # y가 속한 집합의 루트 — O(h)
if v != w:           # 이미 같은 집합이면 합칠 필요 없음
    w.parent = v     # w의 부모를 v로 설정 — O(1)

단계별 진행

Step 1 · find(2)

2 → 부모 3 (루트) → 반환값 v = 3

Step 2 · find(6)

6 → 부모 7 (루트) → 반환값 w = 7

Step 3 · v != w 확인

v = 3, w = 7 → 서로 다름 → 합쳐야 함

Step 4 · w.parent = v

7의 부모를 3으로 설정 → 7이 더 이상 자기 자신을 가리키지 않고 3을 가리킴 → 트리 하나로 합쳐짐

union 후 상태

union 후 — 7이 3을 부모로 가리키면서 두 트리가 하나로 합쳐짐. 트리 높이가 1 증가

union 수행시간

시간 분석
단계 작업 시간
1 v = find(x) O(h)
2 w = find(y) O(h)
3 v != w 비교 O(1)
4 w.parent = v 설정 O(1)
union(x, y) = O(h) + O(h) + O(1) = O(h) find 비용이 지배적

방법 1과 방법 2 비교

연산 방법 1 (연결 리스트) 방법 2 (트리)
make-set O(1) O(1)
find O(n) O(h)
union O(n) O(h)
트리 방식의 장점
  • O(n) → O(h)로 줄었음
  • 균형 잡힌 트리면 h = O(log n) → 목표 달성
  • 단, 트리가 한쪽으로 치우치면 h = O(n)이 될 수도 있음 → 이걸 막는 트릭이 필요 (다음 시간 예고)
아직 안전하지 않은 이유
union을 잘못 하면 트리가 한쪽으로 쏠려서 결국 O(n)이 될 수 있어요. 그래서 weighted union이나 path compression 같은 최적화가 필요. 다음 시간에 이어집니다.

18 union의 핵심 질문 — 누가 누구의 부모로?

지난 시간 union 알고리즘에는 빠진 부분이 있었어요. v와 w 중 누가 부모가 될지 결정하는 부분.

union 의사코드 (불완전) 
# union(x, y)
v = find(x)          # O(h)
w = find(y)
if v != w:
    # ❓ v.parent = w 인가, w.parent = v 인가?
    ???

두 가지 선택지

v와 w가 각각 루트인 두 트리가 있다고 할 때, 합치는 방법은 두 가지:

두 트리를 합치는 두 가지 방법 — 어느 쪽이 더 좋을까?

판단 기준

원칙

우리는 높이를 낮게 만들고 싶음. 트리 연산 시간이 높이에 비례하니까(O(h)).

결론: 높이 낮은 트리를 높이 높은 트리 밑에 붙이자!

왜냐하면 낮은 게 위로 가면 전체 높이가 +1 되는데, 낮은 게 아래로 가면 전체 높이가 그대로 유지되기 때문.

19 Union by Height — 3가지 경우

의사코드 (height 사용 버전)

의사코드 
# 두 트리의 높이를 비교해서 합치기
if v != w:
    if v.height > w.height:       # v가 더 높음
        w.parent = v               # v 밑에 w를 달음
        # 결합 후 높이 = v.height (그대로)
    elif v.height < w.height:    # w가 더 높음
        v.parent = w               # w 밑에 v를 달음
        # 결합 후 높이 = w.height (그대로)
    else:                          # 둘 다 같음
        v.parent = w               # 아무 방향이나 OK
        # 결합 후 높이 = w.height + 1 (1 증가!)

왜 else일 때만 높이가 +1?

두 트리 높이가 같을 때, 한쪽이 다른 쪽 밑에 들어가면 한 단계 더 깊어짐.

같은 높이의 두 트리를 합치면 한 쪽이 다른 쪽 밑으로 들어가면서 높이 +1

3가지 경우 정리

경우 처리 결합 후 높이
v.height > w.height w.parent = v v.height (그대로)
v.height < w.height v.parent = w w.height (그대로)
v.height == w.height 아무 방향이나 +1 증가

20 Node 클래스와 make_set 구현

Python 
class Node:
    def __init__(self, key):
        self.key = key           # 노드의 값
        self.parent = self      # 부모 = 자기 자신 (루트)
        self.rank = 0            # 높이 추적용 (초기값 0)

def make_set(x):
    return Node(x)              # 새 노드 생성해서 반환

rank가 뭔지?

rank = 트리 높이의 상한선

실제 height와 살짝 다른 개념. "이 트리의 높이는 최대 rank 정도다"라는 상한선 역할.

  • 단원소 트리는 rank = 0 (높이 0)
  • union할 때만 갱신, find 호출은 rank 안 바꿈
  • 나중에 배울 path compression 같은 최적화에서 실제 높이가 줄어도 rank는 그대로 → 그래서 "rank"라고 부름 (정확한 높이 ≠ rank)

지금은 일단 "높이 추적용 변수"로 이해하면 충분.

사용 예시

Python 
# 5개의 단원소 집합 생성
a = make_set(1)
b = make_set(2)
c = make_set(3)
d = make_set(4)
e = make_set(5)

초기 상태 시각화

make_set 5번 실행 후 초기 상태

21 find 의사코드

Python 
def find(x):
    while x.parent != x:    # parent가 자신이면 루트
        x = x.parent          # 부모를 따라 올라감
    return x                 # 루트 노드 반환

동작 방식

  1. x에서 시작
  2. x.parent가 자기 자신(x)이면 → x는 루트 → 반환
  3. 아니면 x를 x.parent로 갱신하고 반복
왜 while문?
얼마나 올라가야 하는지 모르니까. 루트(parent == self)에 도달할 때까지 반복.
find(x) = O(h) 최악의 경우 트리 높이만큼 올라감

22 union 의사코드 (rank 사용)

Python 
def union(x, y):
    v, w = find(x), find(y)        # 각자의 루트 찾기 — O(h)
    
    if v.rank > w.rank:           # v가 더 높으면
        v, w = w, v                # v와 w 자리 바꿈 (트릭!)
    
    # 여기서부터 w는 항상 rank가 큰 (또는 같은) 쪽
    v.parent = w                   # v를 w 밑에 달기
    
    if v.rank == w.rank:          # 둘 rank가 같았다면
        w.rank += 1                # 합친 후 높이 +1

코드 트릭 — v, w 자리 바꾸기

왜 if/elif/else가 아니라 swap 하나로?

v.rank > w.rank이면 v, w 자리만 바꿔놓음. 그러면 이후 코드에서 항상 w가 rank 큰 쪽이라 가정 가능. 코드가 간결해짐.

의사코드와 실제 동작 매칭

원래 경우 swap 후 실행되는 코드 결과
v.rank > w.rank (swap) → w가 큰 쪽 v.parent = w 큰 거 밑에 작은 거 ✓
v.rank < w.rank (그대로) v.parent = w 큰 거 밑에 작은 거 ✓
v.rank == w.rank (그대로) v.parent = w
w.rank += 1		 아무 쪽이나 + 높이 +1 ✓

23 실행 예제 — 단계별 union

위에서 만든 a, b, c, d, e 5개 노드로 union을 차례로 실행해봅니다.

Step 1 — union(a, b)

실행 과정
  • v = find(a) = a, w = find(b) = b
  • v.rank = 0, w.rank = 0 → 같음 (swap 안 함)
  • a.parent = b → a가 b 밑으로
  • 같았으므로 → b.rank += 1 → b.rank = 1
union(a, b) 후 — a가 b 밑으로, b.rank=1

Step 2 — union(a, c)

실행 과정
  • v = find(a) = b (a의 루트), w = find(c) = c
  • v.rank = 1, w.rank = 0 → v > w → swap!
  • swap 후: v = c, w = b (이제 w가 큰 쪽)
  • v.parent = w → c.parent = b (c가 b 밑으로)
  • rank가 달랐으므로 rank 변화 없음 → b.rank = 1 그대로
union(a, c) 후 — c가 b 밑으로, rank 그대로

Step 3 — union(d, e)

실행 과정
  • v = find(d) = d, w = find(e) = e
  • v.rank = 0, w.rank = 0 → 같음 (swap 안 함)
  • d.parent = e → d가 e 밑으로
  • 같았으므로 → e.rank += 1 → e.rank = 1
union(d, e) 후 — d가 e 밑으로, e.rank=1

Step 4 — union(c, d) ★ 핵심 케이스

실행 과정
  • v = find(c) = b (c의 루트), w = find(d) = e (d의 루트)
  • v.rank = 1, w.rank = 1 → 같음 (swap 안 함)
  • v.parent = w → b.parent = e (b가 e 밑으로)
  • 같았으므로 → e.rank += 1 → e.rank = 2
중요 관찰
union(c, d)는 c, d 자체를 합치는 게 아니라 c가 속한 트리(루트 b)와 d가 속한 트리(루트 e)를 합치는 거예요. find가 먼저 호출되어 루트를 찾는 이유.
union(c, d) 후 — b가 e 밑으로, e.rank=2. 모든 노드가 e 아래 하나의 트리

전체 진행 요약

단계 실행 변화 이후 rank
1 union(a, b) a → b b.rank = 1
2 union(a, c) c → b (find로 a→b 따라감) b.rank = 1 (그대로)
3 union(d, e) d → e e.rank = 1
4 union(c, d) b → e (두 트리 합침) e.rank = 2
관찰
  • rank가 다를 때는 단순히 작은 게 큰 것 밑으로 → rank 변화 없음
  • rank가 같을 때만 +1 증가 → 신중하게 높이 관리
  • 5개 노드를 다 합쳤는데 최종 높이가 2 → 매우 균형 잡힘

24 높이 분석 — h = O(log n)

이 union 방식으로 트리 높이가 어떻게 되는지 분석해봅시다. 연산이 O(h)이니까 높이가 진짜 중요해요.

핵심 관찰

언제 높이가 변하나?

union 알고리즘에서 높이가 +1 되는 경우는 딱 하나: v.rank == w.rank일 때.

즉 같은 rank의 두 트리를 합칠 때만 높이가 증가합니다.

이 사실에서 한 가지 직관이 나옵니다:

노드 수가 (대략) 2배가 될 때 높이가 +1 증가

왜냐하면 같은 rank의 두 트리를 합칠 때 노드 수가 정확히 2배가 되니까. 이걸 수학적으로 정리해봅시다.

Nh 정의

정의
Nh = 높이가 h인 union-find 트리의 최소 노드 개수

케이스 분석

h = 0인 경우

N0 = 1 단일 노드 (자신을 가리킴)

h = 1인 경우

N1 = 2 단일 노드 두 개를 union → 높이 1, 노드 2개
왜 3이 아니라 2?

"높이 1짜리는 자식이 1개일 수도 있고 2개일 수도 있는데, 왜 최소가 2개?"라고 헷갈릴 수 있어요.

Nh는 최소 노드 수니까, 가장 적은 케이스를 봅니다. 자식 1개짜리(노드 총 2개)가 가장 적음.

참고: union by rank로는 노드 3개짜리 직선(a→b→c)은 만들 수 없어요. 단독 노드(rank 0)는 항상 rank 1 트리 밑에 직접 붙으므로 높이가 늘지 않음.

h = 2인 경우

높이 2인 트리는 어떻게 만들어지나? 높이 1인 두 트리를 union하면 됩니다 (rank가 같아서 +1).

N2 = 4 N1인 두 트리(각 2개) 합치면 4개

점화식 유도

일반화

높이 h인 트리는 높이 h-1인 두 트리를 union해서 만들어짐 (rank가 같아야 높이가 +1).

노드 수를 최소화하려면 두 트리가 각각 Nh-1일 때:

Nh = 2 · Nh-1 노드 수 두 배씩 증가

일반항 풀기

전개
Nh = 2 · Nh-1
= 2 · 2 · Nh-2
= 2 · 2 · 2 · Nh-3
= ... = 2h · N0

N0 = 1이므로:

Nh = 2h

n에 대한 부등식

전체 노드 수 n은 적어도 Nh 이상이어야 함 (Nh가 최소이므로):

유도 과정
Nh ≤ n
2h ≤ n

양변에 log₂ 씌우기 (단조증가, 부등호 방향 유지):

log2 2h ≤ log2 n
h · log2 2 ≤ log2 n
h ≤ log2 n
결론
h ≤ log2 n  ⟹  h = O(log n)
증명 흐름 정리
  1. 같은 rank의 두 트리 union일 때만 높이 +1
  2. 이때 노드 수도 정확히 2배
  3. 최소 노드 수: Nh = 2·Nh-1 = 2h
  4. 2h ≤ n → h ≤ log₂n
  5. ∴ h = O(log n)

25 최종 시간복잡도

이제 §24의 결과 h = O(log n)을 union과 find에 적용해봅시다.

find(x)
find(x) = O(h) = O(log n)
union(x, y)
union(x, y) = O(h) = O(log n)

방법 1과 최종 비교

연산 방법 1 (연결 리스트) 방법 2 (트리 + by rank)
make-set O(1) O(1)
find O(n) O(log n) ✓
union O(n) O(log n) ✓
달성!
우리가 처음 세운 목표(find와 union이 O(log n))를 달성 ✓

Union-Find의 의의

정리
  • Union-Find는 집합(set) 연산에 특화된 자료구조
  • 이런 연산이 빠르게 일어나야 한다는 게 목표
  • 방법 2(트리 + union by rank)로 O(h)로 표현 가능
  • 높이 분석으로 h = O(log n) 증명
  • 방법 1의 O(n) 대비 훨씬 좋아짐 ★
더 나아가면?
Union-Find는 사실 한 번 더 최적화 가능. Path Compression(경로 압축)을 추가하면 거의 O(1) 수준까지 갈 수 있어요 (정확히는 inverse Ackermann 함수). 다음 시간에 다룰 가능성.

27 오늘 꼭 기억할 것

시험 포인트
  1. 치환 규칙: 2-노드 → 1레벨(black), 3/4-노드 → 2레벨(black+red)
  2. 레드블랙 worst case: 모두 3-노드일 때 h'이 최대
  3. 로그 밑 변환 공식: logab = logcb / logca
  4. log₂3의 범위: 1 < log₂3 < 2 (≈ 1.585)
  5. 레드블랙 개선된 상계: h' ≤ 1.26·log₂n (기존 2·log₂n보다 타이트)
  6. 왜 h를 줄이려 하나?: 트리 연산 시간 = O(h), 상계 작을수록 좋음
  7. Union-Find: 집합 연산 특화 자료구조 (= Disjoint Set)
  8. 3개 핵심 연산: make-set(x), find(x), union(x, y)
  9. 방법 1 (연결 리스트): find/union = O(n) → 안 좋음
  10. ★ 방법 2 (트리):
    • 각 집합 = 하나의 트리
    • 노드는 부모 링크만 (자식 X)
    • 루트는 자기 자신을 가리킴
    • 같은 트리 = 같은 집합
  11. find(x): parent 따라 루트까지 → O(h)
  12. ★ Union by Rank:
    • 높이 낮은 트리 → 높은 트리 밑에
    • v.rank > w.rank: w를 v 밑에
    • v.rank < w.rank: v를 w 밑에
    • v.rank == w.rank: 아무 쪽이나 + rank +1
  13. Node 클래스: key, parent(=self), rank(=0)
  14. rank: 트리 높이의 상한선
  15. union 코드 트릭: swap으로 w를 항상 큰 쪽으로 만들기
  16. ★ 높이 변화 조건: rank 같을 때만 +1 (그 외는 그대로)
  17. ★ 핵심 관찰: 노드 수 2배 될 때마다 높이 +1
  18. Nh 정의: 높이 h인 union-find 트리의 최소 노드 수
    • N0 = 1 (단일 노드)
    • N1 = 2 (두 단일 노드 union)
    • N2 = 4 (N1 둘 union)
  19. 점화식: Nh = 2·Nh-1 → Nh = 2h
  20. ★ 높이 증명:
    • 2h ≤ n (Nh는 최소)
    • 양변 log₂ → h ≤ log₂n
    • ∴ h = O(log n)
  21. 최종 시간복잡도: find = union = O(log n) → 목표 달성!
  22. 학기 트리 정리:
    • BST → AVL (엄격) / 레드블랙 (느슨)
    • 2-3-4 트리 (이진 X, 레드블랙과 1:1)
    • Union-Find (탐색 트리 아님, 집합 연산용)
    • 모두 균형 잡으면 O(log n)
