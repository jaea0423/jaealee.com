그래프 — 자료구조의 끝판왕

가장 일반적이고 복잡한 자료구조의 시작

01 수업 시작 — 중간고사 리마인드

참고

수업 도입부에 교수님이 중간고사 문제 풀이를 다뤄주셨음. 이미 끝난 시험이라 기말고사 범위에는 해당하지 않음.

다만 나중에 복습할 때 참고할 수 있도록 "이날 중간고사 풀이가 있었다"는 사실만 기록.

중간고사 ↔ 기말고사 관계
  • 중간고사 풀이는 이미 본 문제 점검용
  • 기말고사는 중간 이후 내용 (균형 트리, 2-3-4, Union-Find, 그래프) 중심
  • 오늘부터 본격적으로 그래프 시작

02 그래프란?

그래프 (Graph)는 가장 복잡하고 일반적인 자료구조라고 할 수 있습니다.

왜 "가장 일반적"인가?

지금까지 배운 자료구조들을 떠올려보면:

  • 배열, 리스트 — 한 줄로 나열
  • 트리 — 부모-자식 계층 구조 (분기는 있지만 순환 X)
  • 그래프 — 아무 노드끼리든 자유롭게 연결 가능 (순환도 OK)
연결 학습 — 이전 자료구조와의 관계
  • 리스트는 그래프의 특수 케이스 (일자형)
  • 트리도 그래프의 특수 케이스 (순환 없는 연결 그래프)
  • 그래프는 이 모든 것을 포괄하는 가장 큰 개념

현실에서의 그래프

  • 지도 — 도시(노드)와 도로(연결)
  • SNS — 사람(노드)과 친구 관계(연결)
  • 웹 — 페이지(노드)와 하이퍼링크(연결)
  • 회로도, 분자 구조, 추천 시스템 등 거의 모든 분야

03 그래프의 정의 — G = (V, E)

그래프 G의 수학적 정의
G = (V, E)

G는 Graph의 첫 글자에서 따온 것. 그래프는 두 개의 집합 V와 E로 정의됩니다.

구성 요소

V — Vertex (꼭짓점, 노드)

노드들의 집합. 그래프에서 "점"에 해당.

V = { 꼭짓점들의 집합 }

한국어로는 꼭짓점, 정점, 노드 등 다양하게 부름

E — Edge (모서리, 링크)

꼭짓점들을 연결하는 선들의 집합. 그래프에서 "선"에 해당.

E = { (u, v) | u, v ∈ V }

각 모서리는 두 꼭짓점의 쌍 (u, v)로 표현

두 집합으로 그래프 표현
그래프를 정의하려면 "어떤 노드가 있는지"(V)와 "어떤 노드들이 연결되어 있는지"(E) 두 가지만 알면 됨.

04 예시 1 — 추상 그래프

6개의 꼭짓점이 있는 간단한 그래프를 봅시다.

6개의 꼭짓점과 6개의 모서리로 이루어진 그래프

이 그래프의 V와 E

집합 표기 
# 꼭짓점들의 집합
V = {1, 2, 3, 4, 5, 6}

# 모서리들의 집합 — 연결된 꼭짓점 쌍
E = {(1,2), (1,5), (2,5), (2,3), (5,4), (4,6)}

# 그래프 = V와 E의 쌍
G = (V, E)

관찰 포인트

  • |V| = 6 — 꼭짓점 개수
  • |E| = 6 — 모서리 개수
  • 꼭짓점 3은 2와만 연결됨
  • 꼭짓점 6은 4와만 연결됨
  • 1, 2, 5는 서로 모두 연결되어 삼각형 형태 (사이클)
모서리 표기 약속
  • (u, v) — 일반적으로 무방향 모서리 표현. (1,2)와 (2,1)은 같음
  • 방향이 있는 그래프(유향 그래프)에서는 (u, v)와 (v, u)가 다름
  • 이번 시간은 일단 무방향 그래프 기준

05 예시 2 — 도시 거리 그래프

그래프가 실제로 어디에 쓰이는지 보여주는 예시. 도시 간 거리를 그래프로 표현해봅시다.

도시 그래프

도시(노드)와 거리(가중치) — 숫자는 km 단위 가정

이 그래프의 V, E

집합 표기 
# 꼭짓점들 — 5개 도시
V = {"서울", "춘천", "대전", "원주", "수원"}

# 모서리들 — 도로 연결 (가중치 포함)
# (도시1, 도시2, 거리)
E = {("서울", "춘천", 70),
     ("서울", "수원", 30),
     ("서울", "원주", 110),
     ("춘천", "원주", 90),
     ("수원", "원주", 80),
     ("원주", "대전", 120)}

그래프로 풀 수 있는 문제 ★

실용적인 질문들

서울 → 원주 가는 가장 짧은 거리는?

  • 직접 경로: 서울 → 원주 = 110
  • 경유 경로 1: 서울 → 수원 → 원주 = 30 + 80 = 110
  • 경유 경로 2: 서울 → 춘천 → 원주 = 70 + 90 = 160
  • 최단 경로: 110 (두 가지 방법 모두 가능)

그래프 알고리즘의 가치

시험 포인트

이런 문제들을 그래프 → 알고리즘으로 풀어낼 수 있음. 시험에 꼭 나올 부분.

  • 최단 경로 문제 (다익스트라 등)
  • 최소 신장 트리 (MST)
  • 그래프 탐색 (BFS, DFS)
  • 네트워크 흐름 등

앞으로 이런 알고리즘들을 배울 예정.

왜 그래프가 강력한가

현실 문제 → 그래프 변환
현실의 많은 문제를 "노드와 연결"로 모델링하면 그래프가 됨. 그러면 이미 만들어진 그래프 알고리즘으로 풀 수 있음.
  • 지도 → 최단 경로 (네비게이션)
  • SNS → 친구 추천
  • 회로 → 최소 비용 설계

06 그래프 표현법 — 두 가지 방법

그래프를 종이 위에 노드와 선으로 그리는 건 시각적으로 좋지만, 컴퓨터 안에서는 어떻게 저장할까요? 두 가지 대표적인 방법이 있습니다.

방법 1 — 인접 행렬 (Adjacency Matrix)

V × V 크기의 2차원 표로 표현. 각 칸은 두 노드가 연결되었는지(1) 아닌지(0)를 저장.

방법 2 — 인접 리스트 (Adjacency List)

각 노드마다 이웃 노드 목록을 따로 저장. 노드 개수만큼 리스트가 있고 각 리스트에 이웃들이 들어감.

미리 보기
  • 인접 행렬: 간단함, 메모리 많이 씀 (V² 공간)
  • 인접 리스트: 메모리 효율적, 구현 살짝 복잡

상세 비교는 인접 리스트 배운 다음에.

07 인접 행렬 (Adjacency Matrix)

정의

인접 행렬은 V × V 크기의 정사각 행렬. 행과 열이 모두 꼭짓점을 의미.

각 칸의 의미

A[i][j]의 값
  • 1: 노드 i와 노드 j가 연결되어 있음 (모서리 있음)
  • 0: 연결 안 됨
  • A[i][i] = 1: 약속 (자기 자신은 항상 1로 채움)
주대각 성분 = 1 약속

교수님께서 주대각 성분(A[i][i])을 모두 1로 둔다고 약속하셨음. 일반 교과서에서는 0으로 두기도 하지만 이번 수업에서는 1로 통일.

  • self-loop(자기 자신으로 가는 모서리)가 있다는 뜻 아님
  • 실제 그래프 그림에는 자기 자신으로 가는 선 없음
  • 단순히 약속/관례로 1로 채움
  • 시험에서도 약속대로 1로 쓰기

예제 — 그래프를 인접 행렬로 변환

다음과 같은 그래프가 주어졌을 때 인접 행렬을 만들어봅시다. V = {1, 2, 3, 4, 5, 6}이고 7개의 모서리가 있어요.

변환할 그래프 — 6개 노드, 7개 모서리

모서리 정리

그래프에서 연결된 노드 쌍을 모두 적어봅니다:

집합 표기 
V = {1, 2, 3, 4, 5, 6}

E = {(1,2), (1,5), (2,3), (2,5),
     (3,4), (4,5), (4,6)}

# |V| = 6, |E| = 7

인접 행렬 만들기

이제 6×6 행렬을 만듭니다. 채우는 규칙:

  1. 주대각 성분 A[i][i]는 모두 1로 채움 (약속)
  2. 각 모서리 (u, v)에 대해 A[u][v] = A[v][u] = 1
  3. 나머지는 모두 0

완성된 인접 행렬:

123456
1 110010
2 111010
3 011100
4 001111
5 110110
6 000101

한 행씩 검증

  • 1행: 자기 자신(1) + 이웃 2, 5 → A[1][1]=1, A[1][2]=1, A[1][5]=1
  • 2행: 자기 자신(2) + 이웃 1, 3, 5 → A[2][1]=1, A[2][2]=1, A[2][3]=1, A[2][5]=1
  • 3행: 자기 자신(3) + 이웃 2, 4
  • 4행: 자기 자신(4) + 이웃 3, 5, 6
  • 5행: 자기 자신(5) + 이웃 1, 2, 4
  • 6행: 자기 자신(6) + 이웃 4

메모리 사용률 분석 ★

교수님 강조

행렬 안에 1이 몇 개 있고, 전체 칸은 몇 개인지 세어보면 메모리 효율을 확인할 수 있음.

1의 개수 세기

채워진 1을 모두 세보면:

  • 주대각 1 (약속): 6개 (A[1][1] ~ A[6][6])
  • 모서리에 의한 1: 모서리가 7개인데, 무방향이라 (u,v)와 (v,u) 둘 다 → 14개
  • 총합: 6 + 14 = 20개

전체 칸 수

n² = 6² = 36 행렬의 총 메모리 칸 수

사용률

메모리 사용률
20 / 36 ≈ 55.6%

전체 36칸 중 20칸이 1로 채워짐. 나머지 16칸은 0으로 비어있는 셈.

희소 그래프에서 문제

이 예제는 모서리가 비교적 많은 편이라 사용률이 55%. 하지만 모서리가 적은 희소 그래프(sparse graph)의 경우:

  • 예: 노드 1000개, 모서리 100개
  • 전체 칸: 1000² = 100만 칸
  • 채워진 1: 약 200개 (모서리 양방향) + 1000개 (주대각) = 약 1200개
  • 사용률: 0.12% — 99.88%가 0으로 낭비

이래서 다음에 배울 인접 리스트가 등장.

가중치가 있다면?

지난 시간 도시 그래프처럼 모서리에 가중치(거리, 비용 등)가 있는 경우:

1 대신 가중치 값을 넣으면 됨.

예시

지난 시간 도시 그래프(서울-춘천 70km, 서울-수원 30km 등)를 인접 행렬로 표현하면:

서울춘천수원원주대전
서울 07030110∞
춘천 700∞90∞
수원 30∞080∞
원주 11090800120
대전 ∞∞∞1200
가중치 행렬 규칙
  • 연결됨: 1 대신 가중치(거리)를 저장
  • 연결 안 됨: 0 또는 ∞(무한대)로 표시. 최단 경로 알고리즘에서는 ∞가 더 편함
  • 주대각: 자기 자신까지의 거리는 보통 0 (다른 표기도 가능)

인접 행렬의 특징

특징 설명
대칭성 무방향 그래프면 A[i][j] = A[j][i] → 대각선 기준 대칭
대각선 약속: A[i][i] = 1 (self-loop 아님, 관례)
크기 V × V = n² 공간
가중치 1 대신 가중치 값 (∞로 비연결 표시)
연결 확인 두 노드의 연결 여부 = O(1)
이웃 찾기 한 노드의 모든 이웃 = O(V) (한 행 훑기)
대칭성 활용
무방향 그래프에서는 대각선 위쪽(또는 아래쪽)만 저장해도 됨. 메모리를 절반으로 줄일 수 있음.

08 인접 리스트 (Adjacency List)

정의

인접 리스트는 각 노드마다 이웃 목록을 연결 리스트로 저장하는 방식.

기본 구조

두 부분으로 구성됨:

① 배열 (헤더 부분)

노드 개수만큼의 칸이 있는 배열. 각 칸은 해당 노드의 이웃 연결 리스트의 시작 지점을 가리킴.

② 연결 리스트 (이웃 목록)

각 노드의 이웃들이 연결 리스트로 줄줄이 연결됨. 마지막 노드는 공집합(∅, None)을 가리킴.

  • 각 노드는 두 칸으로 구성: [데이터 | 다음 포인터]
  • 이웃 노드의 순서는 상관없음

같은 그래프를 인접 리스트로

§7에서 본 6노드 그래프를 인접 리스트로 표현해봅시다. 주대각 약속(자기 자신도 포함)도 인접 행렬과 일관되게 반영.

인접 리스트 — 좌측 배열에서 각 인덱스가 해당 노드의 이웃 연결 리스트를 가리킴

각 리스트 정리

인덱스 연결 리스트 의미
1 (1,1) → (1,2) → (1,5) → ∅ 1의 이웃: 1(자기), 2, 5
2 (2,1) → (2,2) → (2,3) → (2,5) → ∅ 2의 이웃: 1, 2(자기), 3, 5
3 (3,2) → (3,3) → (3,4) → ∅ 3의 이웃: 2, 3(자기), 4
4 (4,3) → (4,4) → (4,5) → (4,6) → ∅ 4의 이웃: 3, 4(자기), 5, 6
5 (5,1) → (5,2) → (5,4) → (5,5) → ∅ 5의 이웃: 1, 2, 4, 5(자기)
6 (6,4) → (6,6) → ∅ 6의 이웃: 4, 6(자기)
노드 표기 (a, b)의 의미

(a, b)는 "a에서 b로 가는 모서리"라는 뜻. 즉 인덱스 a의 리스트에 있는 (a, b)는 a의 이웃이 b다는 의미.

왼쪽 칸에 from(자기 노드), 오른쪽 칸에 to(이웃)를 적어두면 모서리 정보가 명확해짐.

인접 행렬과 비교

같은 그래프, 다른 표현
  • 인접 행렬: V × V = 36칸 고정 사용
  • 인접 리스트: 모서리 수에 비례해서만 메모리 사용
  • 둘 다 정보는 동일하지만 저장 방식과 효율이 다름

09 방향 그래프 예시

이번에는 방향이 있는 그래프를 살펴봅시다. 모서리에 화살표 방향이 있어요.

방향 그래프 (Directed Graph)
  • 모서리 (u, v): u → v 방향으로만 갈 수 있음
  • (u, v) ≠ (v, u) — 두 방향이 별개
  • 인접 행렬은 비대칭일 수 있음 (이전 무방향과 차이)

예시 그래프

V = {1, 2, 3, 4}이고 모서리 5개:

집합 표기 
V = {1, 2, 3, 4}

E = {(1,2), (2,4), (3,1), (3,2), (4,3)}

# 각 (u, v)는 u에서 v로 가는 방향

그래프 그림

방향 그래프 — 화살표 방향대로만 이동 가능

경로 따라가기 확인

  • 1 → 2 → 4 → 3 → 1 → ... (사이클이 있음)
  • 3 → 2 → 4 → 3 (또 다른 사이클)
  • 1에서 3으로 직접 가는 모서리는 없음 (단방향이라)

① 인접 행렬로 표현

방향이 있으므로 A[u][v] = 1은 "u에서 v로 가는 모서리가 있다"는 뜻. 비대칭이 됨.

채우는 규칙:

  • 주대각 A[i][i] = 1 (약속)
  • 각 모서리 (u, v)에 대해 A[u][v] = 1만. (A[v][u]는 별개)
행\열 1234
1 1100
2 0101
3 1110
4 0011
행과 열 구분 (방향 그래프에서 헷갈리지 않게)
  • 행 = from (출발 노드)
  • 열 = to (도착 노드)
  • A[u][v] = "u에서 v로 가는 모서리가 있는가?"

예: A[1][2] = 1 → 1에서 2로 가는 모서리 있음. 하지만 A[2][1] = 0 → 2에서 1로 가는 모서리는 없음.

행별 검증

  • 1행 (1에서 나가는 모서리): 자기 자신(1), 1→2 → A[1][1]=1, A[1][2]=1
  • 2행 (2에서 나가는 모서리): 자기 자신(2), 2→4 → A[2][2]=1, A[2][4]=1
  • 3행 (3에서 나가는 모서리): 자기 자신(3), 3→1, 3→2 → A[3][1]=1, A[3][2]=1, A[3][3]=1
  • 4행 (4에서 나가는 모서리): 자기 자신(4), 4→3 → A[4][3]=1, A[4][4]=1

② 인접 리스트로 표현

각 노드 i의 리스트에는 i에서 갈 수 있는 노드만 들어감 (자기 자신 포함).

방향 그래프의 인접 리스트 — 각 노드에서 "나가는" 방향만 저장
무방향 vs 방향 차이
  • 무방향: 모서리 (u,v) → A[u][v]와 A[v][u] 둘 다 1, 리스트도 양쪽에 등장
  • 방향: 모서리 (u,v) → A[u][v]만 1, 리스트는 u에만 등장

10 표기 약속 — n과 m

앞으로 그래프 분석에서 계속 쓰이는 표기를 정리합니다.

표기 약속
G = (V, E),  |V| = n,  |E| = m
n — 꼭짓점 개수
|V| = n

V 집합의 원소 개수 (절댓값 기호 |·|로 표현)

m — 모서리 개수
|E| = m

E 집합의 원소 개수

예시 그래프의 n, m
위 방향 그래프에서:
  • V = {1, 2, 3, 4} → n = 4
  • E = {(1,2), (2,4), (3,1), (3,2), (4,3)} → m = 5

11 5가지 기본 연산

인접 행렬과 인접 리스트에서 각각 5가지 기본 연산이 어떻게 동작하는지, 시간복잡도가 어떻게 다른지 살펴봅시다.

① 메모리 사용량

Memory
인접 행렬 인접 리스트
O(n²) — 행렬은 무조건 n×n 칸 필요 O(n + m) — 배열 n + 노드 m개

인접 리스트가 일반적으로 메모리 효율이 좋음. 특히 m이 적은 희소 그래프에서.

② 모서리 존재 확인 — (u, v) ∈ E?

"u에서 v로 가는 모서리가 있나?"를 확인하는 연산.

Edge Exists?

인접 행렬

의사코드 
if G[u][v] == 1:    # 가중치 있으면: G[u][v] > 0
    # 모서리 있음!

배열 인덱스 접근 한 번 → O(1)

인접 리스트

의사코드 
G[u].search(v)    # u의 리스트에서 v 찾기

u의 이웃 리스트를 순회해야 함 → 최악 O(n)

③ u의 모든 인접 노드 순회

"u에 인접한 모든 v에 대해 무언가를 수행"하는 연산. 그래프 탐색의 핵심.

Traverse Neighbors

인접 행렬

의사코드 
for v in range(1, n+1):
    # G[u][v]가 1이면 작업 수행
    do with G[u][v]

무조건 n번 훑어야 함 (행렬의 한 행 전체) → O(n)

인접 리스트

의사코드 
for each edge in G[u]:
    do!!    # 실제 이웃만큼만 순회

이웃 수만큼만 순회 → O(인접 노드 개수), 최악 O(n)

두 방식의 미묘한 차이
  • 둘 다 빅오로는 O(n)으로 같음
  • 하지만 인접 행렬은 무조건 n번 (이웃이 없어도 n번 검사)
  • 인접 리스트는 최악일 때만 n번, 실제로는 이웃 개수만큼만
  • 실용적으로 인접 리스트가 조금 더 나음

④ 새 모서리 (u, v) 삽입

Insert Edge

인접 행렬

의사코드 
G[u][v] = 1    # 또는 가중치 값

한 칸만 바꾸면 됨 → O(1)

인접 리스트

의사코드 
G[u].pushfront(v)    # 리스트 앞에 추가

연결 리스트 맨 앞에 추가는 상수 시간 → O(1)

왜 pushfront?
리스트 맨 앞에 추가하면 O(1)인데, 맨 뒤에 추가하려면 끝까지 가야 해서 O(n). 순서가 중요하지 않으니까 앞에 추가하는 게 효율적.

⑤ 모서리 (u, v) 삭제

Delete Edge

인접 행렬

의사코드 
G[u][v] = 0    # 0으로 바꾸기만

한 칸만 바꾸면 됨 → O(1)

인접 리스트

의사코드 
x = G[u].search(v)    # v를 찾기 — O(n)
G[u].remove(x)        # 노드 제거 — O(1)

search가 O(n) + remove가 O(1) → O(n)

왜 인접 리스트 삭제가 느린가?

연결 리스트는 인덱스로 직접 접근 불가. 원하는 노드를 찾을 때까지 처음부터 훑어야 함 → O(n).

삭제할 노드를 찾기만 하면 제거 자체는 포인터 재연결만 하면 되니까 O(1).

12 두 방식 종합 비교

시간복잡도 비교표

연산 인접 행렬 인접 리스트 승자
① 메모리 O(n²) O(n + m) 리스트 ✓
② (u,v) ∈ E? O(1) O(n) 행렬 ✓
③ u의 인접 노드 순회 O(n) O(n) (실질 O(이웃수)) 리스트 (조금 ✓)
④ 모서리 삽입 O(1) O(1) 동일
⑤ 모서리 삭제 O(1) O(n) 행렬 ✓

어느 방식을 써야 할까?

기본 연산 종합 평가

5가지 연산 중 인접 행렬이 유리한 게 더 많음 → 기본 연산만 보면 인접 행렬이 유리
  • 인접 행렬 유리: ②모서리 확인, ⑤삭제 (둘 다 O(1))
  • 인접 리스트 유리: ①메모리, ③인접 노드 순회 (조금)
  • 동일: ④삽입

메모리 관점에서

Sparse vs Dense

메모리 사용량은 그래프의 밀도에 따라 결정됨.

  • Sparse 그래프 (텅텅 빈, m이 작음) → 인접 리스트 유리
    • O(n + m)에서 m이 작으니 메모리 적게 씀
    • 인접 행렬은 0이 대부분이라 낭비
  • Dense 그래프 (빽빽한, m이 큼) → 인접 행렬 유리
    • m이 n²에 가까워지면 인접 리스트도 O(n+m) ≈ O(n²)
    • 오히려 리스트는 포인터 오버헤드까지 있어서 손해

그래프 표현법 선택 — 정리

선택 기준
그래프 사용 시 표현법은 두 가지 기준으로 결정
기준 인접 행렬 추천 인접 리스트 추천
① 자주 쓰는 연산 모서리 확인, 삭제 위주 인접 노드 순회 위주
(BFS, DFS 등 탐색)
② 그래프 밀도 Dense (m이 n²에 가까움) Sparse (m이 작음)
앞으로 배울 알고리즘과의 관계
BFS, DFS 같은 그래프 탐색 알고리즘은 인접 노드 순회가 핵심. 그래서 인접 리스트 방식이 대부분.

13 오늘 꼭 기억할 것

시험 포인트
  1. 그래프 정의: G = (V, E)
    • V = Vertex (꼭짓점), E = Edge (모서리)
  2. 표기 약속:
    • |V| = n (꼭짓점 개수)
    • |E| = m (모서리 개수)
  3. 그래프 표현법 2가지: 인접 행렬 / 인접 리스트
  4. ★ 인접 행렬:
    • V × V 표, A[i][j] = 1: 연결됨
    • 주대각 A[i][i] = 1 (약속, self-loop 아님)
    • 무방향: 대각선 대칭 / 방향: 비대칭
    • 행 = from, 열 = to
    • 1의 총 개수 = n + 2|E| (무방향)
    • 가중치: 1 대신 가중치 값, ∞로 비연결 표시
  5. ★ 인접 리스트:
    • 배열(헤더) + 각 노드별 연결 리스트
    • 각 노드 = [from, to | next] 두 칸
    • 마지막은 ∅
    • 방향 그래프: 나가는 방향만 저장
  6. ★ 5가지 기본 연산 시간복잡도:
    • ① 메모리: 행렬 O(n²) / 리스트 O(n+m)
    • ② (u,v)∈E?: 행렬 O(1) / 리스트 O(n)
    • ③ 인접 노드 순회: 둘 다 O(n)
      • 행렬: 무조건 n번
      • 리스트: 최악 n번 (실질 O(이웃수))
      • → 리스트가 조금 더 나음
    • ④ 모서리 삽입: 행렬 O(1) / 리스트 O(1) pushfront
    • ⑤ 모서리 삭제: 행렬 O(1) / 리스트 O(n)
  7. 상황별 선택:
    • 기본 연산 종합: 인접 행렬 유리 (5개 중 2개 우세, 리스트 1.5개)
    • Sparse 그래프 (m 작음) → 인접 리스트
    • Dense 그래프 (m이 n²에 가까움) → 인접 행렬
  8. ★ 그래프 표현법 선택 2가지 기준:
    • ① 자주 쓰는 연산이 뭔지
    • ② Sparse / Dense (그래프 밀도)
  9. 방향 그래프 핵심:
    • (u, v) ≠ (v, u)
    • 모서리 (u, v) → A[u][v] = 1만 (A[v][u]는 별개)
    • 인접 리스트: u의 리스트에만 v 등장
