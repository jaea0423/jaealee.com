문제은행 — RB 높이 상계 개선 · Union-Find

레드블랙 타이트 bound(1.26·log₂n) · 로그 밑 변환 · Union-Find(Disjoint Set) · Union by Rank

이 문제집은 11주차 1차시 강의노트 범위에서 출제했습니다. 크게 두 주제: ① 레드블랙 높이 상계 개선 ② Union-Find 자료구조.
난이도·유형은 중간고사 족보 기준입니다 (객관식 · 계산 · 추적 · 빈칸 채우기 · 표 채우기 · 서술 · 코드).

Part A. 레드블랙 트리 높이 상계 개선

Q1객관식

이미 알고 있는 상계 h' ≤ 2·log₂ n이 있는데도 "더 작은(타이트한) 상계"를 구하려는 이유로 가장 알맞은 것은?

  1. 빅오 자체가 O(log n)에서 O(1)로 좋아지기 때문
  2. 연산이 O(h)라 높이 상계가 작을수록 보장이 정밀해지기 때문
  3. 상계는 값이 클수록 더 좋은 분석이기 때문
  4. 높이가 줄면 더 많은 키를 담을 수 있기 때문
✎ 나의 답안
정답 / 풀이 보기

정답: 2번

모든 트리 연산은 O(h)입니다. 상계를 2·log₂n → 1.26·log₂n으로 줄이면 빅오는 같아도(둘 다 O(log n)) 실제 상수 계수가 작아져 더 정밀한 성능 보장이 됩니다. (상계는 작을수록 좋음.)

Q2객관식

2-3-4 트리를 레드블랙으로 변환했을 때 높이 h'이 최대가 되는(worst case) 노드 구성은? (키 1개당 레벨 수 기준)

  1. 모두 2-노드
  2. 모두 3-노드
  3. 모두 4-노드
  4. 노드 구성과 무관하다
✎ 나의 답안
정답 / 풀이 보기

정답: 2번 (모두 3-노드)

키 1개당 레벨 수: 2-노드 = 1레벨/1키 = 1, 3-노드 = 2레벨/2키 = 1, 4-노드 = 2레벨/3키 ≈ 0.67. 같은 키 개수에서 변환 결과가 가장 깊어지는 건 3-노드입니다(h' = 2·log₃n ≈ 1.26·log₂n, 셋 중 최대).

Q3계산

모든 노드가 3-노드(자식 3개)인 2-3-4 트리가 있다. (1) 이 트리의 높이 h를 n에 대한 로그로 쓰고, (2) 레드블랙으로 변환한 높이 h'의 상계를 쓰시오.

✎ 나의 답안
정답 / 풀이 보기

정답: (1) h = log₃ n   (2) h' ≤ 2·log₃ n

자식이 x개씩인 균형 트리의 높이는 logₓ n이므로 3-노드 트리는 log₃ n. 3-노드 하나가 레드블랙에서 2레벨로 펼쳐지므로 모든 레벨이 2배 → h' ≤ 2·h = 2·log₃ n.

Q4빈칸 채우기

로그의 밑 변환 공식(Change of Base)을 완성하시오.

loga b = ( __________ ) / ( __________ )      (밑을 c로 변환)
✎ 나의 답안
정답 / 풀이 보기

정답: loga b = logc b / logc a

이를 써서 2·log₃ n = (2 / log₂3) · log₂ n 으로 밑을 2로 통일할 수 있습니다.

Q5계산 · 부등식

log₂ 3의 값의 범위를 부등식으로 유도하시오. (단조증가성과 log₂4 = 2를 이용)

✎ 나의 답안
정답 / 풀이 보기

정답: 1 < log₂ 3 < 2 (≈ 1.585)

2 < 3 < 4 에 단조증가 함수 log₂를 씌우면 log₂2 < log₂3 < log₂4, 즉 1 < log₂3 < 2. (log₂4 = log₂2² = 2·log₂2 = 2)

Q6계산 · 결론

(1) 개선된 레드블랙 높이 상계를 log₂ n에 대한 계수로 나타내시오. (2) n = 1,000,000(log₂n ≈ 20)일 때 기존 상계(2·log₂n)와 개선된 상계의 최악 연산 횟수를 비교하시오.

✎ 나의 답안
정답 / 풀이 보기

정답: (1) h' ≤ (2/log₂3)·log₂n ≈ 1.26·log₂n   (2) 기존 40번 → 개선 25번

2/log₂3 ≈ 2/1.585 ≈ 1.26. n=10⁶: 기존 2×20 = 40번, 개선 1.26×20 ≈ 25번. log₂3 > 1이라 2/log₂3 < 2 → 항상 기존보다 타이트합니다. (빅오는 둘 다 O(log n).)

Part B. Union-Find (Disjoint Set)

Q7빈칸 채우기

Union-Find 자료구조는 (______) Set(분리 집합)이라고도 부른다. 이 자료구조의 3가지 핵심 연산의 이름과 의미를 채우시오.

• make-set(x) : ______
• find(x) : ______
• union(x, y) : ______

✎ 나의 답안
정답 / 풀이 보기

정답: Disjoint Set

• make-set(x): x만으로 된 새 집합 {x} 생성
• find(x): x가 속한 집합의 대표(루트)를 반환 (membership 확인)
• union(x, y): x와 y가 각각 속한 두 집합을 하나로 합침 (x, y 자체가 아님)

Q8객관식

비교용으로 본 방법 1(원형 양방향 연결 리스트) 구현의 시간복잡도로 옳은 것은?

  1. make-set O(1), find O(n), union O(n)
  2. make-set O(n), find O(1), union O(1)
  3. 모두 O(log n)
  4. 모두 O(1)
✎ 나의 답안
정답 / 풀이 보기

정답: 1번

make-set은 노드 2개 연결로 O(1)이지만, find는 리스트를 전부 훑어야 해 O(n), union은 find가 지배적이라 O(n). 목표 O(log n)에 못 미쳐서 트리 방식으로 넘어갑니다.

Q9객관식 · 복수선택

Union-Find의 트리 표현(방법 2)에 대한 설명으로 옳은 것을 모두 고르시오.

  1. 각 노드는 부모를 가리키는 링크만 가진다.
  2. 루트 노드는 자기 자신을 부모로 가리킨다.
  3. 같은 루트에 속하면 같은 집합으로 본다.
  4. 한 노드의 자식 수는 최대 4개로 제한된다.
✎ 나의 답안
정답 / 풀이 보기

정답: 1, 2, 3

4번 틀림 — Union-Find 트리는 자식 수 제한이 없는 다진 트리입니다. BST 계열과 반대로 자식→부모 링크만 사용하며, 루트는 자기 자신을 가리키고, 같은 루트면 같은 집합입니다.

Q10추적

다음 트리에서(화살표 = 부모를 가리킴) find와 집합 판별을 수행하시오.

3(루트) 7(루트) / | \ / \ 1 5 2 4 6

(1) find(2)의 반환값 (2) find(6)의 반환값 (3) 2와 6은 같은 집합인가?

✎ 나의 답안
정답 / 풀이 보기

정답: (1) 3   (2) 7   (3) 아니다 (다른 집합)

find(2): 2 → 부모 3(루트) → 3 반환. find(6): 6 → 부모 7(루트) → 7 반환. find(2)=3 ≠ find(6)=7 이므로 서로 다른 집합입니다.

Q11코드 빈칸 채우기

find(x)의 의사코드를 완성하고, 시간복잡도를 쓰시오.

def find(x):
    while x.parent ____ x:   # ★ ⓐ 루트 조건
        x = ____________     # ★ ⓑ 한 단계 위로
    return x
✎ 나의 답안
정답 / 풀이 보기

정답: ⓐ !=   ⓑ x.parent / 시간복잡도 O(h)

부모가 자기 자신이 아니면(x.parent != x) 루트가 아니므로, x = x.parent로 올라갑니다. 루트까지 거리 = 트리 높이 → O(h).

Q12서술

두 트리를 union할 때 "누가 누구의 부모가 되는지"를 정하는 원칙(Union by Rank/Height)과 그 이유를 설명하시오.

✎ 나의 답안
정답 / 풀이 보기

정답 요지: 높이(rank) 낮은 트리를 높은 트리 밑에 붙인다

연산 시간이 O(h)라 높이를 낮게 유지해야 합니다. 낮은 트리를 높은 트리 밑에 붙이면 전체 높이가 그대로 유지되지만, 반대로 하면 높이가 +1 늘어납니다. 그래서 낮은 쪽을 아래로 보냅니다.

Q13표 채우기

Union by Height(rank)의 3가지 경우에 따른 처리와 결합 후 높이를 채우시오. (v, w는 두 루트)

경우처리결합 후 높이
v.rank > w.rank??
v.rank < w.rank??
v.rank == w.rank??
✎ 나의 답안
정답 / 풀이 보기
경우처리결합 후 높이
v.rank > w.rankw.parent = vv.rank (그대로)
v.rank < w.rankv.parent = ww.rank (그대로)
v.rank == w.rank아무 방향 (예: v.parent=w)+1 증가

rank가 다르면 작은 쪽을 큰 쪽 밑에 → 높이 유지. 같을 때만 한 단계 깊어져 +1.

Q14객관식

Node 클래스의 rank 필드에 대한 설명으로 옳은 것은?

  1. 언제나 트리의 정확한 높이 값과 일치한다.
  2. 높이의 상한선 역할을 하며 make_set 때 0으로 시작한다.
  3. find를 한 번 호출할 때마다 1씩 증가한다.
  4. 그 노드가 저장한 key 값과 항상 같다.
✎ 나의 답안
정답 / 풀이 보기

정답: 2번

rank는 "높이의 상한선"입니다. make_set에서 0으로 시작하고 union(같은 rank일 때만)에서 갱신됩니다. find는 rank를 바꾸지 않습니다. 경로 압축 등 최적화로 실제 높이가 rank보다 작아질 수 있어 "height"가 아닌 "rank"라 부릅니다.

Q15추적 · Union 실행

단원소 집합 a=1, b=2, c=3, d=4, e=5를 만든 뒤 Union by Rank로 다음을 차례로 실행한다.

union(a, b)
union(a, c)
union(d, e)
union(c, d)

최종 트리의 (1) 루트와 (2) 그 루트의 rank를 구하시오.

✎ 나의 답안
정답 / 풀이 보기

정답: (1) 루트 = e(=5)   (2) rank = 2

① union(a,b): 같은 rank0 → a→b, b.rank=1. ② union(a,c): find(a)=b(rank1), c(rank0) → c→b, rank 유지. ③ union(d,e): d→e, e.rank=1. ④ union(c,d): find(c)=b(rank1), find(d)=e(rank1) → 같은 rank → b→e, e.rank=2. 5개가 e 아래 하나의 트리, 최종 높이 2(매우 균형).

  2. rank가 다른 두 트리를 합칠 때
  3. rank가 같은 두 트리를 합칠 때
  4. make_set을 호출할 때

rank가 같은 두 트리를 합칠 때만 한 단계 깊어져 +1. 이때 노드 수는 정확히 2배가 됩니다 → "노드 수가 2배 될 때마다 높이 +1"이라는 핵심 관찰로 이어집니다.

Q17계산 · 증명

높이 h인 Union-Find 트리의 최소 노드 수를 Nh라 하자. (N₀ = 1) (1) 점화식을 세우고 (2) 일반항을 구한 뒤 (3) 높이 h의 상한을 n으로 나타내시오.

✎ 나의 답안
정답 / 풀이 보기

정답: (1) Nh = 2·Nh−1   (2) Nh = 2h   (3) h ≤ log₂ n

높이 h 트리는 높이 h−1인 두 트리(rank 같음)를 합쳐 만들어지므로 최소 노드는 Nh = 2·Nh−1 = 2h·N₀ = 2h. 전체 노드 n ≥ Nh = 2h → 양변 log₂ → h ≤ log₂ n = O(log n).

Q19객관식 · 복수선택

한 학기 동안 배운 트리들의 분류이다. 탐색 트리(Search Tree)에 해당하는 것을 모두 고르시오.

  1. BST / AVL / 레드블랙 트리
  2. 2-3-4 트리
  3. Union-Find (Disjoint Set)
  4. 위 모두 탐색 트리이다
✎ 나의 답안
정답 / 풀이 보기

정답: 1, 2

BST·AVL·레드블랙·2-3-4는 키 탐색을 위한 탐색 트리입니다. Union-Find는 집합 연산에 특화된 자료구조로, 부모 링크만 쓰며 탐색 트리가 아닙니다. 다만 다섯 가지 모두 핵심 연산이 O(log n)으로 동작합니다.
