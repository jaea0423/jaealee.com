레드-블랙 트리 — 정의 · 증명 · 삽입

실무에서 가장 많이 쓰이는 균형 BST의 모든 것

01 레드-블랙 트리란?

레드-블랙 트리 (Red-Black Tree)는 가장 유명하고 실무에서 많이 쓰이는 균형 이진 탐색 트리 (Self-balancing BST)입니다.

각 노드를 레드 또는 블랙으로 칠하고, 색깔에 대한 몇 가지 규칙으로 트리의 균형을 자동 유지합니다.

"AVL이 균형 BST 아니었나?" — 좋은 의문

맞습니다. AVL도 균형 BST가 맞고, 둘 다 O(log n)을 보장해요. 다만 균형을 잡는 방식이 달라서 상황에 따라 어느 쪽이 더 유리한지 갈립니다.

AVL 트리

엄격한 균형 (높이차 ≤ 1)

  • 탐색이 더 빠름
  • 삽입/삭제 시 회전 자주
  • 읽기 위주에 유리

레드-블랙 트리

느슨한 균형 (색 규칙으로만)

  • 삽입/삭제 효율적
  • 탐색 약간 느림
  • 쓰기 잦은 곳에 유리
실무 사용처
Java TreeMap, TreeSet / C++ STL std::map, std::set / Linux 커널 스케줄러(CFS) / DB 인덱스. "균형 BST 쓴다"고 하면 보통 레드블랙입니다.

02 레드블랙 트리 예시

블랙 노드
레드 노드
None / Null (블랙)
배열: [13, 8, 17, 1, 11, 15, 25, None, 6, None, None, None, None, 22, 27, ...]

03 None 노드의 특별한 의미

레드블랙 트리는 자식이 없어도 None / Null 노드를 명시적으로 표시합니다.
트리 종류 자식 없을 때 리프 노드 정의
BST, AVL 표시 안 함 자식이 없는 노드
레드블랙 트리 None 노드로 명시 None 노드 자체
용어 정리
  • 리프 노드 (Leaf) = None = Null = NIL
  • 내부 노드 (Internal node) = 실제 값을 가진 노드
이렇게 정의하면 모든 내부 노드가 정확히 두 자식을 갖는 형태가 되어 알고리즘이 깔끔해집니다.

04 레드블랙 트리의 5가지 조건

이 5가지를 모두 만족해야 레드블랙 트리입니다.

1
모든 노드는 레드 또는 블랙

두 가지 색 중 하나만 가능.

2
루트 노드는 항상 블랙

예시 트리에서 루트 13이 블랙.

3
리프 노드(None)는 모두 블랙

None은 정의상 항상 블랙.

4
레드 노드의 두 자식은 모두 블랙

즉, 레드가 연속으로 나올 수 없음 (블랙의 자식은 무엇이든 OK).

★
★ 임의의 노드에서 자손 리프(None)까지 가는 모든 경로의 블랙 노드 수가 같다

이 값을 블랙 높이 (Black Height)라고 부릅니다.

조건 4 + 5가 균형의 비결
  • 조건 4: 레드 연속 금지 → 레드만으로 길어질 수 없음
  • 조건 5: 모든 경로의 블랙 수 동일 → 한쪽으로 쏠릴 수 없음

05 ★ Black Height 직접 세보기

세는 규칙
  • 경로 위 블랙 노드만 셈 (레드는 안 셈)
  • 출발 노드 자신도 포함 (블랙이라면)
  • 마지막 None(리프)도 블랙이므로 포함

검증 1 — 노드 25 (블랙)

25 → 모든 리프 경로
  • 25(B) → 22(R) → None(B)   블랙 2개
  • 25(B) → 27(R) → None(B)   블랙 2개

✓ 모두 2개로 동일

검증 2 — 노드 11 (블랙)

11 → 모든 리프 경로
  • 11(B) → None(B)   블랙 2개

✓ 2개로 동일

검증 3 — 노드 6 (레드)

6 → 모든 리프 경로
  • 6(R) → None(B)   블랙 1개

✓ 6은 레드라 자기 자신은 안 셈 → 1개로 동일

검증 4 — 루트 13

13 → 모든 리프 경로 (전체 트리)
  • 13(B) → 8(R) → 1(B) → None(B)   블랙 3개
  • 13(B) → 8(R) → 1(B) → 6(R) → None(B)   블랙 3개
  • 13(B) → 8(R) → 11(B) → None(B)   블랙 3개
  • 13(B) → 17(R) → 15(B) → None(B)   블랙 3개
  • 13(B) → 17(R) → 25(B) → 22(R) → None(B)   블랙 3개
  • 13(B) → 17(R) → 25(B) → 27(R) → None(B)   블랙 3개

✓ 모두 3개. 조건 5 완벽 만족

06 h = O(log n) 증명 — 용어 정리

레드블랙 트리가 진짜 균형 BST인지 증명해봅시다. 두 가지 용어를 먼저 정의합니다.

표기 의미 비고
h(v) 노드 v의 높이 v에서 가장 깊은 리프까지 거리
bh(v) 노드 v의 블랙 높이 v에서 리프까지 경로의 블랙 노드 수
(v 자신은 제외)
bh 정의 주의
  • v는 제외하고 셈 (자기 자신은 안 셈)
  • 리프(None)는 셈에 포함
  • 조건 5에 의해 어떤 리프 경로로 가도 같은 값이 나옴
증명 로드맵
  • 사실 1: |v의 서브트리 내부노드 수| ≥ 2bh(v) − 1   (귀납법)
  • 사실 2: bh(루트) ≥ h2   (직관적)
  • 결합: n ≥ 2h/2 − 1 → h ≤ 2·log2(n+1) → h = O(log n)

07 사실 1 증명 — 귀납법

사실 1
|v의 서브트리 내부노드 수| ≥ 2bh(v) − 1

잠깐, 귀납법이 뭐였더라?

연결 학습 — 이산수학
수학적 귀납법 (Mathematical Induction)은 자연수에 대한 명제를 증명하는 방법입니다.
  1. Base case: k = 0(또는 1)일 때 성립함을 보임
  2. 가정 (귀납 가정): k일 때 성립한다고 가정
  3. 귀납 단계: k일 때 성립하면 k+1일 때도 성립함을 증명
이렇게 하면 도미노처럼 모든 자연수에 대해 성립합니다.

증명 — h(v)에 대한 귀납법

Base Case · h(v) = 0

v의 높이가 0이면 v는 None만 존재하는 경우. bh(v) = 0이고 내부노드 수도 0입니다.

0 ≥ 20 − 1 = 0 ✓ 기본 조건 성립
귀납 가정 · h(v) ≤ k

높이가 k 이하인 모든 노드 v에 대해 |서브트리| ≥ 2bh(v) − 1이 성립한다고 가정.

귀납 단계 · h(v) = k + 1

v가 높이 k+1일 때, v의 자식을 w(왼쪽), z(오른쪽)이라 하면:

  • w, z의 높이는 모두 k 이하 → 귀납 가정 적용 가능
  • |L| ≥ 2bh(w) − 1,   |R| ≥ 2bh(z) − 1
  • v의 서브트리 = L + R + (자기 자신 1개)
|v의 서브트리| ≥ (2bh(w) − 1) + (2bh(z) − 1) + 1

bh(w), bh(z)와 bh(v)의 관계

조건 5에서 도출되는 핵심 관계
  • w(또는 z)가 블랙이면: bh(w) = bh(v) − 1
  • w(또는 z)가 레드이면: bh(w) = bh(v)
어느 경우든 bh(w), bh(z) ≥ bh(v) − 1이 성립.

이 관계를 위 식에 대입:

|v의 서브트리| ≥ (2bh(v)−1 − 1) + (2bh(v)−1 − 1) + 1
= 2 · 2bh(v)−1 − 1
= 2bh(v) − 1 증명 완료 ✓

08 사실 2 증명 — 직관적

사실 2
bh(루트) ≥ h2

아이디어

루트에서 가장 깊은 리프까지 가는 경로(높이 h)를 봅시다. 이 경로 위 노드들은 레드와 블랙이 섞여 있는데, 조건 4(레드 연속 금지)에 의해 레드는 절대 연속할 수 없습니다.

경로 시각화

최악의 경우라도 레드와 블랙이 교대로 나타남 (실제로는 블랙이 더 많을 수도)

왜 bh ≥ h/2가 되나?

  • 경로 길이는 h
  • 레드는 절대 연속 불가, 블랙은 연속 가능 → 블랙이 적어도 절반 이상
  • 홀수 길이라도 결국 블랙으로 메워야 함
bh(루트) ≥ h2 조건 4 + 조건 5에 의해 직관적으로 성립

09 두 사실로 h = O(log n) 도출

Step 1 · 사실 1을 루트에 적용

전체 내부노드 수 n은 루트 r의 서브트리 크기와 같음.

n = |r의 서브트리| ≥ 2bh(r) − 1
Step 2 · 사실 2 대입

bh(r) ≥ h/2이므로 2bh(r) ≥ 2h/2.

n ≥ 2bh(r) − 1 ≥ 2h/2 − 1
Step 3 · 정리해서 h에 대해 풀기
n ≥ 2h/2 − 1
⟹   2h/2 ≤ n + 1
Step 4 · 양변에 log2 씌우기

밑 2의 로그는 증가함수 → 부등호 방향 유지.

log2(2h/2) ≤ log2(n + 1)
h2 ≤ log2(n + 1)
h ≤ 2 · log2(n + 1)
최종 결론
h ≤ 2 · log2(n + 1)  ⟹  h = O(log n)
의미
레드블랙 트리의 높이는 최악의 경우라도 2·log2(n+1) 이하로 보장됩니다. AVL은 약 1.44·log2n 정도로 더 짧지만, 레드블랙도 충분히 균형 잡힌 트리예요.

10 Insert 알고리즘 — 큰 그림

레드블랙 트리도 BST이므로 BST의 insert를 활용합니다.

알고리즘 (Algorithm) 
# 레드블랙 트리 Insert 큰 그림

1. BST의 insert 호출해서 새 노드 x 삽입
2. x의 색을 RED로 설정
3. 4가지 경우로 나누어 조정
   (조건 4, 5 만족하도록)

왜 새 노드를 RED로?

RED로 시작하는 이유
새 노드를 RED로 칠하면 조건 5(블랙 높이)는 자동으로 만족합니다 (RED는 안 세니까). 문제는 조건 4(레드 연속 금지)만 점검하면 돼요. BLACK으로 시작하면 모든 경로의 블랙 수가 깨져서 훨씬 복잡해집니다.

4가지 경우 미리보기

경우 상황 처리
a x가 루트가 됨 x를 BLACK으로
b x.parent가 BLACK 아무것도 안 함
c-1 x.parent가 RED, uncle도 RED 색 변경만
c-2 x.parent가 RED, uncle은 BLACK 회전 + 색 변경
용어 — 가족 관계
  • parent (p): 부모
  • grandparent (g): 부모의 부모 = 할아버지
  • uncle (u): 부모의 형제 = 삼촌
이후 그림에서는 g, p, u, x로 표기합니다.

11 Insert 4가지 경우

CASE a

x가 루트가 되는 경우

처음 노드 삽입했을 때만 발생. 트리가 비어있어서 x가 곧 루트.

처리 방법
x.color = BLACK 으로 바꿔주기만 하면 끝. (조건 2: 루트는 블랙)
CASE b

x.parent가 BLACK인 경우

아무것도 할 필요 없음. 새로 들어온 RED의 부모가 BLACK이라 조건 4 안 깨지고, 조건 5도 RED는 안 세니까 그대로 OK.

처리 방법
do nothing — 가장 행복한 경우.
CASE c-1

x.parent가 RED, uncle도 RED인 경우

레드가 연속됐으므로 조건 4 위반. 다행히 uncle도 RED라서 회전 없이 색 변경만으로 해결.

조정 전
→
색 변경
조정 후

조치 사항

  1. p와 u를 BLACK으로 변경 (레드 연속 해결)
  2. g를 RED로 변경

왜 조건 5는 안 깨지나?

  • p, u 기준: 자신은 안 세니까 영향 없음
  • g 기준: 모든 경로가 p나 u를 거치는데, p/u가 BLACK이 되었고 g는 RED가 되어서 결국 같은 수의 블랙을 거침
  • 다른 노드 기준: 영향 없음
주의
g가 RED가 되면서 g의 부모가 RED일 경우 또 조건 4 위반이 생길 수 있어요. 그래서 g를 새로운 x로 보고 위로 올라가며 다시 검사해야 합니다.
CASE c-2

x.parent가 RED, uncle은 BLACK인 경우

색 변경만으로 해결 안 됨. 회전이 필요. 두 하위 케이스로 나뉨.

i) g, p, x가 일직선인 경우 — 회전 1번

조정 전 (일직선)
↻
rotateRight(g)
+ 색 swap
조정 후

조치 사항

  1. g 기준 오른쪽으로 회전 (rotateRight(g))
  2. p를 BLACK으로, g를 RED로 변경 (색 swap)

회전 후 p가 새 부모가 되고, x와 g가 자식이 됩니다. p가 BLACK이 되면서 레드 연속 해결, g가 RED가 되어도 자식들(x, u)은 BLACK이라 OK.

ii) g, p, x가 꺾인 경우 — 회전 2번

x가 p의 반대쪽 자식이라 일자가 아닌 꺾인 모양. 먼저 펴서 일직선으로 만든 뒤 Case c-2 i)처럼 처리.

초기 상태 (꺾임)
↺
rotateLeft(p)
(펴기)
중간 (일직선)

이제 g, x, p가 일직선 → Case c-2 i)과 같은 방식으로 처리:

중간 상태
↻
rotateRight(g)
+ 색 swap
최종

조치 사항 (회전 2번)

  1. rotateLeft(p)로 일직선 만들기
  2. rotateRight(g) + 색 swap (Case c-2 i과 동일)

12 시간복잡도 정리

Insert 분석

단계 작업 시간 복잡도
1 BST의 insert 호출 O(h) = O(log n)
2 x를 RED로 설정 O(1)
3 4가지 경우 조정 (회전 최대 2번 + 색 변경) O(1)
결론
Insert = O(log n) + O(1) = O(log n)

Delete도 비슷한 원리로 O(log n). (자세한 구현은 다루지 않음)

AVL vs 레드블랙 — 회전 횟수 비교

연산 AVL 트리 레드블랙 트리
Search 회전 없음 (BST와 동일) 회전 없음 (BST와 동일)
Insert 최대 2회전 최대 2회전
Delete O(log n)번 rebalance 최대 3회전
전체 시간 O(log n) O(log n)
핵심 비교
둘 다 시간 복잡도는 O(log n)으로 같지만 실제 동작 비용이 다름.
  • Delete의 경우 AVL은 루트까지 연쇄적으로 rebalance해야 함
  • 레드블랙은 최대 3회전이면 끝
  • 그래서 레드블랙이 AVL보다 가볍다고 평가받음 (실무에서 더 많이 쓰는 이유)

13 오늘 꼭 기억할 것

시험 포인트
  1. 5가지 조건 외우기 — 특히 ★ 조건 5 (Black Height)
  2. None = 리프 노드 = 항상 블랙
  3. Black Height 직접 셀 줄 알아야 함 — 트리 주고 검증 문제 가능성 높음
  4. h = O(log n) 증명 흐름:
    • 사실 1: |서브트리| ≥ 2bh(v) − 1 (귀납법)
    • 사실 2: bh(루트) ≥ h/2 (직관적, 조건 4에 의해)
    • 결합: h ≤ 2·log2(n+1) → O(log n)
  5. Insert 4가지 경우:
    • a: 루트 → BLACK으로
    • b: parent BLACK → 그대로
    • c-1: uncle RED → 색 변경
    • c-2: uncle BLACK → 회전 (일직선 1번 / 꺾임 2번)
  6. 새 노드는 RED로 시작하는 이유 — 조건 5 자동 만족, 조건 4만 점검
  7. AVL vs 레드블랙: Delete의 회전 횟수가 결정적 차이 (O(log n) vs 최대 3회)
