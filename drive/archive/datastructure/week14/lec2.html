All-to-All 최단 경로 — Floyd-Warshall

한 출발점이 아니라, 모든 정점 쌍의 최단 경로를 한 번에

01 새 문제 — All-to-All 최단 경로

지난주 복습
SSSP (Single-Source Shortest Path) — 한 출발점 s에서 다른 모든 노드까지의 최단 경로. Bellman-Ford와 Dijkstra로 풀었음.

오늘의 새 문제

All-to-All Shortest Path Problem
모든 출발점에서
모든 도착점까지의 최단 경로

지난주는 출발점 s를 하나 고정하고 풀었어요. 오늘은 모든 정점 쌍 (i, j)에 대해 i → j 최단 경로를 동시에 구하는 문제.

비교

구분 SSSP (지난주) All-to-All (오늘)
출발점 1개 고정 모든 정점
결과 n개 거리 (dist 배열) n × n 거리 (행렬)
응용 내 위치에서 어디든 도시 간 거리표, 라우팅 테이블
현실 비유
  • SSSP: "우리 집에서 다른 모든 곳까지 거리"
  • All-to-All: "전국 도시 간 거리표" — 어디서 어디로든 다 적힌 그 표

02 방법 1 — 단순 반복 방식

가장 단순한 접근: SSSP 알고리즘을 모든 출발점에 대해 반복해서 돌리기.

의사코드

방법 1 — 반복 방식 
for each node s in V:                 # 노드 집합 V의 모든 정점에 대해
    Dijkstra(s)                       # 또는 Bellman-Ford(s)

시간복잡도 분석

n개 정점 각각에 대해 Dijkstra를 한 번씩 돌림.

계산
  • Dijkstra 한 번의 비용 = D
  • n번 반복 → 전체 O(n · D)
  • 지난주에 본 Dijkstra (min-heap) = O((n + m) log n)
    • m은 간선 수, 최악 m = n²
    • 따라서 D = O(n² log n)
  • 전체 = n × n² log n = O(n³ log n)
방법 1 시간복잡도
O(n · D) = O(n³ log n)
(Dijkstra 사용 시, 간선 수 최악 m = n²)
아쉬운 점
각 출발점마다 독립적으로 계산 — 중복 작업이 많음. 더 똑똑한 방법이 있어야 함.

03 방법 2 — Floyd-Warshall 알고리즘

오늘 본격적으로 배울 알고리즘 — Floyd-Warshall (플로이드-워셜). All-to-All 최단 경로를 더 우아하게 푸는 방법.

표기 약속

노드 집합

정점이 n개일 때, 노드 집합을 V = {1, 2, ..., n}으로 둡니다 (1부터 n까지 번호 매김).

P(i, j)와 d(i, j)
  • P(i, j): 노드 i → j의 최단 경로 자체 (경로상의 노드들)
  • d(i, j): 노드 i → j의 최단 경로의 길이 = |P(i, j)|

지난주의 dist[v]와 parent[v]에 해당하는 개념. dist가 d로, parent를 따라간 경로가 P로 바뀐 셈.

알고리즘이 풀어야 할 것

목표 
for i, j ∈ {1, 2, ..., n}:
    P(i, j) 계산        # 노드 i → j의 최단 경로
    d(i, j) 계산        # 노드 i → j의 최단 경로의 길이 = |P(i, j)|

모든 (i, j) 쌍에 대해 두 값을 채우는 게 목표. 결과는 n × n 표(행렬) 형태로 나옴.

출력 형태

d(i, j)를 모으면 거리 행렬 D[i][j], P(i, j)의 정보를 모으면 경로 복원용 행렬이 됨. 두 행렬을 출력하는 게 알고리즘의 결과.

이 문제를 푸는 데 걸리는 시간

시간복잡도 미리 보기
  • (i, j) 쌍이 n² 개 (n × n 표를 채워야 함)
  • 각 쌍 (i, j)에 대해 "어떤 중간 노드 k를 거치는 게 최선인가?" 후보 n개를 확인 → O(n)
  • 전체: n² × n = O(n³)
P(i, j)는 추가 비용 없나?
  • P(i, j)를 경로 전체(노드 시퀀스)로 저장하면 비용이 추가됨
  • 실제 구현에서는 중간 노드 하나만 기록(mid[i][j] = k) — 한 줄, O(1)
  • 14-1에서 parent[v] 한 줄 갱신했던 것과 같은 방식
  • 실제 경로 필요할 때 mid 배열을 재귀적으로 풀어 복원
  • 그래서 d와 P를 같이 갱신해도 시간복잡도는 그대로 O(n³)
Floyd-Warshall 시간복잡도
O(n³)
방법 1 (O(n³ log n))보다 log n 만큼 더 빠름

04 최단 경로 분해와 중간 노드 k

Floyd-Warshall의 핵심 아이디어를 잡으려면 최단 경로를 어떻게 쪼갤 수 있는지부터 봐야 합니다.

분해의 시각화

노드 i에서 j까지 가는 최단 경로를 가만히 보면, 그 중간 어딘가에 노드 k가 있을 거예요.

i → j 최단 경로를 중간 노드 k 기준으로 두 구간으로 쪼개기

★ 분해된 두 구간도 각각 최단

14-1에서 본 부분 경로 최단성이 여기서도 그대로 적용됩니다.

★ 핵심 관찰
  • i → j 최단 경로의 중간에 k가 있다면:
  • i → k 부분 경로는 i에서 k까지의 최단 경로
  • k → j 부분 경로는 k에서 j까지의 최단 경로
  • 둘 다 동시에 만족 (14-1에서 모순 논증으로 증명한 것)

분해 식

★ 최단 경로 분해 (Optimal Substructure)
SP(i, j) = SP(i, k) + SP(k, j)
d(i, j) = d(i, k) + d(k, j)
SP: Shortest Path (최단 경로) / d: 그 경로의 길이

두 식의 차이

식 의미 + 연산의 의미
SP(i, j) = SP(i, k) + SP(k, j) 경로 자체를 분해 경로 이어붙이기 (concat)
d(i, j) = d(i, k) + d(k, j) 경로 길이를 분해 숫자 더하기
왜 이 분해가 중요한가
  • 이 식이 성립한다는 건 큰 문제(i → j 최단)를 작은 문제(i → k, k → j)로 쪼갤 수 있다는 뜻
  • 알고리즘은 작은 문제들의 답을 모아서 큰 문제를 풀어나감 — 동적 계획법(DP)의 전형적 구조
  • Floyd-Warshall은 이 분해를 활용해 모든 (i, j) 쌍을 한 번에 풀어냄

05 ★ 점화식 도출 — 알고리즘의 핵심

지금까지 본 "최단 경로 분해" 아이디어를 점화식으로 만들어봅니다. 이 점화식이 Floyd-Warshall 알고리즘의 심장.

먼저 — "인덱스"가 뭔지

노드 번호 = 인덱스 = ID
  • 노드들에 1, 2, 3, ..., n으로 번호를 매김
  • 이 번호가 인덱스이자 노드 ID
  • "k = 9"는 "9번 노드"를 뜻함
  • 키/값 같은 개념이 아니라 그냥 노드를 부르는 이름표

예시로 시작 — k를 어떻게 정하나

예를 들어 노드 3에서 8까지 가는 최단 경로가 다음과 같다고 합시다:

경로: 3 → 1 → 9 → 4 → 6 → 8
★ k의 정의

경로의 중간 노드들 중에서 인덱스가 가장 큰 노드를 k로 잡음.

위 예시에서 중간 노드는 1, 9, 4, 6. 그중 가장 큰 인덱스 = 9. 그래서 k = 9.

P_k(i, j) 표기 등장

P_k(i, j) 정의

i에서 j로 가는 최단 경로 중, 중간 노드들의 인덱스가 모두 k 이하인 경로.

밑첨자 k는 "이 경로가 사용할 수 있는 중간 노드의 최대 번호"를 뜻함.

  • P_5(3, 8): 중간 노드를 {1, 2, 3, 4, 5} 중에서만 골라 만든 3→8 최단 경로
  • P_9(3, 8): 중간 노드를 {1, 2, ..., 9} 중에서 골라 만든 3→8 최단 경로
  • P_n(3, 8): 중간 노드를 모든 노드 중에서 골라 만든 3→8 최단 경로 = 진짜 최단 경로

k를 거치는 경우 분해

위 예시처럼 P_9(3, 8)이 9를 거친다고 합시다. 그러면:

9를 거치는 경우
P9(3, 8) = P8(3, 9) + P8(9, 8)

★ "중간 노드 인덱스가 8 이하"는 무슨 뜻?

여기가 사용자가 헷갈린 부분. 천천히 풀어볼게요.

왜 P_8이 되는가?
  • 전체 경로 P_9(3, 8): 중간 노드 인덱스가 모두 9 이하
  • 9에서 두 구간으로 쪼개면:
    • 3 → 9 구간: 시작 3, 끝 9. 중간 노드는 1뿐 → 1 ≤ 8 ✓
    • 9 → 8 구간: 시작 9, 끝 8. 중간 노드는 4, 6 → 모두 ≤ 8 ✓
  • ★ 핵심: 9는 분할점이라 두 구간의 중간 노드가 아님 (양 끝점)
  • 그러니 두 구간의 중간 노드 인덱스는 모두 9 미만 (≤ 8)
  • 그래서 P_8(3, 9) + P_8(9, 8)로 쓸 수 있음
왜 9가 다시 중간 노드로 안 들어가나?

최단 경로는 같은 노드를 두 번 거치지 않음 (단순 경로). 9는 이미 분할점이라 자기 자신을 또 거치는 일이 없음. 그래서 두 구간의 중간 노드 후보에서 9는 빠짐.

일반화 — k를 거치는 경우

k를 거치는 경우 일반식
Pk(i, j) = Pk−1(i, k) + Pk−1(k, j)
= "k를 지나는 i→j 최단 경로" = "i→k 최단 (중간 노드 ≤ k-1)" + "k→j 최단 (중간 노드 ≤ k-1)"

★ 잠깐 — k를 안 거치는 경우는?

중요한 부분 빠뜨림

방금까지는 "k를 거치는 경우"만 봤어요. 그런데 사실 — k를 안 거치는 게 더 짧을 수도 있어요!

예를 들어 3→8 가는 길이 두 개 있을 때:

  • 경로 A: 3 → 1 → 9 → 4 → 6 → 8 (9를 거침, 길이 18)
  • 경로 B: 3 → 2 → 5 → 8 (9를 안 거침, 길이 10)

이러면 9를 거치는 게 오히려 손해. 그러니까 알고리즘은 두 경우를 모두 비교해야 함.

두 가지 경우 정리

P_k(i, j)가 될 수 있는 두 후보
  • ① k를 안 거치는 경우: 중간 노드를 {1, ..., k-1}만 써서 i → j
    • = Pk−1(i, j)
  • ② k를 거치는 경우: i → k → j로 가서, 두 구간 각각 중간 노드를 {1, ..., k-1}만 사용
    • = Pk−1(i, k) + Pk−1(k, j)
  • 최단 경로는 둘 중 더 짧은 쪽

★★ 최종 점화식

★★ Floyd-Warshall 점화식
dk(i, j) = min ( dk−1(i, j),
                  dk−1(i, k) + dk−1(k, j) )
↑ k를 안 거침                ↑ k를 거침

최종 목표

우리가 정말 원하는 답은 — 중간 노드 제한 없는 진짜 최단 경로. 표기로 쓰면:

최종 답
Pn(i, j)   또는   dn(i, j)
k = n: 중간 노드를 {1, ..., n} 모두 쓸 수 있음 = 제한 없음
알고리즘이 풀어가는 방식
  • k = 0부터 시작 (중간 노드 없음, 직접 간선만)
  • k = 1 → 2 → 3 → ... → n으로 차례차례 늘려가며 표 갱신
  • 매 단계마다 점화식 dk(i, j) = min(..., ...)으로 모든 (i, j) 쌍 갱신
  • k = n에 도달하면 답 완성

06 Base case와 k의 진행

점화식이 있으면 작은 문제부터 큰 문제로 풀어나갈 수 있어요. 그런데 "가장 작은 문제"의 답은 어디서 시작할까? 그게 base case.

★ 점화식 다시 확인 (min 빠뜨리지 말 것)

★ 진짜 점화식은 min 포함

한 번 더 강조해서 적습니다 — 점화식에 min이 빠지면 안 됩니다. k를 거치는 게 항상 좋은 게 아니라, 안 거치는 게 더 짧을 수도 있어요.

★ Floyd-Warshall 점화식 (정정판)
dk(i, j) = min ( dk−1(i, j),
                  dk−1(i, k) + dk−1(k, j) )

d_k(i, j)의 정확한 의미

d_k(i, j)

노드 집합 {1, 2, ..., k}에 속한 노드들만 중간 노드로 거쳐서 i에서 j까지 갈 때의 최단 경로 길이(비용).

최종 목표

우리가 원하는 답
dn(i, j)
k = n: 중간 노드를 {1, 2, ..., n}에서 모두 골라 쓸 수 있음 = 제한 없음 = 진짜 최단 경로

k의 진행 방향

  • k = 0부터 시작 → 답이 완성되는 k = n까지
  • 각 단계 k에서 이전 단계 (k−1)의 답을 활용해 새 표 만듦

★ Base case — d_0(i, j)

k = 0이면 중간 노드를 쓸 수 없다는 뜻 (집합 {1, ..., 0} = 공집합). 그러니까 i에서 j로 가는 길은 직접 간선만 가능.

★ Base case d_0(i, j)
d0(i, j) = 0     if i = j (자기 자신)
d0(i, j) = w(i, j)  if (i, j) ∈ E (직접 간선 있음)
d0(i, j) = ∞     otherwise (간선 없음)

각 경우 직관적으로

경우 의미 값
i = j 출발점과 도착점이 같음 — 가만히 있으면 됨 0
(i, j) 간선 있음 i에서 j로 직접 가는 간선이 있음 → 그 간선 가중치만큼 비용 w(i, j)
그 외 중간 노드 없이는 갈 수 없음 → 도달 불가 ∞
d_0의 표는 곧 인접 행렬

d_0(i, j) 표를 다 채우면 사실상 가중치 인접 행렬과 같음. 대각선은 0, 간선 있는 칸은 가중치, 나머지는 ∞.

즉 Floyd-Warshall은 "인접 행렬에서 시작해 점점 더 멀리 갈 수 있는 길을 추가해나가는" 알고리즘이라고 볼 수 있음.

전체 흐름 요약

07 예시 그래프 + d_0 표

이제 작은 예시 그래프(노드 4개)로 알고리즘을 직접 돌려보겠습니다. k=0부터 k=4까지 진행하며 표를 채울 거예요.

d_k(i, i) = 0 — 항상 성립

자기 자신으로 가는 거리

모든 k에 대해 d_k(i, i) = 0입니다. 가만히 있으면 비용 0이니까. k 값과 무관하게 대각선은 항상 0.

예시 그래프

그래프 정보
  • 정점 4개: 1, 2, 3, 4
  • 간선 5개 (방향 + 가중치, 음수 가중치 포함):
    • 2 → 1 (가중치 4)
    • 1 → 3 (가중치 −2)
    • 3 → 4 (가중치 2)
    • 4 → 2 (가중치 −1)
    • 2 → 3 (가중치 3)
예시 그래프 — 정점 4개, 간선 5개 (음수 가중치 포함)

음수 가중치가 있어도 OK

★ Dijkstra와의 차이
  • 14-1에서 배운 Dijkstra는 음수 가중치에서 동작하지 않음
  • 그런데 Floyd-Warshall은 음수 가중치 OK
  • 단, 음수 사이클(negative cycle)이 있으면 안 됨 — 사이클을 돌수록 비용이 무한정 줄어 최단 경로가 정의 안 됨
  • 이 예시 그래프는 음수 가중치가 있지만 음수 사이클이 없어서 안전
    • 예: 사이클 1→3→4→2→1 = (−2) + 2 + (−1) + 4 = 3 (양수)

목표 — d_4(i, j) 모두 구하기

n = 4니까 최종 목표는 d_4(i, j) — 모든 (i, j) 쌍에 대한 진짜 최단 거리. 4×4 표 16칸을 다 채우는 게 결과.

진행 순서

d_0 → d_1 → d_2 → d_3 → d_4
각 단계에서 점화식으로 이전 표를 갱신
사용할 점화식

dk(i, j) = dk−1(i, k) + dk−1(k, j)

※ 보통은 이 식을 이전 값과 min으로 비교해서 더 짧은 쪽을 택함 — 하지만 수업에서 다룬 형태는 위 식이라 그대로 진행. 실제 표를 채울 때 "k 거치는 게 더 짧을 때만 갱신"이라고 생각하면 됨.

★ Base case — d_0 표

k = 0이니 중간 노드 없이 직접 간선만 사용. §6에서 본 규칙을 그대로 적용:

  • 대각선 (i = j): 0
  • 직접 간선 있음: w(i, j)
  • 없음: ∞
d_0 표 (직접 간선만)
d_0(i, j) 1 2 3 4
1 0 ∞ −2 ∞
2 4 0 3 ∞
3 ∞ ∞ 0 2
4 ∞ −1 ∞ 0
행 = 출발(i), 열 = 도착(j) — 회색 대각선이 d_k(i,i)=0, 빨간 숫자가 간선 가중치

표 검증

  • d_0(1, 3) = −2 ✓ (1→3 직접 간선 있음, 가중치 −2)
  • d_0(2, 1) = 4 ✓ (2→1 직접 간선)
  • d_0(2, 3) = 3 ✓
  • d_0(3, 4) = 2 ✓
  • d_0(4, 2) = −1 ✓
  • d_0(1, 2) = ∞ (1→2 직접 간선 없음)
  • d_0(i, i) = 0 (모든 대각선)

08 d_0 → d_3 표 갱신 과정

이제 점화식을 적용해 k=1, 2, 3까지 표를 차례차례 갱신합니다.

★ 어떤 칸이 갱신될지 미리 알 수 있을까?

★ 갱신 후보 칸 찾는 트릭

k 단계에서 갱신 가능한 칸 (i, j)는 두 조건을 모두 만족해야 함:

  • ① d_(k−1)(i, k) ≠ ∞ — i에서 k로 갈 수 있어야 함
  • ② d_(k−1)(k, j) ≠ ∞ — k에서 j로 갈 수 있어야 함

즉 "k 열에 ∞ 아닌 값이 있는 행 i" × "k 행에 ∞ 아닌 값이 있는 열 j"의 조합만 후보. 나머지 칸은 안 바뀌니 안 봐도 됨.

또 하나 — k행 자체와 k열 자체는 변화 없음. 자기 자신을 중간 경유지로 쓰는 건 의미 없으니까.

실전 팁
교수님이 "바뀐 부분만 표시"하신 게 이 방법. 한 단계마다 k 행과 k 열을 먼저 보고, ∞ 아닌 값이 있는 곳들끼리 짝지어 검사하면 효율적.

Step 1 — d_0 → d_1 (노드 1을 중간 경유로 허용)

k = 1이니 d_0의 1열과 1행을 봅니다.

  • 1열 (i → 1): d_0(2, 1) = 4만 ∞ 아님 → i = 2만 후보
  • 1행 (1 → j): d_0(1, 3) = −2만 ∞ 아님 → j = 3만 후보
  • 따라서 검사할 칸은 (i, j) = (2, 3) 하나뿐
d_1(2, 3) = min( d_0(2, 3) = 3,
                  d_0(2, 1) + d_0(1, 3) = 4 + (−2) = 2 )
= 2 ← 갱신!
d_1 표
d_1(i, j) 1 2 3 4
1 0 ∞ −2 ∞
2 4 0 2 ★ ∞
3 ∞ ∞ 0 2
4 ∞ −1 ∞ 0
★ 갱신된 칸: (2, 3) — 3 → 2 (2 → 1 → 3 경로 발견)

Step 2 — d_1 → d_2 (노드 2를 중간 경유로 허용)

k = 2이니 d_1의 2열과 2행을 봅니다.

  • 2열 (i → 2): d_1(4, 2) = −1만 ∞ 아님 → i = 4만 후보
  • 2행 (2 → j): d_1(2, 1) = 4, d_1(2, 3) = 2 ∞ 아님 → j = 1 또는 j = 3
  • 검사할 칸: (4, 1), (4, 3)
d_2(4, 1) = min( d_1(4, 1) = ∞,
                  d_1(4, 2) + d_1(2, 1) = (−1) + 4 = 3 )
= 3 ← 갱신!

d_2(4, 3) = min( d_1(4, 3) = ∞,
                  d_1(4, 2) + d_1(2, 3) = (−1) + 2 = 1 )
= 1 ← 갱신!
d_2 표
d_2(i, j) 1 2 3 4
1 0 ∞ −2 ∞
2 4 0 2 ∞
3 ∞ ∞ 0 2
4 3 ★ −1 1 ★ 0
★ 갱신: (4, 1) → 3 (4→2→1 경로), (4, 3) → 1 (4→2→3 경로)

Step 3 — d_2 → d_3 (노드 3을 중간 경유로 허용)

k = 3이니 d_2의 3열과 3행을 봅니다.

  • 3열 (i → 3): d_2(1, 3) = −2, d_2(2, 3) = 2, d_2(4, 3) = 1 → i = 1, 2, 4 후보
  • 3행 (3 → j): d_2(3, 4) = 2 → j = 4만 후보
  • 검사할 칸: (1, 4), (2, 4), (4, 4). (4, 4)는 대각선이라 0 유지.
d_3(1, 4) = min( d_2(1, 4) = ∞,
                  d_2(1, 3) + d_2(3, 4) = (−2) + 2 = 0 )
= 0 ← 갱신! (★ 음수+양수 상쇄)

d_3(2, 4) = min( d_2(2, 4) = ∞,
                  d_2(2, 3) + d_2(3, 4) = 2 + 2 = 4 )
= 4 ← 갱신!

★ d_3(1, 4) = 0이 왜 0?

음수 가중치의 효과
  • 경로: 1 → 3 → 4
  • 비용: w(1, 3) + w(3, 4) = (−2) + 2 = 0
  • 음수 −2와 양수 +2가 정확히 상쇄되어 총 비용 0
  • 현실로 치면 "내리막길과 오르막길이 정확히 같아서 시작 지점과 같은 높이로 도착" 같은 느낌
  • 음수 가중치가 있어야 가능한 결과 — 양수만 있으면 비용 0은 i=j일 때만
d_3 표
d_3(i, j) 1 2 3 4
1 0 ∞ −2 0 ★
2 4 0 2 4 ★
3 ∞ ∞ 0 2
4 3 −1 1 0
★ 갱신: (1, 4) → 0, (2, 4) → 4

09 d_3 → d_4 — 마지막 단계

n = 4니까 k = 4가 마지막. 노드 4를 중간 경유로 허용하면 알고리즘 완료.

갱신 후보 분석

k = 4이니 d_3의 4열과 4행을 봅니다.

  • 4열 (i → 4): d_3(1, 4) = 0, d_3(2, 4) = 4, d_3(3, 4) = 2 → i = 1, 2, 3 후보
  • 4행 (4 → j): d_3(4, 1) = 3, d_3(4, 2) = −1, d_3(4, 3) = 1 → j = 1, 2, 3 후보
  • 검사할 칸: (i, j) ∈ {1, 2, 3} × {1, 2, 3} (대각선 제외) → 6개

각 칸 계산

d_4(1, 2) = min( d_3(1, 2) = ∞,
                  d_3(1, 4) + d_3(4, 2) = 0 + (−1) = −1 )
= −1 ← 갱신! (1→3→4→2)

d_4(1, 3) = min( d_3(1, 3) = −2,
                  d_3(1, 4) + d_3(4, 3) = 0 + 1 = 1 )
= −2 ← 그대로 유지 (이미 더 짧음)

d_4(2, 1) = min( d_3(2, 1) = 4, d_3(2, 4) + d_3(4, 1) = 4 + 3 = 7 ) = 4 (유지)
d_4(2, 3) = min( d_3(2, 3) = 2, d_3(2, 4) + d_3(4, 3) = 4 + 1 = 5 ) = 2 (유지)

d_4(3, 1) = min( d_3(3, 1) = ∞,
                  d_3(3, 4) + d_3(4, 1) = 2 + 3 = 5 )
= 5 ← 갱신! (3→4→2→1)

d_4(3, 2) = min( d_3(3, 2) = ∞,
                  d_3(3, 4) + d_3(4, 2) = 2 + (−1) = 1 )
= 1 ← 갱신! (3→4→2)

최종 d_4 표

★ d_4 = 최종 All-to-All 최단 거리 표
d_4(i, j) 1 2 3 4

4 3 −1 1 0
★ 이번 단계 갱신: (1, 2) → −1, (3, 1) → 5, (3, 2) → 1

★ 이게 우리가 구하려고 했던 All-to-All 표

완성!

d_4(i, j) 표가 바로 알고리즘의 최종 결과. 어떤 (i, j) 쌍이든 표에서 바로 최단 거리를 읽을 수 있음.

  • d_4(1, 4) = 0 → 1에서 4까지 비용 0 (1→3→4)
  • d_4(3, 1) = 5 → 3에서 1까지 비용 5 (3→4→2→1)
  • d_4(2, 4) = 4 → 2에서 4까지 비용 4 (2→3→4)
  • ... 등등 모든 쌍의 답이 한 번에

10 오늘 꼭 기억할 것

시험 포인트
  1. All-to-All Shortest Path 문제: 모든 정점 쌍 (i, j)에 대한 최단 경로 (n×n 표)
  2. 방법 1 — 단순 반복: 모든 출발점에 대해 Dijkstra/BF 반복
    • 시간복잡도 O(n · D) = O(n³ log n) [Dijkstra 기준]
  3. ★ Floyd-Warshall: All-to-All 전용 알고리즘, 시간복잡도 O(n³)
    • 방법 1보다 log n 만큼 빠름
  4. ★ 핵심 아이디어: 최단 경로를 중간 노드 k 기준으로 분해
    • SP(i, j) = SP(i, k) + SP(k, j)
    • d(i, j) = d(i, k) + d(k, j)
    • 부분 경로도 최단 (Optimal Substructure)
  5. ★ d_k(i, j) 정의: 중간 노드를 {1, ..., k}만 쓸 수 있을 때의 i→j 최단 거리
    • k는 "사용 가능한 중간 노드의 최대 인덱스"
  6. ★★ 점화식: d_k(i, j) = d_(k−1)(i, k) + d_(k−1)(k, j)
    • k를 경유하는 경우의 비용
    • 이전 단계 (k−1) 값으로 다음 단계 (k) 계산
    • ※ 실제로는 이전 값과 min 비교 (k 안 거치는 게 더 짧을 수도)
  7. ★ Base case d_0(i, j):
    • i = j → 0 (자기 자신)
    • (i, j) 간선 있음 → w(i, j)
    • 그 외 → ∞
    • = 가중치 인접 행렬
  8. ★ d_k(i, i) = 0: 모든 k에서 대각선은 항상 0
  9. 최종 목표: d_n(i, j) — 모든 노드 다 거쳐갈 수 있는 진짜 최단 거리
  10. 진행 방향: d_0 → d_1 → d_2 → ... → d_n
    • k=0부터 한 단계씩 증가
  11. ★ 갱신 후보 칸 찾기: k 단계에서 변할 수 있는 칸 (i, j)
    • d_(k−1)(i, k) ≠ ∞ AND d_(k−1)(k, j) ≠ ∞
    • k행/k열 자체는 안 바뀜
  12. ★ 음수 가중치 처리:
    • Dijkstra는 안 됨 / Bellman-Ford와 Floyd-Warshall은 OK
    • 단, 음수 사이클이 있으면 안 됨
  13. 시간복잡도 비교 (정리):
    • BF (단일 출발): O(VE) = O(n³)
    • Dijkstra (단일 출발): O((n+E) log n) = O(n² log n)
    • Dijkstra × n번 (All-to-All): O(n³ log n)
    • Floyd-Warshall (All-to-All): O(n³)
