01 이진 탐색 트리 (BST) 복습

10주차 복습
오늘은 균형 검색 트리(Balanced Search Tree)를 복습하는 시간. 그 전에 가장 기본인 BST부터 다시 짚고 갑니다.

BST란?

이진 탐색 트리 (Binary Search Tree)는 자식이 최대 2개인 트리이며, 왼쪽 자식 < 부모 < 오른쪽 자식 규칙을 따름.

예시 트리

다음과 같은 BST를 생각해봅시다 (배열 표현: [10, 5, 17, 3, 6, 14, 20]):

루트 10, 균형 잡힌 BST (높이 2)

13 삽입해보기

이 BST에 13을 삽입해봅시다. 루트부터 시작해서 비교하며 내려갑니다.

13 삽입 경로: 10 → 17 → 14 → 14의 왼쪽 자식

삽입 과정 단계별

  1. 10과 비교: 13 > 10 → 오른쪽으로 이동
  2. 17과 비교: 13 < 17 → 왼쪽으로 이동
  3. 14와 비교: 13 < 14 → 왼쪽으로 이동
  4. 14의 왼쪽이 비어있음 → 여기에 13 삽입

BST 핵심 연산

시간 복잡도
삽입 / 삭제 / 탐색 = O(h)

h는 트리의 높이. 모든 연산이 루트에서 리프까지 한 번 내려가는 구조라서 높이에 비례.

그런데 문제가 있음 — 높이 문제

BST의 약점

BST는 균형이 보장되지 않음. 운이 나쁘면 한쪽으로 치우친 트리가 만들어질 수 있음.

  • 최선: 균형 잡히면 h = O(log n)
  • 최악: 한 줄로 치우치면 h = O(n) — 연결 리스트와 다를 게 없음

치우친 BST 예시

만약 정렬된 순서(1, 2, 3, 4, 5)대로 삽입하면:

치우친 BST — 연결 리스트와 같음, 탐색이 O(n)

해결책 — 균형 검색 트리

균형 검색 트리 등장

높이를 줄이기 위해 만들어진 게 균형 검색 트리(Balanced Search Tree).

  • 삽입/삭제 시 트리가 자동으로 균형을 유지
  • h = O(log n) 보장
  • 대표 종류: AVL 트리, 레드블랙 트리, 2-3-4 트리
앞으로 복습할 내용
이번 시간엔 균형 검색 트리들을 차례로 다시 짚어봅니다. 기말고사 대비 정리 시간.

02 "균형이 좋다"는 게 무슨 뜻?

그럼 트리의 "균형이 좋다"는 게 정확히 뭘까요? 두 트리를 비교해봅시다.

균형 좋음 — Balanced

노드 7개, 높이 2 — Balanced (균형 좋음)

균형 나쁨 — Not Balanced

노드 개수는 같지만 한쪽으로 쏠려서 높이가 훨씬 큼

비교 정리

구분 균형 좋음 (첫 번째) 균형 나쁨 (두 번째)
노드 개수 7개 7개
높이 2 6
탐색 최악 3번 비교 7번 비교

균형의 정의

균형이 좋다 ≡
노드 수에 비해 높이가 낮은 트리

왜 균형이 중요한가

핵심 논리
  • 검색 트리의 모든 작업(검색, 삽입, 삭제)은 O(h)
  • 높이 h가 작아야 작업이 빠름
  • 따라서 트리의 균형이 꼭 필요
연결 학습 — 이전 단원
11주차에서 레드블랙 트리 높이 상계 분석할 때도 "왜 h를 줄이려고 하나?" 질문이 나왔었음. 같은 논리.

03 균형 검색 트리의 분류

균형 검색 트리는 크게 두 종류로 나뉩니다.

① 균형 이진 탐색 트리 (Balanced BST)

특징
  • 자식이 최대 2개 (이진 트리)
  • 검색, 삽입, 삭제 모두 O(log n) 보장
  • 대표 종류:
    • AVL 트리 — 서브트리 높이 차 ≤ 1
    • 레드블랙 트리 (Red-Black Tree) — 색 규칙으로 균형

② 균형 k진 트리 (Balanced k-ary Tree)

특징
  • 자식이 2개 이상 가능 (k진 트리)
  • 검색, 삽입, 삭제 모두 O(log n) 보장
  • 대표 종류:
    • 2-3 트리 — 자식 2 또는 3개
    • 2-3-4 트리 — 자식 2, 3, 또는 4개
    • B-트리 (B-Tree) — 자식 수가 더 큰 범위 (DB, 파일 시스템에서 사용)

분류 한눈에

분류 자식 수 대표 종류 시간복잡도
균형 이진 탐색 트리 최대 2 AVL, 레드블랙 O(log n)
균형 k진 트리 2 ~ k 2-3, 2-3-4, B-트리 O(log n)
공통점

모든 균형 검색 트리는 O(log n)을 보장. 핵심은 트리의 모양에 상관없이 높이를 log n 수준으로 유지한다는 것.

연결 학습 — 이전 단원
  • 11주차에 다룬 트리들이 모두 여기 해당:
    • AVL, 레드블랙 → 균형 BST
    • 2-3-4 → 균형 k진 트리
  • B-트리는 이번 시간에 새로 다룰 가능성

04 AVL 트리 — 정의

AVL 트리
모든 노드에 대해 왼쪽 서브트리와 오른쪽 서브트리의 높이 차이가 최대 1인 이진 탐색 트리

일반 형태

임의의 노드 t에서 왼쪽 서브트리(t.left)와 오른쪽 서브트리(t.right)의 높이 차이가 1 이하면 OK.

AVL 트리 — 모든 노드 t에서 좌/우 서브트리 높이 차 ≤ 1

조건 한 줄 정리

AVL 조건

모든 노드에 대해:

|height(t.left) − height(t.right)| ≤ 1

한 노드라도 이 조건 위반하면 AVL 트리가 아님.

연결 학습 — 이름의 유래
AVL은 발명자 Adelson-Velsky and Landis 세 사람 이름의 약자. 1962년에 발표된 최초의 자가 균형 BST.

05 AVL이 아닌 경우 + 단순 회전으로 수선

균형이 무너지는 순간

AVL 트리도 삽입/삭제하다 보면 균형이 무너질 수 있음. 이때 회전(rotation)으로 수선(repair).

위반 사례 ① — 왼쪽이 무거운 경우

다음 트리를 봅시다. 노드 10이 문제예요.

노드 10에서 왼쪽 높이 0, 오른쪽 높이 2 → 차이 2 (위반!)
왜 위반인가
  • 노드 10에서 왼쪽 서브트리: 없음 (높이 −1 또는 0)
  • 노드 10에서 오른쪽 서브트리: 20 → 17, 30 (높이 2)
  • 차이가 2 → AVL 조건 위반

위반 사례 ② — 또 다른 형태

이번엔 더 큰 트리에서 위반이 일어난 경우.

40 기준은 균형이지만, 노드 10에서 위반 (왼쪽 1, 오른쪽 3)
위반 위치 확인
  • 루트 40: 양쪽 다 높이 3 → OK
  • 노드 10: 왼쪽(7)은 높이 0, 오른쪽(20→17,30→35)은 높이 2 → 차이 2 (위반!)

수선 — 회전 1회로 해결

사례 ①의 수선
회전 1회로 균형 회복. 노드 20을 위로 올리고 10을 왼쪽으로 내림.
사례 ① 수선 후 — 20을 위로 올림, 좌우 균형 회복
사례 ②의 수선
이것도 회전 1회로 해결. 같은 원리.
사례 ② 수선 후 — 마찬가지로 회전 1회로 균형 회복

회전이란?

회전 (Rotation)
  • BST 규칙(왼<부<오)을 유지하면서 트리 모양만 바꾸는 연산
  • 높이가 너무 큰 쪽의 노드를 위로 올리고, 반대쪽으로 균형 옮김
  • O(1) 시간에 가능 (포인터 몇 개만 바꾸면 됨)
  • 좌회전, 우회전 두 가지가 기본 (대칭 관계)
사례 ①, ②는 LL 타입 → 우회전

두 사례 모두 위반 노드 기준 왼쪽-왼쪽이 가장 깊은 LL 타입. 단순 우회전 1회로 수선.

왼쪽 자식을 위로 끌어올리는 회전 = 우회전.

불균형 유형 미리보기
AVL 위반은 총 4가지 유형으로 분류됨 — LL, LR, RR, RL. 각 유형마다 해결 방법이 다름. 다음 섹션에서 자세히.

06 LR / RL 타입 — 이중 회전 필요

단순 회전이 안 통하는 경우

위반 형태가 꺾인 모양이면 회전 1회로는 해결 불가. 두 번 회전해야 함.

위반 사례 ③ — LR 타입

다음 트리는 노드 40에서 위반. 왼쪽이 더 무거운데, 왼쪽 자식의 오른쪽 서브트리가 더 무거운 형태 — 이걸 LR 타입이라고 합니다.

노드 40 위반 — 왼쪽 무거움 + 그 안에서 오른쪽(37)이 더 무거움 (LR 타입)
LR 타입이란?
  • L: 위반 노드 기준 왼쪽 서브트리가 더 무거움
  • R: 그 왼쪽 자식 안에서 오른쪽 서브트리가 더 무거움
  • => "왼쪽-오른쪽" 꺾인 형태

이 경우 단순 회전(좌회전 or 우회전) 1회로는 해결 안 됨.

해결 방법 — 좌회전 → 우회전 (이중 회전)

Step 1: t.left 기준 좌회전 (LL 타입으로 변환)

위반 노드 t의 왼쪽 자식(t.left) 기준 좌회전을 해서 LL 타입으로 바꿈. 일시적으로는 더 불균형해 보이지만 문제 없음.

Step 1 — 왼쪽 서브트리에 좌회전. 37이 위로, 일시적 불균형 발생 (문제 없음)

Step 2: t 기준 우회전 (LL 타입 수선)

이제 LL 타입이 됐으니 위반 노드 t 기준 우회전으로 수선.

Step 2 — 전체에 우회전. 37이 새 루트가 되어 균형 회복!

이중 회전 정리

LR 타입 수선
① t.left 기준 좌회전 → LL 타입으로 변환
② t 기준 우회전 → 균형 회복
왜 두 번 회전?
  • 단순 회전은 LL/RR(꺾이지 않은 직선 형태)에만 통함
  • LR/RL(꺾인 형태)은 먼저 꺾임을 펴줘야 함 → 1차 회전
  • 그 다음에 일반적인 회전으로 마무리 → 2차 회전
  • RL 타입은 대칭으로 처리 (우회전 → 좌회전)

07 4가지 불균형 유형 종합 정리

AVL 트리의 불균형은 가장 깊은 위치가 어디냐에 따라 4가지로 분류됩니다 (t는 위반 노드).

분류 기준

4가지 불균형 유형
  • LL: t.left.left가 가장 깊음
  • LR: t.left.right가 가장 깊음
  • RR: t.right.right가 가장 깊음
  • RL: t.right.left가 가장 깊음

각 유형 시각화

4가지 불균형 유형 — 위는 위반 상태, 아래는 수선 후 (파란 삼각형이 가장 깊은 서브트리)
Claude가 정리한 부분
위 4가지 유형 비교 다이어그램은 교수님 슬라이드의 4장을 한 화면에 모은 것. 시험 대비 빠르게 보기용으로 만들었음.

해결 방법 한눈에 보기

유형 가장 깊은 위치 해결 방법 회전 횟수
LL t.left.left t 기준 우회전 1회
LR t.left.right t.left 기준 좌회전 → t 기준 우회전 2회
RR t.right.right t 기준 좌회전 1회
RL t.right.left t.right 기준 우회전 → t 기준 좌회전 2회

핵심 패턴

암기 팁
  • 이름과 회전 방향이 반대:
    • LL → 오른쪽으로 회전 (우회전)
    • RR → 왼쪽으로 회전 (좌회전)
  • 꺾인 유형은 펴고 시작:
    • LR → 자식을 좌회전해서 LL로 만들고 → 우회전
    • RL → 자식을 우회전해서 RR로 만들고 → 좌회전
  • 일반 절차: 불균형 노드 찾기 → 가장 깊은 위치 확인 → 4가지 중 어디인지 판단 → 해당 회전 수행

08 balanceAVL 알고리즘 — 의사코드

지금까지 본 4가지 유형(LL, LR, RR, RL)을 코드로 정리하면 다음과 같습니다.

메인 함수 — balanceAVL(t, type)

위반 노드 t와 유형(type)을 받아서 적절한 회전을 수행:

의사코드 
def balanceAVL(t, type):
    switch type:
        case LL:                          # t.left.left가 깊음
            우회전(t)                    # t 기준 우회전
        
        case LR:                          # t.left.right가 깊음
            좌회전(t.left)               # 먼저 t.left 기준 좌회전
            balanceAVL(t, LL)             # 이제 LL이 됐으니 재귀 호출
        
        case RR:                          # t.right.right가 깊음
            좌회전(t)                    # t 기준 좌회전
        
        case RL:                          # t.right.left가 깊음
            우회전(t.right)              # 먼저 t.right 기준 우회전
            balanceAVL(t, RR)             # 이제 RR이 됐으니 재귀 호출

코드 읽기 포인트

우아한 재귀 구조
  • LL, RR은 단순 회전 1회로 끝
  • LR, RL은 한 번 회전한 다음 자기 자신을 재귀 호출
  • LR → LL로 변환 후 LL 케이스로 위임
  • RL → RR로 변환 후 RR 케이스로 위임
  • 코드 중복 없이 깔끔하게 4가지 케이스 처리

LR 케이스 시각화

LR 케이스의 동작을 다시 한 번 살펴봅시다 (Type LR → Type LL → 균형):

LR 타입 처리 — ① 좌회전(t.left)로 LL 변환 → ② 우회전(t)로 균형 회복 (재귀로 LL 케이스 호출)

좌회전(t) — 의사코드

t를 회전의 중심으로 하여 왼쪽으로 회전. t.right가 위로 올라오고 t가 그 왼쪽으로 내려감.

의사코드 
def 좌회전(t):                                          # t: 회전의 중심 노드
    RChild ← t.right                                  # t의 오른쪽 자식
    RLChild ← RChild.left                             # 그 노드의 왼쪽 자식 (옮길 서브트리)
    
    RChild.left ← t                                   # RChild가 위로, t가 RChild의 왼쪽 자식이 됨
    t.right ← RLChild                                 # t의 새 오른쪽 자식은 원래 RChild의 왼쪽
    
    # 높이 갱신 (자식부터 갱신 후 부모)
    RChild.height ← max(RChild.right.height, RChild.left.height) + 1
    t.height ← max(t.right.height, t.left.height) + 1

동작 단계별

  1. RChild를 변수에 저장 (t의 오른쪽 자식 = 위로 올라갈 노드)
  2. RLChild를 변수에 저장 (RChild의 왼쪽 자식 = 자리 옮길 서브트리)
  3. RChild.left = t: t를 RChild의 왼쪽 자식으로 (RChild가 새 부모)
  4. t.right = RLChild: t의 오른쪽 자리에 RLChild를 옮김
  5. 두 노드의 height 재계산 — 반드시 t(아래쪽) 먼저, 그 다음 RChild
왜 RLChild를 옮기나?
  • RChild가 위로 올라가면 그 왼쪽 자리가 비게 됨 → 새로 t가 그 자리에 들어감
  • 원래 RChild의 왼쪽 자식(RLChild)은 갈 곳이 필요 → t의 오른쪽 자리로
  • BST 규칙(t < RLChild < RChild)이 자연스럽게 유지됨

우회전(t) — 의사코드

좌회전과 완전 대칭. t.left가 위로 올라오고 t가 그 오른쪽으로 내려감.

의사코드 
def 우회전(t):                                          # t: 회전의 중심 노드
    LChild ← t.left                                   # t의 왼쪽 자식
    LRChild ← LChild.right                            # 그 노드의 오른쪽 자식 (옮길 서브트리)
    
    LChild.right ← t                                  # LChild가 위로, t가 LChild의 오른쪽 자식이 됨
    t.left ← LRChild                                  # t의 새 왼쪽 자식은 원래 LChild의 오른쪽
    
    # 높이 갱신 (자식부터 갱신 후 부모)
    LChild.height ← max(LChild.right.height, LChild.left.height) + 1
    t.height ← max(t.right.height, t.left.height) + 1

좌회전 vs 우회전 — 대칭 관계

단계 좌회전(t) 우회전(t)
저장 1 RChild ← t.right LChild ← t.left
저장 2 RLChild ← RChild.left LRChild ← LChild.right
위로 올림 RChild.left ← t LChild.right ← t
중간 서브트리 이동 t.right ← RLChild t.left ← LRChild
높이 갱신 t 먼저, 그 다음 위로 올라간 노드
핵심 포인트
  • 두 회전 모두 4번의 포인터 조작으로 끝 → O(1)
  • BST 규칙(왼<부<오)이 자동으로 유지됨
  • 높이 갱신은 아래(t)부터 위로 — 자식 높이가 먼저 확정되어야 부모 높이를 계산할 수 있기 때문

전체 시간복잡도

balanceAVL 전체 분석
  • 각 회전은 O(1)
  • balanceAVL은 최대 2번 회전 (LR, RL의 경우)
  • 전체 균형 회복: O(1)
  • 삽입/삭제 자체는 O(h) — 균형 BST이므로 O(log n)
  • 총 비용: O(log n) ✓

09 연쇄 회전 (Cascade Rotation)

한 번의 회전으로 끝나지 않는 경우

회전을 1번 했는데, 그 위쪽 서브트리에서 새로운 불균형이 생길 수 있음. 그러면 또 회전. 또 위쪽에서 깨짐. → 계속 위로 올라가며 회전.

특히 삭제 연산에서 자주 발생.

책 예시 — 큰 AVL 트리에서 연쇄 회전

다음은 큰 AVL 트리에서 연쇄적으로 좌회전이 3번 일어나는 과정.

그림 11-18: 초기 상태 (RR 타입 위반)

그림 11-18: 노드 20에서 RR 타입 균형 깨짐 (23 쪽 서브트리가 더 깊음)

그림 11-19: 1차 좌회전 후 (20 기준)

20 기준 좌회전 → 23이 위로 올라가고 20이 23의 왼쪽 자식이 됨. 그런데 이제 30 노드에서 새로 균형이 깨짐.

그림 11-19: 20 좌회전 후 — 23이 위로, 20이 23 왼쪽으로. 이제 30 노드에서 새로 균형 깨짐

그림 11-20: 2차 좌회전 후 (30 기준)

이제 30 기준 좌회전 → 40이 위로 올라가고 30이 40의 왼쪽 자식이 됨. 이번엔 60 노드에서 또 균형 깨짐.

그림 11-20: 30 좌회전 후 — 40이 위로. 이제 60 노드에서 또 균형 깨짐

그림 11-21: 3차 좌회전 후 (60 기준) — 균형 해결

마지막으로 60 기준 좌회전 → 78이 새 루트가 되고 60이 78의 왼쪽 자식. 드디어 모든 균형 회복.

그림 11-21: 60 좌회전 후 — 78이 새 루트, 모든 노드 균형 회복

연쇄 회전 정리

핵심 메시지
  • 회전 한 번이 끝이 아닐 수 있음
  • 하위에서 회전하면 그 트리의 높이가 변할 수 있고 → 상위에서 새 불균형 발생
  • 특히 삭제 연산에서 자주 발생
  • 최악의 경우: 루트까지 올라가며 회전
  • 경로의 길이가 최대 h = O(log n) → 최대 O(log n)번 회전 가능

전체 비용

연산 회전 횟수 시간복잡도
삽입 최대 2회 (이중 회전 포함) O(log n)
삭제 최대 O(log n)회 (연쇄) O(log n)
삽입 vs 삭제 차이
  • 삽입: 한 번 균형 회복하면 전체 트리 균형 보장 → 회전 1~2회로 끝
  • 삭제: 균형 회복해도 트리 높이가 줄어들 수 있어 상위에서 또 깨질 수 있음 → 연쇄 회전 가능
  • 하지만 한 번의 회전은 O(1), 경로 길이가 O(log n)이므로 전체는 여전히 O(log n)
연결 학습 — 책 그림 11-18 ~ 11-21
교과서의 그림 11-18(초기 위반) → 11-19(1차 회전) → 11-20(2차 회전) → 11-21(3차 회전 후 균형)을 차례로 보여준 예시. 좌회전이 3번 연쇄적으로 일어남.

10 레드-블랙 트리 — 기본 약속

11주차 복습
레드-블랙 트리는 11주차에서 다룬 적이 있음. 이번엔 기말고사 대비로 정의부터 다시 명확히 정리.

핵심 약속

레드-블랙 트리의 기본 약속 3가지
  • ① 모든 null 자리에 리프 노드를 둠
  • ② RB 트리에서 "리프 노드"는 이 null 리프를 의미
  • ③ 모든 노드는 레드 또는 블랙의 색을 가짐

null 리프란?

일반 BST에서는 자식이 없으면 그냥 NULL 포인터로 두지만, RB 트리에서는 모든 NULL 자리마다 "리프 노드"라는 가짜 노드를 둡니다.

일반 BST는 NULL을 그냥 두지만, RB 트리는 모든 NULL 자리에 NIL 리프 노드를 둠
왜 NIL 리프를 두나?
  • 코드 작성이 쉬워짐 (NULL 체크를 일일이 안 해도 됨)
  • "모든 리프는 블랙"이라는 규칙을 통일적으로 표현 가능
  • 경로 분석할 때 모든 경로가 NIL 리프에서 끝남 → 길이 비교가 쉬움

"리프 노드"의 의미 주의

용어 혼동 주의
  • 일반 트리에서 "리프 노드" = 자식이 없는 실제 데이터 노드
  • RB 트리에서 "리프 노드" = NIL 노드 (빈 자리)
  • RB 트리에서는 실제 데이터를 담은 노드는 "내부 노드"라고 부름

노드 색깔

모든 노드(NIL 포함)는 레드 또는 블랙의 색을 가짐.

노드 색깔 표기 — 검은색은 블랙, 빨간색은 레드

11 레드-블랙 트리의 4가지 특성

RB 트리의 4가지 규칙
① 루트는 블랙
② 모든 리프 노드(NIL)는 블랙
③ 루트~리프 경로에 레드 노드 두 개 연속 출현 X
④ 루트~리프 경로의 블랙 노드 수가 모두 같음

특성 ① — 루트는 블랙

규칙
트리의 루트 노드는 항상 블랙이어야 함.

특성 ② — 모든 리프(NIL)는 블랙

규칙
위에서 본 NIL 노드들은 모두 블랙으로 간주. 자동으로 만족됨 (NIL은 정의상 블랙).

특성 ③ — 레드 두 개 연속 X

규칙
부모-자식 관계에서 레드-레드가 나란히 오면 안 됨. 즉, 레드 노드의 자식은 반드시 블랙.
레드 노드의 자식은 반드시 블랙이어야 함

특성 ④ — 블랙 높이 일정

규칙

루트에서 임의의 리프(NIL)에 이르는 경로에서, 만나는 블랙 노드의 수가 모두 같음. 이걸 블랙 높이(black-height)라고 부름.

루트(30)에서 어느 NIL로 가든 만나는 블랙 노드 수 = 3 (자기 자신 포함하지 않거나 일관되게 셈)

왜 이 규칙들이 균형을 만드는가

핵심 통찰
  • 특성 ④로 인해 블랙 노드만 보면 균형 잡힌 트리
  • 특성 ③(레드 연속 금지)로 인해 전체 높이도 너무 커질 수 없음
  • 증명: 최악의 경우에도 h ≤ 2·log₂n (11주차에 다룬 결과)
  • 더 타이트하게는 h ≤ 1.26·log₂n까지 분석 가능

AVL vs 레드-블랙 비교

특징 AVL 트리 레드-블랙 트리
균형 조건 모든 노드 좌우 높이 차 ≤ 1 4가지 색깔 규칙
균형의 엄격함 매우 엄격 (h ≤ 1.44·log₂n) 느슨함 (h ≤ 2·log₂n)
탐색 속도 빠름 (더 균형) 보통
삽입/삭제 시 회전 많음 적음 (실용적)
실무 사용 탐색 위주 일반적 (C++ std::map, Java TreeMap 등)

13 RB 트리 삽입 절차

RB 트리에 새 노드를 삽입할 때 어떻게 해야 4가지 특성을 유지할 수 있을까?

표기 약속

변수 명명
  • x — 새로 삽입하는 노드
  • p — x의 부모 노드

기본 삽입 절차 3단계

삽입 절차
  1. 일반 BST처럼 삽입 — 루트부터 키 비교하며 빈 자리 찾아 삽입
  2. 삽입 노드 x를 레드로 칠함
  3. x의 좌우에 NIL 리프 달기

왜 레드로 칠하나?

레드를 선택하는 이유
  • 만약 블랙으로 칠하면: 특성 ④ (블랙 높이 일정) 위반 가능성 큼 — 한 경로의 블랙 수가 1 늘어남
  • 레드로 칠하면 특성 ④는 안 깨짐 (블랙 개수 안 변함)
  • 최악의 경우 특성 ③ (레드 연속 X)만 깨질 수 있음 → 처리하기 쉬움

왜 x는 무조건 리프?

BST의 특성

BST 삽입은 루트부터 시작해서 키 값에 따라 왼/오로 내려가다가 빈 자리에 들어감.

따라서 새 노드는 항상 리프 위치에 들어감. 그 좌우 자식 자리가 비어 있으니 NIL을 달아주면 됨.

삽입 시각화

삽입 절차 — p(부모) 옆 null 자리에 레드 x를 삽입, x의 좌우엔 새 null 리프

삽입 직후 상황 분석

삽입 후 두 가지 경우로 나뉨:

Case A — p가 블랙
  • x(레드) + p(블랙) → 레드 연속 X (특성 ③ OK)
  • 블랙 개수 변화 없음 (특성 ④ OK)
  • 아무 처리 필요 없음 — 끝!
Case B — p가 레드
  • x(레드) + p(레드) → 레드 연속 발생 (특성 ③ 위반)
  • 수선 작업 필요
  • 구체적인 수선 방법은 p의 형제(uncle) 색깔에 따라 다름

가능한 모양 4가지

삽입 직후 가능한 모양은 다음 4가지뿐. p는 블랙, x는 레드, NIL은 검정 사각형으로 표시됨.

p가 블랙일 때 가능한 4가지 모양 — x의 위치(왼/오) × 형제의 종류(NIL/레드)

4가지 모양 정리

모양 x의 위치 형제 노드 상태
모양 1 p의 왼쪽 NIL 특성 모두 만족 ✓
모양 2 p의 왼쪽 레드 특성 모두 만족 ✓
모양 3 p의 오른쪽 NIL 특성 모두 만족 ✓
모양 4 p의 오른쪽 레드 특성 모두 만족 ✓
핵심 관찰

p가 블랙이면 이 4가지 모양 모두에서 RB 트리 특성이 그대로 유지됨. 추가 작업 필요 없음.

p가 레드인 경우(레드 연속 위반)는 다음에 배울 수선 작업이 필요.

14 p가 레드일 때 — 수선 작업

문제 상황

x를 레드로 삽입했는데 부모 p도 레드라면 — 특성 ③ (레드 연속 X) 위반. 수선 필요.

표기 확장

변수 명명 확장
  • x — 삽입 노드 (레드)
  • p — x의 부모 (레드, 위반의 원인)
  • p² — p의 부모 (x의 조부모)
  • p³ — p²의 부모 (x의 증조부모)
  • s — p의 형제 (sibling) = p²의 다른 자식

가능한 모양 2가지

p가 레드일 때 x의 위치 기준 2가지 경우:

p가 레드일 때 가능한 모양 2가지 (x의 위치만 다름)

분기 기준 — p의 형제 s

수선 방법은 s의 색깔에 따라 결정
  • Case 1: s가 레드 → 색깔만 바꿔서 해결 (재귀 가능)
  • Case 2: s가 블랙 → 회전 + 색깔 변경

Case 1 — s가 레드

p와 s 둘 다 레드인 상황. 색깔만 바꿔서 처리.

Case 1 처리
  1. p와 s를 블랙으로 변경
  2. p²를 레드로 변경
  3. p³ 확인:
    • p³가 블랙 → 끝!
    • p³가 레드 → p²가 새 x가 되어 재귀적으로 같은 과정 반복
Case 1 — p, s를 블랙으로 / p²를 레드로 변경 (회전 없음)
왜 재귀가 필요한가?
  • p²를 레드로 바꾸면 그 위쪽에서 또 레드 연속이 생길 수 있음
  • 만약 p³가 레드이면 → p² + p³ 가 레드 연속 → 위반!
  • 이때 p²를 새 x로 보고 같은 절차 반복
  • 최악의 경우 루트까지 올라가지만, 루트는 무조건 블랙으로 끝내면 됨

Case 2 — s가 블랙

s가 블랙이거나 NIL인 경우. 회전과 색깔 변경으로 한 번에 해결.

Case 2는 x의 위치에 따라 다시 2가지로 나뉨:

Case 2-1: x가 p의 오른쪽 자식 → Case 2-2로 변환

x가 꺾인 위치(p의 오른쪽)에 있으면 먼저 펴줘야 함. p 기준 좌회전으로 x를 위로 올려 Case 2-2 형태로 만듦.

Case 2-1 — p 기준 좌회전으로 x를 위로 올려 Case 2-2 형태로 만듦 (아직 끝 X)

Case 2-2: x가 p의 왼쪽 자식 → 우회전 + 색 교환

x가 펴진 위치(p의 왼쪽)에 있으면 한 번에 해결. p² 기준 우회전 + p와 p²의 색 교환.

Case 2-2 — p² 기준 우회전 후 p와 p²의 색 교환. 수선 끝!

Case 정리

Case 조건 처리 방법 추가 작업
Case 1 s가 레드 p, s를 블랙으로 / p²를 레드로 p³ 확인 (재귀 가능)
Case 2-1 s가 블랙 / x가 p 오른쪽 p 기준 좌회전 Case 2-2로 이어감
Case 2-2 s가 블랙 / x가 p 왼쪽 p² 기준 우회전 + p와 p² 색 교환 끝 ✓
핵심 비교 — Case 1 vs Case 2
  • Case 1: 회전 없음, 색깔만 바꿈, 위로 전파 가능 (재귀)
  • Case 2: 회전 1~2회 + 색 교환, 한 번에 끝
  • 비유: Case 1은 "임시방편이라 또 검사 필요", Case 2는 "완전 해결"
대칭 케이스

지금까지는 p가 p²의 왼쪽 자식인 경우만 다뤘음. p가 오른쪽 자식이면 모든 방향이 반대 (좌↔우, 좌회전↔우회전). 원리는 동일.

전체 삽입 시간복잡도

시간 분석
  • BST 삽입: O(log n) (트리 높이에 비례)
  • Case 2: 회전 + 색 교환 = O(1)
  • Case 1: 색깔만 바꾸고 재귀 — 최대 루트까지 O(log n)번 반복
  • 총합: O(log n)

15 AVL vs RB 시간복잡도 — 정리

오늘 배운 두 균형 검색 트리의 시간복잡도를 정리합니다.

핵심 결론

시간복잡도
AVL 트리, 레드블랙 트리, 2-3-4 트리 모두
검색 / 삽입 / 삭제 = O(log n)

왜 O(log n)?

두 단계 논리
  1. 트리 높이 h의 최대값 = O(log n)
    • 균형 이진 탐색 트리이기 때문에 보장됨
    • AVL: h ≤ 1.44·log₂n
    • RB: h ≤ 2·log₂n (더 타이트하게는 1.26·log₂n)
  2. 모든 연산은 한 번 내려가는 경로 비례
    • BST 검색/삽입/삭제 = O(h)
    • h = O(log n)이므로 결과적으로 O(log n)

추가 작업이 있어도 여전히 O(log n)인 이유

추가 연산의 비용

균형 유지를 위해 추가로 하는 작업도 O(log n)을 넘지 않음:

  • AVL: 회전 연산 추가 — 각 회전 O(1) × 최대 O(log n)번(연쇄) = O(log n)
  • RB: 회전 + 색깔 조정 — 각 작업 O(1) × 최대 O(log n)번(Case 1 재귀) = O(log n)
  • 2-3-4: 노드 분할/병합 — 각 작업 O(1) × 최대 O(log n)번 = O(log n)

BST 작업 O(log n) + 추가 작업 O(log n) = 전체 O(log n)

한 줄 요약

균형 검색 트리 — AVL, RB(이진 계열), 2-3-4(k진 계열) — 모두 O(log n) 보장. 균형 유지를 위한 추가 작업이 있지만 그 비용도 O(log n)을 넘지 않음.

실무 선택 기준
  • 둘 다 시간복잡도는 같음 (O(log n))
  • 다만 상수 차이 + 회전 빈도 차이
  • AVL: 더 엄격한 균형 → 검색 빠름, 회전 많음 → 검색 위주 작업에 유리
  • RB: 느슨한 균형 → 회전 적음 → 삽입/삭제 빈번한 경우에 유리
  • 실무에서는 RB가 더 많이 쓰임 (C++ map, Java TreeMap 등)

16 오늘 꼭 기억할 것

시험 포인트
  1. BST: 작업 모두 O(h), 균형 보장 X → 균형 트리 필요
  2. 균형 검색 트리 분류: 균형 BST(AVL, RB) / 균형 k진(2-3, 2-3-4, B)
  3. AVL 트리: 모든 노드 |h(t.left) − h(t.right)| ≤ 1
  4. ★ AVL 4가지 불균형 유형: LL/LR/RR/RL + balanceAVL 알고리즘
  5. 좌/우회전: O(1), 포인터 4번 조작
  6. 연쇄 회전: 삭제 시 최악 O(log n)회
  7. ★ RB 기본 약속: 모든 null 자리에 NIL, 노드는 레드/블랙
  8. ★ RB 4가지 특성:
    • ① 루트 블랙 ② NIL 블랙 ③ 레드 연속 X ④ 블랙 높이 일정
  9. ★ RB 삽입 3단계: BST 삽입 → x를 레드로 → 좌우 NIL 추가
  10. 레드로 칠하는 이유: 블랙은 특성 ④ 무조건 위반, 레드는 ③만 깨질 수 있음
  11. p가 블랙이면: 끝, 추가 작업 없음
  12. ★ p가 레드 — 수선 (s에 따라 분기):
    • 표기: p² = 조부모, p³ = 증조부모, s = p의 형제
  13. ★ Case 1 — s가 레드:
    • p, s를 블랙으로 / p²를 레드로
    • 회전 없음, 색만 변경
    • p³가 레드면 p²를 새 x로 보고 재귀
    • 최악 루트까지 올라감 → 루트는 블랙으로 마무리
  14. ★ Case 2 — s가 블랙:
    • Case 2-1 (x가 p 오른쪽): p 기준 좌회전 → Case 2-2로 변환
    • Case 2-2 (x가 p 왼쪽): p² 기준 우회전 + p와 p² 색 교환 → 끝
  15. Case 1 vs Case 2 비교:
    • Case 1: 색만 변경, 재귀 가능
    • Case 2: 회전 + 색 교환, 한 번에 끝
  16. RB 삽입 전체 시간복잡도: O(log n)
  17. ★ 최종 시간복잡도 (시험 핵심):
    • AVL, RB, 2-3-4 트리 모두 검색/삽입/삭제 = O(log n)
    • 이유: h의 최대값이 log n (균형 트리)
    • 추가 회전/색조정/분할병합도 O(log n)을 넘지 않음
  18. O(log n)이 보장되는 두 단계 논리:
    • ① 트리 높이 h = O(log n) (균형 보장)
    • ② BST 작업 = O(h) → 결과 O(log n)
