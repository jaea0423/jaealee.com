그래프 순회 — DFS와 BFS

트리 순회 복습부터 깊이/너비 우선 탐색까지

01 트리 순회 복습

복습으로 시작
그래프 순회를 배우기 전에, 이미 배운 트리 순회(traversal)를 가볍게 복습합니다.

순회란?

순회 (traversal)는 트리(또는 그래프)의 모든 노드를 일정한 순서로 한 번씩 읽는 것.

"어떤 순서로 노드를 방문하느냐"가 핵심. 트리에서는 자기 자신을 언제 읽느냐에 따라 세 가지 방식이 있음.

예시 트리

다음 트리를 사용합니다. 루트는 a, a의 자식은 b, d, g (3개).

예시 트리 — a(루트) 아래 b·d·g, b 아래 c, c 아래 h, d 아래 e·f

트리 구조 정리

노드 자식
a (루트)b, d, g
bc
ch
de, f
g없음
이진 트리 아님
이 트리는 자식이 3개인 노드(a)가 있어서 이진 트리가 아님. 이 점이 뒤에서 inorder를 다루지 않는 이유가 됨.

02 preorder / inorder / postorder

세 가지 순회는 자기 자신(노드)을 언제 읽느냐로 구분됨. 자식들은 항상 왼쪽(L)부터 오른쪽(R) 순.

preorder — 자신이 먼저 (pre)

순서: 자신 → L → R

노드에 도착하면 자기 자신을 먼저 읽고, 그 다음 자식들을 왼쪽부터 차례로 순회.

예시 트리에 적용하면:

preorder 결과 
# 자신 먼저 → 왼쪽 자식부터 재귀
a → b → c → h → d → e → f → g
a→ b→ c→ h→ d→ e→ f→ g

읽는 흐름: a(자신) → b로 내려가 b(자신) → c(자신) → h(자신) → 다시 올라와 d(자신) → e → f → 마지막 g

inorder — 자신이 가운데 (in)

이번 트리에서는 다루지 않음
  • inorder는 "왼쪽 → 자신 → 오른쪽" 순서
  • 이건 이진 트리(자식 최대 2개)에서만 명확함 — 자신을 왼쪽 자식과 오른쪽 자식 "사이"에 넣으니까
  • 이 트리처럼 자식이 3개면 자신을 어디에 넣을지 기준이 모호함
  • 그래서 이번 예시에서는 inorder를 고려하지 않음

postorder — 자신이 나중에 (post)

순서: L → R → 자신

자식들을 왼쪽부터 모두 순회한 다음에 자기 자신을 읽음.

예시 트리에 적용하면:

postorder 결과 
# 왼쪽 자식부터 재귀 → 자신 나중에
h → c → b → e → f → d → g → a
h→ c→ b→ e→ f→ d→ g→ a

읽는 흐름: 가장 깊은 h부터 → c → b (b 서브트리 끝) → e → f → d (d 서브트리 끝) → g → 마지막에 루트 a

두 방식 비교

방식 자신 위치 순서 결과
preorder 먼저 자신 → L → R a b c h d e f g
inorder 가운데 L → 자신 → R 이진 트리에서만
postorder 나중 L → R → 자신 h c b e f d g a
여기까지는 트리 순회
이제 이 "순서대로 노드를 읽는다"는 개념을 그래프로 확장합니다.

03 DFS — 깊이 우선 탐색

DFS
Depth(깊이) First(우선) Search(탐색)

한 방향으로 갈 수 있는 데까지 깊이 들어간 다음, 막히면 되돌아와서 다른 길을 탐색하는 방식.

예시 그래프

정점 6개(a~f), 무방향 그래프. a와 f가 좌우 양 끝, 가운데 b·e·d·c가 사각형 형태.

예시 그래프 — 정점 {a,b,c,d,e,f}, 무방향. 가운데 사각형은 b(좌상)·e(우상)·d(우하)·c(좌하)

연결 관계 정리

정점 인접한 정점 (알파벳 순)
ab, c
ba, c, d, e
ca, b, d, e
db, c, e, f
eb, c, d, f
fd, e

DFS 진행 과정 (a에서 시작)

규칙: 갈 수 있는 인접 정점 중 알파벳이 빠른 것으로, 안 가본 곳을 향해 계속 깊이 들어감.

DFS 방문 순서 
# a에서 시작, 안 가본 인접 정점 중 알파벳 빠른 순
a → b → c → d → e → f

# 단계별:
a   # 시작
→ b # a의 이웃 b,c 중 빠른 b
→ c # b의 이웃 중 안 가본 곳, c (a는 이미 방문)
→ d # c의 이웃 중 안 가본 곳, d
→ e # d의 이웃 중 안 가본 곳, e
→ f # e의 이웃 중 안 가본 곳, f
# 모든 노드 방문 완료 → 끝

DFS 경로 시각화

이 그래프를 탐색 흐름에 맞춰 펼치면 — a에서 시작해 깊이 들어가는 모양이 보임.

DFS 경로 — 빨간 화살표가 방문 순서 (a→b→c→d→e→f), 회색은 원래 그래프 엣지

DFS 핵심

DFS의 특징
  • 한 길로 끝까지 들어간 뒤, 막히면 되돌아와(backtrack) 다른 길 탐색
  • 방문한 노드는 다시 안 감 (visited 표시 필요)
  • 보통 재귀 또는 스택(stack)으로 구현
  • "깊이"를 우선하므로 트리의 preorder와 비슷한 느낌

backtrack이 드러나는 예시

앞 예시는 한 줄로 쭉 이어졌지만, 보통은 막다른 길에서 되돌아가는(backtrack) 과정이 생김. 다음 그래프로 확인.

예시 그래프 2
  • 정점: a, b, c, d, e, f, g, h (8개)
  • 간선: a-b, a-c, b-c, b-h, b-e, c-d, d-f, e-g
예시 그래프 2 — a 좌측, 가운데 사각형 b·e·c·d, h(b 우상)·g(e 우하)·f(d 좌상)

연결 관계 정리

정점 인접한 정점 (알파벳 순)
ab, c
ba, c, e, h
ca, b, d
dc, f
eb, g
fd
ge
hb

DFS 진행 과정 (backtrack 포함)

DFS 방문 순서 
# a에서 시작
a → b → c → d → f      # 깊이 들어감, f에서 막힘
   ↓ backtrack          # f→d→c→b 거꾸로 올라가며 안 읽은 곳 찾기
b → e → g               # b에 남은 길 e, e→g, g에서 막힘
   ↓ backtrack          # g→e→b 거꾸로
b → h                   # b에 남은 길 h

# 최종 방문 순서:
a, b, c, d, f, e, g, h

단계별 상세

  1. a → b: a의 이웃 b, c 중 빠른 b
  2. b → c: b의 이웃(a,c,e,h) 중 안 가본 곳 빠른 c
  3. c → d: c의 이웃 중 안 가본 d
  4. d → f: d의 이웃 중 안 가본 f
  5. f 막힘: f의 이웃은 d뿐(이미 방문) → backtrack
  6. d, c 거꾸로: d·c 모두 남은 이웃 없음 → 계속 backtrack
  7. b까지 올라옴: b에 안 가본 이웃 e 있음 → b → e
  8. e → g: e의 이웃 중 안 가본 g
  9. g 막힘: g의 이웃은 e뿐 → backtrack
  10. b까지 올라옴: b에 안 가본 이웃 h 있음 → b → h
  11. h 막힘 + 모든 정점 방문 완료 → 끝

backtrack 경로 시각화

DFS 경로 — a b c d f 깊이 진입 후 backtrack → e g → backtrack → h (방문 순서 ①~⑧)

중요 — 모든 엣지를 훑는 건 아님

핵심 주의
  • DFS 순회의 목표는 모든 정점(노드)을 한 번씩 읽는 것
  • 모든 모서리(엣지)를 다 훑어야 하는 것은 아님
  • 예: b-c 간선은 a-b-c로 이미 b, c를 방문했으니 굳이 다시 지나지 않음
  • 방문한 노드로 가는 엣지는 무시 (visited 체크)
트리 비유
DFS가 실제로 지나간 빨간 경로만 모으면 트리 모양이 됨 (이걸 DFS 신장 트리라고 부름). 안 쓴 엣지는 제외됨.

DFS 트리

DFS 트리는 DFS에서 부모 관계(parent)가 표시된 선들만 추출하여, 시작 노드를 루트로 만든 트리.

방금 그래프(a~h)에서 DFS를 돌렸을 때 만들어진 부모 관계는:

  • a → b (b의 부모 = a)
  • b → c (c의 부모 = b)
  • b → e
  • b → h
  • c → d
  • d → f
  • e → g

이 7개 선만 남기고 루트를 a로 두면:

DFS 트리 — 시작 노드 a가 루트, 부모 관계의 선들만 남김 (총 7개 선, 8개 노드)
DFS 트리의 의미
  • 원래 그래프의 엣지 8개 중 7개만 사용됨 (a-c는 안 씀 — c는 b를 거쳐 도달)
  • 노드 8개 → 트리 엣지 7개 (n−1 법칙)
  • 방문 순서를 따라 자연스럽게 트리가 만들어짐
  • 이 트리에서 pre 값을 순서대로 늘어놓으면 DFS 방문 순서(a,b,c,d,f,e,g,h)와 일치

04 BFS — 너비 우선 탐색 (간단히)

이번 시간엔 가볍게
DFS와 짝을 이루는 방식으로 BFS도 존재. 깊이 다루지는 않고 개념만 짚고 넘어감.
BFS
Breadth(너비) First(우선) Search(탐색)

DFS가 깊이를 우선한다면, BFS는 가까운 노드부터 넓게 훑는 방식. 시작점에서 한 겹씩 바깥으로 펼쳐나감.

BFS 진행 과정 (a에서 시작)

규칙: 시작점의 모든 이웃을 먼저 방문하고, 그 다음 이웃의 이웃을 방문 (한 겹씩 바깥으로).

BFS 방문 순서 (8정점 그래프) 
# a에서 시작, 가까운 노드부터 한 겹씩
거리 0: a            # 시작점
거리 1: b, c         # a의 이웃 전부 먼저
거리 2: d, e, h      # 거리 1 노드들의 이웃 중 안 가본 곳
거리 3: f, g         # 거리 2 노드들의 이웃

# 최종 방문 순서:
a, b, c, d, e, h, f, g
DFS와 다름
  • DFS 순서: a, b, c, d, f, e, g, h (깊이 우선)
  • BFS 순서: a, b, c, d, e, h, f, g (거리 우선)
  • 같은 그래프, 같은 시작점이라도 결과가 다름

BFS 시각화 (거리 층으로 펼침)

BFS — 시작점에서 거리(겹) 단위로 펼침. 같은 거리는 같은 층

DFS vs BFS 비교

구분 DFS (깊이 우선) BFS (너비 우선)
탐색 방향 한 길로 끝까지 깊이 가까운 곳부터 넓게
자료구조 스택 (또는 재귀) 큐 (queue)
특기 경로 존재 여부, 사이클 탐지 최단 거리 (무가중치)
이번 시간은 DFS 중심
BFS는 여기까지만 다루고 다시 DFS로 돌아갑니다. 이제 DFS 코드를 자세히 보겠습니다.

05 DFS 의사코드 — 재귀 + 스택

앞에서 본 8정점 그래프를 코드로 풀어봅시다.

같은 8정점 그래프 — 이번엔 코드로 분석

의사코드

의사코드 
curr_time = 1                       # 전역 시각 카운터, 1부터 시작

def DFS(v):                       # v부터 DFS 순회 시작
    mark[v] = "visited"          # v 방문 표시 (재방문 방지)
    pre[v] = curr_time            # v에 처음 들어온 시각 기록
    curr_time += 1

    for each edge (v, w):         # v에 인접한 모든 w에 대해
        if mark[w] != "visited":   # 아직 안 간 곳이면
            parent[w] = v         # w가 어디서 왔는지(부모) 기록
            DFS(w)                # w로 더 깊이 들어감 (재귀)

    # for문 종료 = v의 모든 이웃을 다 살펴봄 = 더 갈 곳 없음
    post[v] = curr_time           # v에서 DFS가 완전히 끝난 시각
    curr_time += 1

각 부분 설명

코드 의미
mark[v] = "visited" 이미 순회한 노드를 다시 읽지 않기 위한 표시
pre[v] = curr_time v에 처음 들어온 시각 (방문 시작)
for each edge (v, w) v에 연결된 이웃 w를 하나씩 살펴봄
parent[w] = v w의 출처(부모) 저장 — 나중에 경로 복원용
DFS(w) w를 새 시작점으로 더 깊이 들어감 (재귀)
post[v] = curr_time v에서 DFS가 완전히 끝난 시각

네가 헷갈린 부분 정리

"for문을 나왔다 = 모든 인접 노드 고려" 이해
  • v를 갈림길이라고 생각
  • 각 엣지 = 갈림길에서 뻗은 길
  • for문 = 그 갈림길의 모든 길을 하나씩 가보는 것
  • for문을 다 돌았다 = 이 갈림길에서 갈 수 있는 길을 전부 시도함
  • = 여기선 더 갈 데 없음 → backtrack → 그래서 post[v] 기록
curr_time / pre / post 가 뭔가
  • curr_time: 전역 시각 카운터. 노드를 들어가고 나올 때마다 1씩 증가
  • pre[v]: v에 처음 들어간 시각 (발견 시각)
  • post[v]: v를 완전히 떠나는 시각 (종료 시각)
  • 이 타임스탬프로 누가 누구의 조상인지, 사이클이 있는지 등을 분석 가능

★ w를 어떻게 결정하나? (알파벳 순서 문제)

의사코드 자체는 알파벳 순서를 보장하지 않음
  • for each edge (v, w)는 "v의 이웃을 순서대로 본다"일 뿐
  • 그 순서는 인접 리스트에 저장된 순서에 달려 있음
  • 알파벳 빠른 순으로 방문하려면:
    • 인접 리스트를 미리 알파벳 순으로 정렬해서 저장하거나
    • for문에서 매번 정렬된 순서로 꺼내야 함
  • 수업/시험에서 "알파벳 빠른 순"으로 푸는 건 인접 리스트가 알파벳 순으로 정렬돼 있다고 약속한 것

pre / post 시각 추적표

위 그래프에서 a부터 DFS를 돌리면 (인접 리스트가 알파벳 순 정렬이라 가정):

실행 추적 
time 1:  pre[a]=1   # a 진입
time 2:  pre[b]=2   # a→b
time 3:  pre[c]=3   # b→c
time 4:  pre[d]=4   # c→d
time 5:  pre[f]=5   # d→f
time 6:  post[f]=6  # f 막힘, 종료
time 7:  post[d]=7  # d 종료 (backtrack)
time 8:  post[c]=8  # c 종료
time 9:  pre[e]=9   # b→e (b에 남은 이웃)
time 10: pre[g]=10  # e→g
time 11: post[g]=11 # g 막힘, 종료
time 12: post[e]=12 # e 종료
time 13: pre[h]=13  # b→h (b에 남은 이웃)
time 14: post[h]=14 # h 종료

스택 기반 버전 — 재귀 없이 구현

위 코드는 재귀 호출로 DFS를 구현했음. 그런데 같은 동작을 스택(stack) 자료구조로도 만들 수 있음.

스택 (Stack)

맨 위에서만 push(넣기)와 pop(빼기)이 가능한 자료구조. 가장 마지막에 넣은 것이 가장 먼저 빠짐 (LIFO).

새 예시 — c-f 간선 추가

기존 8정점 그래프에 c-f 간선 하나를 추가한 그래프로 진행. 이 간선이 나중에 중요한 역할을 함.

8정점 그래프 + 새 간선 c-f (보라 점선)

스택 기반 의사코드

의사코드 — 스택 버전 
def DFS(s):                       # s부터 DFS 시작 (재귀 없음!)
    stack.push((∅, s))           # (부모, 현재) 쌍을 스택에 넣음, 첫 부모는 공집합
    
    while stack is not empty:
        p, v = stack.pop()
        if v is unmarked:        # 아직 visited가 아니라면
            mark[v] = "visited"
            parent[v] = p
            for each edge (v, w):
                if w is unmarked:
                    stack.push((v, w))   # (부모=v, 자식=w) 쌍을 push

핵심 포인트

왜 (부모, 현재) 쌍을 저장?
  • 재귀 버전은 호출 스택이 자동으로 "어디서 왔는지" 기억해줌
  • 스택 버전은 그게 자동이 아니라 직접 (parent, current) 쌍으로 저장해야 함
  • v를 방문할 때 parent[v] = p로 기록
알파벳 빠른 순으로 방문하려면?
  • 스택은 LIFO — 마지막에 push한 게 먼저 pop됨
  • 그래서 알파벳이 느린 것부터 push해야 빠른 것이 먼저 pop됨
  • 예: v=b의 이웃이 c, e, h라면 h → e → c 순으로 push (pop은 c → e → h)
  • 이렇게 해야 기존 재귀 버전과 같은 결과(a,b,c,d,f,e,g,h)가 나옴

스택 동작 흐름 (요약)

c-f 간선이 추가된 그래프에서 스택 기반 DFS가 어떻게 도는지:

스택 추적 
초기: stack = [(∅, a)]

# pop (∅,a) → a 방문 / a 이웃 c,b push (느린→빠른)
stack = [(a,c), (a,b)]

# pop (a,b) → b 방문 / b 이웃 h,e,c push (a는 visited)
stack = [(a,c), (b,h), (b,e), (b,c)]

# pop (b,c) → c 방문 / c 이웃 f,d push (a,b는 visited)
# * c-f 간선 덕분에 f도 push됨
stack = [(a,c), (b,h), (b,e), (c,f), (c,d)]

# pop (c,d) → d 방문 / d 이웃 f push (c는 visited)
stack = [(a,c), (b,h), (b,e), (c,f), (d,f)]

# pop (d,f) → f 방문 (parent=d) / f 이웃 c는 visited
stack = [(a,c), (b,h), (b,e), (c,f)]

# pop (c,f) → f는 이미 visited! 그냥 버림 ★
stack = [(a,c), (b,h), (b,e)]

# pop (b,e) → e 방문 / e 이웃 g push
stack = [(a,c), (b,h), (e,g)]

# pop (e,g) → g 방문, 더 갈 곳 없음
stack = [(a,c), (b,h)]

# pop (b,h) → h 방문, 더 갈 곳 없음
stack = [(a,c)]

# pop (a,c) → c는 이미 visited! 버림
stack = []  →  종료

# 최종 방문 순서: a, b, c, d, f, e, g, h (재귀 버전과 동일!)
★ 중복된 쌍이 스택에 쌓일 수 있음
  • 스택에 (c,f)와 (d,f)가 둘 다 들어있었음 — c와 d 둘 다 f의 이웃이라서
  • 먼저 pop된 (d,f)에서 f가 방문됨 → parent[f] = d
  • 나중에 (c,f) pop했을 때는 f가 이미 visited → 그냥 버림
  • 이렇게 스택에는 같은 노드가 여러 번 들어갈 수 있지만, 실제 방문은 한 번만
재귀 vs 스택 — 결과는 같다
  • 재귀 버전이 더 짧고 직관적
  • 스택 버전은 재귀 깊이 제한 걱정 없음 (큰 그래프에서 유리)
  • 두 버전 다 같은 DFS 결과 — 어느 쪽이든 본질은 같음

07 DFS 트리와 Back Edge

방금 본 그래프(a~h + c-f 간선)에서 DFS 트리를 다시 그려보면, c-f 간선이 사라져 있음을 알 수 있어요.

DFS 트리 (간선 비교)

DFS 트리 — 검정 실선은 트리 간선, 보라 점선이 back edge (a-c, c-f)

Back Edge란?

Back Edge (역방향 간선)

원래 그래프에는 있지만 DFS 트리에는 안 나타나는 간선. 이미 방문한 조상 노드로 돌아가는 모양이라 "back"이라고 부름.

이 예시에서:

  • a-c 간선: c는 a를 거쳐 b → c로 도달했음. 하지만 a와 c는 원래 그래프에서 직접 연결 → DFS 트리에는 안 보이지만 그래프엔 있음 → back edge
  • c-f 간선: f는 c→d→f 경로로 도달. c-f 직접 연결은 트리에 안 보임 → back edge

★ Back Edge가 있다 = 순환(Cycle)이 존재

중요한 통찰

Back edge가 존재한다는 것은 그래프에 순환(cycle)이 있다는 뜻.

  • 예: c-f가 back edge → c → d → f → (back edge) → c로 돌아옴 → 사이클!
  • 예: a-c가 back edge → a → b → c → (back edge) → a로 돌아옴 → 사이클!
  • 반대로, back edge가 하나도 없으면 그 그래프는 순환 없음
활용
이 성질을 이용하면 DFS로 사이클이 있는지 검사할 수 있음. DFS 돌릴 때 back edge가 한 번이라도 발견되면 사이클 존재.

막대 그래프 (가로 구간)

아래 가로축에 시각 1~16을 놓고, 노드는 아래(a)에서 위(h)로 쌓아 각 [pre, post] 구간을 가로 막대로 그리면 (강의에서 본 방향). 한 막대가 다른 막대를 가로로 완전히 덮으면 조상-자손 관계입니다:

각 노드의 [pre, post] 가로 막대 — 가로로 포함하는 관계(빨간 점선)가 곧 DFS 트리의 부모-자식 관계

핵심 통찰

막대 포함 = DFS 트리 부모-자식
  • 노드 u가 노드 v의 조상이면 → u의 막대가 v의 막대를 완전히 포함
  • 두 노드가 조상 관계가 아니면 → 막대가 겹치지 않음
    • 예: c [3,8]과 e [9,12]는 겹치지 않음 (둘 다 b의 자식, 형제 관계)
  • 이 구조를 보면 막대들을 옆으로 눕히면 그대로 DFS 트리가 됨
왜 이런 구조인가?

DFS가 u에서 v로 들어가면 v의 pre는 u의 pre보다 크고, v를 다 끝낸 뒤(post 찍은 뒤) u가 끝남(post 찍음). 그래서 v의 [pre, post]는 u의 [pre, post] 안에 완전히 포함됨. 이게 콜스택의 push-pop 구조와 정확히 같음.

09 DFSALL — 비연결 그래프 순회

지금까지 본 DFS는 한 정점에서 출발해 갈 수 있는 곳만 훑음. 그런데 그래프가 여러 조각으로 끊어져 있으면 어떻게 될까?

문제 — 비연결 그래프

다음과 같이 두 덩어리로 분리된 그래프를 봅시다.

예시: 비연결 그래프
  • 왼쪽 덩어리: a-b-c (삼각형)
  • 오른쪽 덩어리: d-e
  • 두 덩어리 사이는 이어진 간선 없음
비연결 그래프 — 두 컴포넌트(덩어리)로 분리됨

DFS(a)만 돌리면?

문제 발생
  • DFS(a)는 a에서 갈 수 있는 곳만 탐색 → a, b, c만 방문
  • d, e는 영영 방문 못 함 (a 쪽에서 도달 불가)
  • => 순회가 안 됨 (모든 정점을 못 읽음)

해결 — DFSALL 함수

모든 정점을 빠짐없이 순회하려면, 아직 방문 안 된 정점이 남아 있으면 거기서 DFS를 또 시작해야 함.

의사코드 
def DFSALL(G):                    # 그래프 G 전체를 DFS
    for all nodes v in G:        # 모든 노드 초기화
        mark[v] = "unvisited"
    
    for all nodes v in G:        # 모든 노드 확인
        if mark[v] != "visited": # 아직 방문 안 됐으면
            DFS(v)                # 거기서 DFS 새로 시작

각 부분 설명

코드 의미
첫 for문 (초기화) 모든 노드를 "unvisited"로 표시 — 시작 전 깨끗한 상태 만들기
두 번째 for문 모든 노드를 하나씩 살펴보며, 아직 방문 안 된 노드 발견 시 DFS 시작
DFS(v) 호출 v에서 도달 가능한 모든 정점을 한꺼번에 훑음

위 비연결 그래프에 DFSALL 적용

실행 흐름 
# 초기화: 모든 노드 unvisited

# 첫 번째 노드 a 확인 → unvisited
DFS(a)   →  a, b, c 방문 (왼쪽 덩어리 완료)

# b, c 차례 → 이미 visited, 넘어감

# d 확인 → unvisited
DFS(d)   →  d, e 방문 (오른쪽 덩어리 완료)

# e 차례 → 이미 visited, 끝

# 최종: 모든 정점 a, b, c, d, e 방문 완료
DFSALL의 의미
  • 그래프가 연결되어 있든 아니든 모든 정점을 빠짐없이 순회 보장
  • DFS가 호출된 횟수 = 그래프의 연결 요소 개수
    • 위 예시: DFS 2번 호출 → 연결 요소 2개
  • 방금까지 본 a~h 그래프는 한 덩어리라 DFS(a) 한 번으로 끝났음
  • 실제 코드에서는 보통 DFS만 부르지 않고 DFSALL을 부름

10 방향 그래프와 DAG

지금까지 본 그래프는 모두 무방향이었음 (간선에 방향이 없어서 양쪽으로 다 갈 수 있음). 이제 방향이 있는 그래프를 봅시다.

무방향 vs 방향 — 비교

왼쪽 무방향(선) vs 오른쪽 방향(화살표) — 같은 ABC라도 의미가 다름

DAG — Directed Acyclic Graph

DAG
Directed(방향이 있고) Acyclic(사이클이 없는) Graph
DAG의 핵심 성질
  • 모든 간선에 방향이 있음 (방향 그래프)
  • 어떤 노드에서 출발해도 자기 자신으로 돌아오는 경로가 없음 (acyclic)
  • "일의 순서"를 표현하기에 좋음 — 앞 일이 끝나야 뒤 일을 할 수 있는 의존 관계

DAG 예시

다음 그래프는 8개 정점으로 이루어진 DAG.

그래프 정보
  • 정점: A, B, C, D, F, G, H, I
  • 간선: A→B, A→C, A→D / B→F, B→H / C→B, C→F / D→G, D→I / F→D, F→H / H→G / I→G
DAG 예시 — 화살표 방향대로만 이동, 사이클 없음. 왼쪽에서 오른쪽으로 흐르는 의존 관계
현실 비유 — 일의 순서
  • A를 끝내야 B, C, D를 시작할 수 있음
  • B와 C 둘 다 끝나야 F를 시작 가능 (혹은 두 길 중 어디든)
  • F가 끝나야 D와 H를 시작…
  • 이런 "선후 관계가 있는 작업"을 모델링할 때 DAG가 자연스러움

11 위상 정렬 — Topological Sort

위상 정렬
DAG의 정점들을 일의 순서대로 한 줄로 늘어놓는 것

"앞 일이 끝나야 뒤 일을 할 수 있다"는 규칙을 만족하도록 정점을 줄세우는 것. 다시 말해, 간선 u→v가 있으면 정렬에서 u가 v보다 앞에 와야 함.

위상 정렬과 DFS의 관계 — 시험 핵심

위상 정렬을 DFS로 구하는 방법
  • DAG에 DFS를 돌림
  • 각 노드의 post 값을 기록
  • post 값이 큰 순서대로 (역순) 늘어놓으면 = 위상 정렬!

실제 DAG로 확인

위 DAG에 A부터 DFS(인접 리스트 알파벳 순)를 돌리면:

DFS 추적 (A부터, 알파벳 순) 
pre[A]=1   A → B (B,C,D 중 알파벳 빠른 B)
pre[B]=2     B → F (F,H 중 F)
pre[F]=3       F → D (D,H 중 D)
pre[D]=4         D → G (G,I 중 G)
pre[G]=5           G는 나갈 곳 없음
post[G]=6        backtrack to D
pre[I]=7         D → I
post[I]=8        I → G (방문함)
post[D]=9      backtrack to F
pre[H]=10      F → H
post[H]=11     H → G (방문함)
post[F]=12   backtrack to B
post[B]=13   backtrack to A
pre[C]=14    A → C
post[C]=15   C → B (방문함), C → F (방문함)
post[A]=16

① PRE 값 오름차순 = DFS 순회 순서

→ DFS가 노드를 방문한 순서 (pre 1, 2, 3, 4, 5, 7, 10, 14)

② POST 값 내림차순 = 위상 정렬

A→ C→ B→ F→ H→ D→ I→ G

→ post 16, 15, 13, 12, 11, 9, 8, 6 (역순)

검증 — 정말 위상 정렬인가?

간선 방향 확인

A → C → B → F → H → D → I → G 순서에서 모든 간선이 "앞에서 뒤로" 가는지 확인:

  • A→B ✓ (A 1번째, B 3번째)
  • A→C ✓ (A 1번째, C 2번째)
  • A→D ✓ (A 1번째, D 6번째)
  • B→F ✓ / B→H ✓
  • C→B ✓ / C→F ✓
  • D→G ✓ / D→I ✓
  • F→D ✓ / F→H ✓
  • H→G ✓ / I→G ✓

모든 간선이 앞→뒤 방향 → 유효한 위상 정렬 ✓

왜 POST 역순이 위상 정렬일까?

직관적 이해
  • DFS에서 u → v 간선을 따라가면 v를 먼저 다 끝낸 다음 u가 끝남
  • 즉 post[u] > post[v] (간선 u→v가 있을 때)
  • 그래서 post가 큰 노드부터 줄세우면 자연스럽게 "선행 작업" 먼저 옴
  • 이게 정확히 위상 정렬의 정의
시험 핵심 요약
기준결과
PRE 값 오름차순 DFS 방문 순서
POST 값 내림차순 위상 정렬

12 오늘 꼭 기억할 것

시험 포인트
  1. 순회(traversal): 모든 노드를 일정한 순서로 한 번씩 읽기. 모든 정점을 읽는 것이지 모든 엣지를 훑는 건 아님
  2. 트리 순회 3가지: preorder(자신 먼저) / inorder(자신 가운데, 이진트리 전용) / postorder(자신 나중)
  3. ★ DFS (Depth First Search): 한 길로 끝까지 → 막히면 backtrack. 스택 또는 재귀로 구현
  4. ★ DFS 의사코드 (재귀 버전) 핵심:
    • mark[v]="visited" → pre[v]=curr_time → 이웃 재귀 호출 → post[v]=curr_time
    • pre[v]: v에 처음 들어간 시각 / post[v]: v 완전히 끝난 시각
    • pre 순서 = 방문 순서
    • parent[w]=v: 부모 기록 (경로 복원용)
  5. ★ DFS 스택 버전 (재귀 없이):
    • 스택에 (부모, 현재) 쌍을 push
    • pop해서 unmarked면 방문, 이웃을 push
    • 알파벳 순으로 방문하려면 느린 알파벳부터 push (LIFO이므로)
    • 스택에는 같은 노드가 여러 번 들어갈 수 있지만 실제 방문은 한 번만
  6. 방문 순서(알파벳 순)는 어디서?: 의사코드 자체 보장 X. 인접 리스트가 알파벳 순으로 정렬돼 있다고 약속
  7. ★ DFS 트리: parent 관계 선들만 추출, 시작 노드가 루트. 노드 n개 → 트리 엣지 n−1개
  8. ★ Back Edge:
    • 원래 그래프엔 있지만 DFS 트리에는 안 나타나는 간선
    • 이미 방문한 조상으로 돌아가는 모양
    • Back edge 존재 ⇔ 사이클(순환) 존재
  9. ★ pre/post 막대 구조:
    • 각 노드를 [pre, post] 구간 막대로 그림
    • u가 v의 조상 ⇔ u 막대가 v 막대를 완전히 포함
    • 형제 관계면 막대가 겹치지 않음
    • 막대 포함 관계를 뒤집으면 = DFS 트리
  10. ★ DFSALL(G) — 비연결 그래프 대응:
    • DFS(v)만 부르면 v 쪽 덩어리만 훑음
    • DFSALL: unvisited 초기화 → 안 가본 노드마다 DFS 새로 시작
    • DFS 호출 횟수 = 연결 요소(component) 개수
  11. 방향 그래프 vs 무방향: 간선에 방향이 있으면 화살표 방향대로만 이동
  12. ★ DAG (Directed Acyclic Graph):
    • Directed(방향 있음) + Acyclic(사이클 없음) + Graph
    • "일의 순서" 같은 선후 관계 모델링에 사용
  13. ★★ 위상 정렬 (Topological Sort) — 시험 핵심:
    • DAG의 정점을 "앞 일 → 뒤 일" 순서로 한 줄 정렬
    • 간선 u→v가 있으면 정렬에서 u가 v보다 앞
    • DFS를 돌린 후 POST 값을 내림차순으로 나열하면 위상 정렬
    • PRE 오름차순 = DFS 방문 순서 / POST 내림차순 = 위상 정렬
  14. BFS (너비 우선 탐색): 가까운 노드부터 한 겹씩, 큐로 구현. DFS와 결과 다름
  15. 방문 표시(visited): 그래프는 사이클이 있으니 필수
