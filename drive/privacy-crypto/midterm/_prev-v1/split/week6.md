# 6주차 — 블록 암호 운영 모드

*긴 데이터를 블록으로 나눌 때 정해야 할 두 가지 — 마지막 블록을 채우는 패딩(제로 · 비트 · 바이트 · PKCS#7)과 블록을 잇는 운영 모드(ECB · CBC · CFB · OFB · CTR), 그리고 참고로 인증 암호(AEAD)* · 기간 2026.10.06 ~ 10.12

**이번 주 핵심 3**

1. 패딩은 마지막 블록을 채우고 **복호화 후 정확히 걷어낼 수 있어야** 한다. 가장 널리 쓰는 **PKCS#7** = 채울 개수 n을 값 n으로 n개, 평문이 이미 블록 크기의 배수여도 **블록 하나를 더** 붙인다.
2. **평문이 블록 암호를 통과하는가**가 모든 차이를 만든다: ECB · CBC(직접 입력) → 패딩 필요 · D 함수 필요 / CFB · OFB · CTR(만든 값과 XOR) → 패딩 불필요 · E 함수만 사용.
3. ECB는 같은 평문 블록 → 같은 암호문 블록이라 **패턴이 남고 블록 복사 · 교체 조작**이 된다. IV는 비밀이 아니지만 **매번 달라야** 하고(CBC는 예측 불가), 같은 키 + 같은 IV/카운터 → 같은 키 스트림 → C₁ ⊕ C₂ = P₁ ⊕ P₂.

### [w6-s1-2] 긴 데이터는 블록으로 나누어 처리한다 (교안 p.4)

*[도식] 평문 P (하나의 긴 막대) → 점선으로 잘라 평문 블록 P₁ | P₂ | … | P_N 으로 나눔 → 「블록암호 운영 모드」 → 암호문 C₁ | C₂ | … | C_N (블록마다 하나씩 대응) — p.4 도식* — 도식 속 글자: 평문 P / P₁ / P₂ / … / P_N / 블록암호 운영 모드 / C₁ / C₂ / … / C_N

| 블록 암호 | 블록 크기 | 예 : 1,000바이트를 나누면 |
|---|---|---|
| **DES** | 64비트 (8바이트) | 8바이트 × 125개 (남는 바이트 없음) |
| **AES** | 128비트 (16바이트) | 16바이트 × 62개 + 8바이트가 남음 **(패딩 필요)** |

> **[교안 강조]**
> 
> 블록 암호 = 블록 하나를 바꾸는 함수 / 운영 모드 = 여러 블록을 이어서 처리하는 방법

> **[보충 (교수님 설명 아님)]** **표 보충 — "남는 바이트 없음"이어도 패딩 블록은 붙는다 — 교수님 설명 아님**
> 
> 표는 "남는 바이트" 관점만 보여 줍니다. 뒤(p.11)의 공통 규칙 "평문이 이미 블록 크기의 배수여도 블록 하나를 더 붙임"을 적용하면 DES도 08 × 8 블록이 하나 추가되어 1,008바이트가 되고, AES는 PKCS#7로 08 × 8을 채워 역시 1,008바이트가 됩니다.

### [w6-s1-3] 블록으로 나눌 때 정해야 할 두 가지 (교안 p.5)

**[① 마지막 블록을 어떻게 채울 것인가]**
- 평문 길이가 블록 크기의 배수가 아니면 마지막 블록이 남음 — 예 : AES로 1,000바이트 → 마지막에 8바이트만 남음
- 블록 암호는 정해진 크기의 블록만 처리 가능
- → 남은 자리를 채우는 작업 : **패딩 (Padding)**

**[② 블록들을 어떻게 이어서 처리할 것인가]**
- 각 블록을 따로 처리할 것인가
- 앞 블록의 결과를 다음 블록에 섞을 것인가
- 블록 암호로 만든 값을 평문과 결합할 것인가
- → 이어 붙이는 방식의 규칙 : **운영 모드**

**[방식에 따라 달라지는 것]**
- 처리 속도 (여러 블록을 동시에 처리할 수 있는가)
- 전송 중 오류가 생겼을 때 영향을 받는 범위
- 암호문이 가지는 성질 (같은 평문이 같은 암호문이 되는가)

> **[교안 강조]**
> 
> 각 방식이 어떤 성질을 가지는지는 모드를 하나씩 살펴보며 확인


## [6주차 02] 패딩이 필요한 이유 · 제로 패딩 · 비트 패딩

### [w6-s2-1] 패딩이 필요한 이유 (교안 p.6)

**블록 크기 8바이트, 마지막 데이터가 5바이트인 경우**

*[도식] 앞 5칸 = 원래 데이터 5바이트 / 뒤 3칸(? ? ?) = 채워야 할 3바이트 (p.6)* — 도식 속 글자: 31 / AB / 34 / FE / 52 / ? / ? / ? / 원래 데이터 5바이트 / 채워야 할 3바이트

**[채우는 것으로 끝이 아니다]**
- 복호화 후 원래 평문 데이터를 인식해야 함 — 원본이 5바이트였다면 정확히 5바이트
- 채운 부분을 그대로 돌려주면 데이터가 달라짐

**[좋은 패딩의 조건]**
- 채운 부분을 명확히 구분할 수 있어야 함
- 원래 데이터의 값과 무관하게 동작해야 함
- 송신자와 수신자가 같은 규칙을 사용해야 함

> **[교안 강조]**
> 
> 패딩 = 마지막 블록을 채우는 작업 + 복호화 후 정확히 걷어내는 규칙

> **[교수님 말씀 08:23]**
> 
> 채우는 것만으로 끝나지 않습니다. 암호문을 받은 수신자는 복호화한 뒤 채워 놓은 부분까지 평문으로 인식하면 안 되고, 원본이 5바이트였다면 정확히 5바이트만 평문으로 인식해야 합니다. 그래서 어디까지가 원래 데이터이고 어디부터 패딩인지 구분할 수 있어야 합니다. 송신자와 수신자가 서로 다른 규칙을 쓰면 복호화 후 데이터가 달라집니다.

### [w6-s2-2] 패딩 방식 ① : 제로 패딩 (교안 p.7)

*[도식] 원본 데이터 31 AB 34 FE 52 → 패딩 적용 31 AB 34 FE 52 00 00 00 (p.7)* — 도식 속 글자: 원본 데이터 / 31 / AB / 34 / FE / 52 / 패딩 적용 / 31 / AB / 34 / FE / 52 / 00 / 00 / 00 / 빈 자리를 0x00으로 채움

**[문제 : 원래 데이터가 0x00으로 끝나면?]**
- 원본이 31 AB 34 00 인 경우
- **마지막 00이 데이터인지 채운 값인지 구분 불가**
- **뒤쪽 0을 모두 지우면 원래 데이터까지 삭제됨**
- 0x00으로 끝나지 않는 데이터에만 제한적으로 사용 가능

> **[교안 강조]**
> 
> 구현은 가장 쉽지만, "데이터 값과 무관하게 동작해야 한다"는 조건을 만족하지 못함

> **[교수님 말씀 11:24]**
> 
> 제로 패딩은 데이터가 0으로 끝나지 않는다는 것이 보장되는 경우에만 쓸 수 있습니다. 일반 텍스트처럼 00이 나오지 않는 데이터에는 쓸 수 있지만, 이미지나 압축 파일, 또 널(00)로 끝나는 텍스트처럼 00으로 끝나는 값이 나오는 경우에는 적용할 수 없습니다.

### [w6-s2-3] 패딩 방식 ② : 비트 패딩 (교안 p.8)

*[도식] 원본 데이터 31 AB 34 FE 52 → 패딩 적용 31 AB 34 FE 52 80 00 00 (80 칸 강조) — 0x80 (1000 0000) 을 먼저 넣고 나머지는 0x00 (p.8)* — 도식 속 글자: 원본 데이터 / 31 / AB / 34 / FE / 52 / 패딩 적용 / 31 / AB / 34 / FE / 52 / 80 / 00 / 00 / 0x80 (1000 0000) 을 먼저 넣고 나머지는 0x00

**[패딩 제거 방법]**
- 뒤에서부터 0x00을 지나
- 처음 만나는 0x80까지 제거
- **원래 데이터가 0x00으로 끝나도 경계가 분명**

**[주의할 점]**
- 원래 데이터가 0x80으로 끝나도 문제없음 — 뒤에서 처음 만나는 0x80 하나만 제거
- 평문이 이미 블록 크기의 배수이면
- **블록 하나를 더 붙여 패딩을 넣음**

> **[교안 강조]**
> 
> 비트 패딩 = "1을 하나 넣고 나머지는 0" → 데이터 값과 무관하게 경계를 구분할 수 있음

> **[교수님 말씀 12:24]**
> 
> 채우기 시작하는 자리에 비트 1을 넣고 나머지를 전부 0으로 채웁니다. 1000 0000을 16진수로 보면 0x80입니다. 수신자는 복호화한 뒤 뒤에서부터 0을 확인하다가 처음 만나는 80(비트 1)까지 지우면 원래 5바이트를 얻습니다. 평문이 처음부터 8바이트로 꽉 차 있으면 붙일 곳이 없으므로 같은 길이의 블록을 하나 더 만들어 0x80부터 00까지 채웁니다. 이 규칙은 뒤의 패딩 방식에도 동일하게 적용됩니다.

*[교안 사진 내용]*
- **교수님 화면 손필기 (12:34~15:39, 화면 기록 기준)**: 원본 칸 아래에 붉은 글씨로 1 0 0 0 … (비트 1 다음 0들)을 적어 0x80의 비트 모양을 보여 주심. "주의할 점" 상자 아래에 X 여러 개(꽉 찬 8바이트)를 그리고 사각형으로 감싼 뒤, 오른쪽에 새 블록을 그려 1000…00(추가 패딩 블록)을 적으심. 겹친 작은 글씨는 판독이 불확실하다고 기록되어 있음.

## [6주차 03] 바이트 패딩 · PKCS#7 패딩 · 패딩 방식의 비교

### [w6-s3-1] 패딩 방식 ③ : 바이트 패딩 (교안 p.9)

*[도식] 블록 8바이트, 두 번째 블록에 3바이트(3A FE 00)만 남은 경우 → 00 00 00 00 05를 채움(최하위 바이트에 패딩 바이트 표시) → 복원 시 마지막 값 05만큼 패딩 값 제거 (p.9)* — 도식 속 글자: 원본 메시지 / … / 31 / AB / 34 / FE / 52 / 5E / 97 / 12 / 3A / FE / 00 / 패딩 메시지 / … / 31 / AB / 34 / FE / 52 / 5E / 97 / 12 / 3A / FE / 00 / 00 / 00 / 00 / 00 / 05 / 원본 메시지 복원 / … / 31 / AB / 34 / FE / 52 / 5E / 97 / 12 / 3A / FE / 00 / 00 / 00 / 00 / 00 / 05 / 패딩 값 제거 / 최하위 바이트에 패딩 바이트 표시

원본 메시지 복원 … | 31 AB 34 FE 52 5E 97 12 | 3A FE 00 [00 00 00 00 05] ← 패딩 값 제거

**[규칙과 제거 방법]**

- 복호화 후 마지막 바이트 값만큼 뒤에서 제거 — 그림의 예 : 5바이트를 채웠으므로 마지막 바이트는 05

### [w6-s3-2] 패딩 방식 ④ : PKCS#7 패딩 (교안 p.10)

*[도식] 16바이트(4×4) 블록 단위, 바이트는 행 단위(왼→오, 위→아래)로 읽음 — 예 1: 6바이트 부족 → 06 여섯 개 / 예 2: 32바이트(배수) → 0x10 16개 블록 3 추가 (p.10)* — 도식 속 글자: 예 1 — 마지막 블록이 10바이트 (6바이트 부족) / 원본 메시지 / 23 / AF / 4E / 30 / AB / 3E / 7F / 97 / 64 / 64 / 90 / 5E / 6F / 26 / 8A / 6F / 50 / AF / 4E / 30 / AB / 3E / 84 / 97 / 64 / 64 / 패딩 메시지 / 23 / AF / 4E / 30 / AB / 3E / 7F / 97 / 64 / 64 / 90 / 5E / 6F / 26 / 8A / 6F / 50 / AF / 4E / 30 / AB / 3E / 84 / 97 / 64 / 64 / 06 / 06 / 06 / 06 / 06 / 06 / 패딩된 바이트 수 6 (= 0x06) / 예 2 — 평문이 이미 32바이트 (블록 크기의 배수) / 원본 메시지 / 23 / AF / 4E / 30 / AB / 3E / 7F / 97 / 64 / 64 / 90 / 5E / 6F / 26 / 8A / 6F / 50 / AF / 4E / 30 / AB / 3E / 84 / 97 / 64 / 64 / 98 / 6F / 3E / AC / 68 / 20 / 패딩 메시지 (블록 3 추가) / 23 / AF / 4E / 30 / AB / 3E / 7F / 97 / 64 / 64 / 90 / 5E / 6F / 26 / 8A / 6F / 50 / AF / 4E / 30 / AB / 3E / 84 / 97 / 64 / 64 / 98 / 6F / 3E / AC / 68 / 20 / 10 / 10 / 10 / 10 / 10 / 10 / 10 / 10 / 10 / 10 / 10 / 10 / 10 / 10 / 10 / 10 / 패딩된 바이트 수 16 (= 0x10)

**[규칙]**
- 채울 바이트 수가 n이면 값 n을 n개 채움 — 6바이트 부족 → 06 06 06 06 06 06
- 복호화 : 마지막 바이트 값만큼 뒤에서 제거 — 지우는 바이트가 모두 같은 값인지 확인 가능

**[평문이 이미 블록 크기의 배수이면]**
- 패딩을 생략하지 않고 블록 하나를 추가 — 16바이트 블록 → 0x10을 16개 채운 블록 추가
- 생략하면 수신자가 데이터를 잘못 잘라낼 수 있음

> **[교안 강조]**
> 
> PKCS#7 = "채울 바이트 수를 그 값으로 채운다"

> **[교수님 말씀 17:42]**
> 
> 실무에서 가장 널리 쓰이는 방식이 PKCS#7 패딩입니다. 공개키 암호 표준 문서(PKCS)의 7번째 문서에 정의되어 있어 이런 이름이 붙었습니다. 복호화할 때 지우려는 6바이트가 모두 06인지 확인할 수 있어서 패딩이 올바른 형태인지 검사하기가 훨씬 쉬워집니다. 패딩을 생략하면 수신자가 마지막 바이트를 보고 패딩이 있다고 잘못 판단해 데이터를 잘라낼 수 있습니다.

> **[보충 (교수님 설명 아님)]** **왜 배수여도 블록을 붙여야 하나 — 예 — 교수님 설명 아님**
> 
> 16바이트 평문이 마침 …**01**로 끝난다고 합시다. 패딩을 생략하면 수신자는 마지막 바이트 01을 "패딩 1바이트"로 보고 데이터 1바이트를 지워 버립니다. 항상 패딩을 붙이기로 약속하면(배수일 때는 10 × 16 블록) 수신자는 "마지막 바이트는 반드시 패딩"이라고 확신할 수 있습니다.

### [w6-s3-3] 패딩 방식의 비교 (교안 p.11)

| 방식 | 채우는 값 | 제거 방법 | 특징 |
|---|---|---|---|
| **제로 패딩** | 0x00 | 뒤쪽 0x00 제거 | 가장 단순하나 데이터가 00으로 끝나면 구분 불가 |
| **비트 패딩** | 0x80 + 0x00 | 뒤에서 첫 0x80까지 제거 | 데이터 값과 무관하게 동작 |
| **바이트 패딩** | 0 + 마지막에 개수 | 마지막 바이트 값만큼 제거 | 제거가 빠름 |
| **PKCS#7** | 개수 n을 n개 | 마지막 바이트 값만큼 제거 | 가장 널리 사용, 패딩 형태 검사도 쉬움 |

**[공통 규칙]**
- 평문이 이미 블록 크기의 배수여도 블록 하나를 더 붙임
- 송신자와 수신자가 같은 규칙을 사용해야 함

> **[교안 강조]**
> 
> 패딩은 평문을 블록 단위로 맞추기 위한 작업 → 평문을 블록 암호에 직접 넣는 방식에서만 필요

> **[교수님 말씀 22:05]** 〔시험·중요 신호〕
> 
> 중요한 점 하나를 다시 강조
> 
> 하면, 패딩은 블록 암호를 사용하기 위해 블록 단위로 맞추는 작업입니다. 즉 패딩을 붙인 평문이 블록 암호에 직접 입력으로 들어가는 방식에서만 패딩이 필요합니다. 어떤 모드가 여기에 해당하는지는 이어서 살펴보겠습니다.

> **[작성자 주의 (교안·말씀 차이 · 개정 등)]** **교안 공통 규칙 ↔ 제로 패딩** 〔시험·중요 신호〕

## [6주차 04] 운영 모드의 개요 — 두 가지 사용 방식과 초기 벡터

### [w6-s4-1] 운영 모드 (Mode of Operation) 란 (교안 p.12)

| 모드 | 영문 | 한글 |
|---|---|---|
| **ECB** | Electronic Codebook | 전자 코드북 |
| **CBC** | Cipher Block Chaining | 암호 블록 연쇄 |
| **CFB** | Cipher Feedback | 암호 피드백 |
| **OFB** | Output Feedback | 출력 피드백 |
| **CTR** | Counter | 카운터 |

NIST SP 800-38A 가 제시하는 다섯 가지 기본 운영 모드

**[각 모드를 볼 때 확인할 네 가지]**
- ① 블록을 어떻게 이어 붙이는가 (구조)
- ② 패딩이 필요한가
- ③ 여러 블록을 동시에 처리할 수 있는가 (병렬 처리)
- ④ 전송 중 오류가 생기면 어디까지 영향을 받는가 (오류 전파)

> **[교안 강조]**
> 
> 같은 블록 암호를 쓰더라도 운영 모드에 따라 암호문의 성질과 처리 방식이 달라진다

> **[교수님 말씀 22:50]**
> 
> 오늘날 널리 쓰이는 모드 대부분은 이 다섯 가지이거나 그 변형입니다. **이름이 그 모드의 동작을 그대로 설명**한다고 생각하시면 됩니다 — 암호 블록 연쇄(Cipher Block Chaining)는 암호문 블록을 다음 블록에 연결(체이닝)한다는 뜻이고, 카운터 모드는 카운터 값을 이용한다는 뜻입니다. 오류 전파는 암호문을 전송할 때 암호문에 1비트 오류가 생기면 수신자가 복호화한 평문의 어디까지 영향을 받는가 하는 이야기입니다.

### [w6-s4-2] 블록 암호를 사용하는 두 가지 방식 (교안 p.13)

*[도식] 방식 ①: 평문 블록 m → (n 비트) → Block Cipher (키 k) → 암호문 블록 c / 방식 ②: 키 k → Stream Cipher → S(k) (키 스트림 생성기) → ⊕ m → C, 즉 C = m ⊕ S(k) (p.13)* — 도식 속 글자: 방식 ① 블록 암호 / m / n 비트 / 블록 사이즈 / Block Cipher / k / c / n 비트 / 방식 ② 스트림 방식 / k / Stream Cipher / S(k) / 키 스트림 생성기 / m / C / C = m ⊕ S(k)

**[방식 ① 평문 블록을 블록 암호에 직접 넣는다]**
- 평문이 블록 암호를 통과 → 블록 크기에 맞춰야 함
- **→ 패딩 필요**
- 복호화에는 블록 암호의 복호화 함수가 필요
- 해당 모드 : ECB, CBC

**[방식 ② 블록 암호로 만든 값을 평문과 XOR한다]**
- 블록 암호는 키 스트림을 만드는 데 사용
- 평문은 블록 암호를 통과하지 않고 XOR만 됨
- **→ 패딩 불필요 (암호문 길이 = 평문 길이)**
- **→ 복호화에도 암호화 함수만 사용**
- 해당 모드 : CFB, OFB, CTR

> **[교안 강조]**
> 
> 두 방식 모두 블록 암호를 사용하지만, 평문이 블록 암호를 "통과하는가"가 다르다

> **[교수님 말씀 25:01]** 〔시험·중요 신호〕
> 
> 이 구분을 먼저 이해하면 뒤에서 볼 각 모드의 특성이 쉽게 정리됩니다. 두 번째 방식은 결국 **스트림 암호가 동작하는 방식과 같습니다**. 평문이 5바이트라면 키 스트림 5바이트와 XOR하면 되고 암호문도 5바이트가 됩니다. 또 평문이 블록 암호를 통과하지 않으므로 수신자도 같은 키로 키 스트림을 만들어 XOR하면 되어 **복호화 함수가 따로 필요 없다**는 점만 잘 기억해 주시면 좋겠습니다.

### [w6-s4-3] 초기 벡터 (IV) 의 역할 (교안 p.14)

**[초기 벡터가 없다면]**
- 블록 암호는 같은 입력 → 항상 같은 출력
- 같은 데이터를 두 번 암호화하면 암호문이 동일
- **두 메시지가 같은지 공격자가 알 수 있음**
- **같은 값을 가진 데이터가 그대로 드러남**

**[초기 벡터의 역할]**
- 암호화할 때마다 달라지는 값을 하나 더 넣음
- 같은 평문을 암호화해도 매번 다른 암호문
- **→ 암호문만 보고는 같은 데이터인지 알 수 없음**

| 성질 | 내용 |
|---|---|
| **비밀 값이 아님** | 복호화 시 필요하므로 암호문과 함께 전달 · 저장 (앞에 붙이는 것이 일반적) |
| **매번 달라야 함** | 같은 키로 같은 IV를 다시 사용하면 안 됨 |
| **예측 불가 조건** | 모드에 따라 다음 IV를 예측할 수 없어야 함 |
| **만드는 방법** | 암호용 안전한 난수 발생기로 생성 |

> **[교안 강조]**
> 
> IV = 같은 평문을 매번 다른 암호문으로 만들기 위한 값 (ECB를 제외한 모든 모드에서 사용)

> **[교수님 말씀 29:24]**
> 
> IV가 비밀이 아니어도 되는 이유는 공격자가 IV를 알더라도 **키를 모르면 평문을 알 수 없기** 때문입니다. 그래서 보통 암호문 앞에 IV를 붙여 함께 전달하거나 저장합니다. 이 때문에 일부에서는 초기 벡터를 그냥 **난수**라고 부르기도 합니다.

> **[보충 (교수님 설명 아님)]** **4주차와 연결 — IV는 "확률적 암호화"의 장치 — 교수님 설명 아님**
> 
> 4주차에서 결정적 암호화(같은 평문 → 같은 암호문)는 IND-CPA를 만족하지 못하므로 무작위 값을 섞는 확률적 암호화가 필요하다고 배웠습니다. 운영 모드에서 그 무작위 값 역할을 하는 것이 IV입니다. IV가 없는 ECB가 바로 결정적 암호화라서 다음 섹션의 패턴 문제가 생깁니다.

> **[보충 (교수님 설명 아님)]** **IV 조건 — 교안보다 정확히 — 교수님 설명 아님**
> 
> 교안은 "예측 불가"를 CBC에만 붙였지만, 기준 문서(NIST SP 800-38A)는 **CBC와 CFB 둘 다** IV가 예측 불가해야 한다고 정합니다. OFB는 메시지마다 고유(nonce)하면 되고, CTR은 카운터 블록이 겹치지 않으면 됩니다. 시험 답은 교안 문장(매번 달라야 함, CBC는 예측 불가)으로 쓰되, "**CBC만** 예측 불가"라고 단정하지는 마세요.


## [6주차 05] ECB (Electronic Codebook) 모드와 그 한계

### [w6-s5-1] ECB (Electronic Codebook) 모드 (교안 p.15)

*[도식] Encryption — Pᵢ (n bits) → [K → E] → Cᵢ (n bits), 블록 사이를 잇는 화살표(체인) 없음* — 도식 속 글자: P₁ (n bits) / E / K / C₁ (n bits) / P₂ (n bits) / E / K / C₂ (n bits) / P_N (n bits) / E / K / C_N (n bits) / •••

*[도식] Decryption — Cᵢ (n bits) → [K → D] → Pᵢ (n bits). 범례: E: Encryption, D: Decryption, Pᵢ: Plaintext block i, Cᵢ: Ciphertext block i, K: Secret key (p.15)* — 도식 속 글자: C₁ (n bits) / D / K / P₁ (n bits) / C₂ (n bits) / D / K / P₂ (n bits) / C_N (n bits) / D / K / P_N (n bits) / •••

왼쪽 : 암호화 / 오른쪽 : 복호화 — 블록마다 독립적으로 처리 (교안은 두 그림을 좌우로 배치)

**[동작]**
- Cᵢ = E_K(Pᵢ)
- Pᵢ = D_K(Cᵢ)
- 블록 사이에 연결 없음

**[특성]**
- 패딩 필요 / IV 사용 안 함
- 암호화 · 복호화 모두 병렬 처리 가능
- 원하는 블록만 복호화 가능
- **오류는 해당 블록에만 영향**

> **[교안 강조]**
> 
> 같은 평문 블록 → 항상 같은 암호문 블록 : 이 성질이 어떤 결과를 낳는지 확인해 보자

> **[교수님 말씀 31:21]** 〔시험·중요 신호〕
> 
> 전자 코드북이라는 이름은 키가 정해지면 평문 블록과 암호문 블록의 대응표, 즉 **코드북 하나가 정해진다**는 의미로 붙었습니다. 전송 중 암호문 한 블록에 1비트 오류가 생기면 그 암호문과 대응되는 평문 블록 전체에 오류가 생기고, 나머지 블록은 전혀 영향을 받지 않습니다. 구조가 단순하고 처리도 빠르지만 중요한 한계가 있습니다.

### [w6-s5-2] ECB의 한계 ① : 데이터의 패턴이 남는다 (교안 p.16)

*[교안 사진 내용]*

- **다른 모드로 암호화**: 전체가 균일한 컬러 랜덤 노이즈 — 펭귄 형태를 전혀 알아볼 수 없음

**[왜 패턴이 남는가]**
- 같은 색이 이어지는 영역 = 같은 평문 블록
- ECB : 같은 평문 블록 → 같은 암호문 블록
- **색만 바뀌고 모양은 그대로**

**[개인정보 처리에서의 의미]**

- 값의 종류가 적으면(성별 · 등급 등) 개수를 세어 값 추측 가능

### [w6-s5-3] ECB의 한계 ② : 블록을 복사해 붙일 수 있다 (교안 p.17)

**[상황]**
- 이름 · 점수 표에서 점수 컬럼만 ECB로 암호화
- 공격자 이브는 키를 모름
- 다만 앨리스의 점수가 더 높다는 사실은 알고 있음

**[공격]**

- 블록 잘라내기 · 순서 바꾸기도 가능

**[공격 전]**
| 이름 | 암호화된 점수 (원본 점수) |

| Bob | 3DE9001F (80) |
| Eve | 549F2D4F (50) |

**[공격 후 — 덮어쓰기]**
| 이름 | 암호화된 점수 (원본 점수) |
|---|---|
| Alice | 0F14D3F2 (90) |
| Bob | 3DE9001F (80) |
| Eve | **0F14D3F2 (90)** ← 덮어쓰기 |

> **[교안 강조]**

> ECB는 패턴이 남고 블록 단위 조작이 쉬움 → 여러 표준과 지침에서 단독 사용을 권하지 않음

## [6주차 06] CBC (Cipher Block Chaining) 모드

### [w6-s6-1] CBC (Cipher Block Chaining) 모드 (교안 p.18)

*[도식] 암호화 — P₁ (n bits) ⊕ (IV) → E (K) → C₁ (n bits), C₁이 점선으로 블록 2의 ⊕로 / P₂ ⊕ C₁ → E → C₂ / … / P_N ⊕ C_{N−1} → E → C_N* — 도식 속 글자: P₁ (n bits) / E / K / C₁ (n bits) / IV / P₂ (n bits) / E / K / C₂ (n bits) / P_N (n bits) / E / K / C_N (n bits) / •••

*[도식] 복호화 — C₁ → D (K) → ⊕ (IV) → P₁ / C₂ → D → ⊕ C₁ → P₂ / … / C_N → D → ⊕ C_{N−1} → P_N (p.18)* — 도식 속 글자: C₁ (n bits) / D / K / P₁ (n bits) / IV / C₂ (n bits) / D / K / P₂ (n bits) / C_N (n bits) / D / K / P_N (n bits) / •••

왼쪽 : 암호화 (앞 암호문과 XOR 후 암호화) / 오른쪽 : 복호화 (교안은 좌우 배치, 복호화 그림은 화살표가 아래에서 위로)

**[동작]**
- 암호화 : Cᵢ = E_K(Pᵢ ⊕ Cᵢ₋₁) — C₀ 자리에 초기 벡터(IV) 사용
- 복호화 : Pᵢ = D_K(Cᵢ) ⊕ Cᵢ₋₁

**[기본 성질]**
- 평문 블록을 블록 암호에 직접 입력 → 패딩 필요
- 복호화에 D 함수 필요
- 초기 벡터 사용

> **[교안 강조]**
> 
> CBC = 앞 블록의 암호문을 다음 블록에 섞어 블록들을 사슬처럼 연결

> **[교수님 말씀 38:40]**
> 
> 수신자가 IV를 알아야 첫 번째 평문을 복구할 수 있으므로 보통 IV를 **C₀처럼** 암호문과 함께 전달합니다.

### [w6-s6-2] CBC 모드의 특성 ① : 연결성과 병렬 처리 (교안 p.19)

*[도식] P₂와 P_N이 같은 평문 블록(빨간 "=")이어도 C₂와 C_N은 서로 다른 암호문 블록(빨간 "≠") — 같은 평문 블록(P₂ = Pₙ)이라도 암호문 블록은 서로 다름 (p.19)* — 도식 속 글자: P₁ (n bits) / E / K / C₁ (n bits) / IV / P₂ (n bits) / E / K / C₂ (n bits) / P_N (n bits) / E / K / C_N (n bits) / ••• / = / ≠

> **[교안 강조]**
> 
> 연결성 덕분에 같은 평문 블록도 다른 암호문이 됨 (ECB의 패턴 문제 해결)

**[병렬 처리]**
- 암호화 : 앞 블록의 암호문이 나와야 다음 블록 처리 가능 → 순서대로만 처리 (병렬 불가)
- 복호화 : 필요한 앞 암호문을 이미 모두 가지고 있음 → 여러 블록 동시 처리 가능 (병렬 가능)

**[초기 벡터 조건]**
- IV가 매번 같으면 첫 블록의 패턴이 드러남
- 공격자가 다음 IV를 예측할 수 있으면 — 자신이 고른 평문을 넣어 특정 값을 확인할 수 있음
- → 매번 다르고 예측 불가능한 난수 IV 필요

> **[교수님 말씀 40:56]**
> 
> 복호화는 화살표가 거꾸로 올라가는데, 복호화에 필요한 암호문 블록들은 이미 받은 것이라 모두 알고 있으므로 앞 블록의 복호화 결과가 없어도 바로 XOR할 수 있어 병렬 처리가 가능합니다. IV를 공격자가 예측할 수 있다면 자신이 고른 평문을 넣어 특정 평문을 확인하는 공격이 가능해지므로, **CBC의 IV는 매번 바뀌고 예측할 수 없는 난수**여야 합니다.

> **[보충 (교수님 설명 아님)]** **"다음 IV를 예측하면" 공격의 구체적인 모습 — 교수님 설명 아님**
> 
> 이전 메시지의 첫 블록이 C = E(P ⊕ IV_old)이고 공격자는 P가 "YES"인지 "NO"인지만 모른다고 합시다. 다음 IV_next를 미리 알면 추측 G에 대해 G ⊕ IV_old ⊕ IV_next를 암호화 요청합니다(선택 평문 공격). 그러면 E(G ⊕ IV_old ⊕ IV_next ⊕ IV_next) = E(G ⊕ IV_old)가 되어, G = P일 때만 결과가 C와 같아집니다 — 키 없이 평문을 확인합니다.

### [w6-s6-3] CBC 모드의 특성 ② : 오류가 번지는 범위 (교안 p.20)

*[도식] Cᵢ₋₁(정상) → 정상 평문 / Cᵢ(4번째 칸 1비트 오류) → Pᵢ 8칸 전체 손상 / Cᵢ₊₁(정상) ⊕ 오류 포함 Cᵢ → Pᵢ₊₁의 같은 4번째 칸만 손상 (p.20)* — 도식 속 글자: Cᵢ₋₁ / 복호화 / K / Pᵢ₋₁ / 정상 평문 / Cᵢ / 복호화 / K / Pᵢ / 오류가 발생한 평문 / Cᵢ₊₁ / 복호화 / K / Pᵢ₊₁ / 오류가 발생한 평문 / 오류가 발생한 암호문 Cᵢ (4번째 칸 = 1비트 오류)

**[오류가 번지는 범위]**
- Pᵢ : 블록 전체 손상 — 블록 암호는 입력 1비트만 달라져도 출력이 완전히 달라짐
- Pᵢ₊₁ : 같은 위치 1비트만 반전
- Pᵢ₊₂ 이후 : 정상 복호화
- → 오류가 두 블록에서 멈춤 (자기 복구; Self-recovering)

> **[교안 강조]**
> 
> Cᵢ의 1비트 오류 → Pᵢ 전체 손상 + Pᵢ₊₁의 같은 위치 1비트 반전

> **[교수님 말씀 43:01]**
> 
> 블록 암호에서는 입력의 1비트만 달라져도 출력이 완전히 달라지므로 Pᵢ 전체에 오류가 생깁니다. 다음 블록은 Cᵢ₊₁ 자체는 정상이라 복호화 값은 정상인데, 1비트 오류가 있는 Cᵢ와 XOR되므로 대응되는 위치만 오류가 납니다. 그 이후에는 영향이 없어서 이를 자기 복구(Self-recovering)라고도 부릅니다.


## [6주차 07] CFB (Cipher Feedback) 모드

### [w6-s7-1] CFB (Cipher Feedback) 모드 (교안 p.21)

*[도식] IV → S₁ [n bits] → E (K) → T₁ (왼쪽 검은 부분 = 선택되는 r비트) → k₁ [r bits] → ⊕ ← P₁ [r bits] → C₁ [r bits], C₁이 점선으로 다음 블록 S₂ 오른쪽으로 들어감(되먹임) … C_{N−1} → S_N (p.21)* — 도식 속 글자: S₁ [n bits] / IV / E / K / T₁ / k₁ r bits / P₁ [r] / C₁ [r] / S₂ [n bits] / ← / E / K / T₂ / k₂ r bits / P₂ [r] / C₂ [r] / S_N [n bits] / ← / E / K / T_N / k_N r bits / P_N [r] / C_N [r] / •••

범례: E : Encryption / D : Decryption / Sᵢ: Shift register / Pᵢ: Plaintext block i / Cᵢ: Ciphertext block i / Tᵢ: Temporary register / K: Secret key / IV: Initial vector (S₁). 상단 "←" = 왼쪽으로 쉬프트. 범례에 D(Decryption)가 있으나 그림은 암호화만 표시.

**앞 블록의 암호문을 블록 암호의 입력으로 되먹임**

**[기본 성질]**
- 블록 암호 출력과 평문을 XOR — 패딩 불필요, 복호화에도 E 함수만 사용
- 블록보다 작은 단위(바이트 등)로도 처리 가능

**[병렬 처리와 오류]**
- 암호화 : 순서대로만 가능 (병렬불가)
- 복호화 : 병렬 가능
- **오류 : 해당 블록 1비트 + 쉬프트 레지스터에서 오류가 사라질 때 까지 다음 블록 전체**

> **[교안 강조]**
> 
> CFB = 암호문을 되먹여 다음 블록의 입력으로 사용 (블록 암호를 스트림 암호처럼 사용)

> **[교수님 말씀 44:45]**
> 
> 첫 블록에서 시프트 레지스터에 들어 있는 IV를 암호화하고, 출력에서 일부를 떼어 평문과 XOR해 암호문을 만듭니다. 다음 블록은 방금 나온 암호문을 시프트 레지스터에 밀어 넣어 다시 암호화합니다. 암호문을 계속 되먹인다고 해서 암호문 피드백이라는 이름이 붙었습니다. 암호문 1비트에 오류가 나면 해당 평문의 같은 위치 1비트에 오류가 나고, 오류 난 암호문이 시프트 레지스터로 들어가 출력이 잘못되므로 **그 암호문이 시프트 레지스터에서 빠져나갈 때까지** 이후 평문 블록 전체에 오류가 생깁니다.

*[교안 사진 내용]*
- **교수님 화면 손필기 (47:23~49:03)**: C₁ 칸에 붉은 세로선(오류 비트) → 아래쪽 XOR에서 P₁ 칸의 같은 위치에 붉은 세로선, S₂ 칸으로 향하는 붉은 화살표와 T₂ · P₂ 칸의 붉은 짧은 획들로 "다음 블록 전체 오류"를 표시하심.

> **[보충 (교수님 설명 아님)]** **"레지스터에서 빠져나갈 때까지"를 숫자로 — 교수님 설명 아님**
> 
> 블록 128비트(n), 한 번에 r비트씩 처리한다고 하면 오류 비트가 섞인 암호문 조각은 레지스터 안에서 매번 r비트씩 왼쪽으로 밀려 n/r번 뒤에 빠져나갑니다. r = n = 128이면 다음 1블록, r = 8(바이트 단위)이면 이후 16바이트가 깨집니다. 그래서 교안 비교표는 "Pᵢ₊₁ 이후 쉬프트 레지스터 나갈 때 까지 전체"라고 적습니다. (교안 md 작성 시 CFB-128 · CFB-8로 재계산해 확인된 내용)


## [6주차 08] OFB (Output Feedback) 모드

### [w6-s8-1] OFB (Output Feedback) 모드 (교안 p.22)

*[도식] IV → S₁ [n bits] → E (K) → T₁ → r bits (•) → ⊕ ← P₁ [r bits] → C₁ [r bits], ⊕ 직전의 r bits 지점(•)에서 점선이 S₂로 — 암호문이 아니라 블록 암호 출력이 되먹임됨 … T_{N-1} → S_N (p.22)* — 도식 속 글자: S₁ [n bits] / IV / E / K / T₁ / r bits / P₁ [r] / C₁ [r] / S₂ [n bits] / ← / E / K / T₂ / r bits / P₂ [r] / C₂ [r] / S_N [n bits] / ← / E / K / T_N / r bits / P_N [r] / C_N [r] / •••

범례: E : Encryption / D : Decryption / Sᵢ: Shift register / Pᵢ: Plaintext block i / Cᵢ: Ciphertext block i / Tᵢ: Temporary register / K: Secret key / IV: Initial vector (S₁)

**블록 암호의 "출력"을 다음 입력으로 되먹임 (평문 · 암호문과 무관)**

**[기본 성질]**
- 키 스트림이 평문과 무관 → 미리 계산 가능(전처리)
- **오류는 해당 비트에만 영향 (번지지 않음)**
- 패딩 불필요, 복호화에도 E 함수만 사용
- 병렬 처리 : 암호화 · 복호화 모두 불가

**[주의]**
- 같은 키 + 같은 IV → 같은 키 스트림
- 두 암호문을 XOR하면 두 평문의 XOR이 드러남

> **[교안 강조]**
> 
> OFB = 블록 암호의 출력만 이어 붙여 키 스트림을 만듦 → 오류가 번지지 않음

> **[교수님 말씀 49:44]** 〔시험·중요 신호〕
> 
> OFB는 이어지는 값들이 평문이나 암호문과 전혀 무관하게 **키와 IV만으로 결정**됩니다. 그래서 평문이 도착하기 전에 미리 계산해 둘 수 있고(전처리), 암호문에 오류가 생겨도 다른 블록의 입력에 영향을 주지 않아 같은 위치 1비트만 오류가 납니다 — **잡음이 많은 통신 환경에 유리**합니다. 다만 같은 키에 같은 IV를 쓰면 완전히 같은 키 스트림이 나오므로 IV를 절대 재사용하지 않는 것이 이 모드의 핵심 규칙입니다. 키 스트림은 앞의 출력을 이어받아 만들므로 암 · 복호화 모두 블록을 동시에 처리할 수는 없지만 미리 계산해 두는 것은 가능합니다.

*[교안 사진 내용]*
- **교수님 화면 손필기 (50:22~51:35)**: C₁ 칸과 P₁ 칸에 붉은 세로선을 하나씩 그어 "같은 위치 1비트만 오류"를 표시하심.

> **[보충 (교수님 설명 아님)]** **CFB와 OFB의 차이 한 줄 — 교수님 설명 아님**
> 
> 되먹이는 값이 CFB는 **암호문**(그래서 오류가 레지스터를 타고 번짐 · 키 스트림이 평문에 의존), OFB는 **블록 암호 출력**(오류가 안 번짐 · 키 스트림을 미리 만들 수 있음)입니다.


## [6주차 09] CTR (Counter) 모드

### [w6-s9-1] CTR (Counter) 모드 (교안 p.23)

*[도식] 되먹임 화살표 없음 — IV [n bits] → E (K) → k₁ [n bits] → ⊕ ← P₁ [n bits] → C₁ / Counter [n bits] → E (K) → k₂ → ⊕ ← P₂ → C₂ / … (그림에는 첫 블록 입력이 "IV", 이후 블록은 "Counter"로 표기 — 카운터 증가식은 그림에 없음) (p.23)* — 도식 속 글자: IV [n bits] / E / K / k₁ [n bits] / n bits / P₁ [n] / C₁ [n] / Counter [n bits] / E / K / k₂ [n bits] / n bits / P₂ [n] / C₂ [n] / Counter [n bits] / E / K / k_N [n bits] / n bits / P_N [n] / C_N [n] / •••

**되먹임 없음 : 블록마다 카운터 값을 암호화해 평문과 XOR**

**[기본 성질]**
- 키 스트림이 카운터 값만으로 결정 — 암호화 · 복호화 모두 병렬 처리 가능
- 원하는 위치의 블록만 골라 처리 가능
- 패딩 불필요, 복호화에도 E 함수만 사용
- **오류는 해당 비트에만 영향**

**[주의]**
- 같은 키 + 같은 카운터 값 재사용 금지
- 키 스트림이 그대로 재사용됨

> **[교안 강조]**
> 
> CTR = 카운터 값을 암호화해 키 스트림을 만듦 → 병렬 처리와 임의 위치 접근이 쉬움

> **[교수님 말씀 51:44]**
> 
> CTR 모드가 **현재 가장 널리 쓰이는 모드**입니다. 물론 그대로 쓰는 것이 아니라 변형을 써서 쓰고 있긴 합니다. 카운터는 **1씩 증가하는 값**이라고 생각하시면 됩니다. 열 번째 블록이 필요하면 열 번째 카운터만 암호화해서 그 블록을 골라 처리할 수 있으므로, 큰 파일이나 디스크의 중간을 읽거나 복호화하는 데 적합합니다.

> **[보충 (교수님 설명 아님)]** **왜 "1씩 증가"면 충분한가 — 교수님 설명 아님**
> 
> 블록 암호는 입력이 1비트만 달라도 출력이 완전히 달라지므로(쇄도 효과), 카운터가 1, 2, 3 …처럼 규칙적이어도 E_K(카운터)는 무작위처럼 보이는 키 스트림이 됩니다. 중요한 것은 값이 예측 불가능한 것이 아니라 **같은 키로 같은 카운터가 두 번 쓰이지 않는 것**입니다. 그래서 실제로는 메시지마다 다른 시작값(난수 부분 + 블록 번호)을 씁니다.

> **[작성자 주의 (교안·말씀 차이 · 개정 등)]** **이 보충과 교수님 말씀의 차이** 〔시험·중요 신호〕
> 
> 위 보충(CTR은 **중복만 없으면** 됨)은 확립된 기준(NIST SP 800-38A)이고, 교수님은 정리(1:11:13)에서 "키 스트림 방식에서도 **항상 랜덤한 값으로 예측 불가능하게**, 재사용하면 안 된다"고 더 엄격하게 말씀하셨습니다. 시험에서는 두 기준을 모두 만족하는 "**매번 달라야 하고 절대 재사용 금지**"로 쓰면 안전합니다.


## [6주차 10] 다섯 가지 모드의 비교

### [w6-s10-1] 다섯 가지 모드의 비교 ① : 구조와 패딩 (교안 p.24)

| 구분 | ECB | CBC | CFB | OFB | CTR |
|---|---|---|---|---|---|
| **블록 암호 사용 방식** | 평문을 직접 암호화 | 평문을 직접 암호화 | 만든 값과 XOR | 만든 값과 XOR | 만든 값과 XOR |
| **블록을 잇는 방법** | 연결 없음 | 앞 암호문을 평문에 XOR | 앞 암호문을 입력으로 | 출력을 다시 입력으로 | 카운터 값 사용 |
| **패딩** | **필요** | **필요** | 불필요 | 불필요 | 불필요 |
| **초기 벡터** | **사용 안 함** | 사용 | 사용 | 사용 | 카운터 시작값 |
| **복호화에 D 함수** | 필요 | 필요 | 불필요 | 불필요 | 불필요 |

> **[교안 강조]**
> 
> 패딩 · 복호화 함수의 필요 여부는 모두 "평문이 블록 암호를 통과하는가"에서 나온다

> **[교수님 말씀 55:52]**
> 
> CTR 모드는 카운터의 시작값으로 시작하는데, 그것이 **IV의 역할**을 합니다.

### [w6-s10-2] 다섯 가지 모드의 비교 ② : 병렬 처리와 오류 (교안 p.25)

| 구분 | ECB | CBC | CFB | OFB | CTR |
|---|---|---|---|---|---|
| **암호화 병렬 처리** | **○** | **✕** | **✕** | **✕** | **○** |
| **복호화 병렬 처리** | **○** | **○** | **○** | **✕** | **○** |
| **원하는 블록만 처리** | **○** | **✕** | **✕** | **✕** | **○** |
| **전송 오류의 영향** | Pᵢ 전체 | Pᵢ 전체 + Pᵢ₊₁ 1비트 | Pᵢ 1비트 + Pᵢ₊₁ 이후 쉬프트 레지스터 나갈 때 까지 전체 | 해당 비트 | 해당 비트 |

○ = 초록 동그라미(가능), ✕ = 빨간 X(불가) — 교안 표기

**[선택할 때 보는 점]**
- 큰 파일의 임의 위치 접근 · 빠른 처리 → 카운터 방식
- 전송 오류가 잦은 환경 → 오류가 번지지 않는 방식(OFB · CTR)
- 블록 단위 패턴이 그대로 남는 ECB는 제외

> **[교안 강조]**
> 
> 같은 블록 암호라도 운영 모드에 따라 처리 방식과 오류 특성이 달라진다

> **[교수님 말씀 59:14]**
> 
> 여러분들이 **직접 이 다섯 가지 모드의 암호화 과정과 복호화 과정을 손으로 그려 보시면서** 병렬 처리와 오류가 어떻게 발생하는지, 각각의 차이점이 무엇인지 정리해 나가시면 학습에 더 유리할 거라고 생각합니다.

> **[보충 (교수님 설명 아님)]** **표를 외우지 않고 유도하는 법 — 교수님 설명 아님**
> 
> ① "평문이 블록 암호를 통과하나?" → ECB · CBC만 예 → 패딩 · D 함수 필요. ② "블록 i를 계산하려면 무엇이 필요한가?" ECB = Pᵢ만, CTR = 카운터만 → 암 · 복호화 병렬 · 임의 접근 ○. CBC · CFB 암호화 = 앞 암호문이 먼저 나와야 함 → ✕, 복호화 = 앞 암호문은 이미 받았음 → ○. OFB = 앞 출력이 필요하고 그것은 받은 것이 아님 → 둘 다 ✕. ③ 오류: 오류 난 암호문이 어디에 다시 쓰이는지 따라가면 됩니다(CBC → 다음 블록 XOR, CFB → 레지스터, OFB · CTR → 어디에도 안 쓰임).

> **[보충 (교수님 설명 아님)]** **"원하는 블록만 처리" ✕ 는 교안 기준 — 교수님 설명 아님**
> 
> 교안 표와 교수님(57:35)은 CBC · CFB를 ✕로 두었지만, **복호화**는 사실 원하는 블록만 할 수 있습니다 — CBC는 Pᵢ = D_K(Cᵢ) ⊕ Cᵢ₋₁이라 받은 암호문 두 블록만 있으면 됩니다(위 "유도하는 법"의 복호화 병렬 ○와 같은 이유). 원하는 블록만 **암호화**하는 것은 불가능합니다. 시험에서는 교안 표대로 ✕로 답하세요.
> 
> 또 "OFB · CTR은 오류가 번지지 않는다"는 **비트가 뒤집히는 오류**에만 해당합니다. 비트가 빠지거나 끼어들어 동기가 어긋나면 OFB · CTR은 그 뒤가 모두 깨집니다(교안 범위 밖).

### [w6-s11-2] [Appendix] 암호화가 보장하는 것과 보장하지 않는 것 (교안 p.26)

| 암호화가 보장하는 것 | 암호화가 보장하지 않는 것 |
|---|---|
| ▪ 키가 없으면 내용을 읽을 수 없음<br>– = 기밀성 (Confidentiality) | ▪ 키가 없어도 암호문을 바꿀 수 있음<br>– **바뀐 사실을 수신자가 모를 수 있음**<br>▪ 순서 바꾸기 · 잘라내기도 막지 못함 |

- 공격자 : 내용을 읽으려 함 → **암호화가 막아 준다**
- 공격자 : 내용을 바꾸려 함 → **암호화는 막아 주지 못한다**

**앞에서 본 예**

- ECB 모드에서 점수 블록을 복사해 덮어쓴 경우 — 키를 모르는 공격자가 데이터를 바꾸었지만 암호는 깨지지 않음
- 다른 모드에서도 형태만 다를 뿐 비슷한 조작이 가능

> **[교수님 말씀 1:01:04]**
> 
> 그래서 실제 시스템에서는 암호화와 함께 데이터가 바뀌었는지 확인하는 수단을 같이 써야 합니다. 그것이 뒤에서 살펴볼 무결성 내용이고, 그 수단을 암호화와 하나로 묶어 제공하는 방식이 인증 암호입니다.

### [w6-s11-3] [Appendix] 인증 암호 (AEAD) 의 개념 (교안 p.27)

*[도식] 입력 3개: 비밀키 K / 난수 N (매번 다름) / 평문 P → 인증 암호 (AEAD) → 출력 2개: 암호문 C / 인증 태그 T (p.27)* — 도식 속 글자: 비밀키 K / 난수 N (매번 다름) / 평문 P / 인증 암호 (AEAD) / 암호문 C / 인증 태그 T

**[수신자 측]**
- 같은 키 · 난수로 태그를 다시 계산해 비교
- 같으면 복호화, 다르면 버림 — **복호화 전에 먼저 확인**

**[인증 암호를 쓰는 이유]**
- 기밀성(내용 숨기기)과 무결성(바뀌었는지 확인)을 한 번에 제공
- 두 기능을 따로 구현하면서 생기는 실수를 줄일 수 있음
- 통신 프로토콜과 저장 암호화에서 널리 사용

> **[교수님 말씀 1:01:44]**
> 
> 인증 암호(Authenticated Encryption with Associated Data)의 입력 중 난수는 앞에서 본 초기 벡터와 같은 역할을 한다고 생각하시면 됩니다. 인증 태그는 암호문이 바뀌었는지 확인하기 위한 짧은 값으로, 올바른 비밀키를 가진 쪽만 올바르게 만들 수 있습니다. 태그를 만드는 방법이나 무결성의 성질은 해시 함수나 메시지 인증을 다루는 주제에서 더 살펴보겠습니다.

### [w6-s11-5] [Appendix] 대표적인 인증 암호 : CCM과 GCM (교안 p.29)

| CCM (Counter with CBC-MAC) | GCM (Galois/Counter Mode) |
|---|---|
| ▪ 암호화 : 카운터 모드<br>▪ 인증 : 블록을 사슬로 이어 가며 태그 생성<br>– 태그 계산은 순서대로만 가능<br>▪ 블록당 블록 암호 연산 2회 (암호화 + 인증)<br>▪ 무선랜 보안 규격 등에서 사용 | ▪ 암호화 : 카운터 모드<br>▪ 인증 : 유한체 곱셈으로 태그 생성<br>– 여러 블록을 동시에 계산 가능 → 빠름<br>▪ 하드웨어 가속이 잘 적용됨<br>▪ 웹 통신 등 고속 환경에서 널리 사용 |

| 구분 | CCM | GCM |
|---|---|---|
| **암호화 방식** | 카운터 모드 | 카운터 모드 |
| **태그 생성 방식** | 블록 사슬 방식 (순차) | 유한체 곱셈 (병렬 가능) |
| **속도** | 상대적으로 느림 | 빠름 |
| **추가 인증 데이터** | 지원 | 지원 |
| **난수 재사용** | **금지** | **금지** |

> **[교안 강조]**
> 
> 두 방식 모두 암호화는 카운터 모드 — 차이는 인증 태그를 만드는 방법과 속도

> **[교수님 말씀 1:06:43]** 〔시험·중요 신호〕
> 
> CCM(Counter with CBC-MAC)은 이름에 앞에서 본 카운터 모드와 CBC 모드가 들어 있습니다. 암호화는 카운터 모드로, 인증 태그는 CBC처럼 블록 사슬로 이어 가며 만들어서 블록당 블록 암호 연산이 두 번 필요합니다. 두 방식 모두 **가장 중요한 것은 난수(IV)를 절대로 재사용하면 안 된다**는 점이고, 이 정도만 상식으로 알고 계시면 됩니다.

### [w6-sk-2] 핵심 정리 (1) : 패딩과 운영 모드 (교안 p.30)

| 항목 | 내용 |
|---|---|
| **패딩** | 마지막 블록을 채우고, 복호화 후 정확히 제거할 수 있어야 함<br>PKCS#7 : 채울 바이트 수 n을 값 n으로 n개 (배수여도 한 블록 추가) |
| **두 가지 사용 방식** | 평문을 블록 암호에 직접 입력 (ECB · CBC) → 패딩 필요, D 함수 필요<br>만든 값과 평문을 XOR (CFB · OFB · CTR) → 패딩 불필요, E 함수만 사용 |
| **모드별 요점** | ECB : 연결 없음 / CBC : 앞 암호문을 평문에 XOR<br>CFB : 앞 암호문을 입력으로 / OFB : 출력을 입력으로 / CTR : 카운터 값 사용 |
| **초기 벡터(IV)** | 같은 평문을 매번 다른 암호문으로 만들기 위한 값, 비밀은 아님<br>매번 달라야 함 (CBC는 예측 불가), 같은 키 + 같은 IV → 같은 키 스트림 |

### [w6-sk-3] 핵심 정리 (2) : 모드 비교 (교안 p.31)

| 항목 | 내용 |
|---|---|
| **병렬 처리** | ECB · CTR : 암호화 · 복호화 모두 가능, 원하는 블록만 처리 가능<br>CBC · CFB : 암호화 불가, 복호화는 가능 / OFB : 둘 다 불가 |
| **전송 오류의 영향** | ECB : 해당 블록 / CBC : 해당 블록 + 다음 블록 1비트<br>CFB : 해당 블록 1비트 + 쉬프트 레지스터에서 나갈 때 까지 블록 /<br>OFB · CTR : 해당 비트 |

> **[작성자 주의 (교안·말씀 차이 · 개정 등)]** **말씀 판독 ↔ 교안 — p.31 병렬 처리 줄**

CTR은 암 · 복호화 모두 병렬 가능하므로 **CBC · CFB가 맞습니다**(말실수 또는 판독 오류로 보임). 마찬가지로 57:09의 "CTR 모드, OFB 모드는 복호화도 병렬 불가"는 바로 이어서 "CTR은 병렬 가능"으로 고쳐 말씀하셨습니다 — 복호화 병렬 ✕는 **OFB뿐**입니다.
