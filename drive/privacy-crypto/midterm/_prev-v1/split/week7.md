### [w7-s1-2] 대칭키 암호 시스템의 문제점 (교안 p.4)

1. 안전한 채널을 통해 송/수신자 간 서로 동일한 **키를 사전에 공유할 필요**가 있음 — 키 분배 문제 (Key distribution problem)
2. n명이 서로 비밀통신을 하기 위해서는 n(n−1)/2 개의 키가 필요함 — Ex) 재학생 1000명이 대칭키 암호 통신하기 위해 필요한 키는 1인당 999개 필요, 전체 키의 수: 1000 × 999 ÷ 2 = 499,500 개 — **키 유지 관리의 어려움**
3. 송신자나 수신자의 **부인방지**를 제공하지 못함 — 부인방지: 메시지를 전송한 송신자나 수신한 수신자가 나중에 그 사실을 부인할 수 없도록 하는 기능

*[도식] 4명(A, B, C, D)이 서로 양방향으로 모두 연결된 완전 그래프 — A ↔ B : K_AB, A ↔ C : K_AC, A ↔ D : K_AD, B ↔ C : K_BC, B ↔ D : K_BD, C ↔ D : K_CD → n(n−1)/2 공식의 예 (p.4)* — 도식 속 글자: K_AB / K_AC / K_AD / K_BC / K_BD / K_CD / A / B / C / D / 4명이면 키 6개 = 4×3/2 (각자 3개씩 보유)

> **[교안 강조]**
> 
> 키 분배 문제 · 키 개수 문제 · 부인방지 불가 → 공개키 암호가 등장한 배경

> **[교수님 말씀 04:27]**
> 
> 그런데 안전한 채널이 이미 있다면 애초에 암호화가 필요 없겠죠. 그런 채널이 없기 때문에 키 분배 문제가 생깁니다. 천 명이 통신하면 한 사람이 999개, 전체로는 약 50만 개의 키가 생기고, 키를 만들고 나눠 주고 폐기하는 관리 자체가 큰 부담입니다. 또 송신자와 수신자가 똑같은 키를 가지고 있어서 어떤 메시지를 둘 중 누가 만들었는지 **제3자에게 증명할 방법이 없습니다** — 부인방지를 못 하는 이유입니다.

> 
> 사람을 꼭짓점, 공유 키를 간선으로 보면 모든 쌍이 연결된 **완전 그래프 Kₙ**이고 간선 수는 C(n, 2) = n(n−1)/2입니다. 그림은 K₄(간선 6개), 1000명은 K₁₀₀₀(간선 499,500개)입니다. 대칭키는 "두 사람만 아는 비밀"이라 둘이 같은 키를 쓰면 누가 보냈는지 제3자에게 증명할 수 없어 **부인방지가 안 됩니다**(4주차 MAC과 같은 이유).

### [w7-s1-3] 공개키 암호 시스템 (교안 p.5)

- **각자 한 쌍의 키 (공개키 pk, 개인키 sk) 소유** — **공개키는 모두에게 공개**되고 **개인키는 비밀**로 보관
- 공개키 pk와 개인키 sk는 서로 수학적인 관계를 가짐 — pk로부터 sk를 도출하는 것은 계산적으로 불가능 (Computationally Infeasible)
- 암/복호화 과정이 **전혀 다름** — 비대칭키 (asymmetric) 암호시스템이라 하는 이유, 개인키를 소유한 사람이 암호문을 복호화 가능

*[도식] 왼쪽: A: (pk_A, sk_A) … D: (pk_D, sk_D) / 오른쪽: Public Registry(공개키 저장소) → 1. 공개키 획득 → 2. 암호문 전송 C = Enc_{pk_B}(m) → 3. 복호화 M = Dec_{sk_B}(C), pk_B ≠ sk_B (p.5)* — 도식 속 글자: A / (pk_A, sk_A) / B / (pk_B, sk_B) / C / (pk_C, sk_C) / D / (pk_D, sk_D) / Public Registry (공개키 저장소) / Alice / Bob / 1. 공개키 획득 (pk_B) / 2. 암호문 전송 / C = Enc_{pk_B}(m) / 3. 복호화 / M = Dec_{sk_B}(C) / pk_B / sk_B / pk_B ≠ sk_B

*[교안 사진 내용]*
- 교안 그림: 사람 얼굴이 그려진 자물쇠 여러 개가 쌓인 "Public Registry", Bob 옆에 자물쇠(= pk_B)와 열쇠(= sk_B) 아이콘
- 교안 표기 그대로 — 암호화 식은 소문자 m, 복호화 식은 대문자 M (같은 평문)

> **[교안 강조]**
> 
> 공개키로 암호화 → 짝이 되는 개인키로만 복호화 / 공개키에서 개인키를 구하는 것은 계산적으로 불가능

> **[교수님 말씀 07:12]** 〔시험·중요 신호〕
> 
> 여기서 **중요한 성질이 두 가지**인데, 하나는 **암호화와 복호화에 서로 다른 키**를 쓴다는 겁니다. 암호화할 때는 밥의 공개키, 복호화할 때는 밥의 개인키 — 그래서 **비대칭키 암호**라고도 부릅니다. 공개키로 잠근 것은 공개키로 열 수 없고 짝이 되는 개인키로만 열립니다. 다른 하나는 공개키와 개인키가 **수학적으로 연결된 한 쌍**이라는 점입니다.

> **[교수님 말씀 07:39]**
> 
> 공개키(public key)는 보통 PK, 개인키(secret key)는 SK로 씁니다. 공개키와 개인키는 수학적으로 연결된 한 쌍이니 공개키에서 개인키를 계산할 수 있지 않냐고 생각할 수 있는데, **이론적으로는 가능합니다**. 다만 그 계산이 현실적인 시간 안에 끝나지 않도록 설계되어 있고, 이것이 "계산적으로 불가능"의 뜻입니다. 이 성질 덕분에 공개키를 전 세계에 공개해도 안전합니다.


## [7주차 02] 대칭키 암호와 공개키 암호의 비교 · 하이브리드 암호 시스템

### [w7-s2-1] 대칭키 암호와 공개키 암호의 비교 (교안 p.6)

| 구분 | 대칭키 암호 | 공개키 암호 |
|---|---|---|
| **키 구성** | 하나의 비밀키를 양쪽이 공유 | 공개키 + 개인키 한 쌍 |
| **비밀키 사전 공유** | **필요** | **불필요** |
| **보유 키 수 (n명)** | n − 1 개 | 자신의 키 쌍 1개 |
| **속도** | 빠름 | 느림 (수백 배 이상) |
| **같은 안전성의 키 길이** | 짧음 | 훨씬 김 |
| **대표 알고리즘** | AES, SEED, ARIA | RSA, 엘가말, 타원곡선 암호 |

**[두 방식의 관계]**
- 공개키 암호는 대칭키 암호를 대체하는 기술이 아님
- 키를 나눠 갖기 어려운 문제 → 공개키 암호가 해결
- 속도가 느린 문제 → 대칭키 암호가 해결
- 서로의 약점을 보완하는 관계 → 실제로는 함께 사용

## [7주차 03] 일방향 함수와 트랩도어 일방향 함수

### [w7-s3-1] 일방향 함수 (One-way Function) (교안 p.8)

## [7주차 04] RSA 암호의 개요와 소인수분해 문제

### [w7-s4-1] RSA 암호의 개요 (교안 p.10)

**[RSA 암호]**
- 1978년 발표 (MIT)
- Rivest · Shamir · Adleman 세 사람의 성 첫 글자
- 소인수분해 문제의 어려움에 기반 — 가장 널리 쓰이는 공개키 암호

**[사용되는 곳]**
- 웹 통신에서 서버의 신원 확인 (인증서)
- 전자문서의 서명
- 대칭키를 안전하게 전달

| 기호 | 의미 | 공개 여부 |
|---|---|---|
| **p, q** | 서로 다른 큰 소수 | **비밀** |
| **n = p × q** | 모듈러스 | 공개 |
| **e** | 공개키를 이루는 수 (n과 함께 공개) | 공개 |
| **d** | 개인키가 되는 수 | **비밀** |

**공개키 = (n, e)** **개인키 = d**

- p와 q는 키 생성 후 비밀 보관 또는 폐기 (알려지면 개인키가 계산됨)

> **[교안 강조]**
> 
> 소인수분해의 어려움 위에 세워진 가장 대표적인 공개키 암호

> **[교수님 말씀 15:55]**

### [w7-s4-2] RSA가 사용하는 문제 : 소인수분해 (교안 p.11)

*[도식] p, q → (f, easy) → N = p × q / N = p × q → (f⁻¹, difficult) → p, q (p.11 도식)* — 도식 속 글자: p, q / N = p × q / f   easy / f⁻¹   difficult / 274177 × 6700417 → (easy) → 1837100231809 / 1837100231809 → (difficult) → 274177 × 6700417

**[왜 공개키 암호의 바탕이 되는가]**
- 두 소수 p, q를 아는 사람 → N을 쉽게 계산
- N만 아는 사람 → p, q를 알 수 없음
- p와 q = 개인키를 만드는 재료, N = 공개키의 일부
- 공개키를 알려 주어도 개인키가 안전한 이유

> **[교안 강조]**
> 
> 곱셈은 쉽고 소인수분해는 어렵다 — 이 비대칭이 공개키 암호를 만든다

> **[교수님 말씀 18:33]**

## [7주차 05] RSA 키 생성 — 절차, 계산 예, 큰 소수 찾기

### [w7-s5-1] RSA 키 생성 절차 (교안 p.13)

| 단계 | 내용 | 설명 |
|---|---|---|
| 1 | 서로 다른 큰 소수 p, q 선택 | 실제로는 각각 1024비트 정도 |
| 2 | n = p × q 계산 | 공개키의 일부가 됨 |
| 3 | L = (p−1) × (q−1) 계산 | p, q를 알아야 계산할 수 있는 값 |
| 4 | 1 < e < L 이고 gcd(e, L) = 1 인 e 선택 | 공개키를 이루는 수 |
| 5 | e × d ≡ 1 (mod L) 인 d 계산 | L에 대한 e의 곱셈 역원 |

> **[교안 강조]**
> 
> d를 구하려면 L이 필요하고, L을 구하려면 p와 q가 필요하다<br>→ n에서 p, q를 찾을 수 없다면 d도 알 수 없다 (RSA 안전성의 핵심)

> **[교수님 말씀 22:24]** 〔시험·중요 신호〕
> 
> 중요한 점
> 
> 은 L을 계산하려면 p와 q를 알아야 한다는 것입니다. n만 아는 공격자는 L을 구할 수 없습니다. d는 mod L에서 e의 곱셈 역원이고, 역원이 존재해야 하므로 앞 단계에서 L과 서로소인 e를 고른 것입니다. e는 공개되어 있으니 공격자가 L만 안다면 d를 계산하는 건 굉장히 쉬워지고, 바로 이 점이 RSA의 안전성을 떠받치는 핵심입니다.

### [w7-s5-2] RSA 키 생성 계산 예 (교안 p.14)

| 단계 | 계산 | 결과 |
|---|---|---|
| ① 소수 선택 | p, q 선택 | p = 5, q = 11 |
| ② n 계산 | n = p × q | n = 5 × 11 = 55 |
| ③ L 계산 | L = (p−1)(q−1) | L = 4 × 10 = 40 |
| ④ e 선택 | 1 < e < 40, gcd(e, 40) = 1 | **e = 3** |
| ⑤ d 계산 | e × d ≡ 1 (mod 40) | **d = 27** (3 × 27 = 81 = 2×40 + 1) |

**공개키 (n, e) = (55, 3) 개인키 d = 27**

**[작은 수를 쓰면 안 되는 이유]**
- n = 55 → 5 × 11 임을 금방 알 수 있음 — L = 40, d = 27 까지 바로 계산됨
- 실제로는 n을 2048비트 이상으로 사용

> **[교수님 말씀 25:28]**
>

> **[보충 (교수님 설명 아님)]** **왜 복호화가 되나 — 오일러 정리 (교안에 없는 증명) — 교수님 설명 아님**
> 
> L = (p−1)(q−1)은 n과 서로소인 수의 개수 φ(n)입니다. **오일러 정리**: gcd(m, n) = 1이면 m^φ(n) ≡ 1 (mod n). ed = 1 + kL이므로 c^d = m^(ed) = m · (m^L)^k ≡ m · 1 = m (mod n). 그래서 d로 거듭제곱하면 평문이 돌아옵니다. (gcd(m, n) ≠ 1인 경우도 중국인의 나머지 정리로 성립하지만 시험 범위 밖으로 보입니다.)

## [7주차 06] RSA 암호화와 복호화 — 계산, 지수 연산, 전체 동작

### [w7-s6-1] RSA 암호화와 복호화 (교안 p.16)

**[RSA 암호화와 복호화]**
암호화 : c = m^e mod n<br>복호화 : m = c^d mod n<br>(단, 평문 m < n)

계산 예 : 공개키 (55, 3), 개인키 27, 평문 m = 9

| 과정 | 계산 | 결과 |
|---|---|---|
| 암호화 | 9³ mod 55 = 729 mod 55 | **c = 14** |
| 복호화 | 14²⁷ mod 55 | **m = 9** |

**[확인할 점]**
- 두 식의 모양은 같고 지수만 다름 (e ↔ d)
- 평문은 반드시 n보다 작아야 함 — 긴 메시지는 블록으로 나누거나 하이브리드 방식 사용
- 큰 거듭제곱도 곱할 때마다 나머지를 취하면 작은 수만 다루게 됨

> **[교수님 말씀 29:49]**
> 
> 평문 m은 당연히 n보다 작아야 합니다. 크면 복호화해도 원래 값이 나오지 않습니다. 그래서 2048비트보다 긴 메시지는 블록으로 나누어 각각 암호화하거나, 앞에서 본 하이브리드 방식으로 대칭키만 암호화합니다. 14의 27제곱도 곱할 때마다 55로 나눈 나머지를 취하면 작은 수로 계산되어 평문 9가 그대로 복원됩니다.

> **[보충 (교수님 설명 아님)]** **계산 확인 — 729 mod 55 — 교수님 설명 아님**
> 
> 55 × 13 = 715, 729 − 715 = 14 → c = 14. 왜 m < n이어야 하나: 결과가 mod n이라 0 ~ n−1 밖의 평문은 구별할 수 없습니다(예: m = 9와 m = 64는 n = 55에서 같은 수).

### [w7-s6-2] 지수 연산을 효율적으로 하는 방법 (교안 p.17)

**[두 가지 요령]**
- ① 곱할 때마다 모듈러스로 나눈 나머지를 취한다 — 중간에 나머지를 취해도 결과는 같음 → 수가 작게 유지됨
- ② 제곱을 반복해 필요한 것만 골라 곱한다 (제곱-곱 방법) — 지수를 2의 거듭제곱의 합으로 쪼갬 : 27 = 16 + 8 + 2 + 1

**[① 제곱을 반복해 미리 구하기 (14ˣ mod 55)]**
| 거듭제곱 | 계산 | mod 55 |
|---|---|---|
| 14² | 14 × 14 = 196 | 31 |
| 14⁴ | 31 × 31 = 961 | 26 |
| 14⁸ | 26 × 26 = 676 | 16 |
| 14¹⁶ | 16 × 16 = 256 | 36 |

**[② 필요한 것만 곱하기 (14²⁷ = 14¹⁶ × 14⁸ × 14² × 14¹)]**
| 곱하기 | 계산 | mod 55 |
|---|---|---|
| 14¹⁶ × 14⁸ | 36 × 16 = 576 | 26 |
| × 14² | 26 × 31 = 806 | 36 |
| × 14¹ | 36 × 14 = 504 | **9** |

| 지수 | 그냥 곱하면 | 제곱-곱 방법 |
|---|---|---|
| 27 | 26 번 | **7 번** |
| 2048비트 지수 | 약 2²⁰⁴⁸ 번 (불가능) | **약 3,000 번** |

> **[교수님 말씀 34:36]**
> 
> 지수가 27이라 26번과 7번 차이지만 2048비트 가까운 지수에서는 차이가 극적으로 벌어집니다. RSA 공개키 암호가 이런 요령으로 계산하기 때문에 **현실적으로 사용할 수 있다 정도로 생각**하시면 됩니다.

> **[보충 (교수님 설명 아님)]** **이산수학 · 자료구조와 연결 — 2진수와 O(log e) — 교수님 설명 아님**
> 
> 27 = 11011₍₂₎ — 1인 자리(16, 8, 2, 1)만 곱합니다. 제곱은 (비트 수 − 1)번, 곱하기는 (1의 개수 − 1)번이라 27은 4 + 3 = 7번. 지수가 k비트면 많아야 약 2k번이므로 시간 복잡도가 O(log e)입니다(그냥 곱하면 O(e)). 2048비트 지수는 제곱 약 2047번 + 곱하기 평균 약 1024번 ≈ 3,000번. ①이 가능한 이유는 합동의 성질 (a · b) mod n = ((a mod n) · (b mod n)) mod n입니다.

### [w7-s6-3] RSA의 전체 동작 (교안 p.18)

*[도식] ① Bob이 p, q를 골라 n_Bob = p × q, 공개키 (n_Bob, e_Bob) · 개인키 d_Bob 생성 → ② 공개된 채널에 공개키 공개 → ③ Alice가 수신자의 공개키를 받음 → ④ C = M^(e_Bob) mod n_Bob 으로 평문을 암호화 → ⑤ 암호문 전송 → ⑥ Bob이 m = C^(d_Bob) mod n_Bob 으로 복호화 (p.18 도식)* — 도식 속 글자: 공개 저장소 (공개 채널) / 아이디 / 공개키 (n, e) / A / (n_A, e_A) / B / (n_B, e_B) / Bob / (n_Bob, e_Bob) / Bob / 키 생성 — ① (공개키, 개인키) 생성 / 소수 p, q 선택 ⇒ n_Bob = p × q / 공개키: (n_Bob, e_Bob) / 개인키: d_Bob / 복호화 m = C^(d_Bob) mod n_Bob / ⑥ 암호문을 복호화하여 평문을 얻음 / Alice / 공개키: (n_Bob, e_Bob) 평문: M / 암호화 C = M^(e_Bob) mod n_Bob / ④ 평문을 암호화 / ② 공개된 채널에 / 공개키 공개 / ③ 수신자의 공개키 / ⑤ 암호문 전송

**[순서]**
- ① 밥이 키 쌍 생성
- ② 공개키를 공개 저장소에 등록
- ③ 앨리스가 밥의 공개키 획득
- ④ 공개키로 암호화해 전송
- ⑤ 밥이 개인키로 복호화

**[각 단계에서 누가 무엇을 아는가]**
- 밥 : p, q, n, e, d 전부
- 앨리스 : 밥의 공개키 (n, e)
- 공격자 : 공개키 (n, e)와 암호문 c
- 공격자가 평문을 알려면 n을 소인수분해해야 함

> **[교수님 말씀 36:23]**
> 
> 공격자는 공개키 암호이기 때문에 공개 저장소에서 밥의 공개키를 알 수 있고 전달되는 암호문도 알 수 있습니다. 그래도 평문을 알 수 없는 이유는, 공개키에서 개인키를 구하려면 n을 소인수분해해야 하는데 그것이 굉장히 어렵기 때문입니다.

> **[작성자 주의 (교안·말씀 차이 · 개정 등)]** **교안 안의 차이 — 번호 매기기**
> 
> 왼쪽 "순서" 목록은 ①~⑤ 5단계(④ "공개키로 암호화해 전송"이 암호화 + 전송을 한 단계로 묶음)이고, 도식은 ①~⑥ 6단계(④ 암호화, ⑤ 암호문 전송, ⑥ 복호화)입니다. 내용은 같고 번호만 다릅니다. 또 도식에서 평문을 Alice 쪽은 대문자 M, Bob 쪽 복호 결과는 소문자 m으로 표기했습니다.


## [7주차 07] RSA의 안전성과 사용 시 주의 사항

### [w7-s7-1] RSA의 안전성 (교안 p.19)

**[RSA 문제]**
- 공개키 (n, e)와 암호문 c가 주어졌을 때 평문 m을 구하는 문제
- 알려진 유일한 방법 : n을 소인수분해 → p, q → d 계산

**[안전성의 근거]**
- n을 소인수분해할 수 있으면 RSA는 깨짐
- 소인수분해보다 쉬운 공격은 아직 발견되지 않음
- **증명된 것이 아니라 "아직 발견되지 않은" 것**

**[지켜야 할 사항]**
- n은 2048비트 이상
- 두 소수가 서로 너무 가깝지 않아야 함 — p, q가 비슷하면 n의 제곱근 근처에서 찾을 수 있음
- 소수를 고를 때 안전한 난수를 사용 — 예측 가능하게 고르면 공격자도 같은 소수를 찾음

> **[교안 강조]**
> 
> **같은 평문 + 같은 공개키 → 항상 같은 암호문**<br>**→ 실제로는 평문에 난수를 섞는 패딩을 적용해 매번 다른 암호문이 나오게 함**

> **[교수님 말씀 37:51]**
> 
> 소인수분해보다 쉬운 방법이 "아직 밝혀지지 않았다"는 것은 없다는 뜻이 아닙니다. 더 쉬운 방법이 없다는 게 증명된 건 아니지만, 40년 넘게 쓰면서 아직까지 나오지 않았다는 의미로 생각하시면 됩니다.

> **[교수님 말씀 38:59]** 〔시험·중요 신호〕
> 
> 그리고 **한 가지 더 중요한 건**, 앞에서 살펴본 (패딩 없는) RSA 암호는 같은 평문 · 같은 공개키면 항상 같은 암호문이 나온다는 점입니다.

> **[교수님 말씀 39:36]**
> 
> 같은 평문 · 같은 공개키가 항상 같은 암호문이면 왜 문제냐면, 어떤 서비스가 "예 / 아니오" 설문 응답을 공개키로 암호화해 저장한다고 해 봅시다. 공격자가 공개된 공개키로 "예"와 "아니오"를 직접 암호화해 저장된 암호문과 비교하면 키를 몰라도 내용이 드러납니다. 앞에서 블록 암호에서도 같은 평문이 같은 암호문이 되면 안 된다고 말씀드렸는데, **그것과 같은 이유**입니다.

> **[보충 (교수님 설명 아님)]** **4주차와 연결 — "항상 같은 암호문"이 왜 문제인가 — 교수님 설명 아님**
> 
> 공개키는 누구나 쓸 수 있으므로 공격자는 언제든 원하는 평문을 암호화할 수 있습니다(4주차: 공개키 암호는 항상 CPA를 가정). 교과서 그대로의 RSA는 결정적 암호화라, 후보 평문("예" / "아니오")을 직접 암호화해 가로챈 암호문과 비교하면 평문을 알아냅니다 → IND-CPA 불만족. 그래서 난수 패딩(표준 예: OAEP)으로 확률적 암호화를 만듭니다. "p, q가 비슷하면": p ≈ q ≈ √n이라 √n 근처의 수로 나눠 보면 금방 찾습니다(페르마 인수분해).

### [w7-s7-2] RSA 사용 시 주의 사항 (교안 p.20)

| 항목 | 내용 |
|---|---|
| **① 키 길이** | 2048비트 이상 사용 (1024비트는 권장되지 않음) |
| **② 패딩** | 평문을 그대로 거듭제곱하지 않고 난수를 섞는 표준 패딩 적용 |

## [7주차 08] 이산대수 문제와 엘가말 암호

### [w7-s8-1] 또 하나의 어려운 문제 : 이산대수 문제 (교안 p.21)

**7^x mod 13 의 값 (x = 1 ~ 9)**

| 왼쪽 열 | 오른쪽 열 |
|---|---|
| 7^0 mod 13 = 1 | 7^5 mod 13 = 11 |
| 7^1 mod 13 = 7 | 7^6 mod 13 = 12 |
| 7^2 mod 13 = 10 | 7^7 mod 13 = 6 |
| 7^3 mod 13 = 5 | 7^8 mod 13 = 3 |
| **7^4 mod 13 = 9** | 7^9 mod 13 = 8 |

교안 표기 그대로 — 캡션은 "x = 1 ~ 9"이지만 목록에는 x = 0도 있어 실제로는 x = 0 ~ 9

**[왜 어려운가]**
- 보통의 대수 : 7^x = 49 → x = 2 (쉽게 구함)
- 모듈러 연산 : 결과가 규칙 없이 흩어짐 — 결과만 보고 지수를 짐작할 수 없음
- 모듈러스가 수백 자리가 되면 — **표를 만들 수 없고 효율적인 방법도 알려지지 않음**

**[이산대수 문제 (Discrete Logarithm Problem)]**
- αˣ mod p 를 계산하는 것은 쉬움
- αˣ mod p = β 를 만족하는 x를 찾는 것은 어려움

| 어려운 문제 | 한 방향은 쉬움 | 반대 방향은 어려움 | 이 문제에 기반한 기술 |
|---|---|---|---|
| **소인수분해** | p × q = N | N → p, q | RSA |
| **이산대수** | αˣ mod p 계산 | 결과에서 x 찾기 | 엘가말, 타원곡선 암호, 디피-헬만 |

> **[교수님 말씀 43:30]**
> 
> 보통의 대수에서 7의 몇 제곱이 49냐는 로그를 쓰면 x = 2로 쉽게 구하고, 숫자가 아무리 커져도 계산기로 구할 수 있습니다. 그런데 모듈러 연산에서는 이야기가 달라집니다. 7을 몇 제곱해야 13으로 나눈 나머지가 9냐는, 13이 작아 표를 만들 수 있으니 4라는 걸 바로 알지만, 수가 커지면 결과가 커졌다 작아졌다 규칙 없이 흩어져서 **하나씩 대입해 보는 방법밖에 현재 없습니다**.

> **[작성자 주의 (교안·말씀 차이 · 개정 등)]** **말씀 범위 주의 — "하나씩 대입하는 방법밖에 없다"** 〔시험·중요 신호〕
> 
> 교안 p.21의 표현은 "**효율적인 방법이 알려지지 않음**"입니다. 보통의 이산대수(mod p)에는 수학적 구조를 파고드는 **빠른 계산 방법이 있어서** 엘가말 · 디피-헬만도 RSA처럼 2048비트가 필요하고, "사실상 하나씩 대입하는 수준의 공격밖에 없다"는 것은 **타원곡선**의 경우라고 교수님도 타원곡선 부분(58:07~58:28)에서 설명하셨습니다. 시험에서는 "효율적인 방법이 알려지지 않음"으로 답하세요.

> **[보충 (교수님 설명 아님)]** **이산수학과 연결 — 원시근 — 교수님 설명 아님**
> 
> 7ˣ mod 13은 x = 0 ~ 11에서 1 ~ 12가 한 번씩 모두 나온 뒤(7¹² ≡ 1) 반복합니다. 이렇게 거듭제곱이 0을 뺀 모든 나머지를 다 만드는 수를 mod p의 **원시근(primitive root, 생성원)**이라 하고, 엘가말 · 디피-헬만의 α는 보통 원시근을 씁니다(뒤 예제의 α = 2도 mod 29의 원시근). "로그"라는 이름은 보통 대수의 log₇ 49 = 2처럼 지수를 묻는 문제라서 붙었습니다.

### [w7-s8-2] 엘가말 암호 (ElGamal) 의 구조 (교안 p.22)

*[도식] 밥 ① 비밀값 d 선택 ② β = α^d mod p → 공개키 (p, α, β), 개인키 d → 공개 / 앨리스 ③ 임시 비밀값 i ④ c₁ = α^i mod p ⑤ 마스킹 키 = β^i mod p ⑥ c₂ = 평문 × 마스킹 키 mod p → 암호문 (c₁, c₂) 전송 / 밥 ⑦ 마스킹 키 = c₁^d mod p ⑧ 평문 = c₂ ÷ 마스킹 키 mod p (p.22)* — 도식 속 글자: 앨리스 (보내는 사람) / 밥 (받는 사람) / ① 비밀값 d 선택 ② β = α^d mod p 계산 / → 공개키 (p, α, β), 개인키 d / 공개키 (p, α, β) 공개 / ③ 임시 비밀값 i 선택 ④ 임시 공개값 c₁ = α^i mod p ⑤ 마스킹 키 = β^i mod p ⑥ 마스킹된 평문 c₂ = 평문 × 마스킹 키 mod p / 암호문 (c₁, c₂) 전송 / ⑦ 마스킹 키 = c₁^d mod p (앨리스와 같은 값) ⑧ 평문 = c₂ ÷ 마스킹 키 mod p

**[왜 같은 마스킹 키가 나오는가]**
- 앨리스 : β^i = (α^d)^i
- 밥 : c₁^d = (α^i)^d
- **둘 다 α^(d×i) mod p → 같은 값**

> **[교안 강조]**
> 
> **밥의 공개키와 앨리스의 임시 비밀값으로 "둘만 아는 일회용 키"를 만들어 평문을 가린다**

> **[교수님 말씀 46:25]**
> 
> 이산대수 문제 위에 세워진 공개키 암호가 **1985년 엘가말이 제안한** 방식입니다. 공격자가 β = α^d를 보고 α를 몇 제곱해야 β가 되는지 계산하면 개인키를 알 수 있는데, 그게 굉장히 어려운 문제입니다. c₂는 평문에 마스킹 키를 곱한 것이라 "마스킹"이라는 용어를 씁니다. **잘 따라오셔야 됩니다** — 밥이 계산한 c₁^d = (α^i)^d와 앨리스가 계산한 β^i = (α^d)^i는 같은 값입니다. **손으로 직접 써 보시면 굉장히 쉽게 계산**되는 것을 알 수 있습니다.

### [w7-s8-3] 엘가말 암호의 계산 예와 특징 (교안 p.23)

| 단계 | 계산 | 결과 |
|---|---|---|
| 밥의 키 | d = 12, β = 2¹² mod 29 | β = 7 |
| 앨리스의 임시값 | i = 5, c₁ = 2⁵ mod 29 | c₁ = 3 |
| 마스킹 키 | β^i = 7⁵ mod 29 | 16 |
| 암호화 | c₂ = 15 × 16 = 240 mod 29 | **암호문 (3, 8)** |
| 복호화 | 3¹² mod 29 = 16, 8 ÷ 16 mod 29 | **평문 15** |

※ 모듈러 연산에서 나누기 = 곱셈 역원을 곱하기 (16의 역원은 20, 8 × 20 = 160 ≡ 15 mod 29)

**[특징]**
- 매번 다른 임시값 → 같은 평문도 매번 다른 암호문 — RSA는 패딩이 없으면 같은 암호문
- **암호문이 두 값 → 평문의 두 배 길이**
- 이산대수 문제에 기반

**[주의]**
- 임시 비밀값 재사용 금지
- 같은 값을 두 번 쓰면 두 암호문의 관계에서 평문이 드러남

> **[교안 강조]**
> 
> **엘가말 = 일회용 마스킹 키로 평문을 가리는 공개키 암호**

> **[보충 (교수님 설명 아님)]** **계산 확인 — 공개값 p = 29, α = 2 (교안 표에서는 생략) — 교수님 설명 아님**
>

> **[보충 (교수님 설명 아님)]** **"임시값을 두 번 쓰면 평문이 드러난다"를 식으로 — 교수님 설명 아님**

## [7주차 09] 타원곡선 암호, 세 가지 공개키 암호의 비교, 양자 컴퓨터

### [w7-s10-4] 디피-헬만 계산 예 (교안 p.31)

## [7주차 11] 중간자 공격 : 공격자는 어떻게 키를 만드는가

### [w7-s11-1] 중간자 공격 : 공격자는 어떻게 키를 만드는가 (교안 p.32)

*[도식] 앨리스 비밀값 a ⇄ 공격자 비밀값 m ⇄ 밥 비밀값 b — 1. 앨리스 → 공격자 : A = α^a (가로챔) 2. 공격자 → 밥 : α^m (대신 보냄) 3. 밥 → 공격자 : B = α^b (가로챔) 4. 공격자 → 앨리스 : α^m (대신 보냄) (p.32)* — 도식 속 글자: 앨리스 비밀값 a / 공격자 비밀값 m / 밥 비밀값 b / 1. A = α^a / 2. α^m / 3. B = α^b / 4. α^m / 가로챔 → 대신 보냄 / 가로챔 → 대신 보냄

**각자 계산하는 키**

|  | 앨리스가 계산 | 공격자가 계산 | 밥이 계산 |
|---|---|---|---|
| **앨리스 ↔ 공격자** | **(α^m)^a = α^(m×a)** | **A^m = α^(a×m)** | — |
| **공격자 ↔ 밥** | — | **B^m = α^(b×m)** | **(α^m)^b = α^(m×b)** |

**[결과]**
- 공격자는 두 개의 키를 가짐 : 앨리스와 공유하는 키, 밥과 공유하는 키
- 앨리스의 메시지를 복호화해 읽고, 다시 암호화해 밥에게 전달
- **두 사람은 서로 직접 공유했다고 믿어 아무 이상도 느끼지 못함**

> **[교안 강조]**
> 
> **이산대수 문제는 전혀 깨지지 않았다 — 멜로리는 a도 b도 알아내지 못했다**<br>**공격이 성공한 이유는 "받은 값이 누구에게서 왔는지" 확인하지 않았기 때문**

> **[교수님 말씀 1:12:24]**
> 
> 디피-헬만에서는 받은 값이 정말 상대가 보낸 것인지 확인하지 않고, 그 결과 중간자 공격이 가능합니다. 공격자는 앨리스와 공유한 키로 복호화해 내용을 읽고, 밥과 공유한 키로 **다시 변조한 메시지를** 암호화해 전달할 수도 있습니다. **여기서 분명히 봐야 할 것은 이산대수 문제는 전혀 깨지지 않았다**는 점입니다. 밥이 받은 값을 앨리스가 실제로 보냈는지 확인하는 과정이 있었다면 이 공격은 수행되지 않습니다. 이를 막는 전자서명과 인증은 **나중에 추가로** 살펴보겠습니다.

교안 표기 그대로 — 도식 · 표에서는 "공격자", 강조 상자에서만 "멜로리"(Mallory). 같은 공격자이며 4주차 등장인물(능동적 공격자 멜로리)과 같은 이름입니다.

> **[보충 (교수님 설명 아님)]** **숫자로 확인 — p = 29, α = 2, 공격자 m = 9 (교안에 없는 예시값) — 교수님 설명 아님**
> 
> α^m = 2⁹ mod 29 = 19. 앨리스는 19⁵ mod 29 = **21**, 공격자도 A^m = 3⁹ mod 29 = 21 → 앨리스 ↔ 공격자 키 21. 밥은 19¹² mod 29 = **20**, 공격자도 B^m = 7⁹ mod 29 = 20 → 공격자 ↔ 밥 키 20. 정상 공유값 16과 다르고 서로도 다르지만, 앨리스 · 밥은 각자 "상대와 같은 키"라고 믿습니다. 대응은 핵심 정리(p.34) 「한계」 행의 "전자서명 · 인증서로 상대 확인"(교수님: 전자서명 · 인증은 나중에 추가로 살펴봄) — 공개값 A, B에 서명을 붙여 누가 보냈는지 검증합니다.


## [7주차 12] 핵심 정리 (교안 원문)

### [w7-sk-1] 핵심 정리 (교안 원문) (교안 p.33, 34)

교안 마지막 두 장을 그대로 옮긴 것입니다. 시험 직전 점검용.

### [w7-sk-2] 핵심 정리 (1) : 공개키 암호 (교안 p.33)

| 주제 | 내용 |
|---|---|
| **공개키 암호의 원리** | 일방향 함수 : 한쪽은 쉽고 반대는 어려움<br>트랩도어 : 비밀 정보(= 개인키)를 알면 반대 방향도 쉬워짐 |
| **RSA (소인수분해)** | n = p × q, L = (p−1)(q−1), gcd(e, L) = 1, e × d ≡ 1 (mod L)<br>암호화 c = mᵉ mod n, 복호화 m = c^d mod n / 2048비트 이상 + 난수 패딩 |
| **엘가말 (이산대수)** | 임시 비밀값으로 둘만 아는 일회용 마스킹 키를 만들어 평문을 가림<br>매번 다른 암호문, 길이는 두 배, 임시값 재사용 금지 |
| **타원곡선 암호** | 점을 k번 더하기는 쉽고, P와 Q에서 k를 찾기는 어려움<br>같은 안전성에 훨씬 짧은 키 (RSA 2048 비트 수준 → 타원곡선 224비트) |

### [w7-sk-3] 핵심 정리 (2) : 키 교환 (교안 p.34)

| 주제 | 내용 |
|---|---|
| **키 교환이란** | 공개키 암호 = 메시지를 암호화 / 키 교환 = 같은 대칭키를 만들어 냄<br>키 전송(한쪽이 만들어 전달) vs 키 합의(양쪽이 함께 생성) |
| **디피-헬만** | 공개 : p, α / 비밀 : a, b → A = αᵃ, B = αᵇ 를 교환<br>양쪽 모두 α^(a×b) mod p 를 얻음, 안전성은 이산대수 문제 |
| **한계** | 상대를 확인하지 않음 → 중간자 공격 가능<br>전자서명 · 인증서로 상대를 확인하는 수단이 함께 필요 |

> **[교수님 말씀 1:16:52]** 〔시험·중요 신호〕
> 
> n과 e를 공개키로, d를 개인키로 한다는 점을 **기억해 주시고**, 암호화는 평문을 e제곱, 복호화는 암호문을 d제곱합니다. RSA의 안전성은 소인수분해의 어려움에 기반하므로 p, q는 1024비트 이상, 즉 공개키는 2048비트 이상을 써야 하고, 같은 평문이 항상 같은 암호문이 되는 문제 때문에 실제로는 평문에 난수를 패딩한다는 정도로 **기억해 주시면 됩니다**.
