핵심 1

패딩은 마지막 블록을 채우고 복호화 후 정확히 걷어낼 수 있어야 한다. 가장 널리 쓰는 PKCS#7 = 채울 개수 n을 값 n으로 n개, 평문이 이미 블록 크기의 배수여도 블록 하나를 더 붙인다.

핵심 2

평문이 블록 암호를 통과하는가가 모든 차이를 만든다: ECB · CBC(직접 입력) → 패딩 필요 · D 함수 필요 / CFB · OFB · CTR(만든 값과 XOR) → 패딩 불필요 · E 함수만 사용.

핵심 3

ECB는 같은 평문 블록 → 같은 암호문 블록이라 패턴이 남고 블록 복사 · 교체 조작이 된다. IV는 비밀이 아니지만 매번 달라야 하고(CBC는 예측 불가), 같은 키 + 같은 IV/카운터 → 같은 키 스트림 → C₁ ⊕ C₂ = P₁ ⊕ P₂.

그림의 원본은 3A FE 00으로 끝납니다. 바이트 패딩은 마지막 값 05만큼만 지우므로 원래 데이터의 00은 그대로 남습니다 — 제로 패딩의 문제를 해결한 방식입니다. (교안의 "바이트 패딩"은 표준 이름으로는 ANSI X9.23 방식과 같은 결과)

규칙

교수님 말씀 — 17:42

실무에서 가장 널리 쓰이는 방식이 PKCS#7 패딩입니다. 공개키 암호 표준 문서(PKCS)의 7번째 문서에 정의되어 있어 이런 이름이 붙었습니다. 복호화할 때 지우려는 6바이트가 모두 06인지 확인할 수 있어서 패딩이 올바른 형태인지 검사하기가 훨씬 쉬워집니다. 패딩을 생략하면 수신자가 마지막 바이트를 보고 패딩이 있다고 잘못 판단해 데이터를 잘라낼 수 있습니다.

왜 배수여도 블록을 붙여야 하나 — 예 — 교수님 설명 아님

16바이트 평문이 마침 …01로 끝난다고 합시다. 패딩을 생략하면 수신자는 마지막 바이트 01을 "패딩 1바이트"로 보고 데이터 1바이트를 지워 버립니다. 항상 패딩을 붙이기로 약속하면(배수일 때는 10 × 16 블록) 수신자는 "마지막 바이트는 반드시 패딩"이라고 확신할 수 있습니다.

교수님 말씀 — 22:50

오늘날 널리 쓰이는 모드 대부분은 이 다섯 가지이거나 그 변형입니다. 이름이 그 모드의 동작을 그대로 설명한다고 생각하시면 됩니다 — 암호 블록 연쇄(Cipher Block Chaining)는 암호문 블록을 다음 블록에 연결(체이닝)한다는 뜻이고, 카운터 모드는 카운터 값을 이용한다는 뜻입니다. 오류 전파는 암호문을 전송할 때 암호문에 1비트 오류가 생기면 수신자가 복호화한 평문의 어디까지 영향을 받는가 하는 이야기입니다.

블록 암호를 사용하는 두 가지 방식교안 p.13

방식 ① 평문 블록을 블록 암호에 직접 넣는다
  • 평문이 블록 암호를 통과 → 블록 크기에 맞춰야 함
  • → 패딩 필요
  • 복호화에는 블록 암호의 복호화 함수가 필요
  • 해당 모드 : ECB, CBC
방식 ② 블록 암호로 만든 값을 평문과 XOR한다
  • 블록 암호는 키 스트림을 만드는 데 사용
  • 평문은 블록 암호를 통과하지 않고 XOR만 됨
  • → 패딩 불필요 (암호문 길이 = 평문 길이)
  • → 복호화에도 암호화 함수만 사용
  • 해당 모드 : CFB, OFB, CTR
교안 강조

두 방식 모두 블록 암호를 사용하지만, 평문이 블록 암호를 "통과하는가"가 다르다

교수님 말씀 — 25:01

이 구분을 먼저 이해하면 뒤에서 볼 각 모드의 특성이 쉽게 정리됩니다. 두 번째 방식은 결국 스트림 암호가 동작하는 방식과 같습니다. 평문이 5바이트라면 키 스트림 5바이트와 XOR하면 되고 암호문도 5바이트가 됩니다. 또 평문이 블록 암호를 통과하지 않으므로 수신자도 같은 키로 키 스트림을 만들어 XOR하면 되어 복호화 함수가 따로 필요 없다는 점만 잘 기억해 주시면 좋겠습니다.

초기 벡터 (IV) 의 역할교안 p.14

초기 벡터가 없다면
  • 블록 암호는 같은 입력 → 항상 같은 출력
  • 같은 데이터를 두 번 암호화하면 암호문이 동일
  • 두 메시지가 같은지 공격자가 알 수 있음
  • 같은 값을 가진 데이터가 그대로 드러남
초기 벡터의 역할
  • 암호화할 때마다 달라지는 값을 하나 더 넣음
  • 같은 평문을 암호화해도 매번 다른 암호문
  • → 암호문만 보고는 같은 데이터인지 알 수 없음
성질내용
비밀 값이 아님복호화 시 필요하므로 암호문과 함께 전달 · 저장 (앞에 붙이는 것이 일반적)

예측 불가 조건모드에 따라 다음 IV를 예측할 수 없어야 함
만드는 방법암호용 안전한 난수 발생기로 생성

교수님 말씀 — 29:24

IV가 비밀이 아니어도 되는 이유는 공격자가 IV를 알더라도 키를 모르면 평문을 알 수 없기 때문입니다. 그래서 보통 암호문 앞에 IV를 붙여 함께 전달하거나 저장합니다. 이 때문에 일부에서는 초기 벡터를 그냥 난수라고 부르기도 합니다.

4주차와 연결 — IV는 "확률적 암호화"의 장치 — 교수님 설명 아님

4주차에서 결정적 암호화(같은 평문 → 같은 암호문)는 IND-CPA를 만족하지 못하므로 무작위 값을 섞는 확률적 암호화가 필요하다고 배웠습니다. 운영 모드에서 그 무작위 값 역할을 하는 것이 IV입니다. IV가 없는 ECB가 바로 결정적 암호화라서 다음 섹션의 패턴 문제가 생깁니다.

IV 조건 — 교안보다 정확히 — 교수님 설명 아님

교안은 "예측 불가"를 CBC에만 붙였지만, 기준 문서(NIST SP 800-38A)는 CBC와 CFB 둘 다 IV가 예측 불가해야 한다고 정합니다. OFB는 메시지마다 고유(nonce)하면 되고, CTR은 카운터 블록이 겹치지 않으면 됩니다. 시험 답은 교안 문장(매번 달라야 함, CBC는 예측 불가)으로 쓰되, "CBC만 예측 불가"라고 단정하지는 마세요.

CBC (Cipher Block Chaining) 모드교안 p.18

왼쪽 : 암호화 (앞 암호문과 XOR 후 암호화) / 오른쪽 : 복호화 (교안은 좌우 배치, 복호화 그림은 화살표가 아래에서 위로)

병렬 처리

  • IV가 매번 같으면 첫 블록의 패턴이 드러남
  • 공격자가 다음 IV를 예측할 수 있으면 — 자신이 고른 평문을 넣어 특정 값을 확인할 수 있음

"다음 IV를 예측하면" 공격의 구체적인 모습 — 교수님 설명 아님

이전 메시지의 첫 블록이 C = E(P ⊕ IV_old)이고 공격자는 P가 "YES"인지 "NO"인지만 모른다고 합시다. 다음 IV_next를 미리 알면 추측 G에 대해 G ⊕ IV_old ⊕ IV_next를 암호화 요청합니다(선택 평문 공격). 그러면 E(G ⊕ IV_old ⊕ IV_next ⊕ IV_next) = E(G ⊕ IV_old)가 되어, G = P일 때만 결과가 C와 같아집니다 — 키 없이 평문을 확인합니다.

  • Pᵢ₊₂ 이후 : 정상 복호화

07CFB (Cipher Feedback) 모드교안 p.21

CFB (Cipher Feedback) 모드교안 p.21

범례: E : Encryption / D : Decryption / Sᵢ: Shift register / Pᵢ: Plaintext block i / Cᵢ: Ciphertext block i / Tᵢ: Temporary register / K: Secret key / IV: Initial vector (S₁). 상단 "←" = 왼쪽으로 쉬프트. 범례에 D(Decryption)가 있으나 그림은 암호화만 표시.

기본 성질
  • 블록 암호 출력과 평문을 XOR — 패딩 불필요, 복호화에도 E 함수만 사용
  • 블록보다 작은 단위(바이트 등)로도 처리 가능
병렬 처리와 오류
  • 암호화 : 순서대로만 가능 (병렬불가)
  • 복호화 : 병렬 가능
  • 오류 : 해당 블록 1비트 + 쉬프트 레지스터에서 오류가 사라질 때 까지 다음 블록 전체

교수님 말씀 — 44:45

첫 블록에서 시프트 레지스터에 들어 있는 IV를 암호화하고, 출력에서 일부를 떼어 평문과 XOR해 암호문을 만듭니다. 다음 블록은 방금 나온 암호문을 시프트 레지스터에 밀어 넣어 다시 암호화합니다. 암호문을 계속 되먹인다고 해서 암호문 피드백이라는 이름이 붙었습니다. 암호문 1비트에 오류가 나면 해당 평문의 같은 위치 1비트에 오류가 나고, 오류 난 암호문이 시프트 레지스터로 들어가 출력이 잘못되므로 그 암호문이 시프트 레지스터에서 빠져나갈 때까지 이후 평문 블록 전체에 오류가 생깁니다.

08OFB (Output Feedback) 모드교안 p.22

OFB (Output Feedback) 모드교안 p.22

범례: E : Encryption / D : Decryption / Sᵢ: Shift register / Pᵢ: Plaintext block i / Cᵢ: Ciphertext block i / Tᵢ: Temporary register / K: Secret key / IV: Initial vector (S₁)

기본 성질
  • 키 스트림이 평문과 무관 → 미리 계산 가능(전처리)
  • 오류는 해당 비트에만 영향 (번지지 않음)
  • 패딩 불필요, 복호화에도 E 함수만 사용

주의
  • 같은 키 + 같은 IV → 같은 키 스트림

교수님 말씀 — 49:44

OFB는 이어지는 값들이 평문이나 암호문과 전혀 무관하게 키와 IV만으로 결정됩니다. 그래서 평문이 도착하기 전에 미리 계산해 둘 수 있고(전처리), 암호문에 오류가 생겨도 다른 블록의 입력에 영향을 주지 않아 같은 위치 1비트만 오류가 납니다 — 잡음이 많은 통신 환경에 유리합니다. 다만 같은 키에 같은 IV를 쓰면 완전히 같은 키 스트림이 나오므로 IV를 절대 재사용하지 않는 것이 이 모드의 핵심 규칙입니다. 키 스트림은 앞의 출력을 이어받아 만들므로 암 · 복호화 모두 블록을 동시에 처리할 수는 없지만 미리 계산해 두는 것은 가능합니다.

CTR (Counter) 모드교안 p.23

왜 "1씩 증가"면 충분한가 — 교수님 설명 아님

블록 암호는 입력이 1비트만 달라도 출력이 완전히 달라지므로(쇄도 효과), 카운터가 1, 2, 3 …처럼 규칙적이어도 E_K(카운터)는 무작위처럼 보이는 키 스트림이 됩니다. 중요한 것은 값이 예측 불가능한 것이 아니라 같은 키로 같은 카운터가 두 번 쓰이지 않는 것입니다. 그래서 실제로는 메시지마다 다른 시작값(난수 부분 + 블록 번호)을 씁니다.

13용어 정리

운영 모드Mode of Operation

블록 암호로 여러 블록을 이어서 처리하는 규칙. NIST SP 800-38A의 5가지가 기본.

패딩Padding

마지막 블록을 블록 크기로 채우고, 복호화 후 정확히 걷어내는 규칙.

PKCS#7 패딩PKCS #7

채울 개수 n을 값 n으로 n개 채움. 배수여도 한 블록(16바이트면 10 × 16) 추가.

초기 벡터IV, Initialization Vector

같은 평문도 매번 다른 암호문이 되게 하는 값. 비밀 아님, 매번 달라야 함.

ECBElectronic Codebook

블록마다 독립 암호화. IV 없음, 패턴이 남음, 블록 교체 조작 가능.

CBCCipher Block Chaining

Cᵢ = E_K(Pᵢ ⊕ Cᵢ₋₁). 암호화 순차, 복호화 병렬, IV는 예측 불가해야 함.

CFBCipher Feedback

앞 암호문을 레지스터로 되먹여 키 스트림 생성. 블록보다 작은 단위 가능.

OFBOutput Feedback

블록 암호 출력을 되먹임. 키 스트림 미리 계산 가능, 오류 안 번짐, 병렬 불가.

CTRCounter

카운터 값을 암호화해 키 스트림. 병렬 · 임의 접근 가능, 카운터 재사용 금지.

자기 복구Self-recovering

CBC에서 1비트 오류가 두 블록(Pᵢ 전체 + Pᵢ₊₁ 1비트)에서 멈추는 성질.

시프트 레지스터Shift register

CFB · OFB에서 블록 암호 입력을 담고 r비트씩 밀어 넣는 저장 공간.

인증 암호AEAD

암호화 + 인증 태그를 한 번에 제공. (참고 · 시험 제외)

추가 인증 데이터AAD

암호화하지 않고 인증(태그)에만 반영하는 헤더 등의 데이터. (참고)

인증 태그authentication tag

데이터가 바뀌었는지 확인하는 짧은 값. 키를 가진 쪽만 올바르게 생성.

Q4DB의 성별 컬럼(남/여)을 AES-ECB로 암호화해 저장했다. 키를 모르는 공격자가 알 수 있는 정보 두 가지를 쓰고, 해결 방법을 쓰시오.서술형
모범답안ECB는 같은 평문 블록 → 같은 암호문 블록이라 ① 암호문이 같은 행끼리 같은 성별임을 알고, ② 암호문 종류가 2개뿐이라 개수를 세어(또는 자기 값과 비교해) 어느 암호문이 어떤 값인지 추측할 수 있다. 또 다른 행의 암호문을 복사해 값을 바꿀 수도 있다. 해결: 매번 다른 IV를 쓰는 모드(CBC · CTR 등)로 암호화하고, 조작 방지에는 인증(MAC · AEAD)을 함께 사용.
Q5OFB와 CTR에서 같은 키로 같은 IV(카운터 시작값)를 두 메시지에 재사용하면 안 되는 이유를 식으로 설명하시오.서술형
모범답안두 모드의 키 스트림 S는 키와 IV(카운터)만으로 정해지므로 재사용하면 같은 S가 나온다. C₁ = P₁ ⊕ S, C₂ = P₂ ⊕ S이면 C₁ ⊕ C₂ = P₁ ⊕ P₂로 키 스트림이 상쇄되어 두 평문의 XOR이 드러나고, 한 평문을 알면 다른 평문도 바로 복구된다.
