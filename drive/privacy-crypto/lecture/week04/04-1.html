08모듈러 연산 · 덧셈 암호 · 최대공약수와 곱셈 역원교안 p.20–22

모듈러 연산 (Modular Arithmetic)교안 p.20

정의

  • a mod m = a를 m으로 나눈 나머지 r (0 ≤ r < m) — m : 모듈러스 (modulus)
  • 17 mod 5 = 2, −3 mod 7 = 4
  • 합동 : a ≡ b (mod m) ⇔ 나머지가 같음 — 12 ≡ 3 ≡ 21 (mod 9)

성질 : 중간 계산마다 mod를 취해도 결과가 같음

mod모듈러 연산의 성질 (교안)
(a + b) mod m = ((a mod m) + (b mod m)) mod m   (곱셈도 동일)

(13 + 25 + 102) mod 17 = (13 + 8 + 0) mod 17 = 4
3⁴ mod 7 = 81 mod 7 = 4
교안 강조

모듈러 연산 = 결과가 항상 정해진 범위(0 ~ m−1) 안에 머무는 계산 → 순환하는 암호, 공개키 암호의 기반

이산수학과 연결 — 음수의 mod — 교수님 설명 아님

1학기 이산수학의 나눗셈 정리: 정수 a와 양의 정수 m에 대해 a = m·q + r (0 ≤ r < m)인 q, r이 하나로 정해지고, 이 r이 a mod m입니다. 음수도 나머지가 0 이상이 되게 몫을 잡습니다: −3 = 7 × (−1) + 4 이므로 −3 mod 7 = 4. 합동 a ≡ b (mod m)은 "m이 a − b를 나눈다"와 같은 뜻입니다(12 − 3 = 9, 21 − 12 = 9).

기억할 것 : 역원이 존재하려면 a와 m이 서로소 (gcd(a, m) = 1)
(구체적인 계산 절차는 공개키 암호의 키 생성에서 활용)

이산수학과 연결 — 유클리드 알고리즘 — 교수님 설명 아님

교안은 이름만 언급했습니다. 이산수학에서 배운 방식 그대로 gcd(a, b) = gcd(b, a mod b)를 나머지가 0이 될 때까지 반복합니다. 예: gcd(26, 3) → 26 mod 3 = 2 → gcd(3, 2) → 3 mod 2 = 1 → gcd(2, 1) → 2 mod 1 = 0 → 답 1(서로소). 그래서 3은 mod 26에서 역원이 있고(3 × 9 = 27 ≡ 1), 2는 gcd(2, 26) = 2라서 역원이 없습니다. 역원을 실제로 구하는 절차(확장 유클리드)는 7주차 공개키 암호에서 나올 것으로 보입니다.

암호문 단독 공격 (Ciphertext Only Attack, COA)교안 p.34

  • 공격자가 가진 것 — 암호문 C₁, C₂, …, Cₙ 만 보유
  • 도청으로 누구나 얻을 수 있음 — 가장 약한(공격자에게 불리한) 모델, 그러나 가장 현실적 · 기본적인 상황
  • COA에서 안전하려면 : 암호문이 무작위 비트열처럼 보여 평문의 통계적 특징이 전혀 드러나지 않아야 함

알려진 평문 공격 (Known Plaintext Attack, KPA)교안 p.35

  • 공격자가 가진 것 — 새 암호문 C* + 이전 평문-암호문 쌍 (m₁, C₁), …, (mₙ, Cₙ)
  • 현실 예 : 이메일 인사말, 파일 머리 부분, 정형화된 공문서 — 에니그마 해독 : 반복되는 일기예보 문구 이용
  • 현대 암호 : 많은 평문-암호문 쌍을 알아도 새 암호문의 평문 · 키를 알아낼 수 없어야 함

선택 평문 공격 (Chosen Plaintext Attack, CPA)교안 p.36

  • 공격자가 할 수 있는 것 — 원하는 평문 m₁, …, mₙ 의 암호문을 얻을 수 있음
  • 암호화 오라클 : 키는 모르지만 암호화 기능은 사용 가능
  • 현실 예 : 송신자 기기 해킹, 공격자 입력을 서버가 암호화
  • 공개키 암호 : 누구나 암호화 가능 → 항상 CPA 가정

선택 암호문 공격 (Chosen Ciphertext Attack, CCA)교안 p.37

공격자가 할 수 있는 것설계 원칙
▪ 원하는 암호문의 복호 결과를 얻을 수 있음 — 복호화 오라클 (단, 대상 암호문 C* 는 질의 불가)
▪ 현실 예 : 복호화 장치 일시 사용 — 서버의 복호화 오류 메시지 차이만으로도 평문 노출 가능		▪ 표준 암호는 CCA에서도 안전해야 함
▪ 복호화 실패 원인을 자세히 알려 주지 않기
  • 가장 강한 공격 모델 : 복호화 결과의 아주 작은 정보만 새어도 "복호화 오라클"이 됨
시큐어코딩과 연결 — 오류 메시지 — 교수님 설명 아님

"복호화 실패 원인을 자세히 알려 주지 않기"는 시큐어코딩의 오류 메시지를 통한 정보 노출 방지와 같은 원칙입니다. 예를 들어 서버가 "패딩 오류"와 "형식 오류"를 다르게 응답하면, 공격자는 그 차이를 이용해 암호문을 한 바이트씩 풀어낼 수 있습니다(패딩 오라클 공격 — 블록암호 운영모드 주차에서 다룰 가능성이 있음, 추측).

17용어 정리

스테가노그래피Steganography

메시지의 존재 자체를 숨기는 기술(covered writing). 안전성 근거는 숨긴 방법의 비밀.

암호학Cryptology

암호기법(Cryptography, 설계) + 암호해독(Cryptanalysis, 분석 · 공격).

키 공간Key Space

가능한 모든 키의 집합. 크기 = 전사적 공격의 경우의 수. 필요조건일 뿐.

XORexclusive OR, ⊕

같으면 0, 다르면 1 (= mod 2 덧셈). (A ⊕ K) ⊕ K = A.

모듈러 연산modular arithmetic

a mod m = a를 m으로 나눈 나머지(0 ≤ r < m). 결과가 0~m−1 안에서 순환.

곱셈 역원multiplicative inverse

a · a⁻¹ ≡ 1 (mod m). gcd(a, m) = 1일 때만 존재.

하이브리드 방식hybrid encryption

공개키로 세션 키를 전달하고 대칭키로 데이터를 암호화(예: HTTPS).

전사적 공격Brute-force Attack

가능한 모든 키를 하나씩 시도. k비트면 최대 2ᵏ번.

부채널 공격side-channel attack

구현 공격의 예. 연산 시간 · 소비 전력을 측정해 키를 추출.

오라클oracle

키는 모르지만 암호화(CPA) 또는 복호화(CCA) 기능을 대신 써 주는 가상의 장치.

구별 불가능성Indistinguishability, IND

두 평문 중 어느 것의 암호문인지 맞힐 확률이 ≈ 1/2. 현대 암호의 안전성 기준.

확률적 암호화probabilistic encryption

무작위 값 r을 섞어 같은 평문도 매번 다른 암호문이 나오게 하는 방식.

일회용 패드One-Time Pad

C = P ⊕ K. 키 ≥ 평문 길이, 진정한 난수, 한 번만 사용하면 완전 비밀성.
