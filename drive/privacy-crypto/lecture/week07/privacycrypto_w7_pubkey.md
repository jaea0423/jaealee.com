01. 공개키 암호의 원리

## 대칭키 암호 시스템의 문제점

- 1. 안전한 채널을 통해 송/수신자 간 서로 동일한 **키를 사전에 공유할 필요**가 있음
  - 키 분배 문제 (Key distribution problem)
- 2. n명이 서로 비밀통신을 하기 위해서는 n(n−1)/2 개의 키가 필요함
  - Ex) 재학생 1000명이 대칭키 암호 통신하기 위해 필요한 키는 1인당 999개 필요
    - 전체 키의 수: 1000 × 999 ÷ 2 = 499,500 개 (※ 검증: Python으로 재계산 — 일치, 1000·999/2 = 499500)
  - **키 유지 관리의 어려움**
- 3. 송신자나 수신자의 **부인방지**를 제공하지 못함
  - 부인방지: 메시지를 전송한 송신자나 수신한 수신자가 나중에 그 사실을 부인할 수 없도록 하는 기능

[그림: 4명(A, B, C, D)의 사람 아이콘이 서로 양방향 화살표로 모두 연결된 완전 그래프. 각 연결선마다 두 사람이 공유하는 대칭키가 표시됨]
- A ↔ B : K_AB
- A ↔ C : K_AC
- A ↔ D : K_AD
- B ↔ C : K_BC
- B ↔ D : K_BD
- C ↔ D : K_CD
- → 4명이면 키 6개 = 4×3/2 (각자 3개씩 보유) — n(n−1)/2 공식의 예 (※ 검증: Python으로 재계산 — 일치)

> 키 분배 문제 · 키 개수 문제 · 부인방지 불가 → 공개키 암호가 등장한 배경

01. 공개키 암호의 원리

## 공개키 암호 시스템

- **각자 한 쌍의 키 (공개키 pk, 개인키 sk) 소유**
  - **공개키는 모두에게 공개**되고 **개인키는 비밀**로 보관
  - 공개키 pk와 개인키 sk는 서로 수학적인 관계를 가짐
    - pk로부터 sk를 도출하는 것은 계산적으로 불가능 (Computationally Infeasible)
- 암/복호화 과정이 **전혀 다름**
  - 비대칭키 (asymmetric) 암호시스템이라 하는 이유
  - 개인키를 소유한 사람이 암호문을 복호화 가능

[그림 왼쪽: 4명의 사람 아이콘이 각자 자신의 키 쌍을 가짐]
- A: (pk_A, sk_A)
- B: (pk_B, sk_B)
- C: (pk_C, sk_C)
- D: (pk_D, sk_D)

[그림 오른쪽: 공개키 암호 통신 흐름 — Alice → Bob]
- 위쪽에 사람 얼굴이 그려진 자물쇠 여러 개가 쌓인 "Public Registry"(공개키 저장소)
- 1. **공개키 획득**: Alice가 Public Registry에서 Bob의 공개키 pk_B를 가져옴 (Registry → Alice 화살표)
- 2. **암호문 전송**: Alice가 C = Enc_{pk_B}(m) 을 계산해 Bob에게 전송 (Alice → Bob 화살표)
- 3. **복호화**(빨간 글씨): Bob이 자신의 개인키로 M = Dec_{sk_B}(C) 계산
- Bob 옆에 자물쇠(Bob 얼굴) 아이콘 = pk_B, 열쇠 아이콘 = sk_B, 그 사이에 "pk_B ≠ sk_B" (암호화 키와 복호화 키가 다름)
- (※ 원문 표기 그대로 — 암호화 식은 소문자 m, 복호화 식은 대문자 M)

> 공개키로 암호화 → 짝이 되는 개인키로만 복호화 / 공개키에서 개인키를 구하는 것은 계산적으로 불가능

01. 공개키 암호의 원리

## 대칭키 암호와 공개키 암호의 비교

| 구분 | 대칭키 암호 | 공개키 암호 |
|---|---|---|
| 키 구성 | 하나의 비밀키를 양쪽이 공유 | 공개키 + 개인키 한 쌍 |
| 비밀키 사전 공유 | **필요** (빨간 글씨) | **불필요** (초록 글씨) |
| 보유 키 수 (n명) | n − 1 개 | 자신의 키 쌍 1개 |
| 속도 | 빠름 | 느림 (수백 배 이상) |
| 같은 안전성의 키 길이 | 짧음 | 훨씬 김 |
| 대표 알고리즘 | AES, SEED, ARIA | RSA, 엘가말, 타원곡선 암호 |

**두 방식의 관계**
- 공개키 암호는 대칭키 암호를 대체하는 기술이 아님
- 키를 나눠 갖기 어려운 문제 → 공개키 암호가 해결
- 속도가 느린 문제 → 대칭키 암호가 해결
  - 서로의 약점을 보완하는 관계 → 실제로는 함께 사용

01. 공개키 암호의 원리

## 하이브리드 암호 시스템

- 사전 비밀키 공유 (또는 분배) 가 필요한 대칭키 암호시스템의 단점을 보완
- 암/복호화 소요 시간 및 계산량이 많은 공개키 암호시스템의 단점을 보완
- **공개키 암호시스템과 대칭키 암호시스템을 함께 사용**
  - **대칭키 암호시스템의 비밀키 k를 공개키 암호시스템으로 암호화하여 분배**
  - **분배된 비밀키를 이용**하여 대용량의 **데이터를 대칭키 암호 시스템으로 암호화**

[도식: 하이브리드 암호 시스템 — 송신자 A 박스 → 전송 → 수신자 B 박스]

송신자 A (점선으로 위/아래 두 단계 구분)
1. (위) 평문 m → [블록 암호 (암호화)] → 암호문 C (자물쇠 걸린 문서). 블록 암호 상자 위에서 "대칭키 k_AB"(열쇠 아이콘)가 입력됨
2. (아래) 대칭키 k_AB → [공개키 암호 (암호화)] → E_{PK_B}(k_AB). 공개키 암호 상자 위에서 "B의 공개키 PK_B"가 입력됨

전송 (가운데 큰 화살표 "전 송")
- 자물쇠 걸린 "암호문 c" 문서 아이콘과 E_{PK_B}(k_AB)를 함께 B에게 보냄 (※ 원문 표기 그대로 — 가운데 아이콘 라벨만 소문자 c)

수신자 B (점선으로 위/아래 두 단계 구분)
1. (위) E_{PK_B}(k_AB) → [공개키 암호 (복호화)] → 대칭키 k_AB. 상자 위에서 "B의 개인키 SK_B"가 입력됨
2. (아래) 암호문 C → [블록 암호 (복호화)] → 평문 m. 블록 암호 상자 위에서 앞 단계에서 얻은 "대칭키 k_AB"가 입력됨

> 공개키 암호로 평문을 직접 암호화할 수도 있지만, 대용량 데이터에는 하이브리드 구조를 사용

02. RSA 암호

## RSA 암호의 개요

**RSA 암호**
- 1978년 발표 (MIT)
- Rivest · Shamir · Adleman 세 사람의 성 첫 글자
- 소인수분해 문제의 어려움에 기반
  - 가장 널리 쓰이는 공개키 암호

**사용되는 곳**
- 웹 통신에서 서버의 신원 확인 (인증서)
- 전자문서의 서명
- 대칭키를 안전하게 전달

| 기호 | 의미 | 공개 여부 |
|---|---|---|
| p, q | 서로 다른 큰 소수 | **비밀** |
| n = p × q | 모듈러스 | 공개 |
| e | 공개키를 이루는 수 (n과 함께 공개) | 공개 |
| d | 개인키가 되는 수 | **비밀** |

공개키 = (n, e)
개인키 = d

- p와 q는 키 생성 후 비밀 보관 또는 폐기 (알려지면 개인키가 계산됨)

> 소인수분해의 어려움 위에 세워진 가장 대표적인 공개키 암호

02. RSA 암호
RSA가 사용하는 문제 : 소인수분해
왜 공개키 암호의 바탕이 되는가
- 두 소수 p, q를 아는 사람 → N을 쉽게 계산
- N만 아는 사람 → p, q를 알 수 없음
- p와 q = 개인키를 만드는 재료, N = 공개키의 일부
- 공개키를 알려 주어도 개인키가 안전한 이유
곱셈은 쉽고 소인수분해는 어렵다 — 이 비대칭이 공개키 암호를 만든다

<!-- 아래는 슬라이드 이미지·도표에서 판독한 내용 -->
[도식: 소인수분해 문제의 비대칭성]
- 노란 상자 "p, q" → (실선 화살표 f, "easy") → 노란 상자 "N = p × q"
- "N = p × q" → (점선 화살표 f⁻¹, "difficult") → "p, q"
- 수치 예: 274177 × 6700417 → (easy) → 1837100231809 / 1837100231809 → (difficult) → 274177 × 6700417
  (※ 검증: Python으로 재계산 — 일치. 274177 × 6700417 = 1837100231809, 두 수 모두 소수임을 확인)

02. RSA 암호

## 소인수분해는 실제로 얼마나 어려운가

| 소인수분해 기록 | 자릿수 | 비트 수 | 비고 |
|---|---|---|---|
| 2009년 | 232자리 | 768비트 | 수백 대의 컴퓨터로 2년 |
| 2020년 2월 | 250자리 | 829비트 | 여러 연구 기관이 공동 수행 |
| 2026년 9월 | 260자리 | **862비트** (빨간 글씨) | 현재까지의 기록 |

(※ 검증: Python으로 재계산 — 자릿수↔비트 수 대응 일치. 2^768은 232자리, 2^829는 250자리, 2^862는 260자리, 2^2048은 617자리. 단, "2026년 9월 260자리 기록" 자체는 계산으로 확인할 수 없는 최신 사실로, 판독은 원문 그대로)

**자릿수가 조금만 늘어도**
- 소요 시간은 자릿수에 비례하지 않고 훨씬 가파르게 증가

## RSA 암호화와 복호화

**RSA 암호화와 복호화**
- 암호화 : c = m^e mod n
- 복호화 : m = c^d mod n
- (단, 평문 m < n)

계산 예 : 공개키 (55, 3), 개인키 27, 평문 m = 9

| 과정 | 계산 | 결과 |
|---|---|---|
| 암호화 | 9³ mod 55 = 729 mod 55 | **c = 14** |
| 복호화 | 14²⁷ mod 55 | **m = 9** |

(※ 검증: Python으로 재계산 — 일치. 9³ = 729, 729 = 13·55 + 14 → c = 14, pow(14, 27, 55) = 9)

**확인할 점**
- 두 식의 모양은 같고 지수만 다름 (e ↔ d)
- 평문은 반드시 n보다 작아야 함
  - 긴 메시지는 블록으로 나누거나 하이브리드 방식 사용
- 큰 거듭제곱도 곱할 때마다 나머지를 취하면 작은 수만 다루게 됨

## 지수 연산을 효율적으로 하는 방법

**두 가지 요령**
- ① 곱할 때마다 모듈러스로 나눈 나머지를 취한다
  - 중간에 나머지를 취해도 결과는 같음 → 수가 작게 유지됨
- ② 제곱을 반복해 필요한 것만 골라 곱한다 (제곱-곱 방법)
  - 지수를 2의 거듭제곱의 합으로 쪼갬 : 27 = 16 + 8 + 2 + 1

**① 제곱을 반복해 미리 구하기 (14ˣ mod 55)**

| 거듭제곱 | 계산 | mod 55 |
|---|---|---|
| 14² | 14 × 14 = 196 | 31 |
| 14⁴ | 31 × 31 = 961 | 26 |
| 14⁸ | 26 × 26 = 676 | 16 |
| 14¹⁶ | 16 × 16 = 256 | 36 |

**② 필요한 것만 곱하기 (14²⁷ = 14¹⁶ × 14⁸ × 14² × 14¹)**

| 곱하기 | 계산 | mod 55 |
|---|---|---|
| 14¹⁶ × 14⁸ | 36 × 16 = 576 | 26 |
| × 14² | 26 × 31 = 806 | 36 |
| × 14¹ | 36 × 14 = 504 | **9** |

(※ 검증: Python으로 재계산 — 모든 중간값 일치. 196 mod 55 = 31, 961 mod 55 = 26, 676 mod 55 = 16, 256 mod 55 = 36, 576 mod 55 = 26, 806 mod 55 = 36, 504 mod 55 = 9 = pow(14, 27, 55). 27 = 0b11011 = 16 + 8 + 2 + 1)

| 지수 | 그냥 곱하면 | 제곱-곱 방법 |
|---|---|---|
| 27 | 26 번 | **7 번** |
| 2048비트 지수 | 약 2²⁰⁴⁸ 번 (불가능) | **약 3,000 번** |

(※ 검증: Python으로 재계산 — 일치. 27제곱을 그냥 곱하면 27 − 1 = 26번, 제곱-곱은 제곱 4번 + 곱하기 3번 = 7번. 2048비트 지수는 제곱 약 2047번 + 곱하기 평균 약 1024번 ≈ 3,000번)

[오른쪽 도식 — RSA 공개키 저장소를 이용한 전체 동작 (Bob = 수신자, Alice = 송신자)]

| 아이디 | 공개키 (n, e) |
|---|---|
| A | (n_A, e_A) |
| B | (n_B, e_B) |
| **Bob** | **(n_Bob, e_Bob)** ← 회색 음영 강조 |

- 왼쪽 아래 Bob(남자 아이콘) 상자:
  - **키 생성** — ① (공개키,개인키) 생성
    - 소수 p,q 선택 ⇒ n_Bob = p × q
    - 공개키: (n_Bob, e_Bob)
    - 개인키: d_Bob
  - 열쇠 아이콘 + "개인키: d_Bob"
  - **복호화** — m = C^(d_Bob) mod n_Bob
  - 상자 아래 캡션: ⑥ 암호문을 복호화하여 평문을 얻음
- 오른쪽 아래 Alice(여자 아이콘) 상자:
  - 점선 상자 안: 열쇠 아이콘 + "공개키: (n_Bob, e_Bob)", "평문: M"
  - ↓ 화살표
  - **암호화** — C = M^(e_Bob) mod n_Bob
  - 상자 아래 캡션: ④ 평문을 암호화
- 화살표 흐름:
  1. Bob 키 생성 상자 → 구름(저장소): "② 공개된 채널에 공개키 공개"
  2. 구름(저장소) → Alice 점선 상자: "③ 수신자의 공개키"
  3. Alice 암호화 상자(C) → Bob 복호화 상자: "⑤ 암호문 전송"
- 순서 정리: ① Bob이 p, q를 골라 n_Bob = p×q, (n_Bob, e_Bob)·d_Bob 생성 → ② Bob이 공개키를 공개 저장소에 등록 → ③ Alice가 저장소에서 Bob의 공개키를 받음 → ④ Alice가 C = M^(e_Bob) mod n_Bob 계산 → ⑤ 암호문 C 전송 → ⑥ Bob이 m = C^(d_Bob) mod n_Bob 으로 복호화.

(※ 원문 표기 그대로 — 왼쪽 "순서" 목록은 ①~⑤의 5단계(④ "공개키로 암호화해 전송"이 암호화+전송을 한 단계로 묶음)인데 도식은 ①~⑥의 6단계(④ 암호화, ⑤ 암호문 전송, ⑥ 복호화)로 번호가 다름. 또 도식에서 평문을 Alice 쪽은 대문자 M, Bob 쪽 복호 결과는 소문자 m으로 표기.)
(※ 검증: 이 페이지에는 구체적 수치 예제 없음 — 식 C = M^e mod n, m = C^d mod n 은 33쪽 정리와 일치.)

# RSA의 안전성

(02. RSA 암호)

## RSA 문제
- 공개키 (n, e)와 암호문 c가 주어졌을 때 평문 m을 구하는 문제
  - 알려진 유일한 방법 : n을 소인수분해 → p, q → d 계산

## 안전성의 근거
- n을 소인수분해할 수 있으면 RSA는 깨짐
- 소인수분해보다 쉬운 공격은 아직 발견되지 않음
  - 증명된 것이 아니라 "아직 발견되지 않은" 것 (빨간 글씨)

## 지켜야 할 사항
- n은 2048비트 이상
- 두 소수가 서로 너무 가깝지 않아야 함
  - p, q가 비슷하면 n의 제곱근 근처에서 찾을 수 있음
- 소수를 고를 때 안전한 난수를 사용
  - 예측 가능하게 고르면 공격자도 같은 소수를 찾음

> **같은 평문 + 같은 공개키 → 항상 같은 암호문**
> **→ 실제로는 평문에 난수를 섞는 패딩을 적용해 매번 다른 암호문이 나오게 함** (주황 강조 상자)

# 또 하나의 어려운 문제 : 이산대수 문제

## 7^x mod 13 의 값 (x = 1 ~ 9)  (왼쪽 상자, 2열 목록)

| 왼쪽 열 | 오른쪽 열 |
|---|---|
| 7^0 mod 13 = 1 | 7^5 mod 13 = 11 |
| 7^1 mod 13 = 7 | 7^6 mod 13 = 12 |
| 7^2 mod 13 = 10 | 7^7 mod 13 = 6 |
| 7^3 mod 13 = 5 | 7^8 mod 13 = 3 |
| **7^4 mod 13 = 9** (빨간 굵은 글씨 강조) | 7^9 mod 13 = 8 |

(※ 검증: Python으로 재계산 — [pow(7,x,13) for x in 0..9] = 1, 7, 10, 5, 9, 11, 12, 6, 3, 8 로 10개 값 모두 일치. 7의 13에 대한 위수는 12(원시근)라 x = 0~11에서 1~12가 한 번씩 나옴 — "규칙 없이 흩어짐"의 예.)
(※ 원문 표기 그대로 — 캡션은 "x = 1 ~ 9"이지만 목록에는 x = 0도 포함되어 실제로는 x = 0 ~ 9.)

## 왜 어려운가
- 보통의 대수 : 7^x = 49 → x = 2 (쉽게 구함)
- 모듈러 연산 : 결과가 규칙 없이 흩어짐
  - 결과만 보고 지수를 짐작할 수 없음
- 모듈러스가 수백 자리가 되면
  - 표를 만들 수 없고 효율적인 방법도 알려지지 않음 (빨간 글씨)

(※ 검증: Python으로 재계산 — 7^2 = 49 — 일치)

## 이산대수 문제 (Discrete Logarithm Problem)
- αˣ mod p 를 계산하는 것은 쉬움
- αˣ mod p = β 를 만족하는 x를 찾는 것은 어려움

| 어려운 문제 | 한 방향은 쉬움 | 반대 방향은 어려움 | 이 문제에 기반한 기술 |
|---|---|---|---|
| 소인수분해 | p × q = N | N → p, q | RSA |
| 이산대수 | αˣ mod p 계산 | 결과에서 x 찾기 | 엘가말, 타원곡선 암호, 디피-헬만 |

# 엘가말 암호 (ElGamal) 의 구조

(03. 엘가말 암호)

도식: 왼쪽 열 = 앨리스 (보내는 사람), 오른쪽 열 = 밥 (받는 사람). 위에서 아래로 진행.

**[밥 (받는 사람)]**
- ① 비밀값 d 선택
- ② β = α^d mod p 계산
- → 공개키 (p, α, β), 개인키 d (d는 빨간 글씨)

**밥 → 앨리스 (왼쪽 화살표)** : 공개키 (p, α, β) 공개

**[앨리스 (보내는 사람)]**
- ③ 임시 비밀값 i 선택
- ④ 임시 공개값 c₁ = α^i mod p
- ⑤ 마스킹 키 = β^i mod p
- ⑥ 마스킹된 평문 c₂ = 평문 × 마스킹 키 mod p

**앨리스 → 밥 (오른쪽 화살표)** : 암호문 (c₁, c₂) 전송

**[밥 (받는 사람)]**
- ⑦ 마스킹 키 = c₁^d mod p (앨리스와 같은 값)
- ⑧ 평문 = c₂ ÷ 마스킹 키 mod p

## 왜 같은 마스킹 키가 나오는가 (녹색 상자)
- 앨리스 : β^i = (α^d)^i
- 밥 : c₁^d = (α^i)^d
  - 둘 다 α^(d×i) mod p → 같은 값 (빨간 글씨)

> **밥의 공개키와 앨리스의 임시 비밀값으로 "둘만 아는 일회용 키"를 만들어 평문을 가린다** (주황 강조 상자)

(※ 검증: 23쪽 수치(p = 29, α = 2, d = 12, i = 5)로 Python 재계산 — (α^d)^i mod p = 7^5 mod 29 = 16, (α^i)^d mod p = 3^12 mod 29 = 16, α^(d×i) = 2^60 mod 29 = 16 — 일치)

# 엘가말 암호의 계산 예와 특징

(03. 엘가말 암호)

| 단계 | 계산 | 결과 |
|---|---|---|
| 밥의 키 | d = 12, β = 2¹² mod 29 | β = 7 |
| 앨리스의 임시값 | i = 5, c₁ = 2⁵ mod 29 | c₁ = 3 |
| 마스킹 키 | β^i = 7⁵ mod 29 | 16 |
| 암호화 | c₂ = 15 × 16 = 240 mod 29 | **암호문 (3, 8)** (빨간 글씨) |
| 복호화 | 3¹² mod 29 = 16, 8 ÷ 16 mod 29 | **평문 15** (빨간 글씨) |

※ 모듈러 연산에서 나누기 = 곱셈 역원을 곱하기 (16의 역원은 20, 8 × 20 = 160 ≡ 15 mod 29)

(※ 검증: Python으로 재계산 — 일치. 공개값 p = 29, α = 2 (2의 29에 대한 위수 28 = 원시근). 2¹² = 4096, 4096 mod 29 = 7 → β = 7 / 2⁵ = 32, 32 mod 29 = 3 → c₁ = 3 / 7⁵ = 16807, 16807 mod 29 = 16 → 마스킹 키 16 / 15 × 16 = 240, 240 mod 29 = 8 (240 = 8×29 + 8) → c₂ = 8, 암호문 (3, 8) / 복호화: 3¹² = 531441, 531441 mod 29 = 16 (앨리스의 마스킹 키와 같음) / pow(16, -1, 29) = 20 (16 × 20 = 320 = 11×29 + 1) / 8 × 20 = 160, 160 mod 29 = 15 (160 = 5×29 + 15) → 평문 15 = 원래 평문 15.)

## 특징
- 매번 다른 임시값 → 같은 평문도 매번 다른 암호문
  - RSA는 패딩이 없으면 같은 암호문
- **암호문이 두 값 → 평문의 두 배 길이** (빨간 글씨)
- 이산대수 문제에 기반

## 주의 (빨간 상자)
- 임시 비밀값 재사용 금지
  - 같은 값을 두 번 쓰면 두 암호문의 관계에서 평문이 드러남

> **엘가말 = 일회용 마스킹 키로 평문을 가리는 공개키 암호** (주황 강조 상자)

(※ 참고: 31쪽 디피-헬만 계산 예와 같은 수(p = 29, α = 2, 5와 12)를 써서 공유값/마스킹 키가 똑같이 16이 됨.)

# 엘가말 암호의 특징

(03. 엘가말 암호)

## ① 매번 다른 암호문
- 보낼 때마다 새로운 임시 비밀값 사용
  - 후보 평문을 암호화해 비교하는 공격이 통하지 않음

## ② 암호문이 두 배 길이
- 암호문 = (임시 공개값, 마스킹된 평문)
  - 저장 공간과 통신량이 두 배로 늘어남 (빨간 글씨)

## ③ 임시 비밀값 재사용 금지 (빨간 상자)
- 같은 임시값을 두 번 쓰면 마스킹 키도 같아짐
  - 두 암호문의 관계에서 평문 정보가 드러남 (빨간 글씨)
- "같은 값을 두 번 쓰지 않는다"는 원칙이 그대로 적용

| 구분 | RSA | 엘가말 |
|---|---|---|
| 기반 문제 | 소인수분해 | 이산대수 |

| 암호문 길이 | 평문과 비슷 | 평문의 두 배 |
| 암호화 때마다 난수 | 패딩에 사용 | 임시 비밀값으로 반드시 필요 |

# 타원곡선 암호 (ECC)

(04. 타원곡선 암호와 비교)

## 그림 — 타원곡선의 예 : y² = x³ + ax + b
실수 평면 위 두 곡선 그래프(가로축 −2 ~ 8, 세로축 −4 ~ 4, 빨간 곡선, 연두색 라벨 상자):
- 왼쪽 그래프 **y² = x³ − 4x** : x = −2 ~ 0 사이의 닫힌 타원 고리 하나 + x = 2에서 시작해 오른쪽 위·아래로 뻗는 곡선 → **3 개의 실근 (x = −2, x = 0, and x = 2)**
- 오른쪽 그래프 **y² = x³ − 1** : 하나로 이어진 곡선(꼭짓점이 x축 위 0과 2 사이) → **오직 1개의 실근 (x = 1), 두개의 허근**

(※ 검증: Python numpy.roots — x³ − 4x = 0 의 근 = −2, 0, 2 / x³ − 1 = 0 의 근 = 1, −0.5 ± 0.866i (허근 2개) — 일치. 오른쪽 그래프 곡선의 꼭짓점은 x = 1이어야 하는데 그림에서는 0과 2 사이 약간 왼쪽(약 0.5 부근)에 그려진 것처럼 보임 (판독 확신 낮음, 그림 정밀도 문제로 보임).)

## 기본 아이디어
- 곡선 위의 점들 사이에 덧셈 연산을 정의
- 점 P를 k번 더해 점 Q를 만드는 것은 쉬움
  - P와 Q만 보고 k를 알아내는 것은 어려움 (빨간 글씨)
- k = 개인키, Q = 공개키

## 안전성 수준별 키 길이

| 안전성 수준 | 대칭키 암호 | RSA | 타원곡선 암호 |
|---|---|---|---|
| 보통 | 112비트 | 2048비트 | 224비트 |
| 권장 | 128비트 | 3072비트 | **256비트** (빨간 굵은 글씨) |
| 높음 | 192비트 | 7680비트 | 384비트 |

(※ 검증: NIST SP 800-57 Part 1의 보안 강도 대응표(112 ↔ RSA 2048 ↔ ECC 224, 128 ↔ 3072 ↔ 256, 192 ↔ 7680 ↔ 384)와 일치. 타원곡선 키 길이 = 대칭키 보안 강도의 2배 관계도 3행 모두 성립.)

> **같은 안전성에 훨씬 짧은 키 → 저장 공간 · 통신량 · 계산량 감소**
> **스마트카드, 사물인터넷 기기, 모바일 환경에서 널리 사용** (주황 강조 상자)

# 공개키 암호의 미래 : 양자 컴퓨터

(04. 타원곡선 암호와 비교)

## 양자 컴퓨터가 등장하면 (빨간 상자)
- 소인수분해와 이산대수를 효율적으로 푸는 알고리즘이 이미 존재
  - RSA · 엘가말 · 타원곡선 암호 모두 안전성을 잃음 (빨간 글씨)
- 대칭키 암호는 키 길이를 늘려 대응 가능하지만
  - 공개키 암호는 키를 늘려도 소용없음 (빨간 글씨)

## 대응 : 양자내성암호 (녹색 상자)
- 전혀 다른 수학 문제에 기반한 새로운 공개키 암호
- 현재 표준화가 진행되어 일부 알고리즘이 채택됨
  - 기존 시스템에서 알고리즘을 교체할 수 있도록 설계해 두는 것이 중요

## "지금 저장해 두었다가 나중에 해독한다"
- 공격자가 지금 오가는 암호문을 저장해 둘 수 있음
- 먼 미래에 양자 컴퓨터로 해독 가능
  - 지금 보호한 정보라도 미래에 읽힐 수 있다는 뜻 (빨간 글씨)
- 보관 기간이 긴 정보(의료 · 유전 정보 등)일수록 더 중요

> **암호의 안전성은 영원하지 않다 — 알고리즘을 바꿀 수 있도록 미리 준비해 두어야 한다** (주황 강조 상자)

# 키 교환 : 암호가 아니라 "키를 만드는" 기술

(05. 키 교환과 디피-헬만)

## 방법 ① 키 전송 (Key Transport)
- 한쪽이 대칭키를 만들어 상대의 공개키로 암호화해 전송
- 받는 쪽은 개인키로 복호화해 같은 키 획득
  - RSA 같은 공개키 암호를 사용
  - 한쪽이 키를 정함

## 방법 ② 키 합의 (Key Agreement)
- 양쪽이 각각 비밀값을 정하고 공개 정보를 교환
- 결과적으로 양쪽이 같은 키를 만들어 냄
  - 어느 한쪽이 정하지 않고 함께 만들어 냄
  - 대표 : 디피-헬만 키 교환 (빨간 글씨)

| 구분 | 키 전송 | 키 합의 |
|---|---|---|
| 키를 정하는 주체 | 한쪽 | 양쪽이 함께 |
| 사용하는 기술 | RSA 등 공개키 암호를 활용 | 디피-헬만 등 키 합의 방식 |

> **공개키 암호 = 메시지를 암호화하는 기술 / 키 교환 = 같은 키를 만들어 내는 기술** (주황 강조 상자)

# 디피-헬만 키 교환의 아이디어

(05. 키 교환과 디피-헬만)

색 섞기 비유 도식 (위에서 아래로):

1. **① 공통 색을 공개로 정한다** → [공통 색] (회청색 상자, 가운데)
2. **② 각자 비밀 색을 정한다** → 왼쪽 [앨리스의 비밀 색] (청록 상자) / 오른쪽 [밥의 비밀 색] (주황 상자)
3. **③ 공통 색 + 자기 비밀 색을 섞어 전송 (공개되어도 안전)** → 왼쪽 [섞은 색 A] ⇄ 오른쪽 [섞은 색 B]
   - 화살표: 섞은 색 A → 밥 쪽(오른쪽)으로, 섞은 색 B → 앨리스 쪽(왼쪽)으로 서로 교환
4. **④ 받은 색에 다시 자기 비밀 색을 섞는다 → 양쪽이 같은 색**
   - 왼쪽(앨리스) [공통 색 + 앨리스 색 + 밥 색] **=** 오른쪽(밥) [공통 색 + 밥 색 + 앨리스 색] (두 녹색 상자)

## 공격자는? (빨간 상자)
- 공통 색과 주고받은 섞인 색은 볼 수 있음
- 그러나 섞인 색에서 비밀 색을 분리할 수 없음
  - 색 섞기는 쉽고 분리는 어렵다 = 거듭제곱은 쉽고 이산대수는 어렵다 (빨간 글씨)

# 디피-헬만 키 교환의 절차

(05. 키 교환과 디피-헬만)

**공개 정보 : 큰 소수 p, 1 < α < p 인 수 α (공격자도 알고 있음)**

| | 앨리스 | 밥 |
|---|---|---|
| ① | 비밀값 a 선택 (혼자만 안다) | 비밀값 b 선택 (혼자만 안다) |
| ② | 공개값 A = α^a mod p 계산 | 공개값 B = α^b mod p 계산 |
| 전송 | A 전송 → (앨리스 → 밥, 오른쪽 화살표) | ← B 전송 (밥 → 앨리스, 왼쪽 화살표) |
| ③ | 공유 비밀 = B^a mod p | 공유 비밀 = A^b mod p |

> **앨리스 : (α^b)^a 밥 : (α^a)^b → 둘 다 α^(a×b) mod p = 같은 값**
> **이 값을 대칭키로 사용해 실제 데이터를 암호화** (주황 강조 상자)

(※ 검증: 31쪽 수치(p = 29, α = 2, a = 5, b = 12)로 Python 재계산 — (α^b)^a = 7^5 mod 29 = 16, (α^a)^b = 3^12 mod 29 = 16, α^(a×b) = 2^60 mod 29 = 16 — 일치)

# 디피-헬만 계산 예

(05. 키 교환과 디피-헬만)

**공개 정보 : p = 29, α = 2**

| 단계 | 앨리스 | 밥 |
|---|---|---|
| ① 비밀값 | a = 5 | b = 12 |
| ② 공개값 계산 | A = 2⁵ mod 29 = 32 mod 29 = 3 | B = 2¹² mod 29 = 4096 mod 29 = 7 |
| ③ 서로 전송 | A = 3 을 밥에게 | B = 7 을 앨리스에게 |
| ④ 공유 비밀 | **7⁵ mod 29 = 16** (빨간 글씨) | **3¹² mod 29 = 16** (빨간 글씨) |

(※ 검증: Python으로 재계산 — 일치. 2⁵ = 32, 32 mod 29 = 3 / 2¹² = 4096, 4096 = 141×29 + 7 → 7 / 앨리스: 7⁵ = 16807, 16807 mod 29 = 16 / 밥: 3¹² = 531441, 531441 mod 29 = 16 / 직접 α^(a×b) = 2^60 mod 29 = 16. α = 2는 mod 29의 원시근(위수 28).)

> **두 사람은 비밀값을 모른 채 같은 값 16을 얻었다** (녹색 강조 상자)

## 공격자가 볼 수 있는 것 (빨간 상자)
- 공개 정보 p = 29, α = 2
- 주고받은 공개값 A = 3, B = 7
  - 공유 비밀 16을 구하려면 2ˣ mod 29 = 3 인 x를 찾아야 함 (= 이산대수 문제) (빨간 글씨)
- 실제로는 2048비트 이상의 소수를 사용

(※ 검증: Python 전수 탐색 — 2ˣ mod 29 = 3 을 만족하는 x (1 ≤ x ≤ 28) 는 x = 5 하나뿐(= a), 2ˣ mod 29 = 7 은 x = 12(= b). 작은 p에서는 전수 탐색으로 바로 풀리므로 실제로는 2048비트 이상 소수가 필요하다는 설명과 일치.)
(※ 원문 표기 그대로 — "두 사람은 비밀값을 모른 채"는 '상대의 비밀값을 모른 채'라는 뜻.)

# 중간자 공격 : 공격자는 어떻게 키를 만드는가

(05. 키 교환과 디피-헬만)

## 도식 (왼쪽 → 가운데 → 오른쪽)
[앨리스 비밀값 a] (파란 상자) ⇄ [공격자 비밀값 m] (빨간 상자) ⇄ [밥 비밀값 b] (주황 상자)

전송 순서:
1. 앨리스 → 공격자 (검은 화살표) : A = α^a — 공격자가 가로챔
2. 공격자 → 밥 (빨간 화살표) : α^m (가로챈 후 대신 보냄)
3. 밥 → 공격자 (검은 화살표) : B = α^b — 공격자가 가로챔
4. 공격자 → 앨리스 (빨간 화살표) : α^m (가로챈 후 대신 보냄)

## 각자 계산하는 키

| | 앨리스가 계산 | 공격자가 계산 | 밥이 계산 |
|---|---|---|---|
| 앨리스 ↔ 공격자 | (α^m)^a = α^(m×a) | A^m = α^(a×m) | — |
| 공격자 ↔ 밥 | — | B^m = α^(b×m) | (α^m)^b = α^(m×b) |

(표 안 수식은 모두 빨간 굵은 글씨)

## 결과 (빨간 상자)
- 공격자는 두 개의 키를 가짐 : 앨리스와 공유하는 키, 밥과 공유하는 키
- 앨리스의 메시지를 복호화해 읽고, 다시 암호화해 밥에게 전달
  - 두 사람은 서로 직접 공유했다고 믿어 아무 이상도 느끼지 못함 (빨간 글씨)

> **이산대수 문제는 전혀 깨지지 않았다 — 멜로리는 a도 b도 알아내지 못했다**
> **공격이 성공한 이유는 "받은 값이 누구에게서 왔는지" 확인하지 않았기 때문** (주황 강조 상자)

(※ 원문 표기 그대로 — 도식·표에서는 "공격자"로 쓰다가 하단 강조 상자에서만 "멜로리"(Mallory)라는 이름이 등장함. 같은 공격자를 가리킴.)
(※ 검증: 31쪽 수치 p = 29, α = 2, a = 5, b = 12에 공격자 비밀값 m = 9(임의 예시, 원문에 없음)를 넣어 Python 재계산 — α^m = 2^9 mod 29 = 19; 앨리스 (α^m)^a = 19^5 mod 29 = 21 = 공격자 A^m = 3^9 mod 29 = 21; 밥 (α^m)^b = 19^12 mod 29 = 20 = 공격자 B^m = 7^9 mod 29 = 20. 두 키(21, 20)가 서로 다르고 정상 공유값 16과도 다름 — 표의 관계식과 일치.)

# 핵심 정리 (1) : 공개키 암호

| 주제 | 내용 |
|---|---|
| 공개키 암호의 원리 | 일방향 함수 : 한쪽은 쉽고 반대는 어려움<br>트랩도어 : 비밀 정보(= 개인키)를 알면 반대 방향도 쉬워짐 |
| RSA (소인수분해) | n = p × q, L = (p−1)(q−1), gcd(e, L) = 1, e × d ≡ 1 (mod L)<br>암호화 c = mᵉ mod n, 복호화 m = c^d mod n / 2048비트 이상 + 난수 패딩 |
| 엘가말 (이산대수) | 임시 비밀값으로 둘만 아는 일회용 마스킹 키를 만들어 평문을 가림<br>매번 다른 암호문, 길이는 두 배, 임시값 재사용 금지 |
| 타원곡선 암호 | 점을 k번 더하기는 쉽고, P와 Q에서 k를 찾기는 어려움<br>같은 안전성에 훨씬 짧은 키 (RSA 2048 비트 수준 → 타원곡선 224비트) |

(※ 검증: RSA 식의 일관성을 Python으로 장난감 수치 확인(원문에 수치 없음) — p = 61, q = 53 → n = 3233, L = 3120, e = 17 (gcd(17, 3120) = 1), d = pow(17, -1, 3120) = 2753 (17 × 2753 = 46801 = 15×3120 + 1), m = 65 → c = 65^17 mod 3233 = 2790 → 2790^2753 mod 3233 = 65 — 식 체계 일치. "RSA 2048 ↔ 타원곡선 224"는 25·26쪽 표와 일치.)
