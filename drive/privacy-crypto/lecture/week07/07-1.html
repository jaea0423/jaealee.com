공개키 암호는 오늘날 현대 보안 체계를 떠받치는 핵심 기술 중 하나입니다. 암호화에 쓰는 키와 복호화에 쓰는 키를 다르게 만들어 비밀키를 미리 나눠 갖지 않고도 안전하게 통신하게 해 줍니다. 처음 접속한 웹사이트와도 곧바로 암호 통신을 시작할 수 있는 것이 이 덕분이고, 키 교환 · 전자서명 · 인증서까지 모두 공개키 기술 위에 만들어져 있습니다.

대칭키 암호 시스템의 문제점교안 p.4

  1. 안전한 채널을 통해 송/수신자 간 서로 동일한 키를 사전에 공유할 필요가 있음 — 키 분배 문제 (Key distribution problem)
  2. n명이 서로 비밀통신을 하기 위해서는 n(n−1)/2 개의 키가 필요함 — Ex) 재학생 1000명이 대칭키 암호 통신하기 위해 필요한 키는 1인당 999개 필요, 전체 키의 수: 1000 × 999 ÷ 2 = 499,500 개 — 키 유지 관리의 어려움
  3. 송신자나 수신자의 부인방지를 제공하지 못함 — 부인방지: 메시지를 전송한 송신자나 수신한 수신자가 나중에 그 사실을 부인할 수 없도록 하는 기능

교수님 말씀 — 04:27

그런데 안전한 채널이 이미 있다면 애초에 암호화가 필요 없겠죠. 그런 채널이 없기 때문에 키 분배 문제가 생깁니다. 천 명이 통신하면 한 사람이 999개, 전체로는 약 50만 개의 키가 생기고, 키를 만들고 나눠 주고 폐기하는 관리 자체가 큰 부담입니다. 또 송신자와 수신자가 똑같은 키를 가지고 있어서 어떤 메시지를 둘 중 누가 만들었는지 제3자에게 증명할 방법이 없습니다 — 부인방지를 못 하는 이유입니다.

이산수학과 연결 — 완전 그래프 Kₙ — 교수님 설명 아님

사람을 꼭짓점, 공유 키를 간선으로 보면 모든 쌍이 연결된 완전 그래프 Kₙ이고 간선 수는 C(n, 2) = n(n−1)/2입니다. 그림은 K₄(간선 6개), 1000명은 K₁₀₀₀(간선 499,500개)입니다. 대칭키는 "두 사람만 아는 비밀"이라 둘이 같은 키를 쓰면 누가 보냈는지 제3자에게 증명할 수 없어 부인방지가 안 됩니다(4주차 MAC과 같은 이유).

공개키 암호 시스템교안 p.5

  • 각자 한 쌍의 키 (공개키 pk, 개인키 sk) 소유 — 공개키는 모두에게 공개되고 개인키는 비밀로 보관
  • 공개키 pk와 개인키 sk는 서로 수학적인 관계를 가짐 — pk로부터 sk를 도출하는 것은 계산적으로 불가능 (Computationally Infeasible)
  • 암/복호화 과정이 전혀 다름 — 비대칭키 (asymmetric) 암호시스템이라 하는 이유, 개인키를 소유한 사람이 암호문을 복호화 가능

교수님 말씀 — 07:12

여기서 중요한 성질이 두 가지인데, 하나는 암호화와 복호화에 서로 다른 키를 쓴다는 겁니다. 암호화할 때는 밥의 공개키, 복호화할 때는 밥의 개인키 — 그래서 비대칭키 암호라고도 부릅니다. 공개키로 잠근 것은 공개키로 열 수 없고 짝이 되는 개인키로만 열립니다. 다른 하나는 공개키와 개인키가 수학적으로 연결된 한 쌍이라는 점입니다.

교수님 말씀 — 07:39

공개키(public key)는 보통 PK, 개인키(secret key)는 SK로 씁니다. 공개키와 개인키는 수학적으로 연결된 한 쌍이니 공개키에서 개인키를 계산할 수 있지 않냐고 생각할 수 있는데, 이론적으로는 가능합니다. 다만 그 계산이 현실적인 시간 안에 끝나지 않도록 설계되어 있고, 이것이 "계산적으로 불가능"의 뜻입니다. 이 성질 덕분에 공개키를 전 세계에 공개해도 안전합니다.

점 P, Q를 지나는 직선이 곡선과 만나는 세 번째 점을 x축에 대해 뒤집은 점을 P + Q로 정합니다(P = Q이면 접선을 씀). 이 규칙으로 P + P + … (k번) = kP를 계산하는데, 제곱-곱 방법과 같은 원리(두 배 · 더하기)로 k가 커도 빠릅니다. 실제 암호에서는 실수 평면이 아니라 큰 소수 p로 나눈 나머지(유한체) 위의 점들을 쓰고, "kP에서 k 찾기"가 타원곡선 이산대수 문제입니다. 표에서 타원곡선 키 길이는 대칭키 안전성의 약 2배(112 → 224 …)입니다. 정확히는 NIST 기준 범위(112비트 → 224~255비트 등)의 최솟값이 2배입니다. 또 NIST는 112비트 수준(RSA 2048 · ECC 224)을 2030년까지만 허용하고 그 뒤로는 128비트 이상(RSA 3072 · ECC 256)을 요구합니다 — 교수님의 "더 긴 보호 기간이면 3072"와 같은 맥락입니다.

13용어 정리

키 분배 문제Key distribution problem

대칭키를 안전한 채널로 미리 나눠 가져야 하는 문제.

부인방지Non-repudiation

보내거나 받은 사실을 나중에 부인할 수 없게 하는 기능. 대칭키로는 불가.

공개키 · 개인키public key · private key

공개키(pk)는 모두에게 공개, 개인키(sk)는 비밀. pk에서 sk 도출은 계산적으로 불가능.

비대칭키 암호asymmetric cryptosystem

암호화 키와 복호화 키가 다른 암호 = 공개키 암호.

하이브리드 암호hybrid cryptosystem

대칭키를 공개키로 암호화해 전달하고 데이터는 대칭키로 암호화.

일방향 함수One-way Function

f(x) 계산은 쉽고 f⁻¹은 계산적으로 불가능한 함수.

트랩도어trapdoor

알면 일방향 함수를 쉽게 되돌릴 수 있는 비밀 정보 = 개인키.

계산적으로 불가능Computationally Infeasible

이론상 가능하지만 현실적으로 감당할 수 없는 시간이 걸림.

소인수분해 문제factorization problem

N = p × q에서 p, q를 찾는 문제. RSA의 바탕.

모듈러스modulus

mod 연산에서 나누는 수. RSA의 n = p × q.

곱셈 역원multiplicative inverse

e × d ≡ 1 (mod L)인 d. gcd(e, L) = 1일 때만 존재.

제곱-곱 방법square-and-multiply

지수를 2진수로 보고 제곱을 반복해 필요한 것만 곱하는 거듭제곱 계산법.

확률적 소수 판정법probabilistic primality test

소수가 아니면 높은 확률로 걸러내는 검사를 반복하는 방법.

이산대수 문제Discrete Logarithm Problem

αˣ mod p = β에서 x를 찾는 문제. 엘가말 · ECC · DH의 바탕.

마스킹 키masking key

엘가말에서 평문을 곱해 가리는 일회용 값 α^(d×i) mod p.

타원곡선 암호ECC, Elliptic Curve Cryptography

곡선 위 점의 k배(kP)에서 k를 찾기 어려운 성질 이용. 짧은 키.

양자내성암호post-quantum cryptography

양자 컴퓨터로도 풀기 어려운 다른 수학 문제에 기반한 공개키 암호.

키 전송 · 키 합의Key Transport · Key Agreement

한쪽이 만든 키를 공개키로 전달 vs 양쪽이 함께 같은 키를 만듦(DH).

디피-헬만Diffie-Hellman

공개값 αᵃ, αᵇ를 교환해 둘 다 α^(ab)를 얻는 키 합의.

중간자 공격Man-in-the-Middle attack

가운데서 양쪽과 각각 키를 만들어 중계 · 열람하는 공격. 상대 확인이 없을 때 성공.

Q5디피-헬만 키 교환이 중간자 공격에 당하는 과정을 설명하고, 이때 이산대수 문제가 깨졌는지와 대응 방법을 쓰시오.서술형
모범답안공격자가 앨리스의 A = αᵃ와 밥의 B = αᵇ를 가로채고 각자에게 자신의 α^m을 대신 보낸다. 앨리스는 α^(ma), 밥은 α^(mb)를 계산하고, 공격자는 A^m · B^m으로 두 키를 모두 가져 앨리스의 메시지를 복호화해 읽은 뒤 밥의 키로 다시 암호화해 전달한다. 이산대수 문제는 깨지지 않았다(a, b는 모름). 받은 값이 누구에게서 왔는지 확인하지 않은 것이 원인이므로 전자서명 · 인증서로 상대를 확인해야 한다.
Q6하이브리드 암호 시스템이 필요한 이유를 대칭키 · 공개키 각각의 단점으로 설명하시오.서술형
모범답안대칭키 암호는 빠르지만 비밀키를 미리 안전하게 공유해야 하는 키 분배 문제(와 n(n−1)/2 키 관리 문제)가 있고, 공개키 암호는 키 분배가 필요 없지만 수백 배 이상 느리다. 그래서 대칭키 k를 상대의 공개키로 암호화해 전달하고(짧은 데이터라 느려도 됨), 대용량 데이터는 k로 대칭키 암호화한다 — 서로의 약점을 보완.
