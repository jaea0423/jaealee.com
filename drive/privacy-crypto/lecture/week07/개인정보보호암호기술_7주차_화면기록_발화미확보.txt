- 키 유지 관리의 어려움
3. 송신자나 수신자의 부인방지를 제공하지 못함
- 부인방지: 메시지를 전송한 송신자나 수신한 수신자가 나중에 그 사실을 부인할 수 없도록 하는 기능

화면: 슬라이드 5. ‘01. 공개키 암호의 원리 / 공개키 암호 시스템’.
• 각자 한 쌍의 키 (공개키 pk, 개인키 sk) 소유
- 공개키는 모두에게 공개되고 개인키는 비밀로 보관
- 공개키 pk와 개인키 sk는 서로 수학적인 관계를 가짐
  • pk로부터 sk를 도출하는 것은 계산적으로 불가능 (Computationally Infeasible)
• 암/복호화 과정이 전혀 다름
- 비대칭키 (asymmetric) 암호시스템이라 하는 이유
- 개인키를 소유한 사람이 암호문을 복호화 가능
왼쪽 아래에는 네 사람과 각자의 키 쌍 (pk_A, sk_A), (pk_B, sk_B), (pk_C, sk_C), (pk_D, sk_D)이 있다. 오른쪽에는 자물쇠들이 모인 Public Registry, Alice와 Bob의 그림. 1. 공개키 획득: Public Registry에서 Alice로 향하는 화살표. 2. 암호문 전송: Alice에서 Bob으로 향하는 화살표와 C = Enc_pkB(m). Bob 위에 서로 다른 자물쇠 pk_B와 열쇠 sk_B가 표시된다. 3. 복호화: M = Dec_skB(C).
하단 문구: ‘공개키로 암호화 → 짝이 되는 개인키로만 복호화 / 공개키에서 개인키를 구하는 것은 계산적으로 불가능’.

화면: 슬라이드 8. ‘01. 공개키 암호의 원리 / 일방향 함수 (One-way Function)’.
왼쪽 위 그림: Set A의 x에서 Set B의 y로 가는 실선 화살표에 f, easy가 표시되고, 반대 방향 점선 화살표에 f⁻¹, difficult가 적혀 있다. 위에는 y=f(x). 왼쪽 아래 그림은 사과·오렌지·포도가 믹서기를 거쳐 주스가 되는 순방향 화살표(easy)와 반대 방향 화살표(difficult)이다.
오른쪽 파란 상자 ‘일방향 함수’:
• x → f(x) 계산은 쉬움
• y가 주어졌을 때 x를 찾는 것은 매우 어려움
- 과일 → 주스는 쉽지만, 주스 → 과일은 불가능
오른쪽 주황 상자 ‘"어렵다"의 의미’:
• 이론적으로 불가능하다는 뜻이 아님
• 모든 경우를 시도하면 언젠가는 찾을 수 있음
- 다만 그 시간이 현실적으로 감당할 수 없음
- = 계산적으로 불가능
하단 문구: ‘일방향 함수만으로는 암호를 만들 수 없다 — 정당한 수신자는 되돌릴 수 있어야 하기 때문’.

화면: 슬라이드 10. ‘02. RSA 암호 / RSA 암호의 개요’.
왼쪽 위 파란 상자 ‘RSA 암호’:
• 1978년 발표 (MIT)
• Rivest · Shamir · Adleman 세 사람의 성 첫 글자
• 소인수분해 문제의 어려움에 기반
- 가장 널리 쓰이는 공개키 암호
왼쪽 아래 녹색 상자 ‘사용되는 곳’:
• 웹 통신에서 서버의 신원 확인 (인증서)
• 전자문서의 서명
• 대칭키를 안전하게 전달
오른쪽 표 ‘기호 / 의미 / 공개 여부’:
p, q / 서로 다른 큰 소수 / 비밀
n = p × q / 모듈러스 / 공개
e / 공개키를 이루는 수 (n과 함께 공개) / 공개
d / 개인키가 되는 수 / 비밀
