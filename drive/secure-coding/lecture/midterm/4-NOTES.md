## [4-NOTES] 7주차 2차시 · innerHTML로 넣은 script 태그 실행 여부 (C)

- [2-SLIDES] 7주차 2차시 p.24 · [7주차 2차시 33:38]: 사용자 입력을 innerHTML에 넣으면 script 태그가 실행된다고 설명.

## [4-NOTES] 7주차 2차시 · DOM XSS 실습의 핵심 (C)
키워드: DOM XSS, 서버 이스케이프, unescape, document.write, 디코딩
- 실습 흐름: 서버가 꺾쇠를 HTML 인코딩해서 넘겨도, 클라이언트 스크립트가 받은 값을 다시 디코딩(unescape)한 뒤 document.write로 출력함.
- 핵심: **서버의 이스케이프가 클라이언트의 재디코딩으로 무력화**됨. DOM 조작 전에 클라이언트에서도 정제해야 하고, document.write 대신 안전한 출력을 써야 함. ([2-SLIDES] 7주차 2차시 p.17 · 2차시 실습과 일치)

## [4-NOTES] 5주차 3차시 · JWT 서명=암호화 / 공개키 검증 — 부정확 (C)
키워드: JWT, HS256, HMAC, 서명, 대칭키, 비대칭키
- 발화([3-TRANSCRIPT] 5주차 3차시): 서명을 "비밀키로 암호화", 검증을 "공개키로"라고 함.
- 바로잡음: 교안 실습의 HS256은 **대칭키(HMAC)** — 서명·검증에 같은 비밀키. 암호화가 아니라 키를 넣은 해시. 공개키 검증은 RS256·ES256 같은 비대칭 방식에만 해당. 교수님도 [5주차 3차시 25:30]에는 대칭키라고 정리함.

## [4-NOTES] 4주차 2차시 · ReDoS 예시 설명 — 부정확 (C)
키워드: ReDoS, 백트래킹, 정규식, 성능
- [4주차 2차시 24:50]·[2-SLIDES] 4주차 2차시 p.24: 교안 예시(끝이 X인 a 문자열을 ^(a+)+X$ 로 검사)가 입력이 많을수록 급격히 느려진다고 설명.
- 바로잡음: 그 예시 입력은 끝이 X라서 매칭에 **성공**해 바로 끝남(느리지 않음). ReDoS는 보통 매칭에 **실패하는** 입력(끝 문자가 다르거나 X가 없는 경우)에서 백트래킹이 폭증. 개념(중첩 반복 + 실패 입력 = 지수적 시간)은 교안대로 답하면 됨.
