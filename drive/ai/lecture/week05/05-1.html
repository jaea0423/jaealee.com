01사례 기반 학습 vs 모델 기반 학습

Instance-based Learning / Model-based Learning

세 번째 분류 기준은 새 데이터가 들어왔을 때 어떻게 예측하느냐입니다. 머신러닝의 목적은 결국 처음 보는 데이터에 대해 좋은 예측을 하는 것(일반화)인데, 여기에 두 가지 방법이 있습니다.

사례 기반 (Instance-based)모델 기반 (Model-based)
방식예시들을 통째로 기억한 뒤, 유사도 측정(similarity measure)으로 새 사례에 일반화The system learns the examples by heart, then generalizes to new cases using a similarity measure.예시들로 모델을 만든 뒤, 그 모델로 예측build a model of examples, then use that model to make predictions
대표 알고리즘k-nearest neighbors 등Linear regression 등

그림의 두 방식을 단계별로 따라가 보겠습니다.

사례 기반 학습 (왼쪽)

  1. 훈련 데이터(△, □)를 전부 저장합니다. 이것이 "통째로 기억한다(learns by heart)"입니다.
  2. 새 사례(✖)가 들어오면 저장된 데이터와의 거리(유사도)를 잽니다.
  3. 가장 가까운 3개를 봅니다: △ 2개, □ 1개.
  4. 더 많은 쪽인 △로 판단합니다.

모델 기반 학습 (오른쪽)

  1. 훈련 데이터로 △ 영역과 □ 영역을 나누는 경계(모델, 보라 점선)를 만듭니다.
  2. 새 사례가 들어오면 경계의 어느 쪽에 있는지만 확인합니다.
  3. △ 쪽 안에 있으므로 △로 판단합니다.

차이를 정리하면, 사례 기반은 학습 단계에서 하는 일이 거의 없고 예측할 때마다 저장된 데이터 전체와 비교하므로 예측이 느립니다. 모델 기반은 학습 단계에서 경계를 만드는 데 시간이 들지만, 한 번 만들고 나면 훈련 데이터 없이 모델만으로 빠르게 예측할 수 있습니다.

k-NN 보충 — 교수님이 설명하신 내용 아님

k-최근접 이웃(k-nearest neighbors)은 새 샘플과 가장 가까운 훈련 샘플 k개를 찾아 다수결로 클래스를 정합니다. 교안 그림은 k=3에 해당합니다. 거리는 보통 유클리드 거리로 잽니다.

정리
  • 사례 기반: 예시를 통째로 기억 → 유사도로 가장 가까운 사례와 비교 (예: k-NN)
  • 모델 기반: 예시로 모델(경계)을 만들고 → 모델로 예측 (예: 선형 회귀)

02머신러닝의 주요 과제

Main Challenges of Machine Learning

머신러닝으로 좋은 모델을 만들지 못하는 원인은 크게 두 가지입니다. 데이터가 나쁘거나, 모델이 데이터에 맞지 않거나입니다. 아래 표가 데이터 쪽 문제이고, 뒤의 과적합·과소적합이 모델 쪽 문제입니다.

데이터 문제

English한국어세부

샘플링 잡음은 표본이 너무 작아 우연히 대표성이 없어지는 것, 샘플링 편향은 표본을 뽑는 방법 자체가 한쪽으로 치우쳐 표본이 커도 대표성이 없는 것을 말합니다.

표의 네 가지를 풀어 보면 다음과 같습니다.

  1. 양 부족: 사람은 사과 몇 개만 봐도 사과를 알아보지만, 대부분의 머신러닝 알고리즘은 간단한 문제에도 수천 개, 이미지·음성 같은 복잡한 문제에는 수백만 개의 예시가 필요합니다.
  2. 대표성 없음: 훈련 데이터가 실제로 예측할 데이터를 골고루 대표하지 못하면, 새 데이터에서 틀립니다. 원인은 두 가지입니다. 샘플링 잡음은 표본이 너무 작아서 우연히 치우친 경우이고, 샘플링 편향은 표본을 뽑는 방법 자체가 치우쳐서 표본이 아무리 커도 치우친 경우입니다. 예: 스마트폰 앱으로만 설문을 받으면 스마트폰을 쓰지 않는 사람의 의견은 몇 명을 모아도 빠집니다 → 샘플링 편향.
  3. 낮은 품질: 측정 오류나 이상치, 잡음이 많으면 모델이 진짜 패턴을 찾기 어렵습니다. 그래서 실제 작업에서는 이상치를 제거하거나 빠진 값을 채우는 데이터 정제에 많은 시간을 씁니다.
  4. 관련 없는 특성: 예측과 상관없는 특성이 많으면 성능이 떨어집니다. 쓸모 있는 특성만 고르거나(특성 선택), 기존 특성을 합쳐 더 쓸모 있는 특성을 만듭니다(특성 추출). 예: "키"와 "몸무게"를 합쳐 "BMI"라는 특성을 만드는 것이 특성 추출입니다.

과적합 Overfitting

모델이 훈련 데이터의 양과 잡음에 비해 너무 복잡할 때 일어납니다.

Overfitting happens when the model is too complex relative to the amount and noise of the training data.

과적합은 모델이 데이터에 담긴 일반적인 규칙이 아니라 훈련 데이터 자체(잡음까지 포함)를 외워 버린 상태입니다. 그래서 훈련 데이터에서는 성적이 아주 좋은데 새 데이터에서는 크게 틀립니다. 예: 훈련 데이터 10개를 하나도 빠짐없이 지나가는 복잡한 곡선을 그리면 훈련 오차는 0이 됩니다. 하지만 그 곡선은 데이터에 섞인 잡음까지 따라가느라 심하게 구불구불해서, 그 사이에 새 점이 들어오면 엉뚱한 값을 냅니다.

원인이 "데이터에 비해 모델이 너무 복잡하다"이므로, 해결책은 모델을 단순하게 하거나 데이터를 늘리고 깨끗하게 하는 쪽입니다.

해결책 (The possible solutions are):

  • 모델 단순화 — 파라미터 수가 더 적은 모델 선택, 훈련 데이터의 속성 수 줄이기, 모델에 제약 걸기(regularization, 규제) To simplify the model by selecting one with fewer parameters, by reducing the number of attributes in the training data, or by constraining the model (regularization).
  • 규제(regularization)는 모델의 파라미터 값이 너무 커지지 못하게 제한해서, 모델이 복잡한 모양을 만들기 어렵게 하는 방법입니다.
  • 훈련 데이터 더 모으기 (To gather more training data)
  • 훈련 데이터의 잡음 줄이기 (To reduce the noise in the training data)

과소적합 Underfitting

과적합의 반대로, 모델이 너무 단순해서 데이터의 내재된 구조를 학습하지 못할 때 일어납니다.

Underfitting is the opposite of overfitting: it occurs when your model is too simple to learn the underlying structure of the data.

과소적합은 모델이 데이터의 규칙을 담기에 표현력이 부족한 상태입니다. 그래서 새 데이터는 물론 훈련 데이터에서도 성적이 나쁩니다. 예: 곡선 모양으로 분포한 데이터를 직선 하나로 맞추려 하면, 아무리 학습해도 오차가 줄지 않습니다. 해결책은 과적합과 정반대 방향입니다.

해결책 (The main options to fix this problem are):

  • 파라미터가 더 많은 강력한 모델 선택 (Selecting a more powerful model, with more parameters)
  • 더 좋은 특성을 제공 = 특성 공학 (Feeding better features to the learning algorithm — feature engineering)
  • 모델의 제약 줄이기 (Reducing the constraints on the model)
과적합 (Overfitting)과소적합 (Underfitting)
원인모델이 너무 복잡모델이 너무 단순
모델파라미터 줄이기 · 규제 걸기파라미터 늘리기 · 제약 줄이기
데이터데이터 더 모으기 · 잡음 줄이기더 좋은 특성 제공(feature engineering)

그래프 읽기: 가로축은 학습 시간, 세로축은 손실(오차)입니다. 학습이 진행될수록 훈련 손실(검정)은 계속 줄어듭니다. 테스트 손실(빨강)은 처음엔 같이 줄다가, 어느 지점부터 다시 올라갑니다.

  • 최저점 왼쪽(파란 배경): 두 손실이 모두 큰 구간 = 아직 덜 배운 과소적합
  • 최저점 오른쪽(노란 배경): 훈련 손실은 계속 줄지만 테스트 손실은 커지는 구간 = 훈련 데이터에만 맞춰지는 과적합

따라서 "훈련 손실이 작다"는 것만으로는 좋은 모델이라고 할 수 없고, 반드시 학습에 쓰지 않은 데이터에서 손실을 확인해야 합니다. 그 방법이 다음 섹션의 테스트와 검증입니다.

손실 보충 — 교수님이 설명하신 내용 아님

손실(loss)은 모델 예측과 정답의 차이를 수치로 나타낸 값으로, 작을수록 좋습니다. 테스트 손실이 최저인 지점이 새 데이터에 가장 잘 일반화된 시점입니다.

정리
  • 데이터 문제 4가지: 양 부족 · 대표성 없음(잡음/편향) · 낮은 품질 · 관련 없는 특성
  • 과적합: 모델이 너무 복잡 → 훈련 데이터만 잘 맞춤 → 단순화 · 규제 · 데이터 늘리기 · 잡음 줄이기
  • 과소적합: 모델이 너무 단순 → 훈련 데이터도 못 맞춤 → 더 강력한 모델 · 좋은 특성 · 제약 줄이기

03테스트와 검증

Testing and Validation

모델이 새로운 사례에 얼마나 잘 일반화(generalize)될지 아는 방법은 실제로 새로운 사례에 적용해 보는 것입니다.

How well a model will generalize to new cases is to actually try it out on new cases.
  • 데이터셋을 훈련 세트(training set)와 테스트 세트(test set) 두 개로 나눈다 Split a dataset into two sets: the training set and the test set
  • 보통 데이터의 80%를 훈련에, 20%를 테스트용으로 떼어 둔다(holdout) Common to use 80% of the data for training and holdout 20% for testing.

왜 나눠야 할까요? 훈련에 쓴 데이터로 성능을 재면, 앞에서 본 과적합 모델도 점수가 높게 나옵니다. 모델이 이미 본 데이터이기 때문입니다. 그래서 학습에 한 번도 쓰지 않은 테스트 세트를 따로 떼어 두고, 거기서 잰 성능을 새 데이터에서의 실제 성능으로 봅니다. 테스트 세트에서 잰 오차를 일반화 오차(generalization error)라고 부릅니다.

그림 읽기: 레이블이 있는 원본 데이터를 셋으로 나눕니다(Split). 훈련 세트로 모델을 학습하고, 검증 세트로 여러 후보 모델 중 가장 나은 것을 고르고, 테스트 세트로 마지막에 성능을 확인합니다.

검증 세트의 역할 — 교수님이 설명하신 내용 아님

검증 세트는 여러 모델이나 하이퍼파라미터 중 무엇이 나은지 고르는 데 씁니다. 테스트 세트로 고르면 테스트 세트에 맞춰진 모델을 고르게 되어, 최종 성능을 부풀려 추정하게 됩니다. 그래서 테스트 세트는 마지막 평가에 한 번만 씁니다.

교차 검증 Cross Validation

훈련 세트를 서로 겹치지 않는 여러 부분집합(complementary subsets)으로 나눈 뒤, 각 모델을 서로 다른 부분집합 조합으로 학습시키고 나머지 부분으로 검증합니다.

The training set is split into complementary subsets, and each model is trained against a different combination of these subsets and validated against the remaining parts.

그림을 순서대로 따라가면 5-겹(5-fold) 교차 검증은 다음과 같이 진행됩니다.

  1. 전체 데이터에서 테스트 데이터를 먼저 떼어 둡니다(오른쪽 파란 칸). 이것은 끝까지 쓰지 않습니다.
  2. 나머지 훈련 데이터를 5조각(Fold 1~5)으로 나눕니다.
  3. Split 1: Fold 1을 검증용(파랑), 나머지 4개를 학습용(초록)으로 써서 학습하고 검증 점수를 잽니다.
  4. Split 2~5: 검증용 조각을 Fold 2, 3, 4, 5로 하나씩 바꿔 가며 같은 일을 반복합니다.
  5. 5번의 검증 결과를 종합해 가장 좋은 파라미터를 고릅니다(Finding Parameters).
  6. 떼어 둔 테스트 데이터로 최종 평가합니다(Final evaluation).

장점: 모든 데이터가 한 번씩 검증에 쓰이므로 검증 세트를 따로 크게 떼지 않아도 되고, 한 번 나눈 결과가 운 좋게(또는 나쁘게) 나오는 영향이 줄어듭니다. 단점: 학습을 5번 해야 하므로 시간이 그만큼 더 듭니다.

정리
  • 일반화 성능은 학습에 안 쓴 데이터로만 잴 수 있음 → 훈련/테스트 분리 (보통 80:20)
  • 검증 세트: 모델·파라미터 고르기 / 테스트 세트: 마지막 평가 1번
  • 교차 검증: 훈련 세트를 k조각으로 나눠 검증 조각을 바꿔 가며 k번 학습·검증
필기 원문
(교안 p.29–30 기반 — 실시간 필기 없음)

04공짜 점심은 없다 정리 No Free Lunch Theorem

David Wolpert (1996)

데이터에 대해 아무런 가정도 하지 않는다면, 어떤 모델을 다른 모델보다 선호할 이유가 없다.

If you make absolutely no assumption about the data, then there is no reason to prefer one model over any other.
  • 경험하기 전부터(a priori) 더 잘 작동한다고 보장된 모델은 없다 There is no model that is a priori guaranteed to work better.
  • 어떤 모델이 최선인지 확실히 아는 유일한 방법은 모두 평가해 보는 것이다 The only way to know for sure which model is best is to evaluate them all.

이 정리가 말하는 것은 모든 문제에서 항상 이기는 알고리즘은 없다는 것입니다. 어떤 데이터에는 선형 모델이 잘 맞고, 어떤 데이터에는 신경망이 잘 맞습니다. 데이터를 보기 전에는 무엇이 더 좋을지 알 수 없습니다.

그렇다고 세상의 모든 모델을 다 평가할 수는 없습니다. 그래서 실제로는 데이터에 대해 합리적인 가정을 하고(예: "이 데이터는 대략 직선 관계다"), 그 가정에 맞는 몇 개 모델만 골라 평가합니다. 그 평가 도구가 바로 앞 섹션의 검증 세트와 교차 검증입니다.

정리
  • 데이터에 대해 가정하지 않으면 어떤 모델도 다른 모델보다 낫다고 할 수 없음
  • 미리 더 좋다고 보장된 모델은 없음 → 평가해 봐야 앎
필기 원문
(교안 p.31 기반 — 실시간 필기 없음)
