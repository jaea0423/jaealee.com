01논리란 · 규칙기반 AI에서의 논리

6장은 사람이 규칙을 직접 적어 넣는 인공지능을 다룹니다. 이런 인공지능이 판단한다는 것은 결국 "주어진 사실과 규칙에서 결론을 끌어내는 것"이고, 결론을 올바르게 끌어내는 법칙을 정리한 학문이 논리입니다. 그래서 6장은 논리 → 추론 → 탐색 → 전문가 시스템 순서로 진행합니다.

(1) 규칙기반 인공지능에서의 논리와 추론

  • 규칙기반 인공지능(rule-based AI)은 논리 바탕의 규칙을 통해 추론(inference)한다
  • 논리는 다양한 논리 연산(logical operation)으로 폭넓게 활용된다
  • 탐색 방법(search), 문제 해결 알고리즘, 지식처리(knowledge processing) 등에 필요하다
  • 전문가 시스템(expert system) 등의 응용에 필수적인 기반 지식이다

(2) 논리란 무엇인가?

  • 인간의 사고가 논리적인지를 판단하는 기준 — 객관적이고 명확한 사고 법칙을 지키는지로 결정된다
  • 토론·논쟁에서 중요한 것은 주장의 논리성, 상대를 논리적으로 설득하는 것이 중요하다
  • 논리를 통한 입증에 필요한 법칙을 제공한다

그림 6.1 논리적 판단의 필요성 — "달걀이 먼저야!" / "닭이 먼저라니까!" / "오호! 논리적으로 따져보자."

논리의 활용

  • 규칙기반 인공지능에 이론적 기반을 제공한다
  • AI 학자들이 논리를 규칙기반 인공지능 실현에 적용했다
  • AI에서 지식 표현(knowledge representation)이나 추론(inference)의 도구로 쓰인다
규칙교안 그림 — if-then 규칙의 형태
if APPROVED then INSTALL
if QA       then CONFIG
if OK       then START

교안 그림의 세 줄은 규칙기반 AI가 지식을 담는 기본 형태입니다. "승인되면(APPROVED) 설치하고(INSTALL), 품질 검사(QA)를 거치면 설정하고(CONFIG), 이상이 없으면(OK) 시작한다(START)"처럼 조건과 행동을 짝지은 규칙을 여러 개 모아 두고, 현재 상황이 조건에 맞는 규칙을 찾아 실행합니다. 이 if–then 형태가 다음 섹션에서 배울 조건 명제 p → q입니다.

정리
  • 규칙기반 AI는 논리 바탕의 규칙으로 추론한다
  • 논리는 지식 표현과 추론의 도구 — 탐색, 지식처리, 전문가 시스템의 기반
  • 규칙의 기본 형태: if 조건 then 행동

02명제와 논리 연산

(3) 명제 논리와 술어 논리

논리의 가장 작은 단위는 명제입니다. 명제 여러 개를 연산자로 묶어 더 복잡한 문장(합성 명제)을 만들고, 그 참/거짓을 기계적으로 계산하는 것이 명제 논리입니다. 컴퓨터가 논리를 다룰 수 있는 이유가 이 "기계적으로 계산할 수 있다"는 점입니다.

구분다루는 것
명제 논리(propositional logic)문장 전체의 참/거짓을 판별하는 법칙
술어 논리(predicate logic)문장을 주어와 술어로 구분해 참/거짓을 따지는 법칙 → 03

명제 (proposition)

  • 논리에서 가장 기초적인 개념 — 참(T)/거짓(F)을 명확하게 구분할 수 있는 문장이나 식
  • "2 × 7의 값은 홀수다." → 거짓인 명제 (거짓이어도 T/F가 정해지므로 명제)
  • "사과는 맛있다." → 참/거짓을 구분할 수 없으므로 명제가 아님
  • 합성 명제(compound proposition) — 둘 이상의 명제가 결합된 명제

명제인지 판단하는 기준은 누가 판단해도 참/거짓이 하나로 정해지는가입니다. "2 × 7의 값은 홀수다"는 틀린 말이지만 누구나 거짓이라고 판단하므로 명제입니다. "사과는 맛있다"는 사람마다 판단이 다르므로 명제가 아닙니다. 즉 참인지 여부가 아니라, 참/거짓이 정해지는지 여부가 기준입니다.

진리표 읽는 법: p와 q는 각각 T/F 두 가지 값을 가지므로 조합은 4줄입니다. 각 줄에서 연산 결과를 적습니다. 외울 것은 위 표 "핵심 규칙" 열의 예외 한 줄(표에서 형광 표시한 칸)뿐이고, 나머지 줄은 모두 그 반대입니다.

  • 논리합(∨): 둘 중 하나만 T여도 T → 둘 다 F인 줄만 F
  • 논리곱(∧): 둘 다 T여야 T → 둘 다 T인 줄만 T
  • 조건(→): p가 T, q가 F인 줄만 F

교수님 말씀 — 교안 표 6.4 오류

교안의 조건 진리표 머리글이 ~p → q로 인쇄되어 있는데, 오류이고 p → q가 맞다고 하셨습니다. 위 표는 p → q로 고쳐 두었습니다.

헷갈리는 지점 — 조건 명제

조건 명제에서는 가정(p)이 F이면 결론(q)과 관계없이 항상 T입니다. 그래서 "3 × 2 = 5라면, 런던은 미국의 수도이다"는 둘 다 틀린 말인데도 T입니다. → 기호는 AI에서 if p, then q 형태로 많이 쓰입니다.

조건 명제가 왜 이렇게 정해졌는지 보겠습니다. p → q는 "p가 참인 경우에는 q도 참이다"라는 주장입니다. 이 주장이 틀렸다고 확인되는 경우는 p가 참인데 q가 거짓인 경우 하나뿐입니다. p가 거짓인 경우는 이 주장이 말하는 상황이 아니므로 틀렸다고 할 수 없고, 그래서 T로 둡니다.

이산수학과 연결

1학기 이산수학의 명제 논리와 같은 내용입니다. 이산수학에서는 ¬p, p ∨ q, p ∧ q, p → q로 표기하고, 조건문의 가정을 전건(hypothesis), 결론을 후건(conclusion)이라 부릅니다. 교재는 부정을 ~p로 적습니다.

정리
  • 명제 = 참/거짓이 하나로 정해지는 문장 (거짓이어도 명제)
  • 부정 ~p: 뒤집기 · 논리합 ∨: 둘 다 F일 때만 F · 논리곱 ∧: 둘 다 T일 때만 T
  • 조건 p → q: p = T, q = F일 때만 F (교안 표 6.4 머리글은 p → q가 맞음)

03술어 논리 Predicate Logic

먼저 명제 논리의 한계를 보겠습니다. 명제 논리에서 "영철이는 남자다"와 "민수는 남자다"는 서로 다른 명제 p, q일 뿐입니다. 두 문장이 모두 "남자"라는 같은 성질을 말한다는 공통점을 표현할 방법이 없습니다. 술어 논리는 문장을 대상(주어)과 술어(성질이나 관계)로 쪼개서 이 문제를 해결합니다.

  • 변수의 값에 따라 T 또는 F가 결정된다 — 예: x² + 5x + 6 = 0 은 x가 −2나 −3일 때만 T
  • 지식을 논리적 식으로 표현하며, 대상들 간의 관계도 나타낼 수 있다
문장술어 논리 표현
"영철이는 남자다."남자(영철)
"영철의 아버지는 김춘추 씨다."아버지(김춘추, 영철) — 두 대상 사이의 관계

읽는 법: 괄호 밖이 술어, 괄호 안이 대상입니다.

  • 남자(영철): "영철"이 "남자"라는 성질을 가진다
  • 아버지(김춘추, 영철): "김춘추"와 "영철" 사이에 "아버지" 관계가 있다 — 대상이 두 개인 술어로 관계를 표현
  • 남자(x): x에 누가 들어가느냐에 따라 T/F가 달라지므로 그 자체로는 명제가 아닙니다. 위 x² + 5x + 6 = 0도 같은 경우입니다.

이렇게 쪼개 두면 "모든 사람은 죽는다"를 "x가 사람이면 x는 죽는다"라는 규칙 하나로 적고, 여러 사람에게 적용할 수 있습니다. 08 섹션의 소크라테스 예제가 바로 이 형태입니다.

이산수학과 연결

이산수학의 술어(predicate) P(x)와 같은 개념입니다. 명제 논리는 "영철이는 남자다" 전체를 p 하나로 보지만, 술어 논리는 남자(x)라는 틀에 대상을 넣어 표현하므로 같은 규칙을 여러 대상에 적용할 수 있습니다.

정리
  • 술어 논리 = 문장을 대상과 술어로 나눠 참/거짓을 따짐
  • 변수 값에 따라 T/F가 달라짐 · 대상들 사이의 관계도 표현 가능
  • 예: 남자(영철), 아버지(김춘추, 영철)

04추론의 의미와 종류

(5) 추론의 의미와 인공지능

  • 추론(inference / reasoning)이란 "알려진 사실이나 명제를 근거로 삼아 미지의 사실에 대한 판단이나 결론을 이끌어내는 사고 과정"

  • Prolog(프롤로그)는 추론에 주로 쓰이는 프로그래밍 언어

(6) 추론의 종류

종류방식특징교안 예시
① 귀납 추론(induction)개별적인 사실들로부터 일반적인 결론을 이끌어냄연역 추론 같은 논리적 필연성이 적음. 새로운 지식·이론의 발견과 확장에 쓰임까마귀 1, 2, 3, …, n이 까맣다 → "모든 까마귀는 까맣다"
② 연역 추론(deduction)전제로부터 다른 결론을 도출가장 널리 쓰임. 최초의 대전제가 가장 중요한 근거. 확장성은 부족하나 논리의 일관성이 장점삼단논법 — 소크라테스는 죽는다
③ 유비 추론(analogy) = 유추두 대상에서 어떤 현상이 유사·일치하므로 다른 현상도 유사·일치할 것이라 추론기존에 모르던 새로운 영역 이해에 도움양말 : 발 = 장갑 : 손(Socks is to foot as gloves is to hand)

세 가지를 구분하는 기준은 결론이 반드시 참인가와 새 지식을 만드는가입니다.

  • 연역: 전제가 참이면 결론도 반드시 참입니다. 대신 결론은 이미 전제 안에 들어 있던 내용을 꺼낸 것이라 지식의 범위가 넓어지지는 않습니다(확장성 부족). 규칙기반 AI가 주로 쓰는 방식입니다.
  • 귀납: 까마귀를 n마리 관찰했다고 해서 n+1번째 까마귀도 까맣다는 보장은 없으므로 결론이 틀릴 수 있습니다(필연성 적음). 대신 관찰하지 않은 경우까지 말해 주므로 새 지식을 만듭니다(발견과 확장). 머신러닝이 이 방식입니다.
  • 유비: 이미 아는 관계(양말 : 발)를 새 대상(장갑 : ?)에 그대로 옮겨 적용합니다.

교안연역 추론의 예

소전제 - 사람은 모두 죽는다.

05인공지능에서의 탐색 기법

(1) 추론을 통한 탐색

규칙기반 AI가 문제를 푼다는 것은, 가능한 상태들 가운데에서 출발 상태에서 목표 상태까지 가는 길을 찾는 것입니다. 이것을 탐색(search)이라고 합니다. 이 섹션은 어느 방향으로(순방향/역방향), 어떤 순서로(DFS/BFS), 무엇을 참고해서(휴리스틱) 찾는지를 다룹니다.

방향진행
순방향 추론(forward reasoning / forward chaining)출발 상태 → 목표 상태
역방향 추론(backward reasoning / backward chaining)목표 상태 → 출발 상태
양방향 추론(bidirectional)순방향과 역방향을 접합

순방향은 가진 사실에서 출발해 규칙을 적용하며 결론을 늘려 가고, 역방향은 증명하고 싶은 목표에서 출발해 "이것이 참이려면 무엇이 참이어야 하나"를 거슬러 확인합니다. 08 섹션의 "Is Socrates die?" 질의는 목표(소크라테스는 죽는다)에서 출발해 필요한 사실(소크라테스는 사람이다)을 찾는 역방향 방식으로 볼 수 있습니다. Prolog가 이 방식으로 동작합니다.

(2)·(3) 깊이 우선 탐색 vs 너비 우선 탐색

깊이 우선 탐색 (Depth-First Search, DFS)너비 우선 탐색 (Breadth-First Search, BFS)
방법첫 정점(node) 방문 후 왼쪽으로 이동하며 계속 탐색, 더 갈 정점이 없으면 되돌아와서 순환적으로 탐색시작 정점 방문 후 연결된 모든 정점을 왼쪽부터 차례대로 방문, 이후 level 순서(level 0 → 1 → 2 …)로 탐색
위 트리 순서1 → 2 → 3 → 4 → 5 → 61 → 2 → 3 → 4 → 5 → 6

그림의 번호는 방문 순서입니다. 두 트리는 모양이 같지만 방문 순서가 달라서 번호가 다르게 붙어 있습니다.

  • DFS: 1 → 왼쪽 자식 2 → 그 왼쪽 자식 3 (더 내려갈 곳 없음, 2로 되돌아감) → 2의 다음 자식 4 (되돌아감) → 1로 돌아가 오른쪽 자식 5 → 6
  • BFS: level 0의 1 → level 1의 2, 3 → level 2의 4, 5, 6

DFS는 한 갈래만 따라가므로 메모리를 적게 쓰지만, 찾은 경로가 가장 짧다는 보장이 없습니다. BFS는 가까운 level부터 보므로 목표까지 단계 수가 가장 적은 경로를 찾지만, 한 level의 정점을 모두 저장해야 해서 메모리를 많이 씁니다.

자료구조와 연결

1학기 자료구조의 그래프 순회와 같은 내용입니다. DFS는 스택(stack, 또는 재귀)으로, BFS는 큐(queue)로 구현합니다. 되돌아오는 동작이 스택의 pop, level 순서 방문이 큐의 선입선출(FIFO)에 해당합니다.

(4) 휴리스틱 탐색 heuristic search

구분의미예
무정보 탐색(uninformed search)사전 정보를 쓰지 않고 일정한 순서대로만 탐색깊이 우선 탐색, 너비 우선 탐색
휴리스틱 탐색(heuristic search)탐색 과정에서 경험적 지식을 활용아래 목록

무정보 탐색은 목표가 어느 쪽에 있는지 전혀 모르고 정해진 순서대로 하나씩 확인합니다. 휴리스틱 탐색은 목표에 더 가까워 보이는 쪽을 먼저 확인합니다. 예: 길 찾기에서 목적지까지 직선거리가 짧은 교차로부터 먼저 가 보는 것. 탐색할 상태가 너무 많아 전부 볼 수 없을 때 필요합니다.

교안 그림의 휴리스틱 탐색 기법(Heuristic Search Techniques) 목록:

  • General-purpose heuristics 범용 휴리스틱
  • Best-first search 최상 우선 탐색
  • Branch and bound search (uniform cost search) 분기 한정 탐색 (균일 비용 탐색)
  • A* algorithm → 07
  • Hill climbing 언덕 오르기
  • Beam search 빔 탐색

(5) 최소최대 탐색 minimax search

  • 주로 상대가 있는 2인용 게임에서의 탐색 — 예: 틱텍토(Tic-Tac-Toe), 가로·세로·대각선으로 3개가 연속되면 이김
  • 나의 가능성은 최대, 상대방의 가능성은 최소로 하는 전략을 탐색
  • 탐색이 필요 없는 경로를 잘라내는 작업 = 전지 작업(pruning, 가지치기)

틱택토로 보면, 내 차례에는 둘 수 있는 수 중 나에게 가장 좋은(최대) 수를, 상대 차례에는 상대가 나에게 가장 나쁜(최소) 수를 둔다고 가정하고 몇 수 앞까지 계산합니다. 상대도 최선을 다한다고 가정하는 것이 핵심입니다.

용어 보충 — 교수님이 설명하신 내용 아님

최소최대 탐색에서 쓰는 대표적인 가지치기 방법을 알파-베타 가지치기(alpha-beta pruning)라고 부릅니다. 결과는 바꾸지 않고, 결과에 영향이 없는 가지를 탐색하지 않아 속도를 높입니다.

정리
  • 순방향: 출발 → 목표 · 역방향: 목표 → 출발 · 양방향: 둘을 접합
  • DFS: 한 갈래 끝까지 → 되돌아옴 (스택) · BFS: level 순서 (큐) — 둘 다 무정보 탐색
  • 휴리스틱 탐색: 경험적 지식 활용 (최상 우선, A*, 언덕 오르기 등)
  • 최소최대: 2인 게임에서 나는 최대, 상대는 최소 · 가지치기로 불필요한 경로 제거

06알고리즘과 휴리스틱

(1) 알고리즘이란?

  • 알고리즘(algorithm) — 문제 해결을 위한 단계들을 체계적으로 명시한 것, 문제를 해결하는 방법의 상세한 특징을 기술한 것
  • AI에서 자주 나오는 용어 — 예: 신경망의 역전파 알고리즘(backpropagation)
  • 표현 방법: 순서도(flowchart), 유사 코드(pseudocode), 언어적 표현 등
  • 알고리즘은 단 하나만 있는 것이 아니다

"알고리즘이 단 하나만 있는 것이 아니다"는 같은 문제를 푸는 방법이 여러 개라는 뜻입니다. 알고리즘 과목에서 같은 정렬 문제를 버블 정렬, 퀵 정렬 등 여러 방법으로 풀고 속도를 비교하는 것이 그 예입니다.

(2) 생활 속의 알고리즘

  1. 기초적인 수학 연산 — 덧셈·곱셈 방법, 최대공약수 구하기
  2. 라면 조리법 — 물의 양, 불의 세기, 끓이는 시간 (물 붓기 → 끓이기 → 면·스프 넣기 → 완성)
  3. 하루의 일정 계획 — 기상 시간, 식사 시간, 버스·지하철 이용
  4. 가전제품 사용 매뉴얼 — 세탁기·전자레인지의 단계별 사용 설명서
  5. 지하철 환승 방법 — 어느 역에서 환승하는 것이 효율적인지 판단
  6. 알파고 같은 인공지능 방법론 — 바둑·게임 등 복잡한 것의 해결 방법

(3) 휴리스틱을 이용한 알고리즘

  • 휴리스틱(heuristic) — 비슷한 문제에 대한 과거의 경험을 바탕으로 직관적으로 판단해 선택하는 의사결정 방식
  • 논리적이거나 최적의 방법을 보장하지는 않지만, 만족할 만한 해결책을 비교적 빠르게 찾는 실용적인 방법
  • AI, 심리학, 경제학 분야에서 많이 사용

알고리즘과 휴리스틱의 차이를 정리하면 이렇습니다.

알고리즘휴리스틱
근거체계적으로 명시된 단계과거 경험에 바탕을 둔 직관적 판단
결과단계를 따르면 정해진 답이 나옴최적을 보장하지 않음, 대신 만족할 만한 답
속도문제가 크면 느릴 수 있음비교적 빠름

그래서 탐색할 상태가 너무 많아 모두 확인할 수 없을 때, 알고리즘 안에 휴리스틱을 넣어 확인할 순서를 정합니다. 05 섹션의 휴리스틱 탐색과 다음 섹션의 A*가 이런 방식입니다.

휴리스틱의 예 — 폴리아(G. Polya), 《How to Solve It》
  • 문제를 이해하기 어려우면 그림으로 그려보기
  • 해답을 얻었다고 가정하고 반대 방향으로 유도해보기
  • 문제가 추상적이면 구체적인 예를 시도해보기
정리
  • 알고리즘 = 문제 해결 단계를 체계적으로 명시한 것 (순서도, 유사 코드 등으로 표현, 여러 개 가능)
  • 휴리스틱 = 과거 경험 바탕의 직관적 의사결정 — 최적 보장 X, 빠르고 실용적

07A* 알고리즘 · 8-Queens 문제

(4) A* 알고리즘

  • 최상 우선 탐색(best-first search) 중 가장 잘 알려진 방법, 문제 해결에 매우 효과적인 탐색 알고리즘
  • 출발점에서 목표지점까지 최적 경로를 찾는 방법 — 가장 비용이 적거나 짧은 경로
  • 평가 함수 f(evaluation function)를 사용해 다음에 이동할 경로를 결정

그림 읽기: S(출발)에서 G(목표)로 가야 하는데 가운데 회색 장애물이 막고 있습니다. A*는 갈 수 있는 칸마다 평가 함수 f 값을 계산해 가장 유망한 칸부터 넓혀 가고, 그 결과 장애물을 돌아가는 가장 짧은 경로(굵은 선)를 찾습니다.

평가 함수 보충 — 교수님이 설명하신 내용 아님

A*의 평가 함수는 보통 f(n) = g(n) + h(n)으로 씁니다. g(n)은 출발점에서 현재 칸 n까지 실제로 든 비용, h(n)은 n에서 목표까지 남은 비용의 휴리스틱 추정값입니다. f가 가장 작은 칸을 먼저 넓혀 갑니다.

g만 쓰면 모든 방향으로 똑같이 넓혀 가서 느리고(균일 비용 탐색), h만 쓰면 목표 쪽으로만 가다가 장애물 때문에 더 긴 경로를 고를 수 있습니다. 둘을 더하면 "지금까지 온 거리"와 "남은 거리 추정"을 함께 고려하므로, h가 실제 남은 거리보다 크게 추정하지 않는 한 최단 경로를 찾습니다.

(5) 8-Queens 문제

  • 체스에서 유래 — 서로를 공격하지 않는 위치에 8개의 퀸(Q)을 배치하는 문제 — 어떤 퀸도 서로 공격당하지 않는 위치에 놓여야 함
  • 퀸은 수평, 수직, 대각선 방향으로 몇 칸이든 이동할 수 있다
  • 64칸에 퀸 8개를 놓는 경우의 수는 약 44억 가지 — 보통 AI 방법으로 프로그램해 해답을 구하며, 해답은 여러 개

퀸이 가로·세로·대각선으로 공격하므로 조건을 정리하면 같은 행, 같은 열, 같은 대각선에 퀸이 두 개 이상 있으면 안 됩니다. 그래서 8개의 퀸은 8개 행에 하나씩, 8개 열에 하나씩 들어갑니다. 그림 6.12의 해답을 "행별 열 위치"로 적으면 2, 8, 6, 1, 3, 5, 7, 4처럼 1~8이 한 번씩만 나오는 것도 이 때문입니다.

경우의 수 보충 — 교수님이 설명하신 내용 아님

"약 44억"은 64칸 중 8칸을 고르는 조합 ₆₄C₈ = 4,426,165,368에서 나온 값입니다.

44억 가지를 모두 검사하는 대신, 한 행씩 퀸을 놓으면서 이미 공격받는 칸은 처음부터 제외하면 검사할 경우가 크게 줄어듭니다. 교안의 "보통 AI 방법으로 프로그램해 해답을 구한다"는 이렇게 탐색 범위를 줄여 푼다는 뜻으로 읽을 수 있습니다.

08규칙기반 전문가 시스템

(1) 지식처리 기술과 지식 획득

  • 규칙(rule)은 "If ooo then xxx" 형식으로 표현
  • 지식처리 기술은 규칙이나 프레임(frame)에 의한 표현
  • 의미 네트워크(semantic network) — 개념 사이의 관계를 링크(link)로 연결, 지식을 체계화해 표현하기에 적합

의미 네트워크는 개념을 정점(node)으로, 개념 사이의 관계를 링크로 그린 그래프입니다. "세퍼드 → 개" 링크가 있으면, "개"에 대해 저장된 성질을 세퍼드에 대해 따로 적지 않아도 세퍼드가 그 성질을 가진다고 추론할 수 있습니다.

(2) 규칙기반 시스템의 작동 예

규칙기반 시스템은 사실(fact)을 담은 지식베이스(knowledge base)와 If–then 형태의 추론규칙(inference rules)으로 이루어진다. 질의(query)가 오면 둘을 이용해 추론한 뒤 결과를 알려준다.

교안 그림 — 추론 규칙 표 Table of Rules of Inference

Rule of InferenceName읽는 법
P ∴ P ∨ QAddition (가산)P가 참이면 P ∨ Q도 참
P, Q ∴ P ∧ QConjunction (논리곱)P와 Q가 각각 참이면 P ∧ Q도 참

∴ 는 "따라서(therefore)". '읽는 법' 열은 기호를 풀어 쓴 것입니다.

각 규칙은 "쉼표로 나열한 전제가 모두 참이면, ∴ 뒤의 결론도 참"이라는 뜻입니다. 네 번째 가언적 삼단논법은 02 섹션의 조건 명제(→) 두 개를 이어 붙여 새 조건 명제를 만드는 규칙입니다.

규칙기반 시스템의 간단한 예 — 소크라테스의 죽음

그림 6.15지식베이스 · 추론규칙 · 질의
// 지식베이스 (사실)
Socrates is a human        // 소크라테스는 사람이다
Daesukim is a human        // 김대수는 사람이다
Wurry is an animal         // 워리(강아지 이름)는 동물이다

// 추론규칙
If X is a human,  then X dies   // 모든 사람은 죽는다
If X is an animal then X dies   // 모든 동물은 죽는다

// 질의와 답변
Q: Is Socrates die?   → A: Yes
Q: Tell me what dies? → A: Socrates, Daesukim, wurry
  • "Is Socrates die?" — 사실 Socrates is a human과 규칙 If X is a human, then X dies가 결합해 "소크라테스는 죽는다"를 이끌어냄
  • "Tell me what dies?" — 같은 방식으로 Socrates, Daesukim, wurry가 죽는다는 결론 도출
  • 규칙기반 시스템은 Prolog로 편리하게 프로그래밍할 수 있다

이 예제의 핵심은 "김대수는 죽는다", "워리는 죽는다"라는 사실이 지식베이스에 직접 적혀 있지 않다는 점입니다. 사실 3개와 규칙 2개만 저장해 두면, 추론으로 새로운 사실을 만들어 답합니다. 04 섹션 교재 만화의 "새로운 사실들을 생성해낼 수 있다"가 이것입니다. 또 규칙이 03 섹션의 술어 논리 형태(X is a human → X dies)라서, 규칙 하나가 지식베이스의 모든 사람에게 적용됩니다.

Prolog로 쓰면 — 교수님이 설명하신 내용 아님
Prologsocrates.pl
% 사실(fact): 지식베이스에 해당. 대상은 소문자로 시작해야 상수로 취급된다
human(socrates).
human(daesukim).
animal(wurry).

% 규칙(rule): ":-"는 "if". 대문자 X는 변수라 어떤 대상에도 적용된다
dies(X) :- human(X).    % X가 사람이면 X는 죽는다
dies(X) :- animal(X).   % X가 동물이면 X는 죽는다

% 질의(query) 예시
% ?- dies(socrates).   → true        (소크라테스는 죽는가?)
% ?- dies(X).          → X = socrates ; X = daesukim ; X = wurry

교안 예시를 Prolog 문법으로 옮긴 것입니다. 규칙 하나로 여러 사실에 대해 답을 만들어내는 구조가 그대로 드러납니다.

(3) 인간 전문가를 대신하는 전문가 시스템

  • 전문가 시스템(Expert System)은 컴퓨터 자문 시스템의 일종 — 특정 분야 인간 전문가의 전문 지식과 AI의 추론 능력을 이용한 문제 해결 시스템
  • 전문가의 지식을 정리해 지식베이스부터 구축 → 사용자가 질문하면 추론기구(inference engine)가 지식베이스로 추론 → 결과를 사용자에게 전달

그림을 따라가면:

  1. 전문가가 자신의 지식을 지식베이스에 입력합니다.
  2. 사용자가 질문합니다.
  3. 추론기구가 지식베이스의 사실과 규칙으로 추론합니다.
  4. 결과를 사용자에게 대답합니다.

지식베이스(무엇을 아는가)와 추론기구(어떻게 결론을 내는가)가 분리되어 있어서, 분야가 바뀌어도 추론기구는 그대로 두고 지식베이스만 바꾸면 됩니다.

09인공지능 vs 머신러닝 vs 딥러닝

Artificial Intelligence vs. Machine Learning vs. Deep Learning

뉴스나 광고에서는 AI, 머신러닝, 딥러닝을 거의 같은 뜻으로 섞어 쓰지만, 이 수업에서는 세 용어를 포함 관계로 구분합니다. 가장 넓은 개념이 인공지능이고, 그 안에 머신러닝이, 다시 그 안에 딥러닝이 들어갑니다. 안쪽 원으로 갈수록 "지능을 어떤 방법으로 만드는가"에 대한 조건이 하나씩 더 붙습니다.

영역정의
인공지능(Artificial Intelligence)사람이 하던 일을 기계가 수행하는 모든 자동화Any automation in which machines can perform tasks that humans would otherwise do
머신러닝(Machine Learning)규칙을 명시적으로 프로그래밍하지 않아도, 기계가 데이터에서 의사결정용 패턴을 학습Machines learn patterns for decision-making from data without being explicitly programmed with rules
딥러닝(Deep Learning)신경망 기반 모델로, 비정형 데이터에서 특징 추출과 의사결정을 한 번에(end to end) 수행Neural network-based models that can perform both feature extraction and decision-making end to end from unstructured data

세 단계를 가르는 질문

표의 정의를 나란히 놓으면, 한 단계 안쪽으로 들어갈 때마다 확인할 질문이 하나씩 생깁니다.

  1. 인공지능인가? 사람이 하던 판단을 기계가 대신하면 인공지능입니다. 방법은 따지지 않습니다. 6장에서 배운 전문가 시스템처럼 사람이 규칙을 직접 적어 넣은 프로그램도 인공지능입니다.
  2. 머신러닝인가? 판단 규칙을 사람이 적었는지, 기계가 데이터에서 찾았는지를 봅니다. 데이터에서 찾았다면 머신러닝입니다. 그래서 전문가 시스템은 인공지능이지만 머신러닝은 아닙니다.
  3. 딥러닝인가? 머신러닝 중에서 신경망(neural network)을 쓰고, 데이터의 어떤 부분을 봐야 하는지(특징, feature)까지 스스로 뽑아내면 딥러닝입니다.

예를 들어 사진 속 동물이 고양이인지 판단하는 프로그램을 생각해 보겠습니다. 딥러닝이 아닌 머신러닝에서는 사람이 "귀 모양", "털 색" 같은 특징을 먼저 정하고 숫자로 바꿔 넣어 주면, 기계는 그 숫자로 판단하는 규칙만 학습합니다. 딥러닝에서는 사진의 픽셀 값을 그대로 넣으면 신경망이 어떤 모양을 봐야 하는지부터 최종 판단까지 한 번에 학습합니다. 표의 "특징 추출과 의사결정을 end to end로 수행"이 이 뜻입니다.

교수님 말씀

생성형 AI(Generative AI)는 딥러닝 안에 들어가는 영역입니다. 즉 AI ⊃ 머신러닝 ⊃ 딥러닝 ⊃ 생성형 AI 순서로 포함됩니다. 교안 그림에는 없고 수업에서 덧붙이신 내용입니다.

생성형 AI 보충 — 교수님이 설명하신 내용 아님

생성형 AI는 학습한 데이터와 비슷한 새 데이터(텍스트·이미지·음성 등)를 만들어 내는 모델을 말합니다. 예: GPT 같은 대규모 언어 모델(Large Language Model, LLM), 이미지 생성용 확산 모델(diffusion model). 지금 쓰이는 생성형 AI는 대부분 딥러닝 신경망 기반이라 위 포함 관계가 성립합니다.

다만 통계학의 생성 모델(generative model)이라는 용어는 더 넓어서, 나이브 베이즈(Naive Bayes)나 가우시안 혼합 모델(Gaussian Mixture Model)처럼 딥러닝이 아닌 머신러닝 모델도 포함합니다. 시험에서는 교수님 설명대로 "생성형 AI ⊂ 딥러닝"으로 쓰시면 됩니다.

용어 보충 — 교수님이 설명하신 내용 아님

특징 추출(feature extraction)은 원본 데이터에서 판단에 쓸 값을 뽑는 단계, end to end는 입력부터 출력까지 사람이 중간 단계를 따로 설계하지 않고 모델 하나가 처리한다는 뜻입니다. 비정형 데이터(unstructured data)는 표 형태가 아닌 이미지·음성·텍스트 등을 말합니다.

10머신러닝이란 · 왜 쓰는가

What is Machine Learning? / Why Use Machine Learning?

머신러닝을 한 문장으로 말하면 "규칙을 직접 프로그래밍하지 않고, 데이터(경험)를 통해 성능이 좋아지는 프로그램"입니다. 교안은 이것을 두 학자의 정의로 소개합니다. 첫 번째는 머신러닝이 무엇인지를, 두 번째는 프로그램이 학습했는지를 어떻게 판정하는지를 말합니다.

두 가지 정의

Arthur Samuel, 1959

머신러닝은 컴퓨터가 명시적으로 프로그래밍되지 않고도 학습하는 능력을 갖게 하는 연구 분야다.

Machine learning (ML) is the field of study that gives computers the ability to learn without being explicitly programmed.
Tom Mitchell, 1997

어떤 작업 T에 대한 프로그램의 성능을 P로 측정했을 때, 경험 E로 인해 성능이 향상되면 그 프로그램은 작업 T와 성능 지표 P에 대해 경험 E로부터 학습한다고 말한다.

A computer program is said to learn from experience E with respect to some task T and some performance measure P, if its performance on T, as measured by P, improves with experience E.
기호영어의미
Eexperience경험 — 학습에 쓰는 데이터
Ttask작업 — 모델이 수행할 일
Pperformance measure성능 지표 — 얼마나 잘했는지 재는 기준

Mitchell의 정의는 세 가지를 모두 정해야 "학습"이라는 말을 쓸 수 있다는 뜻입니다. 무엇을 할지(T), 무엇으로 배우는지(E), 잘했는지를 무엇으로 재는지(P)입니다. 경험 E가 늘어났을 때 P로 잰 성적이 올라가면 학습한 것이고, 그대로라면 데이터를 아무리 많이 넣었어도 학습한 것이 아닙니다.

E·T·P 예시 — 교수님이 설명하신 내용 아님

참고 교재(Géron)의 스팸 필터 예: T = 새 메일이 스팸인지 판정, E = 스팸/정상 라벨이 붙은 과거 메일(training data), P = 올바르게 분류한 메일의 비율(정확도, accuracy).

머신러닝을 쓰는 이유

그러면 기존 프로그래밍 대신 머신러닝을 쓰는 이유는 무엇일까요? 교안은 네 가지 경우를 듭니다.

  1. 기존 방식으로는 수작업 조정이나 긴 규칙 목록이 필요한 문제 — ML 알고리즘 하나로 코드를 단순화하고 성능도 더 좋게 만들 수 있음 Problems for which existing solutions require a lot of hand-tuning or long lists of rules: one machine learning algorithm can often simplify code and perform better.
  2. 전통적 방식으로는 좋은 해법이 전혀 없는 복잡한 문제 — 뛰어난 ML 기법은 해법을 찾을 수 있음 Complex problems for which there is no good solution at all using a traditional approach: the best machine learning techniques can find a solution.
  3. 변화하는 환경 — ML 시스템은 새 데이터에 적응할 수 있음 Fluctuating environments: a machine learning system can adapt to new data.
  4. 복잡한 문제와 대량의 데이터에서 통찰을 얻기 Getting insights about complex problems and large amounts of data.

네 가지를 하나씩 풀어 보면 다음과 같습니다.

  1. 규칙이 너무 많은 문제 — 대표적인 예가 스팸 필터입니다. 전통적인 방식에서는 "무료", "당첨" 같은 단어가 있으면 스팸으로 처리하는 규칙을 사람이 계속 추가해야 합니다. 스팸 발송자가 "무.료"처럼 바꾸면 규칙을 또 고쳐야 합니다. 머신러닝은 스팸/정상 메일 예시로부터 어떤 단어 조합이 스팸의 신호인지 스스로 찾습니다.
  2. 규칙으로 적을 수 없는 문제 — 음성 인식처럼 "이 소리 파형이면 '가'다"라는 규칙을 사람이 쓸 수 없는 경우입니다. 예시 데이터를 많이 주고 학습시키는 방법밖에 없습니다.
  3. 환경이 계속 변하는 문제 — 새 데이터로 다시 학습하면 변화를 따라갈 수 있습니다. 교수님은 이 부분을 설명하시며 일반화를 언급하셨습니다(아래 11 섹션).
  4. 사람이 배우는 도구 — 학습된 모델을 들여다보면 사람이 몰랐던 패턴을 발견할 수 있습니다.

다음 섹션의 그림 세 개가 각각 1번(전통 방식 vs ML 방식), 3번(변화에 자동으로 적응), 4번(문제에서 통찰 얻기)을 순서도로 보여 줍니다.

정리
  • 머신러닝 = 명시적으로 프로그래밍하지 않고 데이터로 학습 (Samuel)
  • 학습했다 = 경험 E가 늘수록 작업 T에서 성능 P가 오른다 (Mitchell)
  • 쓰는 이유: 규칙이 너무 많음 · 규칙으로 못 씀 · 환경 변화 · 통찰 얻기

11전통적 방식 vs 머신러닝 방식

Traditional Approach vs. ML Approach

평가가 나쁘면 오류를 분석하고 처음 단계로 돌아가는 반복 구조(loop)는 두 방식이 같습니다. 다른 점은 가운데 단계 하나입니다.

왼쪽 전통적 방식을 순서대로 읽으면 다음과 같습니다.

  1. 문제를 연구합니다 (Study the problem).
  2. 사람이 규칙을 작성합니다 (Write rules). 빨간 칸입니다.
  3. 평가합니다 (Evaluate). 결과가 좋으면(😊) 출시(Launch!)합니다.
  4. 결과가 나쁘면(☹) 오류를 분석하고(Analyze errors) 1번으로 돌아갑니다.

오른쪽 ML 방식은 2번 자리가 초록 칸 "ML 알고리즘 학습"(Train ML algorithm)으로 바뀌고, 위에서 데이터가 들어옵니다. 규칙을 만드는 주체가 사람에서 학습 알고리즘으로 바뀐 것입니다.

이 차이 때문에 문제가 바뀌었을 때의 대응도 달라집니다. 전통 방식은 사람이 규칙을 다시 써야 하지만, ML 방식은 새 데이터로 다시 학습하면 됩니다. 이것을 그린 것이 다음 그림입니다.

변화에 자동으로 적응하기

Automatically adapting to change

그림을 순서대로 따라가면 학습 → 평가(😊) → 출시 → 데이터 갱신 → 다시 학습입니다. 운영하면서 새 데이터가 쌓이면 데이터를 갱신하고(Update data), 갱신된 데이터로 알고리즘을 다시 학습시킵니다. 가운데 타원의 자동화 가능(Can be automated)은 이 순환 전체를 사람이 개입하지 않고 프로그램으로 돌릴 수 있다는 뜻입니다. 전통 방식에서는 "규칙 작성"이 사람 몫이라 이렇게 자동으로 돌릴 수 없습니다.

이렇게 계속 새로 들어오는 데이터에도 모델이 잘 동작해야 하므로, 여기서 일반화라는 개념이 등장합니다.

교수님 말씀 — 일반화

새로 들어오는 데이터를 처리할 수 있게 하는 것을 머신러닝의 일반화(generalization)라고 합니다. 머신러닝을 쓰는 이유를 설명하시면서 언급하셨습니다.

정확한 정의 — "어떤 데이터든"은 아님

일반화는 학습에 쓰지 않은 새 데이터(unseen data)에서도 모델이 잘 동작하는 능력입니다. 새 데이터가 학습 데이터와 같은 종류(같은 분포, distribution)여야 한다는 조건이 붙습니다. 고양이·개 사진으로 학습한 모델은 처음 보는 고양이 사진은 분류할 수 있지만, 음성 데이터는 처리하지 못합니다.

학습 데이터에만 잘 맞고 새 데이터에서 성능이 떨어지면 일반화에 실패한 것이고, 이것이 과적합(overfitting)입니다. 일반화 성능은 테스트 세트로 확인합니다.

12머신러닝에서 '학습'의 의미

"Learning" in Machine Learning

앞에서 "데이터로 학습한다"는 말을 여러 번 썼습니다. 이 섹션은 그 학습이 정확히 무엇을 하는 것인지 정의합니다. 핵심 단어는 표 첫 줄의 추론(Induction)입니다. 개별 사례 여러 개를 보고 거기에 공통으로 들어맞는 일반 규칙을 끌어내는 것, 이것이 머신러닝이 하는 일입니다.

용어의미
추론(Induction)
= 귀납 · 귀납적 추론		특정한 예시들의 집합에서 일반적인 규칙을 뽑아내는 과정process of extracting general rules from a set of particular examples
학습(Learning)데이터를 분석하고 거기서 자동으로 정보를 추출하는 컴퓨터 모델을 만드는 것build computer models that can analyze data and extract information automatically from them
  • 대부분의 경우 데이터는 싸고 풍부하지만, 지식은 비싸고 부족하다 In most cases, data are cheap and abundant, but knowledge is expensive and scarce.
  • 데이터에 대한 좋고 쓸모 있는 근사(approximation)인 모델을 만든다 — 모든 것을 설명하지 못하더라도 데이터의 일부는 설명할 수 있다 Build a model that is a good and useful approximation to the data. ▶ May not explain everything, but may still be able to account for some part of the data.

두 문장을 풀어 보겠습니다.

  1. 데이터는 싸고, 지식은 비싸다. 쇼핑몰의 구매 기록 같은 데이터는 가만히 있어도 쌓입니다. 하지만 그 기록에서 "어떤 고객이 다음에 무엇을 살지"라는 지식을 사람이 뽑아내려면 전문가의 시간이 많이 듭니다. 그래서 싸고 많은 데이터에서 비싼 지식을 자동으로 뽑아내는 것이 학습의 목표입니다.
  2. 모델은 근사(approximation)다. 학습 결과로 나온 모델이 모든 데이터를 완벽하게 설명할 필요는 없습니다. 쓸모 있을 만큼 설명하면 됩니다. 뒤에서 배울 과적합은 이 원칙을 어기고 모든 데이터를 완벽히 맞히려다 생기는 문제입니다.
교수님 표현 — "추론"

교수님은 Induction을 추론이라고 부르셨습니다. 교재·다른 과목에서는 같은 말을 귀납 또는 귀납적 추론(inductive reasoning)으로 번역합니다. 세 표현은 모두 같은 개념입니다.

  • 귀납(Induction): 개별 사례 여러 개 → 일반 규칙. 예: 스팸 메일 1,000통에 "무료"가 자주 나옴 → "무료가 들어간 메일은 스팸일 가능성이 높다"는 규칙을 만듦. 머신러닝의 학습이 이 방향입니다.
  • 연역(Deduction): 일반 규칙 → 개별 사례의 결론. 예: "사람은 모두 죽는다" + "소크라테스는 사람이다" → "소크라테스는 죽는다". 6장 규칙 기반 시스템이 이 방향입니다.
  • 추론(Inference): 위 둘을 모두 포함하는 상위 개념입니다. 그래서 6장에서 "추론"이 나오면 inference, 이 섹션에서 "추론"이 나오면 induction이라고 구분해서 읽으시면 됩니다.
이산수학과 연결 — 헷갈리기 쉬운 지점

여기서 말하는 추론(induction)은 정확히는 여러 사례에서 일반 규칙을 추정하는 귀납적 추론(inductive reasoning)입니다. 6장(04. 추론)의 분류로는 연역이 아니라 귀납 쪽입니다. 이산수학의 수학적 귀납법(mathematical induction)은 이름만 같을 뿐, 전제에서 결론을 반드시 끌어내는 연역적 증명 방법이라 성격이 다릅니다. ML의 추론은 결론이 항상 참이라는 보장이 없습니다.

정리
  • ML의 학습 = 추론(Induction, 귀납): 특정 예시들 → 일반 규칙
  • 목표: 싸고 많은 데이터에서 비싸고 부족한 지식을 자동으로 추출
  • 모델은 데이터의 "좋고 쓸모 있는 근사" — 전부 설명하지 않아도 됨

  • 지도 학습: 입력과 정답이 둘 다 있습니다. 정답이 정해진 종류 중 하나이면 분류, 크기를 가진 숫자이면 회귀입니다. 헷갈리면 "정답 두 개의 중간값이 의미가 있는가"를 따져 보면 됩니다. 집값 3억과 4억의 중간인 3.5억은 의미가 있으므로 회귀이고, "스팸"과 "정상"의 중간은 의미가 없으므로 분류입니다.
  • 비지도 학습: 입력만 있고 정답이 없습니다. 정답을 맞히는 대신 데이터 자체의 구조(무리, 패턴)를 찾습니다.
  • 강화 학습: 정답은 없고, 행동의 결과로 점수(보상)를 받습니다. 보상이 지연된(delayed) 이유는 행동 하나하나마다 바로 점수가 오는 것이 아니라, 여러 행동이 끝난 뒤에야 좋았는지 나빴는지 알게 되는 경우가 많기 때문입니다. 예: 바둑은 대국이 끝나야 승패를 압니다.
Supervised Learning: target outputs {yᵗ} are provided along with the observations {xᵗ} ⇒ {(xᵗ, yᵗ)} / Unsupervised Learning: no target outputs are provided ⇒ {xᵗ} / Reinforcement Learning: no supervised output but delayed reward

정리
  • 분류 기준 3가지: ① 감독 여부 ② 점진적 학습 여부 ③ 비교 방식(사례 vs 모델)

15비지도 학습 Unsupervised Learning

비지도 학습의 훈련 데이터에는 레이블이 없습니다. 시스템은 교사나 감독 없이 학습하려고 합니다.

The training data in unsupervised learning is unlabeled. The system tries to learn without a teacher or any supervision.

정답이 없으므로 비지도 학습의 목표는 "정답 맞히기"가 아니라 데이터 자체의 구조를 찾는 것입니다. 교안은 대표 작업 네 가지를 소개합니다: ① 비슷한 것끼리 묶기(군집화), ② 사람이 볼 수 있게 펼치기(시각화), ③ 정보를 유지하며 줄이기(차원 축소), ④ 튀는 것 찾기(이상치 탐지).

① 군집화 Clustering

군집(cluster)은 서로 '비슷한' 객체들의 모임이며, 다른 군집에 속한 객체와는 '비슷하지 않은' 집합입니다.

A cluster can be defined as a collection of objects which are "similar" between them and are "dissimilar" to the objects belonging to other clusters.

그림의 사람 아이콘은 레이블이 없는 데이터입니다. 알고리즘은 "누가 어느 그룹이다"라는 정보 없이 점들 사이의 거리만 보고 가까운 것끼리 묶어, 점선 경계로 4개 군집을 만들었습니다. 군집이 무엇을 뜻하는지(예: "주말에만 방문하는 고객")는 알고리즘이 알려주지 않습니다. 결과를 보고 사람이 해석합니다.

② 시각화 Visualization — t-SNE

t-SNE(t-distributed Stochastic Neighbor Embedding)는 데이터의 국소 구조(local structure)를 보존하면서 고차원 데이터를 2차원이나 3차원으로 줄여 시각화하는 데 쓰입니다.

t-SNE is used for visualizing high-dimensional data by reducing its dimensionality to two or three dimensions while preserving the local structure of the data.

교안 예시는 이미지 10개 클래스(cat, automobile, truck, frog, ship, airplane, horse, bird, dog, deer)를 2차원으로 펼친 그림입니다. 비슷한 클래스끼리 가까이 모였고, 탈것(automobile·truck·ship·airplane)과 동물 영역이 크게 나뉩니다.

여기서 "고차원"이 무슨 뜻인지 짚고 가겠습니다. 이 10개 클래스는 CIFAR-10이라는 이미지 데이터셋의 클래스와 같은데, 이 데이터셋의 이미지 한 장은 32×32 픽셀 × 색 3개 = 3,072개의 숫자로 표현됩니다. 즉 이미지 한 장이 3,072차원 공간의 점 하나입니다. 사람은 이것을 볼 수 없으므로, 가까운 점은 가깝게 유지하면서 2차원 평면에 옮겨 그린 것이 아래 그림입니다.

③ 차원 축소 Dimension Reduction

고차원 데이터를 다룰 때는, 데이터의 본질을 담는 더 낮은 차원의 부분공간(lower dimensional subspace)으로 투영(projecting)해 차원을 줄이는 것이 유용한 경우가 많습니다.

When dealing with high dimensional data, it is often useful to reduce the dimensionality by projecting the data to a lower dimensional subspace which captures the essence of the data. — Kevin P. Murphy, Machine Learning: A Probabilistic Perspective

시각화(②)와 차원 축소(③)는 둘 다 차원을 줄이지만 목적이 다릅니다. 시각화는 사람이 보기 위해 2·3차원까지 줄이고, 차원 축소는 필요한 정보를 최대한 유지하면서 학습에 드는 계산량을 줄이기 위해 줄입니다.

④ 이상치 탐지 Outlier (Anomaly) Detection

대다수 데이터에서 크게 벗어난 관측값이나 데이터 포인트를 찾아내는 과정입니다.

Outlier (anomaly) detection is a process of identifying observations or data points that significantly deviate from the majority of the data.

그림 읽기: 회색 점(훈련 사례, Training instances)은 대부분 정상인 데이터이고, 모델은 이것으로 "정상 데이터가 어디에 모여 있는지"를 학습합니다. 새 사례 두 개가 들어오면, 초록 X는 무리 가장자리 안쪽에 있어 정상(Normal)으로, 빨간 X는 무리에서 멀리 떨어져 있어 이상치(Anomaly)로 판단합니다. 대표적인 쓰임은 신용카드 부정 사용 탐지, 공장 불량품 검출, 서버 침입 탐지입니다.

정리

  • ① 군집화: 비슷한 것끼리 묶기 · ② 시각화(t-SNE): 고차원 → 2·3차원으로 펼쳐 보기
  • ③ 차원 축소: 본질을 담은 낮은 차원으로 투영 · ④ 이상치 탐지: 다수에서 크게 벗어난 점 찾기

16강화 학습 Reinforcement Learning

학습하는 시스템을 에이전트(agent)라고 부릅니다. 에이전트는 환경(environment)을 관찰하고, 행동(action)을 골라 수행하며, 그 결과로 보상(reward)이나 벌점(penalty)을 받습니다. 시간이 지나면서 보상을 최대화하는 최선의 전략, 즉 정책(policy)을 스스로 학습해야 합니다.

The learning system, referred to as an agent, can observe the environment, select and perform actions, and receive rewards/penalties in return. It must then learn for itself the best strategy, known as a policy, to maximize reward over time.

지도 학습과 가장 큰 차이는, 강화 학습에는 "이 상황에서는 이 행동이 정답"이라는 데이터가 없다는 점입니다. 에이전트는 직접 행동해 보고, 그 결과로 받은 보상·벌점을 근거로 판단 기준을 스스로 고칩니다. 이 판단 기준, 즉 어떤 상황에서 어떤 행동을 할지 정한 규칙이 정책입니다. 학습의 목표는 시간이 지나면서 받는 보상의 합이 가장 커지는 정책을 찾는 것입니다.

교수님 말씀 — 온라인 학습이 좋은 이유

배치 학습에 비해 온라인 학습이 좋은 이유는 더 빠르다는 것입니다.

"빠르다"의 정확한 뜻

교안 표현으로는 "학습 단계 하나하나가 더 빠르고 더 저렴하다"입니다.

Each learning step is faster and cheaper, so the new data can be included in the update the model gradually.

새 데이터가 들어올 때마다 전체 데이터로 처음부터 다시 학습하지 않고, 들어온 데이터(미니배치)만으로 모델을 조금 고치기 때문입니다. 그래서 새 데이터를 반영하는 속도가 빠르고, 변화에 빨리 적응합니다. 전체 데이터를 한 번 학습하는 데 걸리는 총 시간이 항상 짧다는 뜻은 아닙니다.

표를 풀어 보면 다음과 같습니다.

  • 배치 학습: 조금씩 배우는 것이 안 되므로, 새 데이터를 반영하려면 새 데이터를 합친 전체 데이터로 처음부터 다시 학습하고 기존 모델과 교체해야 합니다. 데이터가 많을수록 오래 걸리므로 보통 하루나 일주일 단위로 합니다.
  • 온라인 학습: 데이터를 작은 묶음(미니배치)으로 나눠 하나씩 넣고, 넣을 때마다 모델을 조금씩 고칩니다. 새 데이터가 곧바로 반영됩니다. 대신 잘못된 데이터가 들어오면 그것도 곧바로 반영되어 성능이 떨어질 수 있으므로, 들어오는 데이터를 감시해야 합니다.

그림 읽기: 처음에는 모아 둔 데이터로 학습하고 평가한 뒤 출시합니다(Launch). 그다음부터는 실시간으로 들어오는 새 데이터(New data, on the fly)를 받아 운영하면서 계속 학습합니다(Run and learn).

대용량 데이터와 외부 메모리 학습

온라인 학습 알고리즘은 한 대의 컴퓨터 주기억장치에 다 들어가지 않는 거대한 데이터셋을 학습할 때도 쓸 수 있습니다. 이것을 외부 메모리 학습(out-of-core learning)이라 합니다. 알고리즘은 데이터 일부를 불러와 학습 단계를 수행하고, 전체 데이터를 다 돌 때까지 이를 반복합니다 = 점진적 학습(incremental learning).

Online learning algorithms can also be used to train systems on huge datasets that cannot fit in one machine's main memory (out-of-core learning). The algorithm loads part of the data, runs a training step on that data, and repeats the process until it has run on all of the data (incremental learning).

그림 읽기: 대량의 데이터(*Lots* of data)를 조각으로 나눈 뒤(Chop into pieces), 조각을 하나씩 온라인 ML 알고리즘에 넣어 학습합니다. 나머지 평가·출시·오류 분석 순환은 앞의 순서도와 같습니다.

"온라인"의 뜻 주의 — 교수님이 설명하신 내용 아님

외부 메모리 학습은 보통 운영 전(오프라인)에 이루어집니다. 그래서 여기서 "온라인 학습"은 "운영 중에 배운다"가 아니라 "데이터를 조금씩 나눠 점진적으로 배운다"는 뜻으로 읽어야 합니다. 이런 이유로 참고 교재(Géron)는 "점진적 학습(incremental learning)"이라는 이름이 더 정확하다고 설명합니다.

자료구조·운영체제 개념과 연결

main memory(주기억장치, RAM)에 한 번에 올릴 수 없는 데이터를 조각으로 나눠 순서대로 처리한다는 점에서, 대용량 파일을 버퍼 단위로 읽는 방식과 같은 발상입니다.
