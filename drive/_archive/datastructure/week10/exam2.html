문제은행 — 2-3-4 트리

정의·조건 · Search · Insert(split) · Delete(fusion) · 레드블랙 변환

이 문제집은 10주차 2차시 강의노트(2-3-4 트리) 범위에서 출제했습니다.
아래 여러 문제에서 기준 예시 트리를 사용합니다 (강의노트 §3과 동일). 트리가 필요한 문제에는 트리를 함께 넣었고, 화면 우하단 📌 기준 트리 버튼으로도 언제든 볼 수 있습니다.

Q2객관식 · 복수선택

  2. 모든 리프 노드는 같은 레벨(높이)에 위치한다.
  3. 한 노드는 키를 최대 2개까지만 가질 수 있다.
  4. 자식이 최대 2개인 이진 트리의 일종이다.
✎ 나의 답안
정답 / 풀이 보기

정답: 1, 2

3번 틀림 — 키는 최대 3개(4-노드). 4번 틀림 — 한 노드가 자식을 최대 4개 가지므로 이진 트리가 아닙니다. 조건은 ① 자식 수 2~4, ② 모든 리프가 같은 레벨(균형) 두 가지입니다.

✎ 나의 답안
정답 / 풀이 보기

정답: 아니다 (조건 1 위반)

키가 3개면 4-노드이므로 자식은 반드시 4개여야 합니다(키+1). 자식이 3개면 (자식 수) = (키 개수)+1 규칙을 어겨 2-3-4 트리가 될 수 없습니다. (리프라면 자식이 0개여서 예외)

[37] ├─ [30, 34] │ ├─ [5] │ ├─ [32, 33] │ └─ [35] └─ [48, 60, 82] ├─ [40] ├─ [50, 53, 57] ├─ [69] └─ [86, 98]
✎ 나의 답안
정답 / 풀이 보기

정답: [37] → [48,60,82] → [50,53,57] (53 발견)

① 루트 [37]: 53 > 37 → 오른쪽. ② [48,60,82]: 48 < 53 < 60 → 2번째 자식. ③ [50,53,57]에서 53 발견. 방문 노드 수 = 트리 높이만큼 → O(h).

Q6계산 · 높이

2-3-4 트리의 높이 h의 (1) 최선의 경우(가장 짧을 때)와 (2) 최악의 경우(가장 길 때)를 n에 대한 로그로 나타내고, (3) 점근적 복잡도를 쓰시오.

✎ 나의 답안
정답 / 풀이 보기

정답: (1) log₄ n   (2) log₂ n   (3) O(log n)

모든 노드가 4-노드면 한 레벨에 4배씩 늘어 가장 짧음(log₄ n). 모두 2-노드면 이진 트리와 같아 가장 김(log₂ n). 로그 밑은 빅오에서 상수배라 무시 → log₄ n ≤ h ≤ log₂ n = O(log n).

Q7객관식

2-3-4 트리의 search, insert, delete 연산의 점근적 시간복잡도로 옳은 것은?

  1. 모두 O(n)
  2. 모두 O(log n)
  3. search만 O(log n), 나머지는 O(n)
  4. 모두 O(1)
✎ 나의 답안
정답 / 풀이 보기

정답: 2번

트리가 항상 균형(모든 리프 같은 레벨)이라 높이가 O(log n). search·insert·delete 모두 O(h)=O(log n)입니다 (split·fusion은 각 레벨당 O(1)). 레드블랙 트리와 동일한 성능.

Q9서술 · Split

삽입 중 가득 찬 노드(4-노드, 키 3개)를 만났을 때 수행하는 split의 동작을 세 가지로 설명하시오.

✎ 나의 답안
정답 / 풀이 보기

정답 요지

① 가운데 키를 부모로 올린다. ② 나머지 두 키를 좌·우 두 노드로 분리한다. ③ 원래 노드의 자식 4개를 새 두 노드가 2개씩 나눠 갖는다. 결과적으로 가지(자식)가 하나 더 생기고, 리프 도달 시 항상 자리가 보장됩니다. split 1회는 O(1).

Q10서술

2-3-4 트리 삽입은 내려가는 길에 가득 찬 노드를 미리 쪼개는 top-down split 방식을 쓴다. 리프에 도착해서 쪼개지 않고 미리 쪼개며 내려가는 이유는 무엇인가?

✎ 나의 답안
정답 / 풀이 보기

정답 요지

리프에서 가득 찼다고 그때 쪼개면 부모도 가득 차 있을 수 있어 위로 연쇄적으로 split이 전파됩니다. 미리 깨고 내려가면 부모가 항상 여유가 있어 안전하게 처리되고, 가운데 키를 올릴 부모 자리가 보장됩니다.

Q11객관식

2-3-4 트리에서 트리의 높이가 1 증가하는 유일한 경우는?

  1. 리프에 빈 자리가 있어 그냥 끼워 넣을 때
  2. 중간 노드를 split해 가운데 키를 올릴 때
  3. 루트가 가득 차 split되며 새 루트가 생길 때
  4. 내부 노드를 successor와 교체해 삭제할 때
✎ 나의 답안
정답 / 풀이 보기

정답: 3번

가운데 키를 올릴 부모가 없을 때(루트가 가득 참) 새 루트가 생기며 높이가 1 증가합니다. 이것이 높이가 늘어나는 유일한 경로라서 모든 리프가 같은 레벨을 유지합니다. (반대로 높이 감소는 루트가 2-노드일 때 fusion으로 셋이 합쳐질 때.)

Q12Delete

리프 노드 [32, 34]에서 delete(32)를 수행하면 결과는? 또 fusion 없이 리프에서 그냥 지울 수 있는 조건은 무엇인가?

✎ 나의 답안
정답 / 풀이 보기

정답: [32,34] → [34] (그냥 삭제)

리프가 3-노드 또는 4-노드(키 2개 이상)이면 키 하나를 빼도 노드가 여전히 유효(2-노드 이상)하므로 fusion 없이 그냥 지웁니다. 키가 1개인 2-노드 리프에서 지우면 빈 노드가 되어 조건이 깨지므로 fusion이 필요합니다.

Q13Delete · 내부 노드

삭제할 키가 내부 노드에 있으면 직접 지울 수 없다. 어떻게 처리하는가? (BST 삭제와 같은 트릭)

✎ 나의 답안
정답 / 풀이 보기

정답 요지: successor(또는 predecessor)와 교체 후 리프에서 삭제

BST 삭제처럼, 그 키의 in-order successor(오른쪽 서브트리에서 가장 작은 값)를 찾아 내부 노드 자리에 옮기고, 실제 삭제는 리프에서 수행합니다. 예: 루트 [20,50]에서 20 삭제 → successor 22와 교체 → 리프 [22,24,26]에서 22 제거.

Q14서술 · Fusion

fusion은 split의 반대 개념이다. 삭제 시 내려가는 길에 2-노드를 만나면 미리 fusion한다. fusion의 두 가지 방식(형제가 여유 있을 때 / 형제도 2-노드일 때)을 각각 한 줄로 설명하시오.

✎ 나의 답안
정답 / 풀이 보기

정답 요지: ① Redistribution(재분배)   ② Merge(병합)

① 형제가 3-노드 이상이면, 형제의 키를 부모를 거쳐 빌려옵니다(부모 키가 2-노드로 내려오고 형제의 인접 키가 부모로 올라감 — BST 순서 유지).
② 형제도 2-노드라 빌릴 게 없으면, 부모 키 1개를 끌어내려 두 형제를 하나의 4-노드로 합칩니다(merge).

Q15객관식

처리해야 할 2-노드의 인접 형제도 2-노드여서 키를 빌려올 수 없을 때 수행하는 연산과, 그 부작용으로 옳은 것은?

  1. Redistribution — 트리 높이가 1 증가한다
  2. Merge — 부모가 키 하나와 자식 하나를 잃는다
  3. Split — 가운데 키가 올라가 새 루트 생성
  4. 별도 처리 없이 그대로 삭제하면 된다
✎ 나의 답안
정답 / 풀이 보기

정답: 2번

Merge는 부모 키 1개를 내려 두 형제를 4-노드로 합치므로, 부모는 키 하나와 자식 하나를 잃습니다. 특히 루트가 2-노드이고 자식들도 2-노드라 셋이 합쳐지면 루트가 사라지고 트리 높이가 1 감소합니다.

2-3-4 노드레드블랙 변환
2-노드?
3-노드?
4-노드?
✎ 나의 답안
정답 / 풀이 보기
2-3-4 노드레드블랙 변환
2-노드1레벨: 키 1개 = black
3-노드2레벨: black 1개(부모) + red 1개(자식)

Q17빈칸 채우기 · 높이

변환 규칙(2-노드→1레벨, 3·4-노드→2레벨)에서, 2-3-4 트리의 한 레벨은 레드블랙 트리에서 최대 2레벨이 된다. 빈칸을 채우시오.

hRB ≤ (______) · h234   이고, h234 ≤ log₂ n 이므로 hRB ≤ (______). (더 타이트하게는 2·log₃ n까지 줄일 수 있음)

✎ 나의 답안
정답 / 풀이 보기

정답: 2 · h234 / 2 · log₂ n

2-3-4의 1레벨이 RB에서 최대 2레벨이므로 hRB ≤ 2·h234. h234 ≤ log₂ n을 대입하면 hRB ≤ 2·log₂ n (10-1에서 본 결과와 일치). 더 정밀한 분석으로는 2·log₃ n(log₃ < log₂라 더 타이트한 상계)까지 보일 수 있습니다 — 다음 차시 보충.
