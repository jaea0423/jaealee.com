AVL 트리 (2) — 삽입과 삭제

균형이 깨진 트리를 회전(Rotation)으로 복구하는 알고리즘

01 AVL Insert — 큰 그림

AVL의 삽입은 BST 삽입과 거의 같습니다. 다만 삽입 후에 균형이 깨졌는지 확인하고, 깨졌다면 회전(Rotation)으로 복구하는 단계가 추가됩니다.

4단계 알고리즘

BST의 insert로 노드 삽입

상속받은 BST의 insert를 그대로 호출. v는 삽입된 노드(또는 부모)를 반환받음.

x, y, z 찾기

삽입한 위치에서 부모 방향으로 올라가며 처음으로 균형이 깨진 노드 z를 찾음. 거기서 자식 방향으로 내려오며 y, x.

rebalance(x, y, z)

회전 1~2번으로 균형 복구. 새로 z 자리를 차지한 노드를 w라고 함.

루트 갱신 (필요 시)

w가 새 루트가 됐다면 (w.parent == None), self.root = w로 갱신.

의사코드 (Pseudo-code) 
class AVL(BST):
    def insert(self, key):
        # 1. BST의 insert를 그대로 호출 (상속)
        v = super().insert(key)
        
        # 2. v에서 위로 올라가며 처음 불균형 노드 z 찾기
        #    z 아래로 내려오며 y, x 결정
        x, y, z = find_xyz(v)
        
        # 3. 회전으로 균형 복구
        w = rebalance(x, y, z)
        
        # 4. 루트가 바뀌었으면 갱신
        if w.parent is None:
            self.root = w
파이썬 super() 짧은 정리
super()는 파이썬 내장 함수입니다 (정해진 키워드). 부모 클래스의 메서드를 호출할 때 사용해요.
  • 파이썬 3 권장: super().insert(key)
  • 구버전 스타일: super(AVL, self).insert(key) — 강의 노트에서는 이 방식
자바의 super.insert(key)와 같은 역할입니다.

02 x, y, z 찾기 — 예시로 이해

처음에는 헷갈리니까 구체적인 예시로 봅시다.

상황: [10, 5, 15, _, 7]에 9를 삽입

찾는 순서

  1. 9를 삽입한 자리에서 부모 방향으로 올라감 (9 → 7 → 5 → 10 → ...)
  2. 각 노드에서 균형 검사 (|BF| ≤ 1?)
    • 7: 균형 OK
    • 5: 깨짐! → 이게 z
  3. z에서 내려오면서 방금 올라온 경로 추적
    • z(5)의 자식 중 올라온 방향 = 7 → y
    • y(7)의 자식 중 올라온 방향 = 9 → x
기억할 키워드
  • z: 처음으로 균형이 깨진 조상 (가장 가까운 불균형 노드)
  • y: z의 자식 중 더 무거운 쪽 (= 우리가 올라온 방향)
  • x: y의 자식 중 더 무거운 쪽
z, y, x는 위에서 아래로 연속된 3개 노드입니다.

03 Rebalance Case 1 — 일자형 (회전 1번)

CASE 1z, y, x가 한 방향으로 일자로 이어짐

좌-좌-좌 (LL) 또는 우-우-우 (RR) 형태. 회전 1번으로 해결됩니다.

LL 케이스 — Right Rotation

서브트리 T1
서브트리 T2
서브트리 T3
서브트리 T4
회전 전 (불균형)
↻
rotateRight(z)
회전 후 (균형)

회전 동작 정리

  • y가 위로 올라가서 새로운 루트가 됨
  • z는 y의 오른쪽 자식으로 내려감
  • x는 y의 왼쪽 자식으로 그대로 유지
  • 중요: T3 (y의 원래 오른쪽 서브트리)가 z의 왼쪽으로 이동 ← 점선 표시
  • T1, T2, T4는 자기 부모와 함께 그대로 따라감
왜 BST 조건이 유지되나?
회전 후에도 키 순서는 T1 < x < T2 < y < T3 < z < T4로 그대로입니다. BST의 중위 순회(in-order) 결과가 변하지 않기 때문에 BST 조건이 깨지지 않아요.

RR 케이스

LL의 좌우 대칭 버전입니다. z-y-x가 모두 오른쪽으로 이어진 경우 → rotateLeft(z) 한 번으로 해결.

04 Rebalance Case 2 — 꺾인형 (회전 2번)

CASE 2z, y, x가 꺾인 방향으로 이어짐

좌-우 (LR) 또는 우-좌 (RL) 형태. 회전 2번이 필요합니다.

LR 케이스

z의 왼쪽 자식이 y, y의 오른쪽 자식이 x인 경우 (좌→우로 꺾임).

핵심 아이디어: 꺾인 부분을 먼저 펴서 Case 1 모양으로 만든 다음, Case 1처럼 회전.

1단계: rotateLeft(y) — 꺾인 부분 펴기

초기 상태 (LR 꺾임)
↺
rotateLeft(y)
중간 상태 (Case 1 모양)

중간 상태를 보면 z, x, y가 모두 왼쪽으로 일자로 이어진 모양 (Case 1의 LL과 같음). 아직 균형은 맞지 않습니다 (z의 왼쪽 높이가 여전히 큼). 이제 Case 1처럼 처리하면 됩니다.

2단계: rotateRight(z) — Case 1처럼 처리

중간 상태
↻
rotateRight(z)
최종 (균형 맞춤)

RL 케이스

LR의 좌우 대칭. rotateRight(y) → rotateLeft(z) 순서로 처리합니다.

4가지 케이스 정리

케이스 모양 (z-y-x) 회전 방법 회전 횟수
LL 좌-좌-좌 rotateRight(z) 1번
RR 우-우-우 rotateLeft(z) 1번
LR 좌-우 (꺾임) rotateLeft(y) → rotateRight(z) 2번
RL 우-좌 (꺾임) rotateRight(y) → rotateLeft(z) 2번
코드 외우지 말 것
회전 코드를 외우려 하지 말고 알고리즘 자체를 이해하세요. "어느 노드가 위로 올라가고, 어느 서브트리가 어디로 옮겨가는가"만 그릴 수 있으면 충분합니다.

05 Insert 시간복잡도 분석

단계 작업 시간 복잡도
1 BST insert (트리 따라 내려가기) O(h) = O(log n)
2 x, y, z 찾기 (다시 올라가기) O(h) = O(log n)
3 rebalance (회전 1~2번) O(1)
4 루트 갱신 O(1)
AVL Insert 시간복잡도
O(log n) + O(log n) + O(1) + O(1) = O(log n)
왜 rebalance는 O(1)인가?
회전은 포인터 몇 개만 바꾸는 작업이고, AVL 삽입에서는 딱 한 번만 회전하면 균형이 끝까지 유지됩니다. (삭제는 다름! 다음 섹션에서)

참고: O(n) vs O(log n)

O(n)이 O(log n)보다 훨씬 빠르게 증가 → log n이 더 좋음

06 AVL Delete — 삽입과의 차이

삭제도 기본 아이디어는 같습니다: BST의 삭제로 노드 제거 → 균형 깨졌으면 회전. 하지만 삽입과 결정적인 차이가 하나 있어요.

핵심 차이: 연쇄 rebalance

Insert Delete
rebalance 횟수 최대 1번 최대 O(log n)번
이유 한 번 균형 맞추면 위쪽도 다 OK 한 곳 균형 맞춰도 위쪽이 또 깨질 수 있음
x, y, z 찾는 법 삽입한 노드부터 위로 올라감 z의 무거운 쪽 자식 → y, 그 자식의 무거운 쪽 → x

왜 연쇄적으로 일어나는가?

삭제 후 회전했더니 부모 노드(A)에서 또 균형이 깨질 수 있음 → 루트까지 반복
x, y 선택 규칙 (삭제 시)
z 기준으로 자식이 더 많은(=무거운) 방향으로 내려갑니다.
  • z.left.height > z.right.height면 → y = z.left
  • 그 반대면 → y = z.right
  • x도 마찬가지로 y의 무거운 자식
(삽입에서도 사실 같은 원리지만, 삽입은 어디서 올라왔는지가 곧 무거운 방향이라 자연스럽게 됨)

07 Delete 코드 분석

의사코드 (Pseudo-code) 
def delete(self, u):
    # BST의 삭제 호출 (deleteByMerging도 가능)
    # v는 지운 노드의 부모
    v = super().deleteByCopying(u)
    
    # v부터 루트까지 올라가며 균형 검사
    while v is not None:
        if not v.is_balanced():
            z = v
            
            # ★ y 찾기: z의 무거운 쪽 자식
            if z.left.height > z.right.height:
                y = z.left
            else:
                y = z.right
            
            # ★ x 찾기: y의 무거운 쪽 자식
            if y.left.height > y.right.height:
                x = y.left
            else:
                x = y.right
            
            # 회전으로 복구. v는 새로 z 자리에 들어간 노드
            v = rebalance(x, y, z)
        
        w = v
        v = v.parent  # ★ 한 단계 위로 올라감 (연쇄 검사)
    
    # 루프 끝나면 w가 루트
    self.root = w

핵심 포인트

  • while v is not None: 루트까지 계속 올라가며 검사 (insert와 결정적 차이)
  • 한 번 회전했다고 끝이 아니라, 회전 후에도 부모로 올라가서 또 검사
  • 루프가 끝나면 v는 None이 되고, w는 항상 루트가 됨
  • 마지막에 self.root = w로 루트 갱신
스크랩 표기 정정
원본 스크랩의 if v! None은 if v != None 또는 while v is not None의 오타입니다.

08 시간복잡도 종합 정리

Delete 분석

단계 작업 시간 복잡도
1 BST의 deleteByCopying O(log n)
2 while 루프 (루트까지 올라감) O(log n)번 반복
3 각 반복마다 rebalance O(1)
총합 전체 delete O(log n) × O(1) + O(log n) = O(log n)

최종 정리표

연산 구성 시간 복잡도
탐색 (search) BST 탐색 O(log n)
삽입 (insert) BST insert O(log n) + rebalance O(1) O(log n)
삭제 (delete) BST delete O(log n) + rebalance O(log n) × O(1) O(log n)
높이 (height) 균형 조건으로 보장 O(log n)
결론
AVL 트리 = BST + 높이 균형 조건

→ 모든 주요 연산이 O(log n)으로 보장됨
