균형이 왜 중요한가 Balanced Search Tree

탐색 트리의 모든 연산(검색·삽입·삭제)은 트리 높이 h에 비례한다 → O(h). 그래서 h가 작아야 빠르다.

  • 일반 BST는 균형 보장이 없어, 정렬 순서로 삽입하면 한쪽으로 치우쳐 h = O(n)(연결 리스트)이 된다.
  • "균형이 좋다" = 노드 수에 비해 높이가 낮다. 노드 n개에서 h = O(log n)이면 균형 잡힌 것.

균형 검색 트리 분류

분류자식 수대표BST?
균형 이진 탐색 트리최대 2AVL · 레드블랙O

세 트리(AVL · 레드블랙 · 2-3-4) 모두 검색·삽입·삭제가 O(log n)으로 보장된다.

1

AVL 트리 Adelson-Velsky & Landis, 1962

정의 · 균형 인수(BF)

AVL 트리 = 모든 노드에서 좌우 서브트리 높이 차가 1 이하인 BST.

BF(v) = height(왼쪽 서브트리) − height(오른쪽 서브트리), 조건: |BF(v)| ≤ 1 (즉 −1, 0, +1)

⚠️ 높이 규약: 잎 노드 높이 = 0, 빈 서브트리 높이 = −1. (한 노드라도 위반하면 AVL 아님)

높이 = O(log n) 증명 — 빈출

높이 h인 AVL 트리의 최소 노드 수 Nh를 본다(최악 = 노드는 적은데 높이는 높은 경우).

Nh = Nh−1 + Nh−2 + 1 (N₀=1, N₁=2) → 1,2,4,7,12,20,33,… (피보나치 트리)
  • ① Nh−1 ≥ Nh−2 이용 → Nh ≥ 2·Nh−2 (+1 떼냄)
  • ② 반복 적용 → Nh ≥ 2k·Nh−2k, k=h/2 대입 → Nh ≥ 2h/2
  • ③ n ≥ Nh ≥ 2h/2 에 log₂ → h ≤ 2·log₂ n = O(log n)

이산수학의 피보나치 점화식(Fn=Fn−1+Fn−2)과 +1만 다른 꼴.

회전 4유형 — 불균형 복구

위반 노드 z 기준, 가장 깊은 손자 위치로 유형 결정. 회전은 중위 순회 순서를 보존하므로 BST 조건이 유지됨(O(1)).

유형가장 깊은 위치처리횟수
LLz.left.leftz 우회전1
RRz.right.rightz 좌회전1
LRz.left.rightz.left 좌회전 → z 우회전2
RLz.right.leftz.right 우회전 → z 좌회전2

암기: 이름과 회전 방향이 반대(LL→우회전, RR→좌회전). 꺾인 LR·RL은 먼저 펴서 일직선으로 만든 뒤 처리.

연산 시간복잡도

  • 삽입: BST 삽입 O(log n) + 회전 최대 2회(O(1)) = O(log n)
  • 삭제: 회전이 루트까지 연쇄(cascade)로 최대 O(log n)회 일어날 수 있으나 합쳐도 O(log n)
  • 탐색·삽입·삭제·높이 모두 O(log n)
2

레드-블랙 트리 Red-Black Tree

기본 약속 · 4가지 규칙

모든 NULL 자리에 NIL 노드(항상 검정)를 둔다. RB에서 "리프"=NIL, 실제 값 노드=내부 노드.

  • ① 루트는 B 검정
  • ② 모든 리프(NIL)는 B 검정
  • ③ R 빨강 노드의 두 자식은 모두 검정 (= 레드 연속 금지)
  • ④ 어느 노드에서든 리프까지 경로의 검정 노드 수가 일정 (= 블랙 높이)

균형의 비결: ③(레드는 길게 못 이어짐) + ④(한쪽으로 못 쏠림) → h ≤ 2·log₂(n+1).

블랙 높이 세기

13(B) / \ 8(R) 17(R) 13→8→1→NIL : B,B,B = 3 / \ / \ 13→17→25→NIL: B,B,B = 3 1(B)11(B)15(B)25(B) 빨강은 안 셈 → 모든 경로 3개로 동일 ✓

삽입 — 3단계 + 수선

① BST처럼 삽입 → ② 새 노드 x를 빨강으로 → ③ 좌우 NIL 부착.

빨강으로 시작하는 이유: 규칙 ④(블랙 높이)는 그대로 유지되고, 최악이라도 ③(레드 연속)만 점검하면 됨.

경우상황처리
ax가 루트x를 검정으로
b부모 p가 검정아무것도 안 함
c-1p 빨강, 삼촌 s도 빨강색만 변경(p·s→검정, g→빨강), 위로 재귀
c-2p 빨강, 삼촌 s는 검정회전+색 교환 (일직선 1회 / 꺾임 2회)

높이 상계 개선 · 비교

  • 2-3-4 트리와 관계로 worst case(모두 3-노드) 분석 → h ≤ 1.26·log₂ n (기존 2·log₂ n보다 타이트). 핵심: 1 < log₂3 < 2.
  • AVL vs 레드블랙: AVL은 더 엄격(h ≤ 1.44 log₂n)·탐색 빠름·회전 많음 / 레드블랙은 느슨·회전 적음 → 삽입·삭제 잦은 실무에서 일반적(C++ std::map, Java TreeMap).
3

2-3-4 트리 B-트리의 사촌

정의 · 노드 종류

한 노드가 키 여러 개를 갖는 탐색 트리(이진 X). 조건 2가지: ① 자식 수 2·3·4 중 하나 ② 모든 리프가 같은 레벨(균형).

노드키자식
2-노드12
3-노드23
4-노드34

항상 (자식 수) = (키 개수) + 1. 높이 범위: log₄ n ≤ h ≤ log₂ n = O(log n).

삽입 — top-down split

  • 내려가는 길에 가득 찬 4-노드를 만나면 미리 split: 가운데 키를 부모로 올리고, 나머지 둘을 좌·우 노드로 나눔(자식 4개는 2개씩).
  • 미리 쪼개면 리프 도달 시 항상 자리가 있음(연쇄 방지).
  • 루트가 가득 차 split될 때만 트리 높이가 +1 (높이 증가의 유일 경로).

삭제 — fusion

  • 내부 노드 키는 successor와 교체 후 리프에서 삭제.
  • 2-노드를 만나면 미리 처리: Redistribution(형제가 3-노드↑이면 부모 거쳐 빌리기) 또는 Merge(형제도 2-노드면 부모 키 내려 4-노드로 합침).
  • 루트가 2-노드인데 자식도 2-노드라 합쳐지면 높이 −1 (감소의 유일 경로).

레드블랙과 1:1 등가

2-3-4 노드레드블랙 변환
2-노드B 1개 (1레벨)
3-노드B 1개 + R 1개 (2레벨)
4-노드B 1개 + R 2개 (2레벨)

그래프 표현 G = (V, E)

정의 · 네 종류

G = (V, E). V = 정점(vertex), E = 간선(edge). 간선으로 직접 이어진 두 정점 = 인접(adjacent). |V|=n, |E|=m.

가중치 없음가중치 있음
방향 없음무향 그래프가중 그래프
방향 있음방향 그래프가중 방향 그래프

⚠️ 방향 그래프에서 A↔B는 간선 2개(A→B, B→A). A[i][j]와 A[j][i]가 다를 수 있다.

인접 행렬 vs 인접 리스트

항목인접 행렬인접 리스트
공간O(n²)O(n + m)
간선 (u,v) 확인O(1)O(n)
인접 노드 순회O(n)O(이웃수)
간선 삭제O(1)O(n)
  • 무향 행렬은 대각선 대칭, 방향 행렬은 비대칭. 무향 리스트는 간선 1개가 노드 2개(총 2m).
  • 희소(sparse) → 리스트, 조밀(dense) → 행렬. 탐색(BFS/DFS)은 인접 노드 순회가 핵심이라 보통 리스트.
  • 거리 맥락에서 "연결 안 됨" = ∞, 자기 자신 = 0. (이 ∞ 행렬이 Floyd-Warshall의 d₀)

그래프 순회 DFS · BFS · 위상 정렬

DFS vs BFS

구분DFS (깊이)BFS (너비)
방향한 길로 끝까지 → backtrack가까운 곳부터 한 겹씩
자료구조스택/재귀 (LIFO)큐 (FIFO)
용도사이클 탐지·위상 정렬최단 거리(무가중치)

둘 다 O(n+m). 같은 그래프·시작점이라도 방문 순서가 다름. BFS의 visited는 enqueue할 때 표시(중복 방지).

DFS의 pre / post

  • pre[v] = 진입 시각, post[v] = 종료 시각. pre 오름차순 = 방문 순서.
  • [pre, post] 막대가 포함 관계 ⇔ DFS 트리의 조상-자손. 정점 n개 → DFS 트리 간선 n−1개.
  • Back edge(이미 방문한 조상으로 가는 간선)가 하나라도 있으면 사이클 존재.
  • DFSALL: 안 가본 노드마다 DFS 재시작 → DFS 호출 횟수 = 연결 요소(component) 개수.

위상 정렬 (Topological Sort)

DAG(방향·사이클 없음)의 정점을 "선행 → 후행" 순으로 줄세움. 간선 u→v면 u가 v보다 앞.

DFS 후 POST 값을 내림차순으로 나열 = 위상 정렬 (간선 u→v면 항상 post[u] > post[v])

최단 경로 Shortest Path

공통 핵심 — relax

부분 경로 최단성(Optimal Substructure): 최단 경로의 일부 구간도 반드시 최단. 모든 알고리즘의 기반.

relax(u, v): if dist[v] > dist[u] + w(u,v): dist[v] = dist[u] + w(u,v); parent[v] = u

부등호는 <(더 짧을 때만 갱신), 갱신 시 parent도 기록(경로 역추적·최단 경로 트리 SPT).

Bellman-Ford — SSSP

  • 모든 간선을 n−1번 반복 완화(최단 경로는 간선 최대 n−1개).
  • 한 번 더 돌려 또 줄면 → 음의 사이클 검출.
  • 음수 가중치 OK. 시간복잡도 O(VE), 최악 O(n³).

Dijkstra — SSSP

  • min-heap에서 가장 가까운 미확정 노드를 deleteMin으로 확정(그리디) → 이웃 relax → decreaseKey.
  • 양수라 그 노드의 dist는 더 줄 수 없음(확정해도 안전). 음수 간선 불가.
  • 시간복잡도 O((n+E) log n), 최악 O(n² log n). (Fibonacci heap이면 O(E + n log n))

⚠️ 다익스트라가 음수에서 틀리는 이유: "한 번 확정한 거리는 다시 안 본다"는 가정이 음수에서 깨짐 → 벨만-포드 사용.

Floyd-Warshall — All-to-All

모든 정점 쌍 거리표(n×n). 중간 노드를 {1..k}로 제한한 dk(i,j)를 k=0→n으로 키워감.

dk(i,j) = min( dk−1(i,j), dk−1(i,k) + dk−1(k,j) ) d₀ = 가중치 인접 행렬, 답 = dn
  • O(n³), 음수 가중치 OK(음의 사이클은 X). 갱신 후보: k행·k열에 ∞ 아닌 값 있는 칸만.
  • 모든 k에서 대각선 dk(i,i)=0.

⚠️ 음의 사이클이 있으면 거리가 −∞로 발산 → 최단 경로 자체가 정의되지 않음.
