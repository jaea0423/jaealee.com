01 균형 탐색 트리 세 종류

한 학기 동안 배운 균형 탐색 트리는 세 가지.

균형 탐색 트리 3종
① AVL 트리  ·  ② Red-Black 트리  ·  ③ 2-3-4 트리

이진 탐색 트리(BST) 여부

★ BST에 속하는지
  • AVL 트리: BST에 속함 (자식 최대 2개)
  • Red-Black 트리: BST에 속함 (자식 최대 2개)
  • 2-3-4 트리: BST 아님 (자식이 2~4개라 이진 트리 X)

시각적 비교

AVL 트리 (BST)
자식 최대 2개
높이 차이 ≤ 1
Red-Black 트리 (BST)
자식 최대 2개
검정/빨강 색 규칙
2-3-4 트리 (BST 아님!)
자식 2~4개
한 노드에 키 여러 개

왜 균형이 중요한가

트리 연산은 O(h)
  • 이진 탐색 트리의 검색·삽입·삭제 모두 O(h) (h는 트리 높이)
  • 높이가 낮을수록 좋음 — 균형 잡힌 트리일수록 빠름
  • 최악(한쪽으로 치우친 트리): h = O(n) → O(n) 연산
  • 최선(균형 잡힌 트리): h = O(log n) → O(log n) 연산
"균형 잡혔다"의 정의

노드가 n개일 때 h = O(log n)이면 그 트리는 "균형 잡혔다"고 말함. AVL/RB/2-3-4 트리는 모두 이 조건을 만족.

02 AVL 트리 복습

AVL 트리 조건

AVL 트리 = BST 조건 + 균형 조건

① BST 조건:

  • 자식이 최대 2개
  • 왼쪽 서브트리의 모든 key < 부모 key < 오른쪽 서브트리의 모든 key

② 균형 조건 (★ AVL의 핵심):

  • 모든 노드에 대해 왼쪽 서브트리와 오른쪽 서브트리의 높이 차이가 1 이하
  • = |h(왼쪽) − h(오른쪽)| ≤ 1

이게 정말 최적인가?

AVL 트리는 "균형 잡혔다"고 주장하지만, 정말 h = O(log n)을 보장하는지 따져봐야 함.

증명할 것

노드가 n개인 AVL 트리의 높이 h가 항상 O(log n) 이하임을 보이기.

03 AVL 트리 높이 증명 — 점화식

증명 전략 — N_h 정의

N_h 정의

높이가 h인 AVL 트리 중에서 최소 노드 개수.

왜 "최소" 노드 개수?

"같은 높이를 만드는 데 노드가 얼마나 적게 필요한가?"를 구하면 — 반대로 "같은 노드 개수로 얼마나 높이 만들 수 있는가?" 도 알 수 있음. 즉 노드 n개일 때 최악의 높이를 알아내는 방법.

작은 h부터 규칙 찾기

h = 0 → N_0 = 1

높이 0인 AVL 트리는 노드 1개뿐. (높이 = 가장 깊은 노드까지의 간선 수, 노드 1개면 간선 0개)

h = 0, 노드 1개 → N_0 = 1

h = 1 → N_1 = 2

높이 1인 AVL 트리는 루트 + 자식 1개 또는 2개. 최소는 자식 1개 (총 2개 노드).

★ N_1 = 2 (최소!)
2개 (또 다른 형태)
3개 (최소 아님)

h = 2 → N_2 = 4

높이 2인 AVL 트리에서 최소 노드를 만들려면 — 한쪽은 높이 1, 다른 쪽은 높이 0으로 두면 됨 (높이 차 ≤ 1 만족).

★ N_2 = 1(루트) + N_1 + N_0 = 1 + 2 + 1 = 4

★ h = 3 → 점화식 발견

같은 원리로 h=3을 만들 때:

★ 핵심 통찰

최소 노드 개수를 만들려면 — 좌우 서브트리의 높이 차이를 최대한 벌려야 함 (둘 다 높이 h-1로 두면 노드 수가 많아짐).

  • 한쪽 서브트리: 높이 h-1 (최소 노드 = N_(h-1))
  • 다른 쪽 서브트리: 높이 h-2 (최소 노드 = N_(h-2))
  • 높이 차이 = 1 → AVL 균형 조건 딱 만족
★ N_3 = 1 + N_2 + N_1 = 1 + 4 + 2 = 7

★★ 점화식 도출

★★ N_h 점화식
Nh = Nh−1 + Nh−2 + 1
↑ 왼쪽 서브트리(h-1)    ↑ 오른쪽 서브트리(h-2)    ↑ 루트 1개

값 확인

hN_h 계산N_h
0—1
1—2
2N_1 + N_0 + 1 = 2 + 1 + 14
3N_2 + N_1 + 1 = 4 + 2 + 17
4N_3 + N_2 + 1 = 7 + 4 + 112
5N_4 + N_3 + 1 = 12 + 7 + 120
★ 피보나치 수열과 닮음

N_h = N_(h-1) + N_(h-2) + 1 — 이건 피보나치 수열 F_h = F_(h-1) + F_(h-2)와 거의 같은 구조 (상수 1만 차이). 그래서 N_h가 지수적으로 증가함이 보장됨.

정확히는 N_h ≈ φ^h (φ ≈ 1.618, 황금비). 즉 N_h ≥ c · φ^h 같은 형태로 하한이 잡힘.

04 ★ h = O(log n) 마무리 증명

점화식 N_h = N_(h-1) + N_(h-2) + 1에서 시작해 h = O(log n)까지 도달하는 게 목표.

Step 1 — 식 단순화

먼저 N_(h-1)과 N_(h-2)의 크기를 비교해 봅니다.

자명한 관찰

N_(h-1) ≥ N_(h-2)

  • 높이가 더 큰 트리는 최소 노드 수도 더 많거나 같음 (당연)
  • 예: N_3 = 7, N_2 = 4 → 7 ≥ 4 ✓

이 관찰을 점화식에 대입:

단순화 과정 
Nh = Nh-1 + Nh-2 + 1
   ≥ Nh-2 + Nh-2 + 1     # N_(h-1)을 더 작은 N_(h-2)로 바꿈
   = 2 · Nh-2 + 1
   ≥ 2 · Nh-2                  # +1을 떼냄 (★ 아래 설명)

★ "+1 어디 갔지?" — 사용자가 의문 단 부분

+1을 떼내도 부등호 유지
  • 우리는 N_h의 하한(lower bound)을 구하는 중
  • 2 · N_(h-2) + 1 ≥ 2 · N_(h-2)는 항상 참 (1을 더한 게 더 크니까)
  • 그래서 N_h ≥ 2 · N_(h-2) + 1 ≥ 2 · N_(h-2)
  • 최종 부등식 N_h ≥ 2 · N_(h-2)에는 +1이 없어 보이지만, 사실 "더 느슨한 하한"으로 떨어뜨린 것
왜 일부러 느슨하게 만드나?

+1을 그대로 두면 식이 복잡해져요. 우리는 "지수 증가" 패턴만 보이면 충분한데, +1은 거기 영향 X. 그래서 깔끔한 형태(2·N_(h-2))로 만든 거예요. 정확한 값이 아니라 증가 속도(증가 차수)가 중요한 상황이라 OK.

Step 2 — 반복 적용 (재귀 풀어내기)

N_h ≥ 2 · N_(h-2)를 계속 적용:

반복 적용 
Nh ≥ 2 · Nh-2
   ≥ 2 · (2 · Nh-4)         # N_(h-2) ≥ 2·N_(h-4) 적용
   = 2² · Nh-4
   ≥ 2² · (2 · Nh-6)
   = 2³ · Nh-6
   ⋮
   ≥ 2k · Nh-2k           # k번 적용했을 때 일반항

Step 3 — h가 짝수라 가정

h가 짝수면 k = h/2일 때 h − 2k = 0이 됨.

k = h/2 대입 
Nh ≥ 2h/2 · N0
   = 2h/2 · 1            # N_0 = 1
   = 2h/2
★ Step 3 결과
Nh ≥ 2h/2
h가 홀수이면?

k = (h-1)/2일 때 멈춰서 N_1까지 가면 됨 — N_h ≥ 2^((h-1)/2) · N_1 = 2^((h-1)/2) · 2 = 2^((h+1)/2). 어느 경우든 2의 (h에 비례하는 거듭제곱) 형태라 결론 같음. 보통 짝수 케이스로 이야기.

Step 4 — h를 n으로 옮기기

지금까지 잡힌 식: 2^(h/2) ≤ N_h. 그런데 우리가 진짜 알고 싶은 건 노드 n개일 때 h가 얼마인가.

관계 연결

노드 n개인 AVL 트리의 높이가 h라면 — n은 그 트리의 노드 수니까 그 높이의 최소 노드 수 이상이어야 함.

N_h ≤ n

두 부등식을 연결:

부등식 연결 
2h/2 ≤ Nh ≤ n     # 양 끝만 보면
2h/2 ≤ n

Step 5 — 양변에 log 취하기

로그 적용 
2h/2 ≤ n
log2(2h/2) ≤ log2(n)    # 양변에 log_2
                              # 밑 2 > 1이라 부등호 방향 유지
h/2 ≤ log2(n)              # ★ log_a(a^b) = b 공식
h ≤ 2 · log2(n)
★ 표기 주의

사용자가 적은 "h/2 = log_2 n"은 부등호 흐름상 "h/2 ≤ log_2 n"이 정확. 등호로 적으면 "정확히 같다"는 의미가 되어 결론이 달라져요.

Step 6 — Big-O 결론

★★ 최종 결론
h ≤ 2 log2(n)
⇒ h = O(log n)
Big-O는 상수배 무시 → 2 log_2 n도 그냥 log n

★ 증명의 의미

AVL 트리는 정말 균형 잡혀 있다
  • 노드가 n개인 AVL 트리의 높이 h는 최대 2 log_2 n
  • = h = O(log n) → "균형 잡혔다"의 정의 만족 ✓
  • 이게 AVL 트리의 모든 연산이 O(log n)인 이유

증명 흐름 한눈에

Step내용
1 점화식 단순화: N_h ≥ 2 N_(h-2) (N_(h-1) ≥ N_(h-2) 사용, +1 떼냄)
2 반복 적용: N_h ≥ 2^k · N_(h-2k)
3 k = h/2 대입: N_h ≥ 2^(h/2)
4 N_h ≤ n 활용: 2^(h/2) ≤ n
5 양변에 log_2: h ≤ 2 log_2 n
6 Big-O: h = O(log n)

왜 이 증명이 중요한가

시험 관점
  • "AVL 트리의 높이가 O(log n)임을 증명하라" — 빈출 문제
  • 핵심 흐름: 최소 노드 점화식 → 단순화 → 반복 적용 → log 취하기
  • 이 6단계 흐름을 한 번 손으로 따라 써보면 시험장에서 재현 가능

05 AVL 삽입과 rebalance

이제 AVL 트리가 균형 잡혔다는 게 증명됐으니, 그 균형을 어떻게 유지하는지 봅니다.

각 연산의 시간복잡도

트리 종류 탐색 삽입 삭제
BST (일반) O(h) O(h) O(h)
AVL O(log n) O(log n) O(log n)
왜 AVL 삽입·삭제도 O(log n)?
  • 일반 BST처럼 삽입·삭제하면 균형이 깨질 수 있음
  • 그래서 균형 복구(rebalance) 작업이 추가로 필요
  • ★ rebalance도 O(log n)이라 전체 복잡도는 그대로 O(log n)

클래스 구조

AVL 클래스 정의 (BST 상속) 
# Node 클래스 — BST의 노드와 거의 동일
class Node:
    key, left, right, parent     # BST와 동일
    height                       # ★ AVL은 height 추가로 관리

# BST 클래스 — 기본 연산 정의
class BST:
    insert, deleteByMerging, deleteByCopying, search

# AVL은 BST 상속 — 기본 연산은 그대로 가져옴
class AVL(BST):
    # BST의 모든 메서드를 그대로 받고, 필요한 것만 override
    ...

AVL 삽입 의사코드

AVL.insert 
def insert(self, key):
    # 1. 일단 BST 방식으로 삽입
    v = super(AVL, self).insert(key)
    
    # 2. 삽입 노드 v에서 부모로 거슬러 올라가며
    #    처음으로 AVL 균형이 깨진 노드를 찾음
    #    z (균형 깨진 노드) ← y (z의 자식) ← x (y의 자식)
    z = # 균형이 깨진 가장 가까운 조상
    y = # z의 자식 (새 노드 쪽 방향)
    x = # y의 자식 (새 노드 쪽 방향)
    
    # 3. 회전으로 균형 복구. w는 새로 z 자리를 차지한 노드
    w = rebalance(x, y, z)
    
    # 4. z가 원래 루트였다면, 회전 후 w가 새 루트
    if w.parent == None:
        self.root = w

★ z, y, x 정의 (헷갈리지 말기)

세 노드의 역할
  • z: 새 노드 삽입 후 균형이 깨진 가장 가까운 조상 (밑에서 위로 올라가며 처음 만나는)
  • y: z의 자식 중 새 노드 쪽 (높이가 더 큰 쪽)
  • x: y의 자식 중 새 노드 쪽

z, y, x는 자기 노드 이름이 아니라 "역할 표시"라고 생각하면 편함.

★ rebalance 케이스 — LR (Left-Right)

이번에 다루는 케이스: z에서 봤을 때 왼쪽이 무겁고(왼쪽으로 y), y에서 봤을 때 오른쪽이 무거운(오른쪽으로 x) 경우. 지그재그 모양이라 회전 2번이 필요.

회전 전 상태

LR 케이스 초기 상태: z의 왼쪽 자식 y, y의 오른쪽 자식 x로 지그재그 — 회전 2번 필요
왜 회전 2번 필요?

z 입장에서 새 노드가 "왼쪽 → 오른쪽"으로 꺾인 경로에 있음. 회전 1번으로는 이 꺾임을 못 풀어요. 먼저 y와 x를 단순화(LL 모양으로 변환) → 다시 z 정리의 2단계가 필요.

Step 1: y에서 좌회전 (x를 y 위로)

Step 1 후: y가 x의 왼쪽 자식으로 내려오고, T₂는 y의 오른쪽으로 이동

이제 z-x-y가 모두 왼쪽으로만 꺾인 LL 모양이 됐어요. 회전 한 번 더로 끝.

Step 2: z에서 우회전 (x를 z 위로)

최종 결과: x가 새 루트 (= w). y와 z가 양쪽 자식으로. 모든 서브트리 높이가 균형 ✓

★ 핵심 — 서브트리들의 재배치

색깔로 따라가는 서브트리 이동
서브트리 시작 위치 최종 위치
T₁ (초록) y의 왼쪽 y의 왼쪽 (그대로)
T₂ (분홍) x의 왼쪽 y의 오른쪽
T₃ (주황) x의 오른쪽 z의 왼쪽
T₄ (파랑) z의 오른쪽 z의 오른쪽 (그대로)

왜 BST 조건이 깨지지 않나?

키 순서 검증

원래 BST이므로 키 순서는: T₁ < y < T₂ < x < T₃ < z < T₄

회전 후에도 중위 순회(inorder) 결과는 같은 순서가 유지됨 — 즉 BST 조건은 안 깨짐. 회전은 모양만 바꾸고 키 순서는 보존하는 연산.

다른 케이스들 (개요)

케이스 z 기준 새 노드 위치 회전 횟수
LL 왼쪽 → 왼쪽 1회 (z에서 우회전)
LR ← 오늘 다룬 케이스 왼쪽 → 오른쪽 (지그재그) 2회
RR 오른쪽 → 오른쪽 1회 (z에서 좌회전)
RL 오른쪽 → 왼쪽 (지그재그) 2회
★ 시험 포인트
  • 4가지 케이스 (LL/LR/RR/RL) 구분 — z 기준 두 단계 방향 보기
  • 일직선(LL, RR) = 회전 1번 / 지그재그(LR, RL) = 회전 2번
  • 각 케이스의 회전 결과 트리 모양 그리기

06 Red-Black 트리

BST + 색깔(검정/빨강) 규칙으로 균형을 유지하는 트리. AVL과 함께 표준 라이브러리에서 가장 많이 쓰임.

4가지 규칙

Red-Black 트리 조건
  1. 루트는 검정
  2. NIL(외부 노드)은 검정
  3. 레드 연속 불가: 빨간 노드의 자식은 반드시 검정
  4. 블랙 높이 일정: 어떤 노드에서 출발하든 NIL까지의 검은 노드 수가 같음

각 규칙의 의미 (왜 그렇게 정해졌나)

규칙 의미
루트 검정 2-3-4 트리의 루트 노드를 명확히 구분
NIL 검정 모든 경로의 끝을 통일적으로 표시
레드 연속 불가 2-3-4 트리에서 한 노드 안의 키는 최대 3개 (4-노드까지) → 빨간 노드 연속되면 5-노드 되어 위반
블랙 높이 일정 2-3-4 트리는 완전 균형(모든 리프 같은 깊이) → 검은 노드만 세면 그 깊이 보존

높이가 O(log n)인 이유

★ RB 높이 분석
  • 검은 노드만 따로 보면 완전 균형 트리 → 검은 높이 = O(log n)
  • 빨간 노드는 연속 불가 → 어떤 경로에서도 빨간 노드는 검은 노드 수 이하
  • 전체 높이 ≤ 2 × 검은 높이 = 2 log_2(n+1)
  • = h = O(log n) ✓

AVL과 비교

구분 AVL Red-Black
균형 조건 좌우 높이 차 ≤ 1 (엄격) 색 규칙 (느슨)
높이 최대 ≈ 1.44 log n (더 짧음) 최대 2 log n
탐색 약간 더 빠름 약간 느림
삽입·삭제 회전 최악 O(log n)번 최악 상수번 (보통 2~3회)
적합 상황 탐색 위주 삽입·삭제 잦음 (실무 표준)
실제 사용처
C++ std::map, Java TreeMap, Linux 커널 등 — 대부분 RB. AVL은 학술/특수 용도.

07 2-3-4 트리 + RB 1:1 대응

2-3-4 트리의 노드 종류

노드 종류 키 개수 자식 수
2-노드 1개 2개
3-노드 2개 3개
4-노드 3개 4개

일반 규칙: n개 키를 가진 노드는 자식 n+1개. 모든 리프는 같은 깊이 (완전 균형).

★ RB 트리와의 1:1 대응

변환 규칙
  • 2-노드 → 검은 노드 1개
  • 3-노드 → 검은 노드 + 빨간 자식 1개
  • 4-노드 → 검은 노드 + 빨간 자식 2개

즉 한 2-3-4 노드 = "검은 노드 + 그 옆에 붙은 빨간 노드들". 빨간 노드는 "원래는 같은 노드의 일부였다"는 신호.

왜 이게 중요한가

RB 규칙이 임의의 약속이 아니다
  • 레드 연속 불가 ← 2-3-4의 5-노드(키 4개)를 만들지 마
  • 블랙 높이 일정 ← 2-3-4가 완전 균형이라는 사실의 보존
  • RB 트리는 "2-3-4 트리를 이진 트리로 흉내내는 방법"
  • 구현은 더 쉽고 (균일 노드), 성능은 거의 같음
시험에서 자주 나오는 형태
  • 2-3-4 트리 그려놓고 RB로 변환하라 (또는 반대)
  • 키 개수만 보면 변환 가능: 1개 → 검정만, 2개 → 가운데 큰 거 검정 + 작은 거 빨강, 3개 → 가운데 검정 + 양옆 빨강

08 그래프 표현

두 가지 방식

방식 구조 공간
인접 행렬 n×n 표, G[u][v]가 1이면 간선 있음 O(n²)
인접 리스트 각 노드마다 이웃 노드 리스트 O(n + m)

★ 연산별 시간복잡도 비교

연산 인접 행렬 인접 리스트
u, v가 이웃인가? O(1) (한 칸 확인) O(deg(u))
u의 모든 이웃 순회 O(n) (n칸 다 봐야) O(deg(u))
전체 간선 순회 O(n²) O(n + m)
선택 기준
  • 밀집 그래프(m ≈ n²): 행렬 유리
  • 희소 그래프(m ≪ n²): 리스트 유리
  • 대부분의 실제 그래프(SNS, 도로망 등)는 희소 → 리스트가 표준

★ 왜 인접 행렬은 이웃 순회에 O(n)인가

자주 헷갈리는 부분

"이웃만 보면 되는데 왜 n번?"

  • 행렬은 "있다/없다"를 둘 다 명시적으로 저장 (0 또는 1)
  • 어디가 1인지 미리 모름 → n칸을 다 확인해야 1을 찾을 수 있음
  • 리스트는 "있는 것만 저장" → 그냥 읽으면 끝

09 DFS / BFS

DFS (Depth-First Search)

DFS

한 길로 끝까지 깊이 → 막히면 backtrack. 스택 또는 재귀로 구현.

핵심 변수

  • mark[v]: visited / unvisited 표시
  • pre[v]: v에 처음 들어간 시각 (방문 순서)
  • post[v]: v를 완전히 끝낸 시각 (backtrack 직전)
  • parent[v]: DFS 트리에서의 부모

의사코드 (재귀)

DFS 
def DFS(v):
    mark[v] = "visited"
    pre[v] = curr_time; curr_time += 1
    
    for each edge (v, w):
        if mark[w] != "visited":
            parent[w] = v
            DFS(w)
    
    post[v] = curr_time; curr_time += 1

★ DFS 트리와 Back Edge

두 가지 핵심 개념
  • DFS 트리: parent 관계 선들만 모은 트리 (n−1개 엣지)
  • Back Edge: 원래 그래프엔 있는데 DFS 트리엔 없는 간선 (이미 방문한 조상으로 가는 모양)
  • ★ Back edge 존재 ⇔ 사이클(순환) 존재 — 시험 빈출

pre/post 구간 시각화

[pre, post] 막대의 성질
  • u가 v의 조상 ⇔ u의 [pre, post]가 v의 [pre, post]를 완전 포함
  • 형제 관계면 막대가 겹치지 않음
  • 막대 포함 관계 = DFS 트리의 부모-자식 관계

DFSALL — 비연결 그래프 대응

DFSALL 
def DFSALL(G):
    for all nodes v: mark[v] = "unvisited"
    for all nodes v:
        if mark[v] != "visited":
            DFS(v)

DFS 호출 횟수 = 연결 요소(component) 개수

BFS (Breadth-First Search)

BFS

시작점에서 가까운 노드부터 한 겹씩 펼침. 큐(queue)로 구현.

DFS vs BFS

구분 DFS BFS
탐색 방향 한 길로 깊이 가까운 곳부터 넓게
자료구조 스택 / 재귀 큐
특기 사이클 탐지, 위상 정렬 최단 거리(무가중치)
시간복잡도 O(n + m) O(n + m)

10 DAG와 위상 정렬

DAG (Directed Acyclic Graph)

DAG

Directed (방향 있음) + Acyclic (사이클 없음) + Graph

  • 모든 간선에 방향 있음
  • 어떤 노드에서도 자기 자신으로 돌아오는 경로 없음
  • "일의 순서" 표현에 적합 (선후 관계)

위상 정렬 (Topological Sort)

위상 정렬

DAG의 정점들을 한 줄로 나열하되, 간선 u→v가 있으면 u가 v보다 앞에 오게 정렬.

★ DFS로 위상 정렬 구하는 법

★★ 핵심 관계
DAG에 DFS를 돌린 후,
POST 값을 내림차순으로 나열하면
= 위상 정렬
★ 시험 빈출 정리
기준 결과
PRE 오름차순 DFS 방문 순서
POST 내림차순 위상 정렬
왜 POST 역순인가

u → v 간선이 있으면 DFS에서 v를 먼저 끝낸 다음 u가 끝남 (post[u] > post[v]). 따라서 post 큰 것부터 줄세우면 "선행 작업" 먼저 옴 = 위상 정렬.

11 Bellman-Ford

문제 설정 — SSSP

SSSP (Single-Source Shortest Path)

한 출발점 s에서 다른 모든 정점까지의 최단 경로.

핵심 개념

  • dist[v]: s에서 v까지의 추정 최단 거리 (점점 작아짐)
  • parent[v]: 최단 경로상 v 직전 노드 (경로 복원용)
  • relax(u, v): 더 짧은 길 발견하면 dist[v] 갱신
relax 정의 
def relax(u, v):
    if dist[v] > dist[u] + w(u, v):
        dist[v] = dist[u] + w(u, v)
        parent[v] = u

★ 점화식

최단 경로의 점화식
dist[v] = min ( dist[u] + w(u, v) ) for all u → v
= v로 들어오는 모든 후보 중 비용 합 최소

Bellman-Ford 의사코드

Bellman-Ford 
dist[s] = 0; for v ≠ s: dist[v] = ∞

for i in range(n − 1):              # 최대 n−1 라운드
    for each edge (u, v) in G:        # 모든 간선 검사
        if dist[v] > dist[u] + w(u, v):
            relax(u, v)

★ 왜 n−1 라운드?

근거
  • 최단 경로의 간선 최대 수 = n−1 (정점 n개)
  • 한 라운드마다 한 간선만큼 정보 전파
  • → 최대 n−1 라운드면 모든 최단 거리 확정

시간복잡도

Bellman-Ford 시간복잡도
O(V · E) = O(n · m)
최악 (E = n²): O(n³)

특징

BF의 특기
  • 음수 가중치 OK (Dijkstra가 못하는 부분)
  • 음수 사이클이 있으면 검출 가능 (n번째 라운드에서도 갱신 일어나면 음수 사이클)

12 Dijkstra

핵심 아이디어

Dijkstra 전략

매번 "현재 가장 가까운 미확정 노드"를 골라 확정. 한 번 확정된 노드는 다시 안 봄.

  • 잉크가 천천히 번지듯 가장자리부터 확장
  • BF는 매 라운드 모든 간선 재검사 → Dijkstra는 똑똑하게 골라서

의사코드 (min-heap 사용)

Dijkstra 
dist[s] = 0; for v ≠ s: dist[v] = ∞
parent = [None, ..., None]

Q = min_heap of all nodes with key dist[v]

while Q ≠ ∅:
    u = Q.deleteMin()             # O(log n)
    
    for each edge u → v:
        if dist[v] > dist[u] + w(u, v):
            relax(u, v)
            parent[v] = u
            Q.decreaseKey(v, dist[v])  # O(log n)

return dist, parent

시간복잡도

Dijkstra (min-heap) 시간복잡도
heap 관리: O(n log n) — n번 insert + n번 deleteMin
decreaseKey: O(E log n) — 각 간선마다 한 번
= O((n + E) log n)
최악 (E = n²): O(n² log n)

★ 한계 — 음수 가중치 X

★ 시험 빈출
  • Dijkstra는 모든 가중치가 양수일 때만 정확
  • 음수 가중치 있으면 "한 번 확정 후 안 보기" 전략이 깨짐
  • 음수 가중치 그래프 → Bellman-Ford 사용

Fibonacci heap 사용 시

심화
Fibonacci heap을 쓰면 decreaseKey가 amortized O(1) → 전체 O(E + n log n)으로 개선. 알고리즘은 동일.

parent로 경로 복원

i부터 거꾸로 parent를 따라가면 s까지의 실제 경로 복원 가능:

경로 복원 
path = []
cur = target
while cur != None:
    path.append(cur)
    cur = parent[cur]
path.reverse()    # s에서 target 방향

parent 화살표 전체를 모으면 최단 경로 트리(SPT) — s 루트, n−1개 엣지.

13 Floyd-Warshall

문제 설정 — All-to-All

All-to-All Shortest Path

모든 정점 쌍 (i, j)에 대해 i → j 최단 경로 (n×n 표).

방법 1 vs Floyd-Warshall

방법 설명 시간복잡도
방법 1 모든 출발점에 Dijkstra 반복 O(n³ log n)
Floyd-Warshall 전용 알고리즘 (DP) O(n³)

★ d_k(i, j) 정의

d_k(i, j)

중간 노드를 {1, 2, ..., k}에서만 골라 쓸 수 있을 때의 i → j 최단 거리.

  • 최종 목표: d_n(i, j) (모든 노드 거쳐갈 수 있음 = 제한 없음)

★ 점화식

★★ Floyd-Warshall 점화식
dk(i, j) = min ( dk−1(i, j),
                  dk−1(i, k) + dk−1(k, j) )
↑ k 안 거치는 경우     ↑ k 거치는 경우

Base case d_0

경우값
i = j (자기 자신) 0
(i, j) ∈ E (직접 간선) w(i, j)
그 외 ∞

d_0 표 = 가중치 인접 행렬과 동일.

★ 진행 방식

표 갱신 흐름
  1. d_0 (인접 행렬) 만들기
  2. k = 1, 2, 3, ..., n까지 차례로 표 갱신
  3. 각 단계 k에서: k행과 k열에 ∞ 아닌 값이 있는 칸만 갱신 후보
  4. k행/k열 자체는 변화 없음
  5. d_n이 최종 답

특징

Floyd-Warshall 강점
  • 음수 가중치 OK (음수 사이클은 불가)
  • 한 번 실행으로 모든 쌍의 답
  • 구현이 매우 단순 (삼중 for문 + min)

15 ★ 시험 체크리스트

기말 시험 빈출 포인트
▸ 균형 탐색 트리
  1. AVL 조건: BST + 모든 노드 좌우 높이 차 ≤ 1
  2. ★ AVL 높이 O(log n) 증명: N_h 점화식 → 2^(h/2) ≤ n → h ≤ 2 log n
  3. AVL 회전 4가지: LL/RR (1번), LR/RL (2번)
  4. RB 4규칙: 루트 검정, NIL 검정, 레드 연속 X, 블랙 높이 일정
  5. ★ 2-3-4 ↔ RB 변환: 2-노드→검정, 3-노드→검정+빨강1, 4-노드→검정+빨강2
▸ 그래프 표현·순회
  1. 인접 행렬 O(n²) vs 인접 리스트 O(n+m)
  2. DFS 핵심: pre, post, parent — 막대 포함 관계 = DFS 트리
  3. ★ Back edge ⇔ 사이클 존재
  4. DFSALL: 비연결 그래프 대응, 호출 횟수 = 컴포넌트 수
  5. ★ 위상 정렬 = POST 내림차순 (DAG에서)
▸ 최단 경로
  1. ★ 부분 경로 최단성: 최단 경로의 부분도 반드시 최단
  2. ★ relax(u, v): 더 짧으면 dist[v] 갱신, parent[v] = u
  3. BF: n−1 라운드 × 모든 간선, O(VE), 음수 OK
  4. Dijkstra: min-heap, deleteMin + decreaseKey, O((n+E) log n), 음수 X
  5. 왜 가장 가까운 노드부터? 양수 가중치라 그 dist는 더 줄 수 없음
  6. ★ Floyd-Warshall 점화식: d_k(i,j) = min(d_(k-1)(i,j), d_(k-1)(i,k) + d_(k-1)(k,j))
  7. FW 시간복잡도 O(n³), 음수 OK (음수 사이클은 X)
  8. FW 갱신 후보 찾기: k행/k열에 ∞ 아닌 값 있는 곳만
▸ 자주 헷갈리는 부분
  1. "노드 번호 = 인덱스 = ID" (Floyd-Warshall의 k)
  2. d_k(i, i) = 0 (모든 k에서 대각선은 0)
  3. P(i,j)는 mid[i][j] 한 줄로 기록 — 시간복잡도 변화 없음
  4. Dijkstra heap에서 같은 dist 동률이면 어느 쪽 먼저든 결과 동일
  5. BF에서 같은 라운드 내 갱신 사용 가능 (구현에 따라)

증명·도출 핵심 흐름

★ AVL 높이 증명 6단계
  1. N_h = N_(h-1) + N_(h-2) + 1
  2. N_(h-1) ≥ N_(h-2) 이용 → N_h ≥ 2 N_(h-2) (+1 떼냄)
  3. 반복 적용: N_h ≥ 2^k · N_(h-2k)
  4. k = h/2 대입: N_h ≥ 2^(h/2)
  5. 2^(h/2) ≤ N_h ≤ n → log 취해서 h ≤ 2 log n
  6. h = O(log n)
★ Floyd-Warshall 점화식 도출
  1. 최단 경로의 중간 노드 중 가장 큰 인덱스를 k로 잡음
  2. 두 경우로 나눔: k 거치지 않는 경우 / k 거치는 경우
  3. k 거치는 경우 → i→k 구간, k→j 구간 모두 중간 노드 인덱스 ≤ k−1
  4. min으로 두 경우 비교 → 점화식 완성
