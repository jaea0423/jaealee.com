1. 휴대폰 화면

※ 실제 사용이 대부분 휴대폰이므로 휴대폰 화면에 맞춰 개선.

번호내용
1예약 등록 중 단계 표시(인원·날짜·시간 등)를 눌러 앞뒤 단계로 바로 이동
2예약 등록 중 그날 예약 현황(스케줄)을 팝업으로 확인 — 손님과 통화하며 예약받을 때 사용
3예약 시간 선택 시 'NaN' 표시 오류 수정
4날짜 이동 시 화면이 검게만 바뀌지 않고 이동한 날짜가 보이도록 개선
5인원 표기: 타임라인에서는 넘쳐 잘 보이지 않으나, 휴대폰 목록형에서 잘 보이므로 현행 유지

2. 디스플레이 모드 (TV)

번호내용
1목록형을 기본 화면으로
2목록형의 룸 이름·인원 글씨 확대, 세로 가운데 정렬
3화면 하단에 그날 메뉴(코스·세트 수량) 표시 — 주방 확인용
4그날 예약이 끝나면(마지막 예약 시각 30분 경과) 다음 날 예약 화면으로 자동 전환
5다음 날 예약도 없으면 광고 화면으로 자동 전환 (이틀 뒤 예약까지는 표시하지 않음)

나. 좌석

번호내용
1좌석 종류는 모두 '홀'로 유지. 테이블 이름(하후상 등)은 자리를 가리킬 때만 사용
2여포는 홀과 동일하게 적용 — 최소 인원 없음(2명 가능), 5명도 경고 없이 가능
32명 예약은 2인석 우선 배정
4거동이 불편한 손님은 1층 우선 배정, 1층이 아니면 경고
5'단체(8명 이상)' 구분 및 단체 표시 폐지
6자리 배정은 현행대로 대표가 상황에 따라 직접 배정
714명까지 장비+관우 룸. 15명부터는 룸 중문 개방(원탁 3개) 또는 저층 홀 이용
단체는 원탁을 선호하지 않는 경우가 많아 저층 홀(룸과 비슷한 분위기)로 안내하기도 함
8상견례·돌잔치 등 중요한 자리는 기준 인원보다 적어도 룸 합치기 가능 — 시스템에서 막지 않고 예약 담당자가 판단
9(예정) 룸·홀 배치도를 보고 눌러서 자리를 고르는 화면

라. 홈페이지 예약 (재개 시점부터 적용)

번호내용

3홈페이지 예약은 문자 연결과 함께 재개

감사 문자AI 작성 시 요청사항·메모는 읽지 않음. 이름·인원·코스 등은 참고

알리고사이트 아이디·비밀번호 전달 필요 (비밀번호 변경 후)

5. 손님 관리

구분내용
손님 정보 표시손님 관리 화면 개선. 예약 등록 중 이름·전화번호 입력 시 손님 정보 표시, 누르면 팝업으로 특이사항까지 확인
VIP 기준방문 횟수 기준은 더 엄격하게, 이용 금액을 우선. 직접 지정한 등급이 가장 우선 (금액 기준은 확인 요청 사항 7~9번)
손님 묶기같은 회사 등 예약 담당자가 여러 명이면 이름이 달라도 한 손님으로 묶기.
같은 이름이 이미 있으면 "이미 등록된 이름이 있습니다" → 합치기 / 새로 등록하기 선택
현장 손님 기록예약 없이 온 손님 간단 기록 — 이름, 전화번호(선택), 날짜(선택), 메뉴(선택), 인원(선택)
유아의자현재 6개 보유 — 초과 시 알림

6. 워크시프트 (근무·급여)

구분내용
일용 직원 등록PIN 없이 이름만으로 추가 (로그인 방식은 확인 요청 사항 13번)
일용 급여 지급연속 근무 일괄 / 하루씩 외에, 연속 5일 중 3일만 지급처럼 날짜를 골라 지급
지급 완료 표시근무표 칸 오른쪽 위에 작은 동그라미·체크로 표시 (대표만 확인·수정)
근무표 출력작성된 근무표, 빈 근무표(양식) 모두 출력
급여 자료대표가 월 1회 회계사무소에 엑셀 전달
급여일산정 기간이 끝나고 바로 그 기간 급여가 지급되는 것이 아니라, 한 기간 뒤 지급 (확인 요청 사항 10번)

7. 알림

구분내용
수신 방법텔레그램만 사용 (메일 알림 사용 안 함). 예약 현황 브리핑 사용 안 함
설치 대상대표, 팀장, 근무자 1명
대표홈페이지 예약 알림 항상 수신. 밤 12시~오전 10시 알림은 모아서 오전 10시에 한 번에 발송
팀장·근무자근무하는 날, 근무 시작 1시간 전부터 근무 종료 1시간 후까지 알림 수신 (점심시간 포함)
그 밖의 시간에 생긴 당일 예약 등록·수정 알림은 알림 시간이 되면 바로 발송 (밀린 알림 확인용)
당일 예약당일 예약 등록·수정은 대표에게 시간과 관계없이 즉시 알림
화면 갱신현재 10초마다 서버에서 예약을 받아옴. 속도·사용량에 문제가 있으면 1분 등으로 조정 가능

번호질문

라. 워크시프트

번호질문
