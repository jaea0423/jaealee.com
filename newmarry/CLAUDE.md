# 축의지기 (newmarry) — 작업 안내

결혼식 축의대(봉투 접수·식권·정산)를 노트북 한 대로 운영하게 해 주는 웹서비스 **축의지기**의 화면 시안입니다.
운영 주체는 와이비테크랩(기존 사업자), 서비스명은 축의지기로 확정, 상위 웨딩 브랜드명은 미정입니다.
이 저장소는 **정적 HTML 시안** 단계입니다. 백엔드·로그인·결제는 아직 없습니다.

## 빌드·검사

```
python src/build.py          # 루트에 생성 (site 모드: 모든 페이지가 독립 HTML)
python src/build.py --artifact   # 루트 index.html만 <title>부터 시작하는 조각 (claude.ai 아티팩트 게시용)
npm install && npx playwright install chromium   # 처음 한 번
npm run check                # 8화면 × 3폭 점검 + 등록→설정→요청→준비→진행 흐름, src/tests/shots/에 화면 저장
```

- 화면을 고친 뒤에는 **반드시 빌드 → `npm run check` → 1366×768 스크린샷(src/tests/shots/)을 눈으로 확인**합니다.
- 진행 화면(desk)은 1366×768에서 **스크롤 없이 한 화면**에 들어가야 합니다. check.js가 넘치면 실패로 잡습니다.

## 합의된 서비스 규칙 (바꾸지 말 것)

**요금·보관**
- 예식 1건 9,900원(VAT 포함). 추천 코드가 있으면 7,900원. 추천 코드는 폐쇄형·1회·결제 화면에서만 입력(등록에 두지 않음).
- 등록·설정·요청·준비는 무료, **결제는 축의대를 여는 시점(진행 직전) 한 번**.
- 명부(하객 이름·금액)는 암호화 저장, 예식일로부터 3개월 뒤 영구 삭제. 결과는 HTML·Excel로 내려받기.

**역할·권한**
- 신랑신부 = 공용 계정 하나, 모든 권한(설정, PIN 발급, 혼주 열람 켜기, 계좌이체 후입력, 제출 잠금 해제, 열람).
- 축의대 담당자 = PIN으로 들어와 **자기 구분(신랑측/신부측)** 만 접수·정산·제출. 구분당 입력 기기 1대, 입력자 교체는 기록만 남김.
- 혼주 = 열람만(신랑신부가 켬). 혼주마다 PIN.
- PIN·로그인은 **개발 마지막에** 붙임. 지금 시안은 구분 선택부터 시작.

**설정**
- 담당은 구분별 최대 4명, 이름·관계 칸 분리. 식권 장수·도착 시간·축의대 자리·인계받을 분·담당은 **미정으로 둘 수 있음**. 단 미정이 하나라도 남으면 축의대를 열(결제할) 수 없음.
- 요청서를 보낸 시점 값과 달라진 칸(미정이 채워진 것 포함)에는 **"변동"** 표시. 설정 체크 목록 아래, 요청서, 진행 화면(상단 칩 + 구분 선택 직후 자동 모달)에도 같은 내용이 보임.
- 배경 그림은 제공된 6장 중 고름(직접 올리기 없음). 4번 한복이 기본.

**진행(축의대) 입력 규칙**
- 순번은 구분별 자동. 성함 필수, 없으면 무기명 체크. 받은 방법(현금/계좌이체)은 묻지 않음 — 계좌이체는 신랑신부가 결과 화면에서 따로 추가.
- 금액은 **항상 만 원 단위**. 소수점 첫째 자리 = 천 원(3.5 → 3만 5천 원), 1000 → 1,000만 원, 10000 → 1억 원. 둘째 자리부터 무시. 큰 금액 경고 없음. 금액 칸 옆에는 초기화 버튼만.
- 식권 기본 0장. 직접 입력 + −/+ 버튼 + 단축키 `=`/`+` 올림, `-`/`_` 내림(메모·검색 칸에서는 꺼짐).
- Tab은 성함 → 금액 → 식권 → (메모) 입력칸끼리만 순환, 버튼·체크박스는 건너뜀. Enter = 저장(성함 칸에서는 금액으로 이동).
- 저장 불가(성함·금액 비면)는 **팝업**으로 알리고 닫으면 해당 칸으로 포커스. 동명이인은 팝업으로 확인 후 저장(Enter 기본값 = 저장. 오저장 위험이 크면 "다시 확인"으로 바꾸는 안이 보류 중).
- 저장되면 최근 봉투 첫 줄이 분홍으로 깜빡이고 순번 배지 + "봉투에 N 적기"가 8초 표시. 담당자는 봉투 뒷면에 순번을 적음(정산 대조용).
- 삭제 없음. 취소 = 취소선 + 기록. 수정 가능(이름·금액·식권·메모, 변경 내용과 시각 기록). 최근 봉투 위 검색칸(이름·순번)으로 전체 명부 검색, 명부 전체 보기는 **순번 오름차순**.
- 위쪽 숫자는 접수 건수·식권 남음 두 개만. 현금 합계는 명부 창 안에서 가려 두고 눌러서 보기(15초 후 다시 가림).
- 식권 출납: "식권 추가·따로 지급"에서 추가로 받음(혼주가 전달/직접 받아 옴/도장 추가/기타), 봉투 없이 드림(무축의 요청/혼주·가족/진행팀/기타), 돌려받음. 식권 남음 ≤30이면 빨간색.
- 정산: 권종별(5만·1만·5천·1천) 장수 vs 명부 합계, 남은 식권 vs 기록(받은 식권 = 처음 + 추가). 차이가 있으면 사유 필수. 최종 제출하면 잠김, 인계 요약 표시. 잠금 해제는 신랑신부만(기록 유지).
- 오프라인이면 기기에 저장했다가 다시 연결 시 동기화(시안은 시뮬레이션). 상단에 "저장됨 · 마지막 저장 시각". 전체화면은 사용자 동작(구분 선택) 시 켬.

## 디자인 규칙

- 테마: 흰 유리 카드(반투명 + blur) 위에 남색 글자(`--ink #2B2940`), 강조는 장미 분홍(`--gold #D65F7D`, 토큰 이름은 밤 테마 때 것을 그대로 씀), 완료 녹색, 변동 파랑. 토큰은 `src/desk.html`의 `:root`.
- 글꼴: 제목 Gowun Batang, 영문 eyebrow Cormorant Garamond, 본문·숫자 Pretendard→Noto Sans KR. 숫자는 굵게(800)·tabular-nums.
- 곡률: 애플식 연속 곡률 `corner-shape: squircle` (지원 브라우저) + 작은 반경 fallback. 안쪽 요소 반경은 바깥보다 작게.
- 레이아웃: 노트북 기준. 왼쪽 칸(폭 `--col = min(max(60vh,300px),42vw)`)에 배경 그림의 신랑신부와 이름, 오른쪽이 작업 영역. 휴대폰·태블릿은 세로로 쌓이기만 하는 임시 상태(최적화는 다음 단계).
- 배경 그림 구도(새 그림 만들 때): 3:2 가로, 신랑신부가 가로 5~43% 안(머리는 위 15~25%), 43~60%는 흐려지는 구간, 60%~는 카드 뒤. 왼쪽 아래 30%는 이름 글씨 자리. 지평선 약 40%. `docs/배경구도.jpg` 참고. 그림은 `bg/` 파일로 참조(페이지에 base64로 넣지 않음).
- 블록 정렬: 같은 줄의 카드는 높이를 맞추고(`.grid2`), 카드 안 목록은 `.fill`로 남는 공간을 고르게 채움. 크기가 제각각이거나 여백이 뜨면 안 됨.
- 상단 7단계 표시(`flow()`)는 지난 단계 ✓, 현재 단계만 이름. 개발용 "시안" 이동 막대(`.proto`)는 시안 전용이며 실제 서비스에서는 뺌.
- 문구는 높임말, 짧은 문장. 어떤 버튼이 무엇을 하는지 그대로 씀("저장", "명부 마감하고 정산하기"). 예시 데이터는 가상 인물(이용범 & 김홍매, 2000. 4. 16. 일요일 오후 1시, 신라호텔 영빈관).

## 코드 규약

- 바닐라 HTML/CSS/JS, 라이브러리 없음. 각 페이지는 IIFE 하나. 공용 함수는 `common.js`(`$`, `won`, `esc`, `kor`, `parseAmt`, `toast`, `openModal/closeModal`, `alertPop`, `seedRows`).
- `alert/confirm/prompt`, `window.print`, 다운로드 링크는 쓰지 않음(시안 환경에서 동작하지 않음). 확인은 페이지 안 모달로.
- 사용자 입력은 `esc()`로 넣음. `[hidden]`으로 보이기/숨기기.
- 진행 화면은 `src/desk.html`이 원본이고 `build.py`의 `desk()`가 시안용 변형(PIN 단계 숨김, 입력자 교체 기록만, 변동 칩·모달 주입)을 더함. 진행 화면 규칙을 바꿀 때는 desk.html을 고치고 `desk()`의 치환이 여전히 맞는지(assert) 확인.
- 페이지끼리 상태가 이어지지 않음(설정에서 바꿔도 다른 화면은 예시 값). 실제 구현 전까지는 예시 값을 화면 간에 **일관되게** 유지(식권 200→230, 인계받을 분 미정→신랑 아버지 이정수, 축의대 자리 미정, 담당 이재훈·이민지).

## 작업 방식

- 결론부터, 간결하게, 높임말. 틀린 전제는 먼저 바로잡고 해결책을 제시.
- 합의되지 않은 기능 추가·분위기 전면 교체 금지. 되돌리기 쉬운 서식·구성은 스스로 정하고, 결과가 크게 달라지는 것만 질문.
- 바꾼 뒤에는 빌드·점검·스크린샷 확인 결과와 미검증 사항을 함께 보고.
