# 포스(주문·주방·서빙·결제) — 계획 메모 (2026-09-19, 논의 단계)

재아가 새 세션에서 이어 가려고 적어 둔 것. 아직 코드 없음.

## 결정 방향 (제안)
- **같은 생태계, 다른 앱.** 저장소는 `hanok/` 안에 `pos/`(주문·KDS·서빙 웹앱)와 `pos-bridge/`(C#, 카운터 PC 전용: 영수증 프린터·CAT 단말기)로 나눔.
  예약 시스템(`system/`)과는 **Supabase 프로젝트·로그인·손님(customers)·좌석 설정(stores.settings.rooms)** 을 같이 쓰고, 코드는 섞지 않음.
  · 이유: 예약 시스템은 "파일 하나·구형 TV" 제약이 있고, 포스는 아이패드·윈도우 PC 전용이라 제약이 다름. 한 파일에 넣으면 둘 다 무거워짐.
  · 공유하는 것: 손님 번호(단골 등급·메모), 룸/테이블 이름, 코스·세트 구성(settings.courseGroups), 직원(staff — 누가 주문 받았는지).
  · 예약 → 포스: 예약 손님이 오면 포스에서 "예약 불러오기"(오늘 예약 목록에서 고르면 테이블·인원·코스가 주문에 들어감).
- 실시간 통신: 처음엔 **Supabase Realtime**(orders 표 구독) — 아이패드·PC 모두 웹으로 같은 코드. C#(SignalR) 로컬 서버는 인터넷 끊김 대비가 필요해지면 그때.
- 결제: 포스는 금액만 보여 주고 **나이스정보통신 CAT 단말기**에서 결제. 승인 결과를 받으면 주문에 붙여 영수증 출력·보관. 현금영수증은 단말기에서.
- 배달의민족: 배민 주문접수 프로그램은 그대로 두고, 포스에 "배민 열기" 버튼 + "배달 주문" 매출 한 줄.

## 나이스정보통신에 물어볼 것 (대리점/가맹점 센터 1588-0700 또는 단말기 스티커의 대리점)
1. "저희 가맹점 카드 단말기(모델명 ___)에 **포스 연동(CAT 시리얼/USB 통신) 규격서**를 받을 수 있나요? 자체 개발 포스입니다."
2. "연동 방식이 **시리얼(RS-232/USB) 직결**인가요, 아니면 **NICE 포스 연동 프로그램(예: NicePayments/ NICE VAN 에이전트)** 을 PC 에 깔고 그 프로그램과 통신하는 방식인가요?"
3. "테스트용 단말기나 테스트 승인(취소) 환경이 있나요? 비용은?"
4. "포스 쪽에서 카드 정보를 전혀 다루지 않고 **금액 전송 → 승인 결과 수신**만 하면, 별도 보안 인증(여신금융협회 POS 인증)이 필요 없는 게 맞나요?"
5. "영수증은 포스가 자체 프린터로 뽑아도 되나요, 단말기 영수증과 별개로?"
→ 답을 받으면 `pos-bridge/` 설계 시작. 규격을 안 주면 반자동(포스가 금액 표시 → 단말기 수기 입력 → 승인번호 포스에 기록)으로.

## 화면 (아이패드, 웹/PWA)
- 홀 주문: 테이블/룸 고르기 → 메뉴(사진·코스 구성 조절·요청사항) → 전송. 예약 불러오기.
- KDS(주방): 메뉴별 보기(같은 메뉴 개수 합산) / 테이블별 보기 토글. 접수 → 조리 중 → 준비 완료.
- 서빙 알림: 준비 완료 → 홀 태블릿 소리+팝업, 한 명이 확인하면 다른 기기에서 사라짐, 몇 분 미처리면 주방에 지연 표시.
- 카운터(윈도우 PC): 주문 합계 → 단말기 결제 → 승인 결과 + 주문 내역 영수증 출력 → 보관.

## 순서
① 나이스 규격 확인 → ② 홀 주문 + KDS(웹, Supabase) → ③ 영수증 프린터(C# 브릿지, ESC/POS) → ④ 단말기 연동 → ⑤ 서빙 알림 고도화.
예약 시스템 실사용 안정화(prod 이전·문자 업체) 뒤에 시작.
